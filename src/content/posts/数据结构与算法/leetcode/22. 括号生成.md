## 解题思路
这道题非常适合接着你前面的 **全排列、子集、电话号码组合、组合总和** 来学，因为它也是标准回溯题。

这题最推荐：

> **回溯 + 剪枝：记录已经使用的左括号数 `left` 和右括号数 `right`。**

真正需要掌握的不是记住代码，而是学会一类题：

> **构造所有合法方案时，不要先生成全部方案再检查是否合法，而是在构造过程中就把不合法分支剪掉。**

本题不推荐普通迭代法。可以用 BFS/队列枚举状态，但代码更复杂，也没有比回溯更自然，所以面试优先递归回溯。

---

# ① 破题：题目真正要求什么

假设：

```
n = 3;
```

表示我们有：

```
3 个 '('
3 个 ')'
```

最终字符串长度一定是：

```
2 * n = 6
```

合法答案有：

```
((()))
(()())
(())()
()(())
()()()
```

注意，不是随便排列三个 `(` 和三个 `)`。

例如：

```
)(()()
```

虽然：

```
左括号 3 个
右括号 3 个
```

但它不合法。

所以问题真正变成：

> 我们从左到右构造字符串，每一个位置放 `(` 还是 `)`，怎样保证整个过程中始终合法？

---

# ② 核心技巧：什么时候能放左括号？什么时候能放右括号？

这是整道题最核心的两个规则。

我们定义：

```
left
```

表示已经使用了多少个左括号。

```
right
```

表示已经使用了多少个右括号。

---

## 规则一：左括号没用完，就可以放

总共只有 `n` 个左括号，所以：

```
if (left < n)
```

可以添加：

```
'('
```

然后：

```
left + 1
```

---

## 规则二：右括号数量必须小于左括号数量，才能继续放 `)`

这是本题最重要的一句：

```
if (right < left)
```

才能添加：

```
')'
```

为什么？

因为右括号的作用是：

> 去匹配前面还没有闭合的左括号。

例如：

```
((
```

现在：

```
left = 2
right = 0
```

当然可以放 `)`：

```
(()
```

因为前面有左括号等待匹配。

但是如果：

```
()
```

此时：

```
left = 1
right = 1
```

再放一个：

```
)
```

就会得到：

```
())
```

明显非法。

所以始终必须保证：

```
right <= left
```

而在“准备添加右括号之前”，必须满足：

```
right < left
```

# ③ 图解执行过程

以：

```
n = 3
```

为例。

初始：

```
path = ""
left = 0
right = 0
```

---

## 第一个位置

能不能放左括号？

```
left < n
0 < 3
```

可以：

```
path = "("
left = 1
right = 0
```

能不能一开始放右括号？

判断：

```
right < left
0 < 0
```

不成立。

所以：

```
")"
```

这条非法分支根本不会生成。

这就是**剪枝**。

---

## 当前 `"("`

状态：

```
left = 1
right = 0
```

现在有两个选择。

### 选择左括号

```
"(("
left = 2
right = 0
```

### 选择右括号

因为：

```
0 < 1
```

所以可以：

```
"()"
left = 1
right = 1
```

---

## 先走 `"(("`

继续选左括号：

```
"((("
left = 3
right = 0
```

此时：

```
left == n
```

左括号已经用完了，之后只能不断补右括号：

```
"((()"
"((())"
"((()))"
```

得到第一个答案：

```
((()))
```

然后回溯。

---

## 回到 `"(("`

这次不继续放左括号，而是放右括号：

```
"(()
left = 2
right = 1
```

接下来又有选择。

可以放 `(`：

```
"(()("
```

再补：

```
"(()()"
"(()())"
```

得到：

```
(()())
```

也可以继续放 `)`：

```
"(())"
```

然后再：

```
"(())("
"(())()"
```

得到：

```
(())()
```

---

## 再回到 `"("`，走 `"()"`

```
path = "()"
left = 1
right = 1
```

这时候还能不能放 `)`？

```
right < left
1 < 1
```

不成立。

所以：

```
"())"
```

这种非法字符串根本不会进入搜索树。

只能继续放：

```
"()("
```

后面得到：

```
()(())
()()()
```

最终五个答案：

```
((()))
(()())
(())()
()(())
()()()
```

---

## 回溯树可以这样理解

```
                     ""
                     |
                     (
                  /     \
                ((       ()
              /   \       |
            (((    (()    ()(
             |     / \    /  \
          ((())) (()()) (())() ...
```

更准确地说，每个节点都要检查：

```
左括号还能不能放？
右括号现在是否合法？
```

不合法分支直接不创建。

# ④ 完整代码

推荐你掌握这个版本：

```cpp
class Solution {
private:
    vector<string> result;
    string path;

    void backtrack(int n, int left, int right) {
        // 左右括号都使用完了
        if (left == n && right == n) {
            result.push_back(path);
            return;
        }

        // 1. 左括号还没用完，可以放 '('
        if (left < n) {
            path.push_back('(');

            backtrack(n, left + 1, right);

            path.pop_back();
        }

        // 2. 只有当前右括号少于左括号时，
        // 才能放 ')'
        if (right < left) {
            path.push_back(')');

            backtrack(n, left, right + 1);

            path.pop_back();
        }
    }

public:
    vector<string> generateParenthesis(int n) {
        backtrack(n, 0, 0);
        return result;
    }
};
```

# ⑤ 关键设计解释

## 1. `left` 和 `right` 到底存什么？

```
left
```

表示：

> 当前 `path` 已经使用了多少个 `(`。

```
right
```

表示：

> 当前 `path` 已经使用了多少个 `)`。

例如：

```
path = "(()("
```

有：

```
left = 3
right = 1
```

---

## 2. 为什么左括号条件是：

```
left < n
```

因为左括号最多只能使用：

```
n 个
```

如果：

```
left == n
```

说明已经全部用完。

例如 `n = 3`：

```
(((
```

已经有三个左括号，不能再得到：

```
((((
```

---

## 3. 为什么右括号必须：

```
right < left
```

因为任何合法括号字符串的**任意前缀**都必须满足：

```
右括号数量 <= 左括号数量
```

例如合法：

```
(()())
```

逐步看：

```
(        左1 右0
((       左2 右0
(()      左2 右1
(()(     左3 右1
(()()    左3 右2
(()())   左3 右3
```

始终：

```
right <= left
```

而像：

```
())
```

走到第三个字符时：

```
left = 1
right = 2
```

出现：

```
right > left
```

所以非法。

因此，在添加 `)` 之前必须保证：

```
right < left
```

添加之后最多变成：

```
right == left
```

不会超过。

---

## 4. 为什么终止条件不是 `path.size() == 2 * n`？

其实也可以写：

```
if (path.size() == 2 * n)
```

但是：

```
left == n && right == n
```

语义更直接：

> 所有左括号和右括号都已经使用完成。

因为我们的剪枝已经保证搜索过程中不会生成非法字符串，所以到这里一定是合法答案。

---

## 5. 为什么不先生成所有括号排列，再判断是否合法？

理论上可以。

比如 `n = 3`，长度是 6，每个位置都尝试：

```
(
)
```

那么会有：

```
2^6 = 64
```

条候选字符串。

里面大量都是：

```
))((((
())(((
)))(((
```

这种一眼就知道不可能合法的分支。

而回溯在构造过程中就检查：

```
left < n
right < left
```

非法的直接不往下走。

这就是：

> **剪枝。**

---

## 6. 为什么这里没有 `used`？

全排列使用 `used` 是因为：

> 需要判断某个具体元素有没有被使用过。

本题没有独立的括号对象。

我们只需要知道：

```
用了几个左括号
用了几个右括号
```

所以两个计数器就够了。

---

## 7. 为什么这里没有 `startIndex`？

子集、组合总和中：

```
候选元素来自一个数组
```

所以需要 `startIndex` 控制下一层从哪里继续选择。

本题每一层候选永远只有：

```
(
)
```

而能否选择由：

```
left
right
```

决定。

因此不需要 `startIndex`。

---

# ⑥ 递归三要素

这道题非常适合用递归。

## 1. 递归函数定义

```
backtrack(n, left, right)
```

表示：

> 当前已经使用 `left` 个左括号、`right` 个右括号，并且 `path` 中保存当前合法前缀；接下来继续生成所有合法括号组合。

---

## 2. 递归终止条件

```
if (left == n && right == n) {
    result.push_back(path);
    return;
}
```

说明：

```
n 个 (
n 个 )
```

全部用完。

形成一个完整合法答案。

---

## 3. 当前层做什么？

当前层最多有两个选择：

```
选择 '('：
只有 left < n 才能选。

选择 ')'：
只有 right < left 才能选。
```

然后都是标准回溯：

```
做选择
↓
递归
↓
撤销选择
```

对应：

```
path.push_back('(');
backtrack(...);
path.pop_back();
```

或者：

```
path.push_back(')');
backtrack(...);
path.pop_back();
```

---

# ⑦ 为什么不推荐迭代法？

BFS 当然可以。

例如保存状态：

```
struct State {
    string path;
    int left;
    int right;
};
```

然后使用：

```
queue<State>
```

不断扩展 `(` 和 `)`。

但和递归相比：

```
需要显式保存 path
需要保存 left/right
需要队列
代码更长
```

而回溯本身就是在遍历一棵“括号选择树”，非常自然。

所以本题：

> **优先掌握递归回溯，不需要为了迭代而迭代。**

# ⑧ 面试追问

### Q1：为什么 `right < left` 就能保证合法？

因为任何合法括号字符串的任意前缀，都不能出现：

```
右括号比左括号多
```

否则就存在某个 `)` 找不到前面的 `(` 与它匹配。

因此构造过程中始终维持：

```
right <= left
```

最终再保证：

```
left == right == n
```

就一定是合法括号字符串。

---

### Q2：为什么不用最后再检查是否合法？

因为这样会搜索大量注定失败的分支。

本题回溯的核心价值正是：

> **边构造边判断，尽早剪掉非法分支。**

---

### Q3：时间复杂度是多少？

合法括号组合的数量是第 `n` 个 Catalan 数，记作：

```
C_n
```

每个答案长度是：

```
2n
```

因此仅仅输出所有答案就至少需要大约：

```
O(n * C_n)
```

的时间。

面试中不用强行展开 Catalan 公式，知道：

> 搜索规模远小于暴力 `2^(2n)`，实际生成的是所有合法括号组合。

即可。

---

### Q4：如果要求只计算有多少种，而不需要返回字符串呢？

那就没必要枚举所有具体字符串。

可以使用：

```
动态规划
```

得到 Catalan 数。

但当前题要求：

> 返回每个具体括号字符串。

所以回溯更自然。

---

### Q5：这题与电话号码组合有什么共同点？

电话号码组合：

```
每层从当前数字对应字母中选一个
```

括号生成：

```
每层从 '('、')' 中选一个合法的
```

共同模式都是：

> 构造答案 → 当前层选择 → 递归 → 撤销。

区别在于括号生成有更强的**合法性约束/剪枝条件**。

---

## 面试表达

> 我使用回溯。维护当前已经使用的左括号数 `left` 和右括号数 `right`。如果 `left < n`，说明还有左括号可以使用，可以加入一个 `(`；只有当 `right < left` 时才能加入 `)`，因为任意合法括号字符串的前缀中右括号数量都不能超过左括号数量。这样在生成过程中就能剪掉所有非法分支。当 `left == n && right == n` 时，将当前字符串加入答案。这个方法直接枚举所有合法括号组合。

```
22. 括号生成

题型：
回溯 + 剪枝 + 构造合法方案

状态：
path  = 当前括号字符串
left  = 已使用左括号数量
right = 已使用右括号数量

左括号：
left < n
→ 可以加入 '('

右括号：
right < left
→ 可以加入 ')'

为什么：
任意合法前缀必须满足
right <= left

终止：
left == n && right == n

回溯：
加入括号
→ 递归
→ pop_back()
```

把你现在学过的回溯题串起来：

```
46 全排列：

→ used

78 子集：
只向后选
→ startIndex

17 电话号码：
每层处理一个固定数字
→ index

39 组合总和：
只向后选，但当前元素可重复
→ 递归传 i

22 括号生成：
每层选择 '(' 或 ')'

→ left / right + 剪枝
```

**一句话记忆：**

> **左括号没用完就能放；右括号只有比左括号少时才能放。每做一个选择就递归，回来再撤销，这样生成出来的字符串天然全部合法。**
