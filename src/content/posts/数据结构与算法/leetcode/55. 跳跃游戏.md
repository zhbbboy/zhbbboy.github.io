这题最推荐用：

> **贪心（Greedy）+ 维护目前能够到达的最远位置 `maxReach`。**

这题和你刚做的 121 买卖股票有点像：都不是枚举所有方案，而是在遍历过程中只维护一个“对未来最有用的信息”。

---

## ① 破题：题目真正要求什么

例如：

```
nums = [2,3,1,1,4]
```

下标：

```
下标：  0  1  2  3  4
nums： [2, 3, 1, 1, 4]
```

`nums[i]` 表示：

> 站在下标 `i`，最多可以向右跳 `nums[i]` 步。

例如：

```
nums[0] = 2
```

说明从下标 0：

```
可以跳到 1
也可以跳到 2
```

题目不是问：

> 最少跳几步。

而只是问：

> **有没有一种方法能够到达最后一个下标？**

---

# ② 核心技巧：不要真的模拟“我这一跳跳几步”

很多人一开始会想：

```
当前位置0
↓
到底跳1步还是2步？
↓
到了新位置
↓
再决定下一跳
```

这样就开始产生很多选择。

其实这题根本不需要决定：

> “具体跳到哪里”。

我们只需要知道：

> **到目前为止，我最远能够覆盖到哪个下标。**

定义：

```
int maxReach = 0;
```

表示：

> 从已经能够到达的位置出发，目前最远能够到达哪里。

---

# ③ 最关键的公式

如果当前能够到达下标：

```
i
```

那么从这里最多还能跳：

```
nums[i]
```

所以从 `i` 出发最远能到：

```
i + nums[i]
```

因此：

```
maxReach = max(maxReach, i + nums[i]);
```

这就是整道题最核心的一行。

---

# ④ 图解执行过程

看：

```
nums = [2,3,1,1,4]
```

初始化：

```
maxReach = 0;
```

---

### i = 0

当前：

```
i = 0
nums[0] = 2
```

从 0 最远：

```
0 + 2 = 2
```

于是：

```
maxReach = max(0, 2);
```

得到：

```
maxReach = 2
```

意思：

> 目前已经确定，下标 `0、1、2` 都在我的可达范围里面。

注意：

这里不是说：

```
我一定跳到了2
```

而是：

```
0 ~ 2 这些位置我都有能力到达。
```

这一点非常重要。

---

### i = 1

先检查：

```
i = 1
maxReach = 2
```

因为：

```
1 <= 2
```

所以：

> 下标1是能够到达的。

而：

```
nums[1] = 3;
```

从这里最远：

```
1 + 3 = 4
```

所以：

```
maxReach = max(2, 4);
```

得到：

```
maxReach = 4
```

而最后一个下标：

```
n - 1 = 4
```

已经：

```
maxReach >= n - 1
```

所以可以直接：

```
return true;
```

---

# ⑤ 为什么这个方法不需要决定具体怎么跳？

这是这题最重要的思想。

比如：

```
nums = [2,3,1,1,4]
```

我们站在下标0的时候：

```
可以跳到1
也可以跳到2
```

我们没有真的选择。

只是说：

```
现在可达范围 = [0,2]
```

既然：

```
下标1也能到
下标2也能到
```

那么我们遍历到这些位置时，都可以利用它们继续扩展可达范围。

比如下标1特别厉害：

```
nums[1] = 3
```

于是把覆盖范围从：

```
0 ~ 2
```

扩展到：

```
0 ~ 4
```

所以这道题其实是在不断：

> **扩大可达区间。**

---

# ⑥ 什么时候说明走不到了？

看第二个例子：

```
nums = [3,2,1,0,4]
```

下标：

```
下标：  0  1  2  3  4
nums： [3, 2, 1, 0, 4]
```

开始：

```
maxReach = 0
```

### i = 0

```
0 + 3 = 3
```

所以：

```
maxReach = 3
```

目前：

```
0 ~ 3
```

都能到。

---

### i = 1

```
1 + 2 = 3
```

所以：

```
maxReach = 3
```

没有扩大。

---

### i = 2

```
2 + 1 = 3
```

还是：

```
maxReach = 3
```

---

### i = 3

```
nums[3] = 0;
```

所以：

```
3 + 0 = 3
```

还是：

```
maxReach = 3
```

---

接下来准备：

```
i = 4
```

但是：

```
i = 4
maxReach = 3
```

出现：

```
i > maxReach
```

即：

```
4 > 3
```

这是什么意思？

> 当前连下标4本身都到不了。

既然当前位置都到不了，后面的东西自然也没资格使用。

所以：

```
return false;
```

---

# ⑦ 完整代码

我推荐你写这个版本：

```cpp
class Solution {
public:
    bool canJump(vector<int>& nums) {
        int maxReach = 0;

        for (int i = 0; i < nums.size(); ++i) {

            // 当前下标已经超过最大可达范围
            if (i > maxReach) {
                return false;
            }

            // 更新最远可达位置
            maxReach = max(maxReach, i + nums[i]);

            // 已经可以到达最后一个位置
            if (maxReach >= nums.size() - 1) {
                return true;
            }
        }

        return true;
    }
};
```

---

# ⑧ 为什么 `if (i > maxReach)` 就一定失败？

比如：

```
maxReach = 3
```

说明：

```
目前无论怎么跳，最远只能到下标3。
```

但现在循环已经来到：

```
i = 4
```

那么：

```
0 1 2 3 | 4
          ↑
        到不了
```

既然 4 都到不了，你就不能使用：

```
nums[4]
```

提供的跳跃能力。

即使：

```
nums[4] = 100000;
```

也没用。

因为：

> 你根本站不到 4 上。

所以：

```
if (i > maxReach) {
    return false;
}
```

非常关键。

---

# ⑨ `maxReach` 到底表示什么？

不要理解成：

> “我当前站的位置”。

这是错的。

比如：

```
nums = [2,3,1,1,4]
```

第一次处理完：

```
maxReach = 2
```

并不意味着：

```
当前位置 = 2
```

而是：

> **目前所有已经处理过的可达位置，综合起来最多能够覆盖到下标2。**

所以：

```
maxReach
```

应该理解成：

> **可达范围的最右边界。**

可以画成：

```
[2,3,1,1,4]
 0 1 2 3 4

处理完0：

[ 可达区域 ]
0 1 2 | 3 4
      ↑
   maxReach
```

处理下标1之后：

```
0 1 2 3 4
[ 全部可达 ]
        ↑
     maxReach
```

---

# ⑩ 为什么这是贪心？

因为我们每走到一个可以到达的位置：

```
i
```

都只关心：

> 它能不能让我的最远可达位置变得更远？

也就是：

```
maxReach = max(maxReach, i + nums[i]);
```

我们永远保留：

> 当前能够得到的最远覆盖范围。

并不关心具体跳跃路线。

所以属于典型的：

> **贪心维护最优状态。**

---

# ⑪ 为什么不是动态规划？

当然可以写 DP。

例如：

```
dp[i]
```

表示：

> 下标 i 是否能够到达。

然后：

```
dp[0] = true
```

再从每个能到的位置向后标记。

但是容易做到：

```
O(n²)
```

而贪心只需要：

```
O(n)
```

并且只用一个：

```
maxReach
```

所以这题最推荐贪心。

---

# ⑫ 递归是否适合？

不推荐。

你当然可以从下标0开始：

```
跳1步
↓
递归

跳2步
↓
递归

跳3步
↓
递归
```

但会产生大量重复路径。

例如：

```
0 → 1 → 3
0 → 2 → 3
```

很多状态会重复搜索。

而题目实际上只需要知道：

```
最远能覆盖哪里
```

所以：

> **贪心明显优于递归。**

---

# ⑬ 一个很容易错的想法

有的人会写：

```
i += nums[i];
```

也就是：

> 每次都跳最大步数。

这是错的。

例如：

```
nums = [2,3,1,1,4]
```

如果从 0 一定跳最大距离：

```
0 → 2
```

但有些题目中：

> 跳得最远不一定是最好的具体路线。

所以我们不要真正选择：

```
我要跳几步
```

而是维护：

```
所有目前能够到达的位置提供的最大覆盖范围
```

这才是这道题的贪心核心。

---

# ⑭ 面试追问

### 为什么 `maxReach` 可以代表所有可能路径？

因为如果：

```
i <= maxReach
```

说明 `i` 处于之前某条路径能够覆盖到的范围内。

因此 `i` 是一个合法可达位置，我们就可以使用：

```
i + nums[i]
```

继续扩展覆盖范围。

不断取最大：

```
max(maxReach, i + nums[i])
```

最终就包含了所有可能路径能够达到的最远位置。

---

### 时间复杂度？

每个位置最多访问一次：

```
O(n)
```

空间：

```
O(1)
```
