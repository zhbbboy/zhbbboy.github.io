这题最推荐你掌握：

> **快慢指针 + Floyd 判圈算法（Floyd Cycle Detection，弗洛伊德判环）**

**第一次相遇时，由于快指针比慢指针多走了整数圈，可以推出“起点到环入口的距离”和“相遇点继续走到环入口的距离”在环上等价，因此一个回起点、一个留在相遇点，再同速前进，必然在环入口相遇。**

它表面上是“数组找重复数”，实际上可以把数组转换成一个**隐式链表**，然后问题就变成：

> **寻找链表环的入口。**

这题第一次看会比较抽象，我从“为什么数组能变成链表”开始讲。

---

# ① 破题：题目真正要求什么

例如：
```
nums = [1,3,4,2,2]
```

数组长度：
```
5
```

说明：
```
n = 4
```

而数组中的数字范围一定是：
```
1 ~ 4
```

这里：
```
1 出现1次
2 出现2次  ← 重复
3 出现1次
4 出现1次
```

答案：
```
2
```

题目还有两个很重要的限制：
```
不能修改 nums
额外空间必须 O(1)
```

所以：
- 排序：会修改数组，除非复制，但又需要额外空间；
- `unordered_set`：空间 O(n)；
- 下标标记：通常要修改数组。

因此这题真正想考的就是：
> **Floyd 快慢指针。**

---

# ② 最核心：怎么把数组看成链表？

我们定义一个关系：
```
当前位置 i
↓
下一个位置 nums[i]
```

也就是说：
```
next = nums[i];
```

例如：
```
nums = [1,3,4,2,2]
```

我们把：
```
数组下标
```
看成链表节点。

数组：
```
下标：  0  1  2  3  4
nums： [1, 3, 4, 2, 2]
```

那么：
```
0 → nums[0] = 1

1 → nums[1] = 3

3 → nums[3] = 2

2 → nums[2] = 4

4 → nums[4] = 2
```

于是形成：
```
0 → 1 → 3 → 2 → 4
            ↑   ↓
            └───┘
```
也就是：

```
0 → 1 → 3 → 2 → 4
            ↑   |
            └───┘
```

这里：
```
2 → 4 → 2 → 4 → ...
```

形成一个环。

而：

```
环入口 = 2
```

刚好就是重复数字：

```
2
```

这不是巧合，这就是这题的核心。

---

# ③ 为什么重复数字会形成环？

还是：
```
nums = [1,3,4,2,2]
```

注意：
```
nums[3] = 2
nums[4] = 2
```

也就是说两个不同的下标：
```
3
4
```

都指向：
```
2
```

画出来：

```
3 ──→ 2
      ↑
4 ───┘
```

这就是“重复”的真正含义：

> **存在两个不同的位置，指向同一个下标。**

在这种每个节点只有一个“下一节点”的结构中，最终必然形成环。
**因为节点有限 + 每个节点只有一个 next + 一直往下走 ⇒ 必然重复访问某个节点 ⇒ 一旦重复就形成环。**

---

# ④ 为什么一定有重复数？

题目有：
```
n + 1 个数字
```

但是每个数字只能取：
```
1 ~ n
```
也就是只有：
```
n 种可能
```
例如：
```
5 个数字
```
只能放：
```
1、2、3、4
```
四种值。

就算：
```
1
2
3
4
```
都各出现一次，
第 5 个数字也必须重复其中一个。

这就是：
> **Pigeonhole Principle（鸽巢原理 / 抽屉原理）**

所以题目保证至少存在重复。

---

# ⑤ Floyd 快慢指针第一阶段：先找到环内相遇点
有环以后，就和之前链表判环完全一样。

准备：
```
int slow = nums[0];
int fast = nums[0];
```
然后：
```
slow = nums[slow];
```
慢指针每次走一步。

而：
```
fast = nums[nums[fast]];
```
快指针每次走两步。

---

## 用 `[1,3,4,2,2]` 跑一遍
关系：
```
0 → 1 → 3 → 2 → 4 → 2 → 4 → ...
```
初始化：
```
slow = 1
fast = 1
```

---
### 第一次移动
慢指针：
```
slow = nums[1] = 3;
```
所以：
```
slow = 3
```
快指针：
```
fast = nums[nums[1]];
```
先：
```
nums[1] = 3
```
再：
```
nums[3] = 2
```
所以：
```
fast = 2
```
现在：
```
slow = 3
fast = 2
```

没有相遇。

---

### 第二次移动

慢：

```
slow = nums[3];
```

得到：

```
slow = 2
```

快：

```
fast = nums[nums[2]];
```

先：

```
nums[2] = 4
```

再：

```
nums[4] = 2
```

所以：

```
fast = 2
```

这时候：

```
slow == fast == 2
```

相遇。

但是注意：

> **第一次相遇的位置不一定就是环入口。**

这个例子碰巧相遇在 2，但一般不能直接返回。

所以还需要第二阶段。

---

# ⑥ 第二阶段：找到环入口

第一阶段相遇以后：

```
slow == fast
```

我们让其中一个指针重新回到起点：

```
slow = nums[0];
```

或者更常见另一套写法直接把一个指针设为 `0`，取决于第一阶段初始化方式。

然后两个指针：

> **每次都只走一步。**

最终它们再次相遇的位置，就是：

> **环入口，也就是重复数字。**

为了让逻辑更统一，我推荐你直接从下标 `0` 开始：

```
int slow = 0;
int fast = 0;
```

第一阶段：

```
do {
    slow = nums[slow];
    fast = nums[nums[fast]];
} while (slow != fast);
```

然后：

```
slow = 0;
```

第二阶段：

```
while (slow != fast) {
    slow = nums[slow];
    fast = nums[fast];
}
```

最后：

```
return slow;
```

---

# ⑦ 用完整例子跑第二阶段

还是：

```
0 → 1 → 3 → 2 → 4
              ↑     ↓
              └─────┘
```

第一阶段某处相遇。

然后：

```
slow 回到 0
fast 留在相遇点
```

接下来二者每次都走一步。

最终一定会在：

```
2
```

相遇。

因为：

```
2
```

就是环入口。

所以：

```
return 2;
```

# ⑧ 为什么环入口一定就是重复数字？

这是本题最重要的理解。

假设：

```
nums[a] = x
nums[b] = x
```

其中：

```
a != b
```

那么在我们构造的“链表”里：

```
a → x
b → x
```

两个不同节点都指向 `x`。

这意味着：

```
x
```

就是第一次发生路径汇合的位置。

由于后面每个节点只有唯一的下一跳：

```
x → nums[x] → ...
```

路径继续走以后一定会进入循环。

所以：

> **重复值 x 对应环的入口。**

注意不是：

```
重复数字所在的下标
```

而是：

```
重复的数字本身
```

因为数字本身被拿来当作“下一节点的下标”。

# ⑨ 完整代码

我推荐你记这一版：

```cpp
class Solution {
public:
    int findDuplicate(vector<int>& nums) {
        int slow = 0;
        int fast = 0;

        // 第一阶段：快慢指针在环内相遇
        do {
            slow = nums[slow];
            fast = nums[nums[fast]];
        } while (slow != fast);

        // 第二阶段：寻找环入口
        slow = 0;

        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }

        return slow;
    }
};
```

# ⑩ 最难看懂的一行

```
fast = nums[nums[fast]];
```

很多人第一次会觉得很绕。

拆开：

```
int firstStep = nums[fast];
```

表示快指针走一步。

然后：

```
int secondStep = nums[firstStep];
```

表示再走一步。

所以：

```
fast = secondStep;
```

合并就是：

```
fast = nums[nums[fast]];
```

也就是：

> fast 每次沿着 `i → nums[i]` 走两步。

而：

```
slow = nums[slow];
```

只走一步。

# ⑪ 为什么不会数组越界？

这个细节很好。

数组长度：

```
n + 1
```

所以合法下标：

```
0 ~ n
```

而题目保证：

```
1 <= nums[i] <= n
```

所以：

```
nums[slow]
```

得到的值一定在：

```
1 ~ n
```

它继续拿来当下标一定合法。

同理：

```
nums[nums[fast]]
```

也一定合法。

所以这里不需要像链表一样判断：

```
fast != nullptr
fast->next != nullptr
```

---

# ⑫ 为什么从 0 开始特别方便？

你可能注意到：

```
nums 中没有 0
```

因为所有值都是：

```
1 ~ n
```

所以：

```
下标0
```

很适合作为链表起点：

```
0 → nums[0] → nums[nums[0]] → ...
```

而不会有其他节点通过数组值指回 0。

所以结构可以理解成：

```
0
↓
一条链
↓
进入某个环
```

非常符合 Floyd 判圈模型。

# ⑬ 为什么不能直接用 XOR？

你前面刚做过：

```
136. 只出现一次的数字
```

可能会想到异或。

但这里不行。

136 的条件是：

```
除了一个数出现一次
其他数都恰好出现两次
```

所以：

```
x ^ x = 0
```

能抵消。

但这题例如：

```
[3,3,3,3,3]
```

重复数字：

```
3
```

可能出现很多次。

而且其他数字甚至可能没有完整出现。

所以 XOR 没办法利用固定配对关系。

---

# ⑭ 为什么不能直接二分数组下标？

其实这题还有一个：

> **值域二分 + 鸽巢原理**

的解法，时间：

```
O(n log n)
```

空间：

```
O(1)
```

也不修改数组。

但是题目进阶问能不能做到：

```
O(n)
```

Floyd 可以：

```
时间 O(n)
空间 O(1)
```

所以这题主学 Floyd。

不适合。

这是典型的：

```
隐式链表
+
快慢指针
```

迭代是最自然的。

# ⑰ 面试追问：为什么第二阶段能找到入口？

这个问题是 Floyd 算法经典证明。

你现阶段不一定要背完整数学推导，但要知道结论：

假设：

```
起点到环入口距离 = a
环入口到第一次相遇点距离 = b
环长 = L
```

第一次相遇时：

```
slow走的距离 = a + b
```

fast 走的距离是 slow 的两倍：

```
2(a+b)
```

而 fast 比 slow 多绕了若干圈：

```
2(a+b) - (a+b) = kL
```

所以：

```
a + b = kL
```

于是：

```
a = kL - b
```

而：

```
L - b
```

正好是从相遇点继续走到环入口的距离。

所以：

> 一个指针从起点走 `a` 步，另一个从相遇点走 `a` 步，最终一定会在环入口相遇。

这就是第二阶段为什么成立。
