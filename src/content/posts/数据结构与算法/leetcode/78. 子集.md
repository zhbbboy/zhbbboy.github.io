这道题最适合使用：
> **主方法：回溯 + `startIndex`。**

迭代法也很适合，而且思路非常直观：
> 每加入一个新元素，就把现有的所有子集复制一遍，并在复制结果中加入这个元素。

因此这题递归和迭代两种方法都值得掌握。面试中通常优先写回溯法，因为它能迁移到组合、子集去重、组合总和等大量题目。

---
# ① 破题：题目真正要求什么

给定一个不含重复元素的数组：
```cpp
nums = {1, 2, 3};
```
要求返回它的所有子集：
```text
[]
[1]
[2]
[3]
[1,2]
[1,3]
[2,3]
[1,2,3]
```
这里有三个重要特点。
## 1. 空集也属于子集

所以答案中一定包含：
```cpp
[]
```

## 2. 子集不要求使用所有元素
这和上一题“全排列”不同。

全排列要求：
```text
每个结果必须使用所有数字
```

子集则可以使用：
```text
0 个、1 个、2 个……直到 n 个数字
```

## 3. 子集不考虑排列顺序

例如：
```text
[1,2]
[2,1]
```
在子集问题中，它们表示同一个集合，只能出现一次。

因此我们要避免生成：
```text
先选 1 再选 2
先选 2 再选 1
```
这两条重复路径。

---
# ② 核心技巧：每一个递归节点都是答案

全排列的终止条件是：
```cpp
path.size() == nums.size()
```
因为必须使用全部数字，才是一个完整排列。

但子集不同。

例如：
```text
[]
[1]
[1,2]
[1,2,3]
```
这些全部都是合法子集。

所以子集回溯中：
> 每进入一次递归函数，当前 `path` 就是一个合法答案，应立即加入 `result`。

代码结构：
```cpp
void backtrack(...) {
    result.push_back(path);

    for (...) {
        做选择;
        backtrack(...);
        撤销选择;
    }
}
```

---
## 为什么需要 `startIndex`？

假设数组是：
```cpp
[1,2,3]
```
如果当前已经选择了 `2`，后面只能考虑 `3`，不能再回头选择 `1`。

否则会同时产生：
```text
[1,2]
[2,1]
```
造成重复。

所以定义：
```cpp
startIndex
```

表示：
> 当前这一层只能从数组的哪个下标开始继续选择。

选择 `nums[i]` 后，下一层从：
```cpp
i + 1
```

开始：
```cpp
backtrack(nums, i + 1);
```

这样每个子集中的下标始终递增，不会生成重复顺序。

和全排列相比，最明显的区别是：
> 子集问题中，树上的每一个节点都是答案，而不只是叶子节点。

# 解题思路

# ④ 完整代码：回溯法

```cpp
class Solution {
private:
    vector<vector<int>> result;
    vector<int> path;

    void backtrack(const vector<int>& nums, int startIndex) {
        // 当前 path 本身就是一个合法子集
        result.push_back(path);

        // 从 startIndex 开始选择，避免重复子集
        for (int i = startIndex; i < nums.size(); ++i) {
            // 做选择
            path.push_back(nums[i]);

            // 下一层只能选择当前位置之后的数字
            backtrack(nums, i + 1);

            // 撤销选择
            path.pop_back();
        }
    }

public:
    vector<vector<int>> subsets(vector<int>& nums) {
        backtrack(nums, 0);
        return result;
    }
};
```

---

# ⑤ 关键设计解释

## 1. 为什么一进入递归就保存 `path`？

```cpp
result.push_back(path);
```

因为任意长度的 `path` 都是合法子集。

例如：

```text
path = []        合法
path = [1]       合法
path = [1,2]     合法
path = [1,2,3]   合法
```

因此不能只在叶子节点保存。

---

## 2. 空集是在哪里加入答案的？

第一次调用：

```cpp
backtrack(nums, 0);
```

此时：

```text
path = []
```

函数一开始执行：

```cpp
result.push_back(path);
```

于是空集就自动被加入答案。

不需要单独写：

```cpp
result.push_back({});
```

---

## 3. 为什么不用 `used` 数组？

全排列需要 `used`，因为每一层都可能从所有数字中选择：

```text
第一个位置选 2 后，
第二个位置仍然可以选择 1
```

所以要记录哪些数字已经使用。

但子集中，我们规定下标只能向后走：

```cpp
backtrack(nums, i + 1);
```

选择过的元素以及它前面的元素都不会再次被访问。

因此不需要 `used` 数组。

---

## 4. 为什么循环从 `startIndex` 开始？

```cpp
for (int i = startIndex; i < nums.size(); ++i)
```

假设当前选择了下标 `1` 的数字 `2`。

下一层：

```cpp
startIndex = 2
```

只能继续选择后面的 `3`，不会重新选择 `1`。

这样只生成：

```text
[1,2]
```

不会再生成：

```text
[2,1]
```

---

## 5. 为什么递归传 `i + 1`，不是 `startIndex + 1`？

正确：

```cpp
backtrack(nums, i + 1);
```

因为下一层应该从“本次实际选择的位置”之后开始。

假设：

```text
startIndex = 0
```

但循环本次选择的是：

```text
i = 2
```

也就是数字 `3`。

那么下一层应该从：

```text
3
```

开始，而不是从：

```text
startIndex + 1 = 1
```

开始。

否则可能回头选择下标更小的元素，产生重复或错误。

---
## 6. 为什么没有显式终止条件？

这份代码没有写：

```cpp
if (...) return;
```
因为当：
```cpp
startIndex == nums.size()
```
时，循环自然不会执行：
```cpp
for (int i = startIndex; i < nums.size(); ++i)
```
函数会自动结束。

所以循环边界本身就承担了终止条件。

当然也可以显式写：
```cpp
if (startIndex == nums.size()) {
    return;
}
```

但没有必要。

---
## 7. 为什么只需要 `path.pop_back()`？

本题没有 `used` 数组，所以状态只有：

```cpp
path
```

做选择：
```cpp
path.push_back(nums[i]);
```

撤销选择：
```cpp
path.pop_back();
```

恢复到进入当前分支之前的状态即可。

---

# ⑥ 递归三要素

## 1. 递归函数定义

```cpp
backtrack(nums, startIndex)
```

表示：

> 在当前 `path` 的基础上，只从 `nums[startIndex...]` 中继续选择元素，生成所有可能的子集。

---

## 2. 终止条件

本题通过循环自然终止。

当：

```text
startIndex == nums.size()
```

已经没有元素可以继续选择，循环不执行，函数返回。

而当前 `path` 已经在函数开头记录过。

---

## 3. 当前层做什么？

当前层负责：

> 从 `startIndex` 开始，尝试选择一个元素作为当前子集的下一个元素。

流程：

```text
1. 先保存当前 path。
2. 从 startIndex 开始遍历候选元素。
3. 将 nums[i] 加入 path。
4. 递归从 i + 1 开始继续选择。
5. 删除 nums[i]，恢复现场。
6. 尝试下一个元素。
```

---

# ⑦ 迭代写法

这题的迭代法也非常值得掌握。

核心思想：
> 每加入一个新数字，都基于当前已有的所有子集，生成一批包含该数字的新子集。

以：
```cpp
nums = [1,2,3]
```
为例。

初始只有空集：
```text
result = [[]]
```

处理数字 `1`：
```text
旧子集：[]
新子集：[1]
```

得到：

```text
[[], [1]]
```

处理数字 `2`：

```text
旧子集：[]、[1]

分别添加 2：
[2]、[1,2]
```

得到：

```text
[[], [1], [2], [1,2]]
```

处理数字 `3`：

```text
旧子集：
[]、[1]、[2]、[1,2]

添加 3：
[3]、[1,3]、[2,3]、[1,2,3]
```

最终得到所有子集。

---
## 完整迭代代码

```cpp
class Solution {
public:
    vector<vector<int>> subsets(vector<int>& nums) {
        vector<vector<int>> result = {{}};

        for (int num : nums) {
            int currentSize = result.size();

            // 只遍历加入 num 之前已经存在的子集
            for (int i = 0; i < currentSize; ++i) {
                vector<int> newSubset = result[i];
                newSubset.push_back(num);
                result.push_back(newSubset);
            }
        }

        return result;
    }
};
```

---

## 为什么必须提前保存 `currentSize`？

```cpp
int currentSize = result.size();
```

因为循环过程中：

```cpp
result.push_back(newSubset);
```

会不断增加 `result.size()`。

如果写成：

```cpp
for (int i = 0; i < result.size(); ++i)
```

那么刚刚生成的新子集还会在当前轮继续被处理，可能重复添加当前数字。

例如处理 `1` 时：

```text
[] → [1]
```

如果继续遍历新加入的 `[1]`，又会生成：

```text
[1,1]
```

这是错误的。

所以当前轮只能遍历“加入这个数字之前已有的子集”。

# ⑧ 面试追问

## Q1：全排列和子集的回溯区别是什么？

### 全排列
```text
每一层决定一个位置放哪个数字
每个结果必须使用全部数字
每层都从 0 开始扫描
需要 used 数组
只在叶子节点保存答案
```

### 子集
```text
每个元素可以选，也可以不选
任意长度都是答案
使用 startIndex 保证只向后选择
不需要 used 数组
每个递归节点都保存答案
```

---
## Q2：为什么子集数量是 `2^n`？

每个元素只有两种状态：
```text
选择
不选择
```
一共有 `n` 个元素，因此方案数：
```text
2 × 2 × ... × 2 = 2^n
```
例如 `n = 3`：
```text
2^3 = 8
```
正好有 8 个子集。

---
## Q3：时间复杂度是多少？

一共有：
```text
2^n
```
个子集。
把每个子集复制到答案中，最坏需要复制 `O(n)` 个元素。
所以总时间复杂度：
```text
O(n × 2^n)
```

---

## Q4：空间复杂度是多少？
不计算最终答案：
```text
path 最长 O(n)
递归栈深度 O(n)
```
辅助空间：
```text
O(n)
```
如果计算输出结果，则需要：
```text
O(n × 2^n)
```
保存所有子集。

---

## Q5：如果数组有重复元素怎么办？

当前题目保证所有元素互不相同。

如果：

```cpp
nums = {1,2,2};
```

需要先排序，并在同一递归层跳过重复值：

```cpp
if (i > startIndex && nums[i] == nums[i - 1]) {
    continue;
}
```

这对应 LeetCode 90“子集 II”。

---

## 面试表达

> 我使用回溯算法。`path` 表示当前子集，`startIndex` 表示下一层只能从哪个位置开始选择。由于任意长度的 `path` 都是合法子集，所以每次进入递归函数时都先将当前 `path` 加入答案。然后从 `startIndex` 开始枚举元素，将当前元素加入 `path`，递归时传入 `i + 1`，保证后续只向后选择，从而避免生成 `[1,2]` 和 `[2,1]` 这样的重复集合；递归返回后撤销选择。总时间复杂度是 `O(n·2^n)`。

# ⑨ 复习总结

```text
78. 子集

题型：
回溯 + 子集问题。

核心变量：
result：所有子集。
path：当前子集。
startIndex：下一层从哪个下标开始选择。

核心区别：
子集中的任意 path 都是合法答案，
所以每次进入递归都保存 path。

流程：
1. result.push_back(path)。
2. 从 startIndex 开始遍历。
3. path.push_back(nums[i])。
4. 递归 backtrack(nums, i + 1)。
5. path.pop_back() 回溯。

为什么不用 used：
下标始终向后移动，不会重复选择前面的元素。

为什么使用 startIndex：
避免同时生成 [1,2] 和 [2,1]。
```

全排列和子集对比记忆：

```text
全排列：
每层从头选，used 防止同一元素重复使用，
叶子节点才是答案。

子集：
每层只向后选，startIndex 防止顺序重复，
每个递归节点都是答案。
```

一句话记忆：

> **子集问题中，每个递归节点都是一个答案；用 `startIndex` 保证元素只向后选择。**
