这道题最适合使用：
> **Trie 节点 + 迭代遍历字符串。**

本题不是搜索整棵树，而是按照字符串中的字符顺序，一层一层沿对应分支向下走，所以迭代写法最自然。递归不会简化逻辑，反而会增加调用栈，因此不专门写递归版本。

---
## ① 破题：题目真正要求什么

需要实现一个支持三种操作的数据结构：
```cpp
insert(word);       // 插入完整单词
search(word);       // 查询完整单词是否存在
startsWith(prefix); // 查询某个前缀是否存在
```

关键区别是：
```text
search("app")
```
要求 `"app"` 本身已经被插入过。

而：
```text
startsWith("app")
```
只要求存在某个以 `"app"` 开头的单词，例如：
```text
apple
application
apply
```

---
## ② 核心技巧：公共前缀共享路径

假设插入三个单词：
```text
apple
app
apply
```
Trie 不会分别完整存储三份字符串，而是共享公共前缀：
```text
root
  |
  a
  |
  p
  |
  p  ← app 在这里结束
 / \
l   l
|   |
e   y
↑   ↑
apple apply
结束 结束
```
更准确地说：
```text
root
  └── a
       └── p
            └── p  [isEnd = true，表示 app]
                 └── l
                      ├── e [isEnd = true，表示 apple]
                      └── y [isEnd = true，表示 apply]
```
每个 Trie 节点主要保存两类信息：
```cpp
TrieNode* children[26];
bool isEnd;
```
### `children[26]`
表示当前字符之后，可以接哪些小写字母。
```text
children[0]  对应 'a'
children[1]  对应 'b'
...
children[25] 对应 'z'
```
### `isEnd`
表示：
> 从根节点走到当前节点时，是否正好形成一个已经插入过的完整单词。

这是区分 `search()` 和 `startsWith()` 的关键。

## ③ 图解执行过程

以题目中的操作为例。
### 第一步：创建 Trie

```cpp
Trie trie;
```
初始只有一个虚拟根节点：
```text
root
```
根节点不表示任何字符，它只是所有单词的起点。

---
### 第二步：插入 `"apple"`
依次处理字符：
```text
a → p → p → l → e
```
开始时：
```text
root
```
处理 `'a'`，没有对应节点，就创建：
```text
root
  └── a
```
处理第一个 `'p'`：
```text
root
  └── a
       └── p
```
继续创建：
```text
root
  └── a
       └── p
            └── p
                 └── l
                      └── e
```
字符串处理完后，将最后的 `e` 节点标记为单词结尾：
```text
e.isEnd = true
```

---
### 第三步：查询 `"apple"`
从根节点依次查找：
```text
a → p → p → l → e
```
每个字符对应的节点都存在，并且最后：
```text
e.isEnd == true
```
因此：
```cpp
search("apple") == true
```

---
### 第四步：查询 `"app"`

查找路径：
```text
a → p → p
```
路径确实存在，因为 `"apple"` 包含这个前缀。
但是此时第三个字符节点 `p` 还没有被标记为单词结尾：
```text
p.isEnd == false
```
因此：
```cpp
search("app") == false
```
这说明：

> `"app"` 是已存单词的前缀，但还不是一个被完整插入过的单词。

---
### 第五步：查询前缀 `"app"`

`startsWith()` 只需要确认路径存在：
```text
a → p → p
```
不要求最后节点的 `isEnd` 为 `true`。

因此：
```cpp
startsWith("app") == true
```

---
### 第六步：插入 `"app"`
这次沿着：
```text
a → p → p
```
走时，所有节点都已经存在，不需要创建新节点。
只需要把最后一个 `p` 标记为：
```cpp
p.isEnd = true;
```
以后：
```cpp
search("app") == true
```

## 解题思路

## ④ 完整代码

```cpp
class Trie {
private:
    struct TrieNode {
        // children[i] 表示当前节点是否有字符 'a' + i 的分支
        TrieNode* children[26];

        // 是否有一个完整单词在当前节点结束
        bool isEnd;

        TrieNode() : isEnd(false) {
            for (int i = 0; i < 26; ++i) {
                children[i] = nullptr;
            }
        }
    };

    // 虚拟根节点，不表示具体字符
    TrieNode* root;

public:
    Trie() {
        root = new TrieNode();
    }

    void insert(string word) {
        TrieNode* current = root;

        for (char ch : word) {
            int index = ch - 'a';

            // 对应字符的分支不存在，就创建节点
            if (current->children[index] == nullptr) {
                current->children[index] = new TrieNode();
            }

            // 进入下一层
            current = current->children[index];
        }

        // 整个单词处理结束，标记完整单词结尾
        current->isEnd = true;
    }

    bool search(string word) {
        TrieNode* current = root;

        for (char ch : word) {
            int index = ch - 'a';

            // 中间某个字符路径不存在，单词一定不存在
            if (current->children[index] == nullptr) {
                return false;
            }

            current = current->children[index];
        }

        // 路径存在还不够，必须确实是完整单词结尾
        return current->isEnd;
    }

    bool startsWith(string prefix) {
        TrieNode* current = root;

        for (char ch : prefix) {
            int index = ch - 'a';

            if (current->children[index] == nullptr) {
                return false;
            }

            current = current->children[index];
        }

        // 前缀只要求路径存在，不要求 isEnd
        return true;
    }
};
```

---

## ⑤ 关键设计解释

### 1. 为什么需要虚拟根节点？

```cpp
root = new TrieNode();
```

根节点不保存具体字符，只作为所有字符串的统一起点。
插入：
```text
apple
banana
cat
```
都会从 `root` 出发：
```text
       root
      /  |  \
     a   b   c
```

这样不用为第一个字符做特殊处理。

---

### 2. `ch - 'a'` 是什么意思？
题目保证字符串只包含小写英文字母。
字符在编码中是连续排列的，因此：
```cpp
'a' - 'a' == 0
'b' - 'a' == 1
'c' - 'a' == 2
...
'z' - 'a' == 25
```
所以：
```cpp
int index = ch - 'a';
```
可以把字符转换为数组下标。

例如：
```cpp
char ch = 'c';
int index = ch - 'a'; // 2
```
于是：
```cpp
children[2]
```
就表示字符 `'c'` 对应的分支。

---

### 3. 为什么节点不需要保存自己的字符？

你可能会想到：
```cpp
struct TrieNode {
    char ch;
};
```
但本题实际上不需要。

因为字符信息已经体现在父节点的数组下标中：
```cpp
parent->children[0]  // 这条边表示 'a'
parent->children[1]  // 这条边表示 'b'
```
所以节点本身不用再重复保存字符。

---
### 4. 为什么一定要有 `isEnd`？

假设只插入：
```text
apple
```
那么路径：
```text
a → p → p
```
已经存在。
如果没有 `isEnd`，查询 `"app"` 时，只看到路径存在，就会错误返回 `true`。

但题目要求：
```cpp
search("app") == false
startsWith("app") == true
```
因此必须用：
```cpp
bool isEnd;
```
区分：
```text
路径存在
```
和：
```text
完整单词存在
```

---

### 5. `search()` 和 `startsWith()` 的区别在哪里？

两个函数遍历路径的逻辑几乎完全一样。
区别只在最后：
```cpp
bool search(string word) {
    // 路径查找……
    return current->isEnd;
}
```
而：
```cpp
bool startsWith(string prefix) {
    // 路径查找……
    return true;
}
```
也就是：
```text
search：
路径存在 + 最后节点是单词结尾。

startsWith：
路径存在即可。
```

---
### 6. 插入已有前缀时会发生什么？

先插入：
```text
apple
```
再插入：
```text
app
```
插入 `"app"` 时：
```text
a、p、p 节点已经存在
```
所以不创建新节点，只执行：
```cpp
current->isEnd = true;
```
这就是 Trie 节省公共前缀空间的体现。

---

### 7. 重复插入同一个单词会有问题吗？

不会。

例如连续两次：
```cpp
insert("apple");
insert("apple");
```
第二次只是再次执行：
```cpp
current->isEnd = true;
```
结构不会重复创建。
这道题只需要判断是否存在，不需要统计单词出现次数。
如果题目要求统计插入次数，就需要额外维护：
```cpp
int endCount;
```

---

## ⑥ 为什么本题不推荐递归？

每个操作都是按照字符串顺序处理：
```text
word[0] → word[1] → word[2] → ...
```
这本质上就是一个简单的线性循环。

虽然可以递归写成：
```cpp
insert(node, word, index);
```
但递归不会简化逻辑，还会增加：
```text
函数调用栈
递归参数
边界处理
```
所以本题直接使用迭代最清楚。

---

## ⑦ 可以提取公共查询函数

你会发现 `search()` 和 `startsWith()` 有大量重复代码。
可以写一个辅助函数，返回前缀最后对应的节点：
```cpp
class Trie {
private:
    struct TrieNode {
        TrieNode* children[26]{};
        bool isEnd = false;
    };

    TrieNode* root;

    TrieNode* findNode(const string& text) {
        TrieNode* current = root;

        for (char ch : text) {
            int index = ch - 'a';

            if (current->children[index] == nullptr) {
                return nullptr;
            }

            current = current->children[index];
        }

        return current;
    }

public:
    Trie() {
        root = new TrieNode();
    }

    void insert(string word) {
        TrieNode* current = root;

        for (char ch : word) {
            int index = ch - 'a';

            if (current->children[index] == nullptr) {
                current->children[index] = new TrieNode();
            }

            current = current->children[index];
        }

        current->isEnd = true;
    }

    bool search(string word) {
        TrieNode* node = findNode(word);

        return node != nullptr && node->isEnd;
    }

    bool startsWith(string prefix) {
        return findNode(prefix) != nullptr;
    }
};
```
这个版本减少了重复代码，但第一次学习时，前一个展开版更容易理解。

## ⑧ 面试追问

### Q1：Trie 相比哈希表有什么优势？
哈希表也能快速判断完整单词是否存在：
```cpp
unordered_set<string> words;
```
但是判断前缀时不方便。

例如查询：
```cpp
startsWith("app")
```
普通哈希表无法直接知道是否存在：
```text
apple
application
apply
```
Trie 天然按照前缀组织字符串，因此特别适合：
```text
前缀查询
搜索提示
自动补全
拼写检查
词频统计
敏感词匹配
```

---
### Q2：时间复杂度是多少？

设字符串长度为 `L`。
插入：
```text
O(L)
```
查询完整单词：
```text
O(L)
```
查询前缀：
```text
O(L)
```
因为每个字符只处理一次。

---

### Q3：空间复杂度是多少？

最坏情况下，不同单词几乎没有公共前缀，每个字符都需要一个节点。
因此总空间复杂度可以表示为：
```text
O(所有插入字符串的字符总数 × 字符集大小)
```
当前每个节点都有：
```cpp
TrieNode* children[26];
```
即使很多指针为空，也要占用 26 个指针的空间。
优点是访问字符分支非常快：
```text
O(1)
```

---

### Q4：为什么不用 `unordered_map<char, TrieNode*>`？

也可以：
```cpp
unordered_map<char, TrieNode*> children;
```
两种方案对比：
```text
固定数组 children[26]：
查询快，实现简单；
但每个节点都固定保存 26 个指针，可能浪费空间。

unordered_map：
只保存实际存在的分支，字符集大时更节省；
但哈希表本身也有额外开销，访问常数更大。
```
题目只有 26 个小写字母，因此数组方案最常见。

---
### Q5：怎么实现删除单词？

基础思路是：
1. 先确认单词存在；
2. 将最后节点的 `isEnd` 设为 `false`；
3. 从后往前删除那些：
    - 没有孩子；
    - 也不是其他单词结尾的节点。

不能直接删除公共前缀节点。

例如 Trie 中同时有：
```text
app
apple
```
删除 `"apple"` 时，不能删除前面的：
```text
a → p → p
```
因为 `"app"` 还需要这些节点。

---

### 面试表达
> Trie 是一种按照字符逐层组织字符串的树形结构，相同前缀会共享节点。每个节点维护 26 个子节点指针，并使用 `isEnd` 标记当前路径是否形成完整单词。插入时逐字符向下查找，不存在的节点就创建；查询完整单词时，除了要求路径存在，还要求最后节点的 `isEnd` 为真；前缀查询只要求路径存在。三个操作的时间复杂度都是 `O(L)`，其中 `L` 是字符串长度。

## ⑨ 复习总结
```text
208. 实现 Trie

题型：
字符串数据结构设计。

Trie 结构：
每个节点包含：
1. children[26]：下一层字符分支。
2. isEnd：是否有完整单词在此结束。

字符转下标：
index = ch - 'a'

insert：
1. 从 root 出发。
2. 逐个处理字符。
3. 分支不存在就创建。
4. 移动到对应子节点。
5. 最后将 isEnd 设为 true。

search：
1. 查找完整路径。
2. 中间不存在，返回 false。
3. 路径存在后检查 isEnd。

startsWith：
1. 查找完整前缀路径。
2. 路径存在就返回 true。
3. 不要求 isEnd。
```

一句话记忆：
> **Trie 用路径表示字符串、共享公共前缀；`isEnd` 用来区分“前缀存在”和“完整单词存在”。**
