这题最推荐的方法就是：

> **二分查找 + 判断哪一半是有序区间。**

它和普通二分最大的区别只有一点：

> 数组虽然整体不再有序，但每次取 `mid` 后，**左半边和右半边至少有一边一定是有序的**。

只要先判断哪一边有序，再判断 `target` 是否落在这个有序区间里，就能继续二分。

---

## ① 破题：题目真正要求什么

原数组本来严格递增，例如：

```
[0,1,2,4,5,6,7]
```

旋转以后可能变成：

```
[4,5,6,7,0,1,2]
```

现在要求：

```
target = 0
```

返回它的下标：

```
4
```

并且题目要求：

```
O(log n)
```

所以不能从头到尾遍历，必须二分。

---

# ② 核心技巧：mid 两边一定至少有一边有序

例如：

```
nums = [4,5,6,7,0,1,2]

下标   0 1 2 3 4 5 6
值     4 5 6 7 0 1 2
```

第一次：

```
left = 0;
right = 6;

mid = 3;
nums[mid] = 7;
```

现在：

```
左半边：

4 5 6 7
↑     ↑
left mid
```

是有序的。

右边：

```
7 0 1 2
```

发生了旋转。

所以我们可以利用：

```
nums[left] <= nums[mid]
```

判断：

> 左半边是有序的。

如果这个条件不成立，那么右半边一定有序。

---

# ③ 图解执行过程

用题目例子：

```
nums = [4,5,6,7,0,1,2]
target = 0
```

第一次：

```
left              right
 ↓                   ↓
[4, 5, 6, 7, 0, 1, 2]
          ↑
         mid
```

所以：

```
nums[left] = 4;
nums[mid] = 7;
```

满足：

```
nums[left] <= nums[mid]
```

说明左边：

```
[4,5,6,7]
```

有序。

接下来问：

> `target = 0` 在不在 `[4,7)` 里面？

显然：

```
4 <= 0 < 7
```

不成立。

所以 target 一定不在左边。

直接：

```
left = mid + 1;
```

现在：

```
[0,1,2]
 ↑   ↑
 L   R
```

---

第二次：

```
left = 4
right = 6

mid = 5

nums[mid] = 1
```

也就是：

```
0 1 2
↑ ↑ ↑
L M R
```

此时：

```
nums[left] <= nums[mid]
```

即：

```
0 <= 1
```

成立。

左半边：

```
[0,1]
```

有序。

现在判断 target：

```
nums[left] <= target && target < nums[mid]
```

代入：

```
0 <= 0 && 0 < 1
```

成立。

说明 target 在左半边。

所以：

```
right = mid - 1;
```

变成：

```
left = 4
right = 4
```

第三次：

```
mid = 4;
nums[mid] = 0;
```

于是：

```
return 4;
```

# ④ 完整代码

```cpp
class Solution {
public:
    int search(vector<int>& nums, int target) {
        int left = 0;
        int right = nums.size() - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            // 找到目标
            if (nums[mid] == target) {
                return mid;
            }

            // 左半边有序
            if (nums[left] <= nums[mid]) {

                // target 在左边的有序区间内
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;
                }
                else {
                    left = mid + 1;
                }
            }

            // 否则右半边有序
            else {

                // target 在右边的有序区间内
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;
                }
                else {
                    right = mid - 1;
                }
            }
        }

        return -1;
    }
};
```

# ⑤ 关键设计解释

## 为什么 `nums[left] <= nums[mid]` 能判断左边有序？

因为数组只进行过一次旋转。

假设：

```
[4,5,6,7,0,1,2]
```

如果：

```
nums[left] <= nums[mid]
```

说明从 `left` 到 `mid` 这一段没有经过旋转断点。

例如：

```
4 5 6 7
↑     ↑
L     M
```

所以它一定递增。

反过来，如果：

```
nums[left] > nums[mid]
```

例如：

```
6 7 0 1
↑     ↑
L     M
```

说明旋转点就在左半边。

那么右半边：

```
1 2 ...
```

一定是有序的。

因此每轮一定可以确定一边。

---

## 为什么判断左区间是：

```
nums[left] <= target && target < nums[mid]
```

因为我们已经知道：

```
nums[left] ... nums[mid]
```

是递增的。

所以 target 如果满足：

```
nums[left] <= target < nums[mid]
```

它一定应该在左边。

例如：

```
4 5 6 7
↑     ↑
L     M

target = 5
```

满足：

```
4 <= 5 < 7
```

所以继续搜索左边。

---

## 为什么一边用 `<=`，另一边用 `<`？

因为：

```
nums[mid] == target
```

已经在最前面单独判断过了：

```
if (nums[mid] == target) {
    return mid;
}
```

所以后面判断区间时，可以把 `mid` 排除。

于是左边写：

```
nums[left] <= target && target < nums[mid]
```

右边写：

```
nums[mid] < target && target <= nums[right]
```

这样区间不会重复。

---

# ⑥ 为什么旋转以后还能二分？

普通二分依赖：

> 整个搜索区间有序。

这道题虽然整个区间可能不有序，但是：

> **每次 mid 把区间分成两部分，其中至少有一部分一定有序。**

所以每次仍然可以排除一半。

例如：

```
4 5 6 7 | 0 1 2
────────
 有序
```

或者：

```
6 7 0 | 1 2 3 4 5
        ─────────
           有序
```

我们只要：

```
① 找到有序的一边
② 看 target 是否属于它
③ 决定保留哪一半
```

就可以继续二分。

---

# ⑦ 这题不推荐递归

二分当然能写递归，但是完全没必要。

这里状态只有：

```
left
right
```

不断缩小即可。

所以迭代：

```
while (left <= right)
```

最自然。

时间复杂度：

```
O(log n)
```

空间复杂度：

```
O(1)
```

---

# ⑧ 面试追问

最重要的追问通常是：

**为什么每次至少一边有序？**

因为原数组本来严格递增，只发生过一次旋转，所以旋转断点最多只有一个。`mid` 把当前区间切成两部分，这个唯一的断点不可能同时出现在两边，因此至少有一边没有断点，也就保持递增。

另一个高频追问是：

**如果数组允许重复元素还能这么判断吗？**

例如：

```
[1,0,1,1,1]
```

这时候：

```
nums[left] == nums[mid]
```

并不能明确说明左边是否有序。

而本题明确保证：

```
所有 nums[i] 互不相同
```

所以不存在这个问题。

允许重复元素的是另一类旋转数组题，处理方式会更麻烦。

# ⑨ 复习总结

```
33. 搜索旋转排序数组

核心：
二分 + 判断哪一半有序

每轮：

1. mid == target
   → 直接返回

2. nums[left] <= nums[mid]
   → 左半边有序

   如果：
   nums[left] <= target < nums[mid]

   → 搜左边

   否则：
   → 搜右边

3. 否则
   → 右半边有序

   如果：
   nums[mid] < target <= nums[right]

   → 搜右边

   否则：
   → 搜左边

找不到：
return -1

复杂度：
O(log n)
```

最值得记的一句话是：

> **旋转数组虽然整体无序，但二分后的左右两边至少有一边有序；先找到有序的一边，再判断 target 是否落在其中，就能决定下一步搜索哪一半。**
