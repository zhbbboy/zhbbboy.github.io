这题是非常标准的 **二维动态规划 DP** 入门题。

最推荐你掌握：

> **`dp[i][j]` 表示：从左上角走到 `(i,j)` 一共有多少条不同路径。**

这题特别适合用来真正理解：

> **DP 为什么是“由已经算好的小问题，推出当前问题”。**

---

## ① 破题：题目真正要求什么

机器人从：

```
左上角
```

走到：

```
右下角
```

并且每次只能：

```
→ 向右

或者

↓ 向下
```

例如：

```
m = 3;
n = 2;
```

网格是：

```
起点  □
□     □
□    终点
```

从起点到终点，需要：

```
向下2次
向右1次
```

可以有：

```
右 → 下 → 下
下 → 右 → 下
下 → 下 → 右
```

一共：

```
3 条
```

---

# ② 核心技巧：当前格子只能从哪里过来？

这是整道题最关键的一步。

假设机器人现在要到：

```
(i, j)
```

因为机器人只能：

```
向右
或者
向下
```

所以到达 `(i,j)` 之前，它最后一步只有两种可能。

### 从上面下来

```
(i-1,j)
   ↓
(i,j)
```

### 从左边过来

```
(i,j-1) → (i,j)
```

不可能从右边、下面过来。

所以：

> 到达当前格子的路径数 = 到达上方格子的路径数 + 到达左边格子的路径数。

因此状态转移：

```
dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
```

这就是整道题的核心。

---

# ③ `dp[i][j]` 到底表示什么？

定义：

```
dp[i][j]
```

表示：

> **从左上角 `(0,0)` 走到 `(i,j)` 的不同路径数量。**

注意，它不是：

```
走了多少步
```

而是：

```
一共有多少种不同走法
```

例如：

```
dp[2][1] = 3
```

意思：

> 从 `(0,0)` 到 `(2,1)` 总共有 3 条不同路径。

---

# ④ 为什么第一行和第一列都是 1？

这是初始化最重要的地方。

例如：

```
起点 → → → →
```

如果机器人一直在第一行，那么它只能：

```
一直向右
```

没有第二种走法。

所以：

```
dp[0][j] = 1;
```

第一行全部是：

```
1 1 1 1 1
```

同理第一列：

```
起点
 ↓
 ↓
 ↓
 ↓
```

只能一直向下。

所以：

```
dp[i][0] = 1;
```

第一列也全部：

```
1
1
1
1
```

# ⑤ 用 `m = 3, n = 3` 完整推一遍

网格：

```
(0,0)  (0,1)  (0,2)

(1,0)  (1,1)  (1,2)

(2,0)  (2,1)  (2,2)
```

先初始化第一行第一列：

```
1  1  1

1  ?  ?

1  ?  ?
```

---

## 计算 `(1,1)`

它可以从：

```
上面：(0,1)
左边：(1,0)
```

过来。

所以：

```
dp[1][1] = dp[0][1] + dp[1][0];
```

也就是：

```
1 + 1 = 2
```

变成：

```
1  1  1

1  2  ?

1  ?  ?
```

---

## 计算 `(1,2)`

```
dp[1][2]
=
dp[0][2]
+
dp[1][1];
```

即：

```
1 + 2 = 3
```

得到：

```
1  1  1

1  2  3

1  ?  ?
```

---

## 计算 `(2,1)`

```
dp[2][1]
=
dp[1][1]
+
dp[2][0];
```

即：

```
2 + 1 = 3
```

得到：

```
1  1  1

1  2  3

1  3  ?
```

---

## 计算 `(2,2)`

```
dp[2][2]
=
dp[1][2]
+
dp[2][1];
```

即：

```
3 + 3 = 6
```

最终：

```
1  1  1

1  2  3

1  3  6
```

所以：

```
return dp[2][2];
```

答案：

```
6
```

# ⑥ 完整二维 DP 代码

第一次学习我建议你先写这个版本：

```cpp
class Solution {
public:
    int uniquePaths(int m, int n) {
        vector<vector<int>> dp(m, vector<int>(n, 0));

        // 第一列
        for (int i = 0; i < m; ++i) {
            dp[i][0] = 1;
        }

        // 第一行
        for (int j = 0; j < n; ++j) {
            dp[0][j] = 1;
        }

        // 从左上往右下推
        for (int i = 1; i < m; ++i) {
            for (int j = 1; j < n; ++j) {
                dp[i][j] =
                    dp[i - 1][j] + dp[i][j - 1];
            }
        }

        return dp[m - 1][n - 1];
    }
};
```

# ⑦ 这道题为什么是动态规划？

你可以按照 DP 的四个问题来理解。

### 1. 状态是什么？

```
dp[i][j]
```

表示：

> 到达 `(i,j)` 的路径数量。

---

### 2. 当前状态依赖谁？

只依赖：

```
上方

dp[i-1][j]
```

以及：

```
左方

dp[i][j-1]
```

---

### 3. 状态转移是什么？

```
dp[i][j]
=
dp[i - 1][j]
+
dp[i][j - 1];
```

---

### 4. 初始状态是什么？

```
dp[0][j] = 1;
dp[i][0] = 1;
```

因为第一行只能一路向右，第一列只能一路向下。

最终答案：

```
dp[m - 1][n - 1];
```

---

# ⑧ 为什么两个路径数直接相加？

这是很值得理解的问题。

比如：

```
        上面有3条路径
             ↓
          当前格子
             ↑
        左边有2条路径
```

所有从上面来的路径：

```
3种
```

和所有从左边来的路径：

```
2种
```

它们不可能重复，因为：

```
最后一步不同
```

一部分最后一步是：

```
↓
```

另一部分最后一步是：

```
→
```

所以总数：

```
3 + 2 = 5
```

因此：

```
dp[i][j] = dp[i-1][j] + dp[i][j-1];
```

---

# ⑨ 一个常见问题：为什么循环从 1 开始？

代码：

```
for (int i = 1; i < m; ++i) {
    for (int j = 1; j < n; ++j) {
```

因为：

```
第一行
第一列
```

已经初始化好了。

如果：

```
i = 0
```

还去计算：

```
dp[i - 1][j]
```

就变成：

```
dp[-1][j]
```

越界。

同理 `j=0`：

```
dp[i][j - 1]
```

会访问：

```
dp[i][-1]
```

所以内部状态从：

```
(1,1)
```

开始计算。

# ⑩ 可以优化成一维 DP

当你理解二维以后，可以继续优化。

二维转移：

```
dp[i][j] =
dp[i - 1][j] + dp[i][j - 1];
```

其实当前格子只依赖：

```
上面
+
左边
```

不需要保存整个二维表。

所以可以：

```
vector<int> dp(n, 1);
```

初始：

```
1 1 1 1 ...
```

然后：

```
dp[j] = dp[j] + dp[j - 1];
```

这里：

```
dp[j]
```

更新之前代表：

> 上面的值。

而：

```
dp[j-1]
```

因为本轮已经更新过，所以代表：

> 左边的值。

因此：

```
dp[j] = dp[j] + dp[j - 1];
```

就等价于：

```
当前 = 上面 + 左边
```

完整代码：

```
class Solution {
public:
    int uniquePaths(int m, int n) {
        vector<int> dp(n, 1);

        for (int i = 1; i < m; ++i) {
            for (int j = 1; j < n; ++j) {
                dp[j] = dp[j] + dp[j - 1];
            }
        }

        return dp[n - 1];
    }
};
```

空间从：

```
O(m × n)
```

降低到：

```
O(n)
```

不过第一次学习，**优先掌握二维版本**。

# ⑪ 递归适不适合？

这题从思维上当然可以递归：

```
到达(i,j)的方法数
=
到达(i-1,j)
+
到达(i,j-1)
```

但是纯递归会大量重复计算。

例如：

```
f(3,3)
```

会调用：

```
f(2,3)
f(3,2)
```

而这两边又可能重复计算：

```
f(2,2)
```

所以裸递归效率很低。

可以加记忆化变成：

> 记忆化搜索 DP。

但是本题结构特别规整，直接自底向上的二维 DP 更容易、更适合面试手写。

---

# ⑫ 时间复杂度

二维 DP：

```
m 行 × n 列
```

每个格子计算一次：

```
时间 O(mn)
```

空间：

```
O(mn)
```

如果使用一维优化：

```
时间 O(mn)

空间 O(n)
```

---

# ⑬ 其实还有数学解法

从左上到右下，一定要走：

```
m - 1 次向下

n - 1 次向右
```

总步数：

```
m + n - 2
```

所以本质上是在这些步数中选择：

> 哪 `m-1` 步向下。

因此可以用组合数。

不过对于 Hot100 和 DP 学习，我建议你这题**优先掌握 DP**，因为它是非常典型的网格 DP 模板。

---

# ⑭ 面试追问

这类网格 DP 以后非常常见：

```
左上 → 右下
```

如果只能：

```
向右
向下
```

你首先就应该观察：

> 当前格子是不是只依赖上面和左边？

如果是，就非常可能出现：

```
dp[i][j]
=
某种方式处理(
    dp[i - 1][j],
    dp[i][j - 1]
);
```

比如：

```
路径数量
→ 相加

最小路径和
→ 取 min 再加当前值

最大路径和
→ 取 max 再加当前值
```

这是一个非常重要的 DP 大类。
