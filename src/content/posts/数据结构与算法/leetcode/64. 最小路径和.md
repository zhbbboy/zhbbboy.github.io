这题和你刚做的 **62. 不同路径** 几乎是同一个二维 DP 模板。

区别只在于：

- 62：求“有多少条路径”
- 64：求“路径数字总和最小是多少”

所以核心转移从：

```
dp[i][j] = dp[i - 1][j] + dp[i][j - 1];
```

变成：

```
dp[i][j] = min(dp[i - 1][j], dp[i][j - 1]) + grid[i][j];
```

---

# ① 破题：题目真正要求什么

例如：

```
grid = {
    {1,3,1},
    {1,5,1},
    {4,2,1}
};
```

只能：

```
→ 向右
↓ 向下
```

我们需要从：

```
左上角
```

走到：

```
右下角
```

并让经过的数字总和最小。

比如这条路径：

```
1 → 3 → 1
        ↓
        1
        ↓
        1
```

路径和：

```
1 + 3 + 1 + 1 + 1
= 7
```

所以答案：

```
7
```

---

# ② 核心技巧：`dp[i][j]` 表示什么？

定义：

```
dp[i][j]
```

表示：

> **从左上角 `(0,0)` 走到 `(i,j)` 时，能够得到的最小路径和。**

注意这里和 62 的定义对比：

```
62：

dp[i][j]
= 到(i,j)有多少种路径


64：

dp[i][j]
= 到(i,j)最小需要付出多少路径和
```

---

# ③ 当前格子只能从哪里来？

因为机器人仍然只能：

```
向右
或者
向下
```

所以到达：

```
(i,j)
```

之前，只可能来自：

```
上面：
(i-1,j)

或者

左边：
(i,j-1)
```

所以我们肯定希望：

> 从上面和左边这两条路线里，选路径和更小的那一个。

因此：

```
min(dp[i - 1][j], dp[i][j - 1])
```

然后别忘了：

> 当前格子 `grid[i][j]` 也必须经过。

所以：

```
dp[i][j]
=
min(dp[i - 1][j], dp[i][j - 1])
+
grid[i][j];
```

这就是整题最核心的状态转移。

---

# ④ 为什么要 `+ grid[i][j]`？

比如：

```
上面到当前：

dp[i-1][j] = 5

左边到当前：

dp[i][j-1] = 8

当前格子：
grid[i][j] = 3
```

我们肯定选：

```
5
```

因为：

```
5 < 8
```

但 `5` 只是：

> 走到上面那个格子的最小路径和。

现在还要走进当前格子。

当前格子价格：

```
3
```

所以：

```
dp[i][j]
= min(5,8) + 3
= 8
```

---

# ⑤ 初始化怎么做？

这题和 62 最大的不同之一就是：

> 第一行、第一列不能全部初始化成 1。

因为现在计算的是：

```
路径数字之和
```

---

## 起点

起点：

```
dp[0][0] = grid[0][0];
```

例如：

```
grid[0][0] = 1
```

所以：

```
dp[0][0] = 1
```

---

## 第一行

第一行只能：

```
一直向右
```

例如：

```
grid：

1  3  1
```

走到 `3`：

```
1 + 3 = 4
```

所以：

```
dp[0][1] = dp[0][0] + grid[0][1];
```

走到最后的 `1`：

```
1 + 3 + 1 = 5
```

所以：

```
dp[0][2] = dp[0][1] + grid[0][2];
```

因此第一行：

```
dp[0][j] = dp[0][j - 1] + grid[0][j];
```

---

## 第一列

第一列只能：

```
一直向下
```

所以：

```
dp[i][0] = dp[i - 1][0] + grid[i][0];
```

# ⑧ 完整二维 DP 代码

第一次学习推荐你写这一版：

```cpp
class Solution {
public:
    int minPathSum(vector<vector<int>>& grid) {
        int m = grid.size();
        int n = grid[0].size();

        vector<vector<int>> dp(m, vector<int>(n, 0));

        // 起点
        dp[0][0] = grid[0][0];

        // 第一行
        for (int j = 1; j < n; ++j) {
            dp[0][j] = dp[0][j - 1] + grid[0][j];
        }

        // 第一列
        for (int i = 1; i < m; ++i) {
            dp[i][0] = dp[i - 1][0] + grid[i][0];
        }

        // 其余位置
        for (int i = 1; i < m; ++i) {
            for (int j = 1; j < n; ++j) {
                dp[i][j] =
                    min(dp[i - 1][j], dp[i][j - 1])
                    + grid[i][j];
            }
        }

        return dp[m - 1][n - 1];
    }
};
```

---

# ⑨ 最关键的设计解释

这句：

```
dp[i][j] =
    min(dp[i - 1][j], dp[i][j - 1])
    + grid[i][j];
```

你可以直接翻译成中文：

> 要走到当前 `(i,j)`，最后一步只能从上面或者左边过来；我当然选择“之前路径和更小”的那一边，然后再加上当前格子的值。

这就是整个 DP。

---

# ⑩ 为什么不是：

```
dp[i][j]
=
dp[i - 1][j] + dp[i][j - 1];
```

因为那是你刚才第 62 题的逻辑。

62 问：

> 一共有多少种路径？

上面有 3 条，左边有 2 条：

```
总共 = 3 + 2 = 5条
```

所以用：

```
+
```

但现在 64 问：

> 哪条路径数字和最小？

上面路径和 10，左边路径和 6。

你当然不是：

```
10 + 6
```

而是：

```
min(10,6)
= 6
```

所以：

```
62：
路径数量
→ 加法

64：
最小代价
→ min
```

这个区别非常值得记。

---

# ⑪ 可以直接修改 `grid` 吗？

可以。

因为：

```
grid[i][j]
```

本来存当前格子值。

我们也可以把它直接改成：

> 到当前格子的最小路径和。

也就是说不用额外创建 `dp`。

代码：

```
class Solution {
public:
    int minPathSum(vector<vector<int>>& grid) {
        int m = grid.size();
        int n = grid[0].size();

        for (int j = 1; j < n; ++j) {
            grid[0][j] += grid[0][j - 1];
        }

        for (int i = 1; i < m; ++i) {
            grid[i][0] += grid[i - 1][0];
        }

        for (int i = 1; i < m; ++i) {
            for (int j = 1; j < n; ++j) {
                grid[i][j] +=
                    min(grid[i - 1][j],
                        grid[i][j - 1]);
            }
        }

        return grid[m - 1][n - 1];
    }
};
```

这样额外空间：

```
O(1)
```

但第一次学习建议先写二维 `dp`，语义最清楚。

# ⑫ 一维 DP 优化

和 62 一样，也可以只保存一行。

定义：

```
dp[j]
```

表示：

> 当前处理到这一行时，到第 `j` 列的最小路径和。

代码：

```
class Solution {
public:
    int minPathSum(vector<vector<int>>& grid) {
        int m = grid.size();
        int n = grid[0].size();

        vector<int> dp(n);

        dp[0] = grid[0][0];

        for (int j = 1; j < n; ++j) {
            dp[j] = dp[j - 1] + grid[0][j];
        }

        for (int i = 1; i < m; ++i) {
            dp[0] += grid[i][0];

            for (int j = 1; j < n; ++j) {
                dp[j] =
                    min(dp[j], dp[j - 1])
                    + grid[i][j];
            }
        }

        return dp[n - 1];
    }
};
```

这里：

```
dp[j]
```

更新之前代表：

> 上面的值。

而：

```
dp[j - 1]
```

因为本轮已经更新过，所以代表：

> 左边的值。

因此：

```
dp[j] = min(dp[j], dp[j - 1]) + grid[i][j];
```

和二维完全一样。

---

# ⑬ 递归适不适合？

从思路上是适合递归的：

```
到(i,j)的最小路径和

=
min(
    到(i-1,j)的最小路径和,
    到(i,j-1)的最小路径和
)
+
grid[i][j]
```

但裸递归会重复计算大量状态。

所以可以：

```
递归 + memo
```

变成记忆化搜索。

不过这题网格结构非常规整，面试里优先：

> **自底向上的二维 DP。**

# ⑭ 和上一题 62 一起记

这两题其实可以直接形成一个模板。

### 62 不同路径

```
dp[i][j]
=
dp[i - 1][j]
+
dp[i][j - 1];
```

因为：

```
求方案数量
```

---

### 64 最小路径和

```
dp[i][j]
=
min(dp[i - 1][j],
    dp[i][j - 1])
+
grid[i][j];
```

因为：

```
求最小代价
```

这就是网格 DP 最典型的两种状态转移：

```
计数问题
→ +

最优化问题
→ min / max
```
