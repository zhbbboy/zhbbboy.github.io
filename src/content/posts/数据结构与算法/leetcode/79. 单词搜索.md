这道题非常适合接在你刚学的 **括号生成、组合总和** 后面，因为它也是经典的：

> **回溯 + DFS + 状态恢复。**

但它和前面的“构造字符串”又不太一样：前面的回溯是在一棵“选择树”上做选择，而这道题是在一个**二维网格里走路径**。

这题最推荐：

> **DFS 回溯：从每一个格子尝试作为起点，按照上、下、左、右寻找下一个字符，同时保证同一个格子不能重复使用。**

普通 BFS/迭代写起来更复杂，也不符合这题天然的“沿一条路径匹配到底，再退回来换方向”的结构，所以这题**推荐递归回溯，不推荐普通迭代法**。

---

# ① 破题：题目真正要求什么

例如：

```
board = {
    {'A','B','C','E'},
    {'S','F','C','S'},
    {'A','D','E','E'}
};

word = "ABCCED";
```

我们要判断：

> 能不能从某一个格子开始，按照 `word` 的字符顺序，在网格中一步一步走出来。

每次只能走：

```
上
下
左
右
```

不能斜着走。

而且：

> 同一条搜索路径中，同一个格子不能重复使用。

示例 `"ABCCED"`：

```
A → B → C
        ↓
        C
        ↓
D ← E
```

存在，因此：

```
return true;
```

---

## 一个很重要的限制

假设：

```
A B C E
S F C S
A D E E
```

搜索：

```
ABCB
```

虽然网格中确实有：

```
A、B、C、B
```

但从：

```
A → B → C
```

以后，不能再返回刚刚用过的那个 `B`。

所以结果：

```
false
```

---

# ② 核心技巧：DFS + 回溯

你可以把这题理解成：

> 当前已经匹配到了 `word[index]`，接下来从当前格子的上下左右中，寻找 `word[index+1]`。

我们需要维护三个关键状态：

```
row, col
```

当前搜索到哪个网格位置。

```
index
```

当前正在匹配 `word` 中第几个字符。

以及：

> 当前路径中哪些格子已经用过。

---

## 例如

```
word = "ABCCED";
```

开始：

```
index = 0
要找 'A'
```

找到：

```
board[0][0] = 'A'
```

然后：

```
index = 1
要找 'B'
```

从 `A` 的上下左右找。

找到右边：

```
B
```

继续：

```
index = 2
要找 'C'
```

一直递归。

所以本质是：

```
当前位置匹配成功
        ↓
临时标记当前位置已经使用
        ↓
向四个方向寻找下一个字符
        ↓
如果失败，恢复当前位置
        ↓
换另一个方向继续试
```

这就是标准回溯。

# ③ 图解执行过程

我们用题目示例：

```
board：

A B C E
S F C S
A D E E

word = "ABCCED"
```

---

## 第一步：找第一个字符 `A`

外层遍历整个网格。

发现：

```
(0,0) = A
```

于是从这里 DFS：

```
当前：

A
↑
index = 0
```

匹配成功。

为了防止以后再次走回来，我们先临时标记：

```
# B C E
S F C S
A D E E
```

这里：

```
#
```

表示这个格子当前路径已经使用。

---

## 第二步：找 `B`

当前在：

```
(0,0)
```

需要寻找：

```
word[1] = 'B'
```

检查四个方向。

上：

```
越界
```

下：

```
S != B
```

左：

```
越界
```

右：

```
B == B
```

于是走到：

```
(0,1)
```

现在：

```
index = 1
```

---

## 第三步：找 `C`

继续找：

```
word[2] = 'C'
```

右边：

```
(0,2) = C
```

成功。

路径现在：

```
A → B → C
```

---

## 第四步：再找一个 `C`

因为：

```
word = A B C C E D
             ↑
```

下一字符还是 `C`。

当前位置 `(0,2)` 的下方：

```
(1,2) = C
```

成功。

```
A → B → C
        ↓
        C
```

---

## 第五步：找 `E`

当前位置：

```
(1,2)
```

要找：

```
E
```

下面：

```
(2,2) = E
```

成功。

---

## 第六步：找 `D`

当前位置：

```
(2,2) = E
```

左边：

```
(2,1) = D
```

成功。

完整路径：

```
A → B → C
        ↓
        C
        ↓
D ← E
```

所有字符全部匹配，因此：

```
return true;
```

# 如果某条路走错怎么办？

例如搜索过程中：

```
当前位置有两个方向都可能继续
```

我们先试第一个方向。

如果后面失败：

```
A → B → C → ...
            ×
```

就必须退回当前格子，并尝试其他方向。

这就是：

> **回溯。**

最关键的动作就是：

```
临时标记

递归搜索

恢复现场
```

# ④ 完整代码

这题推荐直接用**原地标记**，不需要额外 `visited` 数组：

```
class Solution {
private:
    int rows;
    int cols;

    bool dfs(vector<vector<char>>& board,
             const string& word,
             int row,
             int col,
             int index) {

        // 1. 越界
        if (row < 0 || row >= rows ||
            col < 0 || col >= cols) {
            return false;
        }

        // 2. 当前字符不匹配
        if (board[row][col] != word[index]) {
            return false;
        }

        // 3. 当前字符已经是 word 最后一个字符
        // 并且刚刚已经匹配成功
        if (index == word.size() - 1) {
            return true;
        }

        // 保存原字符
        char temp = board[row][col];

        // 当前格子临时标记为已使用
        board[row][col] = '#';

        // 4. 搜索上下左右
        bool found =
            dfs(board, word, row - 1, col, index + 1) ||
            dfs(board, word, row + 1, col, index + 1) ||
            dfs(board, word, row, col - 1, index + 1) ||
            dfs(board, word, row, col + 1, index + 1);

        // 5. 回溯：恢复现场
        board[row][col] = temp;

        return found;
    }

public:
    bool exist(vector<vector<char>>& board, string word) {
        rows = board.size();
        cols = board[0].size();

        // 每个格子都可能是单词的起点
        for (int row = 0; row < rows; ++row) {
            for (int col = 0; col < cols; ++col) {

                if (dfs(board, word, row, col, 0)) {
                    return true;
                }
            }
        }

        return false;
    }
};
```

---

# ⑤ 关键设计解释

## 1. 为什么外面还要双层 `for`？

因为题目没有告诉你：

> 单词从哪个格子开始。

所以：

```
每一个格子
```

都有可能是：

```
word[0]
```

例如：

```
A B C
D A E
```

搜索：

```
AE
```

第一个 `A` 可能不行，但第二个 `A` 可以。

所以必须：

```
for (int row = 0; row < rows; ++row) {
    for (int col = 0; col < cols; ++col) {
        dfs(...);
    }
}
```

---

## 2. `index` 到底表示什么？

这是这题非常重要的变量。

```
index
```

表示：

> 当前格子需要匹配 `word[index]`。

例如：

```
word = "ABCCED";
```

那么：

```
index = 0 → A
index = 1 → B
index = 2 → C
index = 3 → C
index = 4 → E
index = 5 → D
```

每成功匹配一个字符：

```
index + 1
```

去找下一个。

---

## 3. 为什么字符不一样立即返回 false？

```
if (board[row][col] != word[index]) {
    return false;
}
```

因为题目要求：

> 必须按照 `word` 的字符顺序匹配。

例如当前应该找：

```
C
```

但当前格子是：

```
F
```

那么以这个位置作为当前路径肯定失败。

没有必要继续往下。

这是一个非常直接的**剪枝**。

---

## 4. 为什么要把当前格子改成 `'#'`？

因为题目规定：

> 一个格子在同一条路径中不能重复使用。

例如：

```
A B
```

如果不做标记，就可能：

```
A → B → A → B → ...
```

不断在两个格子之间来回走。

所以匹配当前格子后：

```
board[row][col] = '#';
```

表示：

> 当前这条路径已经使用这个格子了。

接下来递归时：

```
board[row][col] != word[index]
```

自然就不会再次使用它。

---

## 5. 为什么最后一定要恢复？

这是本题最典型的**回溯**。

```
char temp = board[row][col];

board[row][col] = '#';

dfs(...);

board[row][col] = temp;
```

假设：

```
第一次搜索从某个 A 开始失败
```

那么这个 `A` 对于**下一条搜索路径**仍然应该可以使用。

所以必须恢复。

---

### 举个非常重要的例子

假设：

```
A B
A C
```

我们先从左上角 `A` 开始搜索。

搜索失败以后，如果你没有恢复：

```
# B
A C
```

那么后面的搜索会看到一个被永久修改的网格。

显然错误。

所以回溯的本质就是：

> 当前分支修改状态 → 搜索 → 离开当前分支时恢复到进入之前的状态。

这和你之前的：

```
path.push_back(...)
dfs(...)
path.pop_back()
```

本质完全相同。

这里只不过状态不再是 `path`，而是：

```
board[row][col]
```

---

## 6. 为什么最后一个字符匹配后直接 `true`？

代码：

```
if (index == word.size() - 1) {
    return true;
}
```

注意这句是在：

```
if (board[row][col] != word[index])
    return false;
```

之后。

所以能运行到这里说明：

```
最后一个字符已经匹配成功
```

例如：

```
word = "ABC"
index = 2
board[row][col] = 'C'
```

所有字符都找到了，不需要再继续走。

---

## 7. 为什么这里使用 `||`？

```
bool found =
    dfs(上) ||
    dfs(下) ||
    dfs(左) ||
    dfs(右);
```

因为只需要：

> 找到任意一条合法路径。

只要一个方向：

```
return true;
```

整个表达式就为 `true`。

而且 C++ 的 `||` 有**短路求值**：

如果上面已经返回 `true`：

```
true || ...
```

后面的方向就不会再执行。

因为答案已经找到了。

---

# ⑥ 递归三要素

这道题是非常标准的递归 DFS。

## 1. 递归函数定义

```
dfs(board, word, row, col, index)
```

表示：

> 当前来到 `(row,col)`，需要从这里开始匹配 `word[index...]`，判断是否存在一条合法路径。

这个函数定义一定要理解。

例如：

```
dfs(board, word, 1, 2, 3)
```

表示：

> 现在在 `(1,2)`，看看能不能从这里开始把 `word[3...]` 匹配完。

---

## 2. 终止条件

### 越界

```
if (row < 0 || row >= rows ||
    col < 0 || col >= cols) {
    return false;
}
```

### 字符不匹配

```
if (board[row][col] != word[index]) {
    return false;
}
```

### 最后一个字符匹配成功

```
if (index == word.size() - 1) {
    return true;
}
```

---

## 3. 当前层做什么？

当前层负责：

```
① 判断当前位置是否合法
② 判断当前字符是否匹配
③ 标记当前位置已经使用
④ 向四个方向递归寻找下一个字符
⑤ 恢复当前位置
⑥ 返回搜索结果
```

这就是完整的回溯流程。

---

# ⑦ 为什么不推荐 BFS / 普通迭代？

BFS 更擅长：

```
最短距离
最少步数
按层扩散
```

例如：

```
腐烂的橘子
```

就特别适合 BFS。

但这题要求的是：

> 有没有一条完整路径能够按顺序匹配整个单词。

我们需要：

```
沿一条路一直尝试
失败后退回来
再换另一条路
```

这天然就是：

> **DFS + 回溯。**

如果迭代，就必须自己维护：

```
当前坐标
当前 index
这条路径已经访问过哪些格子
```

状态非常麻烦。

因此不推荐。

# ⑧ 面试追问

## Q1：为什么这题属于回溯？

因为搜索某条路径时，会：

```
选择一个格子
↓
标记为已使用
↓
递归继续搜索
↓
搜索完成
↓
恢复这个格子
```

核心就是：

> **选择 → 递归 → 撤销选择。**

---

## Q2：为什么不能使用全局 `visited` 后永远不恢复？

因为：

> “不能重复使用”只针对同一条路径。

不同搜索路径之间，格子当然可以重新使用。

所以访问状态必须随着递归回退一起恢复。

---

## Q3：和 200. 岛屿数量有什么区别？

这两个都属于网格 DFS/BFS，但访问标记意义完全不同。

### 岛屿数量

访问过一个陆地后：

```
以后永远不用再访问
```

所以可以永久：

```
grid[row][col] = '0';
```

不需要恢复。

### 单词搜索

一个格子只是在：

```
当前路径
```

中不能重复使用。

另一条路径还可以用。

所以必须：

```
标记
→ 搜索
→ 恢复
```

这个区别非常重要。

---

## Q4：时间复杂度是多少？

假设：

```
网格大小 = m × n
word 长度 = L
```

每一个格子都可能作为起点：

```
m × n
```

第一次之后，每一步理论上最多向大约 3 个新方向继续，因为不能立即返回刚刚使用过的格子。

所以常见复杂度估计：

```
O(m × n × 3^L)
```

如果用更宽松的上界，也经常写：

```
O(m × n × 4^L)
```

面试中重点是知道：

> 这是指数级搜索，但通过字符匹配、访问标记等剪枝，大量分支会提前结束。

递归栈最大深度：

```
O(L)
```

原地修改 board，所以不额外需要 `m×n` 的 visited 数组。

---

## Q5：还能怎么剪枝？

题目进阶就问到了。

有几个常见优化。

第一，最简单：

```
if (word.size() > rows * cols)
    return false;
```

单词长度比整个网格格子数还大，一定不可能。

第二，可以统计字符数量。

比如：

```
word 中有 5 个 'A'
board 里只有 3 个 'A'
```

直接：

```
return false;
```

第三，更高级一点：

> 如果 `word` 末尾字符在网格中比开头字符更少，可以把 `word` 反转，从出现更少的字符开始搜索。

例如：

```
开头 A 有 20 个
结尾 Z 只有 1 个
```

从 `Z` 开始尝试，搜索起点会少很多。

这是比较好的面试进阶回答。

---

## 面试表达

> 我会使用 DFS 回溯。从网格中的每个位置尝试作为单词起点，递归参数包含当前坐标和已经匹配到的字符下标。如果当前位置越界或者字符与 `word[index]` 不匹配，就立即返回 false。匹配成功后，将当前格子临时标记为已访问，然后向上下左右递归匹配下一个字符。因为同一个格子只能在当前路径中使用一次，所以递归返回后要恢复原字符，这就是回溯。如果最后一个字符匹配成功则返回 true。

# ⑨ 复习总结

```
79. 单词搜索

题型：
网格 DFS + 回溯

核心：
从每一个格子尝试作为 word[0] 的起点。

递归状态：
row / col：当前位置
index：当前要匹配 word[index]

失败条件：
1. 越界
2. board[row][col] != word[index]

成功条件：
index == word.size() - 1
且当前字符已经匹配

当前层：
1. 匹配当前字符
2. 标记当前格子已使用
3. 搜索上下左右
4. 恢复当前格子
5. 返回结果

为什么恢复：
同一个格子只是当前路径不能重复使用，
其他搜索路径仍然可以使用。
```

把它和前面几道回溯题串起来：

```
全排列：
used 控制元素不能重复使用

子集：
startIndex 控制只能往后选

组合总和：
startIndex + 当前元素可重复使用

括号生成：
left / right 控制合法性

单词搜索：
二维坐标 + 临时访问标记
控制当前路径不能重复经过同一格子
```

**一句话记忆：**

> **从每个格子出发 DFS：当前字符对不上就返回；对上就临时标记，向四个方向找下一个字符，回来后恢复格子。**
