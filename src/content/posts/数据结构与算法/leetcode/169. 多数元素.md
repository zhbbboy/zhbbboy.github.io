这题最推荐你掌握：
> **Boyer-Moore Voting Algorithm（摩尔投票法）**

因为题目进阶明确要求：

```
时间复杂度 O(n)
空间复杂度 O(1)
```
如果用 `unordered_map` 统计次数虽然也能做，但空间是 O(n)。

摩尔投票法只需要两个变量：

```
int candidate; // 当前候选人
int count;     // 当前票数
```

---

## ① 破题：题目真正要求什么

题目说：

> 多数元素是出现次数 **大于 `n/2`** 的元素。

例如：

```
nums = [2,2,1,1,1,2,2]
```

一共：

```
n = 7
```

所以多数元素必须出现：

```
> 7/2
> 3
```

也就是至少 4 次。

这里：
```
2 出现4次
1 出现3次
```

所以答案：
```
2
```

---

# ② 最容易想到的方法：哈希表

可以：
```
unordered_map<int, int> mp;

for (int num : nums) {
    mp[num]++;
}
```

统计：
```
2 -> 4
1 -> 3
```

然后找次数大于：
```
nums.size() / 2
```
的数字。

时间复杂度：
```
O(n)
```

但空间复杂度：
```
O(n)
```

题目进阶要求 O(1)，所以真正要学的是摩尔投票法。

---

# ③ 摩尔投票法的核心思想：不同元素互相抵消

你可以先不要想代码，先想这个事实：
> 如果一个元素出现次数超过一半，那么让它和所有其他不同元素一一抵消，最后它一定还有剩余。

例如：

```
[2,2,1,1,1,2,2]
```

有：

```
2：4个
1：3个
```

我们让：

```
一个2
抵消
一个1
```

可以抵消三组：

```
2 - 1
2 - 1
2 - 1
```

最后：

```
还剩一个2
```

所以多数元素不可能被完全抵消掉。

这就是整个算法的数学基础。

---

# ④ 两个变量是什么意思？

我们定义：

```
int candidate = 0;
int count = 0;
```

其中：

```
candidate
```

表示：

> 当前我们认为“可能是多数元素”的候选人。

而：

```
count
```

表示：

> 当前候选人在“抵消之后”还剩多少优势票。

注意：

`count` **不是 candidate 在整个数组里实际出现的次数**。

这一点非常重要。

它表示的是：

> 当前这一轮候选人在与其他不同元素抵消以后，还剩多少票。

---

# ⑤ 遍历规则

每看到一个数字 `num`：

### 如果 `count == 0`

说明之前候选人的优势已经被完全抵消。

那就重新选择：
```
candidate = num;
```

---

然后判断：

如果：
```
num == candidate
```

候选人自己来了：
```
count++;
```
相当于加一票。

如果：
```
num != candidate
```

来了一个反对者：
```
count--;
```

相当于：
> 当前候选人和这个不同元素互相抵消。

---

# ⑥ 完整跑一遍 `[2,2,1,1,1,2,2]`

初始：

```
candidate = ?
count = 0
```

---

### 第一个数 `2`

因为：

```
count == 0
```

所以选择：

```
candidate = 2
```

然后：

```
num == candidate
```

所以：

```
count = 1
```

状态：

```
candidate = 2
count = 1
```

---

### 第二个数 `2`

还是：

```
2 == candidate
```

所以：

```
count = 2
```

状态：

```
candidate = 2
count = 2
```

---

### 第三个数 `1`

```
1 != candidate
```

所以互相抵消：

```
count = 1
```

可以理解成：

```
一个2
和
一个1
抵消
```

---

### 第四个数 `1`

又不同：

```
count = 0
```

现在之前积累的：

```
2、2
```

已经和：

```
1、1
```

完全抵消了。

---

### 第五个数 `1`

现在：

```
count == 0
```

说明旧候选人没有优势了。

所以重新选择：

```
candidate = 1
```

然后：

```
1 == 1
```

所以：

```
count = 1
```

现在：

```
candidate = 1
count = 1
```

---

### 第六个数 `2`

```
2 != 1
```

所以：

```
count = 0
```

`1` 和 `2` 抵消。

---

### 第七个数 `2`

又：

```
count == 0
```

所以重新选择：

```
candidate = 2
```

然后：

```
count = 1
```

最终：

```
candidate = 2
```

答案就是：

```
2
```

# ⑦ 为什么中途 candidate 甚至可以选错？

这正是很多人第一次最疑惑的地方。

刚才你看见：

```
candidate
```

中间一度变成了：

```
1
```

但最终答案明明是：

```
2
```

这完全没问题。

因为：
> `candidate` 只是当前阶段的候选人，不要求从头到尾一直正确。

当：
```
count == 0
```

时说明：
> 到当前位置为止，之前积累的候选人优势全部被其他元素抵消掉了。

于是剩余后缀可以重新开始选候选人。

由于真正的多数元素数量超过一半：

> 无论前面怎么抵消，最终它一定会成为最后留下的候选人。

---

# ⑧ 再用一个更直观的“消消乐”理解

例如：

```
[2,2,1,1,1,2,2]
```

只要相邻或不相邻的不同元素都允许配对删除：

```
2 和 1
一起删除
```

那么：

```
2 2 1 1 1 2 2
```

可以消掉：

```
2 1
2 1
1 2
```

最后还剩：

```
2
```

原因非常简单：

```
2有4个
其他所有元素总共只有3个
```

所以无论怎么一对一抵消：

```
4 - 3 = 1
```

至少剩一个 2。

摩尔投票法就是在一次遍历中模拟这种：

> **不同元素两两抵消。**

---

# ⑨ 完整代码

推荐你掌握：

```cpp
class Solution {
public:
    int majorityElement(vector<int>& nums) {
        int candidate = 0;
        int count = 0;

        for (int num : nums) {

            if (count == 0) {
                candidate = num;
            }

            if (num == candidate) {
                ++count;
            }
            else {
                --count;
            }
        }

        return candidate;
    }
};
```

还可以把后面的判断压缩成：

```
count += (num == candidate ? 1 : -1);
```

但你第一次学不建议这么写。

保留：

```
if (num == candidate) {
    count++;
}
else {
    count--;
}
```

最清楚。

---

# ⑩ 为什么 `count == 0` 时要换 candidate？

假设当前已经处理：

```
[3,3,2,2]
```

开始候选：

```
candidate = 3
```

两个 3：

```
count = 2
```

然后两个 2：

```
count = 0
```

这意味着：

```
两个3
和
两个非3
```

已经完全抵消。

所以这一段：

```
[3,3,2,2]
```

对于最终“谁是多数元素”的竞争来说，可以整体忽略。

下一次再来数字，比如：

```
5
```

就可以重新：

```
candidate = 5;
```

因为前面的竞争已经打平。

---

# ⑪ 为什么最后 candidate 一定是多数元素？

这里利用了题目的一个非常重要的保证：

> **数组中一定存在多数元素。**

假设多数元素是：

```
M
```

它出现：

```
> n/2
```

次。

其他所有元素加起来：

```
< n/2
```

次。

即使每一个非 `M` 元素都拿去抵消一个 `M`：

```
M vs 其他
M vs 其他
M vs 其他
...
```

由于：

```
M 数量 > 其他元素总数量
```

最终一定还有 `M` 留下来。

所以最后：

```
candidate
```

必然是它。

---

# ⑫ 如果题目没有保证多数元素存在呢？

这是面试很常见的追问。

例如：

```
nums = [1,2,3]
```

这里根本没有任何数字出现超过一半。

但摩尔投票最后依然会得到一个：

```
candidate
```

比如可能得到：

```
3
```

这只说明：

> 它是“抵消后最后剩下的候选人”。

不代表它真的出现超过一半。

因此如果题目**不保证多数元素一定存在**，那么：

第一遍：

```
摩尔投票找 candidate
```

第二遍：

```
统计 candidate 实际出现次数
```

最后检查：

```
realCount > nums.size() / 2
```

才可以确认。

但是 LeetCode 169 明确保证：

> 一定存在多数元素。

所以不用第二遍验证。

---

# ⑬ 为什么不能用 XOR？

你上一题 136 用了：

```
^
```

你可能会想到这里能不能也消掉其他数字。

不行。

136 能 XOR 是因为：

```
其他数字全部恰好出现两次
```

所以：

```
x ^ x = 0
```

完美消掉。

但是这题可能：

```
[2,2,1,1,1,2,2]
```

有：

```
2出现4次
1出现3次
```

XOR：

```
2 ^ 2 ^ 1 ^ 1 ^ 1 ^ 2 ^ 2
```

最后剩的未必表达“多数”关系。

XOR解决的是：

> 偶数次重复抵消。

摩尔投票解决的是：

> 超过一半的元素与其他元素一一抵消后必有剩余。

两题思想不同。

# ⑭ 递归还是迭代？

明显推荐：

> **迭代。**

只需要从左到右扫描一次。

递归没有任何优势。

# ⑯ 面试追问

面试时可以这样解释摩尔投票：

> 由于多数元素出现次数大于数组长度的一半，因此可以把多数元素与所有非多数元素两两抵消。即使把所有非多数元素全部抵消掉，多数元素依然至少剩一个。摩尔投票使用 `candidate` 和 `count` 模拟这个过程：遇到相同元素加一，不同元素减一，计数归零时重新选择候选人。题目保证多数元素存在，因此最终候选人一定就是多数元素。

这是比较标准的面试表达。
