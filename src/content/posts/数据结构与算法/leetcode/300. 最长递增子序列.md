这道题是非常经典的 **序列型动态规划**，也是面试高频题。

我建议你分两层掌握：

> **第一层一定掌握：DP，时间 O(n²)** —— 最容易理解“最长递增子序列”到底怎么转移。
> **第二层面试进阶：贪心 + 二分，时间 O(n log n)** —— LeetCode 题目进阶明确要求。

这题普通递归虽然能写，但不自然且会有大量重复计算，所以不推荐作为主方法。

---

# ① 破题：题目真正要求什么

例如：

```
nums = [10,9,2,5,3,7,101,18]
```

题目要求找到一个：

> **严格递增的子序列的最大长度。**

答案是：

```
[2,3,7,101]
```

长度：

```
4
```

但：

```
[2,5,7,18]
```

也是长度 `4`。

题目只要求：

```
return 4;
```

不要求具体是哪一个序列。

---

## 先搞清楚：子序列 ≠ 子数组

这是这题第一大重点。

### 子数组

必须连续。

例如：

```
[10,9,2,5,3]
       -----
```

### 子序列

可以删除中间一些元素，但是：

> **原来的相对顺序不能改变。**

例如：

```
原数组：

10  9  2  5  3  7  101  18
       ↑     ↑  ↑   ↑

得到：

2 → 3 → 7 → 101
```

虽然它们不连续，但顺序没有改变，所以是合法子序列。

---

# ② 核心技巧：DP —— 以 nums[i] 结尾的最长递增子序列

这道题最关键的是 `dp[i]` 怎么定义。

定义：

> `dp[i]` = **以 `nums[i]` 作为最后一个元素的最长递增子序列长度。**

注意“**以 nums[i] 结尾**”这几个字非常重要。

例如：

```
nums = [10,9,2,5,3,7]
```

如果现在：

```
i = 5
nums[i] = 7
```

我们不是问：

> 前 0~5 个数字总体最长是多少？

而是先问：

> **必须让 7 成为最后一个数字时，最长可以是多少？**

然后看看 `7` 前面有哪些数比它小：

```
2
5
3
```

只要：

```
nums[j] < nums[i]
```

那么 `nums[i]` 就可以接在以 `nums[j]` 结尾的递增子序列后面。

于是状态转移：

如果用代码表达：

```
if (nums[j] < nums[i]) {
    dp[i] = max(dp[i], dp[j] + 1);
}
```

这就是整道 DP 解法最核心的一行。

# ③ 图解执行过程

我们用：

```
nums = [10,9,2,5,3,7]
```

一步一步算。

初始：

```
nums: 10  9  2  5  3  7
dp:   1   1  1  1  1  1
```

为什么全是 `1`？

因为哪怕前面什么都接不上：

```
[10]
[9]
[2]
[5]
...
```

每个数字自己都至少能构成长度为 `1` 的递增子序列。

---

## i = 0，nums[i] = 10

前面没有元素。

所以：

```
dp[0] = 1
```

---

## i = 1，nums[i] = 9

前面只有：

```
10
```

因为：

```
10 < 9
```

不成立。

所以 `9` 接不到 `10` 后面：

```
dp[1] = 1
```

目前：

```
nums: 10  9
dp:   1   1
```

---

## i = 2，nums[i] = 2

前面：

```
10, 9
```

都比 `2` 大。

所以：

```
dp[2] = 1
```

---

## i = 3，nums[i] = 5

前面：

```
10  9  2
```

检查：

```
10 < 5 ×
9  < 5 ×
2  < 5 √
```

所以 `5` 可以接到：

```
[2]
```

后面：

```
[2,5]
```

因此：

```
dp[3] = dp[2] + 1 = 2;
```

现在：

```
nums: 10  9  2  5
dp:   1   1  1  2
```

---

## i = 4，nums[i] = 3

前面：

```
10 9 2 5
```

只有：

```
2 < 3
```

所以：

```
[2,3]
```

长度：

```
2
```

因此：

```
dp[4] = 2
```

---

## i = 5，nums[i] = 7

现在是最关键的一步。

前面：

```
10 9 2 5 3
```

比 `7` 小的：

```
2
5
3
```

分别尝试。

从 `2` 接：

```
dp[2] + 1
= 1 + 1
= 2
```

得到类似：

```
[2,7]
```

从 `5` 接：

```
dp[3] + 1
= 2 + 1
= 3
```

得到：

```
[2,5,7]
```

从 `3` 接：

```
dp[4] + 1
= 2 + 1
= 3
```

得到：

```
[2,3,7]
```

所以：

```
dp[5] = 3
```

最终：

```
nums: 10  9  2  5  3  7
dp:   1   1  1  2  2  3
```

# ④ 完整代码：O(n²) DP

第一次学习这题，我建议你先把这个版本完全掌握：

```
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        int n = nums.size();

        // dp[i]：以 nums[i] 结尾的最长递增子序列长度
        vector<int> dp(n, 1);

        int ans = 1;

        for (int i = 0; i < n; ++i) {
            // 枚举 i 前面的每一个位置 j
            for (int j = 0; j < i; ++j) {

                // nums[i] 可以接到 nums[j] 后面
                if (nums[j] < nums[i]) {
                    dp[i] = max(
                        dp[i],
                        dp[j] + 1
                    );
                }
            }

            ans = max(ans, dp[i]);
        }

        return ans;
    }
};
```

# ⑤ 关键设计解释

## 1. 为什么 `dp[i]` 要定义成“以 nums[i] 结尾”？

因为这样我们才能判断：

```
nums[j] < nums[i]
```

时：

> 可以把 `nums[i]` 接到以 `nums[j]` 结尾的序列后面。

例如：

```
nums[j] = 5
nums[i] = 7
```

如果：

```
以 5 结尾的最长递增子序列：
[2,5]
```

长度：

```
dp[j] = 2
```

那么直接把 `7` 接上：

```
[2,5,7]
```

所以：

```
dp[i] = dp[j] + 1;
```

---

## 2. 为什么要遍历所有 `j < i`？

因为你不知道：

> `nums[i]` 接在哪个前面的元素后面最好。

例如：

```
nums = [1,4,2,3,5]
```

计算 `5` 时，可以接：

```
1 → 5
1 → 4 → 5
1 → 2 → 5
1 → 2 → 3 → 5
```

显然最后一种最长。

所以必须检查所有：

```
j < i
并且 nums[j] < nums[i]
```

然后取：

```
max(...)
```

---

## 3. 为什么初始化全部为 `1`？

```
vector<int> dp(n, 1);
```

因为每个数字本身都是一个长度为 `1` 的递增子序列。

例如：

```
nums[i] = 100
```

即使前面所有数字都比 `100` 大，至少还有：

```
[100]
```

所以：

```
dp[i] >= 1
```

---

## 4. 为什么条件必须是 `<`，不能是 `<=`？

题目要求：

> **严格递增。**

例如：

```
[2,2,3]
```

两个 `2` 不能同时出现在严格递增序列里。

所以：

```
nums[j] < nums[i]
```

而不是：

```
nums[j] <= nums[i]
```

这也是为什么：

```
nums = [7,7,7,7]
```

答案是：

```
1
```

---

## 5. 为什么最后不能直接 `return dp[n-1]`？

这是这道题非常容易犯的错误。

因为：

```
dp[n-1]
```

表示的是：

> **必须以最后一个元素 `nums[n-1]` 结尾的 LIS 长度。**

但整个数组的 LIS 不一定以最后一个元素结尾。

例如：

```
nums = [1,2,3,4,0];
```

那么：

```
dp = [1,2,3,4,1]
```

如果你：

```
return dp[n - 1];
```

会返回：

```
1
```

但正确答案显然：

```
[1,2,3,4]
长度 = 4
```

所以最终答案必须是：

```
max(dp[0], dp[1], ..., dp[n-1])
```

代码中就是：

```
ans = max(ans, dp[i]);
```

# ⑥ DP 五步法

这题特别适合继续练你的 DP 分析流程。

### 1. 状态定义

```
dp[i] =
以 nums[i] 结尾的最长严格递增子序列长度
```

### 2. 状态转移

对于所有：

```
j < i
```

如果：

```
nums[j] < nums[i]
```

则：

```
dp[i] = max(dp[i], dp[j] + 1);
```

### 3. 初始化

```
dp[i] = 1;
```

每个元素自己至少是一条长度为 1 的序列。

### 4. 遍历顺序

因为：

```
dp[i]
```

依赖：

```
dp[0...i-1]
```

所以从左向右计算。

### 5. 最终答案

不是 `dp[n-1]`，而是：

```
所有 dp[i] 的最大值
```

# ⑦ 进阶：O(n log n) 贪心 + 二分

这部分是本题面试进阶。

我们创建：

```
vector<int> tails;
```

它的核心含义非常重要：

> `tails[k]` 表示：长度为 `k+1` 的递增子序列中，**目前能够得到的最小结尾值**。

为什么希望结尾越小越好？

例如两个长度都为 `3` 的递增子序列：

```
[1,4,8]
[1,3,5]
```

第二个更好。

因为结尾：

```
5 < 8
```

以后遇到：

```
6
```

`6` 可以接到 `5` 后面：

```
[1,3,5,6]
```

但无法接到 `8` 后面。

所以：

> **同样长度的递增子序列，结尾越小，未来越容易继续增长。**

这就是这里的贪心。

---

## 例子

```
nums = [10,9,2,5,3,7,101,18]
```

开始：

```
tails = []
```

遇到 `10`：

```
[10]
```

遇到 `9`：

不能增加长度，但用更小的 `9` 替换 `10`：

```
[9]
```

遇到 `2`：

```
[2]
```

遇到 `5`：

比最后的 `2` 大，可以扩展：

```
[2,5]
```

遇到 `3`：

不能扩展长度，但是：

```
3 < 5
```

把 `5` 替换成 `3`：

```
[2,3]
```

注意：

> 这里的替换不是说原数组里的 `5` 被修改了。

而是在维护：

> “长度为 2 的递增子序列，最优的结尾目前可以做到 3”。

继续 `7`：

```
[2,3,7]
```

`101`：

```
[2,3,7,101]
```

`18`：

找到第一个 `>= 18` 的位置，也就是 `101`：

```
[2,3,7,18]
```

最终：

```
tails.size() = 4
```

答案就是：

```
4
```

---

## 为什么用 `lower_bound`？

```
auto it = lower_bound(
    tails.begin(),
    tails.end(),
    num
);
```

它会找到：

> 第一个 `>= num` 的位置。

如果找不到：

```
it == tails.end()
```

说明：

```
num > tails 中所有元素
```

可以直接扩展长度：

```
tails.push_back(num);
```

否则：

```
*it = num;
```

用更小的结尾替换原来的结尾。

---

## O(n log n) 完整代码

```
class Solution {
public:
    int lengthOfLIS(vector<int>& nums) {
        vector<int> tails;

        for (int num : nums) {
            auto it = lower_bound(
                tails.begin(),
                tails.end(),
                num
            );

            // num 比 tails 中所有值都大
            // 可以让递增子序列长度 +1
            if (it == tails.end()) {
                tails.push_back(num);
            }
            else {
                // 用更小的尾部替换
                *it = num;
            }
        }

        return tails.size();
    }
};
```

时间复杂度：

```
每个 num 做一次二分 O(log n)
一共有 n 个 num

所以 O(n log n)
```

空间：

```
O(n)
```

# ⑧ 面试追问

### Q1：`tails` 本身一定是原数组的 LIS 吗？

**不一定。**

这是一个很重要的面试点。

`tails` 的核心作用不是保存最终真实 LIS，而是保存：

> 各种长度的递增子序列能达到的最小尾部。

因此：

```
tails.size()
```

一定等于 LIS 长度，但 `tails` 在一般情况下不能简单理解为已经恢复出的那条 LIS。

如果题目要求返回具体 LIS，还需要额外记录前驱等信息。

---

### Q2：为什么尾部越小越好？

因为长度相同时：

```
尾部越小
→ 后面的数字越容易接上
→ 更有机会构造更长的递增序列
```

这就是贪心思想。

---

### Q3：为什么是 `lower_bound` 而不是 `upper_bound`？

题目要求：

```
严格递增
```

遇到相等元素：

```
7,7
```

不能让 LIS 长度增加。

所以需要找到：

```
第一个 >= num
```

的位置进行替换：

```
lower_bound
```

如果题目要求的是：

> 最长**非递减**子序列

才通常会考虑：

```
upper_bound
```

---

### Q4：DP 和二分版本分别什么复杂度？

DP：

```
时间 O(n²)
空间 O(n)
```

贪心 + 二分：

```
时间 O(n log n)
空间 O(n)
```

面试中如果先写出 O(n²)，面试官继续问：

> 能不能优化？

就进入 `tails + lower_bound`。

# ⑨ 复习总结

```
300. 最长递增子序列

首先注意：
子序列可以不连续，
但不能改变原元素相对顺序。

方法一：DP

dp[i] =
以 nums[i] 结尾的最长递增子序列长度。

初始化：
dp[i] = 1

对于所有 j < i：

如果：
nums[j] < nums[i]

那么：
dp[i] = max(dp[i], dp[j] + 1)

最终答案：
max(dp[i])

不是 dp[n-1]。

复杂度：
O(n²)
```

进阶版本记：

```
tails[k] =
长度为 k+1 的递增子序列中，
目前最小的结尾值。

对于每个 num：

找到 tails 中第一个 >= num 的位置。

找不到：
push_back(num)
→ LIS 长度增加。

找到了：
把该位置替换成 num
→ 长度不变，但尾部变小，更利于以后扩展。

最终：
tails.size() 就是 LIS 长度。

复杂度：
O(n log n)
```

这题最应该形成的一句话记忆是：

> **DP 版：对于 `nums[i]`，枚举前面所有更小的 `nums[j]`，把 `nums[i]` 接到它们后面，取最长。进阶版则维护“相同长度下尽可能小的尾巴”，通过二分做到 O(n log n)。**
