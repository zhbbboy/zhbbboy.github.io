这道题和你刚才在 **300. 最长递增子序列**里手写的 `lower_bound` 逻辑几乎一模一样。

这题最推荐的思路就是：

> **二分查找第一个 `>= target` 的位置。**

因为如果 `target` 存在，这个位置就是它的下标；如果不存在，这个位置刚好就是它应该插入的位置。

---

## ① 破题：题目真正要求什么

例如：

```
nums = [1,3,5,6]
```

如果：

```
target = 5
```

5 已经存在：

```
下标：  0 1 2 3
nums： 1 3 5 6
           ↑
```

返回：

```
2
```

如果：

```
target = 2
```

虽然不存在，但为了保持升序：

```
1 [2] 3 5 6
   ↑
```

应该插在下标：

```
1
```

如果：

```
target = 7
```

应该：

```
1 3 5 6 [7]
          ↑
```

返回：

```
4
```

所以三个例子其实都是同一个问题：

> **找数组中第一个 `>= target` 的位置。**

---

## ② 核心技巧：二分查找左边界

我们定义：

```
int left = 0;
int right = nums.size();
```

注意这里使用的是：

```
[left, right)
```

左闭右开区间。

然后不断找中间位置：

```
int mid = left + (right - left) / 2;
```

判断：

```
nums[mid] >= target
```

如果成立：

> `mid` 有可能就是答案，但左边也可能还有更合适的位置。

所以：

```
right = mid;
```

如果：

```
nums[mid] < target
```

说明：

> `mid` 以及 `mid` 左边都不可能是答案。

所以：

```
left = mid + 1;
```

最终：

```
left == right
```

这个位置就是答案。

---

## ③ 图解执行过程

例如：

```
nums = [1,3,5,6]
target = 2
```

初始化：

```
left = 0
right = 4
```

数组：

```
下标： 0 1 2 3
      [1 3 5 6)
       ↑       ↑
      left   right
```

第一次：

```
mid = 0 + (4 - 0) / 2 = 2
```

所以：

```
nums[2] = 5
```

因为：

```
5 >= 2
```

说明答案可能是 `2`，也可能在左边：

```
right = 2;
```

现在：

```
left = 0
right = 2
```

第二次：

```
mid = 1
nums[1] = 3
```

因为：

```
3 >= 2
```

继续：

```
right = 1;
```

现在：

```
left = 0
right = 1
```

第三次：

```
mid = 0
nums[0] = 1
```

因为：

```
1 < 2
```

所以：

```
left = mid + 1;
```

得到：

```
left = 1
right = 1
```

循环结束。

返回：

```
1
```

正好是：

```
1 [2] 3 5 6
   ↑
```

## ④ 完整代码

我推荐你直接掌握这个版本：

```cpp
class Solution {
public:
    int searchInsert(vector<int>& nums, int target) {
        int left = 0;
        int right = nums.size();

        // 找第一个 >= target 的位置
        while (left < right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] >= target) {
                right = mid;
            }
            else {
                left = mid + 1;
            }
        }

        return left;
    }
};
```

这就是你之前自己实现 `lower_bound` 的标准逻辑。

---

## ⑤ 关键设计解释

最重要的是这两个判断。

当：

```
nums[mid] >= target
```

为什么不能：

```
return mid;
```

因为我们不仅是找一个 `>= target` 的数字，而是：

> **找第一个 `>= target` 的位置。**

例如：

```
nums = [1,3,5,6]
target = 2
```

第一次找到：

```
nums[2] = 5 >= 2
```

但答案明显不是 `2`，而是：

```
1
```

所以只能：

```
right = mid;
```

继续向左找。

而当：

```
nums[mid] < target
```

例如：

```
nums[mid] = 3
target = 5
```

因为数组已经升序：

```
mid 左边全部 <= 3
```

它们肯定都：

```
< 5
```

所以这一整片区域全部排除：

```
left = mid + 1;
```

---

## ⑥ 为什么 `right = nums.size()`？

这个地方非常重要。

假设：

```
nums = [1,3,5,6]
target = 7
```

正确插入位置是：

```
下标 4
```

也就是数组最后面：

```
1 3 5 6 [7]
        ↑
        4
```

所以答案有可能等于：

```
nums.size()
```

因此搜索区间必须允许：

```
right = nums.size();
```

最终：

```
left == 4
```

然后直接返回。

---

## ⑦ 这题不需要递归

二分查找当然可以写递归，但这题完全没必要。

迭代写法：

```
while (left < right)
```

更短、更直观，而且：

```
时间 O(log n)
空间 O(1)
```

所以面试推荐迭代二分。

---

## ⑧ 面试追问

这题最容易问的就是：为什么时间复杂度是 `O(log n)`？

因为每一次二分都会把搜索范围缩小一半。

例如长度：

```
16
```

经过：

```
16
↓
8
↓
4
↓
2
↓
1
```

只需要大约 4 次。

因此：

```
时间复杂度 O(log n)
空间复杂度 O(1)
```

另外，如果面试官问：

> 这和 `lower_bound` 有什么关系？

可以直接回答：

> 这道题本质就是 `lower_bound`：寻找有序数组中第一个 `>= target` 的位置。
