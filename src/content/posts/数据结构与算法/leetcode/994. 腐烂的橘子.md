这道题最适合使用：
> **多源 BFS（广度优先搜索）+ 按层统计时间**

它和上一题“岛屿数量”都属于网格搜索，但目的不同：
```
200. 岛屿数量：
从一块陆地出发，找到整座岛。

201. 腐烂的橘子：
从所有腐烂橘子同时出发，计算感染全部新鲜橘子的最短时间。
```
这题不推荐递归 DFS。DFS 可以判断哪些橘子最终能够腐烂，却不适合直接计算“所有腐烂橘子同时扩散时的最短分钟数”。

---
## ① 破题：题目真正要求什么

网格中有三种状态：
```
0：空格
1：新鲜橘子
2：腐烂橘子
```
每过一分钟，腐烂橘子会让自己上下左右相邻的新鲜橘子腐烂。

例如：
```
初始：
2 1 1
1 1 0
0 1 1
```
第 1 分钟：
```
2 2 1
2 1 0
0 1 1
```
第 2 分钟：
```
2 2 2
2 2 0
0 1 1
```
第 3 分钟：
```
2 2 2
2 2 0
0 2 1
```
第 4 分钟：
```
2 2 2
2 2 0
0 2 2
```
所以答案是：
```
4
```

题目要求的是：
> 所有新鲜橘子全部腐烂所需的最少分钟数。

如果存在永远无法被感染的新鲜橘子，则返回：
```
-1
```

---
## ② 核心技巧：多源 BFS

普通 BFS 通常只有一个起点。

例如岛屿数量中：
```
q.push({row, col});
```
从一块陆地向外扩散。
但这题可能一开始就有多个腐烂橘子：
```
2 1 1 2
```
这些腐烂橘子在现实中是**同时开始传播**的。

因此不能：
```
先从第一个腐烂橘子完整 BFS
再从第二个腐烂橘子 BFS
```
否则无法正确模拟“同时扩散”。

正确做法是：
> 一开始把所有腐烂橘子全部放入同一个队列。

```cpp
queue<pair<int, int>> q;

for (...) {
    if (grid[row][col] == 2) {
        q.push({row, col});
    }
}
```
这叫：
```
多源 BFS
```
它们共同构成第 0 分钟的起点。

---
## 为什么 BFS 的一层就是一分钟？

假设初始腐烂橘子都在队列中：
```
队列：[第 0 分钟已经腐烂的橘子]
```
处理完当前队列中的所有节点后，新加入队列的是：
```
第 1 分钟腐烂的橘子
```
下一轮处理它们时，新加入的是：
```
第 2 分钟腐烂的橘子
```
所以：
```
BFS 第 1 层扩散 = 经过 1 分钟
BFS 第 2 层扩散 = 经过 2 分钟
BFS 第 3 层扩散 = 经过 3 分钟
```
因此必须像二叉树层序遍历那样记录：
```cpp
int size = q.size();
```

每轮只处理当前这一分钟已经腐烂的橘子。
## 解题思路
1. 该题也主要是要考虑遍历图的问题，所以就得思考是层次遍历还是深度遍历，根据题意可知需要的是层次遍历。
2. 然后如何去解决的问题呢，这就得思考，层次遍历一般直接考虑队列数据结构，然后要想可能会出现哪些结果，例如刚开始就全部是腐烂橘子，那就直接返回，或者多少分钟后橘子才全部腐烂，或者是无论多久总有橘子不会被腐烂，所以这个时候就得考虑加个fresh橘子的数量来协助判断是哪种情况
3. 然后多个腐烂橘子是得同时进行的腐烂其它鲜橘子的，所以这个也得处理

## ④ 完整代码：多源 BFS

```cpp
class Solution {
public:
    int orangesRotting(vector<vector<int>>& grid) {
        int rows = grid.size();
        int cols = grid[0].size();

        queue<pair<int, int>> q;
        int fresh = 0;

        // 1. 统计新鲜橘子，并把所有腐烂橘子加入队列
        for (int row = 0; row < rows; ++row) {
            for (int col = 0; col < cols; ++col) {
                if (grid[row][col] == 1) {
                    fresh++;
                } else if (grid[row][col] == 2) {
                    q.push({row, col});
                }
            }
        }

        // 如果一开始就没有新鲜橘子，不需要等待
        if (fresh == 0) {
            return 0;
        }

        int directions[4][2] = {
            {-1, 0}, // 上
            {1, 0},  // 下
            {0, -1}, // 左
            {0, 1}   // 右
        };

        int minutes = 0;

        // fresh > 0 可以避免处理完后多计算一分钟
        while (!q.empty() && fresh > 0) {
            int size = q.size();

            // 当前这一层代表同一分钟内进行扩散
            for (int i = 0; i < size; ++i) {
                auto [currentRow, currentCol] = q.front();
                q.pop();

                for (auto& direction : directions) {
                    int nextRow =
                        currentRow + direction[0];

                    int nextCol =
                        currentCol + direction[1];

                    // 越界
                    if (nextRow < 0 || nextRow >= rows ||
                        nextCol < 0 || nextCol >= cols) {
                        continue;
                    }

                    // 只感染新鲜橘子
                    if (grid[nextRow][nextCol] != 1) {
                        continue;
                    }

                    // 入队时立刻标记为腐烂
                    grid[nextRow][nextCol] = 2;
                    fresh--;

                    q.push({nextRow, nextCol});
                }
            }

            // 当前一整层扩散完成，经过一分钟
            minutes++;
        }

        // 还有新鲜橘子，说明存在无法感染的位置
        return fresh == 0 ? minutes : -1;
    }
};
```

## ⑤ 关键设计解释

### 1. 为什么所有腐烂橘子都要先入队？

因为它们在第 0 分钟已经腐烂，并且会同时向四周扩散。

例如：

```text
2 1 1 1 2
```

左右两边的腐烂橘子应该同时传播。

初始队列：

```text
[(左边腐烂橘子), (右边腐烂橘子)]
```

这样 BFS 每一层才能正确表示“一分钟内所有腐烂橘子的同时传播”。

---

### 2. 为什么要统计 `fresh`？

```cpp
int fresh = 0;
```

它表示当前还剩多少个新鲜橘子。

每感染一个：

```cpp
fresh--;
```

最后：

```cpp
return fresh == 0 ? minutes : -1;
```

如果队列已经空了，但 `fresh > 0`，说明剩下的橘子被空格或边界隔开，永远无法腐烂。

例如：

```text
2 1 1
0 1 1
1 0 1
```

左下角的 `1` 周围没有可以传播过来的路线，因此最终：

```text
fresh > 0
q.empty()
```

返回：

```text
-1
```

---

### 3. 为什么一定要记录 `size = q.size()`？

```cpp
int size = q.size();
```

用于固定当前一分钟要处理的橘子数量。

在处理过程中，新腐烂的橘子会加入队列，但它们必须等到下一分钟才能继续传播。

例如：

```text
2 1 1
```

正确过程：

```text
第 1 分钟：
2 2 1

第 2 分钟：
2 2 2
```

如果不分层，新感染的中间橘子可能在同一轮中立刻感染最右边橘子，就会错误地认为只需要一分钟。

所以：

```text
当前层节点：这一分钟前已经腐烂
新入队节点：下一分钟才能继续感染
```

---

### 4. 为什么在入队时立刻改成 `2`？

```cpp
grid[nextRow][nextCol] = 2;
q.push({nextRow, nextCol});
```

和“岛屿数量”一样，节点第一次被发现时就必须标记。

否则一个新鲜橘子可能被多个腐烂橘子重复发现、重复入队，并导致：

```text
fresh 被重复减少
```

例如：

```text
2 1 2
```

中间的新鲜橘子会同时被左右两边发现。

第一次发现时立即改成 `2`，第二次再检查时：

```cpp
grid[nextRow][nextCol] != 1
```

就不会重复处理。

---

### 5. 为什么 `minutes++` 在一整层结束后？

一整层代表：

> 当前一分钟内，所有已经腐烂的橘子同时完成扩散。

所以要在：

```cpp
for (int i = 0; i < size; ++i)
```

全部执行完成后，再：

```cpp
minutes++;
```

不能每处理一个橘子就加一分钟。

一分钟内可能有很多个腐烂橘子同时传播。

---

### 6. 为什么循环条件加上 `fresh > 0`？

代码写成：

```cpp
while (!q.empty() && fresh > 0)
```

可以避免所有新鲜橘子已经腐烂后，又继续处理最后一批新入队的腐烂橘子，导致分钟数多加一次。

例如：

```text
2 1
```

初始：

```text
fresh = 1
q = [腐烂橘子]
minutes = 0
```

第一轮将新鲜橘子感染：

```text
fresh = 0
minutes = 1
```

此时队列中虽然还有刚腐烂的橘子，但已经没有新鲜橘子需要传播了。

由于：

```text
fresh > 0
```

不成立，循环直接停止，答案正确为 `1`。

---

### 7. 为什么一开始没有新鲜橘子要返回 0？

例如：

```text
0 2
```

本来就没有新鲜橘子，因此不需要经过任何时间：

```cpp
if (fresh == 0) {
    return 0;
}
```

不能返回 `-1`，因为题目要求的目标已经满足。

---

## ⑥ 为什么不推荐递归 DFS？

DFS 可以从某个腐烂橘子向外传播，但本题有两个困难。

### 多个腐烂橘子同时传播

例如：

```text
2 1 1 1 2
```

传播时间应由离某个腐烂橘子最近的距离决定。

DFS 如果从左边先完整搜索，可能先为很多格子设置较大的时间；之后从右边搜索时，还需要重新比较和更新。

### 需要求最短感染时间

本质上，每个新鲜橘子的腐烂时间是：

```text
它到最近初始腐烂橘子的最短距离
```

无权图中的多源最短距离问题，最自然的算法就是多源 BFS。

因此本题：

```text
DFS：
可以判断可达性，但不适合直接按最短时间分层。

BFS：
天然按距离一层一层扩散，每层就是一分钟。
```

---

## ⑦ BFS 模板与岛屿数量的区别

你上一题的 BFS 是：

```text
发现一个新岛
→ 单独创建队列
→ 遍历整座岛
→ 再继续找下一座岛
```

本题是：

```text
先把所有腐烂橘子统一入队
→ 所有起点同时 BFS
→ 每层代表一分钟
```

对比：

```text
200 岛屿数量：
多次单源 BFS，每次处理一个连通块。

994 腐烂的橘子：
一次多源 BFS，所有腐烂橘子同时扩散。
```

## ⑧ 面试追问

### Q1：为什么这是多源 BFS？

因为网格中所有初始值为 `2` 的橘子，都是传播起点，并且它们同时开始腐烂周围橘子。

所以需要在 BFS 开始前，把所有起点一起放入队列。

---

### Q2：时间复杂度是多少？

每个网格最多：

```text
入队一次
出队一次
```

设网格为 `m × n`：

```text
时间复杂度：O(m × n)
```

队列最坏可能保存大量橘子：

```text
空间复杂度：O(m × n)
```

---

### Q3：为什么 BFS 可以保证分钟数最少？

BFS 按距离逐层扩散：

```text
距离初始腐烂橘子 1 格的，第一分钟腐烂
距离 2 格的，第二分钟腐烂
距离 3 格的，第三分钟腐烂
```

第一次到达某个橘子时，就是从任意初始腐烂橘子到它的最短距离，因此得到的是最短时间。

---

### Q4：如果没有腐烂橘子，但有新鲜橘子呢？

例如：

```text
1 1
```

初始队列为空：

```text
q.empty()
```

但：

```text
fresh > 0
```

无法进行任何传播，最终返回：

```text
-1
```

---

### 面试表达

> 我使用多源 BFS。首先遍历网格，将所有初始腐烂橘子加入队列，并统计新鲜橘子的数量。因为所有腐烂橘子同时开始传播，所以它们共同构成 BFS 的第 0 层。之后按层处理队列，每一层代表一分钟；对于每个腐烂橘子，将上下左右的新鲜橘子标记为腐烂、加入队列，并减少新鲜橘子数量。当一层处理结束后分钟数加一。最终如果新鲜橘子数量为 0，就返回分钟数，否则返回 -1。时间复杂度是 `O(mn)`。

## ⑨ 复习总结

```
994. 腐烂的橘子

题型：
网格搜索 + 多源 BFS + 最短传播时间。

为什么用多源 BFS：
所有初始腐烂橘子同时传播，
所以一开始全部加入同一个队列。

准备工作：
1. 所有 grid[row][col] == 2 的位置入队。
2. 统计新鲜橘子数量 fresh。

BFS：
1. 每轮记录 size = q.size()。
2. size 个节点表示当前一分钟的腐烂橘子。
3. 搜索上下左右。
4. 如果相邻位置是 1：
   - 修改为 2；
   - fresh--；
   - 加入队列。
5. 当前层结束，minutes++。

最终：
fresh == 0，返回 minutes；
fresh > 0，返回 -1。
```

一句话记忆：

> **所有腐烂橘子一起入队做多源 BFS，每扩散一层就是一分钟，用 `fresh` 判断是否存在永远无法腐烂的橘子。**
