## 解题思路


这道题是你进入 **动态规划 DP** 非常重要的一道入门题。
这题最推荐：

> **动态规划：先写 `dp` 数组理解状态转移，再优化成两个变量。**

递归虽然非常容易想到，而且正好能帮助推导状态转移方程，但普通递归会产生大量重复计算，时间复杂度接近指数级，所以**不推荐作为最终解法**。

---

# ① 破题：题目真正要求什么

有 `n` 阶楼梯。
每次只能选择：
```text
爬 1 阶
或者
爬 2 阶
```

问：

> 到达第 `n` 阶，一共有多少种不同的方法？

例如：
```text
n = 2
```
有：
```text
1 + 1
2
```
所以：
```text
答案 = 2
```

---

如果：
```text
n = 3
```
有：
```text
1 + 1 + 1
1 + 2
2 + 1
```
所以：
```text
答案 = 3
```
注意：
```text
1 + 2
2 + 1
```
是两种不同方案，因为爬楼顺序不同。

---

# ② 核心技巧：不要正着枚举，想“最后一步”

这是动态规划中特别重要的思考方式：
> **到达当前状态之前，最后一步可能从哪里来？**

假设我们现在要到第 `n` 阶。

最后一步只有两种可能。
### 情况 1：最后爬了 1 阶
那么之前一定站在：
```text
第 n - 1 阶
```

到达 `n-1` 阶的方法数假设是：

```text
dp[n - 1]
```

---

### 情况 2：最后爬了 2 阶

那么之前一定站在：

```text
第 n - 2 阶
```

方法数：

```text
dp[n - 2]
```

---

而这两种情况不会重复，因此：

```text
到达 n 阶的方法数
=
到达 n-1 阶的方法数
+
到达 n-2 阶的方法数
```

所以状态转移方程是：

```cpp
dp[i] = dp[i - 1] + dp[i - 2];
```

这就是整道题最核心的一行。

---

# ③ 图解执行过程

例如：

```text
n = 5
```

我们逐层计算。

## 第 1 阶

只有：

```text
1
```

所以：

```text
dp[1] = 1
```

---

## 第 2 阶

有：

```text
1 + 1
2
```

所以：

```text
dp[2] = 2
```

---

## 第 3 阶

要到第 3 阶：

```text
从第 2 阶爬 1 阶
或者
从第 1 阶爬 2 阶
```

所以：

```text
dp[3]
= dp[2] + dp[1]
= 2 + 1
= 3
```

---

## 第 4 阶

```text
dp[4]
= dp[3] + dp[2]
= 3 + 2
= 5
```

---

## 第 5 阶

```text
dp[5]
= dp[4] + dp[3]
= 5 + 3
= 8
```

最终：

```text
阶数：  1   2   3   4   5

方法：  1   2   3   5   8
```

你会发现：

> 这实际上就是 Fibonacci 数列的变形。

# ④ 完整代码

第一次学习动态规划，我建议你**先写 dp 数组版本**，因为最容易看懂。

```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) {
            return n;
        }

        vector<int> dp(n + 1);

        dp[1] = 1;
        dp[2] = 2;

        for (int i = 3; i <= n; ++i) {
            dp[i] = dp[i - 1] + dp[i - 2];
        }

        return dp[n];
    }
};
```

这个版本就是最标准的动态规划。

# ⑤ 关键设计解释

## 1. `dp[i]` 到底表示什么？

这是学习 DP 最重要的问题。

一定要先给 `dp[i]` 一个明确含义：

> `dp[i]` 表示爬到第 `i` 阶楼梯一共有多少种方法。

例如：

```text
dp[3] = 3
```

表示：

> 到达第 3 阶一共有 3 种方案。

而不是：

```text
爬了多少步
当前在哪
还能爬多少
```

---

## 2. 为什么是：

```cpp
dp[i] = dp[i - 1] + dp[i - 2];
```

因为到达第 `i` 阶的最后一步：

```text
要么从 i-1 爬 1 阶过来
要么从 i-2 爬 2 阶过来
```

第一类方案数量：

```text
dp[i - 1]
```

第二类方案数量：

```text
dp[i - 2]
```

所以相加。

这里实际上是在做：

```text
按照“最后一步是什么”进行分类讨论。
```

这种思维以后在 DP 里会反复出现。

---

## 3. 为什么不是乘法？

有人刚学时可能会想：

```cpp
dp[i - 1] * dp[i - 2]
```

但这里是两个**互斥方案集合**：

```text
最后一步爬 1 阶的所有方案
+
最后一步爬 2 阶的所有方案
```

所以是加法。

可以简单理解：

> “或者”通常对应方案数相加。

---

## 4. 为什么初始化：

```cpp
dp[1] = 1;
dp[2] = 2;
```

因为状态转移：

```cpp
dp[i] = dp[i - 1] + dp[i - 2];
```

必须从已经知道的最小问题开始推。

第 1 阶：

```text
只有 1
```

所以：

```cpp
dp[1] = 1;
```

第 2 阶：

```text
1+1
2
```

所以：

```cpp
dp[2] = 2;
```

后面才能计算：

```text
dp[3]
dp[4]
dp[5]
...
```

这就是 DP 里的：

> **初始化 / 边界条件。**

---

# ⑥ 动态规划五个基本步骤

这道题非常适合用来学习一个通用 DP 思考模板。
### 第一步：定义状态
```text
dp[i] = 到达第 i 阶的方法数量
```
### 第二步：找状态转移
想最后一步：
```text
i-1 → i
i-2 → i
```
所以：
```cpp
dp[i] = dp[i - 1] + dp[i - 2];
```
### 第三步：初始化
```cpp
dp[1] = 1;
dp[2] = 2;
```
### 第四步：确定遍历顺序
因为：
```text
dp[i]
```
依赖前面的：
```text
dp[i-1]
dp[i-2]
```
所以必须从小到大：
```cpp
for (int i = 3; i <= n; ++i)
```
### 第五步：确定答案
题目问第 `n` 阶，所以：
```cpp
return dp[n];
```
以后你学动态规划，可以先机械地问自己这五个问题。

# ⑦ 空间优化：面试更推荐的最终写法

观察：
```cpp
dp[i] = dp[i - 1] + dp[i - 2];
```

计算 `dp[i]` 时只需要前两个状态。

比如算：
```text
dp[10]
```
根本不再需要：
```text
dp[1]
dp[2]
...
dp[7]
```
只需要：
```text
dp[8]
dp[9]
```
所以没必要保存整个数组。

可以只保留两个变量：
```cpp
class Solution {
public:
    int climbStairs(int n) {
        if (n <= 2) {
            return n;
        }

        int prev2 = 1;  // dp[i - 2]
        int prev1 = 2;  // dp[i - 1]

        for (int i = 3; i <= n; ++i) {
            int cur = prev1 + prev2;

            prev2 = prev1;
            prev1 = cur;
        }

        return prev1;
    }
};
```

---
## 这个代码怎么移动？

开始：
```text
prev2 = dp[1] = 1
prev1 = dp[2] = 2
```
计算：
```text
cur = dp[3] = 1 + 2 = 3
```
然后整体向前移动：
```text
prev2 = dp[2] = 2
prev1 = dp[3] = 3
```
再算：
```text
cur = dp[4] = 2 + 3 = 5
```
继续：
```text
prev2 = 3
prev1 = 5
```
实际上就是维护一个长度为 2 的“滑动窗口”。

---
# ⑧ 递归为什么能想到，但不推荐？

根据前面的分析，我们也可以直接写：
```cpp
int climb(int n) {
    if (n <= 2) {
        return n;
    }

    return climb(n - 1) + climb(n - 2);
}
```
逻辑本身完全正确。

因为：
```text
f(n) = f(n-1) + f(n-2)
```
但问题是会重复计算。

例如计算：
```text
f(5)
```
递归树：
```text
                f(5)
              /      \
           f(4)      f(3)
          /   \      /   \
       f(3)  f(2)  f(2) f(1)
       / \
    f(2) f(1)
```

你会发现：

```text
f(3)
f(2)
```

被重复计算很多次。

`n` 再大一些，重复会非常严重。

普通递归时间复杂度接近：

```text
O(2^n)
```

而动态规划：

```text
每个状态只计算一次
```

所以：

```text
O(n)
```

因此这题可以这样理解 DP 的来源：

```text
暴力递归
↓
发现重复子问题
↓
把结果保存下来
↓
动态规划
```

# ⑨ 面试追问

### Q1：为什么这是动态规划？

因为它具有两个明显特征：

```text
1. 重叠子问题
2. 当前状态依赖之前已经计算的状态
```

例如：

```text
dp[5]
依赖
dp[4] 和 dp[3]
```

而这些结果可以重复利用。

---

### Q2：时间复杂度是多少？

DP 数组：

```text
时间复杂度：O(n)
空间复杂度：O(n)
```

滚动变量优化后：

```text
时间复杂度：O(n)
空间复杂度：O(1)
```

---

### Q3：如果一次可以爬 1、2、3 阶呢？

最后一步就有三种情况：

```text
从 i-1 来
从 i-2 来
从 i-3 来
```

所以：

```cpp
dp[i] =
    dp[i - 1]
    + dp[i - 2]
    + dp[i - 3];
```

这也是为什么我希望你真正理解：

> **状态转移方程来自“最后一步有哪些可能”。**

而不是死记：

```cpp
dp[i] = dp[i-1] + dp[i-2]
```

---

### Q4：如果一次可以爬 `1~k` 阶呢？

同理：

```text
dp[i]
=
dp[i-1]
+ dp[i-2]
+ ...
+ dp[i-k]
```

只要下标合法。

所以这一题实际上可以帮你掌握一类：

> **计数型 DP / 路径方案数 DP。**

---
### 面试表达
> 我定义 `dp[i]` 表示到达第 `i` 阶楼梯的方法数。考虑到达第 `i` 阶的最后一步，只可能从第 `i-1` 阶爬 1 阶过来，或者从第 `i-2` 阶爬 2 阶过来，因此状态转移方程为 `dp[i] = dp[i-1] + dp[i-2]`。初始化 `dp[1]=1、dp[2]=2`，从小到大计算。由于每个状态只依赖前两个状态，还可以用两个变量将空间复杂度从 `O(n)` 优化到 `O(1)`。

---

```text
70. 爬楼梯

题型：
动态规划 / 计数型 DP。

状态定义：
dp[i] = 到达第 i 阶的方法数量。

破题关键：
不要枚举所有爬法，
而是考虑“到达第 i 阶的最后一步”。

最后一步：
从 i-1 爬 1 阶
或者
从 i-2 爬 2 阶

状态转移：
dp[i] = dp[i-1] + dp[i-2]

初始化：
dp[1] = 1
dp[2] = 2

遍历：
从 3 到 n。

答案：
dp[n]

复杂度：
DP 数组：O(n) 时间，O(n) 空间
滚动变量：O(n) 时间，O(1) 空间
```
这道题你尤其要形成一个 DP 习惯：
> **遇到“有多少种方法到达某个状态”，先不要想着把所有方案枚举出来，而是问：到达当前状态的最后一步，可以从哪些状态转移过来？**
