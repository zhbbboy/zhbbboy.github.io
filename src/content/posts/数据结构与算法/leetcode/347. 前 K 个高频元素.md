可以，这题用 `unordered_map + 小顶堆` 很合适，而且这是面试里非常经典的 Top K 解法。

核心思路就是：

> `unordered_map` 负责统计频率，`priority_queue` 维护“当前频率最高的 k 个元素”。

我们维护一个**小顶堆**，堆顶永远是这 k 个元素里“频率最低的那个”。

---

## ① 为什么是小顶堆？

比如统计结果：

```
1 -> 5次
2 -> 3次
3 -> 8次
4 -> 2次
5 -> 6次
```

假设：

```
k = 3;
```

我们最终想保留频率最高的 3 个：

```
3 -> 8
5 -> 6
1 -> 5
```

这 3 个里面，频率最小的是：

```
1 -> 5
```

它应该放在堆顶。

因为后面如果来了：

```
6 -> 7次
```

我们就可以很方便地比较：

```
7 > 堆顶的5
```

然后把最弱的 `1 -> 5` 踢出去。

所以：

> Top K 最大问题，常常维护一个大小为 k 的小顶堆。

---

# ② 第一步：unordered_map 统计频率

```
unordered_map<int, int> count;
```

遍历：

```
for (int num : nums) {
    count[num]++;
}
```

例如：

```
nums = [1,1,1,2,2,3]
```

最后：

```
count：

1 -> 3
2 -> 2
3 -> 1
```

---

# ③ 第二步：小顶堆应该存什么？

我们需要同时保存：

```
数字
频率
```

所以可以存：

```
pair<int, int>
```

比如：

```
{frequency, num}
```

也就是：

```
{3, 1}
{2, 2}
{1, 3}
```

我建议你这样存：

```
pair<int, int>
```

其中：

```
first  = frequency
second = num
```

这样小顶堆可以天然按 `first` 也就是频率排序。

---

# ④ 小顶堆怎么定义？

```
priority_queue<
    pair<int, int>,
    vector<pair<int, int>>,
    greater<pair<int, int>>
> pq;
```

你先不用害怕这串。

它的意思就是：

```
priority_queue<
    存什么,
    底层容器,
    怎么比较
>
```

所以：

```
pair<int, int>
```

表示存：

```
{频率, 数字}
```

```
vector<pair<int, int>>
```

是底层容器。

```
greater<pair<int, int>>
```

表示：

> 小的放堆顶。

因此：

```
pq.top()
```

就是当前频率最小的那个。

---

# ⑤ 为什么只维护 k 个元素？

代码：

```
for (auto& p : count) {
    int num = p.first;
    int freq = p.second;

    pq.push({freq, num});

    if (pq.size() > k) {
        pq.pop();
    }
}
```

这段是整题核心。

什么意思？

每来一个元素：

```
pq.push(...)
```

先放进去。

如果发现：

```
pq.size() > k
```

说明现在有：

```
k+1 个
```

那就删掉一个。

删谁？

```
pq.pop();
```

小顶堆会删：

> 当前频率最小的那个。

这样堆里始终保留：

> 频率最高的 k 个元素。

---

# ⑥ 用例子跑一遍

假设：

```
nums = [1,1,1,2,2,3]
k = 2
```

统计：

```
1 -> 3
2 -> 2
3 -> 1
```

开始堆为空。

### 放入 `1 -> 3`

```
pq.push({3,1});
```

堆：

```
(3,1)
```

大小：

```
1 <= 2
```

不弹。

---

### 放入 `2 -> 2`

```
pq.push({2,2});
```

堆里：

```
(2,2)
(3,1)
```

堆顶：

```
(2,2)
```

因为频率 2 最小。

大小：

```
2
```

刚好。

---

### 放入 `3 -> 1`

```
pq.push({1,3});
```

现在三个：

```
(1,3)
(3,1)
(2,2)
```

堆顶：

```
(1,3)
```

因为频率 1 最小。

此时：

```
pq.size() = 3 > k
```

所以：

```
pq.pop();
```

弹出：

```
(1,3)
```

剩下：

```
(2,2)
(3,1)
```

也就是：

```
2 -> 2次
1 -> 3次
```

正好是前 2 高频。

---

# ⑦ 最后怎么取答案？

堆里存的是：

```
{频率, 数字}
```

所以：

```
pq.top().second
```

才是数字。

代码：

```
vector<int> result;

while (!pq.empty()) {
    result.push_back(pq.top().second);
    pq.pop();
}
```

最后：

```
return result;
```

题目允许：

> 任意顺序返回。

所以不用再排序。

---

# ⑧ 完整代码

推荐你掌握这个版本：

```cpp
class Solution {
public:
    vector<int> topKFrequent(vector<int>& nums, int k) {
        unordered_map<int, int> count;

        // 1. 统计频率
        for (int num : nums) {
            count[num]++;
        }

        // 2. 小顶堆
        // pair.first  = 频率
        // pair.second = 数字
        priority_queue<
            pair<int, int>,
            vector<pair<int, int>>,
            greater<pair<int, int>>
        > pq;

        // 3. 维护大小为 k 的小顶堆
        for (auto& p : count) {
            int num = p.first;
            int freq = p.second;

            pq.push({freq, num});

            if (pq.size() > k) {
                pq.pop();
            }
        }

        // 4. 取出答案
        vector<int> result;

        while (!pq.empty()) {
            result.push_back(pq.top().second);
            pq.pop();
        }

        return result;
    }
};
```

---

# ⑨ 为什么 `greater<pair<int,int>>` 可以直接用？

`pair` 默认是按字典序比较的。

先比较：

```
first
```

如果 `first` 相同，再比较：

```
second
```

我们存：

```
{freq, num}
```

所以主要就是按：

```
frequency
```

比较。

例如：

```
{2,100}
{5,1}
```

显然：

```
{2,100} < {5,1}
```

因为先比较第一个：

```
2 < 5
```

因此小顶堆顶部就是频率更小的那个。

---

# ⑩ 为什么不是大顶堆？

如果用大顶堆，当然也能做。

比如把所有：

```
{freq,num}
```

全部放进去，然后：

```
pop k 次
```

也能拿到前 k 高频。

但是如果不同元素很多，堆大小可能达到：

```
O(n)
```

而我们现在的小顶堆始终只保留：

```
k 个
```

所以空间：

```
O(k)
```

堆操作也是：

```
O(log k)
```

更符合 Top K 的经典写法。

---

# ⑪ 时间复杂度

假设有：

```
n 个数组元素
m 个不同元素
```

第一步统计：

```
O(n)
```

第二步遍历 hashmap，一共 m 个不同元素。

每个元素最多做：

```
push/pop
```

而堆大小最多 k：

```
O(log k)
```

所以：

```
O(m log k)
```

因为：

```
m <= n
```

所以总体：

```
O(n log k)
```

空间复杂度：

```
unordered_map：O(n)
heap：O(k)

总空间：
O(n)
```

---

# ⑫ 面试时可以怎么说

你可以这样回答：

> 先用 `unordered_map` 统计每个元素的出现频率，然后维护一个大小为 `k` 的小顶堆，堆中存 `{频率, 元素}`。遍历所有不同元素时先入堆，如果堆大小超过 `k`，就弹出频率最小的元素。这样最终堆里剩下的就是频率最高的 `k` 个元素，时间复杂度为 `O(n log k)`。

# ⑬ 这题一句话记忆

```
Top K 高频：

unordered_map
→ 统计频率

小顶堆大小保持 k
→ 堆顶是这 k 个里频率最低的

新元素进来
→ 超过 k
→ pop 最低频

最后剩下
→ 前 k 高频
```

所以你以后看到：

```
前 K 大
前 K 高频
Top K
```

首先就应该想到：

> **大小为 k 的小顶堆。**
