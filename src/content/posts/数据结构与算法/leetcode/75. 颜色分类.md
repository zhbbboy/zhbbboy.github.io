这题最推荐你掌握：
> **三指针 + 荷兰国旗算法（Dutch National Flag）**

因为题目进阶要求：
- 原地修改
- 常数空间
- 一趟扫描

而这道题刚好只有：

```
0
1
2
```

三种数字，非常适合把数组划分成三个区域。

---

## ① 破题：题目真正要求什么

例如：

```
nums = [2,0,2,1,1,0]
```

最终要求：

```
[0,0,1,1,2,2]
```

也就是：

```
所有 0 放左边
所有 1 放中间
所有 2 放右边
```

你当然可以统计：
```
0 有几个
1 有几个
2 有几个
```

然后重新覆盖数组。

这可以做到：
```
时间 O(n)
空间 O(1)
```

但是需要两趟。

题目的进阶想让你做到：

> **一次遍历完成。**

所以我们使用三个指针。

---

# ② 核心技巧：三个指针

定义：
```
int left = 0;
int cur = 0;
int right = nums.size() - 1;
```

它们分别表示：

```
left
→ 下一个 0 应该放的位置

cur
→ 当前正在检查的位置

right
→ 下一个 2 应该放的位置
```

整个数组始终可以理解成：
```
0区域 | 1区域 | 未处理区域 | 2区域
```

更精确一点：

```
[0, left-1]       全部是0

[left, cur-1]     全部是1

[cur, right]      还没处理

[right+1, n-1]    全部是2
```

这就是整道题最核心的不变量。

---

# ③ 三种情况分别怎么办？

我们只看：

```
nums[cur]
```

---

## 情况一：`nums[cur] == 0`

0 应该去最左边。

所以：

```
swap(nums[cur], nums[left]);
```

然后：

```
left++;
cur++;
```

---

## 情况二：`nums[cur] == 1`

1 本来就应该待在中间。

所以什么都不用交换：

```
cur++;
```

---

## 情况三：`nums[cur] == 2`

2 应该去最右边。

所以：

```
swap(nums[cur], nums[right]);
```

然后：

```
right--;
```

注意：

> **这里不能 `cur++`。**

这是这题最容易错的地方，后面重点讲。

---

# ④ 完整代码

```cpp
class Solution {
public:
    void sortColors(vector<int>& nums) {
        int left = 0;
        int cur = 0;
        int right = nums.size() - 1;

        while (cur <= right) {

            if (nums[cur] == 0) {
                swap(nums[cur], nums[left]);

                ++left;
                ++cur;
            }

            else if (nums[cur] == 1) {
                ++cur;
            }

            else {  // nums[cur] == 2
                swap(nums[cur], nums[right]);

                --right;
            }
        }
    }
};
```

这就是标准的一趟扫描写法。

# ⑤ 用 `[2,0,2,1,1,0]` 完整跑一遍

初始：

```
nums = [2,0,2,1,1,0]

        ↑         ↑
      cur       right
        ↑
      left
```

所以：

```
left = 0
cur = 0
right = 5
```

---

## 第一次：`nums[cur] = 2`

当前：

```
[2,0,2,1,1,0]
 ↑         ↑
cur       right
```

2 应该去右边。

所以：

```
swap(nums[cur], nums[right]);
```

交换下标 0 和 5：

```
[0,0,2,1,1,2]
 ↑       ↑
cur     right
```

然后：

```
right--;
```

得到：

```
right = 4
```

但是：

```
cur 仍然 = 0
```

为什么？

因为刚刚从右边交换过来的：

```
nums[0] = 0
```

还没有处理。

---

## 第二次：还是看 `cur = 0`

现在：

```
nums[cur] = 0
```

0 应该放左边。

此时：

```
left = 0
cur = 0
```

所以：

```
swap(nums[0], nums[0]);
```

其实自己和自己交换。

然后：

```
left++;
cur++;
```

得到：

```
left = 1
cur = 1
right = 4
```

数组：

```
[0,0,2,1,1,2]
   ↑     ↑
 left   right
   ↑
  cur
```

---

## 第三次：`nums[cur] = 0`

当前：

```
cur = 1
```

还是：

```
0
```

所以：

```
swap(nums[1], nums[left]);
```

因为：

```
left = 1
```

还是自己交换。

然后：

```
left = 2
cur = 2
```

数组不变：

```
[0,0,2,1,1,2]
```

---

## 第四次：`nums[cur] = 2`

现在：

```
cur = 2
right = 4
```

数组：

```
[0,0,2,1,1,2]
     ↑   ↑
    cur right
```

遇到 2：

```
swap(nums[2], nums[4]);
```

变成：

```
[0,0,1,1,2,2]
     ↑ ↑
    cur right
```

然后：

```
right--;
```

所以：

```
right = 3
cur = 2
```

---

## 第五次：`nums[cur] = 1`

现在：

```
nums[2] = 1
```

1 本来就在中间。

所以：

```
cur++;
```

得到：

```
cur = 3
```

---

## 第六次：`nums[cur] = 1`

继续：

```
cur++;
```

得到：

```
cur = 4
right = 3
```

此时：

```
cur > right
```

结束。

最终：

```
[0,0,1,1,2,2]
```

# ⑥ 最关键：为什么遇到 2 后不能 `cur++`？

这题最值得理解的就是这里。

假设：

```
nums = [2,0,1]
```

初始：

```
left = 0
cur = 0
right = 2
```

当前：

```
nums[cur] = 2
```

所以交换：

```
swap(nums[0], nums[2]);
```

得到：

```
[1,0,2]
 ↑
cur
```

注意：

> 从右边换过来的这个 `1`，我们之前根本没检查过。

所以必须继续检查：

```
cur = 0
```

的这个新元素。

如果你错误地：

```
cur++;
```

那么直接去：

```
cur = 1
```

刚刚交换过来的：

```
nums[0] = 1
```

就被跳过了。

这个例子刚好最终没错，但如果交换过来的是 0，问题就更明显。

例如：

```
[2,1,0]
```

交换 2 和 0：

```
[0,1,2]
 ↑
cur
```

这个新来的 0 应该被放到左边区域。

因此必须再次检查。

所以：

```
nums[cur] == 2
```

时：

```
swap(nums[cur], nums[right]);
--right;

// cur不动
```

---

# ⑦ 那为什么遇到 0 之后可以 `cur++`？

你可能会问：

> 0 也是交换，为什么 0 交换后 `cur` 就可以前进？

这是因为：

```
swap(nums[cur], nums[left]);
```

时，从 `left` 换到 `cur` 的那个元素：

> **一定已经处理过了。**

为什么？

因为数组区域是：

```
0区 | 1区 | 未处理区 | 2区
```

即：

```
[0,left-1]      0
[left,cur-1]    1
[cur,right]     未处理
```

所以：

```
left 到 cur-1
```

之间已经全都是 1。

当 `cur` 位置发现一个 0：

```
... 1 1 1 | 0 ...
    ↑       ↑
   left    cur
```

交换：

```
... 0 1 1 | 1 ...
```

从 `left` 换到 `cur` 的一定是：

```
1
```

而 1 已经是正确的中间元素。

因此：

```
++left;
++cur;
```

都可以。

---

# ⑧ 这就是为什么左右两种交换不对称

你可以直接记：

### 遇到 0

```
swap(nums[cur], nums[left]);
left++;
cur++;
```

因为：

> 从左边换过来的东西已经处理过。

---

### 遇到 2

```
swap(nums[cur], nums[right]);
right--;
```

因为：

> 从右边换过来的东西还没处理过，所以 `cur` 不能动。

这是整道题最高频的面试追问。

---

# ⑨ 为什么循环条件是 `cur <= right`？

因为：

```
[cur, right]
```

表示：

> 尚未处理的区域。

只要：

```
cur <= right
```

说明至少还有一个元素没处理。

当：

```
cur > right
```

说明：

```
未处理区域已经为空
```

此时数组已经变成：

```
0区 | 1区 | 2区
```

所以结束。

---

# ⑩ 三个指针到底指什么，再总结一次

不要把：

```
left
cur
right
```

理解成普通左右指针。

它们真正表示的是：

```
left
→ 下一个0应该放的位置

cur
→ 当前正在检查的位置

right
→ 下一个2应该放的位置
```

并且始终维护：

```
0                left
|----------------|
全部0


left            cur
|---------------|
全部1


cur             right
|---------------|
未知区域


right+1          n-1
|----------------|
全部2
```

---

# ⑪ 为什么这是“荷兰国旗问题”？

经典 Dutch National Flag Problem 就是：

> 把三种元素原地划分成三个区域。

本题：

```
0
1
2
```

刚好对应三种颜色：

```
红
白
蓝
```

最终：

```
0区 | 1区 | 2区
```

所以这就是标准荷兰国旗算法。

---

# ⑫ 还有更简单的方法：计数

如果面试官没有要求：

```
一趟扫描
```

其实最容易的方法是：

```
int count0 = 0;
int count1 = 0;
int count2 = 0;
```

第一遍统计：

```
for (int num : nums) {
    if (num == 0) ++count0;
    else if (num == 1) ++count1;
    else ++count2;
}
```

然后重新填：

```
count0 个0

count1 个1

count2 个2
```

同样：

```
时间 O(n)
空间 O(1)
```

但是：

```
需要两趟
```

而三指针：

```
一趟 O(n)
```

更符合进阶要求。

---

# ⑬ 递归是否适合？

不适合。

这是典型的：

```
数组原地划分
+
三指针
```

没有任何必要用递归。

---

# ⑭ 面试追问

这题最需要会回答三个问题：

**1. 为什么 `cur` 遇到 2 不前进？**

因为从右侧未处理区交换过来的元素还没检查。

**2. 为什么遇到 0 可以前进？**

因为 `left ~ cur-1` 已经全部是 1，从左边交换过来的元素已经处理过。

**3. 为什么是 O(n)？**

虽然有交换，但每次：

```
cur向右
或者
right向左
```

未处理区都会缩小，因此每个元素最多被处理常数次。

时间：

```
O(n)
```

空间：

```
O(1)
```
