这题是二分查找里比较难的一道。它和前面的二分题不太一样：

> 不是在数组里“找某个数”，而是在**找一个正确的分割位置**。

题目要求时间复杂度：

```
O(log(m+n))
```

所以不能真的把两个数组合并后再找中位数。最推荐的方法是：

> **在较短数组上二分，寻找两个数组的正确分割位置。**

---

# ① 破题：题目真正要求什么

例如：

```
nums1 = [1,3]
nums2 = [2]
```

如果真的合并：

```
[1,2,3]
```

中位数就是：

```
2
```

再例如：

```
nums1 = [1,2]
nums2 = [3,4]
```

合并：

```
[1,2,3,4]
```

中间两个数：

```
2 和 3
```

所以：

```
(2 + 3) / 2 = 2.5
```

因此中位数的本质就是：

> 把所有元素分成左右两部分，使左边元素数量和右边差不多，并且左边所有数都 ≤ 右边所有数。

---

# ② 核心技巧：不用真的合并，只找“分割线”

假设：

```
nums1 = [1,3]
nums2 = [2]
```

我们想在两个数组中分别切一刀：

```
nums1:

1 | 3


nums2:

2 |
```

合起来左边：

```
1 2
```

右边：

```
3
```

于是：

```
左边最大值 = 2
右边最小值 = 3
```

因为总数是奇数：

```
3个元素
```

所以中位数就是：

```
左边最大值 = 2
```

也就是说：

> 我们真正要找的是两个数组各切在哪里。

---

# ③ 分割以后需要满足什么条件？

设：

```
i = nums1 的分割位置
j = nums2 的分割位置
```

例如：

```
nums1 = [1,3]

       i=1
        ↓
[ 1 | 3 ]


nums2 = [2]

        j=1
         ↓
[ 2 | ]
```

我们定义四个值：

```
Aleft   = nums1 分割线左边最大的数
Aright  = nums1 分割线右边最小的数

Bleft   = nums2 分割线左边最大的数
Bright  = nums2 分割线右边最小的数
```

这个例子中：

```
Aleft  = 1
Aright = 3

Bleft  = 2
Bright = +∞
```

为什么 `Bright = +∞`？

因为 nums2 右边没有元素。

---

正确分割必须满足：

```
Aleft <= Bright

并且

Bleft <= Aright
```

为什么？

因为我们需要保证：

> 左半部分所有数都不能比右半部分的数大。

由于每个数组内部本来就是有序的，所以只需要检查这两个“交叉边界”。

---

# ④ 左右两边数量怎么保证？

这是第二个核心。

假设总共有：

```
m + n
```

个元素。

我们希望左边数量：

```
(m + n + 1) / 2
```

为什么要 `+1`？

因为如果总数是奇数，我们让：

> 左边比右边多一个元素。

例如总共 5 个：

```
左边3个
右边2个
```

那么中位数直接就是：

```
左边最大值
```

---

假设 nums1 左边切出：

```
i 个元素
```

那么 nums2 左边必须切：

```
j = (m + n + 1) / 2 - i;
```

这样就能保证：

```
i + j = 左半部分应该拥有的元素数量
```

所以：

> 我们只需要二分 `i`，`j` 就能直接算出来。

这就是为什么只需要在一个数组上做二分。

---

# ⑤ 图解完整执行过程

先用：

```
nums1 = [1,3]
nums2 = [2]
```

为了方便，我们始终让：

```
nums1 是较短数组
```

所以交换一下：

```
A = [2]
B = [1,3]
```

长度：

```
m = 1
n = 2
```

我们在 `A` 上二分分割位置。

---

初始：

```
left = 0;
right = m;
```

也就是：

```
left = 0
right = 1
```

计算：

```
i = left + (right - left) / 2;
```

得到：

```
i = 0
```

那么：

```
j = (m+n+1)/2 - i;
```

代入：

```
j = (1+2+1)/2 - 0
  = 2
```

现在分割：

```
A = [ | 2 ]

B = [1,3 | ]
```

四个值：

```
Aleft  = -∞
Aright = 2

Bleft  = 3
Bright = +∞
```

检查：

```
Aleft <= Bright

-∞ <= +∞
成立
```

但是：

```
Bleft <= Aright

3 <= 2
不成立
```

什么意思？

说明：

> A 左边元素太少了。

因为 B 左边最大的 `3` 都跑到左半边了，而 A 右边还有更小的 `2`。

所以应该让：

```
A 多拿一些元素到左边
```

即：

```
left = i + 1;
```

---

下一轮：

```
left = 1
right = 1
```

所以：

```
i = 1
```

那么：

```
j = 2 - 1 = 1
```

分割：

```
A = [2 | ]

B = [1 | 3]
```

四个值：

```
Aleft  = 2
Aright = +∞

Bleft  = 1
Bright = 3
```

检查：

```
Aleft <= Bright

2 <= 3
成立
```

以及：

```
Bleft <= Aright

1 <= +∞
成立
```

找到正确分割。

总元素数：

```
3
```

是奇数。

所以：

```
median = max(Aleft, Bleft)
       = max(2,1)
       = 2
```

答案：

```
2
```

---

# ⑥ 完整代码

推荐掌握这一版：

```cpp
class Solution {
public:
    double findMedianSortedArrays(vector<int>& nums1,
                                  vector<int>& nums2) {
        // 始终让 nums1 是较短数组
        if (nums1.size() > nums2.size()) {
            return findMedianSortedArrays(nums2, nums1);
        }

        int m = nums1.size();
        int n = nums2.size();

        int left = 0;
        int right = m;

        while (left <= right) {
            // nums1 的分割位置
            int i = left + (right - left) / 2;

            // nums2 的分割位置
            int j = (m + n + 1) / 2 - i;

            // 四个边界值
            int Aleft =
                (i == 0 ? INT_MIN : nums1[i - 1]);

            int Aright =
                (i == m ? INT_MAX : nums1[i]);

            int Bleft =
                (j == 0 ? INT_MIN : nums2[j - 1]);

            int Bright =
                (j == n ? INT_MAX : nums2[j]);

            // 找到正确分割
            if (Aleft <= Bright &&
                Bleft <= Aright) {

                // 总数为奇数
                if ((m + n) % 2 == 1) {
                    return max(Aleft, Bleft);
                }

                // 总数为偶数
                return
                    (max(Aleft, Bleft)
                    + min(Aright, Bright)) / 2.0;
            }

            // nums1 左边取多了
            else if (Aleft > Bright) {
                right = i - 1;
            }

            // nums1 左边取少了
            else {
                left = i + 1;
            }
        }

        return 0.0;
    }
};
```

# ⑦ 关键设计解释

## 1. 为什么必须让 nums1 是短数组？

因为我们只在：

```
nums1
```

上二分。

所以时间复杂度实际上是：

```
O(log(min(m,n)))
```

这比题目要求的：

```
O(log(m+n))
```

还好。

更重要的是，这样可以保证：

```
j = (m+n+1)/2 - i;
```

不会轻易超出 `nums2` 的合法分割范围。

所以开头写：

```
if (nums1.size() > nums2.size()) {
    return findMedianSortedArrays(nums2, nums1);
}
```

只是：

> 如果 nums1 更长，就交换两个数组重新做。

这里用递归只是为了交换参数一次，不是算法本身使用递归搜索。

---

## 2. 为什么 Aleft 是 `nums1[i-1]`？

因为：

```
i
```

表示 nums1 左边有几个元素。

例如：

```
nums1 = [1,3,5,7]

i = 2
```

分割：

```
[1,3 | 5,7]
```

左边有两个元素：

```
下标0
下标1
```

所以左边最后一个元素：

```
nums1[i - 1]
```

即：

```
nums1[1] = 3
```

而右边第一个就是：

```
nums1[i]
```

即：

```
nums1[2] = 5
```

因此：

```
Aleft  = nums1[i-1]
Aright = nums1[i]
```

---

## 3. 为什么需要 `INT_MIN` 和 `INT_MAX`？

假设：

```
i = 0
```

即：

```
[ | 1,3]
```

左边一个元素都没有。

那么：

```
nums1[i-1]
```

就变成：

```
nums1[-1]
```

越界。

所以人为定义：

```
Aleft = INT_MIN;
```

相当于：

```
-∞
```

意思就是：

> 左边没有数字，因此它不可能干扰最大值判断。

同理，如果：

```
i == m
```

说明：

```
[1,3 | ]
```

右边没有元素。

就用：

```
Aright = INT_MAX;
```

相当于：

```
+∞
```

---

## 4. 为什么找到正确分割的条件是：

```
Aleft <= Bright &&
Bleft <= Aright
```

画出来：

```
nums1:

... Aleft | Aright ...


nums2:

... Bleft | Bright ...
```

我们希望：

```
左半部分 <= 右半部分
```

同一个数组内部已经保证：

```
Aleft <= Aright
Bleft <= Bright
```

因为数组本身有序。

所以还缺的只有两个交叉关系：

```
Aleft <= Bright

Bleft <= Aright
```

四个关系全部成立，就说明：

```
左边所有数 <= 右边所有数
```

分割成功。

---

# ⑧ 二分到底怎么移动？

这部分一定要理解。

### 情况一

如果：

```
Aleft > Bright
```

例如：

```
A:

1 8 | 10
  ↑
Aleft = 8


B:

2 | 5 9
    ↑
Bright = 5
```

出现：

```
8 > 5
```

说明：

> nums1 左边拿得太多了。

把比较大的 `8` 放到了左半边。

所以分割线应该往左：

```
right = i - 1;
```

---

### 情况二

如果：

```
Bleft > Aright
```

例如：

```
A:

1 | 4 8
    ↑
Aright = 4


B:

2 6 | 9
  ↑
Bleft = 6
```

有：

```
6 > 4
```

说明：

> nums1 左边拿少了。

应该让 nums1 再多拿一些元素：

```
left = i + 1;
```

所以你可以记：

```
Aleft > Bright
→ A左边太多
→ i往左
→ right = i-1


Bleft > Aright
→ A左边太少
→ i往右
→ left = i+1
```

---

# ⑨ 找到分割以后，中位数怎么算？

分割成功后：

```
左半部分 | 右半部分
```

## 总数是奇数

例如：

```
1 2 | 3
```

由于我们前面故意让左边多一个，所以：

```
中位数 = 左边最大的数
```

也就是：

```
max(Aleft, Bleft)
```

---

## 总数是偶数

例如：

```
1 2 | 3 4
```

中位数：

```
左边最大值 + 右边最小值
---------------------
          2
```

所以：

```
(max(Aleft, Bleft)
 + min(Aright, Bright)) / 2.0
```

注意必须：

```
2.0
```

而不是：

```
2
```

这样才能得到：

```
2.5
```

这样的浮点结果。

---

# ⑩ 为什么不推荐普通合并？

最容易想到的方法是双指针：

```
nums1 + nums2
↓
合并成一个有序数组
↓
取中位数
```

例如：

```
nums1 = [1,3]
nums2 = [2]

合并：
[1,2,3]
```

这个方法当然正确。

但是时间复杂度：

```
O(m+n)
```

题目明确要求：

```
O(log(m+n))
```

所以面试时真正考察的是：

> **二分分割。**

---

# ⑪ 递归还是迭代？

这题主算法明显推荐：

> **迭代二分。**

不需要递归搜索。

代码开头：

```
return findMedianSortedArrays(nums2, nums1);
```

虽然形式上递归调用了一次，但只是为了交换两个数组，让短数组放前面，并不是“递归算法”。

---

# ⑫ 面试追问

这题最常问的几个问题：

**为什么只二分短数组？**

因为 `j` 可以通过 `i` 直接计算，只需要搜索一个分割位置；二分短数组复杂度为：

```
O(log(min(m,n)))
```

并且更容易保证另一个数组的分割位置合法。

**为什么左边元素数是 `(m+n+1)/2`？**

为了统一奇偶情况。偶数时左右一样多；奇数时左边多一个，中位数直接取左边最大值。

**为什么只比较四个边界？**

因为两个数组内部本身有序，只需要保证两个数组之间的交叉边界也满足大小关系。

# ⑬ 复习总结

后面复习时，可以浓缩成：

```
4. 两个正序数组中位数

核心：
二分找分割线

先保证：
nums1 是较短数组

在 nums1 中二分分割位置 i

nums2 分割位置：

j = (m+n+1)/2 - i


四个边界：

Aleft  = nums1[i-1]
Aright = nums1[i]

Bleft  = nums2[j-1]
Bright = nums2[j]


正确分割：

Aleft <= Bright
并且
Bleft <= Aright


如果：

Aleft > Bright

说明 nums1 左边拿多了
→ right = i-1


否则：

nums1 左边拿少了
→ left = i+1


找到正确分割后：

总数奇数：

max(Aleft, Bleft)


总数偶数：

(max(Aleft,Bleft)
+ min(Aright,Bright)) / 2.0


复杂度：

O(log(min(m,n)))

空间：

O(1)
```

这道题最重要的理解不是背代码，而是这一句话：

> **我们不需要真的合并两个数组，只要找到两条分割线，使左半部分元素数量正确，并且“左边最大值 ≤ 右边最小值”，就能直接从分割线附近的四个数字求出中位数。**
