这题最经典、最推荐的做法是：

> **两个堆：大顶堆 + 小顶堆。**

核心思想是把当前所有数字动态分成：

```
较小的一半 | 较大的一半
```

然后让中位数永远出现在两个堆的堆顶附近。

---

## ① 破题：题目真正要求什么

普通情况下，求中位数很简单。

例如：

```
[1, 2, 3, 4, 5]
       ↑
     中位数3
```

偶数：

```
[1, 2, 3, 4]
    ↑  ↑

中位数 = (2 + 3) / 2
       = 2.5
```

但这道题不是一次性给你数组，而是：

```
addNum(1)
addNum(2)
findMedian()

addNum(3)
findMedian()

addNum(100)
...
```

数字会不断进来。

所以我们不能每来一个数字就：

```
重新排序整个数组
```

这样效率太低。

真正的问题是：

> **如何让数据不断加入的同时，始终能快速拿到中间位置的数字？**

---

# ② 核心技巧：两个堆

我们准备：

```
priority_queue<int> left;
```

这是：

> **大顶堆**

保存较小的一半。

以及：

```
priority_queue<int, vector<int>, greater<int>> right;
```

这是：

> **小顶堆**

保存较大的一半。

最终结构想象成：

```
left                      right

较小的一半               较大的一半

1 2 3        |        4 5 6
    ↑                     ↑
 left.top()           right.top()

最大的小数             最小的大数
```

因此中位数就在：

```
left.top()
和
right.top()
```

附近。

---

# ③ 为什么左边必须是大顶堆？

假设较小的一半：

```
[1, 2, 3]
```

我们真正关心的是：

```
最大的那个 = 3
```

因为它最靠近中间。

所以需要：

```
left.top() == 3;
```

因此：

> 左边使用大顶堆。

---

右边：

```
[4, 5, 6]
```

我们关心：

```
最小的那个 = 4
```

因为它最靠近中间。

所以：

```
right.top() == 4;
```

因此：

> 右边使用小顶堆。

---

# ④ 两个堆必须满足两个条件

这是整道题最重要的地方。

## 条件一：左右数据大小关系

必须保证：

```
left 中所有元素
<=
right 中所有元素
```

例如：

```
left           right

1 2 3    |    4 5 6
```

这样中位数才可能从两个堆顶直接得到。

---

## 条件二：两个堆大小不能差太多

我们规定：

```
left.size() == right.size()
```

或者：

```
left.size() == right.size() + 1
```

也就是说：

> `left` 可以和 `right` 一样多，或者比 `right` 多一个。

绝对不能：

```
left 有5个
right 有2个
```

否则中位数就不在两个堆顶附近了。

---

所以我们最终维护：

```
left.size() >= right.size()

并且：

left.size() - right.size() <= 1
```

---

# ⑤ 加入一个数字应该怎么办？

推荐你掌握一种非常稳定的写法：

```
left.push(num);

right.push(left.top());
left.pop();

if (right.size() > left.size()) {
    left.push(right.top());
    right.pop();
}
```

第一次看这段代码可能非常奇怪：

> 为什么所有数字都先扔进 `left`？

我们一步一步看。

---

# ⑥ 用 `1,2,3` 完整模拟

初始：

```
left  = []
right = []
```

---

## addNum(1)

第一步：

```
left.push(1);
```

得到：

```
left:

1
```

然后：

```
right.push(left.top());
left.pop();
```

把 `left` 最大的元素 `1` 放到 right。

变成：

```
left  = []

right:
1
```

现在：

```
right.size() > left.size()
```

即：

```
1 > 0
```

所以：

```
left.push(right.top());
right.pop();
```

把 right 最小的 1 拿回来：

```
left:

1

right:
空
```

最终：

```
left.size() = 1
right.size() = 0
```

正确。

---

## addNum(2)

当前：

```
left = [1]
right = []
```

先：

```
left.push(2);
```

由于 left 是大顶堆：

```
left:

2 ← top
1
```

然后：

```
right.push(left.top());
left.pop();
```

把：

```
2
```

送到右边。

得到：

```
left:
1

right:
2
```

现在：

```
left.size() = 1
right.size() = 1
```

平衡。

所以：

```
1 | 2
```

---

此时调用：

```

```

因为两个堆大小相同：

```
总元素是偶数
```

所以：

```
中位数 =
(left.top() + right.top()) / 2
```

也就是：

```
(1 + 2) / 2
= 1.5
```

```

left 变：

```

然后：

```

把：

```

现在：

```

```

此时：

```

```

right 多了。

把 right 最小的：

2

非常漂亮。

# ⑦ 为什么“先放 left，再把最大值送 right”？

这是这套写法最值得理解的地方。

假设：

```
left:
1 2 3

right:
7 8 9
```

现在来了：

```
100
```

先：

```
left.push(100);
```

左边暂时：

```
1 2 3 100
```

显然 `100` 不应该属于较小的一半。

但没关系。

因为马上：

```
right.push(left.top());
left.pop();
```

left 是大顶堆，所以：

```
left.top() = 100
```

100 马上就被送到 right。

最终：

```
left:
1 2 3

right:
7 8 9 100
```

大小关系又恢复了。

---

如果新来的反而是：

```
0
```

先：

```
left:
0 1 2 3
```

最大值还是：

```
3
```

于是把 3 送到 right：

```
left:
0 1 2

right:
3 7 8 9
```

同样正确。

所以这个操作：

```
left.push(num);

right.push(left.top());
left.pop();
```

实际上是在保证：

> **left 留下较小的一批数字，而把其中最大的那个送去 right。**

因此始终保持：

```
left中的元素 <= right中的元素
```

---

# ⑧ 为什么还需要第二次平衡？

前面执行：

```
left.push(num);
right.push(left.top());
left.pop();
```

每次都会让：

```
right
```

多收到一个元素。

所以有可能出现：

```
right.size() > left.size()
```

但我们的规则规定：

```
left不能比right少
```

所以：

```
if (right.size() > left.size()) {
    left.push(right.top());
    right.pop();
}
```

把 right 最小的那个拿回来。

因为 right 的最小值：

```
right.top()
```

正好是较大一半里面：

> 最应该放回左边的元素。

---

# ⑨ findMedian() 为什么这么写？

只有两种情况。

### 情况一：两个堆一样大

例如：

```
left          right

1 2    |    3 4
  ↑         ↑
```

中间两个数：

```
2 和 3
```

分别就是：

```
left.top()
right.top()
```

所以：

```
return (left.top() + right.top()) / 2.0;
```

---

### 情况二：left 比 right 多一个

例如：

```
left          right

1 2 3   |    4 5
    ↑
```

因为总数是奇数，而我们故意让多出来的那个放在：

```
left
```

所以中位数直接：

```
left.top()
```

即：

```
3
```

---

# ⑩ 完整代码

推荐你掌握这个版本：

```cpp
class MedianFinder {
private:
    // 左边：较小的一半
    // 大顶堆
    priority_queue<int> left;

    // 右边：较大的一半
    // 小顶堆
    priority_queue<int, vector<int>, greater<int>> right;

public:
    MedianFinder() {
    }

    void addNum(int num) {
        // 先放入左边
        left.push(num);

        // 把左边最大的元素送到右边
        right.push(left.top());
        left.pop();

        // 保证 left 的元素个数 >= right
        if (right.size() > left.size()) {
            left.push(right.top());
            right.pop();
        }
    }

    double findMedian() {
        // 偶数个元素
        if (left.size() == right.size()) {
            return (left.top() + right.top()) / 2.0;
        }

        // 奇数个元素
        return left.top();
    }
};
```

# ⑫ 也可以用“先判断放哪边”的写法

还有一种可能更符合直觉：

```cpp
void addNum(int num) {
    if (left.empty() || num <= left.top()) {
        left.push(num);
    }
    else {
        right.push(num);
    }

    if (left.size() > right.size() + 1) {
        right.push(left.top());
        left.pop();
    }

    if (right.size() > left.size()) {
        left.push(right.top());
        right.pop();
    }
}
```

这个版本逻辑是：

```
num <= 左边最大值
→ 放左边

否则
→ 放右边
```

然后再调整两个堆大小。

对于初学理解，我其实觉得这个版本更直观。

完整代码：

```cpp
class MedianFinder {
private:
    priority_queue<int> left;

    priority_queue<int,
                   vector<int>,
                   greater<int>> right;

public:
    MedianFinder() {
    }

    void addNum(int num) {
        // 1. 判断应该放哪边
        if (left.empty() || num <= left.top()) {
            left.push(num);
        }
        else {
            right.push(num);
        }

        // 2. 平衡两个堆
        if (left.size() > right.size() + 1) {
            right.push(left.top());
            left.pop();
        }

        if (right.size() > left.size()) {
            left.push(right.top());
            right.pop();
        }
    }

    double findMedian() {
        if (left.size() == right.size()) {
            return ((double)left.top() + right.top()) / 2.0;
        }

        return left.top();
    }
};
```

你现在第一次学习的话，**我更推荐你先理解这个版本**，因为代码和我们的思维完全一致：

```
数字来了
↓
判断放左边还是右边
↓
如果两边数量不平衡
↓
移动堆顶元素
↓
中位数直接看两个堆顶
```

# ⑬ 为什么是两个“不同方向”的堆？

这个问题非常高频。

我们并不需要：

```
左边所有元素完全排序
右边所有元素完全排序
```

只关心中间附近的两个元素。

也就是：

```
左边最大的
右边最小的
```

因此：

```
左边
→ 只需要快速知道最大值
→ 大顶堆

右边
→ 只需要快速知道最小值
→ 小顶堆
```

这就是堆在这道题里特别适合的原因。

---

# ⑭ 时间复杂度

`addNum()`：

其中会进行：

```
push
pop
```

堆操作：

```
O(log n)
```

所以：

```
addNum:
O(log n)
```

而 `findMedian()`：

只读取：

```
left.top()
right.top()
```

所以：

```
findMedian:
O(1)
```

空间：

```
O(n)
```

---

# ⑮ 递归是否适合？

不适合。

这是典型的：

> **动态数据结构维护问题。**

核心是：

```
数据不断加入
+
持续维护两个堆
```

不需要递归。

---

# ⑯ 面试追问

最关键的两个不变量（invariant）一定要会说。

整个算法始终维护：

```
① left中所有元素 <= right中所有元素

② left.size() == right.size()
   或
   left.size() == right.size() + 1
```

只要这两个条件成立：

```
偶数：
median =
(left.top + right.top) / 2


奇数：
median =
left.top
```

就是必然的。

以后复习这题直接看：

```
295 数据流的中位数

核心：

两个堆


left：
大顶堆

保存：
较小的一半

left.top：
较小一半中的最大值


right：
小顶堆

保存：
较大的一半

right.top：
较大一半中的最小值


始终保证：

left所有元素 <= right所有元素

并且：

left.size == right.size

或者：

left.size == right.size + 1

判断 num 应该放left还是right

然后调整两个堆大小


求中位数：

如果大小相等：

(left.top + right.top) / 2.0

否则：

left.top


复杂度：

addNum
O(log n)

findMedian
O(1)

空间
O(n)
```

一句话记忆：

> **用大顶堆保存较小的一半、小顶堆保存较大的一半，并始终让两边数量差不超过 1；这样中位数永远就是 `left.top()`，或者两个堆顶的平均值。**
