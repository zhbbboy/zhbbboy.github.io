这道题本质上不是普通数组题，而是经典的：
> **有向图判环问题。**

最推荐的方法是：

> **拓扑排序 + BFS + 入度表。**

DFS 三色标记也能解决，而且是图论判环的重要方法，所以会作为补充讲解。不过校招面试中，这道题通常优先写拓扑排序，因为“课程依赖关系”与拓扑排序的含义非常直接。

---

## ① 破题：题目真正要求什么

一共有：
```cpp
numCourses
```
门课程，编号为：
```text
0 ~ numCourses - 1
```
依赖关系：
```cpp
prerequisites[i] = [a, b]
```
表示：
> 想学习课程 `a`，必须先完成课程 `b`。

例如：
```cpp
[1, 0]
```
表示：
```text
先学课程 0
再学课程 1
```
可以画成一条有向边：
```text
0 → 1
```
方向一定是：
```text
先修课程 → 后续课程
```

---

题目问的是：
> 是否存在一种顺序，可以把所有课程全部学完？

如果课程依赖形成环：
```text
0 → 1 → 0
```
就表示：
```text
学习 0 之前必须先学 1
学习 1 之前又必须先学 0
```
互相等待，永远无法开始。

所以这道题可以转换为：
> 判断课程依赖构成的有向图中是否存在环。
- 没有环：可以完成所有课程；
- 存在环：无法完成所有课程。

---

# ② 核心技巧：拓扑排序

## 什么是入度？

一个节点的**入度**，表示有多少条边指向这个节点。
在课程题里，入度可以理解为：
> 学习当前课程之前，还有多少门先修课程没有完成。

例如：
```text
0 → 1
2 → 1
```
课程 `1` 需要先完成课程 `0` 和课程 `2`。

所以：
```text
indegree[1] = 2
```

---
## 什么课程可以立即学习？
当然是：
```text
入度为 0 的课程
```
因为它没有任何先修要求。

例如：
```text
0 → 1 → 2
```

初始入度：
```text
课程 0：入度 0
课程 1：入度 1
课程 2：入度 1
```
所以最开始只能学课程 `0`。

学完 `0` 后，相当于删除：
```text
0 → 1
```

这条依赖关系，因此：
```text
课程 1 的入度：1 → 0
```
课程 `1` 现在也可以学习。
整个过程就是：
```text
不断寻找入度为 0 的课程
→ 学完它
→ 删除它指向的边
→ 更新其他课程的入度
```
这就是拓扑排序。

---

# 解题思路
1. 该题是有向图判断是否有环问题，所以我们先得建立一个有向图，然后再考虑如何判断是否有环无环，那就考虑到他给了一个参数就是课程数量，所以我们可以定义一个完成数量，如果完成课程的数量等于课程数量那就是无环，因为有环的环肯定有课程完成了不了的，然后因为存在的关系是我得先修要修的课程才能修要修后才能修的课程，所以就存在了拓扑关系
2. 后续就得去思考如何写算法了，首先得创建图，然后同时建立其拓扑关系，拓扑结构里面有个关键因素是入度，这个能协助我们判断当前课程是否可以修了
3. 后续再用队列进行修课程，如果入度为0的课程就可以直接修，因为这是无条件可以修的课程或者是前面已经修了所需要修的课程后才能直接修，修完当前课程了后，与其有拓扑关系依赖的课程也就可以进行更新了
4. 最后判断结果就是完成课程的量是否等于所有课程数量

# ④ 完整代码：拓扑排序 BFS

```cpp
class Solution {
public:
    bool canFinish(
        int numCourses,
        vector<vector<int>>& prerequisites
    ) {
        // graph[i] 表示：
        // 学完课程 i 后，可以继续学习哪些课程
        vector<vector<int>> graph(numCourses);

        // indegree[i] 表示：
        // 课程 i 还有多少门先修课程
        vector<int> indegree(numCourses, 0);

        // 建图
        for (const auto& prerequisite : prerequisites) {
            int course = prerequisite[0];
            int preCourse = prerequisite[1];

            // preCourse -> course
            graph[preCourse].push_back(course);

            // course 多了一个先修要求
            indegree[course]++;
        }

        queue<int> q;

        // 所有入度为 0 的课程都可以立即学习
        for (int course = 0;
             course < numCourses;
             ++course) {
            if (indegree[course] == 0) {
                q.push(course);
            }
        }

        int completed = 0;

        while (!q.empty()) {
            int course = q.front();
            q.pop();

            // 当前课程可以完成
            completed++;

            // 学完当前课程后，
            // 更新依赖它的后续课程
            for (int nextCourse : graph[course]) {
                indegree[nextCourse]--;

                // 所有先修课程都已完成
                if (indegree[nextCourse] == 0) {
                    q.push(nextCourse);
                }
            }
        }

        // 能处理全部课程，说明没有环
        return completed == numCourses;
    }
};
```

# ⑤ 关键设计解释

## 1. 为什么边是 `b → a`？

题目给出：
```cpp
[a, b]
```
表示：
```text
学习 a 之前必须先学 b
```
所以执行顺序是：
```text
b → a
```
代码：
```cpp
graph[b].push_back(a);
indegree[a]++;
```
不能反过来写成：
```cpp
graph[a].push_back(b);
```
否则图的含义就变成：
```text
学习 b 之前先学 a
```
与题意相反。

记忆方式：
```text
[要学的课, 先修课]

先修课 → 要学的课
```

---
## 2. 邻接表 `graph` 存的是什么？
```cpp
graph[preCourse].push_back(course);
```
含义是：
> 完成 `preCourse` 后，会解锁哪些后续课程。

例如：
```text
0 → 1
0 → 2
```
邻接表：
```cpp
graph[0] = {1, 2};
```
表示完成课程 `0` 后，课程 `1` 和课程 `2` 都少了一个先修要求。

---
## 3. `indegree` 存的是什么？

```cpp
indegree[course]
```
表示：
> 当前课程还有多少门先修课程尚未处理。

例如：
```text
0 → 2
1 → 2
```
那么：
```cpp
indegree[2] = 2;
```
因为课程 `2` 需要课程 `0` 和 `1`。

---
## 4. 为什么所有入度为 0 的课程都要入队？

图中可能有多个互不依赖的起点：
```text
0 → 2
1 → 3
4
```
初始可以直接学习：
```text
0、1、4
```
所以必须扫描全部课程：
```cpp
for (int i = 0; i < numCourses; ++i) {
    if (indegree[i] == 0) {
        q.push(i);
    }
}
```
课程 `4` 虽然没有出现在 `prerequisites` 中，但它也是一门课程，并且可以直接完成。

---
## 5. 为什么课程出队后要让后续课程入度减一？
假设：
```text
0 → 2
1 → 2
```
课程 `2` 的初始入度为 `2`。
完成课程 `0`：
```text
indegree[2]：2 → 1
```
此时课程 `2` 还不能学习，因为课程 `1` 还没完成。
完成课程 `1`：
```text
indegree[2]：1 → 0
```
现在所有先修要求都完成了，课程 `2` 才能入队。

所以必须写：
```cpp
indegree[nextCourse]--;

if (indegree[nextCourse] == 0) {
    q.push(nextCourse);
}
```

---
## 6. 为什么最后比较 `completed == numCourses`？

如果图中没有环，所有课程最终都会变成入度 `0` 并被处理：
```text
completed == numCourses
```
如果存在环，环中的课程入度永远无法降到 `0`：
```text
completed < numCourses
```
例如：
```text
0 → 1 → 2
    ↑     ↓
    └─────┘
```
课程 `0` 可以完成，但 `1、2` 形成环。

最终可能是：
```text
completed = 1
numCourses = 3
```
因此返回 `false`。

---

## 7. 为什么不能只判断初始有没有入度为 0 的节点？
因为即使存在一个入度为 `0` 的节点，其他部分仍然可能存在环。
例如：
```text
0

1 → 2
↑   ↓
└───┘
```
课程 `0` 可以完成，但课程 `1、2` 互相依赖。
初始确实存在入度为 `0` 的课程 `0`，但仍然无法完成所有课程。
所以必须完整执行拓扑排序，并统计最终处理的课程数量。

# ⑥ 另一种方法：DFS 三色标记判环

DFS 也适合这题。
给每门课程设置三种状态：
```text
0：未访问
1：正在当前递归路径中访问
2：已经完成访问
```
关键是：
> 如果 DFS 过程中再次遇到状态为 `1` 的节点，说明沿当前递归路径绕回来了，形成环。

例如：
```text
0 → 1 → 2 → 0
```
访问过程：
```text
0 标记为正在访问
1 标记为正在访问
2 标记为正在访问
再次遇到 0
```
此时 `0` 仍然处于“正在访问”状态，说明存在环。

---
## DFS 完整代码
```cpp
class Solution {
private:
    bool hasCycle(
        int course,
        const vector<vector<int>>& graph,
        vector<int>& state
    ) {
        // 当前递归路径中再次遇到该节点
        if (state[course] == 1) {
            return true;
        }

        // 该节点之前已经完整检查过，而且没有环
        if (state[course] == 2) {
            return false;
        }

        // 标记为正在访问
        state[course] = 1;

        for (int nextCourse : graph[course]) {
            if (hasCycle(nextCourse, graph, state)) {
                return true;
            }
        }

        // 当前节点所有后续路径都检查完毕
        state[course] = 2;

        return false;
    }

public:
    bool canFinish(
        int numCourses,
        vector<vector<int>>& prerequisites
    ) {
        vector<vector<int>> graph(numCourses);

        for (const auto& prerequisite : prerequisites) {
            int course = prerequisite[0];
            int preCourse = prerequisite[1];

            graph[preCourse].push_back(course);
        }

        vector<int> state(numCourses, 0);

        for (int course = 0;
             course < numCourses;
             ++course) {
            if (state[course] == 0 &&
                hasCycle(course, graph, state)) {
                return false;
            }
        }

        return true;
    }
};
```

---
## DFS 递归三要素

### 1. 递归函数定义
```cpp
hasCycle(course, graph, state)
```

表示：
> 从当前课程 `course` 出发继续搜索，判断后续依赖路径中是否存在环。

---
### 2. 终止条件

遇到正在访问的节点：
```cpp
if (state[course] == 1) {
    return true;
}
```
说明形成环。

遇到已经完整处理过的节点：
```cpp
if (state[course] == 2) {
    return false;
}
```
说明从该节点出发的所有路径此前已经验证过，不存在环，不需要重复搜索。

---
### 3. 当前层做什么
```text
1. 将当前节点标记为正在访问。
2. 递归检查所有后续课程。
3. 如果某条路径发现环，返回 true。
4. 所有路径都安全，将当前节点标记为已完成。
5. 返回 false。
```

---

# ⑦ BFS 和 DFS 怎么选择？

两种都能做到：
```text
时间复杂度：O(V + E)
```

其中：

- `V` 是课程数；
- `E` 是依赖关系数。

本题更推荐 BFS 拓扑排序，因为：
```text
课程入度 = 剩余先修课程数
入度为 0 = 当前可以学习
处理所有课程 = 可以完成
```
题意与算法含义高度一致。

DFS 更适合回答：
> 有向图如何通过递归判断环？

建议学习顺序：
```text
主掌握：BFS 拓扑排序
补充掌握：DFS 三色标记
```

# ⑧ 面试追问

## Q1：什么是拓扑排序？

拓扑排序是对有向无环图中的节点进行线性排序，使每一条有向边：
```text
u → v
```
中，`u` 都排在 `v` 前面。

在课程题中就是：
```text
先修课程必须排在后续课程前面
```
只有有向无环图才存在拓扑序。

---

## Q2：为什么有环就不能完成课程？

环内的每门课程都至少依赖环内另一门课程，所以没有任何一门课程能够率先把入度降到 `0`。

它们会永远互相等待。

---

## Q3：时间复杂度是多少？

建立邻接表需要遍历所有依赖关系：
```text
O(E)
```
每门课程最多入队、出队一次：
```text
O(V)
```
每条边只处理一次：
```text
O(E)
```
总时间复杂度：
```text
O(V + E)
```
空间复杂度：
```text
O(V + E)
```
用于邻接表、入度数组和队列。

---

## Q4：如何返回具体的学习顺序？

在课程出队时，将其加入数组：
```cpp
vector<int> order;

while (!q.empty()) {
    int course = q.front();
    q.pop();

    order.push_back(course);
    // ...
}
```
如果最终：
```cpp
order.size() == numCourses
```
`order` 就是一种合法拓扑序。
这就是 LeetCode 210“课程表 II”的核心。

---

## 面试表达
> 我把课程依赖关系建成有向图。对于 `[a,b]`，表示先学 `b` 再学 `a`，因此建立边 `b→a`，并让课程 `a` 的入度加一。然后使用 Kahn 拓扑排序，把所有入度为零的课程加入队列。每取出一门课程，就认为它已经完成，并将它指向的后续课程入度减一；若某门课程入度降为零，就加入队列。最后，如果处理的课程数量等于总课程数，说明图中无环，可以完成所有课程；否则说明存在环。时间复杂度为 `O(V+E)`。

# ⑨ 复习总结

```text
207. 课程表

题型：
有向图判环 + 拓扑排序。

依赖关系：
[a, b]
表示先学 b，再学 a。

建边：
b → a

入度含义：
indegree[a]
表示课程 a 还有多少门先修课程。

算法流程：
1. 建立邻接表 graph。
2. 统计每门课程的入度。
3. 所有入度为 0 的课程加入队列。
4. 每次出队一门课程，完成数量 completed++。
5. 将其后续课程入度减一。
6. 后续课程入度变为 0 时入队。
7. 判断 completed 是否等于 numCourses。

结果：
completed == numCourses：
    无环，可以完成。

completed < numCourses：
    有环，无法完成。
```

一句话记忆：
> **把先修关系建成有向图，不断学习入度为 0 的课程；最后能处理完所有节点就无环，否则有环。**
