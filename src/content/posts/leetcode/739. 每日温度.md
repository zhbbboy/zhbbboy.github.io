这题最推荐用 **单调栈**。它和普通栈最大的区别是：栈里不是随便存元素，而是通过弹栈维持一种单调性。

这题不适合递归，核心是：

> **维护一个“还没找到右边更高温度”的下标栈。**

---

## ① 破题：题目真正要求什么

例如：

```
temperatures = [73,74,75,71,69,72,76,73]
```

对于每一天，我们要找：

> 右边第一个比今天温度更高的位置，距离今天几天。

例如：

```
73 → 后面第一个更高是74 → 1天
74 → 后面第一个更高是75 → 1天
75 → 后面第一个更高是76 → 4天
71 → 后面第一个更高是72 → 2天
69 → 后面第一个更高是72 → 1天
72 → 后面第一个更高是76 → 1天
76 → 后面没有更高     → 0
73 → 后面没有         → 0
```

答案：

```
[1,1,4,2,1,1,0,0]
```

---

# ② 核心技巧：栈里存下标

准备：

```
stack<int> st;
```

注意：

> **栈里存的是数组下标，不是温度本身。**

因为最后我们需要计算：

```
距离 = 当前下标 - 之前下标
```

也就是：

```
i - st.top()
```

如果只存温度：

```
73
74
```

你不知道它们相隔几天。

所以一定存：

```
index
```

---

# ③ 单调栈到底维护什么？

这个栈保存：

> **那些还没有找到“右边第一个更高温度”的天。**

并且从栈底到栈顶，对应温度保持：

> **单调不增。**

例如当前处理过：

```
[73, 74, 75, 71, 69]
```

其实 73、74 已经找到答案并弹出了。

栈中可能是：

```
下标：
2  3  4

温度：
75 71 69
```

也就是：

```
75
71
69 ← top
```

温度从底到顶越来越小。

---

# ④ 为什么当前温度更高时要一直弹栈？

例如：

```
当前栈：

75
71
69 ← top
```

现在来了：

```
72
```

先比较栈顶：

```
72 > 69
```

说明：

> 69 这一天终于找到了右边第一个比它高的温度，就是今天的 72。

所以把 69 对应的下标弹出来，并计算答案。

但是弹掉 69 后：

```
栈顶变成 71
```

继续：

```
72 > 71
```

说明：

> 71 这一天也找到答案了，也是当前这个 72。

所以还得继续弹。

然后栈顶变成：

```
75
```

现在：

```
72 > 75
```

不成立。

停止。

所以这里必须是：

```
while (...)
```

而不是：

```
if (...)
```

因为一个新的高温，可能一次解决前面很多天。

# ⑤ 图解完整过程

我们用：

```
temperatures = [73,74,75,71,69,72,76,73]
```

初始化：

```
vector<int> answer(temperatures.size(), 0);
stack<int> st;
```

### i = 0，温度 73

栈空，没人需要解决。

直接：

```
st.push(0);
```

栈：

```
下标：
0

温度：
73
```

### i = 1，温度 74

比较：

```

```

成立。

说明：

```
第0天的73

```

```
1 - 0 = 1
```

所以：

```

```

弹出 0。

然后把当前：

```

```

栈：

```
74
```

---

### i = 2，温度 75

```
75 > 74
```

所以：

```

```

弹出。

再压入 2。

栈：

```
75
```

### i = 3，温度 71

比较：

```

```

不成立。

说明：

> 当前 71 解决不了之前 75 的问题。

直接压入：

```

```

### i = 4，温度 69

```

```

不成立。

压入：

```

69
```

现在关键来了。

栈：

```

```

成立。


弹掉下标 4。

栈变：

```

```

成立。

不成立。

```

```

```

```

继续：


# ⑥ 完整代码

```cpp
class Solution {
public:
    vector<int> dailyTemperatures(vector<int>& temperatures) {
        int n = temperatures.size();

        vector<int> answer(n, 0);
        stack<int> st;

        for (int i = 0; i < n; ++i) {

            while (!st.empty() &&
                   temperatures[i] > temperatures[st.top()]) {

                int index = st.top();
                st.pop();

                answer[index] = i - index;
            }

            st.push(i);
        }

        return answer;
    }
};
```

---

# ⑦ 最关键的一段代码

就是：

```
while (!st.empty() &&
       temperatures[i] > temperatures[st.top()])
```

意思：

> 只要当前温度比栈顶那一天的温度更高，就说明栈顶这一天终于找到了答案。

然后：

```
int index = st.top();
st.pop();
```

拿出那一天。

再：

```
answer[index] = i - index;
```

计算：

```
当前第 i 天
-
之前第 index 天
=
等了多少天
```

---

# ⑧ 为什么是 `>`，不是 `>=`？

题目要求的是：

> **更高温度**

例如：

```
[73,73,74]
```

第一个 73 看到第二个 73：

```
73 >= 73
```

虽然成立，但第二天并没有变暖。

所以不能处理。

必须等到：

```
74 > 73
```

才算。

因此：

```
temperatures[i] > temperatures[st.top()]
```

必须严格大于。

---

# ⑨ 为什么栈里一定存下标？

这点非常重要。

如果存：

```
stack<int> st;
st.push(temperature);
```

那你能判断：

```
72 > 69
```

但是无法计算：

```
到底等了几天？
```

而存下标：

```
st.push(i);
```

既可以通过：

```
temperatures[st.top()]
```

拿到温度，

又可以通过：

```
i - st.top()
```

计算距离。

所以：

> **需要同时使用“值”和“位置”的单调栈题，通常存下标。**

---

# ⑩ 为什么时间复杂度不是 O(n²)？

你可能看到：

```
for (...)
{
    while (...)
}
```

会觉得：

```
O(n²)
```

其实不是。

因为每个下标：

```
只会入栈一次
```

并且：

```
最多出栈一次
```

比如 n 个元素：

```
push 最多 n 次
pop 最多 n 次
```

总操作次数最多大约：

```
2n
```

所以：

```
时间复杂度 O(n)
```

空间：

```
O(n)
```

---

# ⑪ 递归是否适合？

不适合。

这题核心是：

> 从左向右扫描 + 保存还没有找到答案的元素。

单调栈可以 O(n) 完成。

递归不仅没有优势，还不能自然表达这种“找右边第一个更大元素”的维护关系。

# ⑫ 面试追问

这题属于非常经典的：

> **Next Greater Element（下一个更大元素）**

类问题。

看到这种关键词：

```
右边第一个更大的
右边第一个更小的
左边第一个更大的
左边第一个更小的
```

就应该想到：

> **单调栈。**

每日温度本质上就是：

```
对于每一个 temperatures[i]

找到右边第一个：

temperatures[j] > temperatures[i]
```

然后答案不是那个温度，而是：

```
j - i
```
