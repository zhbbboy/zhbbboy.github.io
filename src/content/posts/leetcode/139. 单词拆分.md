## 解题思路
# 139. 单词拆分

这道题是非常经典的 **字符串动态规划**，而且特别适合继续练习一个核心 DP 思维：

> **如果前面这一段已经能成功拆分，再看看最后补上的这一段是不是字典里的单词。**

这题我推荐：

> **动态规划 + `unordered_set` 查询单词。**

递归/回溯当然也能做，但会反复计算“从某个位置开始能不能拆”的问题；加记忆化后本质上又变成了 DP，所以面试主解法直接掌握 DP。

---

# ① 破题：题目真正要求什么

例如：

```cpp
s = "leetcode"

wordDict = ["leet", "code"]
```

我们可以拆成：

```text
"leet" + "code"
```

两个部分都存在于字典，所以：

```cpp
return true;
```

再比如：

```cpp
s = "applepenapple"

wordDict = ["apple", "pen"]
```

可以：

```text
"apple" + "pen" + "apple"
```

注意：

> 字典中的单词可以重复使用。

所以 `apple` 用两次完全没问题。

---

最关键的是：

题目不是问：

> 字符串里有没有某个字典单词？

而是问：

> **能不能把整个字符串，从头到尾完整切成若干个字典单词。**

比如：

```cpp
s = "catsandog"

wordDict = ["cats","dog","sand","and","cat"]
```

虽然里面有：

```text
"cat"
"cats"
"sand"
"and"
"dog"
```

但无法把**整个字符串**完整拼出来，所以答案是：

```cpp
false;
```

---

# ② 核心技巧：`dp[i]` 表示前 i 个字符能不能拆

我们定义：

```cpp
dp[i]
```

表示：

> 字符串 `s` 的前 `i` 个字符，是否能够由字典中的单词拼出来。

注意是：

```text
前 i 个字符
```

不是“下标 `i` 的字符”。

因为字符串下标从 `0` 开始，所以：

```text
dp[0]：空字符串
dp[1]：s[0]
dp[2]：s[0...1]
dp[3]：s[0...2]
...
dp[n]：整个字符串
```

比如：

```cpp
s = "leetcode";
```

那么：

```text
dp[4]
```

表示：

```text
"leet"
```

能不能拆分。

而：

```text
dp[8]
```

表示：

```text
"leetcode"
```

能不能拆分。

---

## 状态转移怎么想？

假设我们要判断：

```cpp
dp[i]
```

也就是：

> 前 `i` 个字符能不能被成功拆分。

我们尝试找一个切割位置 `j`：

```text
0              j                 i
|--------------|-----------------|
    前半部分          最后一个单词
```

我们要求同时满足两个条件：

### 条件 1

前 `j` 个字符已经可以成功拆分：

```cpp
dp[j] == true
```

### 条件 2

从 `j` 开始到 `i-1` 的字符串是一个字典单词：

```cpp
s.substr(j, i - j)
```

存在于 `wordDict`。

所以：

```cpp
dp[i] = true;
```

可以记成：

```text
dp[j] 为 true
+
s[j ... i-1] 在字典里

↓

dp[i] 为 true
```

这就是整道题最核心的状态转移。



```text
dp：
```

## 为什么 `dp[0] = true`？

这个后面重点解释。

现在先把它理解成：

> 空字符串可以被“合法地拆分完成”。

---

## 计算 `dp[1]`

前 1 个字符：

```text
"l"
```

尝试：

```text
j = 0
```

前半部分：

```cpp
dp[0] == true
```

最后一段：

```cpp
s.substr(0, 1)
```

得到：

```text
"l"
```

不在字典。

所以：

```text
dp[1] = false
```

---

## 计算 `dp[2]`

前两个字符：

```text
"le"
```

尝试各种切割位置。

```text
j = 0：

"" | "le"
```

`"le"` 不在字典。

```text
j = 1：

"l" | "e"
```

但：

```cpp
dp[1] == false
```

前面的 `"l"` 本来就不能成功拆分，所以这一刀没有意义。

最终：

```text
dp[2] = false
```

---

## 一直到 `dp[4]`

前四个字符：

```text
"leet"
```

当：

```text
j = 0
```

有：

```cpp
dp[0] == true
```

并且：

```cpp
s.substr(0, 4) == "leet"
```

而：

```text
"leet"
```

存在于字典。

所以：

```cpp
dp[4] = true;
```

现在：


这里的：

```text
dp[4] = true
```

表达：

> `"leet"` 已经能够被合法地拆出来。


# ④ 完整代码

推荐你先掌握这个最标准版本：

```cpp
class Solution {
public:
    bool wordBreak(string s, vector<string>& wordDict) {
        unordered_set<string> wordSet(
            wordDict.begin(),
            wordDict.end()
        );

        int n = s.size();

        // dp[i]：s 的前 i 个字符能否被成功拆分
        vector<bool> dp(n + 1, false);

        // 空字符串认为可以成功拆分
        dp[0] = true;

        for (int i = 1; i <= n; ++i) {
            // 枚举最后一个单词的起始位置 j
            for (int j = 0; j < i; ++j) {

                // 前 j 个字符必须已经能拆分
                if (!dp[j]) {
                    continue;
                }

                // s[j ... i-1]
                string word = s.substr(j, i - j);

                if (wordSet.count(word)) {
                    dp[i] = true;
                    break;
                }
            }
        }

        return dp[n];
    }
};
```

# ⑤ 关键设计解释

## 1. 为什么 `dp` 长度是 `n + 1`？

因为我们定义的是：

```text
dp[i] = 前 i 个字符能不能拆
```

所以除了：

```text
1 ~ n
```

还需要：

```text
dp[0]
```

表示空字符串。

例如：

```cpp
s = "leet";
```

长度 `4`：

```text
dp[0] -> ""
dp[1] -> "l"
dp[2] -> "le"
dp[3] -> "lee"
dp[4] -> "leet"
```

因此需要：

```cpp
vector<bool> dp(n + 1);
```

---

## 2. 为什么必须 `dp[0] = true`？

这是这题非常重要的初始化。

假设：

```cpp
s = "leet"
```

整个 `"leet"` 本身就是一个字典单词。

当：

```text
i = 4
j = 0
```

我们检查：

```cpp
dp[j]
```

也就是：

```cpp
dp[0]
```

以及：

```cpp
s.substr(0, 4)
```

得到：

```text
"leet"
```

如果：

```cpp
dp[0] = false;
```

那么即使 `"leet"` 在字典中，也无法让：

```cpp
dp[4] = true;
```

所以规定：

```cpp
dp[0] = true;
```

可以理解成：

> 在第一个单词之前，有一个“已经成功拆完的空字符串”。

这和前缀和中：

```cpp
mp[0] = 1;
```

那种“人为增加一个起点状态”的思想很像。

---

## 3. `s.substr(j, i - j)` 到底是什么意思？

C++：

```cpp
s.substr(start, length)
```

参数是：

```text
起始下标
长度
```

不是：

```text
起始下标、结束下标
```

例如：

```cpp
s = "leetcode"
```

执行：

```cpp
s.substr(4, 4)
```

表示：

```text
从下标 4 开始
取 4 个字符
```

得到：

```text
code
```

因为：

```text
下标：

0 1 2 3 4 5 6 7
l e e t c o d e
        ↑
        j=4
```

如果：

```text
i = 8
```

那么长度：

```text
i - j
= 8 - 4
= 4
```

所以：

```cpp
s.substr(j, i - j)
```

得到的范围就是：

```text
[j, i)
```

也就是：

```text
j ~ i-1
```

---

## 4. 为什么要判断 `dp[j]`？

这是非常关键的。

假设某一段：

```text
s[j...i-1]
```

确实是字典单词。

但如果：

```text
s[0...j-1]
```

根本无法拆分，那整个前 `i` 个字符还是不合法。

例如：

```text
xxxxx | code
```

即使：

```text
code
```

在字典里，如果：

```text
xxxxx
```

拆不出来，也没用。

所以必须同时满足：

```cpp
dp[j] == true
```

和：

```cpp
wordSet.count(s.substr(j, i - j))
```

---

# 5. `j` 到底表示什么？

这个变量最好这样理解：

> `j` 是**最后一个单词的起始位置**，同时也是前后两部分的分割点。

比如：

```text
"leetcode"

leet | code
     ↑
     j = 4
```

那么：

```text
前面：
s[0...j-1]

后面：
s[j...i-1]
```

对应：

```text
dp[j]
+
最后一个单词
```

---

# 6. 为什么找到一个合法 `j` 就可以 `break`？

因为题目只问：

```text
能不能拆？
```

不是问：

```text
有多少种拆法？
```

一旦找到某个 `j` 满足：

```text
dp[j] == true
```

而且：

```text
s[j...i-1]
```

在字典里，我们就已经知道：

```cpp
dp[i] = true;
```

后面的 `j` 没必要再检查。

所以：

```cpp
break;
```

---

# 7. 为什么使用 `unordered_set`？

原来的：

```cpp
vector<string> wordDict;
```

判断某个单词是否存在时，如果每次都遍历整个 `vector`：

```text
O(wordDict.size())
```

会比较慢。

转成：

```cpp
unordered_set<string> wordSet;
```

之后：

```cpp
wordSet.count(word)
```

平均查询复杂度可以认为是：

```text
O(1)
```

所以很适合做：

> “这个字符串是否在字典里？”

# ⑥ 动态规划五步法

这题非常建议用这一套复习。

## 1. 定义状态

```text
dp[i]
=
s 的前 i 个字符能否被字典中的单词成功拆分。
```

---

## 2. 状态转移

枚举切割点 `j`。

如果：

```text
dp[j] == true
```

并且：

```text
s[j...i-1] 在字典里
```

那么：

```text
dp[i] = true
```

可以记成：

```text
前面能拆
+
最后一段是单词
=
当前能拆
```

---

## 3. 初始化

```cpp
dp[0] = true;
```

表示空字符串作为递推起点。

---

## 4. 遍历顺序

因为：

```text
dp[i]
```

依赖：

```text
dp[0]
dp[1]
...
dp[i-1]
```

所以 `i` 必须从小到大：

```cpp
for (int i = 1; i <= n; ++i)
```

然后枚举：

```cpp
j = 0 ... i-1
```

---

## 5. 返回答案

题目问：

> 整个字符串能不能拆？

所以：

```cpp
return dp[n];
```

# ⑦ 为什么不推荐普通递归？

我们也可以暴力思考：

例如：

```text
leetcode
```

尝试：

```text
l | eetcode
le | etcode
lee | tcode
leet | code
...
```

如果发现：

```text
leet
```

在字典，就递归处理：

```text
code
```

逻辑没有问题。

但很多位置会被重复计算。

例如不同拆分路径最后都可能递归到：

```text
从下标 5 开始的字符串能不能拆？
```

它会被反复求解。

可以使用：

```text
记忆化递归
```

避免重复。

不过记忆化之后，本质上也是：

```text
记录每个位置的拆分状态
```

所以面试时直接 DP 更简洁。

# ⑧ 面试追问

### Q1：为什么这题不能贪心，每次尽量匹配最长单词？

因为局部最长匹配不一定能让剩余字符串成功拆分。

例如某个较长单词虽然能匹配前缀，但剩下部分可能无法拆；选择一个较短单词反而可以完成整体拆分。

所以必须考虑不同切割点。

---

### Q2：和“完全背包”有什么关系？

这题也可以从完全背包角度理解：

```text
wordDict 中的单词可以重复使用
```

目标是：

```text
拼出整个字符串
```

但这里还必须满足字符串的字符顺序，因此直接用“字符串前缀 DP”通常更容易理解。

---

### Q3：时间复杂度是多少？

有两层循环：

```text
i：1 ~ n
j：0 ~ i-1
```

状态数量大约：

```text
O(n²)
```

但是 C++ 的：

```cpp
substr()
```

本身还需要复制字符串，长度最坏为 `O(n)`。

因此严格分析当前写法最坏可以达到：

```text
O(n³)
```

不过很多面试讨论中，会把核心 DP 状态转移描述为：

```text
O(n²)
```

如果考虑子串构造成本，则需要额外计算。

空间：

```text
dp：O(n)
wordSet：O(字典总字符量)
```

---

### Q4：如果要求返回具体拆分方案怎么办？

就不能只保存：

```cpp
bool dp[i]
```

还需要保存：

```text
dp[i] 是从哪个 j 转移过来的
```

例如：

```cpp
prev[i] = j;
```

最后从 `n` 倒着恢复：

```text
n → j → 更前面的 j → 0
```

从而得到具体单词序列。

---

### Q5：如果要求“有多少种拆分方式”呢？

`dp` 就不能是 `bool`，而应该是计数：

```cpp
dp[i] += dp[j];
```

前提是：

```text
s[j...i-1]
```

在字典中。

这就是 DP 中非常常见的变化：

```text
问“是否存在” → bool
问“最大值” → max
问“方案数量” → 加法
```

---

## 面试表达

> 我定义 `dp[i]` 表示字符串前 `i` 个字符能否被字典中的单词成功拆分，并设置 `dp[0]=true` 作为递推起点。对于每个位置 `i`，枚举最后一个单词的起点 `j`。如果前 `j` 个字符已经能够拆分，即 `dp[j]` 为真，同时子串 `s[j...i-1]` 存在于字典中，那么 `dp[i]` 就可以设为真。为了快速判断单词是否存在，我把字典放入 `unordered_set`。最终返回 `dp[n]`。

# ⑨ 复习总结

```text
139. 单词拆分

题型：
字符串 DP / 前缀 DP。

状态：
dp[i] =
字符串前 i 个字符能否成功拆分。

初始化：
dp[0] = true。

枚举：
i 表示当前字符串结尾。
j 表示最后一个单词的起点。

切分：

s[0 ... j-1] | s[j ... i-1]

判断：

dp[j] == true
并且
s.substr(j, i-j) 在字典中

那么：

dp[i] = true。

最后：

return dp[s.size()];
```

把你现在做过的几个 DP 放在一起看，会发现状态转移的来源其实非常统一：

```text
爬楼梯：
当前状态 ← 前两个楼梯状态

打家劫舍：
当前状态 ← 偷 / 不偷两种决策

杨辉三角：
当前位置 ← 左上 + 右上

单词拆分：
当前前缀 ← 某个可拆前缀 + 一个合法单词
```

**一句话记忆：**

> **枚举最后一刀 `j`：如果前 `j` 个字符已经能拆，而且 `j~i-1` 又是一个字典单词，那么前 `i` 个字符也能拆。**
