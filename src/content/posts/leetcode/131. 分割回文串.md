## 解题思路
这道题最适合的方法是：

> **回溯 + 双指针判断回文串。**

这题和你前面做的「子集」很像，都需要 `startIndex`。但这次不是“选哪个元素”，而是：

> **从当前位置开始，枚举“这一刀切在哪里”。**

比如：

```
s = "aab"
```

最终合法分割：

```
["a", "a", "b"]
["aa", "b"]
```

这题非常适合递归回溯；普通迭代写法会很别扭，所以不推荐。

---

# ① 破题：题目真正要求什么

题目给你一个字符串，例如：

```
s = "aab";
```

要求把整个字符串切成若干段，而且：

> **每一段都必须是回文串。**

所谓回文串，就是正着读和倒着读一样：

```
"a"     是
"aa"    是
"aba"   是
"abba"  是

"ab"    不是
"aab"   不是
```

对于：

```
a a b
```

一种切法：

```
a | a | b
```

三段：

```
"a"
"a"
"b"
```

全部是回文，所以合法。

另一种：

```
aa | b
```

其中：

```
"aa"
"b"
```

也都是回文，所以合法。

但是：

```
aab
```

整体不是回文，因此不能作为一种答案。

---

# ② 核心技巧：每一层决定“这一段切到哪里”

这是这题最重要的思想。

假设现在从下标：

```
startIndex
```

开始。

我们不知道当前这一段应该切多长。

所以枚举结束位置：

```
i = startIndex ... s.size() - 1
```

当前尝试的字符串就是：

```
s[startIndex ... i]
```

如果它是回文串：

```
可以选
```

加入 `path`：

```
path.push_back(s.substr(startIndex, i - startIndex + 1));
```

然后剩下的字符串从：

```
i + 1
```

开始继续切：

```
backtrack(s, i + 1);
```

如果不是回文：

```
直接跳过
```

这就是剪枝。

## 回溯树

你可以把它理解成：

```
                         ""
                  /       |       \
                "a"      "aa"    "aab"×
               /   \       |
             "a"   "ab"×   "b"
              |
             "b"
```

最终到达字符串末尾的两条合法路径：

```
a → a → b

aa → b
```

# ④ 完整代码

推荐你先掌握这个版本：

```cpp
class Solution {
private:
    vector<vector<string>> result;
    vector<string> path;

    // 判断 s[left...right] 是否为回文串
    bool isPalindrome(const string& s, int left, int right) {
        while (left < right) {
            if (s[left] != s[right]) {
                return false;
            }

            ++left;
            --right;
        }

        return true;
    }

    void backtrack(const string& s, int startIndex) {
        // 整个字符串已经切完
        if (startIndex == s.size()) {
            result.push_back(path);
            return;
        }

        // 枚举当前这一段的结束位置
        for (int i = startIndex; i < s.size(); ++i) {

            // 当前这一段不是回文，不能选
            if (!isPalindrome(s, startIndex, i)) {
                continue;
            }

            // 1. 做选择
            path.push_back(
                s.substr(startIndex, i - startIndex + 1)
            );

            // 2. 递归切剩余部分
            backtrack(s, i + 1);

            // 3. 回溯
            path.pop_back();
        }
    }

public:
    vector<vector<string>> partition(string s) {
        backtrack(s, 0);
        return result;
    }
};
```

# ⑤ 关键设计解释

## 1. `startIndex` 是什么意思？

这一题中：

```
startIndex
```

表示：

> **还没有被分割的字符串从哪个位置开始。**

例如：

```
s = "aab"
```

最开始：

```
startIndex = 0

aab
↑
```

如果已经选择 `"aa"`：

```
aa | b
     ↑
```

那么：

```
startIndex = 2
```

下一层从 `b` 开始。

---

## 2. `i` 是什么意思？

```
for (int i = startIndex; i < s.size(); ++i)
```

`i` 表示：

> 当前这一段字符串的结束位置。

所以：

```
[startIndex ... i]
```

就是当前准备切出来的一段。

例如：

```
s = "abcd"

startIndex = 1
```

如果：

```
i = 1
```

当前段：

```
"b"
```

如果：

```
i = 2
```

当前段：

```
"bc"
```

如果：

```
i = 3
```

当前段：

```
"bcd"
```

所以这个 `for` 循环实际上就是：

> **枚举这一刀到底切在哪里。**

这是这题最应该记住的理解。

---

## 3. 为什么递归传 `i + 1`？

如果当前切的是：

```
s[startIndex ... i]
```

这一段已经处理完了。

那么下一段当然应该从：

```
i + 1
```

开始。

例如：

```
a a b
0 1 2
```

当前选择：

```
"aa"
```

也就是：

```
[0...1]
```

那么下一段：

```
从 2 开始
```

所以：

```
backtrack(s, i + 1);
```

---

## 4. `substr` 为什么这样写？

```
s.substr(startIndex, i - startIndex + 1)
```

C++ 的：

```
substr(起始位置, 长度)
```

第二个参数是**长度**，不是结束下标。

例如：

```
startIndex = 0
i = 1
```

我们想取得：

```
s[0...1]
```

也就是 `"aa"`。

长度：

```
1 - 0 + 1 = 2
```

所以：

```
s.substr(0, 2);
```

得到：

```
"aa"
```

一定记住：

> 闭区间 `[startIndex, i]` 的长度是 `i - startIndex + 1`。

---

## 5. 为什么结束条件是：

```
startIndex == s.size()
```

因为这说明：

> 所有字符都已经被成功分割。

例如：

```
a | a | b |
          ↑
```

最后：

```
startIndex = 3
s.size() = 3
```

说明整个字符串正好全部处理完成。

于是：

```
result.push_back(path);
```

---

## 6. 为什么每一段必须先判断回文？

因为题目要求：

> 分割后的每个子串都必须是回文串。

所以：

```
if (!isPalindrome(...)) {
    continue;
}
```

其实就是一个**剪枝**。

例如：

```
a | ab
```

当发现：

```
"ab"
```

不是回文时：

> 以 `"ab"` 作为当前分段的所有后续方案都不用搜索了。

---

## 7. 双指针怎么判断回文？

例如：

```
"abba"
```

两个指针：

```
a b b a
↑     ↑
L     R
```

比较：

```
a == a
```

向中间移动：

```
a b b a
  ↑ ↑
  L R
```

比较：

```
b == b
```

全部相等，所以是回文。

代码：

```cpp
bool isPalindrome(const string& s, int left, int right) {
    while (left < right) {
        if (s[left] != s[right]) {
            return false;
        }

        ++left;
        --right;
    }

    return true;
}
```

一旦发现不同：

```
a b c
↑   ↑

a != c
```

立即：

```
return false;
```

# ⑥ 递归三要素

这题非常适合递归。

## 1. 递归函数定义

```
backtrack(s, startIndex)
```

表示：

> `s[0...startIndex-1]` 已经成功分割，并保存在 `path` 中；现在从 `startIndex` 开始继续寻找所有合法的回文分割方式。

例如：

```
s = "aab"

path = ["aa"]
startIndex = 2
```

表示：

```
aa | ?
```

前面的 `"aa"` 已经处理好，现在处理剩下的 `"b"`。

---

## 2. 递归终止条件

```cpp
if (startIndex == s.size()) {
    result.push_back(path);
    return;
}
```

整个字符串全部被合法切完。

---

## 3. 当前层做什么？

当前层负责：

```
从 startIndex 开始，
枚举当前这一段结束在哪里。
```

也就是：

```
[startIndex...startIndex]
[startIndex...startIndex+1]
[startIndex...startIndex+2]
...
```

对于每一段：

```
不是回文 → 跳过

是回文
→ 加入 path
→ 递归处理剩下部分
→ pop_back 回溯
```

---

# ⑦ 为什么不推荐普通迭代法？

因为这题需要不断：

```
切第一段
↓
切剩余部分
↓
再切下一段
↓
失败后退回来换切法
```

这天然是一棵搜索树。

如果迭代实现，需要自己维护：

```
当前切到哪里
已经切了哪些字符串
之前的切割点
当前分支状态
```

会明显更复杂。

所以这题：

> **主方法就是递归回溯。**

不过“判断回文”这一部分可以进一步用 DP 预处理优化，这是进阶内容。

# ⑧ 面试追问

## Q1：这题和子集有什么相似之处？

非常像。

子集：

```
startIndex 表示下一次从哪个元素开始选择
```

回文分割：

```
startIndex 表示下一段从哪个字符开始
```

但区别是：

子集每层是在：

> 选择一个元素。

本题每层是在：

> 选择一个结束位置，也就是决定“这一刀切在哪里”。

---

## Q2：为什么不需要 `used`？

因为字符串只能：

```
从左到右进行分割
```

选择：

```
[startIndex...i]
```

之后：

```
startIndex = i + 1;
```

天然不会重新使用前面的字符。

所以不需要 `used`。

---

## Q3：为什么必须回溯 `path.pop_back()`？

例如：

```
s = "aab"
```

先走：

```
["a","a","b"]
```

搜索完成后，要回到：

```
[]
```

再尝试：

```
["aa","b"]
```

如果不：

```
path.pop_back();
```

之前的分段会残留在 `path` 中，影响其他分支。

---

## Q4：能不能优化回文判断？

可以。

目前每次：

```
isPalindrome(s, left, right)
```

都要重新扫描这一段。

可以提前使用二维 DP：

```
palindrome[i][j]
```

表示：

> `s[i...j]` 是否为回文。

预处理完成后：

```
if (palindrome[startIndex][i])
```

就可以 `O(1)` 判断。

这是一个很好的面试进阶优化。

---

## Q5：复杂度是多少？

分割位置本身就存在指数级组合。

长度为 `n` 的字符串，中间有：

```
n - 1
```

个位置：

```
a | b | c | d
```

每个位置可以：

```
切
不切
```

所以最坏搜索规模接近：

```
O(2^n)
```

再考虑每次回文判断和复制字符串，朴素实现还会有额外的 `O(n)` 开销。

因此可以理解为：

> **指数级回溯搜索，回文预处理可以降低重复判断的成本。**

---

## 面试表达

> 我使用回溯。`startIndex` 表示当前还未分割部分的起点，每一层枚举结束位置 `i`，即尝试把 `s[startIndex...i]` 作为当前分段。如果该子串不是回文就直接跳过；如果是回文，就加入当前路径，然后从 `i+1` 继续递归分割剩余字符串，递归返回后撤销选择。当 `startIndex == s.size()` 时，说明整个字符串已经被合法分割，将当前路径加入结果。

# ⑨ 复习总结

```
131. 分割回文串

题型：
回溯 + 字符串切割 + 回文判断

核心变量：
path：
当前已经切出来的回文串

startIndex：
剩余字符串从哪里开始

i：
当前这一段切到哪里结束

每层：
枚举 i = startIndex ... n-1

当前子串：
s[startIndex ... i]

如果不是回文：
continue

如果是回文：
path.push_back(...)
backtrack(s, i + 1)
path.pop_back()

终止：
startIndex == s.size()

回文判断：
双指针 left / right 向中间靠拢
```

你可以把它和前几道回溯题这样串起来：

```
全排列：
每层决定“下一个位置放哪个数字”

子集：
每层决定“下一个元素选哪个”

组合总和：
每层决定“下一个数字选哪个”

括号生成：
每层决定“下一个放 ( 还是 )”

单词搜索：
每层决定“下一步走哪个方向”

分割回文串：
每层决定“这一刀切在哪里”
```

**一句话记忆：**

> **从 `startIndex` 开始枚举结束位置 `i`；`s[startIndex...i]` 是回文就切下来，递归处理 `i+1` 后面的字符串，回来后再撤销这次切割。**
