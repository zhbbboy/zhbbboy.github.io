这题和你刚做的 **33. 搜索旋转排序数组** 很像，但其实更简单，因为：

> **33 是找某个 target；153 只需要找到旋转后的最小值。**

最推荐的方法：

> **二分查找，并始终拿 `nums[mid]` 和 `nums[right]` 比较。**

这题不推荐递归，迭代二分最自然。

---

# ① 破题：题目真正要求什么

原数组本来严格递增：

```
[1,2,3,4,5]
```

旋转后可能变成：

```
[3,4,5,1,2]
```

最小值是：

```
1
```

实际上我们就是要找到：

> **旋转断点。**

因为原本：

```
1 2 3 4 5
```

旋转以后：

```
3 4 5 | 1 2
          ↑
        最小值
```

最小值就是第二段有序区间的第一个元素。

---

# ② 核心技巧

每次取：

```
mid
```

然后比较：

```
nums[mid]
nums[right]
```

只有两种主要情况：

```
nums[mid] > nums[right]
```

说明：

> 最小值一定在 `mid` 右边。

所以：

```
left = mid + 1;
```

反之：

```
nums[mid] <= nums[right]
```

说明：

> `mid ~ right` 这一段已经是正常递增的，`nums[mid]` 自己都有可能就是最小值。

所以：

```
right = mid;
```

注意：

> 这里是 `right = mid`，不是 `mid - 1`。

这是本题最重要的地方。

---

# ③ 图解执行过程

例如：

```
nums = [3,4,5,1,2]
```

初始：

```
下标：  0  1  2  3  4
nums：  3  4  5  1  2
        ↑     ↑     ↑
        L     M     R
```

现在：

```
nums[mid] = 5;
nums[right] = 2;
```

有：

```
5 > 2
```

这说明什么？

如果 `mid` 右边是正常递增区间，不可能：

```
5 ... 2
```

说明旋转断点一定就在 `mid` 后面。

所以：

```
left = mid + 1;
```

得到：

```
下标：        3  4
nums：        1  2
              ↑  ↑
              L  R
```

---

现在：

```
mid = 3;
```

所以：

```
nums[mid] = 1
nums[right] = 2
```

有：

```
1 <= 2
```

说明：

```
[1,2]
```

这一段已经递增。

而 `1` 有可能就是最小值。

所以不能把 `mid` 丢掉，而是：

```
right = mid;
```

得到：

```
left = 3
right = 3
```

循环结束。

返回：

```
nums[left]
```

也就是：

```
1
```

# ④ 完整代码

推荐你直接掌握这个版本：

```cpp
class Solution {
public:
    int findMin(vector<int>& nums) {
        int left = 0;
        int right = nums.size() - 1;

        while (left < right) {
            int mid = left + (right - left) / 2;

            if (nums[mid] > nums[right]) {
                // 最小值一定在 mid 右边
                left = mid + 1;
            }
            else {
                // mid 可能就是最小值，不能丢掉
                right = mid;
            }
        }

        return nums[left];
    }
};
```

# ⑤ 关键设计解释

## 1. 为什么拿 `nums[mid]` 和 `nums[right]` 比？

因为 `right` 可以帮助我们判断：

> `mid` 处于旋转点左边的大数区间，还是右边的小数区间。

例如：

```
[4,5,6,7,0,1,2]
```

大致可以看成：

```
4 5 6 7 | 0 1 2
高值区    低值区
```

如果：

```
nums[mid] > nums[right]
```

例如：

```
7 > 2
```

说明 `mid` 还在高值区。

所以最小值一定：

```
在 mid 右边
```

---

## 2. 为什么 `nums[mid] > nums[right]` 时一定 `left = mid + 1`？

例如：

```
4 5 6 7 0 1 2
      ↑     ↑
     mid   right
```

有：

```
7 > 2
```

如果整个：

```
mid ~ right
```

都是正常递增的，就应该：

```
7 < ... < 2
```

显然不可能。

所以：

> 旋转断点一定存在于 `mid` 的右侧。

而且：

```
nums[mid]
```

明显不是最小值。

所以可以放心排除：

```
left = mid + 1;
```

---

## 3. 为什么另一种情况是 `right = mid`，而不是 `mid - 1`？

这个非常重要。

例如：

```
3 4 5 1 2
      ↑
     mid=3
```

假设现在搜索区间只剩：

```
1 2
↑ ↑
M R
```

有：

```
nums[mid] < nums[right]
```

此时 `mid` 自己：

```
1
```

就可能是最终最小值。

如果你写：

```
right = mid - 1;
```

就会把真正答案直接删掉。

所以只能：

```
right = mid;
```

也就是说：

> **确认最小值在 `[left, mid]` 中，但 mid 不能排除。**

---

# ⑥ 为什么循环条件是 `left < right`

这里和你之前一些普通二分：

```
while (left <= right)
```

不一样。

因为这道题不是：

> 找不到就返回 -1。

题目保证：

> 一定存在最小值。

我们是在不断缩小一个“最小值一定存在的区间”。

例如：

```
[left ........ right]
```

不断缩：

```
[left ... right]
```

最后：

```
left == right
```

这个唯一位置就是最小值。

所以：

```
while (left < right)
```

即可。

最终：

```
return nums[left];
```

---

# ⑦ 一个没有旋转的情况

例如：

```
nums = [11,13,15,17]
```

最小值：

```
11
```

看看算法是否还能工作。

初始：

```
11 13 15 17
↑     ↑  ↑
L     M  R
```

有：

```
13 < 17
```

所以：

```
right = mid;
```

得到：

```
11 13
↑  ↑
L  R
```

再次：

```
11 < 13
```

所以：

```
right = mid;
```

最终：

```
left = right = 0
```

返回：

```
11
```

完全没问题。

也就是说：

> **没有旋转，本质上也只是旋转 0 次或旋转 n 次的特殊情况。**

# ⑧ 面试追问

### Q1：为什么不能和 `nums[left]` 比？

也不是完全不能设计，但和 `right` 比通常逻辑更稳定、模板更简洁。

尤其：

```
nums[mid] > nums[right]
```

可以直接判断：

> 最小值一定在右半区。

这是这题最经典的写法。

---

### Q2：为什么这里不需要像 33 题一样判断哪半边有序？

因为我们的目标更简单。

33 题有一个：

```
target
```

需要判断：

> target 究竟在哪个有序区间。

153 题只找：

```
旋转断点 / 最小值
```

只需要判断最小值在 `mid` 左边还是右边即可。

---

### Q3：如果数组里允许重复数字呢？

本题明确：

```
所有元素互不相同
```

所以不存在：

```
nums[mid] == nums[right]
```

但两者下标不同、又不知道应该往哪边走的麻烦情况。

如果允许重复：

```
[2,2,2,0,1,2]
```

就需要额外处理：

```
nums[mid] == nums[right]
```

通常可以：

```
--right;
```

但最坏复杂度可能退化成：

```
O(n)
```

这是另一道题的变体。

# ⑨ 复习总结

你后续复习可以直接记：

```
153. 寻找旋转数组最小值

核心：
二分找旋转断点。

每次比较：
nums[mid] 和 nums[right]

如果：

nums[mid] > nums[right]

说明 mid 在旋转点左边的大数区，
最小值一定在右边：

left = mid + 1


否则：

nums[mid] <= nums[right]

说明 mid 到 right 已经有序，
mid 自己可能就是最小值：

right = mid


循环：

while(left < right)

最后：

left == right

返回：

nums[left]

复杂度：
时间 O(log n)
空间 O(1)
```

把 **33 和 153** 连起来记最方便：

```
33 搜索旋转数组中的 target：
判断哪半边有序，再判断 target 在哪边。

153 找旋转数组最小值：
比较 mid 和 right，直接判断旋转断点在哪边。
```

一句话记忆：

> **`mid > right`，说明最小值在 mid 右边；否则 mid 可能就是最小值，所以保留 mid，令 `right = mid`。**
