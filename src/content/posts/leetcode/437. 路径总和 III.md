这道题最适合使用：
> **DFS 递归 + 前缀和 + 哈希表 + 回溯**

它和你之前做过的 **560. 和为 K 的子数组**非常相似。

区别是：
```
560：在数组中找连续子数组
437：在二叉树的一条祖先到后代路径中找连续路径
```
迭代也可以实现，但需要手动保存每个节点的前缀和状态，并在离开节点时回溯哈希表，逻辑比递归复杂很多，所以本题不推荐迭代写法。

---
## ① 破题：题目真正要求什么
题目要求统计二叉树中，节点值之和等于 `targetSum` 的路径数量。
路径需要满足：
```
1. 不一定从根节点开始
2. 不一定到叶子节点结束
3. 必须从父节点向子节点移动
4. 中间不能跳过节点
```
例如：
```
        10
       /  \
      5   -3
     / \    \
    3   2    11
       /
      1
```
当：
```
targetSum = 8
```
合法路径包括：
```
5 → 3       和为 8
5 → 2 → 1   和为 8
-3 → 11     和为 8
```
所以答案是：
```
3
```
注意，路径不是只能从根节点 `10` 开始。

---
## ② 核心技巧：树上的前缀和

### 先回忆数组中的前缀和
假设当前前缀和是：
```
currentSum
```
之前某个位置的前缀和是：
```
oldSum
```
如果两者之间这段连续区间之和等于 `targetSum`，那么：
```
currentSum - oldSum = targetSum
```
变形得到：
```
oldSum = currentSum - targetSum
```
所以只需要查看：
```
prefixCount[currentSum - targetSum]
```
之前出现过多少次。

---
### 放到二叉树里怎么理解？
在树中，我们把：
```
从根节点到当前节点的路径和
```
看作当前前缀和。
例如当前递归路径是：
```
10 → 5 → 3
```
对应前缀和：
```
到 10：10
到 5：15
到 3：18
```
现在：
```
currentSum = 18
targetSum = 8
```
我们寻找：
```
currentSum - targetSum
= 18 - 8
= 10
```
之前前缀和 `10` 出现过，它对应节点 `10`。
因此：
```
当前前缀和 18 - 之前前缀和 10 = 8
```
减掉根节点 `10` 之前的那部分，剩下的路径就是：
```
5 → 3
```
所以找到一条合法路径。

---
## 哈希表到底存什么？
```
unordered_map<long long, int> prefixCount;
```
它存储：
```
prefixCount[某个前缀和]
=
这个前缀和在“当前根到当前节点的递归路径上”
出现过多少次
```
这里最重要的是：
> 哈希表只保存当前递归路径上的前缀和，不能永久保存其他分支的前缀和。

否则会错误地把左子树节点和右子树节点拼成一条不存在的路径。
因此递归返回时必须回溯：
```
prefixCount[currentSum]--;
```
## ④ 完整代码
```cpp
class Solution {
private:
    int dfs(
        TreeNode* node,
        long long currentSum,
        long long targetSum,
        unordered_map<long long, int>& prefixCount
    ) {
        if (node == nullptr) {
            return 0;
        }

        // 当前根到当前节点的前缀和
        currentSum += node->val;

        // 统计以当前节点结尾、和为 targetSum 的路径数量
        int answer = 0;

        if (prefixCount.count(currentSum - targetSum)) {
            answer += prefixCount[currentSum - targetSum];
        }

        // 当前前缀和加入当前递归路径
        prefixCount[currentSum]++;

        // 继续搜索左右子树
        answer += dfs(
            node->left,
            currentSum,
            targetSum,
            prefixCount
        );

        answer += dfs(
            node->right,
            currentSum,
            targetSum,
            prefixCount
        );

        // 回溯：离开当前节点，删除当前路径中的前缀和
        prefixCount[currentSum]--;

        return answer;
    }

public:
    int pathSum(TreeNode* root, int targetSum) {
        unordered_map<long long, int> prefixCount;

        // 表示遍历开始前，前缀和 0 出现过一次
        prefixCount[0] = 1;

        return dfs(root, 0, targetSum, prefixCount);
    }
};
```

实际上可以把查询简化为：
```cpp
int answer = prefixCount[currentSum - targetSum];
```
因为 `unordered_map` 使用 `operator[]` 查找不存在的键时会插入一个值为 `0` 的键。不过为了明确“只查询，不插入”，上面的 `count()` 写法更容易理解。

## 如果有一个链条是5->10->3，然后targetSum=8，这不会出现问题吗，而我在代码中好像没有看到处理这种情况的
不会出问题。你这个例子正好能说明一个最容易混淆的点：
> 哈希表里存的是**前缀和**，不是节点值。

链条是：
```
5 → 10 → 3
```
`targetSum = 8`。
这条链上所有可能的连续向下路径是：
```
5               和为 5
10              和为 10
3               和为 3
5 → 10          和为 15
10 → 3          和为 13
5 → 10 → 3      和为 18
```
没有任何路径的和等于 `8`，所以答案应该是 `0`。

---
### 代码是如何避免误判的？
初始：
```
prefixCount[0] = 1;
```
然后按照 `5 → 10 → 3` 遍历。
#### 访问节点 5
```
currentSum = 5
currentSum - targetSum = 5 - 8 = -3
```
哈希表里没有前缀和 `-3`，所以没有合法路径。
然后记录：
```
prefixCount[5] = 1
```
当前哈希表中的前缀和：
```
0、5
```

---
#### 访问节点 10
注意，当前前缀和不是节点值 `10`，而是：
```
currentSum = 5 + 10 = 15
```
查找：
```
currentSum - targetSum
= 15 - 8
= 7
```
哈希表中没有前缀和 `7`，所以没有合法路径。
然后记录：
```
prefixCount[15] = 1
```
当前哈希表：
```
0、5、15
```

---
#### 访问节点 3
当前前缀和：
```
currentSum = 5 + 10 + 3 = 18
```
查找：
```
currentSum - targetSum
= 18 - 8
= 10
```
关键来了：
```
prefixCount[10]
```
查找的是：
> 之前是否出现过“前缀和等于 10”的位置。

虽然链条中有一个**节点值**为 `10`，但是之前的前缀和并没有等于 `10`。
之前的前缀和是：
```
0、5、15
```
没有 `10`，所以：
```
prefixCount[10] = 0
```
答案不会增加。

## ⑤ 关键设计解释

### 1. 为什么要初始化 `prefixCount[0] = 1`？
为了处理从根节点开始的合法路径。
例如：
```
    5
   /
  3
```
目标：
```
targetSum = 8
```
遍历到节点 `3` 时：
```
currentSum = 5 + 3 = 8
```
查找：
```
currentSum - targetSum
= 8 - 8
= 0
```
如果：
```
prefixCount[0] = 1;
```
就能找到从根节点开始的路径：
```
5 → 3
```
可以把这个前缀和 `0` 理解为：
> 根节点之前存在一个虚拟位置，它的前缀和是 0。

---
### 2. 为什么先查找，再执行 `prefixCount[currentSum]++`？
正确顺序是：
```cpp
answer += prefixCount[currentSum - targetSum];
prefixCount[currentSum]++;
```
因为查找时，只应该匹配当前节点之前的祖先前缀和。

如果先把当前前缀和加入哈希表，在：
```
targetSum = 0
```
时，会用当前前缀和减去自己，错误地统计出一条长度为 0 的空路径。
所以必须：
```
先使用祖先信息计算答案
再把当前节点加入路径
```

---
### 3. 为什么必须回溯？
代码：
```
prefixCount[currentSum]--;
```
作用是：
> 离开当前节点时，把它产生的前缀和从当前路径中删除。

例如：
```
        10
       /  \
      5   -3
```

遍历完左子树 `5` 后，再去右子树 `-3`。

节点 `5` 不属于：
```
10 → -3
```
这条路径，因此左分支产生的前缀和不能继续保留。

不回溯就可能把：
```
左子树中的某个节点
+
右子树中的某个节点
```
错误地当成一条向下路径。

---
### 4. 为什么哈希表存的是“次数”而不是是否出现？

同一个前缀和可能在当前路径上出现多次。
例如节点中有正数、负数和零时：
```
前缀和 5
```
可能在不同祖先位置重复出现。

如果当前：
```
currentSum - targetSum = 5
```
而前缀和 `5` 出现了两次，那么就有两种不同的起点，可以形成两条合法路径。
所以：
```
answer += prefixCount[currentSum - targetSum];
```
不能只写：
```
answer++;
```

---

### 5. 为什么使用 `long long`？

题目中节点值可能达到：
```
10^9
```
路径最多可能包含很多节点，前缀和可能超出 `int` 范围。

例如：
```
1000 个节点 × 10^9
= 10^12
```

因此：
```
long long currentSum;
```

否则可能整数溢出。

---
### 6. 为什么不能使用普通滑动窗口？
因为：
```
节点值可以是负数
树的结构也不是线性数组
```

负数会导致：
```
扩大路径后，路径和不一定增大
缩小路径后，路径和也不一定减小
```
因此不能根据大小关系移动左右指针。
本题更适合前缀和。

---
## ⑥ 递归三要素

这题非常适合递归，因为需要沿着每一条根到后代的路径进行搜索。
### 1. 递归函数的定义
```cpp
dfs(node, currentSum, targetSum, prefixCount)
```
表示：
> 当前递归到 `node`，已知它之前路径的前缀和为 `currentSum`，统计当前子树中所有满足条件的向下路径数量。

---
### 2. 递归终止条件
```cpp
if (node == nullptr) {
    return 0;
}
```
空节点不存在路径，因此返回 0。

---
### 3. 当前层做什么
当前节点需要完成：
```
1. 将 node->val 加入当前前缀和
2. 查找 currentSum - targetSum 出现次数
3. 将当前前缀和加入哈希表
4. 递归统计左子树
5. 递归统计右子树
6. 回溯删除当前前缀和
7. 返回当前子树的答案数量
```
核心顺序不能乱：
```
计算当前和
→ 查询答案
→ 加入哈希表
→ 递归左右子树
→ 回溯
```

---
## ⑦ 为什么不推荐迭代写法？
迭代可以用栈模拟 DFS，但栈中不仅需要保存节点，还要保存：
```
当前前缀和
当前节点是进入状态还是退出状态
退出时需要删除哪个前缀和
```
因为本题存在回溯操作，迭代通常需要类似：
```
stack<进入节点事件 / 离开节点事件>
```
手动模拟递归调用栈。

这种实现：
- 状态更多；
- 更容易忘记回溯；
- 代码可读性更差；
- 时间复杂度没有改善。
所以本题递归 DFS 是更自然、更适合面试的写法。

## ⑧ 面试追问

### Q1：暴力解法是什么？
可以枚举每个节点作为路径起点，再从该节点向下枚举所有路径。
每个节点都可能重新遍历一部分子树，最坏时间复杂度：
```
O(n²)
```
前缀和方法把重复计算合并到一次 DFS 中，平均时间复杂度降低到：
```
O(n)
```

---
### Q2：为什么哈希表只能记录当前递归路径？
题目要求路径必须满足：
```
祖先 → 后代
```
不同分支中的节点不存在祖先关系。
所以在进入某个子树时，哈希表必须只包含：
```
根节点到当前节点的祖先链
```
回溯就是为了维护这个不变量。

---
### Q3：时间复杂度是多少？
每个节点只访问一次，哈希表查询和修改平均是 `O(1)`：
```
时间复杂度：O(n)
```
递归栈最多保存一条根到叶子的路径，设树高为 `h`：
```
递归空间：O(h)
```
哈希表最多记录当前路径上的前缀和：
```
哈希表空间：O(h)
```
最坏情况下树退化成链表：
```
空间复杂度：O(n)
```

---
### Q4：为什么答案不是遇到 `currentSum == targetSum` 就加一？
因为路径不一定从根节点开始。
只判断：
```
currentSum == targetSum
```
只能找到从根开始的路径。
而使用：
```
prefixCount[currentSum - targetSum]
```
可以找到从任意祖先节点之后开始、到当前节点结束的路径。

---
### 面试表达

> 这题可以看成树上的“和为 K 的连续子数组”。我在 DFS 过程中维护从根到当前节点的前缀和，并用哈希表记录当前递归路径上每种前缀和出现的次数。若当前前缀和为 `sum`，之前存在前缀和 `sum - targetSum`，那么两者之间的向下路径和就是 `targetSum`。进入节点时加入当前前缀和，左右子树处理完成后将其删除，保证哈希表只保存当前祖先路径。每个节点只访问一次，时间复杂度为 `O(n)`。

## ⑨ 复习总结
```
437. 路径总和 III

题型：
二叉树 DFS + 前缀和 + 哈希表 + 回溯。

路径条件：
1. 可以从任意节点开始。
2. 可以在任意节点结束。
3. 必须从父节点向子节点连续移动。

核心公式：
当前前缀和 - 之前前缀和 = targetSum

所以查找：
之前前缀和 = currentSum - targetSum

哈希表含义：
prefixCount[sum]
=
前缀和 sum 在当前根到当前节点路径上出现的次数。

代码流程：
1. prefixCount[0] = 1。
2. currentSum += node->val。
3. 答案加上 prefixCount[currentSum - targetSum]。
4. prefixCount[currentSum]++。
5. 递归左子树和右子树。
6. prefixCount[currentSum]--，进行回溯。
```

一句话记忆：

> **把根到当前节点看成一条数组：用前缀和找目标路径，用回溯保证哈希表只属于当前祖先链。**
