## 解题思路
这道题你一定要和刚刚的 **279. 完全平方数**放在一起理解，因为它们几乎是同一个 DP 模型：

```
279 完全平方数：
“物品” = 1, 4, 9, 16...
目标 = 凑出 n
每个平方数可以无限使用
求最少使用几个

322 零钱兑换：
“物品” = coins 中的硬币
目标 = 凑出 amount
每种硬币可以无限使用
求最少使用几枚
```

所以这是一道非常标准的：

> **完全背包 + 最少数量 DP**

---

# ① 破题：题目真正要求什么

例如：

```
coins = [1, 2, 5]
amount = 11
```

每种硬币可以无限使用。

我们需要：

> 恰好凑出金额 `11`，并且硬币数量尽可能少。

例如：

```
1 + 1 + 1 + ...          很多枚
2 + 2 + 2 + 2 + 2 + 1   6 枚
5 + 5 + 1               3 枚
```

所以答案：

```
3
```

如果：

```
coins = [2]
amount = 3
```

不管用多少个 `2`：

```
2
4
6
...
```

都凑不出 `3`。

所以返回：

```
-1
```

---

# ② 核心技巧：最后一枚硬币选什么？

这是 DP 最重要的思考。

定义：

```
dp[i] = 凑出金额 i 最少需要多少枚硬币
```

现在假设我们要计算：

```
dp[11]
```

如果**最后一枚硬币选 `5`**：

```
11
↑
先凑出 6，再加一枚 5
```

那么：

```
dp[11] = dp[6] + 1
```

如果最后一枚硬币选 `2`：

```
dp[11] = dp[9] + 1
```

最后选 `1`：

```
dp[11] = dp[10] + 1
```

所以我们把所有可能都试一下，取最小：

```cpp
dp[i] = min(
    dp[i],
    dp[i - coin] + 1
);
```

这就是整道题最核心的状态转移。

你应该把它翻译成中文：

> 如果最后使用一枚 `coin`，那么前面只需要用最优方案凑出 `i - coin`，再加当前这一枚硬币。

# ③ 图解执行过程

用：

```
coins = [1, 2, 5]
amount = 11
```

来走。

首先定义：

```
dp[i] = 凑出 i 最少需要多少枚硬币
```

初始化：

```
dp[0] = 0
```

因为凑出金额 `0`：

```
什么都不拿
```

需要：

```
0 枚硬币
```

---

## 先只使用硬币 1

因为硬币可以无限使用：

```
dp[1] = 1
dp[2] = 2
dp[3] = 3
...
dp[11] = 11
```

此时相当于：

```
金额： 0  1  2  3  4  5 ... 11
dp：   0  1  2  3  4  5 ... 11
```

---

## 再加入硬币 2

来到金额 `2`：

```
原来：
dp[2] = 2
对应 1 + 1
```

如果使用一个 `2`：

```
dp[0] + 1
= 0 + 1
= 1
```

所以：

```
dp[2] = 1
```

---

金额 `3`：

最后使用一枚 `2`：

```
dp[3 - 2] + 1
= dp[1] + 1
= 1 + 1
= 2
```

所以：

```
3 = 1 + 2
```

只需要两枚。

---

金额 `4`：

```
dp[4 - 2] + 1
= dp[2] + 1
```

注意此时：

```
dp[2] = 1
```

刚刚已经由硬币 `2` 更新过。

所以：

```
dp[4] = 2
```

对应：

```
2 + 2
```

这里已经出现了**完全背包最重要的特点**：

> 同一枚硬币类型 `2` 可以重复使用。

---

## 再加入硬币 5

金额 `5`：

```
dp[5]
= min(原来的答案, dp[0] + 1)
= 1
```

因为：

```
5
```

本身一枚就够。

金额 `10`：

```
dp[10]
← dp[5] + 1
= 1 + 1
= 2
```

得到：

```
5 + 5
```

金额 `11`：

```
dp[11]
← dp[6] + 1
```

而：

```
dp[6] = 2
```

可以是：

```
5 + 1
```

所以：

```
dp[11] = 3
```

对应：

```
5 + 5 + 1
```

最终答案：

```
3
```

# ④ 完整代码

我建议你这道题先掌握**标准完全背包写法**：

```cpp
class Solution {
public:
    int coinChange(vector<int>& coins, int amount) {
        // amount + 1 相当于“无穷大”
        vector<int> dp(amount + 1, amount + 1);

        // 凑出 0 元不需要任何硬币
        dp[0] = 0;

        // 枚举每种硬币
        for (int coin : coins) {

            // 完全背包：容量从小到大遍历
            for (int j = coin; j <= amount; ++j) {

                dp[j] = min(
                    dp[j],
                    dp[j - coin] + 1
                );
            }
        }

        // 仍然无法被更新，说明无法凑出 amount
        return dp[amount] == amount + 1
            ? -1
            : dp[amount];
    }
};
```

# ⑤ 关键设计解释

## 1. `dp[i]` 到底是什么？

必须先把这句话记住：

```
dp[i]
=
凑出金额 i
最少需要多少枚硬币
```

例如：

```
coins = [1,2,5]

dp[5] = 1
dp[6] = 2
dp[10] = 2
dp[11] = 3
```

---

## 2. 为什么 `dp[0] = 0`？

因为：

```
金额 0
```

不需要硬币。

更重要的是，它是整个递推的起点。

例如硬币 `5`：

```
dp[5]
= dp[5 - 5] + 1
= dp[0] + 1
= 1
```

这样才能自然得到：

```
5 元只需要 1 枚 5 元硬币
```

---

## 3. 为什么其他位置不能初始化为 0？

我们要求：

```
min(...)
```

如果：

```
dp[i] = 0
```

那么：

```
min(0, 正数)
```

永远等于 `0`。

显然错误。

所以要初始化成一个“不可能的大值”。

这里推荐：

```
amount + 1
```

为什么？

假设最极端情况下有：

```
1 元硬币
```

凑 `amount` 最多也只需要：

```
amount 枚
```

所以：

```
amount + 1
```

一定比任何合法答案大，可以表示“目前无法凑出”。

---

## 4. 为什么我不太推荐直接用 `INT_MAX`？

也能用，但要小心：

```
dp[j - coin] + 1
```

如果：

```
dp[j - coin] == INT_MAX
```

再：

```
INT_MAX + 1
```

可能发生整数溢出。

所以如果使用 `INT_MAX`，要先判断：

```cpp
if (dp[j - coin] != INT_MAX) {
    dp[j] = min(dp[j], dp[j - coin] + 1);
}
```

对于这题，直接：

```
amount + 1
```

更简单安全。

---

## 5. 为什么完全背包要从小到大遍历？

这是这道题最值得理解的地方。

代码：

```cpp
for (int j = coin; j <= amount; ++j)
```

为什么是：

```
小 → 大
```

？

因为这样可以**重复使用当前硬币**。

例如：

```
coin = 2
```

先计算：

```
dp[2] = dp[0] + 1 = 1
```

接下来计算：

```
dp[4]
```

可以使用刚刚更新好的：

```
dp[2]
```

所以：

```
dp[4]
= dp[2] + 1
= 2
```

对应：

```
2 + 2
```

继续：

```
dp[6]
= dp[4] + 1
= 3
```

对应：

```
2 + 2 + 2
```

也就是说：

```
dp[2] → dp[4] → dp[6]

  2       2+2      2+2+2
```

这就是：

> **正序遍历容量，让当前硬币能够被反复使用。**

---

## 6. 如果倒序遍历会怎么样？

假设：

```
coin = 2
```

如果写：

```
for (int j = amount; j >= coin; --j)
```

当前这一轮计算较大的 `dp[j]` 时，较小的：

```
dp[j - coin]
```

还没有使用当前 `coin` 更新。

于是当前硬币只能被使用一次。

这更接近：

> **0-1 背包**

所以你现在先记这个高频规律：

```
0-1 背包：
每个物品只能用一次
→ 容量倒序

完全背包：
每个物品可以无限用
→ 容量正序
```

这个以后面试很常问。

---

## 7. 为什么状态转移是 `+1`？

```
dp[j - coin] + 1
```

`dp[j - coin]` 表示：

> 已经最优地凑出了 `j - coin`。

现在：

```
再使用一枚 coin
```

所以硬币数量：

```
+ 1
```

例如：

```
j = 11
coin = 5
```

那么：

```
dp[6] + 1
```

表示：

```
先最优地凑 6 元
再加一枚 5 元
```

得到 `11` 元。

---

## 8. 为什么最后可能返回 `-1`？

例如：

```
coins = [2]
amount = 3
```

初始化：

```
dp = [0, 4, 4, 4]
```

其中：

```
amount + 1 = 4
```

使用硬币 `2` 后：

```
dp[2] = 1
```

但：

```
dp[3]
```

永远无法更新：

```
dp[3] = 4
```

所以：

```
dp[amount] == amount + 1
```

说明：

> amount 根本无法被硬币组合出来。

返回：

```
-1
```

# ⑥ 递归为什么不推荐？

可以写暴力递归：

```
想凑 11：

最后选 1
→ 再解决凑 10

最后选 2
→ 再解决凑 9

最后选 5
→ 再解决凑 6
```

本质上：

```
f(amount)
=
1 + min(
    f(amount - coin1),
    f(amount - coin2),
    ...
)
```

逻辑完全正确。

但是会反复计算：

```
f(6)
f(5)
f(4)
...
```

造成大量重复子问题。

加上记忆化当然也可以达到不错复杂度，但这题状态特别简单：

```
0 ~ amount
```

所以直接用自底向上的 DP 更自然。

因此本题：

> **推荐迭代 DP，不推荐普通递归。**

# ⑦ 和 279 完全平方数到底有多像？

把两道题并排放一下。

### 279

```
n = 12

可用“物品”：
1, 4, 9

每种无限使用

求：
最少几个物品凑出 12
```

状态转移：

```
dp[i] = min(
    dp[i],
    dp[i - square] + 1
);
```

---

### 322

```
amount = 11

可用“物品”：
1, 2, 5

每种无限使用

求：
最少几枚硬币凑出 11
```

状态转移：

```
dp[i] = min(
    dp[i],
    dp[i - coin] + 1
);
```

你会发现：

```
square
```

换成：

```
coin
```

几乎就是同一道题。

所以真正应该学会的是这个模板：

```cpp
dp[0] = 0;

for (物品) {
    for (容量 = 物品重量; 容量 <= target; ++容量) {
        dp[容量] = min(
            dp[容量],
            dp[容量 - 物品重量] + 1
        );
    }
}
```

这是：

> **完全背包——最少物品数量模型。**

# ⑧ 面试追问

### Q1：为什么这是完全背包？

因为题目明确：

> 每种硬币的数量是无限的。

同一个硬币可以重复使用：

```
5 + 5 + 1
```

所以是完全背包。

---

### Q2：为什么不能贪心，每次选最大的硬币？

因为局部最优不一定全局最优。

例如：

```
coins = [1, 3, 4]
amount = 6
```

贪心：

```
先拿 4
剩 2

4 + 1 + 1
= 3 枚
```

但是最优：

```
3 + 3
= 2 枚
```

所以不能简单贪心。

---

### Q3：时间复杂度？

假设：

```
coins.size() = m
amount = n
```

两层循环：

```
时间复杂度 O(m × n)
```

DP 数组：

```
空间复杂度 O(n)
```

---

### Q4：如果问的是“有多少种组合方式”，还能用这个 DP 吗？

可以，但状态含义和转移会改变。

例如零钱兑换 II：

```
dp[i] = 凑出金额 i 的组合数量
```

状态转移就会从：

```
min(...)
```

变成：

```
dp[j] += dp[j - coin];
```

这体现了一个很重要的 DP 规律：

```
问最少几个
→ min

问最大值
→ max

问多少种
→ 加法

问能不能
→ bool
```

---

### Q5：为什么完全背包容量正序？

因为：

> 当前物品可以重复使用。

正序时：

```
dp[j - coin]
```

可能已经使用过当前 `coin`，现在再使用一次也合法。

这就是完全背包正序的根本原因。

# ⑨ 复习总结

```
322. 零钱兑换

题型：
一维 DP + 完全背包 + 最少数量问题

物品：
coins 中的硬币

容量：
amount

特点：
每种硬币可以无限使用
→ 完全背包

状态：
dp[i]
=
凑出金额 i 最少需要多少枚硬币

初始化：
dp[0] = 0
其他 = amount + 1

状态转移：
dp[j] =
min(
    dp[j],
    dp[j - coin] + 1
)

遍历：
外层枚举硬币
内层容量从 coin 到 amount 正序

为什么正序：
允许当前硬币重复使用

最后：
如果 dp[amount] 还是 amount + 1：
返回 -1

否则：
返回 dp[amount]
```

你现在可以把 **279 和 322** 统一成一句模板：

> **有一组可以无限重复使用的数，要恰好凑出一个目标，并且要求使用数量最少——考虑完全背包，`dp[target]` 记录最少数量，状态转移使用 `min(dp[j], dp[j - item] + 1)`。**
