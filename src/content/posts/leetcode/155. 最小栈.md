这道题最推荐的做法是：

> **一个普通栈保存真实数据，再用一个辅助栈同步保存“当前最小值”。**

这样 `push / pop / top / getMin` 全部都可以做到 **O(1)**。

这题不适合递归，核心就是数据结构设计。

## ① 破题：题目真正要求什么

普通 `stack` 本来已经支持：

```
push()
pop()
top()
```

而且都是 O(1)。

现在题目额外要求：

```
getMin()
```

也必须 O(1)。

假设栈里有：

```
-2
 0
-3
```

如果每次 `getMin()` 都从头扫描一遍：

```
min(-2, 0, -3)
```

需要 O(n)。

题目不允许这样。

所以真正的问题是：

> **怎样在每次 push/pop 的同时，把当前最小值也维护下来？**

---

## ② 核心技巧：两个栈

准备两个栈：

```
stack<int> st;
stack<int> minSt;
```

其中：

```
st
保存真实的数据

minSt
保存“每一层对应的最小值”
```

例如依次：

```
push(-2);
push(0);
push(-3);
```

两个栈会变成：

```
st：

底
-2
 0
-3  ← top


minSt：

底
-2
-2
-3  ← top
```

你重点看 `minSt`：

```
压入 -2 后：
当前最小值 = -2

压入 0 后：
当前最小值仍然 = -2

压入 -3 后：
当前最小值 = -3
```

所以：

```
minSt.top()
```

永远就是：

> **当前整个栈的最小值。**

因此 `getMin()` 直接：

```
return minSt.top();
```

就是 O(1)。

---

# ③ 图解执行过程

题目示例：

```
push(-2);
push(0);
push(-3);
getMin();
pop();
top();
getMin();
```

初始：

```
st     = []
minSt  = []
```

### push(-2)

真实数据栈：

```
st：

-2
```

辅助栈因为目前没有元素：

```
minSt.push(-2);
```

得到：

```
minSt：

-2
```

此时最小值：

```
-2
```

---

### push(0)

真实数据：

```
st：

-2
 0
```

当前旧最小值：

```
minSt.top() == -2
```

新来的：

```
0
```

所以新的最小值：

```
min(0, -2) = -2
```

因此：

```
minSt：

-2
-2
```

注意这里为什么又存了一个 `-2`。

因为第二层对应的状态就是：

> 栈有 `[-2,0]` 时，最小值是 `-2`。

---

### push(-3)

真实栈：

```
st：

-2
 0
-3
```

原来的最小值：

```
-2
```

新来的：

```
-3
```

于是：

```
min(-3, -2) = -3
```

辅助栈：

```
minSt：

-2
-2
-3
```

所以：

```
getMin()
```

直接得到：

```
-3
```

---

### pop()

普通栈弹出：

```
-3
```

变成：

```
st：

-2
 0
```

与此同时：

```
minSt.pop();
```

辅助栈也弹掉这一层：

```
minSt：

-2
-2
```

于是当前最小值自动恢复成：

```
-2
```

这就是这个设计最漂亮的地方：

> **pop 时不需要重新计算最小值，辅助栈自己就回到了上一层的最小值。**

# ④ 完整代码

建议你先掌握这个版本，逻辑最清晰：

```cpp
class MinStack {
private:
    stack<int> st;       // 保存真实数据
    stack<int> minSt;    // 保存每一层对应的最小值

public:
    MinStack() {
    }

    void push(int val) {
        st.push(val);

        if (minSt.empty()) {
            minSt.push(val);
        }
        else {
            minSt.push(min(val, minSt.top()));
        }
    }

    void pop() {
        st.pop();
        minSt.pop();
    }

    int top() {
        return st.top();
    }

    int getMin() {
        return minSt.top();
    }
};
```

---

# ⑤ 关键设计解释

最值得理解的是这一句：

```
minSt.push(min(val, minSt.top()));
```

比如之前栈：

```
[3, 1, 5]
```

当前最小值：

```
1
```

现在：

```
push(4);
```

新的最小值显然还是：

```
1
```

所以：

```
min(4, 1) = 1;
```

往 `minSt` 里再压一个 `1`。

如果现在：

```
push(-2);
```

则：

```
min(-2, 1) = -2;
```

所以新的栈顶最小值就是 `-2`。

---

另一个非常关键的问题是：为什么 `pop()` 必须两个栈一起弹？

因为两个栈的每一层是一一对应的：

```
st            minSt

-2             -2
 0             -2
-3             -3
↑               ↑
同一层
```

如果：

```
st.pop();
```

却不：

```
minSt.pop();
```

那么真实数据中的 `-3` 已经没了，但是：

```
minSt.top()
```

还会告诉你：

```
最小值 = -3
```

结果当然错了。

所以：

```
void pop() {
    st.pop();
    minSt.pop();
}
```

两个栈必须同步。

# 该题重点♥♥♥♥♥♥♥♥♥♥
# ⑦ 为什么不能只用一个变量 `minValue`？

你可能会想到：

```
int minValue;
```

每次：

```
push(val)
```

更新：

```
minValue = min(minValue, val);
```

看起来也可以。

但问题出现在 `pop()`。

例如：

```
栈：

3
1
5
```

当前：

```
minValue = 1
```

如果弹出：

```
5
```

没问题。

但是如果：

```
栈：

3
1
```

再弹出：

```
1
```

现在应该恢复：

```
minValue = 3
```

但单独一个：

```
minValue
```

已经不知道：

> **1 出现之前的最小值是多少。**

除非重新遍历整个栈，这样又变成 O(n)。

辅助栈实际上就是帮我们保存：

```
每一个历史阶段的最小值
```

所以 pop 后可以瞬间恢复。

# ⑧ 面试追问

面试里最常问的是为什么辅助栈需要和主栈一样多的元素。这个版本的设计就是让两边严格一一对应，因此逻辑最简单，空间复杂度 O(n)。

也有一种空间稍省的写法，只在：

```
val <= minSt.top()
```

时才把 `val` 压入最小栈，然后 pop 时检查：

```
if (st.top() == minSt.top())
```

才同步弹出 `minSt`。这种做法也对，但第一次学习不如“同步栈”直观，所以建议先掌握现在这个版本。

所有操作的复杂度都是：

```
push    O(1)
pop     O(1)
top     O(1)
getMin  O(1)
```

空间复杂度：

```
O(n)
```

> **主栈记录“当前有哪些元素”，辅助栈记录“每一层时的最小值”；两边同步 push/pop，因此 `minSt.top()` 永远就是当前最小值。**
