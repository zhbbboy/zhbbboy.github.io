## 解题思路

这道题非常适合接在你刚学的 **279 完全平方数、322 零钱兑换** 后面，因为它正式把你带到另一个非常重要的背包模型：

> **0-1 背包。**

这题最推荐：

> **一维 DP + 0-1 背包。**

这题虽然也可以回溯枚举“每个数字选还是不选”，但复杂度会接近指数级；DP 更适合。

而且你一定要重点理解：

> **为什么这题容量必须倒序遍历，而完全背包是正序遍历。**

---

# ① 破题：题目真正要求什么

例如：

```
nums = [1,5,11,5]
```

总和：

```
1 + 5 + 11 + 5 = 22
```

如果能分成两个和相等的子集，那么每个子集的和一定是：

```
22 / 2 = 11
```

所以原问题：

> 能不能把数组分成两个和相等的子集？

其实可以转化成：

> **能不能从 nums 中挑一些数字，使它们的和恰好等于 totalSum / 2？**

例如：

```
target = 11
```

我们可以直接选：

```
[11]
```

或者：

```
[1,5,5]
```

都能得到 `11`。

因此返回：

```
true
```

---

再看：

```
nums = [1,2,3,5]
```

总和：

```
11
```

是奇数。

如果两个子集和相等：

```
A + B = 11
A = B
```

那么：

```
2A = 11
```

不可能。

所以：

```
return false;
```

甚至都不用 DP。

---

# ② 核心技巧：转成 0-1 背包

为什么这是 0-1 背包？

因为数组中的每个数字：

```
nums[i]
```

只能：

```
选一次
或者
不选
```

不能重复使用同一个数组元素。

例如：

```
nums = [1,5,11,5]
```

注意这里有两个 `5`。

它们是两个不同的数组元素，所以每个各自可以使用一次。

但是不能说：

```
只有一个 11
却把这个 11 使用两次
```

因此每个元素：

```
0 次 / 1 次
```

这就是：

> **0-1 背包。**

### 322 零钱兑换

```
coins = [1,2,5]
```

每种硬币：

```
可以无限次使用
```

所以：

> 完全背包。

---

### 416 分割等和子集

```
nums = [1,5,11,5]
```

每个具体元素：

```
只能使用一次
```

所以：

> 0-1 背包。

先把这句话牢牢记住：

```
0-1 背包：
每个物品只能用一次

完全背包：
每个物品可以无限使用
```

# ③ `dp` 到底怎么定义？

这题有两种常见定义。

我更推荐你现在先学最直观的：

```
dp[j]
```

表示：

> **使用已经遍历过的数字，能不能恰好凑出和 `j`。**

所以这是一个：

```
vector<bool> dp;
```

例如：

```
dp[5] = true
```

表示：

> 当前已经处理过的数字中，存在一种选择方式，可以凑出 `5`。

而：

```
dp[8] = false
```

表示当前还不能凑出 `8`。

---

## 初始化

```
dp[0] = true;
```

为什么？

因为：

> 什么都不选，就可以凑出和 `0`。

这个和之前：

```
零钱兑换：
dp[0] = 0
```

虽然具体含义不同，但都是：

> 给状态转移提供一个合法起点。

---

# ④ 状态转移

假设现在处理：

```
num
```

我们想知道：

```
能不能凑出 j？
```

有两种情况。

### 不选 num

那么 `dp[j]` 保持原样。

### 选 num

如果之前能够凑出：

```
j - num
```

那么现在再加入 `num`：

```
(j - num) + num = j
```

所以现在也能凑出 `j`。

因此：

代码：

```
dp[j] = dp[j] || dp[j - num];
```

翻译：

> 原来能凑出 `j`，当然继续可以；或者原来能凑出 `j-num`，现在加上当前 `num`，也能凑出 `j`。

# ⑥ 为什么必须倒序遍历？★★★★★

这是这题最重要的部分。

标准代码：

```cpp
for (int num : nums) {
    for (int j = target; j >= num; --j) {
        dp[j] = dp[j] || dp[j - num];
    }
}
```

注意：

```
target → num
```

是从大到小。

---

## 为什么不能像完全背包一样正序？

总和：

```
sum = 2 + 6 = 8
```

所以：

```
target = 8 / 2 = 4
```

现在问题变成：

> 能不能从 `[2,6]` 中选一些元素，恰好凑出 `4`？

显然：

```
只能选：
2
6
2 + 6 = 8
```

没有办法得到 `4`。

所以正确答案应该是：

```
false
```

但是看看**错误的正序遍历**会发生什么。

初始：

```
dp[0] = true

dp:
下标  0  1  2  3  4
      T  F  F  F  F
```

处理第一个元素：

```
num = 2;
```

如果错误地写：

```
for (int j = num; j <= target; ++j)
```

也就是：

```
j = 2 → 3 → 4
```

### j = 2

```
dp[2] = dp[2] || dp[0];
```

因为：

```
dp[0] = true
```

所以：

```
dp[2] = true
```

现在：

```
下标  0  1  2  3  4
      T  F  T  F  F
```

这一步没问题，相当于：

```
选一次 2
```

### 接着 j = 4

```
dp[4] = dp[4] || dp[2];
```

但注意：

```
dp[2] = true
```

是**刚刚这一轮使用当前这个 2 更新出来的！**

于是：

```
dp[4] = true;
```

这相当于：

```
2 + 2 = 4
```

问题是数组：

```
nums = [2,6]
```

明明只有**一个 2**。

你却在处理这个 `2` 的同一轮里把它用了两遍。

最后错误得到：

```
dp[4] = true
```

导致算法返回：

```
true
```

但正确答案明明是：

```
false
```

---

而如果**倒序遍历**：

```
for (int j = target; j >= num; --j)
```

处理 `num = 2`：

```
j = 4 → 3 → 2
```

先算 `j=4`：

```
dp[4] = dp[4] || dp[2];
```

此时 `dp[2]` 还是上一轮的：

```
false
```

所以：

```
dp[4] = false
```

然后最后才算：

```
j = 2
```

得到：

```
dp[2] = true;
```

但 `j=4` 已经处理过去了，所以当前这个 `2` 没机会再用第二遍。
这就是 0-1 背包倒序遍历的真正原因：

> **倒序保证 `dp[j-num]` 读取的是“当前 num 还没加入之前”的状态，因此一个元素这一轮最多只能使用一次。**

---

# 0-1 背包 vs 完全背包最核心区别

你刚学了完全背包，这里一定要串起来：

```
0-1 背包：

每件物品只能用一次
↓
容量倒序

for (j = target; j >= num; --j)
```

而：

```
完全背包：

每种物品可以无限使用
↓
容量正序

for (j = num; j <= target; ++j)
```

为什么？

## 核心不是死记“倒序/正序”，而是：

> **正序会读取到当前这一轮刚更新过的状态，因此允许当前物品再次使用；倒序读取的还是上一轮状态，因此当前物品最多使用一次。**

这个才是底层原因。

# ⑦ 完整代码

我推荐你掌握这个 `bool DP` 版本：

```cpp
class Solution {
public:
    bool canPartition(vector<int>& nums) {
        int sum = 0;

        for (int num : nums) {
            sum += num;
        }

        // 总和为奇数，不可能平分
        if (sum % 2 != 0) {
            return false;
        }

        int target = sum / 2;

        vector<bool> dp(target + 1, false);

        // 什么都不选，可以凑出 0
        dp[0] = true;

        // 0-1 背包
        for (int num : nums) {

            // 必须倒序
            for (int j = target; j >= num; --j) {

                dp[j] =
                    dp[j] ||
                    dp[j - num];
            }
        }

        return dp[target];
    }
};
```

# ⑧ 关键设计解释

## 1. 为什么只需要找一个和为 `sum / 2` 的子集？

假设总和：

```
sum
```

如果找到子集 A：

```
sum(A) = sum / 2
```

那么剩下所有没选的元素自然组成 B：

```
sum(B)
=
sum - sum(A)
=
sum - sum/2
=
sum/2
```

所以只需要找到一半。

根本不用同时构造两个集合。

---

## 2. 为什么总和是奇数直接 false？

因为如果：

```
A = B
```

那么：

```
A + B = 2A
```

一定是偶数。

所以总和为奇数不可能平分。

---

## 3. 为什么 `dp[0] = true`？

因为：

```
不选任何元素
```

就已经凑出了：

```
0
```

而且状态转移需要它。

例如当前：

```
num = 5
```

计算：

```
dp[5]
```

会查看：

```
dp[5 - 5] = dp[0]
```

因为：

```
dp[0] = true
```

所以：

```
只选择当前 5
```

就能凑出 `5`。

---

## 4. 为什么 `j >= num`？

因为：

```
dp[j - num]
```

必须保证：

```
j - num >= 0
```

如果：

```
j < num
```

当前这个数字本身已经比目标容量 `j` 大，不可能使用它。

# ⑩ 为什么不推荐递归？

当然可以写：

```
每个数字：

选
或者
不选
```

例如：

```
             nums[0]
            /       \
          选         不选
         /             \
      nums[1]          nums[1]
      /   \             /   \
    选    不选         选    不选
```

这是一棵二叉搜索树。

`n` 个数字最坏大约：

```
2^n
```

种组合。

而本题：

```
nums.length <= 200
```

暴力枚举显然太大。

DP 把大量重复状态：

```
当前处理到了哪里
当前能凑出的和是多少
```

压缩保存下来。

所以这题更推荐迭代 DP。

# ⑪ 面试追问

### Q1：为什么这是 0-1 背包？

因为 `nums` 中每个具体元素最多使用一次：

```
选 / 不选
```

所以每个物品的使用次数只能是：

```
0 或 1
```

---

### Q2：为什么 0-1 背包必须倒序？

因为倒序可以保证：

```
dp[j-num]
```

还是当前物品加入之前的状态。

因此当前元素不会在同一轮被重复使用。

---

### Q3：如果正序会发生什么？

会导致：

> 当前物品在同一轮中重复使用。

从而变成完全背包。

例如只有一个：

```
2
```

正序却可能得到：

```
2 + 2 = 4
```

显然非法。

---

### Q4：时间复杂度？

假设：

```
n = nums.size()
target = sum / 2
```

那么：

```
时间 O(n × target)
空间 O(target)
```

---

### 面试表达

> 我先计算数组总和。如果总和是奇数，则不可能分成两个等和子集。否则问题可以转化为：能否从数组中选择若干元素，使其和恰好等于 `sum/2`。由于每个数组元素最多使用一次，所以这是一个 0-1 背包问题。我定义 `dp[j]` 表示使用已经遍历过的元素是否能够凑出和 `j`，初始化 `dp[0]=true`。对于当前元素 `num`，状态转移为 `dp[j] = dp[j] || dp[j-num]`。容量必须从大到小遍历，从而避免当前元素在同一轮被重复使用。最后返回 `dp[target]`。

```

       0-1 背包            完全背包
```

> **0-1 背包倒序，是为了让 `dp[j-num]` 保持为“使用当前物品之前”的状态，防止一个元素在同一轮被使用多次；完全背包恰恰允许重复使用，所以正序。**
