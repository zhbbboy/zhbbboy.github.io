## 解题思路


# 230. 二叉搜索树中第 K 小的元素

这题递归和迭代都能做，但我建议：

> **主方法：迭代中序遍历。**  
> 因为找到第 `k` 个节点后可以立即返回，不需要成员变量，代码状态更清楚。

递归适合帮助理解“BST 中序遍历是升序”的原理，所以作为补充方法讲解。

---

## ① 破题：题目真正要求什么

给你一棵二叉搜索树 `root` 和整数 `k`，要求返回其中第 `k` 小的节点值。

例如：

```text
        3
       / \
      1   4
       \
        2
```

所有节点从小到大排列：

```text
1, 2, 3, 4
```

因此：

```text
k = 1，答案是 1
k = 2，答案是 2
k = 3，答案是 3
```

题目的关键不是普通二叉树，而是：

```text
二叉搜索树 BST
```

---

## ② 核心技巧：BST 中序遍历是升序

二叉搜索树满足：

```text
左子树所有值 < 当前节点值 < 右子树所有值
```

中序遍历的顺序是：

```text
左子树 → 当前节点 → 右子树
```

把两者结合起来：

```text
先访问更小的值
再访问当前值
最后访问更大的值
```

所以，BST 的中序遍历结果一定是严格升序的。

因此这题可以转换成：

> 对 BST 进行中序遍历，访问到的第 `k` 个节点，就是第 `k` 小的节点。

---

## ③ 图解执行过程

使用示例：

```text
        5
       / \
      3   6
     / \
    2   4
   /
  1
```

题目给出：

```text
k = 3
```

这棵树的中序遍历结果是：

```text
1, 2, 3, 4, 5, 6
```

所以第 3 小是 `3`。

下面看迭代方法如何得到它。

### 第一步：不断向左走并压栈

从根节点 `5` 出发：

```text
push 5
向左到 3

push 3
向左到 2

push 2
向左到 1

push 1
向左到 nullptr
```

此时栈中是：

```text
栈底 [5, 3, 2, 1] 栈顶
```

为什么一路向左？

因为 BST 越往左，节点值越小。因此栈顶 `1` 是当前还没有访问过的最小节点。

---

### 第二步：访问节点 1

弹出栈顶：

```text
访问 1
```

让：

```cpp
k--;
```

变化：

```text
k：3 → 2
```

节点 `1` 没有右子树，继续从栈中弹出。

---

### 第三步：访问节点 2

弹出节点 `2`：

```text
访问顺序：1, 2
k：2 → 1
```

节点 `2` 也没有右子树。

---

### 第四步：访问节点 3

弹出节点 `3`：

```text
访问顺序：1, 2, 3
k：1 → 0
```

此时：

```cpp
k == 0
```

说明当前节点就是原来的第 3 小，返回：

```text
3
```

后面的 `4、5、6` 不需要再访问。

---

## ④ 完整代码：推荐的迭代写法

```cpp
class Solution {
public:
    int kthSmallest(TreeNode* root, int k) {
        stack<TreeNode*> st;
        TreeNode* cur = root;

        while (cur != nullptr || !st.empty()) {
            // 1. 不断向左走，将沿途节点压栈
            while (cur != nullptr) {
                st.push(cur);
                cur = cur->left;
            }

            // 2. 栈顶是当前最小的未访问节点
            cur = st.top();
            st.pop();

            // 3. 当前节点是中序遍历中的一个节点
            k--;

            if (k == 0) {
                return cur->val;
            }

            // 4. 当前节点访问完成，处理它的右子树
            cur = cur->right;
        }

        return -1; // 题目保证 k 合法，正常不会执行到这里
    }
};
```

## ⑤ 关键设计解释

### 1. 为什么队列不合适，而要使用栈？

队列适合层序遍历：

```text
一层一层访问
```

但这题需要模拟中序遍历：

```text
左 → 根 → 右
```

递归中“暂时没有处理完的祖先节点”会保存在调用栈里。

迭代时，我们使用：

```cpp
stack<TreeNode*> st;
```

手动模拟递归调用栈。

---

### 2. 为什么循环条件是这个？

```cpp
while (cur != nullptr || !st.empty())
```

存在两种还没有处理完的情况：

```text
cur != nullptr：
当前还有一棵子树需要向左探索。

!st.empty()：
虽然 cur 已经为空，但栈中还有祖先节点没有访问。
```

只有当：

```text
cur == nullptr
并且
st.empty()
```

才代表整棵树遍历完成。

---

### 3. 为什么要一直向左压栈？

```cpp
while (cur != nullptr) {
    st.push(cur);
    cur = cur->left;
}
```

因为 BST 中左边的节点更小。

我们必须先找到当前子树最左侧的节点，才能按照从小到大的顺序访问。

例如：

```text
        5
       /
      3
     /
    2
   /
  1
```

中序遍历首先访问的一定是 `1`，所以要先把 `5、3、2、1` 全部压栈。

---

### 4. 为什么栈顶是当前最小的未访问节点？

一路向左走到空之后，栈顶就是最左侧节点。

例如：

```text
栈底 [5, 3, 2, 1] 栈顶
```

`1` 比路径中的 `2、3、5` 都小，同时它没有更小的左孩子，因此应该第一个访问。

---

### 5. 为什么弹出节点后要进入右子树？

中序遍历是：

```text
左 → 根 → 右
```

弹出栈顶时：

- 它的左子树已经处理完；
    
- 当前节点现在被访问；
    
- 接下来应该处理右子树。
    

所以：

```cpp
cur = cur->right;
```

进入右子树后，下一轮又会不断向左走，找到右子树中的最小节点。

---

### 6. 为什么用 `k--`？

这里可以把 `k` 理解为：

> 距离答案还需要访问多少个节点。

假设最初：

```text
k = 3
```

访问第一个节点：

```text
k = 2
```

访问第二个节点：

```text
k = 1
```

访问第三个节点：

```text
k = 0
```

因此：

```cpp
k--;

if (k == 0) {
    return cur->val;
}
```

## ⑥ 递归写法与递归三要素

递归也很适合这题，因为中序遍历天然可以递归表示。

但相较迭代写法，它通常需要成员变量保存访问次数和答案，并且递归返回只退出当前调用层，提前终止稍微不够直观。因此这里把递归作为补充。

### 递归代码

```cpp
class Solution {
private:
    int count = 0;
    int answer = 0;
    bool found = false;

    void inorder(TreeNode* node, int k) {
        if (node == nullptr || found) {
            return;
        }

        // 左
        inorder(node->left, k);

        if (found) {
            return;
        }

        // 根
        count++;

        if (count == k) {
            answer = node->val;
            found = true;
            return;
        }

        // 右
        inorder(node->right, k);
    }

public:
    int kthSmallest(TreeNode* root, int k) {
        inorder(root, k);
        return answer;
    }
};
```

### 递归三要素

#### 1. 递归函数定义

```cpp
inorder(node, k)
```

表示：

> 对以 `node` 为根的 BST 进行中序遍历，并在访问到第 `k` 个节点时记录答案。

#### 2. 终止条件

```cpp
if (node == nullptr || found) {
    return;
}
```

- `node == nullptr`：当前分支没有节点；
    
- `found == true`：答案已经找到，不再继续遍历。
    

#### 3. 当前层做什么

按照中序顺序：

```text
1. 递归遍历左子树
2. 访问当前节点，让 count++
3. 如果 count == k，记录答案
4. 递归遍历右子树
```

---

## ⑦ 为什么本题更推荐迭代？

两种方法都适用，但面试中我更推荐迭代：

```text
迭代法：
找到第 k 个节点后可以直接 return。
状态都在当前函数内，不依赖成员变量。
显式展示中序遍历的栈过程。

递归法：
代码符合树的递归结构，更容易理解。
但需要额外变量保存 count、answer 和是否已找到。
提前结束所有递归层的处理不如直接 return 直观。
```

所以学习顺序建议是：

```text
先理解递归中序遍历为什么升序；
再重点掌握迭代栈写法。
```

## ⑧ 面试追问

### Q1：为什么不能使用前序遍历？

前序遍历顺序是：

```text
根 → 左 → 右
```

它不能保证从小到大。

例如：

```text
        3
       / \
      1   4
       \
        2
```

前序遍历：

```text
3, 1, 2, 4
```

不是升序。

只有中序遍历：

```text
1, 2, 3, 4
```

是升序。

---

### Q2：时间复杂度是多少？

迭代方法不一定访问整棵树，访问到第 `k` 小后就停止。

若树高为 `h`，可以近似表示为：

```text
O(h + k)
```

- 最开始沿左边走到最小节点需要 `O(h)`；
    
- 然后访问到第 `k` 个节点。
    

最坏情况下仍可能访问所有节点：

```text
O(n)
```

空间复杂度是栈的大小：

```text
O(h)
```

平衡树中：

```text
O(log n)
```

退化成链表时：

```text
O(n)
```

---

### Q3：频繁查询第 k 小怎么优化？

给每个节点额外维护：

```cpp
int size;
```

表示该节点的整棵子树有多少个节点。

设左子树大小为 `leftSize`：

```text
k <= leftSize：
答案在左子树。

k == leftSize + 1：
当前节点就是答案。

k > leftSize + 1：
答案在右子树，并令
k -= leftSize + 1。
```

若配合平衡二叉搜索树，查询、插入和删除都可以做到 `O(log n)`。

---

### 面试表达

> 二叉搜索树的中序遍历结果是严格升序的，因此第 `k` 小的元素就是中序遍历访问到的第 `k` 个节点。我使用栈模拟中序遍历，先不断沿左孩子压栈，到达最左节点后弹栈访问。每访问一个节点就让 `k--`，当 `k == 0` 时直接返回当前节点值；然后进入当前节点的右子树继续中序遍历。最坏时间复杂度为 `O(n)`，辅助空间复杂度为 `O(h)`。

## ⑨ 复习总结

```text
230. 二叉搜索树中第 K 小的元素

题型：
BST + 中序遍历。

核心性质：
BST 的中序遍历结果严格升序。

推荐方法：
迭代中序遍历。

执行流程：
1. 使用 stack 保存节点。
2. 从当前节点开始不断向左，将沿途节点压栈。
3. 到达空节点后，弹出栈顶并访问。
4. 每访问一个节点就执行 k--。
5. 当 k == 0 时，当前节点就是第 k 小。
6. 然后进入当前节点的右子树。

关键代码：
while (cur != nullptr) {
    st.push(cur);
    cur = cur->left;
}

cur = st.top();
st.pop();

if (--k == 0) {
    return cur->val;
}

cur = cur->right;
```

一句话记忆：

> **BST 中序遍历天然升序，第 K 小就是中序遍历访问到的第 K 个节点。**
