# C++知识  
#### 1、sizeof和strlen的区别 （第一时间想不出）
	`sizeof` 和 `strlen` 的核心区别是：**`sizeof` 算“占多少字节内存”，`strlen` 算“C 字符串有多少个字符”。**
	`sizeof` 用于计算对象或类型所占的字节数；`strlen` 用于计算以 `\0` 结尾的 C 字符串长度，不包含结尾的 `\0`。对于字符数组，`sizeof` 得到整个数组大小；对于字符指针，`sizeof` 只得到指针大小。

#### 2、const关键字，const int* p，int* const p有什么区别  （第一遍错误）
	`const int* p`：**指向常量的指针**，`p` 保存的地址可以改变，不能通过 `p` 修改它指向的值
	`int* const p`：**常量指针**，`p` 保存的地址不能改变，可以修改它指向的值

#### 3、static关键字  （部分对）
`static` 成员变量：**属于类本身，不属于某个对象**，所有对象共享同一份数据。
`static` 成员函数：也属于类本身，可以直接通过 `类名::函数名()` 调用；**没有 `this` 指针，因此不能直接访问非静态成员**。
**函数内部的 static 局部变量**：只初始化一次，生命周期持续到程序结束。
**文件作用域的 static 函数/变量**：限制在当前源文件内使用，也就是具有**内部链接（internal linkage）**。
  
#### 4、explicit关键字，什么情况下应该禁止隐式类型转换  
`explicit` 一般用于单参数构造函数，防止编译器把其他类型隐式转换为当前类对象，使类型转换必须显式进行，提高代码安全性和可读性。
例如：
```cpp
class A {
public:
    explicit A(int x) {}
};

A a1(10);    // 可以
// A a2 = 10; // 不可以，禁止 int 隐式转换成 A
```
什么时候该禁止隐式转换？
> 当这种自动转换可能让代码产生歧义、误调用，或者隐藏 bug 时，就应该加 `explicit`。

再注意一点：**C++11 以后转换运算符也可以加 `explicit`**。
#### 5、结构体字节对齐  （不懂）
  结构体字节对齐是编译器为了提高内存访问效率，根据各成员的对齐要求插入 padding，使成员地址满足对齐规则，并使结构体总大小通常是最大对齐数的整数倍。
#### 6、define inline typedef  
	  `#define` 是预处理指令，在编译前进行**文本替换**。
	例如：
```cpp
#define PI 3.14
#define MAX(a, b) ((a) > (b) ? (a) : (b))
```
	  `inline` 用于内联函数，但是否展开由编译器决定，同时允许函数定义放在头文件中
	  `typedef` 用于给已有类型定义别名，C++11 后通常更推荐 `using`。
#### 7、四种类型转换  
- `static_cast`
    - 用于**有明确类型关系、编译期可检查的转换**
    - 比如基本类型转换、父子类之间的向上转换，以及程序员确认安全的向下转换
    - 例：`double -> int`
```cpp
int a = static_cast<int>(3.14);
```

- `reinterpret_cast`
    - 用于**底层的、几乎不做语义检查的类型重新解释**
    - 常见于指针、整数地址等底层转换
    - 风险高，不应该简单理解成“不相近类型转换”
```cpp
int* p = ...;
char* q = reinterpret_cast<char*>(p);
```

- `const_cast`
    - 用于**增加或去掉 `const/volatile` 属性**
    - 但如果对象本身原来就是真正的 `const` 对象，去掉 `const` 后再修改它，属于**未定义行为**
```cpp
const int a = 10;
int* p = const_cast<int*>(&a);
// *p = 20;  // 未定义行为
```

- `dynamic_cast`
    - 用于**多态类体系中的安全运行时类型转换**
    - 常见是父类指针/引用向子类转换
    - 父类通常必须有虚函数
    - 指针转换失败返回 `nullptr`，引用转换失败抛 `std::bad_cast`
```cpp
Base* p = new Derived;
Derived* d = dynamic_cast<Derived*>(p);
```

#### 8、dynamic_cast的底层原理，实例的type_info存在哪的  (不知道)
**这题重点是把 RTTI、虚表、`type_info` 串起来。**

**面试建议回答：**
> `dynamic_cast` 的底层依赖 RTTI（Run-Time Type Information，运行时类型信息）。  
> 对于多态类，对象里通常有一个 `vptr` 指向虚表，虚表附近会关联这个类型的 RTTI 信息。执行 `dynamic_cast` 时，编译器会通过对象的 `vptr` 找到运行时类型信息，再根据继承关系判断目标类型是否合法，并在多继承等情况下做指针偏移调整。转换成功返回正确地址，失败时指针返回 `nullptr`，引用则抛 `std::bad_cast`。[Microsoft Learn](https://learn.microsoft.com/en-us/cpp/cpp/run-time-type-information?view=msvc-170&utm_source=chatgpt.com)

你问的重点：**`type_info` 存在哪？**
不要回答：
> `type_info` 存在对象里面。

更准确是：
> 对象本身通常只额外保存一个 `vptr`；`type_info` 对象一般是编译器生成的静态 RTTI 数据，存放在程序的只读数据区域附近。对象通过 `vptr -> 虚表/RTTI结构 -> type_info` 间接找到类型信息。[C++参考](https://en.cppreference.com/cpp/language/object?utm_source=chatgpt.com)

可以简单理解成：
```
Derived对象
┌──────────────┐
│ vptr ─────────────┐
│ 成员变量      │    │
└──────────────┘    │
                    ↓
                 虚表/RTTI
              ┌─────────────┐
              │ RTTI信息    │ ──→ type_info(Derived)
              │ 虚函数地址  │
              │ ...         │
              └─────────────┘
```

如果面试官继续问 **MSVC 下具体实现**，可以再说：
> 在 MSVC 中具体布局属于 ABI 实现细节，RTTI 信息会通过虚函数表附近的 RTTI 描述结构关联到类型描述；而 GCC/Clang 常见的 Itanium ABI 中，虚表中明确存在指向 `type_info` 对象的指针。C++ 标准本身并没有规定必须采用哪一种具体内存布局。[itanium-cxx-abi.github.io](https://itanium-cxx-abi.github.io/cxx-abi/abi.html?utm_source=chatgpt.com)

另外这也是为什么 `dynamic_cast` 做运行时向下转换时通常要求源类型是**多态类型，也就是至少存在一个虚函数**。[C++参考](https://en.cppreference.com/cpp/language/dynamic_cast?utm_source=chatgpt.com)

#### 9、多态是怎么实现的  
  多态是通过虚指针和虚函数表实现的，对于一个有虚函数的父类和其子类，他们类中都会有一个虚指针，该指针会指向虚函数表，若子类都重新写了父类的虚函数，那么他们自己所对应的虚表里面的虚函数不重写会是继承父类的，重写了就会被自己重写的虚函数覆盖掉，所以不同类都会有不同的重写这样就造成了多态

**AI诊断及建议**：你的回答：**整体正确**。主要有两点可以改得更严谨：
- 不是“父类和子类都会有一个虚指针”这么绝对，更准确说是**多态对象通常含有 `vptr`**，具体布局属于编译器实现。
- “覆盖虚表里的函数”可以说成：**子类自己的虚表槽位指向重写后的函数地址**，没重写的槽位仍指向基类版本。C++ 标准保证动态绑定语义，但不强制必须用虚表；主流编译器通常这样实现。[Microsoft Learn](https://learn.microsoft.com/en-us/cpp/cpp/virtual-functions?view=msvc-170&utm_source=chatgpt.com)
**面试建议回答：**
> C++ 的运行时多态通常通过虚函数表 `vtable` 和虚指针 `vptr` 实现。  
> 一个包含虚函数的多态对象，通常会有一个 `vptr`，指向当前实际类型对应的虚函数表。虚表里保存虚函数入口地址。  
> 如果子类重写了父类虚函数，那么子类虚表中对应位置会指向子类实现；如果没有重写，则仍然使用父类实现。  
> 当我们通过父类指针或引用调用虚函数时，程序运行时会通过对象的 `vptr` 找到虚表，再调用对应函数，因此即使静态类型是父类，也能调用实际对象类型的函数，这就是动态绑定，也就是运行时多态。 [Microsoft Learn](https://learn.microsoft.com/en-us/cpp/cpp/virtual-functions?view=msvc-170&utm_source=chatgpt.com)

一个经典例子：
```cpp
Base* p = new Derived;
p->func();
```
如果 `func()` 是虚函数，就会根据 `p` 实际指向的 `Derived` 对象，在运行时调用 `Derived::func()`。[Microsoft Learn](https://learn.microsoft.com/en-us/cpp/cpp/virtual-functions?view=msvc-170&utm_source=chatgpt.com)
**面试高频追问：**  
`vptr` 一般什么时候设置？——通常在构造过程中由编译器初始化，MSVC 文档也明确提到构造时会初始化虚函数指针，使其指向对应类的虚函数表。[Microsoft Learn](https://learn.microsoft.com/en-us/cpp/cpp/constructors-cpp?view=msvc-170&utm_source=chatgpt.com)
  
#### 10、虚指针和虚函数表  
  当一个对象有虚函数的时候，那么它将会有虚指针和虚函数表，虚指针是该对象构造时会初始化的使它指向虚函数表，虚函数表存储的是虚函数，若该对象是某多态对象的子类，那么它的虚函数表将会也有父类的虚函数表
**AI诊断与建议：**
你的回答**基本正确，但有两个关键点要改**：
- 对象里通常只有 **虚指针 `vptr`**，**虚函数表 `vtable` 不是每个对象一份**，通常是同一个类的对象共享一张虚表。
- 子类虚表不是“包含父类虚表”，而是**子类有自己的虚表**；继承来的虚函数占据相应槽位，重写后对应槽位改为指向子类函数。C++ 标准只规定动态绑定行为，`vptr/vtable` 属于主流编译器的典型实现。[C++参考](https://en.cppreference.com/cpp/language/virtual?utm_source=chatgpt.com)
**面试建议回答：**
> 一个类只要声明或继承了虚函数，它的对象通常就会包含一个 `vptr`，指向该对象实际类型对应的 `vtable`。  
> `vtable` 一般由同一类型的所有对象共享，里面主要保存虚函数的入口地址。  
> 子类继承父类后会有自己的虚表，如果没有重写某个虚函数，对应位置仍然指向父类实现；如果重写了，则该位置会改为指向子类实现。  
> 当通过父类指针或引用调用虚函数时，会通过对象的 `vptr` 找到虚表，再找到最终应该调用的函数，从而实现运行时多态。[Microsoft Learn](https://learn.microsoft.com/en-us/cpp/cpp/virtual-functions?view=msvc-170&utm_source=chatgpt.com)

你这题最重要的一句可以记成：
> **对象持有 `vptr`，同类型对象共享 `vtable`；子类有自己的虚表，而不是“包含父类虚表”。**

#### 11、类的初始化顺序，考虑虚继承、多重继承情况下呢？类成员的初始化顺序和初始化列表顺序有关系吗？  
和初始化列表没有关系，而是和类成员定义的顺序有关系

**AI诊断与建议：**
你没看懂主要是因为这题其实同时在问 **3 层初始化顺序**：
1. 虚基类怎么初始化
2. 多继承的多个父类怎么初始化
3. 类自己的成员变量怎么初始化

真正顺序是：
> **虚基类 → 直接基类 → 成员变量 → 构造函数体**

其中成员变量的初始化顺序，**确实与初始化列表里的书写顺序无关，而与成员在类中的声明顺序有关**。[C++参考](https://en.cppreference.com/cpp/language/constructor?utm_source=chatgpt.com)

例如：
```cpp
class A {
public:
    A() : b(1), a(2) {}

private:
    int a;
    int b;
};
```
虽然初始化列表写的是：
```
b(1), a(2)
```
但实际还是：
```
a 先初始化
b 后初始化
```
因为类里是：
```
int a;
int b;
```
微软也专门会对这种初始化列表顺序与声明顺序不一致的情况给出警告。[Microsoft Learn](https://learn.microsoft.com/is-is/cpp/error-messages/compiler-warnings/c5038?view=msvc-170&utm_source=chatgpt.com)

多继承也是类似：
```cpp
class C : public A, public B
{
};
```
一定是：
```
A
↓
B
↓
C自己的成员
↓
C构造函数体
```
不是看构造函数初始化列表里 `A()`、`B()` 谁写前面，而是看：
```
class C : public A, public B
```
这里的继承声明顺序。[Microsoft Learn](https://learn.microsoft.com/en-us/cpp/cpp/constructors-cpp?view=msvc-170&utm_source=chatgpt.com)

虚继承再多一层：
```
虚基类
↓
直接基类
↓
成员变量
↓
构造函数体
```
而且虚基类由**最派生类（most-derived class）负责初始化**。[C++参考](https://en.cppreference.com/cpp/language/constructor?utm_source=chatgpt.com)

**面试建议回答：**
> C++ 类对象构造时，初始化顺序与构造函数初始化列表的书写顺序无关。  
> 如果涉及虚继承，先初始化虚基类；然后按照继承声明顺序初始化直接基类；再按照成员变量在类中的声明顺序初始化成员；最后执行构造函数体。  
> 对于多继承，多个直接基类按照继承列表从左到右初始化。虚基类则由最派生类负责初始化。[C++参考](https://en.cppreference.com/cpp/language/constructor?utm_source=chatgpt.com)

这题你面试直接背这一句就够：
> **虚基类 → 直接基类 → 成员变量 → 构造函数体；成员顺序看声明，不看初始化列表。**

析构顺序则正好相反。[C++参考](https://en.cppreference.com/cpp/language/constructor?utm_source=chatgpt.com)

#### 12、基类的析构函数为什么应该声明为虚函数  （方向搞错了）
因为有时候有些子类没有申请内存资源，但是它继承的父类申请了内存资源，那它可以不用自己重写析构函数直接继承父类的析构函数去释放资源就行。也有些子类它是自己申请了内存资源的所以它们不能用父类的析构函数，只能是自己重写一个析构函数来释放内存资源

**AI诊断与建议：**
你的回答**方向偏了**。这题核心不是“父类和子类谁申请了内存”，而是：
> **当通过父类指针删除一个实际的子类对象时，必须保证先调用子类析构，再调用父类析构。**

如果基类析构函数不是虚函数，那么：
```cpp
Base* p = new Derived;
delete p;
```
这种通过基类指针删除派生类对象的行为是未定义行为，可能导致子类析构函数不被正确调用，从而造成资源泄漏。[C++参考](https://en.cppreference.com/cpp/language/virtual?utm_source=chatgpt.com)

**面试建议回答：**
> 基类析构函数声明为虚函数，主要是为了保证通过基类指针删除派生类对象时，能够正确调用完整的析构链。  
> 当析构函数是虚函数时，`delete` 基类指针会先调用派生类析构函数，再调用基类析构函数，从而正确释放派生类和基类各自管理的资源。  
> 如果基类析构函数不是虚函数，而又通过基类指针删除派生类对象，会产生未定义行为。  
> 因此对于需要作为多态基类使用的类，析构函数通常应该声明为 `virtual`。[C++参考](https://en.cppreference.com/cpp/language/virtual?utm_source=chatgpt.com)

这题你最该记住的是：
> **虚析构不是为了“让子类继承父类析构”，而是为了通过父类指针 `delete` 子类对象时，能够正确走完整析构链。**

#### 13、虚继承解决什么问题  
  虚继承解决的问题是子类可以修改从父类继承过来的行为，例如父类是人类，那么父类的行为行走可能就是两条腿走，因为这个正常人都是两条腿跑，如果婴儿继承它的话，那肯定得修改一下行为，因为婴儿行走只能是爬，所以虚继承能够解决子类能够重写行为的问题

**AI诊断与建议：**
你的回答**把“虚继承”和“虚函数重写”混淆了**。  
你举的“人类/婴儿修改行为”属于**虚函数实现多态**，不是虚继承。

虚继承主要解决的是：
> **多重继承中的菱形继承问题，避免最底层子类中出现多份同一个公共基类对象。** [C++参考](https://en.cppreference.com/cpp/language/derived_class?utm_source=chatgpt.com)

**面试建议回答：**
> 虚继承主要用于解决 C++ 多重继承中的菱形继承问题。  
> 当两个中间类都继承自同一个基类，而一个子类又同时继承这两个中间类时，如果使用普通继承，最底层子类中会存在两份公共基类子对象，容易造成数据冗余和成员访问歧义。  
> 使用虚继承后，这些派生路径会共享同一份虚基类子对象，从而避免重复继承和二义性。[C++参考](https://en.cppreference.com/cpp/language/derived_class?utm_source=chatgpt.com)

你可以直接记：
> **虚函数解决“行为多态”，虚继承解决“菱形继承中的重复基类”。**

14、深拷贝和浅拷贝  
  深拷贝是指将一个对象里面的东西全部复制一份出来，然后再用一个新的指针指向这一份复制出来的数据上，而浅拷贝指的是创建一个新指针指向同一份数据上

**AI诊断与建议：**
你的回答**基本正确**，但“浅拷贝就是创建一个新指针”不够准确。  
浅拷贝本质是**直接复制成员值**；如果成员里有指针，就会导致两个对象中的指针指向同一块内存。

#### 27、在析构函数中delete this会发生什么  （没接触过不清楚）
**AI诊断与建议：**
不是，**析构函数里有 `this` 指针**。析构函数本质上也是非静态成员函数，所以可以访问成员变量和成员函数。[Microsoft Learn](https://learn.microsoft.com/zh-cn/cpp/cpp/destructors-cpp?utm_source=chatgpt.com)

真正的问题是：如果你在析构函数里写 `delete this;`，会非常危险，通常会导致**重复析构 / 重复释放**，属于未定义行为风险。

**面试建议回答：**
> 析构函数中是有 `this` 指针的。  
> `delete this` 的含义是通过当前对象指针再次销毁并释放自己。  
> 但如果这句本身就在析构函数内部，那么 `delete this` 会再次触发当前对象的析构流程，形成递归析构，并且最终可能造成重复释放内存，因此这种写法通常是错误的。  
> 另外，即使在普通成员函数中使用 `delete this`，也必须保证对象确实由 `new` 创建，并且执行之后不能再访问任何成员，因为此时 `this` 已经失效。[cppreference](https://en.cppreference.com/cpp/language/this?utm_source=chatgpt.com)

你可以直接记：
> **析构函数有 `this`，但析构函数里 `delete this` 基本就是“销毁过程中再次销毁自己”，容易递归和重复释放。**


#### 28、为什么析构函数不应该抛异常？  （不知道）
**AI诊断与建议：**
这题核心是：
> **析构函数可能在异常栈展开过程中被调用，如果此时析构函数再抛出一个异常，就会同时存在两个异常，程序通常会直接 `std::terminate()`。**

另外，析构函数默认就是 `noexcept(true)`，随意抛异常本身也很危险。

**面试建议回答：**
> 析构函数不应该抛异常，主要是因为析构函数经常会在异常栈展开过程中执行。  
> 如果当前已经有一个异常正在传播，而析构函数又抛出第二个异常，C++ 无法同时处理两个异常，会调用 `std::terminate()` 直接终止程序。
> 
> 因此析构函数一般应该保证不抛异常。如果析构过程中可能失败，通常应该在析构函数内部捕获异常并处理，而不是继续向外抛。

你面试里直接记一句：
> **析构函数不能在栈展开期间再抛异常，否则会触发 `std::terminate()`。**

#### 29、(int)0.1和(int)-0.1的结果为什么都是0？  （不知道）
**AI诊断与建议：**

不是主要因为二进制表示问题。核心原因是：
> **浮点数转换成整数时，小数部分会被直接截断，方向是朝 0 截断。**

所以：
```
(int)0.1   // 0
(int)-0.1  // 0
```

**面试建议回答：**
> C++ 中浮点数转换为整数时，会直接丢弃小数部分，也就是向 0 截断，而不是四舍五入。
> 因此 `0.1` 截断后是 `0`，`-0.1` 截断后也是 `0`。
> 
> 同理：
> (int)3.9   // 3
> (int)-3.9  // -3
> 
> 所以这个结果主要由 **C++ 的类型转换规则**决定，而不是由浮点数的二进制精度问题导致。
