## 一、值类别与引用基础

### 第 1 题：如何区分左值、纯右值和将亡值？

**必答范围：表达式与类型 → 值类别 → 对象身份与资源复用 → 分类判断。**

1. C++ 中的值类别描述的是变量、类型还是表达式？左值（lvalue）、纯右值（prvalue）、将亡值（xvalue）各有什么特点？泛左值（glvalue）与右值（rvalue）分别包含哪些类别？
2. 判断“有名字”“能取地址”“可以修改”能否作为各值类别的严格定义？为什么要把对象是否存在、是否有身份与表达式能否用于资源复用分开考虑？
3. 逐项判断下面表达式的类型及值类别；哪些可以作为赋值操作的左操作数，为什么？

```cpp
int x = 1;
const int cx = 2;
int* p = &x;
int&& rr = 3;

x;  cx;  *p;  42;  x + 1;  rr;  std::move(x);
```

4. 返回 `T`、`T&`、`T&&` 的函数调用表达式通常分别是什么值类别？C++17 对类类型纯右值和临时对象实质化有什么影响？
#### 正确回答
C++ 的值类别是表达式的属性，主要分为左值、纯右值和将亡值。
左值通常具有对象身份，可以标识已有对象，但不一定能够修改。
纯右值主要表示计算结果或用于初始化对象的值，例如整数字面量和算术表达式的结果。
将亡值既具有对象身份，又属于右值，其资源可以被复用，例如 `std::move(x)` 返回的表达式。
泛左值包括左值和将亡值，右值包括纯右值和将亡值。
需要特别区分变量声明类型和表达式值类别。例如右值引用变量 `int&& rr`，当使用 `rr` 这个名字时，它仍然是左值表达式。

#### 示例
##### 一、重新理解 C++ 的三种基本值类别
首先必须纠正：
C++ 的值类别描述的是表达式，不是变量、类型，也不是数据存储在哪个内存区域。
例如：
```cpp
int&& rr = 10;
```
`rr` 的声明类型是 `int&&`，但表达式 `rr` 是左值。这是因为变量的类型和使用变量名时表达式的值类别是两回事。
![](../../_Pasted_Image/Pasted%20image%2020261103154614.png)

| 值类别          | 核心理解                   | 常见示例               |
| ------------ | ---------------------- | ------------------ |
| 左值（lvalue）   | 可以标识某个对象或函数，通常用于定位已有对象 | `x`、`*p`、`rr`      |
| 纯右值（prvalue） | 主要表示计算结果或用于初始化对象的值     | `42`、`x + 1`、`T{}` |
| 将亡值（xvalue）  | 有对象身份，并且其资源可以被考虑复用     | `std::move(x)`     |
这里特别注意：
- 左值不一定能修改，例如 `const int cx`。
- 右值不一定是只读常量，更不一定存储于 `.rdata`。
- 将亡值不代表对象马上死亡，也不代表一定发生资源转移。
例如整数 `42` 可能作为立即数参与计算，并不需要存储到 `.rdata`。字符串字面量 `"hello"` 虽然通常存储在只读区域，但表达式本身属于左值。
##### 二、为什么有名字不代表一定是左值？
你需要建立一个最重要的区分：
```cpp
int x = 10;
int&& rr = 20;
```

```cpp
x;             // 左值
rr;            // 左值
std::move(x);  // 将亡值
42;            // 纯右值
```
`rr` 虽然声明为右值引用，但当你使用 `rr` 这个名字时，它表达的是一个左值。
`std::move(x)` 则将表达式转换为可以绑定右值引用的将亡值表达式，但不负责执行真正的移动操作。
同样，“能够取地址”和“能够修改”也不适合作为严格定义，因为存在 `const` 左值、位域左值，以及能够修改的类类型右值等情况。
##### 三、你第 3 问的完整正确答案
原题：
```cpp
int x = 1;
const int cx = 2;
int* p = &x;
int&& rr = 3;
```

|表达式|表达式类型|值类别|能否作为普通内置赋值左操作数|
|---|---|---|---|
|`x`|`int`|左值|可以|
|`cx`|`const int`|左值|不可以，具有 const 限定|
|`*p`|`int`|左值|可以|
|`42`|`int`|纯右值|不可以|
|`x + 1`|`int`|纯右值|不可以|
|`rr`|`int`|左值|可以|
|`std::move(x)`|`int`|将亡值|不可以|
最后一行要特别注意：`std::move(x)` 是 `int` 的将亡值，而内置赋值要求左操作数为可修改左值。
但对于具有合适赋值运算符的类类型，将亡值也可能允许赋值，不能把这个结论机械套到所有类型。
##### 四、函数返回值的值类别
假设 `T` 为合适的对象类型：
```cpp
T f1();
T& f2();
T&& f3();
```

|表达式|值类别|
|---|---|
|`f1()`|纯右值（prvalue）|
|`f2()`|左值（lvalue）|
|`f3()`|将亡值（xvalue）|
记忆方法：
- 返回 `T`：得到值，通常是纯右值。
- 返回 `T&`：得到左值引用，对应左值表达式。
- 返回 `T&&`：得到右值引用，对应将亡值表达式。
###### C++17 的重要变化
C++17 引入了更明确的纯右值语义，某些场景不再要求先创建一个临时对象，再移动到目标对象。
```cpp
struct A {};

A make()
{
    return A{};
}

A obj = make();
```
在 C++17 中，这类同类型纯右值初始化可以直接构造最终对象，不需要额外的复制或移动构造。
这属于保证的拷贝消除，后面第 8 题会专门学习。

#### 正确回答
C++ 的普通左值引用 `T&` 主要绑定左值，`const T&` 可以绑定左值和右值，右值引用 `T&&` 则可以绑定纯右值和将亡值。

通过函数返回引用不会再次延长临时对象的生命周期，因此需要警惕悬空引用。

##### 一、三种引用分别能绑定什么？
这是本题最重要的知识点。
![](../../_Pasted_Image/Pasted%20image%2020261103161338.png)
这里讨论普通非模板引用绑定，`T` 假设为非 const 的普通对象类型，不涉及转发引用等特殊推导规则。

看具体代码：
```cpp
int n = 10;

// 1. 普通左值引用
int& a = n;       // 正确
// int& b = 20;   // 错误

// 2. const 左值引用
const int& c = n;             // 正确
const int& d = 20;            // 正确
const int& e = std::move(n);  // 正确

// 3. 右值引用
int&& f = 20;            // 正确
int&& g = std::move(n);  // 正确
// int&& h = n;          // 错误
```
为什么 `const T&` 能够绑定右值？
因为它允许通过只读引用访问临时对象，而不要求修改临时对象。
需要记住：`const T&` 可以绑定左值，也可以绑定右值。
另外，`int&& f = 20` 之后，表达式 `f` 仍然是左值，因为使用名字 `f` 时，它标识的是一个已有对象。
##### 二、临时对象的生命周期延长
这是你第 3 问完全不会的部分。
###### 1. 正常情况下，临时对象什么时候销毁？
```cpp
std::string("boss");
```
这条语句创建的临时字符串对象，通常在该完整表达式结束时销毁，也就是分号对应的完整表达式结束时。
###### 2. 直接绑定到局部引用时
```cpp
const std::string& a = std::string("boss");
```
这里临时对象的生命周期会被延长。
![](../../_Pasted_Image/Pasted%20image%2020261103161402.png)
普通局部右值引用也可以延长临时对象的生命周期：
```cpp
std::string&& b = std::string("enemy");
```
注意：这是直接绑定临时对象的情况，不意味着任何间接传递引用的方式都能延长生命周期。
###### 3. 临时对象作为函数参数时
```cpp
void Print(const std::string& s)
{
    std::cout << s;
}

Print(std::string("boss"));
```
这里临时对象会存活到包含函数调用的完整表达式结束。
也就是说，`Print()` 执行期间是安全的；调用语句结束后，临时对象就会被销毁。
###### 4. 函数返回引用时，能不能继续延长生命周期？
不能。
看文档中的原题：
```cpp
const std::string& identity(const std::string& s)
{
    return s;
}

const std::string& a = std::string("boss");

const std::string& b =
    identity(std::string("enemy"));
```
分别分析：

| 引用  | 是否安全 | 原因                       |
| --- | ---- | ------------------------ |
| `a` | 安全   | 临时对象直接绑定局部引用，生命周期延长      |
| `b` | 不安全  | 临时对象只存活到初始化 `b` 的完整表达式结束 |
`identity()` 返回的只是引用，并没有创建新的字符串对象，也不会再次延长临时对象的生命周期。
因此，当初始化 `b` 的语句执行结束后，`b` 就成为悬空引用（Dangling Reference）。
后续通过 `b` 访问被销毁的对象会产生未定义行为。

### 第 3 题：`std::move` 做了什么，为什么调用它不一定发生移动？

**必答范围：类型转换 → 重载选择 → `const` → 被移动对象的状态。**

```cpp
std::string a = "texture";

auto p = std::make_unique<int>(7);
auto q = std::move(p);
```

3. `std::move(const T)` 为什么常常不能调用 `T(T&&)`？如果类型提供 `T(const T&&)`，这个问题应怎样重新分析？
4. 标准库对象被移动后通常有什么状态保证？`unique_ptr` 移动后有什么更具体的保证？用户自定义类型应依据什么判断移动后状态？还能否析构、赋值或调用成员函数？
5. 多次移动同一对象、移动后继续使用、对返回值或基本类型使用 `std::move`，分别需要检查什么？

#### 正确回答
`std::move` 本质上是将表达式转换为将亡值的工具，并不会直接移动资源。真正是否调用移动构造或移动赋值，需要根据重载决议决定。
例如，普通 `std::string` 使用 `std::move` 初始化另一个字符串，通常会选择移动构造；但是对 `const std::string` 使用 `std::move`，得到的是 `const std::string&&`，无法绑定普通移动构造函数的 `std::string&&` 参数，因此通常退回复制构造。
对于移动后的状态，标准库类型通常保证对象仍然有效，但值可能未指定；`unique_ptr` 则明确保证移动后源指针为空。
移动后的对象仍然可以析构和重新赋值，而对返回值滥用 `std::move` 还可能妨碍拷贝消除。

#### 示例
##### 一、为什么 std::move 不一定发生移动？
先记住：
`std::move` 本质上是一种类型转换，它不会直接移动任何资源。
例如：
```cpp
std::string a = "hello";
std::string b = std::move(a);
```
执行过程是：
1. `a` 是左值表达式。
2. `std::move(a)` 将其转换成将亡值表达式。
3. 编译器根据这个表达式进行重载决议。
4. 因为 `std::string` 有适用的移动构造函数，所以通常选择移动构造。
可以简化理解为：
```cpp
std::move(a);                 // 只转换值类别
std::string b(std::move(a));  // 后续构造才可能真正移动
```
`std::move` 不负责移动，移动构造函数或移动赋值运算符才可能负责资源转移。
##### 二、为什么 const 对象使用 std::move 仍然会复制？
你第 2、3 问最大的错误就在这里。
原代码：
```cpp
const std::string c = "mesh";
std::string d = std::move(c);
```
`std::move(c)` 的结果类型是 `const std::string&&`，而不是 `std::string&&`。
假设 `string` 提供以下两个构造函数：
```
string(const string& other); // 复制构造

string(string&& other);      // 移动构造
```
分析：

|候选函数|能否接收 `const string&&`|原因|
|---|---|---|
|`string(const string&)`|可以|const 左值引用能够绑定右值|
|`string(string&&)`|不可以|不能丢弃源对象的 const 限定|
因此：
```cpp
std::string d = std::move(c); // 调用复制构造
```
如果用户自定义类型专门提供：
```cpp
T(const T&& other);
```
它就可以接受 const 将亡值，但这也不意味着一定能够转移资源。因为 `const` 仍然限制对源对象的修改。
核心结论：`std::move` 不会去掉 `const`。
##### 三、移动后的对象还能不能使用？
你这里回答了两个常见错误。
###### 1. string 移动后一定为空吗？
不一定。
```cpp
std::string a = "hello";
std::string b = std::move(a);
```
移动后，`a` 仍然是一个有效的 `std::string` 对象，但其值通常处于有效但未指定的状态（Valid but Unspecified State）。
也就是说：
- 可以正常析构。
- 可以重新赋值。
- 可以调用满足当前状态要求的成员函数。
- 不能假设其内容一定为空。
###### 2. unique_ptr 移动后呢？
```cpp
auto p = std::make_unique<int>(10);
auto q = std::move(p);
```
这里有明确保证：
```
p == nullptr; // true
```
`q` 接管对象所有权，`p` 变为空智能指针。
注意：移动后状态要看具体类型的规定，不是所有类型都像 `unique_ptr` 一样保证为空。
###### 3. 已经移动的对象还能继续使用吗？
可以，但必须满足对应操作的前置条件。
```cpp
std::string a = "hello";
std::string b = std::move(a);

a = "world";  // 合法
a.clear();    // 合法
```
移动并不会自动结束源对象的生命周期。
##### 四、三个高频陷阱
① 对同一个对象连续调用两次 `std::move`，一定错误吗？
不一定。`std::move` 本身只是类型转换，重复调用不会自动产生错误。但是如果后续操作会消费对象资源，就必须考虑第一次移动后的状态。
② 对 int 使用 std::move，能提升性能吗？
通常不能。
```cpp
int a = 10;
int b = std::move(a);
```
这里本质上还是复制整数值，不存在需要转移所有权的动态资源。

③ 对函数返回值使用 std::move，是否一定更快？
不一定，反而可能妨碍拷贝消除。
```cpp
std::string Make1()
{
    return std::string("hello");
}

std::string Make2()
{
    std::string s = "hello";
    return std::move(s);
}
```
`Make1()` 在 C++17 中符合保证的拷贝消除条件。
`Make2()` 的 `return std::move(s)` 会阻止 NRVO，通常不如直接写 `return s;`。
详细机制在第 8 题继续学习。

##### 五、重复移动一定会产生未定义行为吗？
不一定。对于这里的 `std::string`，连续两次移动是合法的。
```cpp
std::string a = "hello";

std::string b = std::move(a);
std::string c = std::move(a);
```
你的误区是认为第一次移动后，`a` 的资源被消耗，所以 `a` 已经不能再使用。

实际上：
- 第一次移动后，`a` 仍然是有效的 `std::string` 对象。
- `a` 的具体内容处于有效但未指定的状态。
- 第二次移动仍然可以调用移动构造函数。
- `c` 的内容不保证为空，需要依据类型的具体保证判断。

移动资源 ≠ 销毁源对象。

至于：
```cpp
int x = 100;
int y = std::move(x);
```
这里不存在 `int` 的移动构造函数，因为 `int` 是内置类型。它只是将整数值复制给 `y`，所以 `x == 100` 仍然成立。

##### 六、RVO、NRVO 和 std::move 的区别
你把 `Make1` 和 `Make2` 说反了。
```cpp
std::string Make1()
{
    return std::string("hello");
}

std::string Make2()
{
    std::string s = "hello";
    return s;
}

std::string Make3()
{
    std::string s = "hello";
    return std::move(s);
}
```

|函数|机制|是否保证拷贝消除|
|---|---|---|
|`Make1`|C++17 同类型纯右值直接构造|保证|
|`Make2`|NRVO（具名返回值优化）|不保证，但允许|
|`Make3`|返回将亡值，通常选择移动构造|不符合 NRVO 条件|
为什么 `Make3` 会阻止 NRVO？

因为 NRVO 要求返回表达式是符合条件的局部对象名字：
```cpp
return s;             // 满足 NRVO 的形式要求
return std::move(s);  // 返回的是将亡值表达式
```
第二种写法不再是直接返回局部变量名，所以不符合 NRVO 条件。
记忆：
- `return T{};`：C++17 保证的直接构造。
- `return local;`：可能发生 NRVO。
- `return std::move(local);`：阻止 NRVO，通常发生移动。
##### 七、从零理解如何手写 std::move

先看答案：
```cpp
#include <type_traits>

template<typename T>
std::remove_reference_t<T>&& myMove(T&& value)
{
    return static_cast<std::remove_reference_t<T>&&>(value);
}
```
先不要死记，拆成三步理解。
###### 第一步：T&& 接收参数
```cpp
template<typename T>
void func(T&& value);
```
这里 `T&&` 是转发引用，可以在模板推导的配合下接收左值或右值。

例如：
```cpp
int x = 10;
func(x);
```
传入左值时，`T` 推导为 `int&`。
而：
```cpp
func(10);
```
传入右值时，`T` 推导为 `int`。
引用折叠的详细规则会在第 10 题学习。
###### 第二步：remove_reference_t 去掉引用
```cpp
std::remove_reference_t<T>
```
它的作用是去掉类型中的引用限定。

|T|remove_reference_t<T>|
|---|---|
|`int`|`int`|
|`int&`|`int`|
|`int&&`|`int`|
|`const int&`|`const int`|
注意：它不会去掉 `const`。
因此，加上 `&&`：
```cpp
std::remove_reference_t<T>&&
```
我们便可以构造出需要返回的右值引用类型。
###### 第三步：static_cast 转换表达式
```cpp
return static_cast<std::remove_reference_t<T>&&>(value);
```
为什么需要 `static_cast`？
因为无论 `value` 的声明类型是什么，它作为一个有名字的变量表达式，都是左值。
需要显式转换才能得到将亡值。
例如：
```cpp
int x = 10;
auto&& r = myMove(x);
```
内部发生的类型推导是：
myMove(x) 的推导过程
1. 实参 `x` 为左值，所以 `T` 推导为 `int&`。
2. `remove_reference_t<T>` 得到 `int`。
3. 目标转换类型为 `int&&`。
4. `static_cast<int&&>(value)` 产生将亡值表达式。
如果传入：
```cpp
const std::string s = "hello";
auto&& r = myMove(s);
```
则 `T` 推导为 `const std::string&`，最后返回的是 `const std::string&&`，表达式值类别为将亡值。
这也解释了为什么 `std::move` 不会去掉 const。
#### 面试追问
- 手写简化版 `std::move`，解释 `std::remove_reference_t` 和 `static_cast<T&&>` 各自的作用，并分别推导传入左值、右值和 `const` 对象时的返回类型及值类别。
**回答：**
`std::move` 的底层主要利用模板类型推导、类型萃取和 `static_cast` 实现。
首先通过转发引用接收参数，再利用 `remove_reference_t` 去掉引用限定，最后通过 `static_cast<T&&>` 将表达式转换为将亡值。
`std::move` 本身不转移资源，也不会移除 const 限定，真正的移动由后续选中的构造函数或赋值运算符完成。
被移动对象仍然具有有效的生命周期；返回局部对象时，一般应避免无意义地显式使用 `std::move`，以免阻止 NRVO。

##### 一、移动构造和移动赋值的区别

原代码：
```cpp
std::string a = "boss";
std::string b = std::move(a);

std::string c;
c = std::move(b);

c = std::move(c);
```

正确分析：

|语句|操作|
|---|---|
|`std::string a = "boss"`|普通字符串构造|
|`std::string b = std::move(a)`|移动构造|
|`std::string c`|默认构造|
|`c = std::move(b)`|移动赋值|
|`c = std::move(c)`|自移动赋值|

核心区别：
- 移动构造：创建一个新对象，接管源对象的资源。
- 移动赋值：目标对象已经存在，因此需要考虑如何处理它原来持有的资源。

例如：
```cpp
Buffer b(std::move(a)); // 移动构造

b = std::move(c);       // 移动赋值
```
##### 二、移动与浅拷贝到底有什么区别？

你说浅拷贝后两个对象各有各的资源，这一点是错误的。
假设对象 A 持有一块堆内存：
![](../../_Pasted_Image/Pasted%20image%2020261104185346.png)
对于我们这个独占资源类：
浅拷贝：
```cpp
B.data_ = A.data_;
```
两个对象保存相同的指针值。如果两个析构函数都执行 `delete[]`，就有重复释放风险。

移动：
```cpp
B.data_ = A.data_;
A.data_ = nullptr;
```
B 接管资源，A 不再持有这块资源。

注意：在正确转移之前，A 的原始指针并不是悬空指针，它仍然指向有效内存。真正的问题是两个对象可能同时认为自己拥有这块资源。
##### 三、正确手写移动构造和移动赋值

你尝试使用 `swap` 的方向有一定道理，但代码存在以下问题：
- `other = nullptr` 错误：`other` 是 `Buffer` 对象。
- `if (other == this)` 错误：需要比较 `&other` 和 `this`。
- `return this` 错误：返回类型是 `Buffer&`，应返回 `*this`。
- 移动赋值还需要处理目标对象已有的资源。

先学习下面这个直观版本。
```cpp
#include <cstddef>

class Buffer
{
private:
    int* data_ = nullptr;
    std::size_t size_ = 0;

public:
    explicit Buffer(std::size_t n)
        : data_(new int[n]), size_(n)
    {
    }

    ~Buffer()
    {
        delete[] data_;
    }

    Buffer(const Buffer&) = delete;
    Buffer& operator=(const Buffer&) = delete;

    // ① 移动构造
    Buffer(Buffer&& other) noexcept
        : data_(other.data_),
          size_(other.size_)
    {
        other.data_ = nullptr;
        other.size_ = 0;
    }

    // ② 移动赋值
    Buffer& operator=(Buffer&& other) noexcept
    {
        if (this == &other)
        {
            return *this;
        }

        // 先释放当前对象原有的资源
        delete[] data_;

        // 接管源对象资源
        data_ = other.data_;
        size_ = other.size_;

        // 清空源对象的资源所有权
        other.data_ = nullptr;
        other.size_ = 0;

        return *this;
    }
};
```
###### 移动构造如何执行？
假设：
```cpp
Buffer a(100);
Buffer b(std::move(a));
```
移动后：
- `b.data_` 接管原来 `a.data_` 的指针。
- `a.data_ = nullptr`。
- `a.size_ = 0`。
- 两个对象以后都能安全析构，不会重复释放这块资源。
###### 移动赋值如何执行？
```cpp
Buffer a(100);
Buffer b(200);

b = std::move(a);
```
移动赋值必须完成三个重要步骤：
1. 释放 b 原来的资源，避免内存泄漏。
2. 接管 a 的资源，实现所有权转移。
3. 清空 a 的资源指针，避免重复释放。
另外：
```cpp
b = std::move(b);
```
如果没有自移动保护，可能先删除自己的资源，再从自己读取刚刚释放的指针，导致严重错误。

所以我们写：
```cpp
if (this == &other)
{
    return *this;
}
```
其中：
- `this`：当前对象地址。
- `&other`：源对象地址。
- `*this`：当前对象本身，满足 `Buffer&` 返回类型。
###### 四、移动一定比复制快吗？
不一定。

例如：
```cpp
int a = 10;
int b = std::move(a);
```
对于内置类型 `int`，没有特殊的移动构造，仍然只是复制整数值。

再例如：
```cpp
struct Data
{
    int values[1000];
};
```
即使执行：
```cpp
Data b(std::move(a));
```
**固定大小数组也不会像堆指针一样直接转移整块存储的所有权，元素仍需要逐个初始化。**
因此，移动的性能收益主要取决于对象是否有可低成本转移的资源，而不是是否写了 `std::move`。

##### 一、编译器什么时候自动生成移动构造？

```cpp
struct A
```

##### 二、编译器生成的移动构造如何处理成员？
假设：
```cpp
struct Data
{
    std::string name;
    std::unique_ptr<int> ptr;
    const int id;
    int& ref;
};
```
如果移动构造函数能够正常生成，成员大致这样处理：

| 成员     | 移动构造时的处理                    |
| ------ | --------------------------- |
| `name` | 通常调用 `string` 的移动构造         |
| `ptr`  | 调用 `unique_ptr` 的移动构造，转移所有权 |
| `id`   | 复制整数值进行初始化                  |
| `ref`  | 新引用绑定到原引用所指向的对象             |
重点：编译器生成的移动构造是逐成员处理的，不代表每个成员都一定执行移动。
###### 为什么 const 和引用成员可能导致移动赋值被删除？
注意区分：
```cpp
Data b(std::move(a)); // 移动构造
b = std::move(a);     // 移动赋值
```
移动构造是初始化成员，而移动赋值是给已经存在的成员赋值。
对于：
```cpp
const int id;
int& ref;
```
- `id` 是 const 成员，不能在对象构造完成后重新赋值。
- `ref` 是引用成员，不能重新绑定到另一个对象。

因此，含有这类成员的类，其默认化的移动赋值运算符通常会被定义为已删除。本题这种成员组合就会导致这种结果。
但移动构造可以通过初始化列表初始化它们，两者不能混为一谈。

你第 4 问判断正确。
```cpp

};

struct B
{
    std::unique_ptr<int> value;
    ~B() {}
};
```
对于 A：
```cpp
A a;
A a2(std::move(a));
```
可以编译。

因为 A 没有隐式移动构造，但有可用的复制构造，`const A&` 可以绑定将亡值，因此调用复制构造。

对于 B：
```cpp
B b;
B b2(std::move(b));
```
不能编译。

因为 B 没有隐式移动构造，而包含的 `unique_ptr` 不支持复制，因此 B 的隐式复制构造被删除。
###### 如何让 B 可以移动但不能复制？
```cpp
struct B
{
    std::unique_ptr<int> value;

    B() = default;

    B(const B&) = delete;
    B& operator=(const B&) = delete;

    B(B&&) noexcept = default;
    B& operator=(B&&) noexcept = default;

    ~B() = default;
};
```
这里的 `B() = default` 不要漏掉。

因为显式声明了移动构造函数，编译器不会再隐式声明默认构造函数。

#### 示例
##### 一、Rule of Three、Five、Zero

###### 1. Rule of Three（三法则）

如果一个类需要自己管理资源，并且必须自定义以下三个函数中的某一个，那么通常应该考虑另外两个：
1. 析构函数：`~T()`
2. 复制构造函数：`T(const T&)`
3. 复制赋值运算符：`T& operator=(const T&)`
**为什么？**
因为如果一个类直接管理动态内存，而只定义析构函数，默认复制操作可能只是复制指针地址，造成重复释放。
###### 2. Rule of Five（五法则）

在三法则的基础上，再增加：
- 移动构造函数：`T(T&&)`
- 移动赋值运算符：`T& operator=(T&&)`
这五个特殊成员函数共同决定了资源的复制、转移和销毁行为。
###### 3. Rule of Zero（零法则）
你的理解方向正确，但要进一步明确：

尽量使用已经实现 RAII 的成员类型，让编译器管理特殊成员函数，而不是自己手写资源管理代码。
例如：
```cpp
class PlayerData
{
public:
    std::string name;
    std::vector<int> scores;
};
```
不需要手写析构、复制和移动函数。因为 `string`、`vector` 已经正确实现了这些操作。
如果类包含 `unique_ptr`，编译器也可以根据成员的能力提供适合的移动操作，而复制操作通常不可用。
##### 二、重要纠正：原始指针类不能直接依赖 = default 实现所有权移动
你说： 复制函数 `= delete`，移动函数 `= default` 或自己实现。
对于直接管理堆内存的 `Buffer`，移动函数不能直接用 `= default` 来实现所有权转移。
例如：
```cpp
class Buffer
{
    int* data_ = nullptr;

public:
    ~Buffer()
    {
        delete[] data_;
    }

    Buffer(Buffer&&) = default;
};
```
问题在于：
编译器默认生成的移动构造对原始指针成员只是复制指针值，不会自动把源指针设置为 `nullptr`。
因此，两个 `Buffer` 对象可能同时保存相同的资源地址，最终发生重复释放。
正确选择有两种：
方案 A：手写移动操作
```cpp
Buffer(Buffer&& other) noexcept
    : data_(other.data_)
{
    other.data_ = nullptr;
}
```
方案 B：改用 unique_ptr 管理资源（更推荐）
```cpp
class Buffer
{
    std::unique_ptr<int[]> data_;
};
```
这样可以把资源释放和所有权转移交给 `unique_ptr` 处理。
##### 三、异常安全的三个级别
这是你最需要重新学习的部分。

你回答：
> 写该函数的时候加一个限定 noexcept。
这不正确。`noexcept` 是异常说明，不是自动处理异常的机制。
###### 三种异常安全保证

|保证级别|核心含义|面试记忆|
|---|---|---|
|基本异常保证（Basic Guarantee）|抛出异常后，对象仍处于有效状态，不泄漏资源，但状态可能改变|不泄漏、不损坏|
|强异常保证（Strong Guarantee）|操作失败时，对外可观察状态保持不变|要么成功，要么不变|
|不抛异常保证（No-throw Guarantee）|操作保证不会让异常传播给调用方|不向外抛异常|
###### 结合动态数组理解
假设移动或复制赋值之前：
![[Pasted image 20261105200121.png]]
如果复制赋值这样写：
```cpp
delete[] data_;

data_ = new int[other.size_];
```
万一 `new` 抛出 `std::bad_alloc`：
- 原有资源已经释放。
- `data_` 仍然保存被释放的地址。
- 后续析构可能发生重复释放。
连基本异常保证都没有满足。
###### 怎样实现强异常保证？
最容易理解的方法是：先申请新资源，成功后再替换旧资源。
```cpp
Buffer& operator=(const Buffer& other)
{
    if (this == &other)
    {
        return *this;
    }

    // 先申请新内存，可能抛异常
    int* newData = new int[other.size_];

    // 假设元素类型是 int，复制不会抛异常
    std::copy_n(other.data_, other.size_, newData);

    // 新资源准备成功后，才释放旧资源
    delete[] data_;

    data_ = newData;
    size_ = other.size_;

    return *this;
}
```
假设 `new` 抛出了异常：
- 旧资源还没有释放。
- `data_` 和 `size_` 都没有改变。
- 对象仍然保持原来的状态。
因此，这种写法在该示例的条件下实现了强异常保证。
对于可能在复制过程中抛异常的复杂元素类型，还需要使用 RAII 管理临时资源，防止复制过程中泄漏。
###### noexcept 的真正作用
```cpp
void Func() noexcept
{
    throw std::runtime_error("error");
}
```
如果异常逃出 `noexcept` 函数，就会调用 `std::terminate()`。
所以：`noexcept` 并不是让函数自动变得异常安全，而是要求异常不能从该函数向外传播。
##### 四、为什么实际工程更推荐现有 RAII 类型？
你说“因为更有保证”，方向正确。
更具体的原因是：
- 减少重复代码：不需要反复手写析构、移动构造和移动赋值。
- 降低资源泄漏风险：异常发生时，局部 RAII 对象仍能自动清理资源。
- 所有权语义清晰：`unique_ptr` 表达独占，`shared_ptr` 表达共享。
- 更容易维护：以后增加新成员时，不必逐一检查全部手写特殊成员函数。
注意，使用 RAII 仍然需要正确设计所有权和异常边界，并不意味着程序自动没有任何错误。

##### 一、为什么 vector 扩容时可能选择复制而不是移动？
这是本题最重要的知识点。
假设：
```cpp
std::vector<Resource> v;
```
容器里已经有三个元素：
![[Pasted image 20261105205653.png]]
假设旧元素移动时：
1. A 移动成功，原来的 A 已经失去资源。
2. B 移动成功，原来的 B 已经失去资源。
3. C 移动构造时抛出异常。
这时问题来了。

如果要实现强异常保证，就需要让原来的 vector 保持扩容前的状态。
但是 A、B 的资源已经被转移了，想恢复原来的状态可能很困难，甚至无法保证恢复操作不抛异常。
所以，`vector` 在能够复制元素时，可能选择先复制旧元素。

###### 为什么复制可能更安全？
假设复制 A、B 成功，复制 C 时发生异常。
- 旧的 A、B、C 都没有被修改。
- 已经构造的新元素可以被销毁。
- 新分配的内存可以被释放。
- 原来的 `vector` 保持不变。
这样就容易实现强异常保证。
而如果移动构造保证 `noexcept`，旧元素迁移过程中就不会因为移动构造抛异常，所以容器通常更愿意使用移动来减少复制开销。

![[Pasted image 20261105210414.png]]
注意：这是标准库实现的典型策略，不意味着标准强制每次扩容都必须调用某一个特定函数。
##### 二、std::move_if_noexcept 是什么？
你已经学过：
```cpp
std::move(x);
```
它通常将表达式转换为将亡值，不关心移动构造是否抛异常。

而：
```cpp
std::move_if_noexcept(x);
```
会根据类型的特征，选择更有利于异常安全的引用类型。
###### 核心规则
对于类型 `T`：

|条件|`std::move_if_noexcept(x)` 返回类型|
|---|---|
|移动构造是 `noexcept`|`T&&`|
|移动可能抛异常，且不能复制|`T&&`|
|移动可能抛异常，但可以复制|`const T&`|
你可以记成：能安全移动就移动；移动可能抛异常且能复制，就倾向于复制。

但要注意：
`std::move_if_noexcept` 和 `std::move` 一样，自身都不会真正复制或移动资源。

例如：
```cpp
T b(std::move_if_noexcept(a));
```
这里先得到合适的表达式，再由构造函数进行真正的复制或移动。
而且，即使它返回 `T&&`，也不意味着后续操作一定不会抛异常。
##### 三、重新分析 vector 扩容代码
```cpp
std::vector<std::string> names;

names.reserve(1);
names.push_back("boss");

auto* first = &names[0];

names.push_back("enemy");
```
你的判断正确：第二次 `push_back` 会触发扩容，`first` 会失效。

原因：
- `reserve(1)` 保证容量至少为 1。
- 第一次添加后，容器有 1 个元素，容量仍为 1。
- 第二次添加需要容纳 2 个元素，因此必须重新分配存储空间。
- `first` 仍然指向旧存储中的元素，扩容后成为悬空指针。
但你对“新元素构造和旧元素迁移”的理解需要调整。

新元素构造：
```cpp
names.push_back("enemy");
```
需要在容器中构造新的 `std::string` 元素。这里通常会先由字符串字面量构造临时 `std::string`，再将其移动到容器。

旧元素迁移：原来保存 `"boss"` 的 `std::string` 需要在新存储空间重新构造，可以通过复制或移动等实现方式完成。

所以，两者的区别不是“新元素获得所有权、旧元素转移所有权”，而是：
- 新元素：由传入的实参构造。
- 旧元素：从原存储空间迁移到新存储空间。
对于 `std::string`，旧元素究竟复制还是移动，需要考虑其移动构造的异常说明和具体实现，不能只凭代码断定所有迁移操作的数量。
##### 四、所有移动构造函数都应该加 noexcept 吗？
不应该无条件添加。
假设：
```cpp
class Resource
{
public:
    Resource(Resource&& other) noexcept
    {
        // 假设这里执行了可能抛异常的操作
    }
};
```
如果异常逃出该函数，程序就会调用：
```
std::terminate();
```
这与你之前第 6 题掌握的规则一致。

因此，只有当移动构造确实能够保证异常不向外传播时，才应该声明为 `noexcept`。

对于默认生成的移动构造：
```cpp
struct Data
{
    std::string name;
    std::unique_ptr<int> ptr;

    Data(Data&&) = default;
};
```
它的异常说明由成员、基类等相关操作是否可能抛异常共同决定。不是说所有编译器默认生成的移动构造都必然是 `noexcept`。

| 2. 未发生 NRVO               | 错误   | 通常优先尝试移动构造，而不是复制构造            |
| 3. 删除复制和移动                | 正确   | C++17 的保证拷贝消除不要求可用的复制或移动构造    |
| 4. 返回参数与 const 对象         | 部分错误 | 函数形参不能进行 NRVO                 |
| 5. 返回引用与 unique_ptr       | 部分错误 | 返回局部引用会悬空；`unique_ptr` 可以按值返回 |
#### 示例
##### 一、最重要的错误：不写 std::move，为什么仍然可以移动？
你第 2 问认为：如果没有发生 NRVO，通常选择复制构造。
实际上，对于符合条件的局部对象，C++17 会在返回时尝试隐式移动。

例如：
```cpp
std::string Make()
{
    std::string s = "hello";
    return s;
}
```
这里有两种情况：
![](../../_Pasted_Image/Pasted%20image%2020261106143246.png)
这不是编译器简单地判断“移动比较快”，而是 C++ 语言规定了特定返回表达式的隐式移动规则。

因此，通常应该写：
```cpp
return s;
```
而不是：
```cpp
return std::move(s);
```
因为前者既保留了 NRVO 的机会，又可能在未发生 NRVO 时自动移动。
需要注意：如果类型没有可用的移动构造，是否能够复制，还要继续根据构造函数的可用性和重载决议判断；显式删除的移动构造不一定能退回复制。
##### 二、函数参数能不能进行 NRVO？
你认为：如果是普通的值参数，应该可以进行 NRVO。
这个判断错误。

看下面的代码：
```cpp
std::string Process(std::string s)
{
    return s;
}
```
虽然 `s` 是局部使用的变量，但它属于函数形参。
NRVO 的适用条件排除了函数形参，所以这里不能进行 NRVO。
不过，对于这种符合隐式移动条件的按值参数，返回时仍然可以选择移动构造。

对比：

|返回表达式|C++17 机制|
|---|---|
|`return std::string("A");`|保证的拷贝消除|
|`std::string s; return s;`|可能 NRVO；否则通常隐式移动|
|`return std::move(s);`|阻止 NRVO，通常移动|
|`std::string Func(std::string s) { return s; }`|不能 NRVO，但通常隐式移动|
至于 `const` 局部变量：
```cpp
std::string Make()
{
    const std::string s = "hello";
    return s;
}
```
这里仍然可能 NRVO。如果没有发生 NRVO，通常无法调用 `std::string` 的普通移动构造，因为它需要非 const 的右值引用，于是可能调用复制构造。
##### 三、为什么 unique_ptr 可以直接按值返回？
这是你第 5 问最需要理解的地方。

你认为：`unique_ptr` 没有复制构造，所以按值返回可能会编译失败。对于符合条件的局部 `unique_ptr`，直接按值返回完全合法。

例如：
```cpp
std::unique_ptr<int> Create()
{
    auto p = std::make_unique<int>(100);

    return p;
}

int main()
{
    auto ptr = Create();
}
```
为什么能编译？
- 如果编译器执行 NRVO，就不需要额外移动或复制。
- 如果没有执行 NRVO，`return p;` 可以触发隐式移动，调用 `unique_ptr` 的移动构造。
- 不需要复制构造函数。
因此：按值返回 `unique_ptr` 是转移独占所有权的正常方式。

反而下面这种写法有问题：
```cpp
std::unique_ptr<int>& Create()
{
    auto p = std::make_unique<int>(100);
    return p; // 错误设计：返回局部变量的引用
}
```
函数结束后 `p` 被析构，返回的引用悬空。你之前称它为“空引用”，但准确术语是悬空引用。它不是自动变成 `nullptr`。
##### 四、重新总结三种返回方式
```cpp
Item Make1()
{
    return Item{};
}

Item Make2()
{
    Item x;
    return x;
}

Item Make3()
{
    Item x;
    return std::move(x);
}
```

| 函数      | 具体行为                | 是否保证消除      |
| ------- | ------------------- | ----------- |
| `Make1` | C++17 同类型纯右值直接构造    | 保证          |
| `Make2` | 可选 NRVO；否则按隐式移动规则判断 | 不保证         |
| `Make3` | 显式转为将亡值，通常移动构造      | 不符合 NRVO 条件 |

## 三、模板推导与完美转发

### 第 9 题：理解完美转发前，需要掌握哪些模板参数推导规则？

**必答范围：按值、按引用推导 → cv 限定 → 数组与函数。**

1. 分别使用 `T`、`T&`、`const T&` 和 `T&&` 接收实参时，模板推导关注哪些信息？什么是顶层 `const`，什么是底层 `const`？
2. 分别推导下列调用中 `T` 和形参的类型；如果某调用不合法，说明原因：

```cpp
template<class T> void by_value(T x);
template<class T> void by_ref(T& x);
template<class T> void by_const_ref(const T& x);

int x = 1;
const int cx = 2;
const int* p = &cx;
by_value(x); by_value(cx); by_value(p);
by_ref(x); by_ref(cx);
by_const_ref(x); by_const_ref(cx); by_const_ref(3);
```

3. 按值传参与按引用传参时，数组和函数类型的推导可能有什么不同？为什么字符串字面量值得单独分析？
4. 模板参数推导失败、实参转换和函数重载决议有什么区别？显式指定模板参数后，还能否假设所有参数都经过相同的推导过程？

#### 正确回答

#### 我存在的问题
|问题|判断|主要问题|
|---|---|---|
|1. 模板推导基础|部分正确|不清楚 `T`、`T&`、`const T&` 的推导区别|
|2. A～H 类型推导|不会|需要学会同时判断 `T` 和最终形参类型|
|3. 数组类型推导|部分错误|按值时数组通常退化为指针，按引用时保留数组类型|
|4. 推导与重载决议|部分正确|显式指定 `T` 的理解正确，其余需要补充|
你这里有一个需要先纠正的认识：`T&&` 属于万能引用，什么类型都能接受。
更准确地说，当 `T&&` 中的 `T` 需要进行模板类型推导，并满足转发引用条件时，才是转发引用（Forwarding Reference）。它可以根据左值和右值推导出不同的引用类型，并不是所有带 `&&` 的参数都可以这样使用。
#### 示例
##### 一、先弄懂什么是模板类型推导
假设我们写了一个普通函数：
```cpp
void Func(int x)
{
}
```
调用时：
```cpp
Func(10);
```
编译器已经知道形参是 `int`。

现在换成模板：
```cpp
template<typename T>
void Func(T x)
{
}
```
调用：
```cpp
Func(10);
```
编译器需要先判断：实参 `10` 是 `int`，所以模板参数 `T` 应该推导为 `int`。

相当于实例化出：
```cpp
void Func(int x);
```
这就叫模板实参推导（Template Argument Deduction）。

注意两个概念：
- `T`：编译器推导出来的模板参数类型。
- 形参类型：将 `T` 代入函数声明后得到的类型。
它们有时相同，有时不同。
##### 二、T、T&、const T& 如何推导？

我们按照文档第 9 题的三个函数来分析。
```cpp
template<typename T>
void by_value(T x);

template<typename T>
void by_ref(T& x);

template<typename T>
void by_const_ref(const T& x);
```
###### 1. 按值传递：T
```cpp
int x = 10;
const int cx = 20;

by_value(x);
by_value(cx);
```
推导结果：

|调用|推导的 T|最终形参类型|
|---|---|---|
|`by_value(x)`|`int`|`int`|
|`by_value(cx)`|`int`|`int`|
为什么 `cx` 的 `const` 消失了？因为按值传递会创建独立的形参对象。对于这种情况，实参自身的顶层 `const` 不会保留到推导出的 `T` 中。
###### 2. 按引用传递：T&
```cpp
by_ref(x);
by_ref(cx);
```
推导结果：

|调用|推导的 T|最终形参类型|
|---|---|---|
|`by_ref(x)`|`int`|`int&`|
|`by_ref(cx)`|`const int`|`const int&`|
这里 `T` 可以被推导成带 `const` 的类型。由于引用直接绑定已有对象，不能随意丢弃对象的 `const` 限定。
###### 3. 按 const 引用传递：const T&
```cpp
by_const_ref(x);
by_const_ref(cx);
by_const_ref(3);
```
推导结果：

|调用|推导的 T|最终形参类型|
|---|---|---|
|`by_const_ref(x)`|`int`|`const int&`|
|`by_const_ref(cx)`|`int`|`const int&`|
|`by_const_ref(3)`|`int`|`const int&`|
为什么 `cx` 的 `T` 反而是 `int`？
因为函数参数模式已经包含 `const`：
```cpp
const T&
```
编译器只需要把 `T` 推导为 `int`，就能得到符合要求的 `const int&`。
这三种规则是后面理解完美转发的基础。
##### 三、什么是顶层 const 和底层 const？

**顶层和底层 const 的区分，不是看最终能不能修改 int 值，而是看 const 修饰的是对象本身，还是通过指针、引用间接访问的对象。**

你之前复习过 `const int*` 和 `int* const`，这里正好可以联系起来。
```cpp
int x = 10;

const int* p1 = &x;
int* const p2 = &x;
```
区别：

| 类型                 | const 限制谁                      | 名称              |
| ------------------ | ------------------------------ | --------------- |
| `const int*`       | 不能通过指针修改 `int`,限制通过指针或引用访问的对象。 | 底层 const        |
| `int* const`       | 指针变量本身不能修改,限制变量本身。             | 顶层 const        |
| `const int* const` | 两者都限制                          | 同时具有顶层和底层 const |
对于按值模板推导：
```cpp
template<typename T>
void Func(T value);
```

```cpp
const int x = 10;
Func(x);  // T = int
```
顶层 `const` 被忽略。

但：
```cpp
const int* p = &x;
Func(p);  // T = const int*
```
指向对象的底层 `const` 被保留下来。
记忆：按值推导通常忽略顶层 const，但保留指向对象的底层 const。
##### 四、原题 A～H 的完整答案
```cpp
int x = 1;
const int cx = 2;
const int* p = &cx;
```

| 调用                    | 推导的 T        | 最终形参类型       | 能否编译 |
| --------------------- | ------------ | ------------ | ---- |
| A. `by_value(x)`      | `int`        | `int`        | 可以   |
| B. `by_value(cx)`     | `int`        | `int`        | 可以   |
| C. `by_value(p)`      | `const int*` | `const int*` | 可以   |
| D. `by_ref(x)`        | `int`        | `int&`       | 可以   |
| E. `by_ref(cx)`       | `const int`  | `const int&` | 可以   |
| F. `by_const_ref(x)`  | `int`        | `const int&` | 可以   |
| G. `by_const_ref(cx)` | `int`        | `const int&` | 可以   |
| H. `by_const_ref(3)`  | `int`        | `const int&` | 可以   |
注意：本题 A～H 全部可以编译。
##### 五、为什么数组按值与按引用推导不同？
原题：
```cpp
template<typename T>
void Func1(T x);

template<typename T>
void Func2(T& x);

int arr[5] = {};
```
###### 按值传递
```cpp
Func1(arr);
```
数组作为按值实参进行模板推导时，通常发生数组到指针的转换（Array-to-Pointer Decay）。

所以：
```cpp
T = int*
```
最终形参也是：
```cpp
int* x
```
###### 按引用传递
```cpp
Func2(arr);
```
因为是引用传递，数组类型可以被完整保留：
```cpp
T = int[5]
```
最终形参：
```cpp
int (&x)[5]
```

这里的 `(&x)[5]` 表示对具有 5 个 int 元素的数组的引用。

所以两者不一样：
- `Func1(arr)`：数组退化为 `int*`。
- `Func2(arr)`：保留 `int[5]` 数组类型。
对于函数实参也存在类似区别：按值推导可能发生函数到函数指针的转换，按引用推导则可以保留函数类型。
##### 六、T&& 为什么比较特殊？
```cpp
template<typename T>
void Func(T&& value);
```
在这里，`T&&` 是转发引用。

例如：
```cpp
int x = 10;

Func(x);
Func(20);
```

|调用|推导的 T|最终形参类型|
|---|---|---|
|`Func(x)`|`int&`|`int&`|
|`Func(20)`|`int`|`int&&`|
第一行为什么最终是 `int&`？
因为引用折叠：
```cpp
int& &&  // 折叠为 int&
```
第二行则是：
```cpp
int&&
```
转发引用能够根据实参是左值还是右值，保留相应的引用属性。
这是第 10 题引用折叠的重点，目前只需要建立初步认识。
##### 七、模板推导与重载决议不是一回事
两者是不同步骤：
1. 模板参数推导： 判断 `T` 应该是什么类型，尝试形成可用的函数模板特化。
2. 重载决议： 在候选函数中，根据参数匹配等规则选择应该调用哪一个。
推导失败，可能只是导致某个函数模板候选不可用；如果还有其他合适重载，整个调用仍可能成功。

如果显式写：
```cpp
Func1<int>(10);
```
这里已经明确指定：
```cpp
T = int
```
所以不需要再推导这个 `T`。
不过，如果函数还有其他没有显式指定的模板参数，它们仍然可能需要推导。

### 第 10 题：引用折叠与转发引用是怎样工作的？

**必答范围：四条折叠规则 → 特殊推导 → 转发引用识别。**

1. 写出 `& + &`、`& + &&`、`&& + &`、`&& + &&` 四种引用折叠结果。哪些语境会间接形成需要折叠的引用类型？
2. 什么情况下 `T&&` 是转发引用？为什么不是看到 `&&` 就能认定是转发引用？分别分析 `const T&&`、普通函数的 `Widget&&` 和类模板成员中的 `T&&`。
3. 推导下列调用中的 `T` 和最终形参类型，并判断函数体内表达式 `x` 的值类别：

```cpp
template<class T>
void inspect(T&& x) { /* 分析 T、decltype(x) 和 x */ }

int n = 1;
const int cn = 2;
inspect(n);
inspect(cn);
inspect(3);
inspect(std::move(n));
```

4. `auto&&` 常见情况下怎样推导？花括号初始化列表和类模板参数推导中有哪些需要单独检查的例外？显式指定模板参数时，判断依据是什么？

#### 正确回答
C++ 引用折叠共有四条规则，只要组合中存在左值引用，最终就折叠为左值引用；只有两个右值引用组合时，才折叠为右值引用。
转发引用通常表现为需要进行函数模板参数推导的 `T&&`。传入左值时，`T` 会推导为左值引用类型；传入右值时，通常推导为非引用类型。
需要注意，不是所有 `T&&` 都是转发引用，例如 `const T&&`、固定类型的 `int&&`，以及使用已确定的类模板参数形成的 `T&&`。
另外，必须区分模板参数 `T`、最终形参类型和表达式值类别。即使参数声明类型为 `T&&`，只要在函数体中通过名字访问参数，该表达式仍然是左值。
#### 我存在的问题
| 问题                       | 判断     | 主要问题                 |
| ------------------------ | ------ | -------------------- |
| 1. 引用折叠                  | 3/4 正确 | `&&` 与 `&` 折叠后是 `&`  |
| 2. 转发引用识别                | 3/4 正确 | F4 不是转发引用            |
| 3. `T`、`decltype(x)`、`x` | 部分正确   | 前两项全对，但表达式 `x` 永远是左值 |
| 4. `auto&&`              | 部分错误   | `y`、`z` 都是 `int&&`   |
你目前最需要解决的是：引用类型不等于表达式的值类别，`T&&` 也不一定是转发引用。
#### 示例
##### 一、引用折叠的四条规则
你只错了第三条。

|引用组合|正确结果|
|---|---|
|`T&` + `&`|`T&`|
|`T&` + `&&`|`T&`|
|`T&&` + `&`|`T&`|
|`T&&` + `&&`|`T&&`|
记忆方式：只要有一个 `&`，结果就是 `&`；只有两个都是 `&&`，结果才是 `&&`。

例如：
```cpp
using T = int&&;

T& a = /* ... */;
```
这里 `T&` 经过类型别名替换和引用折叠，最终类型是 `int&`。
引用折叠通常发生在模板类型推导、类型别名替换、`decltype` 等场景。
##### 二、为什么 F4 不是转发引用？
原题：
```cpp
template<typename T>
void F1(T&& value);

template<typename T>
void F2(const T&& value);

void F3(int&& value);

template<typename T>
class Test
{
    void F4(T&& value);
};
```
正确答案：

|函数|是否为转发引用|原因|
|---|---|---|
|F1|是|`T` 由该函数模板推导|
|F2|否|`const T&&` 不满足转发引用条件|
|F3|否|类型固定为 `int&&`|
|F4|否|`T` 是类模板参数，不是 F4 调用时推导的函数模板参数|
重点理解 F4：
```cpp
Test<int> obj;
```
此时类模板参数 `T` 已经确定为 `int`。

所以：
```cpp
void F4(int&& value);
```
它就是普通右值引用参数。

如果希望类模板中的成员函数支持转发引用，可以这样写：
```cpp
template<typename T>
class Test
{
public:
    template<typename U>
    void F4(U&& value);
};
```
此时 `U` 才是在调用 F4 时进行推导的函数模板参数。
因此，判断转发引用不能只看 `T&&` 的外观，还要看 `T` 是否在当前函数调用中参与推导。
##### 三、为什么 decltype(x) 是 int&&，但 x 仍然是左值？
这是本题最关键的知识点。

原代码：
```cpp
template<typename T>
void inspect(T&& x)
{
    // 分析 T、decltype(x) 和表达式 x
}

int n = 1;
const int cn = 2;

inspect(n);             // A
inspect(cn);            // B
inspect(3);             // C
inspect(std::move(n));  // D
```
你对 `T` 和 `decltype(x)` 的推导全部正确。

完整答案：

|调用|T|decltype(x)|表达式 x 的值类别|
|---|---|---|---|
|A|`int&`|`int&`|左值|
|B|`const int&`|`const int&`|左值|
|C|`int`|`int&&`|左值|
|D|`int`|`int&&`|左值|
为什么 C、D 的 `x` 都是左值？

因为：
```cpp
void inspect(T&& x)
```
无论 `x` 最终是左值引用类型还是右值引用类型，在函数体中直接使用有名字的参数 `x` 时，表达式 `x` 都是左值。

还有一个容易混淆的地方：
```cpp
decltype(x)   // 获取 x 的声明类型
decltype((x)) // 根据表达式 (x) 的值类别推导
```

如果 `x` 声明为 `int&&`：
```cpp
decltype(x)   // int&&
decltype((x)) // int&
```
第二个结果是 `int&`，因为表达式 `(x)` 是左值。
这也是为什么后面学习完美转发时，需要使用 `std::forward<T>(x)` 来恢复原始实参的左值或右值属性。
##### 四、auto&& 的类型推导
原代码：
```cpp
int a = 10;

auto&& x = a;
auto&& y = 20;
auto&& z = std::move(a);
```
正确结果：

|变量|初始化表达式|最终声明类型|
|---|---|---|
|`x`|左值 `a`|`int&`|
|`y`|纯右值 `20`|`int&&`|
|`z`|将亡值 `std::move(a)`|`int&&`|
这里 `auto&&` 按转发引用的类似规则进行推导：
- 左值初始化：最终折叠为左值引用。
- 右值初始化：最终为右值引用。
但注意：直接使用 `x`、`y`、`z` 这三个变量名时，它们都是左值表达式。
`auto&&` 也存在花括号初始化等特殊情况，之后再学，不需要现在死记。

##### 二、std::forward 的核心原理
先看一个便于理解的简化版本：
```cpp
template<typename T>
T&& MyForward(std::remove_reference_t<T>& x)
{
    return static_cast<T&&>(x);
}
```
这里暂时不需要研究 `remove_reference_t` 的内部实现。

它的作用就是：
```cpp
std::remove_reference_t<int&>   // int
std::remove_reference_t<int&&>  // int
std::remove_reference_t<int>    // int
```
最核心的一行是：
```cpp
return static_cast<T&&>(x);
```
你可以暂时将 `std::forward<T>(x)` 理解为：
```cpp
static_cast<T&&>(x)
```
那么它是怎么恢复左值和右值的？

情况 ①：原始实参是左值
```cpp
std::string s = "hello";
Relay(s);
```
第一步，模板推导：
```cpp
T = std::string&
```
第二步，代入 `std::forward<T>(x)` 的核心转换：
```cpp
static_cast<T&&>(x)

= static_cast<std::string& &&>(x)
```
第三步，引用折叠：
```cpp
std::string& && → std::string&
```
最终返回左值表达式。

情况 ②：原始实参是右值
```cpp
Relay(std::string("hello"));
```
第一步，模板推导：
```cpp
T = std::string
```
第二步，代入：
```cpp
static_cast<T&&>(x)

= static_cast<std::string&&>(x)
```
第三步，结果是右值引用类型，转换表达式属于将亡值。最终返回右值表达式。

这就是 `std::forward` 的核心工作机制：通过模板推导得到的 `T`，结合 `static_cast<T&&>` 和引用折叠，有条件地恢复原始实参的值类别。
##### 三、std::move 和 std::forward 到底有什么区别？

你之前学习过，`std::move` 的核心是：
```cpp
static_cast<
    std::remove_reference_t<T>&&
>(x)
```
而 `std::forward<T>` 的核心是：
```cpp
static_cast<T&&>(x)
```
虽然只差一点，但效果完全不同。

|对比|`std::move(x)`|`std::forward<T>(x)`|
|---|---|---|
|目的|无条件转换成将亡值|根据 `T` 有条件地转发|
|传入普通左值|转换成将亡值|保持左值|
|传入普通右值|将亡值|保持右值|
|是否实际移动资源|否|否|
|常见用途|表示资源可以被移动|泛型包装函数、完美转发|
注意：`std::move` 并不去除 `const`，所以对于 `const` 对象仍可能无法调用移动构造。

例如：
```cpp
template<typename T>
void Relay(T&& x)
{
    Print(std::move(x));
}
```
如果你传入的是普通左值 `s`，它也会被转换成将亡值。这可能使后续函数移动 `s` 的资源，而调用者本来并没有要求这样做。

所以中转函数通常需要：
```cpp
template<typename T>
void Relay(T&& x)
{
    Print(std::forward<T>(x));
}
```

```cpp

template<typename T>
void relay(T&& x)
{

}

std::string s = "boss";
const std::string cs = "enemy";
```

现在你就可以按照三个步骤分析：

第一步：推导 T → 第二步：引用折叠 → 第三步：选择重载。

|调用|T|`forward` 表达式类型及值类别|最终调用|
|---|---|---|---|
|`relay(s)`|`string&`|`string&`，左值|`consume(const string&)`|
|`relay(cs)`|`const string&`|`const string&`，左值|`consume(const string&)`|
|`relay(string("mesh"))`|`string`|`string&&`，将亡值|`consume(string&&)`|
|`relay(std::move(s))`|`string`|`string&&`，将亡值|`consume(string&&)`|
另外，不能随意写成：
```cpp
std::forward<T&>(x)
```
因为显式添加 `&` 会使结果始终折叠为左值引用，从而无法正确转发右值。

同一个右值参数连续转发给两个可能移动资源的函数也不安全：第一次调用后，对象可能已经处于被移动状态，第二次再使用可能不符合业务预期。完美转发本身也不保证生命周期安全或线程安全。

## 一、先理解 auto 和 decltype 的区别

### 1. auto：根据初始化表达式推导变量类型

```
int x = 10;
const int cx = 20;

auto a = x;    // int
auto b = cx;   // int
auto& c = cx;  // const int&
```

为什么 `auto b` 是 `int`？

因为普通 `auto` 按值推导时，类似于模板中的 `T` 按值推导，会忽略顶层 const 和引用属性。

但是 `auto&` 属于引用声明，会保留对应的 `const`。

### 2. decltype：根据表达式推导类型

`decltype` 是 C++11 引入的关键字。

它的作用是：

在编译期获取表达式对应的类型，通常不会真正执行该表达式。

例如：

```
int x = 10;
const int cx = 20;

decltype(x) a = 10;    // int
decltype(cx) b = 20;   // const int
```

与 `auto` 最大的不同是：

`decltype` 不会像普通按值 `auto` 那样自动丢弃声明中的 `const` 和引用。

例如：

```
const int& ref = cx;

auto a = ref;       // int
decltype(ref) b = cx; // const int&
```

因此，你可以先这样记忆：

|对比|`auto`|`decltype`|
|---|---|---|
|主要用途|根据初始化表达式推导声明类型|获取给定表达式的类型|
|顶层 const|普通按值推导会忽略|根据规则可能保留|
|引用|普通按值推导通常不保留|可以保留|
|是否需要初始化|普通变量使用 auto 需要初始化|变量是否需初始化遵循其推导后类型等规则|

## 二、decltype 最重要的两条规则

这是整道题的核心。

### 规则一：直接使用未加括号的变量名，获取其声明类型

```
int x = 10;
const int cx = 20;
int& ref = x;

decltype(x) a = 10;    // int
decltype(cx) b = 20;   // const int
decltype(ref) c = x;   // int&
```

规则：`decltype(变量名)` 获取变量的声明类型。

准确地说，这适用于未加括号的标识符表达式等特殊情况。

### 规则二：其他表达式，根据值类别推导

只要不是上面的特殊情况，就要考虑表达式的值类别。

|表达式的值类别|decltype 推导结果|
|---|---|
|左值（lvalue）|`T&`|
|将亡值（xvalue）|`T&&`|
|纯右值（prvalue）|`T`|

结合例子：

```
int x = 10;

decltype((x)) a = x;         // int&
decltype(std::move(x)) b = 20; // int&&
decltype(x + 1) c = 30;      // int
```

注意：上面第二行 `int&&` 不能直接绑定左值 `20` 以外的类型问题？`20` 是右值，可以正常绑定。

为什么 `decltype((x))` 是 `int&`？

因为 `(x)` 被当作一个表达式分析，而表达式 `(x)` 是左值。

## 三、decltype(auto) 又是什么？

你现在已经知道：

```
auto
```

使用 `auto` 的类型推导规则。

而：

```
decltype(auto)
```

使用 `decltype` 的类型推导规则，直接根据初始化表达式或返回表达式确定类型。

例如：

```
int x = 10;

auto a = (x);            // int
decltype(auto) b = (x);  // int&
```

所以：

- `auto a`：按值推导，`a` 是独立的 `int`。
    
- `decltype(auto) b`：按 `decltype((x))` 推导，`b` 是 `int&`，引用原来的 `x`。
    

这也是为什么 `decltype(auto)` 常用于希望保留返回引用类型的函数。

## 五、decltype(auto) 的最大陷阱：悬空引用

```
decltype(auto) Get()
{
    int x = 10;
    return (x);
}
```

根据刚才的规则：

```
decltype((x)) → int&
```

因此：

```
Get() // 返回 int&
```

但 `x` 是函数局部变量，函数结束后就被销毁。

所以返回的是悬空引用。

如果改成：

```
decltype(auto) Get()
{
    int x = 10;
    return x;
}
```

返回类型就是 `int`，按值返回，不存在返回局部引用的问题。

这里还有一个与你之前学习的完美转发相关的场景：

```
template<typename T>
decltype(auto) Wrapper(T&& x)
{
    return std::forward<T>(x);
}
```

- 传入 `int` 左值：返回 `int&`。
    
- 传入 `int` 右值：返回 `int&&`。
    

但返回引用不代表生命周期安全。例如传入临时对象并把返回的引用保存下来，临时对象生命周期结束后，引用就可能悬空。
