# 移动语义、完美转发与 Lambda：一张 Boss 贴图的回忆主线

> 配套笔记：[21 道综合面试题与学习记录](<5.移动语义与完美转发.md>)。本文用于学完后的串联回忆。

## 先复习这一版：一张 Boss 贴图串起 21 道题

把下面这个故事当作一张地图：**创建贴图 → 把贴图交给容器 → 把参数转发给接收者 → 通过回调观察角色 → 将独占资源交给任务**。先顺着故事判断「表达式是什么、谁拥有资源、谁还能活着」，再用后面的提示展开原题。

**一句话回忆：**名字是左值，`move` 只改表达式；移动看对象，返回先想消除；推导记 `T`，转发靠折叠；闭包看捕获，异步查寿命。

### 主例：一张贴图的创建、转交与回调

以下是一份可独立运行的 **C++17** 程序。先顺着注释预测所有权和输出；`observe` 只借用，不保存参数。

```cpp
#include <cassert>
#include <functional>
#include <iostream>
#include <memory>
#include <string>
#include <type_traits>
#include <utility>
#include <vector>

// Rule of Zero：成员负责自己的资源，Texture 不手写析构和移动操作。
struct Texture {
    std::string name;
    std::unique_ptr<int> pixel;

    explicit Texture(std::string n)
        : name(std::move(n)), pixel(std::make_unique<int>(7)) {}
};

Texture load() {
    return Texture{"boss"};                 // 同类型纯右值
}

void observe(const Texture&) { std::cout << "borrow\n"; }
void observe(Texture&&)       { std::cout << "rvalue\n"; }

struct Actor { int hp = 100; };

int main() {
    Texture tex = load();                  // ① 创建贴图
    int&& level = 3;                       // level 的名字是左值
    (void)level;

    auto relay = [](auto&& x) {            // ② 推导、折叠、转发
        observe(std::forward<decltype(x)>(x));
    };
    relay(tex);                            // borrow：只观察，不转移

    std::vector<Texture> textures;
    textures.push_back(std::move(tex));     // ③ 移动到容器
    assert(!tex.pixel);                    // unique_ptr 移动后源为空
    relay(std::move(textures.front()));     // rvalue：observe 仍只借用

    int* pixel = textures.front().pixel.get();
    textures.reserve(textures.capacity() + 1); // ④ 必定重新分配
    assert(pixel == textures.front().pixel.get());
    // 原 Texture 元素的指针、引用和迭代器已失效，不能再访问。

    auto actor = std::make_shared<Actor>();
    std::weak_ptr<Actor> weak = actor;
    std::function<void()> refresh = [weak] { // ⑤ 闭包按值保存弱引用
        if (auto a = weak.lock()) std::cout << "hp=" << a->hp << '\n';
        else std::cout << "actor gone\n";
    };
    refresh();
    actor.reset();
    refresh();

    auto asset = std::make_unique<Texture>("ui");
    auto task = [owned = std::move(asset)] { // ⑥ 闭包独占资源
        std::cout << "task=" << owned->name << '\n';
    };
    assert(!asset);
    task();
    // C++17/20：std::function<void()> copyable = std::move(task); // 不满足可复制要求
}
```

预期输出：

```text
borrow
rvalue
hp=100
actor gone
task=ui
```

先画出这条交接线：

```text
load() ──直接构造──> tex ──移动──> vector 中的 Texture ──独占──> pixel
                         observe 只借用；reserve 后 Texture 搬家，pixel 所指对象仍在

actor ──强拥有──> Actor <──弱观察── refresh 闭包（lock 成功时临时强拥有）
asset ──移动交出──> task 闭包 ──独占──> UI Texture
```

主例里 `std::move(textures.front())` 只是把表达式交给右值引用重载，`observe(Texture&&)` 没有从中取走资源。`Texture` 的移动会移动 `unique_ptr`，**不是移动 `int` 对象本身**；上面的 `pixel` 只在其拥有者继续存活且不重置该资源时有效。`textures` 销毁或对应元素被删除后，不可再解引用它。

### 第一站：同一张贴图，先分清表达式与生命周期（第 1～3 题）

看 `Texture tex = load();` 和 `relay(std::move(textures.front()))`，先问三件事：表达式是什么类别，能绑定哪个引用，谁会执行移动？

| 表达式 | 值类别 | 在故事里意味着什么 |
| --- | --- | --- |
| `tex`、`level`、`textures.front()` | 左值 | 即使 `level` 声明为 `int&&`，使用名字的表达式仍是左值。 |
| `load()`、`Texture{"boss"}` | 纯右值 | 这里用于初始化返回或接收对象；C++17 对同类型纯右值有直接构造规则。 |
| `std::move(tex)` | 将亡值 | 使表达式可参与右值重载；是否转移资源由后续操作决定。 |

值类别属于**表达式**。左值和将亡值构成泛左值；纯右值和将亡值构成右值。能否取地址、是否有名字或能否修改都不是通用的严格判据；例如 `const` 左值不可修改。对象类型函数按 `T`、`T&`、`T&&` 返回时，调用表达式分别通常是纯右值、左值、将亡值。

沿贴图的寿命再想：`T&` 通常绑定可匹配的左值，`const T&` 可绑定左值或右值，`T&&` 可绑定匹配的右值。`const Texture& r = Texture{"ui"};` 直接绑定可延长临时对象寿命到 `r` 的生命周期；若临时对象只是传给引用参数，则通常活到包含调用的完整表达式结束，**返回或保存该引用不会再次延长寿命**。生命周期规则有例外，见第 2 题。

`std::move` 不去掉 `const`：对 `const std::string` 调用它通常仍会选择复制；对于只可移动不可复制的 `const Texture`，相应构造可能无法编译。标准库对象移动后通常有效但值未指定，使用其操作时仍要满足前置条件；`unique_ptr` 的移动源明确为空，不应推断所有成员或自定义类型都变空。

### 第二站：贴图进入容器，区分移动、扩容和返回（第 4～8、14 题）

**① `push_back(std::move(tex))` 是移动构造。**容器里出现新 `Texture`，它的成员逐一移动；`std::string` 和 `unique_ptr` 各自负责自己的资源。若写 `existing = std::move(other)`，则是移动赋值，目标已存在，需要先妥善处理原有资源并考虑自移动。直接管理裸指针时，浅拷贝指针不等于转移所有权；默认移动裸指针也只是复制指针值，可能导致重复释放。

**② `Texture` 用 Rule of Zero。**已有 RAII 成员负责析构、复制和移动；由于含 `unique_ptr`，本例不可复制但可移动。若自己直接管理资源，才重点检查 Rule of Three/Five：析构、复制构造/赋值、移动构造/赋值。用户声明析构等特殊成员会影响隐式移动生成；成员的 `const`、引用及不可移动性也会影响具体操作。显式 `= default` 或 `= delete` 前要检查其他所需成员是否仍可用。

**③ `reserve` 搬动容器元素。**新容量超过旧容量会重新分配，旧元素的指针、引用和迭代器失效。本例 `pixel` 指向单独分配的 `int`，因 `unique_ptr` 转移所有权而仍有效；这不代表所有容器元素中的地址都保持有效。移动是否便宜取决于类型和资源，不能一概而论。

**④ 回答异常安全。**基本保证：失败后对象仍有效且不泄漏；强保证：失败后操作相关状态保持原样；不抛异常保证：异常不向外传播。`vector` 迁移元素时，为满足适用的异常保证，可能在移动会抛且可复制时选择复制；不可复制且移动会抛时，强保证可能受影响。`std::move_if_noexcept` 在移动构造不抛或类型不可复制时提供右值引用，否则提供 `const` 左值引用；它本身不搬运元素。只在确实不会让异常逃出时标记 `noexcept`；异常逃出会调用 `std::terminate`。

**⑤ `load()` 与 `push_back` 各回答不同问题。**C++17 中 `return Texture{"boss"};` 的同类型纯右值直接构造结果对象；若改成 `Texture t{"boss"}; return t;`，是允许但不保证的 NRVO，未发生时还需按版本和类型分析隐式移动/复制。函数参数不能做 NRVO，`const` 局部对象也可能使普通移动构造不可用；C++23 的隐式移动规则有调整。`return std::move(t);` 一般会妨碍 NRVO。`emplace_back("boss")` 使用参数在容器中构造元素；`push_back` 接收已有的元素值。两者都可能触发扩容，`emplace_back` 不保证总是更快，也可能选中不同构造函数。返回局部对象的引用则会悬空，不能用它替代按值返回。[标准草案：拷贝消除](https://eel.is/c%2B%2Bdraft/class.copy.elision)

### 第三站：`relay` 把贴图交给谁？推导、折叠、转发（第 9～13、20 题）

将主例的泛型 Lambda 想成 `template<class T> relay(T&& x)`；`auto&&` 通过推导形成转发引用。它先记住调用者传来的类别，然后 `std::forward<decltype(x)>(x)` 把这个信息传给 `observe`：

| 调用 | 推导出的 `T` | 折叠后的参数类型 / `decltype(x)` | 函数体中的 `x` | 转发后的结果 |
| --- | --- | --- | --- | --- |
| `relay(tex)` | `Texture&` | `Texture&` | 左值 | 左值，选 `observe(const Texture&)` |
| `relay(std::move(tex))` | `Texture` | `Texture&&` | 左值 | 将亡值，选 `observe(Texture&&)` |
| 若传入 `const Texture` 左值 | `const Texture&` | `const Texture&` | 左值 | `const` 左值，选 `observe(const Texture&)` |

四条折叠可记为 `& + & → &`、`& + && → &`、`&& + & → &`、`&& + && → &&`。`const T&&`、固定类型 `Texture&&` 或已确定的类模板参数形成的 `T&&` 不因写了 `&&` 就成为转发引用。

**`decltype(x)` 与 `decltype((x))` 是两个问题。**前者针对未加括号的变量名得到其声明类型；后者对一般表达式按值类别推导，而有名字的 `x` 表达式是左值，所以会得到左值引用。把 `forward<decltype(x)>` 改成 `forward<decltype((x))>` 会把这里的右值也当左值传递；直接写 `observe(x)` 也会丢掉右值信息，无条件 `std::move(x)` 则可能把调用者的左值当右值。

按值推导通常忽略顶层 `const`、引用并让数组或函数退化；按引用推导可以保留相关限定和数组类型。`auto` 通常类似按值推导，`auto&`、`auto&&` 的引用形式要分别分析；`decltype(auto)` 按 `decltype` 规则保留类型或引用，因而返回局部对象的引用会悬空。

完美转发有边界：`relay({1, 2, 3})` 的花括号列表通常无法为 `auto&&` 单独推导类型；重载函数名、位域、默认实参等也需要额外处理；转发不能延长临时对象寿命。若下游接收指针，直接传字面量 `0` 与转发一个被推导为 `int` 的 `0` 的转换语境不同，`nullptr` 更能明确表达空指针。转发构造函数还可能与复制/移动构造竞争，可用约束限制。一个右值被下游消费后，再转发同一对象要重新检查它的状态。

**手写追问的骨架**（教学简化，省略标准库的其他细节）：

```cpp
template<class T>
constexpr std::remove_reference_t<T>&& my_move(T&& x) noexcept {
    return static_cast<std::remove_reference_t<T>&&>(x);
}

template<class T>
constexpr T&& my_forward(std::remove_reference_t<T>& x) noexcept {
    return static_cast<T&&>(x);
}

template<class T>
constexpr T&& my_forward(std::remove_reference_t<T>&& x) noexcept {
    static_assert(!std::is_lvalue_reference_v<T>, "cannot forward rvalue as lvalue");
    return static_cast<T&&>(x);
}
```

`remove_reference_t` 先去掉引用，`my_move` 再统一转换为对应右值引用；`my_forward` 则由显式传入的 `T` 经引用折叠决定结果。两个 `my_forward` 重载分别接收左值和右值实参；第二个的检查防止把右值错误转发成左值。通常包装函数的具名形参 `x` 本身是左值，因此调用 `my_forward<T>(x)` 时进入左值参数重载，再依 `T` 恢复类别。这些转换本身都不搬运资源。[标准草案：forward/move helpers](https://eel.is/c%2B%2Bdraft/forward)

### 第四站：回调捕获谁，任务由谁销毁？（第 15～21 题）

主例中 `refresh` 和 `task` 都是**闭包对象**：每个 Lambda 表达式产生自己的闭包类型，对象通过其 `operator()` 调用。可把捕获看成闭包保存的状态；默认调用运算符为 `const`，`mutable` 可让它修改自己的按值捕获状态。不同 Lambda 表达式即使写法相同，闭包类型也不同。满足转换条件的无捕获 Lambda 可转换为相应函数指针，有捕获的闭包一般不能这样转换。

| 捕获方式 | 跟随故事回忆 | 最需要追问什么 |
| --- | --- | --- |
| `[weak]` | `refresh` 自己保存一份弱引用；调用时 `lock()` 暂时持有角色。 | `lock` 保活，不保证对象数据访问线程安全，也不自动取消任务。 |
| `[&local]` | 闭包只引用外部局部变量。 | 回调延迟执行或返回后，局部变量是否仍存活？ |
| `[this]` | 闭包保存指向原对象的指针。 | 原对象可能先销毁；捕获指针不负责保活。 |
| `[*this]` | C++17 起可按值捕获当前对象副本。 | 对象须可复制；副本里的裸指针或共享资源仍要单独分析。 |
| `[owned = std::move(asset)]` | C++14 初始化捕获，把独占贴图移交给 `task`。 | 闭包能否复制？任务移动、取消或销毁时谁释放资源？ |

`[=]` / `[&]` 决定隐式捕获方式，具体捕获哪些实体仍要看使用；`[=]` 下隐式捕获 `this` 在 C++20 被弃用，C++20 支持显式 `[=, this]`。值捕获的闭包复制会复制其捕获成员，引用捕获的闭包复制不会复制被引用对象。若对象保存的回调又强捕获该对象，可能形成 `shared_ptr` 环；按业务需要改为弱引用并处理失效。即使没有环，长期保留的强引用也可能延长寿命。

`task` 含 `unique_ptr`，因此闭包不可复制。C++17/20 的 `std::function` 要求目标可复制，不能直接保存这个闭包；可以设计模板化的移动专用任务队列，或在支持时考虑 C++23 的 `std::move_only_function`。改用 `shared_ptr` 是改变为共享所有权，应按需求选择。`std::function` 类型擦除可能带来调用或分配开销；是否使用小对象优化、是否分配应看实现和测量。[标准草案：function 构造要求](https://eel.is/c%2B%2Bdraft/func.wrap.func.con)

设计接口时，从「借用还是拥有」开始：只读借用可考虑 `const T&`，修改借用可考虑 `T&`；需要自己的值可考虑按值接收再移动，需要独占或共享时用相应所有权类型。`T&&` 参数本身不意味着已经转移。异步提交后还要检查任务队列何时执行或销毁闭包、取消是否生效、最终析构在哪个线程；所有权转移本身不是线程同步。UE 场景还要区分普通 C++ 对象与 `UObject/Actor` 的生命周期和项目版本约束。

泛型 Lambda 的 `auto&&`、`decltype(x)` 与 `std::forward` 正是第三站的规则；C++20 还能写显式模板参数列表，如 `[]<class T>(T&& x)`，并按需添加约束。
