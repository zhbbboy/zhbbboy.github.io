# GME 缝合项目整体入门与源码导读

这是一份给第一次接手项目的人的学习笔记。目标是沿着“为什么需要缝合 → 模型如何表示 → 一个例子如何缝 → GME 代码如何组织 → 如何调试和验证”的顺序，建立完整的项目地图。

本文以本机 `D:/cppcode/GMEPR/GME/module/stitching` 工作区代码为依据，编写时模块 HEAD 为 `4ab92c3`。代码会继续变化，遇到差异以当前源码、具体接口契约和测试为准。普通 `api_stitch` 和 CAXA 风格属性流程是两条相关但不相同的路径，本文分别讲解；它不是所有几何内核或所有 CAD 缝合算法的通用规格。

推荐先完整阅读第一至六节，能画出两个面缝合前后的关系，再读后面的源码。面试复习时可搭配 [缝合模块基础知识](<1.缝合模块基础知识.md>) 和 [性能优化原理与追问](<2.性能优化原理与追问.md>)。

## 一、项目到底解决什么问题？

### 1. 先认识几何建模内核

CAD 软件中看到的零件，不只是显示在屏幕上的一组三角形。建模系统还需要知道模型的精确或参数化形状、面与面如何连接，才能继续做圆角、切割、布尔运算、测量或数据交换。

几何建模内核提供底层的几何对象、拓扑对象和建模操作。GME 是此类项目；`stitching` 是其中一个模块，主要围绕片体边界的匹配、连接与相关修复工作。它依赖底层内核提供实体、曲线、曲面、拓扑操作等能力，并不是单独的可视化软件。

### 2. 为什么会出现需要缝合的模型？

一个模型可能由多个独立曲面组成：例如从其他系统导入若干面，或从现有实体中抽取、生成若干片体。这些片体在空间上看起来贴合，但系统内部可能仍记录为互不相连的对象。

```text
外观看上去：                  内部拓扑可能是：

  面 A  |  面 B              面 A 的边 eA    面 B 的边 eB
         接缝                 两条边位置接近，但分别属于不同面
```

缝合要判断边界是否满足连接条件，进而更新边、顶点、面和所属结构之间的关系。它既是几何匹配，也是对模型连接关系的修改。

### 3. 缝合能保证什么，不能保证什么？

- 预期用途：把满足接口规则和容差条件的边界或顶点连接起来。
- 可能结果：得到连接后的开放片体、若干未连接的结果体，或者在输入形成合适闭合边界时得到封闭结果。
- 不应自动推断：接口返回成功就说明所有面已连成一个封闭实体、自动修复所有缺口、消除所有自相交，或保证后续所有建模操作都能成功。

**一个常见疑问：**两块长方形面拼成一张更大的平面，能否算成功？可以产生有效的边界连接，但整体仍是开放片体，并没有包围三维体积。若要验证实体，应单独检查闭合性和相关有效性。

## 二、必须掌握的模型表示

### 1. 几何和拓扑是两层信息

| 层次 | 回答的问题 | 例子 |
| --- | --- | --- |
| 几何 | 对象在哪里、是什么形状？ | 一个位置、一条直线／圆弧、一张平面／圆柱面。 |
| 拓扑 | 对象之间如何连接、归谁所有？ | 一条边连哪两个顶点；一个面如何使用边界；两个面是否共享一条边。 |

两条直线段即使空间位置完全相同，也可能是两个独立 Edge。只把它们画在同一位置，不会自动让面共享拓扑。缝合的难点之一就是让几何判断和拓扑修改保持一致。

### 2. B-rep 是什么？

B-rep 是边界表示：通过顶点、边、面和它们的连接关系描述模型边界。它不等同于只有三角形索引的渲染网格：这里的边可以引用参数化曲线，面可以引用参数化曲面，并保留建模需要的关系。

下面的关系是一个普通面模型的阅读入口，不是说所有模型都严格只有一种组织方式：

```text
Body（模型体）
 └─ Lump（体中的组成部分）
     └─ Shell（面的壳）
         └─ Face（面）
             └─ Loop（边界环）
                 └─ Coedge（有方向地使用一条边）
                     └─ Edge（边） ── Vertex（端点）
```

一个 Body 可以包含多个组成部分；Shell 可以开放或闭合；一个 Face 可以有外环和内环。WIRE 是另一类拓扑，不能简单假定每条 Edge 都可以通过面上的 Loop 完整找到。

### 3. 一个面里的各对象

假设 Face A 是一张矩形平面片：

```text
V1 ---- E1 ---- V2
 |                |
 E4      Face A   E2
 |                |
V4 ---- E3 ---- V3
```

- Vertex：拓扑顶点，通常关联位置；相同位置可以存在不同 Vertex 对象。
- Edge：拓扑边，关联支撑曲线、端点和参数范围等；不是只存两个坐标。
- Coedge：一个 Loop 对 Edge 的有方向使用，用来表达沿边界走的方向。
- Loop：把面的一圈有方向边界组织起来；有孔的面还可能有内环。
- Face：由支撑曲面和边界等共同确定的一块面；无限平面和矩形 Face 不是同一个概念。

当两个面共享同一条 Edge 时，各自仍可能使用各自的 Coedge，并通过 partner 等关系关联。实现里需要处理 Coedge 的方向、环及与 Edge 的一致性。

### 4. 曲线参数和 pcurve

一条参数曲线可以写为 `P(t)`，`t` 在某个区间内变化时得到 Edge 对应的曲线段。两条 Edge 可能来自同一条支撑曲线，但只使用不同的参数区间。

面也可以有参数坐标 `(u, v)`；pcurve 可以理解为面参数空间中的一条边界曲线。三维边、面上的参数曲线以及方向需要相互协调。合并或分裂边后，原参数范围、方向或 pcurve 可能需要更新，不能只改一个顶点指针。

## 三、跟着一个例子理解缝合

### 1. 准备输入

有两个相邻矩形片体 A 和 B。A 的右边是 `eA`，B 的左边是 `eB`：

```text
缝合前：  A          B
        +----+    +----+
        |    |    |    |
        +----+    +----+
          eA        eB
```

示意图为了便于区分画出了一条缝隙；实际判断要看三维位置、容差和曲线形状。假设 eA 与 eB 在允许的误差内，方向和拓扑也允许合并。

### 2. 找到可能匹配的边

程序先收集待处理边界，使用端点位置或空间范围排除相距很远的边。某一对边进入候选，只表示“值得进一步检查”。

接下来需要判断几何类型、端点对应方式以及相关方向等条件。对于普通非退化直线段，在代码满足相应前提时可以利用端点匹配；对于圆弧、椭圆或其他曲线，端点相同不一定是同一条曲线段。

### 3. 更新连接而不是只改坐标

如果接受这对边，程序需要保留或建立共享边的使用关系，重连相关顶点和边，处理 Coedge 方向，并合并必要的上层拓扑。被吸收的旧对象可能被删除或不再可用，调用者不能假设输入中的所有原始指针一直有效。

```text
缝合前：Face A → Coedge A → Edge A → 顶点 A1/A2
        Face B → Coedge B → Edge B → 顶点 B1/B2

缝合后：Face A → Coedge A ┐
                           ├→ 共享边与对应顶点
        Face B → Coedge B ┘
```

这是概念示意，具体哪个对象保留、如何管理实体，要看具体实现和接口契约。

### 4. 分开理解三种结果

| 输入情况 | 可能的处理 | 需要注意 |
| --- | --- | --- |
| 边界满足条件 | 合并边及必要顶点，维护连接 | 不自动代表模型整体闭合。 |
| 只有一点接触 | 某些路径可能合并顶点 | 点接触不是共享整条边。 |
| 没有满足条件的边或点 | 保持多个结果体或报告相关状态 | 外层接口的整体返回与内部单对 Body 的返回不一定完全相同。 |

不要把这张表当成所有选项下的严格返回值规范；要查对应入口和具体测试。

### 5. 部分重叠边为什么更难？

例如一条直边覆盖参数范围 `[0, 10]`，另一条只覆盖 `[3, 7]` 对应的位置。若业务允许处理部分重叠，需要先找到重叠区间，在适当位置切分边，再只连接匹配部分。切分会产生新的边和顶点，也会影响 Coedge、pcurve、属性和对象引用。

本文后面的 CAXA 路径有重叠区间、拆分和候选计划相关实现；不要据此假设普通 `api_stitch` 的所有模式都支持任意曲线的任意部分重叠。

## 四、缝合中最重要的业务规则

### 1. 容差：允许的偏差尺度

导入数据或浮点计算可能让理论上相接的边界出现微小偏差。容差用于控制允许比较或连接的距离尺度，单位随模型长度单位而定。

例如边界间距 `0.0005`，候选容差 `0.001`：距离层面可能满足条件，但仍需满足曲线、方向和拓扑要求。容差为 `0.0001` 时，这个间距可能无法被接受。这个数字只是理解用的例子，不代表项目默认值。

过小可能漏掉应连接的边；过大可能连接本不应连接的边，也可能放大模型误差。容差应该与模型单位、精度和业务要求一起讨论。

### 2. 精确缝合和容差缝合

当前 `stchapi.hxx` 将 `EXACT_STITCH_TYPE` 说明为模型基础容差内的精确匹配；“精确”不等于对浮点数做无限精度比较。容差模式允许配置最大缝合容差；受限边容差模式由调用方给出需要处理的边。

当前普通入口的容差解析：精确模式使用 `THXresabs`；容差／边容差模式的配置值为负时使用默认容差，非有限值或非负但小于基础绝对容差会被拒绝。默认值如何计算应看当前的 `compute_default_stitch_tol`，不要从名字推断为某个固定常数。

### 3. 坐标系

Body 可能带变换，同一个局部坐标在不同 Body 的世界位置不一定相同。几何比较必须使用一致的坐标系，包围盒也一样。CAXA 候选结构中记录的参数属于原局部支撑曲线，距离和验证容差在世界坐标下解释；普通路径也有处理 Body 变换的代码。

### 4. 方向与流形

相邻面如何沿共享边使用 Coedge，会影响边界环和整体拓扑。合并时要维护方向和 partner 等关系。

从直观上看，普通二维流形表面的每个局部位置像一小块平面，边界位置像半平面；多个面以复杂方式共用边等情形可能出现非流形关系。实际判断要结合内核规定，不能把单一“面数阈值”视为所有非流形情形的完整定义。

### 5. 自由边、片体和实体

自由边可直观理解为尚未与另一面形成普通共享连接的边界；具体实现如何识别，要看函数条件。开放片体通常仍有未闭合边界；闭合边界具备形成实体的可能，但有效性、方向及其他条件也要检查。不能只用一项边数统计代替全部实体有效性判断。

## 六、普通 `api_stitch` 的调用链

### 1. 先读接口契约

普通入口接收待处理实体列表、两个输出列表、缝合选项以及可选 GME 配置：

```text
api_stitch(to_be_stitched, output_bodies, new_bodies, sopts, aopts)
```

这只是示意调用，不是可直接编译的完整示例。具体声明和类型以头文件为准。

| 项 | 当前头文件说明 |
| --- | --- |
| `to_be_stitched` | 待缝合实体；成功后输入实体拓扑和所有权可能改变。 |
| `output_bodies` | 返回仍含面的结果体；列表元素是模型中借用的指针。 |
| `new_bodies` | 返回为自由 Face 或受限 Edge 输入新建的结果体子集，实体生命周期按接口约定管理。 |
| `sopts` | 非空；决定缝合类型及相关配置。 |
| 返回值 `outcome` | 表示接口执行结果，需要结合输出和具体错误解释。 |

函数开始会清空两个输出列表。不要把清空列表理解为释放原列表内的实体；应按容器和内核实体的实际所有权契约处理。

### 2. 不同模式的输入约束

| 模式 | 当前普通入口的主要约束 |
| --- | --- |
| 精确模式 | 接受 Body，使用模型基础绝对容差。 |
| 容差模式 | 接受 Body 或无所有者的 Face，容差按选项解析。 |
| 受限边容差模式 | 处理调用方给出的 Edge；源码检查其关联面、Coedge 及所有者等条件。 |
| 多面体／多线程枚举 | 不能因为枚举存在就认为普通入口支持；多线程相关接口另有框架。 |

对于已有所有者的 Face、非 Edge 输入、没有面的 Edge 等情况，错误与处理依路径不同，查 `validate_restricted_edge_input` 和具体测试。

### 3. 主流程示意

```text
api_stitch
  ├─ 清空输出、检查输入和选项、解析有效容差
  ├─ 受限边模式 → 受限 Edge 入口
  └─ 其他支持模式 → 整理为 Body
       ├─ 单输入等简单情况 → 直接处理
       ├─ 符合前提的简单片体 → 快路径
       └─ 通用多体处理
            ├─ 可用时做端点／包围盒保守预筛
            └─ 调用 gme_stitch 处理 Body 对
                 ├─ 收集拓扑
                 ├─ 边匹配与合并
                 ├─ 顶点匹配与合并
                 └─ 返回本次双体处理状态
```

这是教学概括：实际控制流有更多检查、缓存与回退，并非每次都走完所有分支。

### 4. `gme_stitch` 中发生什么？

1. **坐标准备**：检查两个 Body 的变换；需要时调整到一致表达，等值或恒等情况可以跳过不必要的变换。
2. **收集候选拓扑**：普通面路径一次遍历收集 Coedge、Edge、Vertex；WIRE 等情况使用通用查询回退。
3. **边阶段**：依据规模选择直接比较或网格筛选；对候选检查几何、端点对应、方向和相关拓扑条件，再连接边及上层对象。
4. **顶点阶段**：继续处理符合条件的顶点连接；不是每个输入都必然执行完全相同的扫描，有些条件可安全跳过。
5. **收尾**：根据处理结果、变换及拓扑情况完成相关工作；若没有可缝合几何，内部双体函数可能返回 `NO_STITCHABLE_GEOM`。

当前外层多体处理会处理内部 Body 对的结果并组织输出，因此不能把一个内部双体错误码简单等同于整个 `api_stitch` 的最终结果。

### 5. 为什么要分边阶段和顶点阶段？

边重合是较强的匹配关系：可以连接整段边界，并涉及两个端点；有些输入只有顶点接近而边不重合，这时可能需要单独处理点连接。阶段之间会修改拓扑，所以顺序和重复处理保护很重要。

## 七、CAXA 风格属性流程

### 1. 它解决什么不同的问题？

普通入口偏向一次调用完成缝合；CAXA 风格流程提供与实体关联的属性、参数、分析结果和候选计划，可以先分析和计算，再执行修改。它最终在部分处理里也会调用普通受限边 `api_stitch`，但不能把两条路径当作完全相同的实现。

```text
聚合缝合属性 ATTRIB_HH_AGGR_STITCH
  ├─ 选项和结果：容差、开关、统计
  ├─ 边属性 ATTRIB_HH_ENT_STITCH_EDGE：伙伴、间隙等
  └─ 候选计划 caxa_stitch_plan：配对边及重叠区间

analyze → calculate / calculate_at_tol → fix → 查询结果 / cleanup
```

这是典型阅读顺序，不表示任何调用组合都自动合法，也不是完整的状态机规范。

### 2. `analyze`：先认识输入

聚合属性的 `analyze()` 取得所属 Body 的边，统计有效和无效自由边及部分拓扑信息，在适用条件下检查 partner 和边界连接；还会根据世界包围盒规模给出建议容差。

建议值和用户配置是两回事：分析给出建议，不等于自动覆盖用户设置。跳过拓扑检查也不等于跳过所有几何和边界句柄检查，更不意味着关闭 `fix` 的最终有效性检查。

### 3. `calculate`：找候选，暂不合并拓扑

`calculate()` 根据选项和容差范围计算候选；`calculate_at_tol(t)` 在指定容差下寻找自由边配对。代码会维护边属性和候选计划，但接口注释明确这一步不执行拓扑合并。

理解边界：**不改变模型拓扑不代表没有任何状态变化**。候选、属性、统计和计划都可能被更新，重复计算时也要考虑旧候选如何清理。

当前普通 `calculate()` 有增量容差调度；候选记录自身首次满足条件的容差。检查法向的选项路径当前只分析并清空候选，不要据选项名称推断已经完成一般意义上的法向修正或完整法向筛选。

### 4. `pair` 和候选计划记录了什么？

配对时检查边属性、是否跳过、是否为自由边、已有伙伴以及几何分析等条件。可用的候选计划可以记录两条 Edge、参数区间、间隙、方向、是否需要切分、额外重叠区间，以及部分原始 pcurve 信息。

**边属性记录伙伴 ≠ 边已缝合。**候选只是待执行信息；是否成功改变拓扑要看后续 `fix` 和结果。

### 5. `fix`：真正执行拓扑修改

当前实现先检查是否有待处理伙伴，进入试运行／历史事务保护，分析输入，然后对需要处理的变换、重叠区间裁切和边合并逐步执行；完成后再次检查实体与拓扑，更新统计。失败时利用内核事务机制恢复，并记录失败阶段。

`stitch_two_edges` 会在校验伙伴关系后，构造受限边选项，调用普通 `api_stitch`，并处理相邻边重连、必要的 pcurve 更新和容差边等事项。具体对象是否保留、删除及失败恢复要跟实际代码逐句理解。

一个有用的调试问题是：失败发生在 `validate`、`transform`、`trim` 还是 `merge`？它能帮助区分输入、坐标、分裂和拓扑合并问题。

### 6. 当前几何范围要单独确认

`caxa_supported_edge` 当前识别直线，以及被表示为 `ellipse` 且半径比接近 1 的圆形支撑曲线；`caxa_overlap` 还会检查变换形式、参数范围和几何条件。这是**该候选实现的范围**，不能推广成整个模块只支持直线和圆，也不能声称它已经支持所有样条、任意椭圆或任意变换。

### 7. 属性、复制与持久化

属性是挂在模型或边上的数据，用来记录选项、关联、候选、结果或日志。复制和保存恢复不仅是复制几个数值，还要考虑模型实体引用如何映射到复制后的对象、哪些引用属于借用、失败时如何回滚。

当前代码和历史记录中存在分阶段实现与旧注释；例如部分源码注释可能落后于后续复制／持久化变更。**具体哪些类可复制或可保存，应核对当前类的实际实现、宏和对应测试，不能仅凭基类注释或历史计划推断。**

## 八、性能优化放在整个项目的哪里？

当你已经理解普通主流程，就能知道优化解决的是哪一段：

| 问题 | 当前代码中的思路 | 正确性边界 |
| --- | --- | --- |
| 很多 Body 不可能接触 | 世界空间包围盒扩张后做预筛 | 不相交可排除；相交只是候选。 |
| 边／顶点两两比较多 | 按容差建立空间网格，查询相邻格 | 要包含所有可能匹配；后续仍做判断。 |
| 小规模建索引成本高 | 根据候选规模择路，使用直接循环 | 阈值是当前实现参数，需测量。 |
| 一次操作中重复比较曲线 | 按曲线对和容差缓存结果 | 对象变化、替换或变换时需失效。 |
| 重复遍历上层拓扑链表 | 缓存链表尾节点、减少重复收集 | 拓扑重排时缓存需要更新或失效。 |
| 简单输入走完整通用流程 | 对符合前提的单输入／双面等场景使用快路径 | 必须验证前提，无法处理则回退。 |

更详细的空间网格推导、复杂度和面试问答见 [性能优化原理与追问](<2.性能优化原理与追问.md>)。不要根据源码存在某个优化就自行填性能提升百分比；需要可复核的基线和复测。

## 九、容易忽略的对象生命周期

### 1. 为什么指针问题特别重要？

缝合不只是读取对象：它可能把边和顶点替换、分裂、合并或删除。一个指针在缝合前指向有效 Edge，并不意味着缝合后仍可解引用；缓存、属性和列表里存放的引用也可能需要更新。

例如把边 B 合并到边 A 后，不能继续假定旧的边 B 和它的顶点仍存在。具体保留谁、何时释放，要看调用路径，不应只凭示意图猜测。

### 2. 区分容器、指针和对象

- `ENTITY_LIST` 是列表；里面放实体指针不自动意味着列表拥有并删除实体。
- 接口说明的借用指针不能当作调用方新分配对象随意 `delete`。
- `new_bodies` 的实体需要按头文件和模型生命周期管理；也不能根据变量名就假设应使用普通 C++ `delete`。
- CAXA 的候选计划和边属性可能引用拓扑；切分、合并、复制、回滚时需要保持引用有效或清理。
- 借用的选项对象不自动延长生命周期；读具体 setter、复制和恢复策略确认责任。

### 3. 为什么事务重要？

部分重叠处理可能先切边、再合边。如果中间失败，留下“只切了一半”的模型可能让拓扑不一致。当前 CAXA `fix()` 采用内核历史事务机制，失败时恢复；使用者仍需理解事务边界以及哪些外部状态是否参与回滚。

## 十、怎样从零读懂一次测试？

建议选择一个简单的相邻平面用例，按下面步骤写下自己的观察：

1. **构造**：创建了几个面／体？接缝原来是共享边还是两条独立边？是否带变换？
2. **输入**：调用哪个重载？传入的是 Body、自由 Face 还是 Edge？选项和容差是什么？
3. **预期**：希望共享边、只共享点，还是保持分离？期望几个输出？是否要求闭合？
4. **执行**：入口走的是普通路径、受限边路径还是聚合属性的 `calculate`／`fix`？
5. **断言**：不仅看 `outcome`，还看输出、拓扑连接、方向和模型有效性。
6. **清理**：哪些实体是原输入，哪些是新建结果，谁负责释放？

可以从 `tests/gme/src/stitching_impl/Stitching_entity_test.cpp` 的 `Stitching_EntityTest` 中选择平面和直线相关用例，再从 `tests/gme/src/stitching/stitching_attrib_test.cpp` 找 `calculate_at_tol` 和 `fix` 相关用例。先确认测试宏启用和构建配置；看见测试代码不等于它已经在当前配置下运行。

### 最值得补齐或查证的测试维度

| 维度 | 具体例子 | 为什么要看 |
| --- | --- | --- |
| 基础连接 | 完全共享直线边、完全不接触、仅点接触 | 建立最小可理解模型。 |
| 容差 | 小于、接近和大于临界距离；无效配置 | 检查是否漏连或误连。 |
| 几何 | 圆弧、同端点不同曲线、退化边、闭合边 | 防止把端点匹配误认为几何等价。 |
| 拓扑 | 部分重叠、相同／相反方向、非流形、WIRE | 验证前提和回退。 |
| 坐标 | 不同 Body 变换、世界坐标间距 | 防止比较不在同一坐标系。 |
| 性能 | 小／大规模、稀疏／密集分布 | 检查索引收益及退化。 |
| 生命周期 | 失败回滚、复制、保存恢复、内存清理 | 防止悬空引用或泄漏。 |

这些是测试设计清单，不是本文已逐项确认所有用例都已执行的结论。

## 十一、问题排查路线

### 情况 A：看起来接触了，但没有缝上

先记录输入模式和返回值，再依次检查：

1. 输入类型和归属是否符合入口约束？
2. 两条边在同一坐标系下的真实间距是多少？设置的有效容差是多少、单位是否一致？
3. 是整段重合、部分重合，还是只有一点接触？曲线类型和参数区间是否匹配？
4. 边是否自由、方向和拓扑检查是否允许？有没有命中本路径的几何支持限制？
5. 有没有走快路径或回退路径？缩小到两面两边后问题还在吗？

### 情况 B：返回成功，但下游操作失败

检查结果是否仍开放、是否有多个 Body、边与顶点是否正确共享、方向是否一致，以及内核实体检查是否报告问题。成功代表什么，要按该入口契约解释，不能推断结果一定是封闭实体。

### 情况 C：小模型快，大模型很慢

固定输入和 Release 配置，记录 Body／边／顶点规模及数据分布；测量候选数量、几何比较、拓扑合并和分配等阶段。重点看是否有密集网格导致候选爆炸、是否重复遍历长链、是否频繁构建临时对象。先有证据，再决定调整阈值或数据结构。

### 情况 D：缝合后崩溃或内存异常

确认是否仍在使用已删除或被替换的 Edge／Vertex，列表中的实体是否被重复释放，缓存是否引用过期对象，以及失败路径是否回滚。使用项目支持的调试与内存检查工具定位，不要假定所有裸指针都由当前作用域负责释放。
