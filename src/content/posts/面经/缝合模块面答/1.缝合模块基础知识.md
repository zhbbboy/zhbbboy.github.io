# 缝合模块基础知识

这篇笔记先解决一个问题：不懂 CAD 的面试官听完后，能否知道项目在做什么、难在哪里。学习时先看第一至四节，再看后面的具体代码。涉及代码的描述基于当前工作区 GME 的实现，不代表所有几何内核都有相同设计。

## 一、先用一句话解释项目

GME 是几何建模内核，缝合模块要在一定容差下，寻找多个曲面片体之间可以连接的边或顶点，并更新它们的拓扑关系，得到连接后的模型。

可以把它想成把多块表面拼起来：不仅要判断两块表面的边界在空间中是否对得上，还要让程序内部的数据结构知道它们已经连接。判断接近是几何问题，更新连接关系是拓扑问题。

**注意：** 成功缝合不必然得到封闭实体。输入可能只有部分边界匹配，也可能保留多个不相连的结果体；结果是否封闭，需要另外检查。

## 二、建模内核中的基本概念

### 1. 什么是 B-rep？
B-rep（边界表示）通过点、边、面及其连接关系描述模型边界。几何数据描述形状和位置，拓扑数据描述实体之间的连接与归属。

例如一个长方体有顶点、边和面：顶点坐标、边对应的曲线、面对应的曲面属于几何信息；哪条边连接哪些顶点、哪些面共享哪条边属于拓扑信息。

### 2. 主要拓扑对象是什么？

| 对象 | 可以怎样理解 | 面试时需要知道 |
| --- | --- | --- |
| Vertex | 拓扑顶点 | 可关联几何位置，也关联边。位置接近不等于已经是同一个顶点。 |
| Edge | 拓扑边 | 通常关联曲线和端点；其形状不能仅由两个端点完整描述。 |
| Coedge | 面边界对 Edge 的一次有方向使用 | 同一条 Edge 可被不同的面边界使用，使用方向可能不同。 |
| Loop | 面上的一条边界环 | 按顺序组织 Coedge；一个面可能有外边界和内边界。 |
| Face | 一块有边界的面 | 关联底层曲面和边界，不能简单等同于无限延伸的数学曲面。 |
| Shell | 相连接的面的集合 | 可能开放，也可能闭合，是否可构成实体还需检查。 |
| Lump / Body | 更高层次的拓扑组织和模型体 | 具体归属依赖内核实现；Body 不一定是封闭实体。 |

可以先记住普通面路径的遍历关系：`Body → Lump → Shell → Face → Loop → Coedge → Edge → Vertex`。这不是所有拓扑的唯一表示：例如 WIRE 路径需要额外处理，不能只靠 Face 的 Loop 遍历覆盖所有情况。

### 3. Edge 和 Coedge 有什么区别？

Edge 表示拓扑边，Coedge 表示某个边界环如何有方向地使用这条边。两块面连接后可能共用一条 Edge，但各自的边界使用方向不同。区分二者有助于理解环的方向、共享关系和缝合时的方向修正。

### 4. 曲线、曲面和拓扑边、面有什么区别？

曲线和曲面描述几何形状；Edge 和 Face 是模型中具有连接与归属关系的拓扑对象。一个 Face 通常还依赖边界来确定实际使用的曲面区域；一个 Edge 也有自身的参数范围和端点。

## 三、一次缝合大致怎么做？

下面是便于理解的概括，不等于每一种模式都严格执行相同顺序。

1. 校验输入、选项和容差，确定待处理实体。
2. 处理输入类型并收集需要比较的拓扑对象；当前普通入口会按选项处理 Body、自由 Face 等输入。
3. 寻找候选：先用位置、端点、包围盒或空间索引筛选不可能匹配的对象。
4. 精确判断：根据端点、曲线几何、方向及拓扑约束等判断候选能否合并。
5. 更新拓扑：合并边或顶点，调整相关 Coedge 和上层拓扑的连接与归属。
6. 处理剩余的可连接顶点、组织输出，并根据具体接口检查结果和错误码。

当前 `api_stitch` 还存在简单输入快路径，以及普通双体处理中的边阶段和顶点阶段。不同路径有自己的前置条件，无法处理的情况会交回通用逻辑。

### 只检查端点相同就能合并边吗？

一般不能。同样两个端点之间可以有不同的曲线，例如不同弧线。因此还需要检查几何类型、形状、参数范围、方向和拓扑约束。当前实现对满足条件的**非退化直线边**使用端点匹配快路径，不能推广为所有曲线都可以只看端点。

### 两个顶点坐标相同就是同一个顶点吗？

不是。两个 Vertex 对象可能位于相同或接近的位置，但引用它们的 Edge 仍然彼此独立。缝合还需要重连关联边，并维护对象归属和生命周期。

## 四、容差与数值问题

### 1. 什么是容差？

实际模型数据会受到浮点计算、数据转换和建模精度影响，理论上重合的点可能存在微小偏差。容差是判定“足够接近”时使用的尺度，具体如何比较由接口和实现决定。

容差过小可能漏掉本来希望连接的边界；过大可能把本不应连接的对象视作候选或改变模型语义。不能说“只要距离小于容差就一定缝合”，还要通过几何和拓扑等条件。

### 2. 容差与浮点比较有什么关系？

不宜把计算得到的浮点坐标一律用 `==` 判断几何重合，但也不能随便使用任意 epsilon。需要说明数值单位、模型尺度、接口的容差约定和比较对象。容差不是用来掩盖所有数值错误的。

### 3. 需要注意哪些特殊数据？

- 零长度或退化边、闭合边：端点可能重合，不能照搬普通开边的假设。
- 大坐标、负坐标、零或非有限容差：计算网格坐标时需要防止非有限值和整数转换溢出。
- 局部与世界坐标：带变换的 Body 需要在一致的坐标系中比较；包围盒也要在正确坐标系下计算。
- 同端点不同曲线、切点、复杂曲线：端点接近只能作为候选条件。

## 五、流形、方向与结果

**流形直观理解：** 对普通二维曲面的内部点，局部邻域类似一张小圆盘；边界点的邻域类似半圆盘。非流形连接则可能让局部关系更复杂，例如多张面在同一条边相接。实际判定需依具体模型与接口规则，不能仅靠“边上有几张面”覆盖所有非流形情形。

**为什么要考虑方向？** Face 边界通过有方向的 Coedge 使用 Edge，合并时需要处理边和使用方向的关系。如果只合并对象而不维护方向，可能出现错误的边界连接或后续操作异常。

**缝合与求交、布尔运算的区别：**缝合重点是识别并连接已有边界；求交寻找几何相交关系；布尔运算关注并、交、差等集合结果。它们可能相互配合，但不能认为它们是同一个操作，也不能假设缝合自动修复所有自相交或缺口。

## 六、GME 入口和代码对应关系

当前工作区的公开声明在 `GME/module/stitching/include/gme/stitching/stchapi.hxx`，入口实现在 `src/stchapi.cpp`。

- 输入 `to_be_stitched`：待缝合实体；成功后，其拓扑和所有权可能改变。
- 输出 `output_bodies`：仍含面的结果体，列表中的指针按头文件说明为借用指针。
- 输出 `new_bodies`：为自由 Face 或受限 Edge 等输入新建的结果体子集，实体生命周期按接口约定管理。
- `sopts`：缝合选项，当前声明要求非空。精确、容差、边容差模式有不同输入约束，不能混说。
- `outcome`：返回处理结果；返回成功也不代表所有输入必然组成一个封闭实体。

上面的具体契约以当前源码和头文件为准；不同版本、其他重载和其他内核可能不同。

## 七、高频基础问答

**问：项目和游戏客户端有什么关系？**

答：业务领域不同，但都涉及 C++ 数据结构、空间筛选、性能分析、资源生命周期和边界条件处理。项目中候选筛选的思想与碰撞检测里的宽相位有相似点，但缝合和游戏碰撞检测的算法及语义并不相同。

**问：缝合失败有哪些原因？**

答：可能是输入类型不符合接口约束、几何不在容差范围内、曲线不匹配、方向或拓扑约束不满足，也可能是退化或特殊拓扑需要不同处理。具体要根据返回值、输入和日志排查，不能只根据“没有合成一个体”判断接口失败。

**问：缝合后如何判断结果正确？**

答：先看返回状态和输出，再针对测试场景检查输出体数量、边面顶点连接、方向、必要的几何等价和所有权；需要封闭实体的场景再验证闭合性。单看输出不为空或只统计面数不够。

**问：如何解释游戏网格焊接和 CAD 缝合的不同？**

答：二者都可能涉及位置接近的点或边及连接关系，但游戏网格通常处理离散顶点和三角形；这里的 B-rep 还涉及精确曲线、曲面、参数范围与更复杂的拓扑约束，因此不能直接把一个方案等同于另一个。
