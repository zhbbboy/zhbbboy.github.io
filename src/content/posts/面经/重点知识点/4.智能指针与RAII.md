## 一、所有权与独占管理

### 第 1 题：如何用所有权和 RAII 解释智能指针的作用，并选择合适的资源管理方式？

**必答范围：资源与生命周期 → 所有权分类 → 类型选择 → 拷贝与移动。**
1. 什么是 RAII？正常返回、提前返回和异常发生时，资源怎样得到清理？构造函数抛异常时，完整对象、已构造成员和基类分别会怎样？RAII 除了内存还能管理哪些资源？
2. `unique_ptr`、`shared_ptr`、`weak_ptr` 分别表达什么所有权？能否复制、移动、直接访问对象？它们与值对象、引用、裸指针各适合什么场景？
3. `std::move` 到底做了什么？智能指针的移动构造、移动赋值分别如何处理源和目标？能否把智能指针的移动后状态推广到所有类型？
4. Rule of Three、Five、Zero 与资源所有权有什么关系？含智能指针成员的类如何决定拷贝、移动和析构行为？
5. 智能指针能否自动解决越界、悬空借用、循环引用和数据竞争？它与 GC 有什么区别？旧的 `auto_ptr` 有什么问题？

#### 正确回答
RAII 是将资源所有权与对象生命周期绑定，利用构造和析构自动管理资源。正常返回、提前返回以及异常栈展开时，已构造完成的局部 RAII 对象都能够按规则清理资源。
智能指针主要有三种：`unique_ptr` 表达独占所有权，支持移动但不支持复制；`shared_ptr` 通过引用计数管理共享所有权；`weak_ptr` 不延长对象生命周期，可以通过 `lock()` 尝试访问有效对象。
`std::move` 本身不会移动资源，它只是进行右值转换，实际是否移动取决于类型的移动操作。
对于管理资源的类，需要考虑 Rule of Three/Five；实际开发中更推荐 Rule of Zero，优先使用 RAII 成员，让标准库类型负责资源释放和所有权管理。
智能指针不能自动解决越界访问、悬空借用、循环引用及数据竞争。`shared_ptr` 与 GC 也不等价，前者主要基于引用计数，后者依据具体垃圾回收机制管理对象生命周期。
旧的 `auto_ptr` 因为复制会转移所有权，语义容易产生误用，已经在 C++17 中移除。

#### 示例
##### 一、RAII：资源为什么能自动清理？（第 1 问）
RAII（Resource Acquisition Is Initialization，资源获取即初始化）的核心是：
通过对象生命周期管理资源，在对象构造或初始化阶段建立资源所有权，在析构时自动清理资源。
例如：
```cpp
void Test()
{
    auto p = std::make_unique<int>(100);

    if (SomeCondition())
        return;

    // 其他操作
}
```
无论函数正常结束还是提前 `return`，局部变量 `p` 离开作用域时都会析构，自动释放拥有的动态资源。
如果函数抛出异常，正常的栈展开（Stack Unwinding）同样会析构已经构造完成、需要清理的局部对象。

```cpp
    }

```

RAII 除了动态内存，还能管理互斥锁（`std::lock_guard`）、文件句柄、网络套接字等资源。C++20 的 `std::jthread` 也提供了自动请求停止并等待线程结束的生命周期管理能力。
##### 二、unique_ptr、shared_ptr、weak_ptr（第 2 问）
三种智能指针最重要的区别如下：

|对比|unique_ptr|shared_ptr|weak_ptr|
|---|---|---|---|
|所有权|独占|共享|不拥有|
|能否复制|不可以|可以|可以|
|能否移动|可以|可以|可以|
|能否直接 `->` 访问|可以|可以|不可以|
|是否延长对象生命周期|是|是|否|
###### 为什么 weak_ptr 不能直接访问对象？
因为它不负责保持对象存活。
```cpp
auto p = std::make_shared<Enemy>();

std::weak_ptr<Enemy> weak = p;

if (auto temp = weak.lock())
{
    temp->health = 50;
}
```
`lock()` 会尝试获取临时的共享所有权。成功之后可以修改对象（如果对象类型允许修改），失败说明被管理对象已经销毁。所以 weak_ptr 是弱所有权关系，不是只读指针。

至于什么时候选择哪种类型：

|使用场景|推荐方式|
|---|---|
|普通成员对象，不需要动态分配|值对象|
|唯一负责销毁对象|`unique_ptr`|
|多个模块确实需要共同负责生命周期|`shared_ptr`|
|只需要观察共享对象是否还存活|`weak_ptr`|
|临时访问非空对象，不接管所有权|`T&`|
|临时访问可能为空的对象，不接管所有权|`T*`|
原则：能用值对象就不必使用动态分配；需要动态所有权时，优先考虑独占所有权。
###### 三、std::move 到底做了什么？（第 3 问）

你说“把非右值资源变成具有右值移动能力”，方向接近，但不够准确。
`std::move` 本质上进行类型转换，将表达式转换成右值类别中的 xvalue（将亡值），使移动构造或移动赋值有机会被选中。

它自己并不移动资源。
例如：
```cpp
auto a = std::make_unique<int>(10);

auto b = std::move(a);
```

这里真正转移资源的是 `unique_ptr` 的移动构造函数。
注意区分：
```cpp
auto b = std::move(a); // 移动构造

b = std::move(c);      // 移动赋值
```
移动赋值时，`b` 已经存在，因此还要正确处理 `b` 原来拥有的资源。
对于标准 `unique_ptr` 和 `shared_ptr`，移动后源智能指针为空；但不能推广成所有 C++ 类型移动后都为空。
例如被移动的 `std::vector` 通常只保证处于有效但未指定的状态。
##### 四、Rule of Three、Five、Zero（第 4 问）
你已经能记住三法则和五法则的成员函数，这部分没有问题。

还要进一步理解它们与所有权的关系。

|法则|主要意义|
|---|---|
|Rule of Three|自己管理资源时，需要协调析构、拷贝构造和拷贝赋值|
|Rule of Five|在三法则基础上，还需要考虑移动构造和移动赋值|
|Rule of Zero|尽量将资源管理交给 RAII 成员，让业务类不需要自己实现这些特殊成员函数|
###### 智能指针成员对类有什么影响？
例如：
```cpp
class Player
{
public:
    std::unique_ptr<Weapon> weapon;
};
```

在没有其他特殊成员函数干扰的情况下：
- `Player` 默认不能复制，因为 `unique_ptr` 禁止复制。
- `Player` 可以通过隐式生成的移动操作转移 `weapon` 所有权。
- `Player` 销毁时，成员 `weapon` 会自动析构并处理其资源。

如果改成：
```cpp
class Player
{
public:
    std::shared_ptr<Weapon> weapon;
};
```
默认复制 `Player` 时，共享指针成员会被复制，因此两个 `Player` 可能共享同一个 `Weapon` 对象。
Rule of Zero 不代表完全不用考虑所有权，而是让资源管理机制由成员类型承担。
业务类仍然需要决定允许复制、允许移动还是禁止复制。
##### 五、智能指针不能解决哪些问题？（第 5 问）
智能指针能减少部分资源管理错误，但不能自动解决所有内存安全问题。

|问题|能否自动解决|原因|
|---|---|---|
|普通数组越界|不能|智能指针不保证下标检查|
|悬空借用指针|不能|外部裸指针可能仍指向已销毁对象|
|shared_ptr 循环引用|不能|相互持有的强引用计数可能无法归零|
|多线程数据竞争|不能|引用计数安全不等于对象成员线程安全|
|不匹配的资源释放|取决于管理方式|需要正确选择删除器和所有权构造方式|
###### 智能指针与 GC 的区别
`shared_ptr` 主要根据引用计数判断何时销毁对象。
GC（Garbage Collection，垃圾回收）则根据具体实现的规则确定对象是否仍然可达或存活。
以 UE 的 UObject GC 为例，主要根据引擎可以识别的引用关系判断对象的可达性，而不是依赖普通 `std::shared_ptr` 的强引用计数。
所以两者不等价。
###### 旧的 auto_ptr 为什么被淘汰？
`std::auto_ptr` 的突出问题是复制操作会意外转移所有权。

例如，概念上：
```cpp
std::auto_ptr<int> a(new int(10));
std::auto_ptr<int> b = a;
```
执行所谓的“复制”后，`a` 会失去所有权。这违反了人们对正常拷贝语义的直觉，容易造成错误，也不适合现代容器要求。因此 `auto_ptr` 在 C++11 被弃用，并在 C++17 从标准库中移除，应该使用 `unique_ptr` 替代。
#### 面试追问
- 一个类的构造函数抛出异常，完整对象的析构函数会执行吗？已经构造成功的成员和基类怎么办？
- `unique_ptr`、`shared_ptr`、`weak_ptr` 分别能不能复制、移动？为什么 `weak_ptr` 需要 `lock()`？
- `std::move` 本身会移动资源吗？`unique_ptr` 移动后源指针是什么状态？能否把结论推广到 `std::vector`？
- 一个类只有 `std::unique_ptr<T>` 成员，通常能否默认拷贝？为什么这仍然符合 Rule of Zero？
- `shared_ptr` 能否自动解决循环引用和被管理对象的数据竞争？`auto_ptr` 为什么被淘汰？
**回答：**
- 部分正确①： 如果某个类的构造函数抛出异常，这个完整对象自身的析构函数不会执行，因为它没有构造成功。但已经构造完成的成员对象和基类子对象，会按照规定逆序析构。你把完整对象与成员子对象混淆了。
- 基本正确②： `unique_ptr` 不能复制但能移动，`shared_ptr` 和 `weak_ptr` 都能复制、移动。注意 `weak_ptr::lock()` 是尝试获取临时强引用，不是先修改对象，修改失败才说明对象被销毁。`lock()` 返回空指针才表示没有成功获取共享所有权。
- 正确③： `std::move` 本身不会移动资源。更准确地说，它把表达式转换为将亡值（xvalue），使移动操作有机会被选中。移动后的 `unique_ptr` 为空，不能把这个结论推广到所有类型。
- 正确④： 含 `unique_ptr` 成员的类通常不能隐式拷贝，但可以在满足条件时隐式移动。使用 RAII 成员管理资源，符合 Rule of Zero。
- 正确⑤： 智能指针不能自动解决所有越界、悬空借用、循环引用和数据竞争问题；`auto_ptr` 被淘汰的重要原因是复制操作会转移所有权。
RAII 是将资源管理与对象生命周期绑定，通过构造和析构自动管理资源。在正常退出、提前返回和异常栈展开时，已经构造成功的 RAII 对象能够按规则清理资源。
`unique_ptr` 表示独占所有权，不能复制但能移动；`shared_ptr` 表示共享所有权；`weak_ptr` 不拥有资源，可以通过 `lock()` 尝试获取有效的共享所有权。
`std::move` 本身只进行类型转换，不负责实际移动资源。
对于资源管理类，需要理解 Rule of Three/Five；实际开发优先采用 Rule of Zero，利用 RAII 成员自动处理资源。
智能指针不能自动解决循环引用、越界和数据竞争等问题，也不等价于垃圾回收机制。
### 第 2 题：怎样正确使用 `unique_ptr` 管理对象、数组和自定义资源？

先分析下面的所有权变化，并分别判断两条注释语句能否成立：

```cpp
void TestUnique()
{
    auto first = std::make_unique<int>(10);
    auto second = std::move(first);
    // auto copy = second;

    int* observed = second.get();
    int* raw = second.release();
    std::unique_ptr<int> third(raw);
    third.reset(new int(20));

    // std::cout << *observed << '\n';
}
```

逐行说明 `first/second/third` 是否拥有资源，`observed/raw` 在哪些时刻可以访问对象，以及原来的 `int(10)` 在哪里被清理。

**必答范围：独占与转移 → 操作接口 → 创建与释放 → 工程用法。**

1. 为什么 `unique_ptr` 禁止复制？如何接管已有资源、传递所有权、从工厂返回对象、放入容器？返回局部变量时如何选择是否写 `std::move`？
2. `get()`、`release()`、`reset()`、`swap()` 分别做什么？调用后谁负责释放？`delete p.get()`、`p.reset(p.get())`、忽略 `release()` 返回值各有什么风险？
3. `unique_ptr<T>` 与 `unique_ptr<T[]>` 在删除方式和访问接口上有什么区别？是否记录数组长度、检查越界？什么时候应改用 `vector`？
4. `make_unique` 怎样创建和初始化对象、数组？与直接使用 `new` 有什么区别？私有构造函数、自定义删除器及 `make_unique_for_overwrite`【进阶，首轮可略】分别有哪些限制和版本要求？
5. 怎样用自定义删除器管理文件、`malloc` 内存、对象池或库句柄？删除器的类型、状态、异常行为会怎样影响资源释放、移动和 `sizeof(unique_ptr)`？Placement New 的对象如何清理？
6. `unique_ptr<Derived>` 转为 `unique_ptr<Base>` 时，怎样保证正确析构？不完整类型、PImpl 和在 `.cpp` 中定义析构函数之间有什么关系？
7. 如果要求手写一个简化的独占指针，至少需要实现哪些操作、删除哪些操作、维护哪些不变量？如何检查移动赋值、自赋值和异常路径？

#### 正确回答
`std::unique_ptr` 是表达独占所有权的 RAII 智能指针，禁止复制但支持移动。移动会转移资源所有权，并使源 `unique_ptr` 为空。
它的核心接口包括 `get()`、`release()`、`reset()` 和 `swap()`。其中 `get()` 只返回非拥有型原始指针，`release()` 放弃所有权但不释放资源，`reset()` 负责清理原有对象并可接管新对象，`swap()` 交换管理状态。
`unique_ptr<T>` 默认使用 `delete`，`unique_ptr<T[]>` 使用 `delete[]`。对于需要维护长度和动态扩容的数组，通常优先考虑 `std::vector`。
`make_unique` 是推荐的创建方式。对于文件、内存池等需要特殊释放协议的资源，可以提供自定义删除器。
实际使用中还要注意多态删除时的虚析构要求，以及 PImpl 中不完整类型的析构位置。
如果手写简化版 `unique_ptr`，重点是禁止复制，实现析构、移动构造、移动赋值及所有权管理接口，保证同一资源只由一个管理者负责释放。

#### 示例
##### 一、先从零理解 unique_ptr 的工作原理

###### 1. unique_ptr 究竟是什么？
看两种管理动态内存的方式。

普通指针：
```cpp
int* p = new int(10);

// 使用资源

delete p; // 必须自己负责释放
```

使用 `unique_ptr`：
```cpp
auto p = std::make_unique<int>(10);

// 使用资源
// 离开作用域时自动清理
```
`unique_ptr` 本质上是一个 C++ 类模板，它将一个资源的独占所有权封装起来，并通过析构函数执行清理。
![](../../_Pasted_Image/Pasted%20image%2020261022132441.png)
关键区分：
- `unique_ptr` 变量是一个管理对象。
- 堆中的 `int(10)` 是被管理对象。
- `unique_ptr` 销毁时，调用删除器清理自己拥有的对象。
可以把它理解为一个管理资源的类，简化思想如下：
```cpp
template <typename T>
class SimpleUniquePtr
{
private:
    T* ptr;

public:
    explicit SimpleUniquePtr(T* p) : ptr(p) {}

    ~SimpleUniquePtr()
    {
        delete ptr;
    }

    SimpleUniquePtr(const SimpleUniquePtr&) = delete;

    SimpleUniquePtr& operator=(
        const SimpleUniquePtr&) = delete;
};
```
这段代码仅用于说明核心原理，还不是完整实现，缺少移动构造、移动赋值和访问接口等。
###### 2. 为什么 unique_ptr 禁止复制，但允许移动？
你这一点已经回答正确。

如果允许普通复制：
```cpp
auto p1 = std::make_unique<int>(10);

auto p2 = p1; // 编译错误
```
就可能产生两个独立管理者都认为自己应该删除同一个对象的问题。因此，`unique_ptr` 禁止复制。

但可以移动：
```cpp
auto p1 = std::make_unique<int>(10);

auto p2 = std::move(p1);
```
![](../../_Pasted_Image/Pasted%20image%2020261022132829.png)
![](../../_Pasted_Image/Pasted%20image%2020261022132838.png)
最重要的结论：移动的是所有权，不是把堆对象本身搬到另一个地址。
##### 二、四个最重要的成员函数（第 2 分项）
这部分是整道题的核心，建议你重点记忆。

|接口|做了什么|是否删除原资源|
|---|---|---|
|`get()`|返回保存的原始指针，供临时访问|否|
|`release()`|放弃所有权，返回原始指针|否|
|`reset()`|替换当前管理的指针，清理旧资源|是，若旧资源存在|
|`swap()`|交换两个智能指针的管理状态|否|
###### 1. get()：只借地址，不转移所有权
```cpp
auto p = std::make_unique<int>(10);

int* raw = p.get();

std::cout << *raw;
```
此时：
```
p ───────→ int(10)   拥有资源
raw ─────→ int(10)   仅临时借用
```
`raw` 不能因为自己拿到了地址，就擅自释放它。

尤其不要这样写：
```
delete p.get(); // 错误
```
因为 `p` 仍然认为自己拥有这个资源，将来还会尝试删除，可能造成重复释放。
###### 2. release()：放弃所有权，但不删除资源
```cpp
auto p = std::make_unique<int>(10);

int* raw = p.release();
```
现在：
```
p   → nullptr
raw → int(10)
```
`p` 不再管理资源。这时候调用者必须明确安排谁负责清理这块资源。

例如：
```cpp
delete raw;
```
特别注意：`release()` 不是“释放堆内存”，而是“释放智能指针对资源的所有权”。

如果写成：
```
p.release(); // 没有接收返回值
```
在没有其他所有者接管时，就可能导致内存泄漏。
###### 3. reset()：释放旧资源，可以接管新资源
```cpp
auto p = std::make_unique<int>(10);

p.reset(new int(20));
```
执行结果：
```
原来：p → int(10)

执行 reset：

① p 接管 int(20)
② 原来的 int(10) 被删除
```
你还可以：
```cpp
p.reset();
```
效果是清理当前管理的对象，并使 `p` 为空。

但是：
```cpp
p.reset(p.get()); // 错误
```
这不是安全的重置方式。它会让 `p` 继续保存原来的地址，却删除原来管理的对象，造成悬空指针，后续可能重复释放。
###### 4. swap()：交换所有权
```cpp
auto p1 = std::make_unique<int>(10);
auto p2 = std::make_unique<int>(20);

p1.swap(p2);
```
交换后：
```cpp
p1 → int(20)
p2 → int(10)
```
不会因为交换而删除这两个对象。
##### 三、现在重新分析文档给出的代码
```cpp
void TestUnique()
{
    auto first = std::make_unique<int>(10);
    auto second = std::move(first);
    // auto copy = second;

    int* observed = second.get();
    int* raw = second.release();
    std::unique_ptr<int> third(raw);
    third.reset(new int(20));

    // std::cout << *observed << '\n';
}
```

逐行看：

|语句|发生的事情|
|---|---|
|`first = make_unique<int>(10)`|first 独占 `int(10)`|
|`second = std::move(first)`|所有权转给 second，first 为空|
|`auto copy = second`|不合法，unique_ptr 禁止复制|
|`observed = second.get()`|observed 借用地址，不拥有对象|
|`raw = second.release()`|second 放弃所有权，raw 获取地址|
|`third(raw)`|third 接管原来的 `int(10)`|
|`third.reset(new int(20))`|删除 `int(10)`，third 接管 `int(20)`|
|`*observed`|不合法，observed 已经悬空|
|函数结束|third 析构，删除 `int(20)`|
这里有一个非常重要的细节：在 `second.release()` 执行之后，`observed` 和 `raw` 都仍指向有效的 `int(10)`，只是它们都不拥有资源。直到 `third.reset(new int(20))` 删除原来的对象之后，它们才变成悬空指针。
理解这段代码，`unique_ptr` 的所有权机制就基本通了。
##### 四、unique_ptr 管理单对象和数组有什么区别？（第 3 分项）
两种类型：
```cpp
// 管理一个对象
std::unique_ptr<int> p1 = std::make_unique<int>(10);

// 管理一个动态数组
std::unique_ptr<int[]> p2 = std::make_unique<int[]>(5);
```
区别：

|对比|`unique_ptr<T>`|`unique_ptr<T[]>`|
|---|---|---|
|默认删除方式|`delete`|`delete[]`|
|常用访问方式|`*p`、`p->member`|`p[index]`|
|自动记录数组长度|不适用|不提供数组长度接口|
|自动检查数组越界|不适用|不保证检查|
特别注意：
```cpp
auto p = std::make_unique<int[]>(5);

p[0] = 10;
p[4] = 50;

p[5] = 100; // 越界，未定义行为
```
所以如果你需要动态改变数组大小、查询长度、进行边界检查，优先考虑 `std::vector<T>`。
##### 五、make_unique 与自定义删除器（第 4、5 分项）
###### 1. make_unique 的作用
比较：
```cpp
std::unique_ptr<int> p(new int(10));
```
与：
```cpp
auto p = std::make_unique<int>(10);
```
两者都能够创建由 `unique_ptr` 独占管理的整数对象。

但是一般更推荐 `make_unique`，因为它可读性更好，也更容易避免把裸指针暴露在复杂表达式中导致的所有权和异常安全问题。

`make_unique` 从 C++14 开始提供。

它还有一些限制：例如无法直接指定 `unique_ptr` 的自定义删除器；通过标准库内部调用构造函数时，也不能直接绕过类的私有构造函数访问控制。
文档中的 `make_unique_for_overwrite` 属于 C++20 功能，首轮先不展开。
###### 2. 为什么需要自定义删除器？
因为不是所有资源都应该使用 `delete` 清理。

例如使用 C 语言文件接口：
```cpp
#include <cstdio>
#include <memory>

int main()
{
    using FilePtr = std::unique_ptr<
        FILE, decltype(&std::fclose)>;

    FilePtr file(
        std::fopen("data.txt", "r"),
        &std::fclose
    );
}
```
这里的资源是文件句柄。
`unique_ptr` 析构时调用 `fclose`，而不是普通 `delete`。

类似地：
- `malloc()` 分配的内存应该使用 `free()` 清理。
- 对象池借出的对象应该按照对象池约定归还。
- 第三方库句柄应该调用对应的释放接口。

自定义删除器可以是函数、函数对象或 lambda。它的类型以及是否保存状态，会影响 `unique_ptr` 的实际对象大小与移动行为。清理操作应避免抛出异常，否则可能导致 `std::terminate` 等严重后果。
###### 3. Placement New 怎么处理？

你之前学过 Placement New，它只是在已有存储上构造对象。
例如：
```cpp
void* memory = ::operator new(sizeof(Enemy));

Enemy* p = new (memory) Enemy();
```
如果由我们手动管理，就需要匹配两个动作：
```cpp
p->~Enemy();               // 结束对象生命周期
::operator delete(memory); // 释放原始存储
```
不能想当然地用普通 `delete p` 代替这一套操作。如果希望通过智能指针管理，需要设计与构造方式匹配的自定义删除器，并确保底层分配器或内存池仍然有效。
##### 六、继承与不完整类型（第 6 分项）
###### 1. 为什么基类析构函数需要关注 virtual？
```cpp
class Base
{
public:
    virtual ~Base() = default;
};

class Derived : public Base
{
};

std::unique_ptr<Base> p =
    std::make_unique<Derived>();
```
这里实际创建的是 `Derived` 对象，但最终可能通过 `Base*` 执行删除。使用默认删除器时，基类通常需要虚析构函数，才能保证通过基类指针正确销毁派生类对象。如果基类析构函数不是虚函数，通过普通基类指针删除派生类对象通常属于未定义行为（特殊销毁删除机制除外）。
这和你之前学过的多态析构是同一个知识点。
###### 2. 不完整类型与 PImpl
例如，我们想隐藏一个类的具体实现：
头文件中：
```cpp
class Widget
{
private:
    struct Impl;

    std::unique_ptr<Impl> impl;

public:
    Widget();
    ~Widget();
};
```
在 `.cpp` 中：
```cpp
struct Widget::Impl
{
    int value = 10;
};

Widget::Widget()
    : impl(std::make_unique<Impl>())
{
}

Widget::~Widget() = default;
```
`Impl` 在头文件里只是前置声明，属于不完整类型。

在 `.cpp` 文件中定义析构函数，可以保证默认删除器需要销毁 `Impl` 时，编译器已经看到它的完整定义。

这个技巧叫作 PImpl（Pointer to Implementation，实现隐藏），用于降低头文件依赖、隐藏实现细节等。

##### 七、面试如何手写简化版 unique_ptr？（第 7 分项）

这是验证你真正理解所有权的最好方法之一。

下面只实现管理单个对象、使用默认 `delete` 的简化版本：
```cpp
#include <utility>

template <typename T>
class MyUniquePtr
{
private:
    T* ptr_ = nullptr;

public:
    // 1. 构造
    explicit MyUniquePtr(T* p = nullptr) noexcept
        : ptr_(p) {}

    // 2. 析构
    ~MyUniquePtr()
    {
        delete ptr_;
    }

    // 3. 禁止复制
    MyUniquePtr(const MyUniquePtr&) = delete;

    MyUniquePtr& operator=(const MyUniquePtr&) = delete;

    // 4. 移动构造
    MyUniquePtr(MyUniquePtr&& other) noexcept
        : ptr_(other.release())
    {
    }

    // 5. 移动赋值
    MyUniquePtr& operator=(MyUniquePtr&& other) noexcept
    {
        if (this != &other)
        {
            reset(other.release());
        }

        return *this;
    }

    // 6. 获取原始指针
    T* get() const noexcept
    {
        return ptr_;
    }

    // 7. 放弃所有权
    T* release() noexcept
    {
        return std::exchange(ptr_, nullptr);
    }

    // 8. 替换资源
    void reset(T* p = nullptr) noexcept
    {
        T* old = std::exchange(ptr_, p);
        delete old;
    }

    // 9. 访问对象
    T& operator*() const
    {
        return *ptr_;
    }

    T* operator->() const noexcept
    {
        return ptr_;
    }
};
```
这个教学版本不支持数组、自定义删除器等完整标准库功能，也要求被管理对象按约定由普通 `delete` 正确销毁。

你当前最需要理解的是其中三个设计：

第一：复制操作被删除。
```cpp
MyUniquePtr(const MyUniquePtr&) = delete;
```
保证不能通过普通复制产生第二个所有者。

第二：移动必须让源对象失去所有权。
```cpp
ptr_(other.release())
```
`release()` 将旧对象管理的地址交给新对象，同时让源指针为空。

第三：移动赋值必须先处理目标已有资源。
```cpp
reset(other.release());
```
目标对象原本可能已经管理一个资源。
如果直接覆盖它保存的指针，就会丢失旧资源的释放路径。
`if (this != &other)` 用于处理自移动赋值。`reset()` 还必须遵守不能用自身 `get()` 的结果重新接管自身这一约束。

### 第 6 题：`weak_ptr` 如何观察对象、解决循环引用，并用于缓存与观察者关系？

分析下面父子对象的持有关系，预测离开作用域后能否看到析构输出，再提出满足业务语义的修改方案：

```cpp
struct Parent;

struct Child
```
