## 模块 A：虚函数的基本原理（10 题）
### 1.什么是虚函数？为什么需要虚函数？★★★ --说不清楚
##### 正确回答：
使用virtual声明的成员函数是虚函数，主要用于实现运行时多态；
它与普通成员函数的主要区别是：普通非虚函数调用通常在编译期根据静态类型确定，而虚函数可以在运行时根据对象的实际类型决定调用哪个版本；
其底层在主流编译器中通常通过虚指针`vptr` 和虚函数表`vtable`实现。当通过基类指针或引用调用虚函数时，会根据对象实际类型对应的虚表，找到最终要执行的函数；
因此，虚函数能够让我们通过统一的基类接口，实现不同派生类的行为，提高代码的扩展性；
##### 我回答存在的问题
```
正确： 使用 `virtual` 声明的成员函数是虚函数；主流编译器通常通过虚指针和虚函数表实现。
   
错误： 虚函数不是用来解决菱形继承问题的。解决菱形继承中公共基类重复问题的是虚继承。
  
关键遗漏： 虚函数最重要的作用是实现运行时多态（动态绑定），让基类指针或引用能够调用派生类重写后的函数。
```

##### 举例
结合游戏客户端中的角色攻击：
```cpp
class Character {
public:
    virtual void Attack() {
        cout << "普通攻击";
    }
};

class Boss : public Character {
public:
    void Attack() override {
        cout << "Boss技能攻击";
    }
};
```
调用：
```cpp
Boss boss;
Character* p = &boss;

p->Attack();  // 输出：Boss技能攻击
```

这里最核心的地方：
- `p` 的静态类型是 `Character*`。
- 实际指向的对象类型是 `Boss`。
- 因为 `Attack()` 是虚函数，所以最终调用 `Boss::Attack()`。
这就是运行时多态。

##### 面试追问：
假设把上面 `Character` 中的 `virtual` 去掉，其他代码不变。
那么：
```
p->Attack();
```
最终会调用 `Character::Attack()` 还是 `Boss::Attack()`？为什么？
	去掉 `virtual` 后，`Attack()` 就是普通非虚函数，它的调用在编译期根据表达式的静态类型确定。由于 `p` 的静态类型是 `Character*`，所以调用的是 `Character::Attack()`，即使它实际指向一个 `Boss` 对象，也不会发生运行时动态绑定。



### 2. C++ 多态的底层实现原理是什么？★★★
##### 正确回答
C++运行时多态在主流编辑器中通常通过虚指针`vptr`和虚函数表`vtable`实现。
当一个类拥有虚函数时，编译器通常会为该类生成对应的虚函数表，其中保存虚函数的入口地址等信息。同时，该类的对象通常包括一个虚指针`vptr`，在对象构造过程中由编译器生成的代码进行初始化。
当派生类继承基类时，派生类会有直接对应的虚表。如果派生类重写了基类的虚函数，那么对应的虚表槽位就会指向派生类的实现；如果没有重写，则仍指向继承类的实现。
当通过基类指针或引用调用虚函数的时，程序会根据实际对象的`vptr`找到对应虚表，再通过虚表中的函数入口调用最终的重写版本，从而实现运行时多态。
**需要知道，上面描述的是主流 ABI 的典型实现方式，C++ 标准本身并不强制要求使用虚函数表。**

##### 我存在的问题
```
正确： 理解了 `vptr → vtable → 虚函数地址` 的调用机制，也知道子类重写虚函数后可以实现动态绑定。
   
不严谨①： 不叫“虚类”，通常称为多态类，即拥有至少一个虚函数的类。
   
不严谨②： `vptr` 不是构造函数执行时才临时生成的。编译器会在对象布局中预留虚指针的位置，构造过程中初始化或更新其指向。

错误③： 子类虚表中不需要保存一个“父类虚表地址”。通常是子类虚表保留继承来的虚函数槽位，重写的槽位指向子类实现。
 
不严谨④： `vptr` 不一定指向虚表的物理起始位置，而是指向该虚表用于访问的地址点。

注意：就是子类生成的虚表应该是在基类的虚表基础上进行生成的，子类虚表的构建过程，本质上就是一个对基类虚表进行“复制（继承）-> 替换（重写）-> 追加（新增）”的演进过程

我的主要问题集中在虚表的生成、继承关系和对象初始化，动态绑定的核心思路已经掌握。
```

### 3. 什么是 `vptr` 和 `vtable`？有什么区别？★★★
##### 正确回答：
vptr是虚指针，vtable是虚函数表，它们是C++实现运行时多态的主要机制。
vptr通常存储在多态对象的内存布局中，每个对象都有直接的虚指针，并在构造过程中被初始化，用于关联对应的虚函数表。
vtable通常由编译器为多态类生成，同一类型的对象共享对应的虚表，表中主要保存虚函数的入口地址，还可能包含RTTI等信息。
当通过基类指针或引用调用虚函数时，程序可以通过对象的vptr找到虚表，再通过相应的槽位调用实际类型对应的虚函数，实现动态绑定。
##### 我存在的问题
```
我的回答还缺少最重要的区别：归属关系。

正确： `vptr` 指向 `vtable`，`vtable` 存储虚函数的入口地址。
 
关键遗漏： `vptr` 通常存储在对象内部，每个多态对象都有自己的虚指针；`vtable` 则通常由同一类型的对象共享，并非每个对象都生成一张。
  
补充： 在多重继承等复杂情况下，一个对象可能包含多个 `vptr`，也可能涉及多组虚表。
```

### 4. 虚函数是如何完成动态绑定的？★★★
##### 正确回答：
C++虚函数的动态绑定主要通过vptr和vtable实现，可以分为编译期和运行期两个阶段。
**编译期**，编译器会根据对象表达式的静态类型完成函数查找和重载决议，确定虚函数调用对应的虚函数槽位，并生成相关的虚表数据和调用代码。
**运行期**，对象构造时会初始化虚指针vptr。当通过基类指针或引用调用虚函数时，程序通常会通过实际对象的vptr找到对应虚表，再根据编译期确定的槽位获取函数地址，最终调用实际类型对应的虚函数。这就是运行时动态绑定的基本原理。

**补充：** 如果编译器能确定具体调用目标，也可能通过**去虚拟化（Devirtualization）** 优化为直接调用，不一定每次都实际查虚表。

##### 我存在的问题
```
对编译期和运行期的理解存在一点混淆。

正确： 运行时通过实际对象的 `vptr` 找到虚表，再调用对应的虚函数。
  
错误： `vptr` 不是编译期初始化的，而是对象构造过程中在运行期初始化的。
  
关键遗漏： 编译期会确定函数是否为虚函数、完成函数查找与重载决议，并确定对应的虚表槽位；运行期才根据实际对象找到最终调用的函数。
```

### 5. `vptr` 和 `vtable` 分别存在哪里？★★★
##### 正确回答：
vptr通常存储在多态对象的内部，具体位置取决于对象自身的存储位置。如果对象在栈上，那么vptr就在栈上；如果对象存储在堆上，vptr就在堆上。
vtable则通常由编译器生成，存放在程序的只读数据区域，例如Windows/MSVC中的.rdata，Linux/GCC中的.rodata或.data.rel.ro等区域。
因为虚函数表通常由同一类型的对象共享，不需要每个对象保存一份，所以将虚函数表放在静态数据区域，而对象内容只需要通过vptr关联对应的虚表。

需要注意，具体内存布局属于编译器和 ABI 的实现细节，C++ 标准没有强制规定。
##### 我存在的问题
```
正确： `vptr` 确实存储在对象内部。

错误： `vptr` 不一定在栈区，它的位置取决于对象本身存储在哪里。

关键遗漏： `vtable` 通常存储在程序的只读数据区，而不是对象内部。
```

##### 举例理解
```cpp
class Base {
public:
    virtual void func() {}
};

Base a;              // 栈上对象
Base* b = new Base;  // 堆上对象
```

### 6. 虚函数表什么时候生成？虚指针什么时候初始化？★★★
##### 正确回答：
虚函数表通常在编译阶段由编译器根据类的虚函数和继承关系生成，编译器会把相关虚表数据放入目录文件，之后由链接器完成符号解析、地址重定位等工作。
而虚指针vptr是对象内部的指针，通常在运行时执行构造函数的过程中，由编译器生成的代码进行初始化，使其指向当前构造阶段对应的虚函数表。
如果存在继承关系，例如创建一个Derived对象，会执行Base的构造过程，此时虚函数调用按照Base的规则分派；进入Derived的构造阶段后，vptr会被调整为对应派生类的虚表，最终支持派生类的动态绑定。
因此可以总结为：**虚表通常在编译和链接阶段准备好，虚指针在对象构造过程中初始化。**
##### 我存在的问题
```
正确： 虚函数表通常在编译阶段生成相关数据，vptr 在运行时对象构造过程中初始化。
   
不严谨①： 虚表还涉及链接阶段，链接器会处理虚表符号、地址重定位以及重复定义的合并等。
  
关键遗漏②： 如果存在继承关系，构造对象时 vptr 可能会随着基类、派生类的构造阶段发生变化。
```

#### 7. 一个类有多个虚函数，会有多个虚表吗？★★★
##### 正确回答：
一个类有多个虚函数，并不意味着它会有多个虚函数表。
在普通单继承情况下，一个多态类通常只有一张主要虚表，多个虚函数的入口地址保存至不同的槽位中。
而在多继承情况下，如果派生类继承了多个多态基类，那么对象内部可能存在多个vptr，分别关联不同的虚函数表部分，以支持通过不同基类接口进行虚函数调用。
所以虚表数量主要取决于**继承结构、需要支持的多态基类子对象以及编译器的 ABI 实现**，而不是虚函数的数量。
##### 我存在的问题
```
正确： 虚函数数量不会直接决定虚表数量，普通单继承通常只有一组主要虚表。
   
正确： 多重继承可能导致一个对象存在多个 `vptr`，对应多个虚表入口。
   
需要完善： 不是只看是否多继承，还取决于各个基类是否具有多态性，以及具体的继承结构。例如，继承两个普通非多态类，并不一定产生多个虚表。
```


### 8. 同一个类的多个对象是否共享虚表？★★★
##### 正确回答：
同一个多态类的多个对象通常共享同一张虚函数表，但每个对象都有自己的虚指针vptr。
虚函数表通常由编译器生成，存放在程序的静态数据区域，保存该类型的虚函数入口地址等信息。
因为相同类型的对象具有相同的虚函数分派规则，所以不需要为每个对象生成独立的虚表，而是通过各自vptr指向共享的虚表，从而减少内存开销。
因此，如果创建1000个相同类型的多态对象，在普通单继承的典型实现下，会有1000个vptr，但只需要一张共享的虚表

##### 我存在的问题
```
正确： 同一类型的多个对象通常共享虚表，每个对象拥有自己的 `vptr`。
  
正确： 虚表通常存放在静态数据区域，不会为每个对象重新生成。
  
需要完善： 共享虚表的主要原因是同类型对象具有相同的虚函数分派规则，可以共享同一份虚表数据，节省内存。不发生访问冲突只是通常只读共享的一个特点。
```


### 9. 虚函数的函数体存在虚表里吗？★★
##### 正确回答
虚函数的函数体并不存储在虚函数表中，虚函数表中主要保存虚函数的入口地址，而函数编译后的机器指令通常存储在程序的代码区，也就是.text段。
虚函数表通常存储在静态数据区域，除了虚函数入口地址，还可能包含RTTI类型信息，对象偏移量等数据。
当程序进行虚函数调用时，会通过对象的vptr找到对应的虚函数表，再根据虚函数表中的函数入口地址跳转到代码区执行对应的函数
因此，虚表存储的是函数入口信息，而不是函数的实际代码。
##### 我存在的问题
```
正确： 虚函数表存储的是虚函数入口地址，而不是函数体本身。
   
关键遗漏①： 虚函数的实际机器指令通常存储在程序的代码区（`.text` 段）。

关键遗漏②： 虚表除了函数入口地址，还可能存储 RTTI 类型信息、对象偏移量等数据，具体取决于编译器 ABI。
```


### 10. 虚函数会增加对象的内存大小吗？★★★
##### 正确回答：
虚函数通常会增加对象的内存大小，因为主流编译器会在多态对象内部保存虚函数指针vptr，用于指向对应的虚函数表。
在64位环境下，虚指针通常占8字节。虚函数表和虚函数代码本身不存储在对象内部，因此不会字节增加对象的sizeof。
例如，一个类只有一个 `int` 成员时，通常占 4 字节。如果增加一个虚函数，对象内部通常需要额外保存一个 8 字节的 `vptr`，**再考虑内存对齐，最终 `sizeof` 通常是 16 字节**。

**需要注意**，如果类已经有虚函数，继续添加普通虚函数通常不会继续增加对象的大小，因为一般不需要再增加新的 `vptr`。

##### 我存在的问题
```
- 正确： 虚函数表通常存储在静态数据区域，不会直接增加每个对象的内存大小。
    
- 错误①： 64 位环境下，`vptr` 通常占 8 字节，不是 4 字节。
    
- 错误②： 虚函数的函数体存储在代码区，不会因为增加虚函数而直接占用对象内部空间。
    
- 关键遗漏： 需要考虑内存对齐，所以增加一个 8 字节的 `vptr`，对象的 `sizeof` 不一定只增加 8 字节。
```
