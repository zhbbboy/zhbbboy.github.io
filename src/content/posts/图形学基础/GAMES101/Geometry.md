## 1. Representation(表示方法)


> **一个三维物体的表面，到底要怎么在计算机里表示？**

标题里的：
- `Representation`：表示方法
- `Implicit`：隐式表示
- `Explicit`：显式表示

核心就是把三维几何表面的表示方法分成两大类：**隐式表示**和**显式表示**。

### 1. 1 Implicit（隐式表示）

隐式表示的思路是：

> **我不直接告诉你表面上有哪些点，而是给你一个“规则/函数”，满足这个规则的点就是物体表面。**

比如一个球，可以用类似这样的方程描述：

\[ x^2+y^2+z^2=1 \]

它没有列出来“球面上一共有哪几个点”，而是告诉你：

> 任何满足这个方程的 `(x,y,z)`，都在球面上。

所以叫 **Implicit Representation（隐式表示）**。

你图片里列了几种隐式表示方式。

|英文|中文|直观理解|
|---|---|---|
|`algebraic surface`|代数曲面|用数学方程定义表面|
|`constructive solid geometry (CSG)`|构造实体几何|用基本形状做并、交、差|
|`distance function`|距离函数|用“点距离表面多远”描述物体|
|`level set`|水平集|用一个函数的某个等值面表示表面|
|`fractal`|分形|用递归/数学规律生成复杂形状|

比如 CSG（Constructive Solid Geometry，构造实体几何）很好理解。

假设有：

```
一个球
+
一个立方体
```

可以做：

```
Union        并集：球 + 立方体
Intersection 交集：只保留重叠部分
Difference   差集：从一个里面挖掉另一个
```

所以不是把最终模型的三角形全存下来，而是保存：

> “这个物体 = 球体 - 一个圆柱体”

这就是一种隐式描述。

`distance function`（距离函数）也是后面图形学很常见的东西。

它给空间里每一个点一个值：

```
这个点距离物体表面多远？
```

例如：

```
距离表面 = 0
```

的所有点，就构成物体表面。

如果带正负号，就是你以后经常会见到的：

> `Signed Distance Function, SDF（有符号距离函数）`

通常还可以用正负表示点在物体内部还是外部。

---

####  隐式表示的优点 Pros

图片里的 `Pros` 就是 **Advantages（优点）**。
`compact description (e.g., a function)`

意思：
> 描述非常紧凑，例如一个函数就可以表示整个物体。

比如球只需要一个方程，而不是保存几十万个顶点。
`certain queries easy (inside object, distance to surface)`

意思：
> 某些查询特别容易。

例如：
```
这个点在物体里面还是外面？
这个点距离表面多远？
```

如果你的隐式函数本来就包含这些信息，就很好求。
`good for ray-to-surface intersection`
意思：
> 对 Ray-to-Surface Intersection（射线与表面求交）比较方便。

这和后面 Ray Tracing（光线追踪）有关。
`for simple shapes, exact description / no sampling error`
意思：
> 对简单物体可以进行精确描述，不会有采样误差。

例如：x^2+y^2+z^2=1 
描述的是一个数学意义上真正光滑的球，而不是很多小三角形拼出来的“近似球”。
`easy to handle changes in topology (e.g., fluid)`
这里：
- `topology`：拓扑结构
- `fluid`：流体
意思是：
> 对物体结构变化很大的情况比较容易处理。

例如水：
```
一团水
↓
分裂成两团
↓
又重新合在一起
```
它的连接关系一直变化。
如果你用固定三角网格描述，就会比较麻烦；某些隐式表示处理这种变化更方便。

---

#### 隐式表示的缺点 Cons

`Cons` = 缺点。
图片只有一条：
`difficult to model complex shape`
意思：
> **复杂形状很难直接用隐式函数建模。**

比如：
```
一个人
一辆汽车
一条龙
一个复杂游戏角色
```

你很难写一个简单方程： f(x,y,z)=0 
就把整个人表示出来。
所以隐式表示虽然数学上漂亮，但复杂模型不一定方便。

---

### 1.2 Explicit（显式表示）

显式表示正好反过来：
> **我直接告诉你表面上的点在哪里，或者这些点怎么连接。**

比如你直接存：
```
顶点 A = (1,2,3)
顶点 B = (3,4,5)
顶点 C = (5,2,1)

A、B、C组成一个三角形
```
这就是显式表示。

你图片第一条：
![](../../_Pasted_Image/Pasted%20image%2020260908160904.png)

可以理解为：
> 给我两个参数 `(u,v)`，我直接算出表面上的一个三维点 `(x,y,z)`。

这叫 Parametric Surface（参数曲面）一类的思想。

例如球面可以通过两个角度参数：
```
u
v
```
算出：
```
x
y
z
```
所以：
> 给参数 → 直接得到表面上的点

这就是“显式”的感觉。

但图片里也写了一个非常重要的区别：
> 得到表面上的点容易，判断一个任意空间点是在表面内部还是外部比较困难。

因为你只是知道“这些点在表面上”，并没有天然获得 inside/outside（内部/外部）信息。

---

图片里还列了：
##### Point Cloud（点云）

就是保存大量三维点：
```
●      ●
   ●
       ●
 ●
```
每个点可能就是：
```
(x, y, z)
```
例如激光雷达扫描得到的就是很典型的 Point Cloud（点云）。

但只知道点的位置，不一定知道它们怎么连接。

---
##### Mesh（网格）

这是你游戏和图形学里最重要的。
Mesh（网格）通常就是：
> **顶点 + 顶点之间的连接关系**

最常见的是 Triangle Mesh（三角形网格）。
例如：
```
A ----- B
 \     /
  \   /
    C
```
保存：
```
Vertex:
A
B
C

Index:
A-B-C
```
于是知道这三个点组成一个三角形。

你图片里说：
> `mesh，使用 .obj 文件描述 mesh`

`.obj` 就是一种很经典的三维模型文件格式，可以保存：
```
vertices（顶点）
texture coordinates（纹理坐标）
normals（法线）
faces（面）
```

### 1.3 最重要的区别

```
Implicit（隐式）

我给你一个规则
↓
你自己判断哪些点属于表面

例如：
f(x,y,z)=0
```

而：
```
Explicit（显式）

我直接把表面告诉你
↓
这些点/三角形就是表面

例如：
Triangle Mesh
```

举个球：
**隐式表示：** x^2+y^2+z^2=1 
意思：
> 满足这个方程的点组成球面。

**显式表示：**
```
生成几万个顶点
+
把它们连接成三角形
```
看起来像：
```
       /\
    /\/  \/\
   /  \  /  \
   \  /\/   /
    \/  \  /
```
用很多小三角形去逼近球面。

---

所以：
> **Implicit Representation（隐式表示）是“用函数/规则定义表面”；Explicit Representation（显式表示）是“直接存储或生成表面上的点和连接关系”。**

而游戏开发里你以后接触最多的：
```
Mesh
Triangle
Vertex
.obj
.fbx
```
基本都属于 **Explicit Representation（显式表示）**。

这里着重介绍**贝塞尔曲线（Bézier Curves）**。下图有三个**控制点（control point）**，取所有[0,1]之间的t，便可以画出该曲线。当然四个甚至更多的控制点都是可行的。特别的四个控制点的称为**cubic Bézier curve**

![](https://iewug.github.io/book/img/11curve.png)

代数形式：

![](https://iewug.github.io/book/img/11algebraic.png)

更一般的，n+1个控制点下，曲线可以表示为：
![](../../_Pasted_Image/Pasted%20image%2020260908162201.png)
#### 贝塞尔曲线的端点切线
这个很重要。

以三次贝塞尔为例：
```
P0, P1, P2, P3
```
曲线从：
```
P0
```
出发的时候，它的切线方向由：
```
P0 → P1
```
决定。

到了终点 `P3`，切线方向由：
```
P2 → P3
```
决定。

所以可以直观记：
```
P1 决定“怎么离开 P0”

P2 决定“怎么进入 P3”
```
更准确的导数是：
![](../../_Pasted_Image/Pasted%20image%2020260908162539.png)
因此：
> 起点切线平行于 `P0P1`，终点切线平行于 `P2P3`。

这对后面的 **Piecewise Bézier Curve（分段贝塞尔曲线）**非常重要。

---
#### Affine Transformation（仿射变换）性质

> 仿射变换后做贝塞尔，与先做贝塞尔再仿射变换，结果一致。

**什么意思？**
假设你有四个控制点：
```
P0 P1 P2 P3
```

方案 A：
```
先用它们生成 Bézier Curve
↓
再把整条曲线旋转、平移、缩放
```
方案 B：
```
先把 P0 P1 P2 P3
旋转、平移、缩放
↓
再生成 Bézier Curve
```
结果一样。

也就是说：
```
先生成曲线 → 做变换
```
和：
```
先变换控制点 → 再生成曲线
```
等价。

所以实际程序里：
> 通常只需要变换控制点，不需要把曲线上无数个点逐个处理。

---

# 8. Convex Hull Property（凸包性质）

这是贝塞尔曲线非常重要的性质：
> **贝塞尔曲线一定位于所有控制点形成的 Convex Hull（凸包）内部。**

Convex Hull（凸包）你可以理解成：
> 用一根橡皮筋把所有控制点包起来形成的最小区域。

例如：
```
       ● P1
      /     \
     /       \
P0 ●    曲线   ● P2
     \       /
      \     /
       ● P3
```

曲线不会突然跑到这个区域外面。

这意味着控制点给出了曲线活动范围。

---

# 9. Piecewise Bézier Curve（分段贝塞尔曲线）

如果想表示一条非常复杂的曲线，一般不会：
> 一口气用几十个控制点搞一条超高次贝塞尔。

更常见的是：

> **用很多段低次贝塞尔曲线拼起来。**

比如：

```
第一段 Bézier
P0 ───────→ P3

              第二段 Bézier
            P3 ───────→ P6
```

整体：

```
~~~~~~~|~~~~~~~~
       ↑
     连接点
```

这就是：

> Piecewise Bézier Curve（分段贝塞尔曲线）

尤其常用：

> 一段一段的 Cubic Bézier Curve（三次贝塞尔曲线）。

---

#### C0 Continuity（C0 连续）

假设有两段曲线：
```
第一段终点：P3
第二段起点：Q0
```
要实现 C0 连续，只要求：
![](../../_Pasted_Image/Pasted%20image%2020260908164805.png)
也就是：
> 两条曲线接上了，没有断开。

例如：
```
~~~~~~●~~~~~~
      ↑
   同一个点
```
但是可能出现：
```
        /
       /
~~~~~~●
```
虽然接上了，但有一个明显折角。

所以：
> C0 只保证“位置连续”，不保证光滑。

---

#### C1 Continuity（C1 连续）

C1 比 C0 更严格。
不仅要求：
```
第一段终点 = 第二段起点
```
还要求：
> **连接处的一阶导数相同。**

你可以先理解成：
> 连接处不仅位置一样，而且切线方向和速度也一样。

例如：
```
第一段：
P2 ----> P3

第二段：
Q0 ----> Q1
```
其中：
```
P3 = Q0
```
还要让：
```
P2 → P3
```
和：
```
Q0 → Q1
```
方向一致，并且在严格 C1 下导数大小也要匹配。
这样连接处看起来就是：
```
~~~~~~~~~~~~~~
```
而不是：
```
~~~~~~╱
     ╱
```

---

```
Bézier Curve
│
├─ control points（控制点）
│
├─ t ∈ [0,1]
│
├─ 3点 → quadratic（二次）
│
├─ 4点 → cubic（三次）
│
├─ 性质
│   ├─ 经过首尾控制点
│   ├─ 首尾切线由相邻控制点决定
│   ├─ 仿射不变性
│   └─ 凸包性质
│
└─ Piecewise Bézier（分段贝塞尔）
    ├─ C0：位置连续
    └─ C1：位置 + 一阶导数连续
```


贝塞尔曲线性质（n个控制点）：
- 端点切线斜率：
- 仿射变换后做贝塞尔曲线，与先做贝塞尔曲线再仿射变换，结果一致
- 凸包性质：贝塞尔曲线一定在凸包（最小围住控制点的多边形）内

**分段贝塞尔曲线（Piecewise Bézier Curve）**

也就是一根曲线由多个贝塞尔曲线组成。连接点的连续性可以定义：
- C0 continuity：第一段终点和第二段起点相同，
- C1 continuity：还要求切线斜率一致，

## 3. Surface

### 3.1 Bézier Surface

考虑的控制点阵，先用每列四个控制点画出四条贝塞尔曲线（图中灰色，参数u控制），再利用这四条曲线在相同参数u上的点，画出一条贝塞尔曲线（图中蓝色，参数v控制）。诸多这样蓝色的曲线就可以组成贝塞尔曲面。
![](../../_Pasted_Image/Pasted%20image%2020260908165104.png)
> **把一维的 Bézier Curve（贝塞尔曲线）推广到二维，得到 Bézier Surface（贝塞尔曲面）。**

前面已经知道，一条三次贝塞尔曲线需要 4 个控制点：
```
P0 —— P1 —— P2 —— P3
```
然后通过一个参数：
```
t ∈ [0,1]
```
就能得到曲线上的一个点。
贝塞尔曲面只是把“控制点”从一排，变成一个 **控制点网格**。

比如最常见的是 `4 × 4`：
```
P00   P01   P02   P03
P10   P11   P12   P13
P20   P21   P22   P23
P30   P31   P32   P33
```
一共有 16 个控制点。

---

**图片描述的过程可以拆成两步**。

第一步，沿一个方向做 Bézier。
比如每一列都有 4 个控制点：
```
P00
P10
P20
P30
```
可以形成一条贝塞尔曲线。

四列就得到 4 条曲线：
```
curve0
curve1
curve2
curve3
```
图里那些灰色曲线，就可以理解成这 4 条曲线。

然后选定一个参数：
```
u = 0.3
```
在每一条灰色曲线上，都取同样 `u=0.3` 对应的点。

于是得到 4 个点：
```
Q0
Q1
Q2
Q3
```
大概就是：
```
灰曲线1 —— ● Q0
灰曲线2 —— ● Q1
灰曲线3 —— ● Q2
灰曲线4 —— ● Q3
```

---

第二步，再拿这 4 个点：
```
Q0 Q1 Q2 Q3
```
继续做一次贝塞尔曲线。

这次用另一个参数：
```
v ∈ [0,1]
```
于是得到图里的蓝色 Bézier Curve（贝塞尔曲线）。

所以：
```
第一方向：u
↓
得到4个中间点

第二方向：v
↓
得到曲面上的一个点
```
更准确地说，对于固定的 `u`，让 `v` 从 0 到 1 变化，就能得到一条蓝色曲线。

然后再不断改变：
```
u = 0
u = 0.01
u = 0.02
...
u = 1
```
你会得到很多很多条蓝色曲线：
```
~~~~~~
 ~~~~~~
  ~~~~~~
   ~~~~~~
```
这些曲线铺在一起，就形成一个 **Surface（曲面）**。

---

可以把 Bézier Surface 理解成：
> **先沿 u 方向做一次贝塞尔插值，再沿 v 方向做一次贝塞尔插值。**

它有两个参数：
```
u ∈ [0,1]
v ∈ [0,1]
```
因此曲面上的点可以写成：
```
S(u,v)
```
这和曲线：
```
B(t)
```
区别就在于：
```
贝塞尔曲线：
1个参数 t

贝塞尔曲面：
2个参数 u、v
```
你可以把它想成：
```
Curve：
沿着一条线走
→ 只需要一个参数 t

Surface：
可以左右走 + 前后走
→ 需要两个参数 u、v
```

> **Bézier Surface 本质上就是“二维 Bézier”：用一个 4×4 控制点网格，通过 u、v 两次贝塞尔插值生成一个光滑曲面。**
### 3.2 Mesh

这里介绍对网格的**细分（subdivision）**、**简化（simplification）**和**正则（regularization）**操作。
![](../../_Pasted_Image/Pasted%20image%2020260908165041.png)
#### 3.2.1 Subdivision
网格细分的思路是：
1. 创建更多的三角形（顶点）
2. 调整所有顶点的位置

下面介绍两种细分方法。
**1）Loop Subdivision**（注意到Loop是人名）
首先，将每个三角形分成四份：

![](../../_Pasted_Image/Pasted%20image%2020260908165154.png)

然后，**调整顶点位置：**
- 新顶点
![](../../_Pasted_Image/Pasted%20image%2020260908165143.png)

- 旧顶点，可以看到如果度越大，相邻顶点对原始顶点的影响越小
![](../../_Pasted_Image/Pasted%20image%2020260908165149.png)

**2）Catmull-Clark Subdivision**
Loop细分只能解决三角形网格的细分问题，对于一般的情况可以采用Catmull-Clark细分。
**基本概念**
- **非四边形面（Non-quad face）**：顾名思义。
- **奇异点（Extraordinary vertex）**：度数不为4的点。

首先，**添加新点**
- 取每个面的一个点（比如重心），取每个边的中点，将所有新添加的点做连接
- 经过一次细分，所有非四边形面会消失，变成一个奇异点
![](../../_Pasted_Image/Pasted%20image%2020260908165205.png)

然后，调整位置![](../../_Pasted_Image/Pasted%20image%2020260908165212.png)


#### 3.2.2 Simplification
我们采取**边坍缩（edge collapsing）**的方法来简化曲面。
![](../../_Pasted_Image/Pasted%20image%2020260908165218.png)


先要介绍**二次误差（quadric error）**，即新的点应该使与它相关联的面的平方和达到最小。
![](../../_Pasted_Image/Pasted%20image%2020260908165223.png)

于是**简化的步骤如下：（贪心算法）**
1. 假设坍缩每一条边，然后分别得到它们的二次误差。 做为各自的分数
2. 每次都坍缩分数最小的边，然后更新被影响边的分数
3. 重复步骤1

## 另. Shadow Mapping

**不属于几何这一部分，但是somehow就在lecture12介绍了，应该还是属于光栅这一块的**

这里提供一个生成物体影子的办法，其**核心想法**是：**不在影子中的点必须同时被光源和照相机看到。**

1. 首先记录光源能看到点的深度信息
2. 从眼睛看向物体，将所看到的点，投射回记录深度信息的那张图。在对应像素位置，找到当时的深度信息，与现在该点到光源的距离进行比较。如果当前距离比之前的深度大，说明中间有物体遮挡，即在阴影之中（如点2）；如果相等，则不在阴影中（如点1）。

**Shadow Mapping的优点**：快

**Shadow Mapping 的问题**

- 理论上只能硬阴影（适用于点光源）
- 依赖贴图的分辨率，走样问题
- 浮点精度误差，浮点数判断相等

所谓的硬阴影和软阴影，其实可以理解为**本影（umbra）** 和 **半影（penumbra）**。

CS3310还补充了**阴影体（shadow volume）** 和**平面阴影（planar shadow）** 来计算阴影的方法。

**planar shadow**

思想很简单，根据光源和投影面位置推导一个投影矩阵，通过这个矩阵能把模型上所有顶点投射到投影面（比如地面）上，也就是将渲染物体压扁到一个平面上。

**shadow volume**

![](../../_Pasted_Image/Pasted%20image%2020260908165233.png)

上图中红色点是进入阴影体，紫色点是出阴影体。只需判断观察点进出阴影体数目是否相同（可以使用stencil buffer来计数）。相同的话就不在阴影体中。该算法性能不好，且理论上也只能生成硬阴影，不过不会因采样和分辨率而产生的问题。
