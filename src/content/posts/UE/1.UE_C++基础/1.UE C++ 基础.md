# UE C++ 第一层基础笔记：从 UObject 到 Delegate

这 10 个知识点不要分开背。它们实际上组成了 UE C++ 最核心的一条链：

```
普通 C++
   │
   ▼
UObject 对象体系
   │
   ├── UCLASS / UPROPERTY / UFUNCTION
   │              │
   │              ▼
   │          Reflection
   │              │
   │              ▼
   │             UHT
   │              │
   └──────────────┤
                  ▼
                 UBT
                  │
                  ▼
              C++ 编译器
                  │
                  ▼
            UE 运行时对象系统
                  │
        ┌─────────┼──────────┐
        ▼         ▼          ▼
       GC       Blueprint   Serialization
                  │
        ┌─────────┴─────────────┐
        ▼                       ▼
 UE基础数据结构              Delegate
 TArray/TMap/...          对象之间事件通信
```

下面的笔记主要依据 Epic 官方 Unreal Engine 文档整理。最重要的不是把 API 全背下来，而是理解：**UE 为什么不能只用“普通 C++”来做游戏。**

---

# 一、先理解最核心的问题：为什么 UE 要有 UObject？

## 1. 普通 C++ 类有什么？

例如：

```
class Player
{
public:
    int HP;

    void Attack();
};
```

C++ 编译器知道：

```
Player 是一个类型
HP 是 int
Attack 是函数
```

但是程序运行起来以后，通常没有一个统一的运行时系统能方便地回答：

```
这个对象到底是什么类？
这个类有哪些属性？
哪些属性应该显示到编辑器？
哪些属性需要保存？
哪些属性需要网络同步？
哪些对象还活着？
哪个函数可以给 Blueprint 调？
```

这就是 UE 自己建立对象系统的原因。

---

# 二、UObject：UE 对象系统的根基

`UObject` 是 Unreal Engine 对象系统最核心的基类。UE 在普通 C++ 对象之上增加了反射、GC、序列化、类型信息以及和编辑器等系统的集成能力。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/objects-in-unreal-engine)

最简单的 UObject：

```
UCLASS()
class MYGAME_API UMyObject : public UObject
{
    GENERATED_BODY()

public:

    UPROPERTY()
    int32 HP;

    UFUNCTION()
    void Attack();
};
```

你可以暂时把它理解为：

```
普通 C++ 对象
       +
UE 运行时身份
       =
UObject
```

---

## 1. UObject 和普通 C++ 类最本质的区别

普通 C++：

```
class FWeapon
{
};
```

通常自己决定生命周期：

```
FWeapon* Weapon = new FWeapon();

delete Weapon;
```

而：

```
UCLASS()
class UWeapon : public UObject
{
    GENERATED_BODY()
};
```

属于 UObject 系统，应由 UE 对象创建机制管理，而不是直接：

```
new UWeapon;
delete Weapon;
```

Epic 官方明确要求 UObject 使用 UE 的对象创建方式；运行时通常使用 `NewObject`，构造默认子对象使用 `CreateDefaultSubobject`。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/objects-in-unreal-engine?lang=zh-CN&utm_source=chatgpt.com)

例如：

```
UWeapon* Weapon = NewObject<UWeapon>();
```

Actor 又有所不同：

```
AEnemy* Enemy =
    GetWorld()->SpawnActor<AEnemy>();
```

---

# 三、一个很重要的概念：UClass

假设：

```
UCLASS()
class AMonster : public AActor
{
    GENERATED_BODY()
};
```

你创建：

```
AMonster* Monster;
```

这里存在两个不同层次：

```
AMonster
│
├── C++ 编译期类型
│
└── 对应一个 UE 运行时 UClass
```

可以：

```
UClass* Class = Monster->GetClass();
```

因此你可以把：

```
UClass
```

暂时理解成：

> **UE 对某个 C++/Blueprint 类在运行时的描述对象。**

它记录这个 UE 类相关的反射信息。Epic 文档也把 `UClass` 描述为 UE 对类的特殊表示；每个 UCLASS 还具有 Class Default Object。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/gameplay-classes-in-unreal-engine?utm_source=chatgpt.com)

---

# 四、CDO：Class Default Object

这是 UObject 面试中比较值得知道的概念。

每一个 `UCLASS` 都维护一个：

```
Class Default Object
简称 CDO
```

例如：

```
AMonster
```

存在：

```
AMonster 的 CDO
```

CDO 可以近似理解成：

> **这个类的默认模板对象。**

例如：

```
AMonster::AMonster()
{
    MaxHP = 100;
    MoveSpeed = 600;
}
```

这些默认数据会体现在类默认对象中，之后创建对象时可以基于默认值进行初始化。Epic 官方文档也说明，生成 Actor 时若没有指定 Template，默认会使用该类的 CDO 初始化 Actor。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/objects-in-unreal-engine?lang=zh-CN&utm_source=chatgpt.com)

因此有一个很重要的 UE 编程原则：

```
AMonster::AMonster()
```

主要做：

```
设置默认值
创建默认组件
```

例如：

```
AMonster::AMonster()
{
    MaxHP = 100;

    WeaponMesh =
        CreateDefaultSubobject<UStaticMeshComponent>(
            TEXT("WeaponMesh")
        );
}
```

而很多依赖游戏世界的运行时逻辑应该放到：

```
BeginPlay()
```

而不是全部塞进构造函数。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/objects-in-unreal-engine?lang=zh-CN&utm_source=chatgpt.com)

---

# 五、UCLASS / UPROPERTY / UFUNCTION 到底是什么？

这是下一层。

你可以先记一句：

> **这些宏本质上是在告诉 UE：“这个 C++ 东西我要交给你的对象系统管理/描述。”**

Epic 官方把它们作为让 Unreal Engine 认识类、属性和函数的重要入口。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/reflection-system-in-unreal-engine)

---

# 六、UCLASS

普通类：

```
class MyObject
{
};
```

UE 类：

```
UCLASS()
class MYGAME_API UMyObject : public UObject
{
    GENERATED_BODY()
};
```

其中：

```
UCLASS()
```

告诉 UE：

```
这个类需要进入 UObject / Reflection 系统
```

`GENERATED_BODY()` 则加入 UE 为这个类生成的基础设施代码；Epic 要求 UCLASS/USTRUCT 使用它。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/objects-in-unreal-engine)

---

## 常见 UCLASS 写法

例如：

```
UCLASS(Blueprintable)
class UWeapon : public UObject
```

表示可以作为 Blueprint 类的基础。

或者：

```
UCLASS(Abstract)
class UWeaponBase : public UObject
```

表示这是抽象类型。

不用现在背几十个 Class Specifier，第一阶段知道：

```
UCLASS
    ↓
控制“整个类”如何进入 UE 系统
```

即可。官方完整 Class Specifier 列表也就是围绕 Engine / Editor 如何处理该类展开。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/class-specifiers?utm_source=chatgpt.com)

---

# 七、UPROPERTY

这是 UE C++ 最常遇到的宏之一。

例如：

```
UPROPERTY(EditAnywhere)
float Damage;
```

本质：

```
把 Damage 注册成 UE Reflection Property
```

之后 UE 才可以根据 Specifier 决定：

```
编辑器是否显示
Blueprint 是否能访问
是否网络复制
是否保存
对象引用是否参与 GC
……
```

属性 Specifier 正是用来控制属性如何与 Engine 和 Editor 交互。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-uproperties)

---

## 最值得先掌握的 UPROPERTY

### EditAnywhere

```
UPROPERTY(EditAnywhere)
float Damage;
```

可以在：

```
Blueprint 默认值
+
场景实例 Details
```

修改。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-uproperties)

---

### VisibleAnywhere

```
UPROPERTY(VisibleAnywhere)
TObjectPtr<UStaticMeshComponent> Mesh;
```

能看到，但是不能直接修改这个属性引用。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-uproperties)

组件经常这样写。

---

### BlueprintReadOnly

```
UPROPERTY(BlueprintReadOnly)
float HP;
```

Blueprint：

```
能读
不能写
```

---

### BlueprintReadWrite

```
UPROPERTY(BlueprintReadWrite)
float HP;
```

Blueprint：

````
能读
能写
``` citeturn435653view2


---

### 常见组合

```cpp
UPROPERTY(EditAnywhere, BlueprintReadWrite,
          Category="Combat")
float Damage = 20.f;
````

分别解决：

```
EditAnywhere
     ↓
Editor 能不能改

BlueprintReadWrite
     ↓
Blueprint 能不能访问

Category
     ↓
编辑器放在哪个分类
```

这是非常重要的理解：

> `EditAnywhere` 和 `BlueprintReadWrite` **不是同一个维度**。

# 八、UFUNCTION

普通函数：

```
void Attack();
```

UE 反射函数：

```
UFUNCTION()
void Attack();
```

Epic 对 UFunction 的定义非常直接：

> 一个被 Unreal Engine Reflection System 识别的 C++ 函数。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/ufunctions-in-unreal-engine)

---

## 最常见的几个

### BlueprintCallable

```
UFUNCTION(BlueprintCallable)
void Attack();
```

Blueprint 可以调用它。

---

### BlueprintPure

比如：

```
UFUNCTION(BlueprintPure)
float GetHealth() const;
```

通常用于：

```
查询数据
不修改对象状态
```

Blueprint 中表现为 Pure Node。

---

### BlueprintImplementableEvent

```
UFUNCTION(BlueprintImplementableEvent)
void OnDeath();
```

意思大概是：

```
C++：
我定义这个事件

Blueprint：
你负责实现
```

---

### BlueprintNativeEvent

```
UFUNCTION(BlueprintNativeEvent)
void Attack();
```

C++ 可以提供默认实现：

```
void ACharacter::Attack_Implementation()
{
}
```

Blueprint 还可以覆盖。

Epic 官方也明确区分 `BlueprintImplementableEvent` 与 `BlueprintNativeEvent`：前者主要交由蓝图实现，后者允许 C++ 默认实现并由蓝图覆盖。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/coding-in-unreal-engine-blueprint-vs-cplusplus?utm_source=chatgpt.com)

---

# 九、Reflection：反射系统到底是什么？

这是前面所有东西真正的核心。

普通 C++：

```
class Player
{
    int HP;
};
```

运行时主要只剩：

```
对象内存
机器代码
```

但 UE 希望运行过程中能够知道：

```
这个对象是什么类？

这个类有哪些属性？

HP 是什么类型？

Attack 是什么函数？

这个 Property 能不能在 Editor 编辑？

这个函数是不是 BlueprintCallable？
```

于是 UE 建立：

```
Reflection System
```

---

## 可以这样理解 Reflection

假设：

```
UCLASS()
class APlayerCharacter : public ACharacter
{
    GENERATED_BODY()

public:

    UPROPERTY(EditAnywhere)
    float MaxHealth;

    UFUNCTION(BlueprintCallable)
    void Attack();
};
```

除了真正的数据：

```
Player对象
┌──────────────┐
│ MaxHealth=100│
└──────────────┘
```

UE 还会有关于类型的描述信息：

```
UClass : APlayerCharacter
│
├── Property
│      MaxHealth
│      类型 = float
│      EditAnywhere
│
└── UFunction
       Attack
       BlueprintCallable
```

所以：

> **反射不是保存对象的数据本身，而是让运行时拥有描述这些类型、属性和函数的信息。**

---

# 十、反射到底有什么用？

它是很多 UE 功能的底座：

```
                 Reflection
                     │
       ┌─────────────┼─────────────┐
       ▼             ▼             ▼
     Editor       Blueprint    Serialization
       │
       ▼
 Details Panel
       │
       ├──────────► Network Replication
       │
       └──────────► GC 对象引用追踪
```

例如：

```
UPROPERTY(EditAnywhere)
float Damage;
```

为什么 Details 能自动出现：

```
Damage    [ 20.0 ]
```

因为 Editor 能读取反射属性信息。

类似地，UFunction 可以被暴露给 Blueprint，反射属性可以带有网络复制、序列化等行为。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-uproperties)

# 十一、那 Reflection 信息从哪里来的？

答案就是：

# UHT

全名：

```
Unreal Header Tool
```

这是理解 UE 编译系统最关键的一环。

Epic 官方定义：

> UHT 是专门为 UObject 系统服务的 C++ 解析和代码生成工具。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-header-tool-for-unreal-engine)

# 十二、为什么需要 UHT？

因为：

```
UCLASS()

UPROPERTY()

UFUNCTION()
```

这些东西并不是标准 C++ 自带的反射系统。

所以 Epic 写了一个工具扫描你的 `.h`。

大体流程：

```
Player.h
   │
   ▼
UHT
   │
   ├──发现 UCLASS
   ├──发现 UPROPERTY
   ├──发现 UFUNCTION
   │
   ▼
生成 UObject 系统需要的代码
   │
   ▼
C++ Compiler
```

官方给出的构建顺序正是：

````
UBT
 ↓
调用 UHT
 ↓
解析 C++ Header
 ↓
生成 UObject 相关代码
 ↓
UBT 调用 C++ Compiler

# 十三、为什么 UE 头文件有 `.generated.h`？

你会经常看到：

```cpp
#include "CoreMinimal.h"
#include "GameFramework/Actor.h"

#include "MyCharacter.generated.h"
````

这个：

```
MyCharacter.generated.h
```

就是 UE 生成代码的一部分。

因此：

```
#include "MyCharacter.generated.h"
```

必须放在当前头文件 include 区域的**最后一个 include**。Epic 官方 UObject 文档对此有明确要求。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/objects-in-unreal-engine)

所以：

```
#include "MyCharacter.generated.h"

#include "Weapon.h"   // ❌
```

就可能被 UHT 报错。

正确：

```
#include "Weapon.h"
#include "MyCharacter.generated.h"
```

# 十四、GENERATED_BODY() 是什么？

看到：

```
UCLASS()
class APlayerCharacter : public ACharacter
{
    GENERATED_BODY()
};
```

不要把：

```
GENERATED_BODY()
```

理解成装饰品。

它把 UHT 生成的一部分基础设施放进你的类定义中，让这个类型正确接入 UObject 系统。官方文档称它用于设置 Engine 所要求的 infrastructure。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/objects-in-unreal-engine)

第一阶段不需要展开所有宏源码。

知道：

```
UCLASS
   ↓
UHT 识别类

GENERATED_BODY
   ↓
把生成代码接回这个类
```

就够了。

Unreal Build Tool
```

UHT ≠ UBT

负责：

Build Process

# 十六、`.Build.cs` 为什么存在？

例如：

```
PublicDependencyModuleNames.AddRange(
    new string[]
    {
        "Core",
        "CoreUObject",
        "Engine",
        "InputCore"
    }
);
```

这是：

```
UBT Module Rules
```

意思是：

> 我的 Module 依赖哪些 UE Module。

UE 本身就是由大量 Module 构成的；官方文档也明确指出每个 Module 都有自己的 `.Build.cs`，用于定义依赖、库和 Include Path 等构建规则。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-build-tool-in-unreal-engine)

因此以后遇到：

```
明明 include 了头文件
为什么 Link Error？
```

经常就要检查：

```
XXX.Build.cs
```

# 十七、Target.cs 是干什么的？

可以简单区分：

```
Build.cs
    ↓
一个 Module 怎么编译

Target.cs
    ↓
我要构建什么目标
```

例如：

```
Game
Editor
Client
Server
```

这些都是 UBT Target。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-engine-build-tool-target-reference?utm_source=chatgpt.com)

因此：

```
MyGame.Build.cs
MyGame.Target.cs
MyGameEditor.Target.cs
```

不是一回事。

# 十八、现在进入生命周期核心：GC

GC：

```
Garbage Collection
垃圾回收
```

UE 的 GC 主要解决：

```
UObject 生命周期
```

而不是所有 C++ 内存。

Epic 当前文档描述 UE 的 UObject GC 会从 Root Set 出发构建/遍历引用关系，无法从根引用图到达的 UObject 会被认为已经不再需要。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-object-handling-in-unreal-engine)

可以简化为：

```
                Root
                 │
       ┌─────────┴─────────┐
       ▼                   ▼
     Object A            Object B
       │
       ▼
     Object C


Object D
   ↑
没人引用

      ↓ GC

Object D 被回收
```

---

# 十九、GC 与 UPROPERTY 的关系

比如：

```
UPROPERTY()
TObjectPtr<UWeapon> Weapon;
```

这是一个：

```
GC 可以追踪的强引用
```

只要：

```
当前对象活着
   ↓
Weapon 引用存在
   ↓
UWeapon 可达
```

GC 就不会把 Weapon 当垃圾处理。

当前 Epic Object Pointer 文档明确说明：被 `UPROPERTY` 标记的 `TObjectPtr` 是影响 GC 的强引用，会阻止目标对象被 GC。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/object-pointers-in-unreal-engine)

---

# 二十、GC 最容易产生的误解

不要记成：

> “只要对象是 UObject，它永远不会有悬空问题。”

错误。

正确思想：

```
UObject 生命周期
       ↓
由 UE GC 管理

但：
       ↓
你的引用方式仍然很重要
```

因此 UE5 代码里经常看到：

```
UPROPERTY()
TObjectPtr<UWeapon> Weapon;
```

而不是随便保存裸指针。

# 二十一、Actor 为什么调用 Destroy，而不是 delete？

例如：

```
Enemy->Destroy();
```

不要：

```
delete Enemy; // ❌
```

Actor 属于 UE 对象生命周期体系；Epic 官方文档指出运行中的 Actor 标准移除方式就是调用 `Destroy()`，ActorComponents 则可调用 `DestroyComponent()`。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-object-handling-in-unreal-engine)

记：

```
普通 C++ Object
       → delete / RAII

UObject
       → GC

AActor
       → Destroy()
          ↓
       后续由 UE 完成生命周期处理
```

---

# 二十二、UE Smart Pointer：这里必须分成两个世界

这是特别重要的面试点。

很多初学者看到：

```
TSharedPtr
TWeakPtr
TUniquePtr
```

于是想：

```
TSharedPtr<UObject>
```

通常这是错误思路。

Epic 官方明确说明：

> Unreal Smart Pointer Library 的 `TSharedPtr/TWeakPtr/TUniquePtr/TSharedRef` **不能用于 UObject 生命周期管理**；UObject 使用独立的对象追踪与 GC 系统。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/smart-pointers-in-unreal-engine)

因此必须画一条线：

```
              UE Pointer
                  │
       ┌──────────┴──────────┐
       ▼                     ▼

普通 C++ 对象            UObject
       │                     │
       ▼                     ▼
TSharedPtr              TObjectPtr
TWeakPtr                TWeakObjectPtr

# 二十三、TSharedPtr

类似：

# 二十五、TWeakPtr

它观察：

```cpp

````

管理的对象。

# 二十八、TSoftObjectPtr

这是 UE 游戏开发很重要的 Asset Reference。

例如：

```

   ↓

   ↓

# 三十二、TMap

```

Attributes.Add(TEXT("Health"), 100);
Attributes.Add(TEXT("Mana"), 50);
```

逻辑：

```
Key          Value

Health   →   100
Mana     →    50
```

TMap 基于 Key 哈希查找，默认 Key 唯一；Key 类型需要支持相等比较以及相应 Hash。[Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/map-containers-in-unreal-engine)

常用：

```

Map.Find(Key);

Map.Contains(Key);

Map.Remove(Key);
```

特别注意：

```
Value* Ptr = Map.Find(Key);
```

通常返回：

```
找到      → Value*
没找到    → nullptr
```

所以：

```
if (int32* Value = Map.Find(Key))
{
    UE_LOG(LogTemp, Warning, TEXT("%d"), *Value);
}
```

是 UE 很常见的写法。

# 四十五、现在把全部知识串成一个真正 UE 类

以后你看到这样的代码：

```
UCLASS()

    GENERATED_BODY()

public:

    AEnemy();

protected:

    virtual void BeginPlay() override;

    UPROPERTY(VisibleAnywhere)

# 四十六、这一层最重要的 10 句话

如果最后要压缩成面试前复习版，我建议记住这十句：

1. **UObject 是 UE 对象系统的核心基础，提供了普通 C++ 类没有直接拥有的反射、GC 等 Engine 集成能力。**
2. **UCLASS / UPROPERTY / UFUNCTION 是把 C++ 类型和成员暴露给 UE Reflection System 的入口。**
3. **UClass 是 UE 在运行时对一个类的反射描述。**
4. **UHT 负责解析 UE Header 元数据并生成 UObject 相关代码。**
5. **UBT 负责组织整个 UE Build Process，并在编译流程中调用 UHT 和 C++ Compiler。**
6. **UObject 生命周期主要由 GC 管理，Actor 一般使用 Destroy，而不是直接 delete。**
7. **`TSharedPtr/TWeakPtr/TUniquePtr` 主要管理普通 C++ 对象，不用于 UObject 的 GC 生命周期。**
8. **现代 UObject 成员引用重点掌握 `TObjectPtr / TWeakObjectPtr / TSoftObjectPtr`。**
9. **`TArray / TMap / TSet` 分别对应有序动态序列、Key-Value Hash 容器、唯一元素 Hash 容器的典型需求。**
10. **`FString` 用于字符串处理，`FName` 用于名字/标识，`FText` 用于面向玩家、支持本地化的文本；Delegate 用于事件通知和降低对象耦合。** [Epic Games Developers](https://dev.epicgames.com/documentation/unreal-engine/unreal-header-tool-for-unreal-engine)

## 第一层建议学习顺序

不要按照你原来的列表机械地一个个背，我建议真正学习时按下面走：

```
① UObject
    ↓
② UCLASS / GENERATED_BODY
    ↓
③ Reflection
    ↓
④ UPROPERTY / UFUNCTION
    ↓
⑤ UHT
    ↓
⑥ UBT / Build.cs / Target.cs
    ↓
⑦ GC
    ↓
⑧ UObject Pointer + UE Smart Pointer
    ↓
⑨ TArray / TMap / TSet
    ↓
⑩ FString / FName / FText
    ↓
⑪ Delegate
```

其中 **①～⑧是一整套“UE 对象系统”**，这是这一层最重要的部分；容器和字符串更多是 UE 版 C++ 基础设施；Delegate 则会在输入、碰撞、UI、GAS、异步回调、Gameplay Event 等地方反复出现。

如果以“能写 UE + 能回答校招面试”为标准，下一步最适合从 **`UObject` 单独开始深挖**：`UObject → UClass → CDO → Outer → NewObject → CreateDefaultSubobject → 生命周期 → Cast`。这一块搞懂以后，后面的 Reflection、GC 和 UPROPERTY 会明显容易很多。
