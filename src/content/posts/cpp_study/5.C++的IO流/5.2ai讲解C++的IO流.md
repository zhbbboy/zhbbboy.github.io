# C++ 的 I/O 流

I/O 是：

```text
Input / Output
输入 / 输出
```

C++ 的 I/O 流，就是用统一的“流”模型完成：

- 从键盘读取数据；
- 向屏幕输出数据；
- 读写文件；
- 在字符串中读写和格式化数据。

先记住核心定义：
> **流是一串按顺序流动的字符或字节。输入流把数据流入程序，输出流把数据从程序流出。**

---

# 一、什么是“流”？

假设程序执行：
```cpp
int age;
std::cin >> age;
```
数据流向是：
```text
键盘输入
   ↓
标准输入设备
   ↓
std::cin
   ↓
变量 age
```
这叫**输入流**。

再看：
```cpp
std::cout << age;
```
数据流向是：
```text
变量 age
   ↓
std::cout
   ↓
标准输出设备
   ↓
终端屏幕
```
这叫**输出流**。

所以可以记为：
```text
输入流：外部设备 → 程序
输出流：程序 → 外部设备
```
这里的“外部设备”不一定是键盘或显示器，也可能是：
```text
文件
字符串
网络连接
内存缓冲区
```

# 二、C++ I/O 流相关头文件

常见头文件：

|头文件|主要用途|
|---|---|
|`<iostream>`|标准输入输出|
|`<fstream>`|文件输入输出|
|`<sstream>`|字符串输入输出|
|`<iomanip>`|输出格式控制|
例如：
```cpp
#include <iostream>
#include <fstream>
#include <sstream>
#include <iomanip>
```

# 三、四个标准流对象
包含：
```cpp
#include <iostream>
```
后，可以使用四个常见全局流对象。
## 1. `std::cin`
标准输入流，类型是：
```cpp
std::istream
```
默认通常关联键盘输入：
```cpp
int age;
std::cin >> age;
```

---
## 2. `std::cout`
标准输出流，类型是：
```cpp
std::ostream
```
默认通常关联终端的标准输出：

```cpp
std::cout << "hello";
```

---
## 3. `std::cerr`
标准错误输出流，类型也是：
```cpp
std::ostream
```
通常用于输出错误信息：
```cpp
std::cerr << "文件打开失败\n";
```
`cerr` 默认设置了立即刷新相关属性，因此通常比普通 `cout` 更及时地显示错误信息。

---
## 4. `std::clog`
标准日志输出流：
```cpp
std::clog << "程序正在启动\n";
```
通常也关联标准错误设备，但更适合输出允许缓冲的日志信息。
可以简单记为：
```text
cin  ：标准输入
cout ：普通输出
cerr ：错误输出，强调及时显示
clog ：日志输出，通常允许缓冲
```

# 四、I/O 流的类体系
C++ 标准库不是只定义了四个对象，而是设计了一套流类体系。
可以先建立下面这个简化模型：
```text
ios_base
   ↓
basic_ios
   ├── basic_istream
   │       ↓
   │   basic_ifstream
   │
   ├── basic_ostream
   │       ↓
   │   basic_ofstream
   │
   └── basic_iostream
           ↓
       basic_fstream
```
常用名字其实是这些模板类针对 `char` 的类型别名：
```cpp
std::istream
std::ostream
std::iostream

std::ifstream
std::ofstream
std::fstream
```
例如：
```cpp
std::ostream
```
大致对应：
```cpp
std::basic_ostream<char>
```
标准库也提供宽字符流：
```cpp
std::wcin
std::wcout
std::wifstream
```
它们主要使用 `wchar_t`。

# 五、`<<` 和 `>>` 到底是什么？

很多初学者以为：
```cpp
std::cout << 10;
std::cin >> age;
```
中的 `<<` 和 `>>` 是普通位运算。
实际上，这里调用的是经过重载的运算符。

---

## 1. `operator<<`
对于输出流：
```cpp
std::cout << 10;
```
可以粗略理解为：
```cpp
std::cout.operator<<(10);
```
或者调用某个对应的非成员重载。
它的作用是：

1. 接收数值 `10`；
2. 把它格式化为字符；
3. 写入输出流。

---

## 2. `operator>>`
```cpp
std::cin >> age;
```
可以粗略理解为：
```cpp
std::cin.operator>>(age);
```
它的作用是：
1. 从输入流读取字符；
2. 按照 `age` 的类型进行解析；
3. 把结果保存进 `age`。

---
# 六、为什么可以连续写？
```cpp
std::cout << "age = " << age << '\n';
```
因为每次输出运算通常都会返回原来的流对象引用：
```cpp
std::ostream&
```
所以执行过程类似：
```cpp
((std::cout << "age = ") << age) << '\n';
```
第一步：
```cpp
std::cout << "age = "
```
输出后返回 `std::cout`。
然后继续：
```cpp
std::cout << age
```
再返回 `std::cout`。
输入也是同理：
```cpp
std::cin >> a >> b;
```
相当于：
```cpp
(std::cin >> a) >> b;
```

---
# 七、格式化输入与非格式化输入
C++ 输入操作可以分成两类：
```text
格式化输入
非格式化输入
```

---
## 1. 格式化输入：`operator>>`
例如：
```cpp
int age;
double height;

std::cin >> age >> height;
```
`operator>>` 会根据目标变量类型解析数据。
如果输入：
```text
18 1.75
```
编译器运行时会分别读取：
```text
18   → int
1.75 → double
```
格式化输入对于大多数类型，默认会跳过前导空白字符，例如：
```text
空格
换行
Tab
```
所以：
```cpp
std::string name;
std::cin >> name;
```
如果输入：
```text
Zhang San
```
`name` 通常只会得到：
```text
Zhang
```
因为 `>>` 读取字符串时，遇到空白字符就停止。

---

## 2. 非格式化输入：`getline`
如果需要读取整行，包括空格，应使用：
```cpp
std::string name;
std::getline(std::cin, name);
```
输入：
```text
Zhang San
```
会完整得到：
```text
Zhang San
```

---
# 八、`cin >>` 和 `getline` 连用的坑
下面代码非常常见：
```cpp
int age;
std::string name;

std::cin >> age;
std::getline(std::cin, name);
```
假设输入：
```text
18
Zhang San
```
`cin >> age` 读取了数字 `18`，但是按回车产生的换行符通常还留在输入缓冲区中。
接下来：
```cpp
std::getline(std::cin, name);
```
立即读取到这个换行符，于是得到一个空字符串。

---
## 解决方法一：使用 `ignore`
```cpp
#include <limits>

std::cin >> age;

std::cin.ignore(
    std::numeric_limits<std::streamsize>::max(),
    '\n'
);

std::getline(std::cin, name);
```
这表示忽略当前行剩余内容，直到遇到换行符。

---
## 解决方法二：使用 `std::ws`
```cpp
std::cin >> age;
std::getline(std::cin >> std::ws, name);
```
`std::ws` 会先跳过前导空白字符，再由 `getline` 读取。
但需要注意：它会跳过所有前导空白，包括本来可能有意义的行首空格。

---
# 九、输入流的状态
输入操作并不一定成功。
例如：
```cpp
int number;
std::cin >> number;
```
如果用户输入：
```text
abc
```
无法把 `abc` 解析为 `int`，流会进入失败状态。
C++ 流对象内部维护若干状态位：

|状态|含义|
|---|---|
|`goodbit`|没有错误|
|`eofbit`|到达文件末尾|
|`failbit`|格式解析失败等可恢复错误|
|`badbit`|严重底层 I/O 错误|

---

## 常见状态检查函数
```cpp
stream.good();
stream.eof();
stream.fail();
stream.bad();
```
例如：
```cpp
int number;
if (std::cin >> number)
{
    std::cout << "输入成功：" << number << '\n';
}
else
{
    std::cout << "输入失败\n";
}
```
为什么可以直接写：
```cpp
if (std::cin >> number)
```

因为流对象可以在条件判断中转换成表示操作是否成功的状态。

---
# 十、输入失败后如何恢复？
例如：
```cpp
int number;
std::cin >> number;
```
用户输入：
```text
abc
```
此时：
1. `cin` 设置 `failbit`；
2. 错误字符通常还留在缓冲区；
3. 后续读取也会继续失败。

正确恢复：
```cpp
#include <iostream>
#include <limits>

int main()
{
    int number;

    while (!(std::cin >> number))
    {
        std::cout << "请输入整数：";

        std::cin.clear();

        std::cin.ignore(
            std::numeric_limits<std::streamsize>::max(),
            '\n'
        );
    }

    std::cout << "输入成功：" << number << '\n';
}
```
其中：
```cpp
std::cin.clear();
```
用于清除错误状态。
而：
```cpp
std::cin.ignore(...);
```
用于清除输入缓冲区中的错误数据。
只写 `clear()` 通常还不够，因为错误字符可能仍然存在。

---
# 十一、什么是 I/O 缓冲区？
如果每次执行：
```cpp
std::cout << 'A';
```
都立即请求操作系统向终端写一个字符，开销会很大。
所以标准流通常使用缓冲区：
```text
程序写入数据
    ↓
流缓冲区
    ↓ 满足刷新条件
操作系统
    ↓
终端或文件
```
程序先把数据写入内存中的缓冲区，积累到一定程度后再统一输出，提高效率。

---
# 十二、什么时候会刷新输出缓冲区？
常见情况包括：

1. 缓冲区已满；
2. 程序正常结束；
3. 手动调用 `flush`；
4. 使用 `std::endl`；
5. 某些输入操作前，和输入流绑定的输出流被刷新；
6. 对设置了 `unitbuf` 的流进行输出，例如默认的 `cerr`。

---
# 十三、`\n`、`std::endl` 和 `std::flush`

## 1. `'\n'`
```cpp
std::cout << "hello\n";
```
只插入换行字符，通常不会强制刷新缓冲区。

---
## 2. `std::endl`
```cpp
std::cout << "hello" << std::endl;
```
会做两件事：
```text
插入换行符
+
刷新输出缓冲区
```
大致相当于：
```cpp
std::cout << '\n' << std::flush;
```

---
## 3. `std::flush`
```cpp
std::cout << "loading..." << std::flush;
```
只刷新缓冲区，不换行。

---
## 应该使用哪个？
普通输出一般推荐：
```cpp
std::cout << "hello\n";
```
只有确实需要立即显示时再使用：
```cpp
std::endl
std::flush
```
例如：
```cpp
std::cout << "请输入密码：" << std::flush;
```

如果在循环中频繁使用 `std::endl`，会因反复刷新缓冲区而影响性能。

---
# 十四、`cin` 为什么会让提示信息及时显示？

默认情况下，`std::cin` 通常与 `std::cout` 绑定：
```cpp
std::cin.tie() == &std::cout
```
这意味着执行输入操作前，通常会先刷新 `cout`。
例如：
```cpp
std::cout << "请输入数字：";
std::cin >> number;
```
即使没有写：
```cpp
std::flush
```
提示语通常也能在等待输入前显示出来，因为读取 `cin` 前会刷新它绑定的 `cout`。
可以解除绑定：
```cpp
std::cin.tie(nullptr);
```
这有时用于提高大量输入输出的性能，但之后提示输出可能不会自动及时刷新。

---
# 十五、关闭 C 和 C++ I/O 同步

竞赛代码中经常出现：
```cpp
std::ios::sync_with_stdio(false);
std::cin.tie(nullptr);
```
## `sync_with_stdio(false)`
默认情况下，C++ 标准流会与 C 标准 I/O 保持一定同步：
```cpp
std::cout
printf

std::cin
scanf
```
关闭同步后，C++ 流通常会更快。
但是随后不建议随意混用：
```cpp
std::cout
printf
```
否则输出顺序可能不符合预期。

---
## `cin.tie(nullptr)`
解除 `cin` 和 `cout` 的绑定，避免每次输入前自动刷新 `cout`。
常见高性能输入写法：
```cpp
int main()
{
    std::ios::sync_with_stdio(false);
    std::cin.tie(nullptr);

    // 大量输入输出
}
```
在普通业务代码中，不需要无脑添加，理解其含义更重要。

# 十六、输出格式控制
可以通过 `<iomanip>` 控制输出格式。
```cpp
#include <iomanip>
```

---
## 1. 小数位数
```cpp
double value = 3.1415926;

std::cout << std::fixed
```

输出：
```text

```
注意：

```cpp
std::cout << std::setw(10) << 123;
```

设置下一个输出项的字段宽度。
`setw` 通常只影响紧接着的一个输出项：
```cpp
std::cout << std::setw(10) << 123

```

---
## 3. 填充字符

```cpp
std::cout << std::setfill('0')
```

输出：
```text
00042
```

## 4. 进制转换

```cpp
int value = 255;

std::cout << std::dec << value << '\n';

```
输出：
```text
255
ff
377
```

## 5. 布尔值

```cpp

```
输出：
```text

```

```cpp

```
输出：
```text

```

```cpp
std::noboolalpha
```

# 十七、文件流
包含：
```cpp
#include <fstream>
```
常见文件流：

|类型|用途|
|---|---|
|`std::ifstream`|读取文件|
|`std::ofstream`|写入文件|
|`std::fstream`|同时读写文件|

---
## 1. 写文件
```cpp
#include <fstream>
#include <iostream>

int main()
{
    std::ofstream file("data.txt");

    if (!file)
    {
        std::cerr << "文件打开失败\n";
        return 1;
    }

    file << "hello\n";
    file << 100 << '\n';

    return 0;
}
```
`ofstream` 对象离开作用域时会自动关闭文件，这体现了 RAII。
也可以显式：
```cpp
file.close();
```
但多数情况下没有必要手动调用。

---
## 2. 读文件
```cpp
#include <fstream>
#include <iostream>
#include <string>

int main()
{
    std::ifstream file("data.txt");

    if (!file)
    {
        std::cerr << "文件打开失败\n";
        return 1;
    }

    std::string line;

    while (std::getline(file, line))
    {
        std::cout << line << '\n';
    }
}
```
推荐循环条件：
```cpp
while (std::getline(file, line))
```
不推荐：
```cpp
while (!file.eof())
```
因为 `eof()` 通常是在一次读取失败并确认到达文件末尾之后才设置，容易造成最后一行重复处理或无效处理。

---
# 十八、文件打开模式
常见模式：

|模式|含义|
|---|---|
|`std::ios::in`|读取|
|`std::ios::out`|写入|
|`std::ios::app`|每次写入都追加到文件末尾|
|`std::ios::ate`|打开后初始位置在文件末尾|
|`std::ios::trunc`|清空原文件内容|
|`std::ios::binary`|二进制模式|

例如追加写入：
```cpp
std::ofstream file(
    "log.txt",
    std::ios::out | std::ios::app
);
```
`app` 和 `ate` 不完全相同：
```text
app：每一次写操作都在末尾
ate：打开时先定位到末尾，之后可以移动位置
```

# 十九、文本文件和二进制文件
## 文本方式
```cpp
std::ofstream file("data.txt");
file << 123;
```
写入的是字符：
```text
'1' '2' '3'
```

---
## 二进制方式
```cpp
std::ofstream file(
    "data.bin",
    std::ios::binary
);

int value = 123;

file.write(
    reinterpret_cast<const char*>(&value),
    sizeof(value)
);
```
读取：
```cpp
std::ifstream file(
    "data.bin",
    std::ios::binary
);

int value;

file.read(
    reinterpret_cast<char*>(&value),
    sizeof(value)
);
```
二进制直接写对象内存时需要谨慎，因为可能受到：

- 字节序；
- 内存对齐；
- 填充字节；
- 类型大小；
- 编译器和平台；
- 指针成员；
- 虚函数表；
- 非平凡对象内部结构
的影响。

因此不能随便把任意 C++ 类直接 `write` 到文件。

# 二十、字符串流
包含：
```cpp
#include <sstream>
```
主要类型：

|类型|用途|
|---|---|
|`std::istringstream`|从字符串读取|
|`std::ostringstream`|向字符串写入|
|`std::stringstream`|同时读写字符串|

---
## 1. 将数据格式化成字符串
```cpp
#include <sstream>
#include <string>

int age = 20;
double height = 1.75;

std::ostringstream oss;

oss << "age=" << age
    << ", height=" << height;

std::string result = oss.str();
```

---
## 2. 从字符串中解析数据
```cpp
std::string text = "10 3.14 hello";

std::istringstream iss(text);

int a;
double b;
std::string c;

iss >> a >> b >> c;
```
得到：
```text
a = 10
b = 3.14
c = "hello"
```

字符串流常用于：
- 解析配置文本；
- 日志格式化；
- 类型转换；
- 分割一行中的字段；
- 测试输入输出代码。

# 二十一、底层的 `streambuf`
`cin`、`cout` 本身主要负责：
```text
格式化
状态管理
类型转换
```
真正和底层字符序列交互的核心对象叫：
```cpp
std::streambuf
```
可以通过：
```cpp
std::cout.rdbuf()
```
取得 `cout` 关联的流缓冲区。

简化理解：
```text
ostream / istream
负责高层格式化和状态

streambuf
负责底层字符缓冲与读写
```
例如输出：
```cpp
std::cout << 123;
```
大致经历：
```text
整数 123
   ↓
operator<< 将它格式化
   ↓
字符 '1' '2' '3'
   ↓
写入 streambuf
   ↓
缓冲区刷新
   ↓
操作系统标准输出
```
输入过程反过来：
```text
键盘字符
   ↓
操作系统
   ↓
streambuf
   ↓
operator>> 解析字符
   ↓
生成 int/double/string 等对象
```

---
# 二十二、自定义类型如何支持 I/O？
可以重载 `operator<<`：
```cpp
#include <iostream>
#include <string>

class Player
{
private:
    std::string name;
    int level;

public:
    Player(std::string name, int level)
        : name(std::move(name)),
          level(level)
    {
    }

    friend std::ostream& operator<<(
        std::ostream& out,
        const Player& player)
    {
        out << "Player{name="
            << player.name
            << ", level="
            << player.level
            << '}';

        return out;
    }
};
```
使用：
```cpp
Player player("Alice", 10);

std::cout << player << '\n';
```
注意返回：
```cpp
std::ostream&
```
这样才能继续链式输出：
```cpp
std::cout << player << " finished\n";
```
输入运算符类似：
```cpp
friend std::istream& operator>>(
    std::istream& in,
    Player& player)
{
    in >> player.name >> player.level;
    return in;
}
```

# 二十三、常见错误

## 1. 用 `cin >> string` 读取带空格文本
```cpp
std::string name;
std::cin >> name;
```
遇到空格停止。

需要整行时使用：
```cpp
std::getline(std::cin, name);
```

---
## 2. `cin >>` 后直接 `getline`

需要处理残留换行符：
```cpp
std::cin.ignore(...);
```
或者根据场景使用：
```cpp
std::ws
```

---
## 3. 输入失败后只调用 `clear`
```cpp
std::cin.clear();
```
只恢复状态，不会自动删除错误字符。
通常还需要：
```cpp
std::cin.ignore(...);
```

---
## 4. 使用 `while (!file.eof())`
错误模式：
```cpp
while (!file.eof())
{
    std::getline(file, line);
    // 处理 line
}
```

推荐：
```cpp
while (std::getline(file, line))
{
    // 处理 line
}
```

---
## 5. 滥用 `std::endl`
```cpp
for (...)
{
    std::cout << value << std::endl;
}
```
每次都刷新，可能降低性能。
普通换行优先：
```cpp
std::cout << value << '\n';
```

---
## 6. 关闭同步后混用 C 和 C++ I/O
```cpp
std::ios::sync_with_stdio(false);

std::cout << "A";
printf("B");
```
输出顺序可能不符合直觉。
关闭同步后尽量统一使用一种 I/O 系统。

# 二十四、I/O 流和 RAII
文件流是 RAII 的典型应用：
```cpp
void Save()
{
    std::ofstream file("data.txt");

    file << "hello";
}
```
执行过程：
```text
ofstream 构造
    ↓
打开文件

离开作用域
    ↓
ofstream 析构
    ↓
刷新缓冲区并关闭文件
```
即使函数中途：
```cpp
return;
```
或者抛出异常，局部文件流对象的析构函数通常仍会被调用，文件资源得到释放。
这比手动管理文件句柄更安全。

# 二十五、面试回答版本

面试官问：

> 什么是 C++ I/O 流？

可以这样回答：

C++ I/O 流是一套基于流抽象的输入输出机制。流可以理解为有序的字符或字节序列，输入流把数据从外部设备读入程序，输出流把程序数据写到外部设备。

`std::cin` 是标准输入流对象，类型是 `std::istream`；`std::cout`、`std::cerr` 和 `std::clog` 是输出流对象，类型是 `std::ostream`。`operator>>` 负责格式化输入，`operator<<` 负责格式化输出，并返回流对象引用，因此支持链式操作。

C++ 流对象还维护 `goodbit`、`eofbit`、`failbit` 和 `badbit` 等状态。输入失败后通常需要调用 `clear()` 恢复状态，并使用 `ignore()` 清除错误输入。
![](../../_Pasted_Image/Pasted%20image%2020260728211944.png)

标准库还提供 `ifstream/ofstream/fstream` 进行文件读写，以及 `istringstream/ostringstream/stringstream` 进行字符串流操作。流内部通常通过 `streambuf` 管理字符缓冲和底层设备交互，文件流利用 RAII 在析构时自动关闭文件。

# 二十六、你最需要记住的主线
```text
I/O 流
├── 标准流
│   ├── cin
│   ├── cout
│   ├── cerr
│   └── clog
│
├── 文件流
│   ├── ifstream
│   ├── ofstream
│   └── fstream
│
└── 字符串流
    ├── istringstream
    ├── ostringstream
    └── stringstream
```

核心结论：
```text
1. 流是有序的字符或字节序列。
2. cin 是输入流，cout 是输出流。
3. << 和 >> 是重载运算符。
4. 流运算返回流引用，因此可以链式调用。
5. cin >> 默认按类型解析并跳过前导空白。
6. getline 用来读取整行。
7. 流具有错误状态，需要用 clear 和 ignore 恢复。
8. \n 只换行，endl 还会刷新缓冲区。
9. 文件流和字符串流使用同一套流接口。
10. streambuf 负责底层字符缓冲和设备交互。
```

最核心的一句话：
> **C++ I/O 流把键盘、屏幕、文件和字符串统一抽象成字符流，程序通过同一套 `>>`、`<<` 和状态管理接口完成输入输出。**
