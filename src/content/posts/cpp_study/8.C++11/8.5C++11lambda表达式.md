# 🐉版
## lambda表达式

### lambda表达式概念
lambda表达式是一个匿名函数，恰当使用lambda表达式可以让代码变得简洁，并且可以提高代码的可读性。

举个例子
商品类 Goods的定义如下：
```cpp
struct Goods
{
	string _name;  //名字
	double _price; //价格
	int _num;      //数量
};
```

现在要对若干商品分别按照价格和数量进行升序、降序排序。
- 要对一个数据集合中的元素进行排序，可以使用sort函数，但由于这里待排序的元素为自定义类型，因此需要用户自行定义排序时的比较规则。
- 要控制sort函数的比较方式常见的有两种方法，一种是对商品类的的`()`运算符进行重载，另一种是通过仿函数来指定比较的方式。
- 显然通过重载商品类的`()`运算符是不可行的，因为这里要求分别按照价格和数量进行升序、降序排序，每次排序就去修改一下比较方式是很笨的做法。

所以这里选择传入仿函数来指定排序时的比较方式。比如：
```cpp
struct ComparePriceLess
{
	bool operator()(const Goods& g1, const Goods& g2)
	{
		return g1._price < g2._price;
	}
};
struct ComparePriceGreater
{
	bool operator()(const Goods& g1, const Goods& g2)
	{
		return g1._price > g2._price;
	}
};
struct CompareNumLess
{
	bool operator()(const Goods& g1, const Goods& g2)
	{
		return g1._num < g2._num;
	}
};
struct CompareNumGreater
{
	bool operator()(const Goods& g1, const Goods& g2)
	{
		return g1._num > g2._num;
	}
};
int main()
{
	vector<Goods> v = { { "苹果", 2.1, 300 }, { "香蕉", 3.3, 100 }, { "橙子", 2.2, 1000 }, { "菠萝", 1.5, 1 } };
	sort(v.begin(), v.end(), ComparePriceLess());    //按价格升序排序
	sort(v.begin(), v.end(), ComparePriceGreater()); //按价格降序排序
	sort(v.begin(), v.end(), CompareNumLess());      //按数量升序排序
	sort(v.begin(), v.end(), CompareNumGreater());   //按数量降序排序
	return 0;
}
```
仿函数确实能够解决这里的问题，但可能仿函数的定义位置可能和使用仿函数的地方隔得比较远，这就要求仿函数的命名必须要通俗易懂，否则会降低代码的可读性。

对于这种场景就比较适合使用lambda表达式。比如：
```cpp
int main()
{
	vector<Goods> v = { { "苹果", 2.1, 300 }, { "香蕉", 3.3, 100 }, { "橙子", 2.2, 1000 }, { "菠萝", 1.5, 1 } };
	sort(v.begin(), v.end(), [](const Goods& g1, const Goods& g2)
	{
		return g1._price < g2._price; 
	}); //按价格升序排序
	sort(v.begin(), v.end(), [](const Goods& g1, const Goods& g2)
	{
		return g1._price > g2._price;
	}); //按价格降序排序
	sort(v.begin(), v.end(), [](const Goods& g1, const Goods& g2)
	{
		return g1._num < g2._num;
	}); //按数量升序排序
	sort(v.begin(), v.end(), [](const Goods& g1, const Goods& g2)
	{
		return g1._num > g2._num;
	}); //按数量降序排序
	return 0;
}
```
这样一来，每次调用sort函数时只需要传入一个lambda表达式指明比较方式即可，阅读代码的人一看到lambda表达式就知道本次排序的比较方式是怎样的，提高了代码的可读性。

### lambda表达式语法
lambda表达式书写格式：`[capture-list](parameters)mutable->return-type{statement}`
```
lambda表达式各部分说明
```
- `[capture-list]`：捕捉列表。该列表总是出现在lambda函数的开始位置，编译器根据`[]`来判断接下来的代码是否为lambda函数，捕捉列表能够捕捉上下文中的变量供lambda函数使用。
- `(parameters)`：参数列表。与普通函数的参数列表一致，如果不需要参数传递，则可以连同`()`一起省略。
- `mutable`：默认情况下，lambda函数总是一个const函数，`mutable`可以取消其常量性。使用该修饰符时，参数列表不可省略（即使参数为空）。
- `->return-type`：返回值类型。用追踪返回类型形式声明函数的返回值类型，没有返回值时此部分可以省略。返回值类型明确情况下,也可省略，由编译器对返回类型进行推导。
- `{statement}`：函数体。在该函数体内，除了可以使用其参数外，还可以使用所有捕获到的变量。

lambda函数的参数列表和返回值类型都是可选部分，但捕捉列表和函数体是不可省略的，因此最简单的lambda函数如下：
```cpp
int main()
{
	[]{}; //最简单的lambda表达式
	return 0;
}
```
该lambda函数不能做任何事情。

```
捕获列表说明
```
捕获列表描述了上下文中哪些数据可以被lambda函数使用，以及使用的方式是传值还是传引用。
- `[var]`：表示值传递方式捕捉变量var。
- `[=]`：表示值传递方式捕获所有父作用域中的变量（成员函数包括this指针）。
- `[&var]`：表示引用传递捕捉变量var。
- `[&]`：表示引用传递捕捉所有父作用域中的变量（成员函数包括this指针）。
- `[this]`：表示值传递方式捕捉当前的this指针。

**说明一下：**
- 父作用域指的是包含lambda函数的语句块。
- 语法上捕捉列表可由多个捕捉项组成，并以逗号分割。比如`[=, &a, &b]`。
- 捕捉列表不允许变量重复传递，否则会导致编译错误。比如`[=, a]`重复传递了变量a。
- 在块作用域以外的lambda函数捕捉列表必须为空，即全局lambda函数的捕捉列表必须为空。
- 在块作用域中的lambda函数仅能捕捉父作用域中的局部变量，捕捉任何非此作用域或者非局部变量都会导致编译报错。
- lambda表达式之间不能相互赋值，即使看起来类型相同。

### lambda表达式交换两个数
如果要用lambda表达式交换两个数，可以有以下几种写法：
**标准写法**
参数列表中包含两个形参，表示需要交换的两个数，注意需要以引用的方式传递。比如：
```cpp
int main()
{
	int a = 10, b = 20;
	auto Swap = [](int& x, int& y)->void
	{
		int tmp = x;
		x = y;
		y = tmp;
	};
	Swap(a, b); //交换a和b
	return 0;
}
```
**说明一下：**
- lambda表达式是一个匿名函数，该函数无法直接调用，如果想要直接调用，可借助auto将其赋值给一个变量，此时这个变量就可以像普通函数一样使用。
- lambda表达式的函数体在格式上并不是必须写成一行，如果函数体太长可以进行换行，但换行后不要忘了函数体最后还有一个分号。

**利用捕捉列表进行捕捉**
以引用的方式捕捉所有父作用域中的变量，省略参数列表和返回值类型。比如：
```cpp
int main()
{
	int a = 10, b = 20;
	auto Swap = [&]
	{
		int tmp = a;
		a = b;
		b = tmp;
	};
	Swap(); //交换a和b
	return 0;
}
```
这样一来，调用lambda表达式时就不用传入参数了，但实际我们只需要用到变量a和变量b，没有必要把父作用域中的所有变量都进行捕捉，因此也可以只对父作用域中的a、b变量进行捕捉。比如：
```cpp
int main()
{
	int a = 10, b = 20;
	auto Swap = [&a, &b]
	{
		int tmp = a;
		a = b;
		b = tmp;
	};
	Swap(); //交换a和b
	return 0;
}
```
**说明一下：** 实际当我们以`[&]`或`[=]`的方式捕获变量时，编译器也不一定会把父作用域中所有的变量捕获进来，编译器可能只会对lambda表达式中用到的变量进行捕获，没有必要把用不到的变量也捕获进来，这个主要看编译器的具体实现。

**传值方式捕捉？**
如果以传值方式进行捕捉，那么首先编译不会通过，因为传值捕获到的变量默认是不可修改的，如果要取消其常量性，就需要在lambda表达式中加上mutable，并且此时参数列表不可省略。比如：
```cpp
int main()
{
	int a = 10, b = 20;
	auto Swap = [a, b]()mutable
	{
		int tmp = a;
		a = b;
		b = tmp;
	};
	Swap(); //交换a和b？
	return 0;
}
```
但由于这里是传值捕捉，lambda函数中对a和b的修改不会影响外面的a、b变量，与函数的传值传参是一个道理，因此这种方法无法完成两个数的交换。

### lambda表达式底层原理

**lambda表达式的底层原理**
实际编译器在底层对于lambda表达式的处理方式，完全就是按照函数对象的方式处理的。函数对象就是我们平常所说的仿函数，就是在类中对()运算符进行了重载的类对象。

下面编写了一个Add类，该类对()运算符进行了重载，因此Add类实例化出的add1对象就叫做函数对象，add1可以像函数一样使用。然后我们编写了一个lambda表达式，并借助auto将其赋值给add2对象，这时add1和add2都可以像普通函数一样使用。比如：
```cpp
class Add
{
public:
	Add(int base)
		:_base(base)
	{}
	int operator()(int num)
	{
		return _base + num;
	}
private:
	int _base;
};
int main()
{
	int base = 1;

	//函数对象
	Add add1(base);
	add1(1000);

	//lambda表达式
	auto add2 = [base](int num)->int
	{
		return base + num;
	};
	add2(1000);
	return 0;
}
```

调试代码并转到反汇编，可以看到：
- 在创建函数对象add1时，会调用Add类的构造函数。
- 在使用函数对象add1时，会调用Add类的`()`运算符重载函数。

- 借助auto将lambda表达式赋值给add2对象时，会调用`<lambda_uuid>`类的构造函数。
- 在使用add2对象时，会调用`<lambda_uuid>`类的`()`运算符重载函数。

本质就是因为lambda表达式在底层被转换成了仿函数。
- 当我们定义一个lambda表达式后，编译器会自动生成一个类，在该类中对`()`运算符进行重载，实际lambda函数体的实现就是这个仿函数的`operator()`的实现。
- 在调用lambda表达式时，参数列表和捕获列表的参数，最终都传递给了仿函数的`operator()`。

lambda表达式和范围for是类似的，它们在语法层面上看起来都很神奇，但实际范围for底层就是通过迭代器实现的，lambda表达式底层的处理方式和函数对象是一样的。

**lambda表达式之间不能相互赋值**
- 因为lambda表达式底层的处理方式和仿函数是一样的，在VS下，lambda表达式在底层会被处理为函数对象，该函数对象对应的类名叫做`<lambda_uuid>`。
- 类名中的uuid叫做通用唯一识别码（Universally Unique Identifier），简单来说，uuid就是通过算法生成一串字符串，保证在当前程序当中每次生成的uuid都不会重复。
- lambda表达式底层的类名包含uuid，这样就能保证每个lambda表达式底层类名都是唯一的。

因此每个lambda表达式的类型都是不同的，这也就是lambda表达式之间不能相互赋值的原因，我们可以通过`typeid(变量名).name()`的方式来获取lambda表达式的类型。比如：
```cpp
int main()
{
	int a = 10, b = 20;
	auto Swap1 = [](int& x, int& y)->void
	{
		int tmp = x;
		x = y;
		y = tmp;
	};
	auto Swap2 = [](int& x, int& y)->void
	{
		int tmp = x;
		x = y;
		y = tmp;
	};
	cout << typeid(Swap1).name() << endl; //class <lambda_797a0f7342ee38a60521450c0863d41f>
	cout << typeid(Swap2).name() << endl; //class <lambda_f7574cd5b805c37a13a7dc214d824b1f>
	return 0;
}
```
可以看到，就算是两个一模一样的lambda表达式，它们的类型都是不同的。

**说明一下：** 编译器只需要保证每个lambda表达式底层对应类的类名不同即可，并不是每个编译器都会将lambda表达式底层对应类的类名处理成<lambda_uuid>，这里只是以VS 为例。

# AI版C++11 Lambda 表达式

Lambda 表达式是 C++11 引入的重要特性，可以理解为：
> **在使用函数的地方，直接定义一个匿名的可调用对象。**

最简单的 Lambda：
```cpp
[]()
{
    std::cout << "Hello Lambda\n";
};
```
它定义了一个匿名函数，但没有调用。

可以立即调用：
```cpp
[]()
{
    std::cout << "Hello Lambda\n";
}();
```
也可以保存起来：
```cpp
auto print = []()
{
    std::cout << "Hello Lambda\n";
};

print();
```

Lambda 最常见的应用包括：
- STL 算法的比较器、谓词；
- 回调函数；
- 事件处理；
- 线程任务；
- 延迟执行；
- 临时封装一小段逻辑。

---
## 一、Lambda 的完整语法

常用完整形式是：
```cpp
[捕获列表](参数列表) mutable -> 返回类型
{
    函数体
};
```
例如：
```cpp
int base = 10;

auto add = [base](int value) mutable -> int
{
    base += value;
    return base;
};
```
各部分含义：
```text
[base]       捕获外部变量
(int value)  参数列表
mutable      允许修改按值捕获的副本
-> int       显式指定返回类型
{ ... }      函数体
```
并不是每个部分都必须写。

最常见形式：
```cpp
[](int a, int b)
{
    return a + b;
};
```

---
## 二、Lambda 的基本使用
```cpp
auto add = [](int a, int b)
{
    return a + b;
};

int result = add(10, 20);
```
编译器可以推导返回类型为 `int`。

这和普通函数的使用效果类似：
```cpp
int Add(int a, int b)
{
    return a + b;
}
```

区别是 Lambda：
- 可以直接写在使用位置；
- 可以捕获所在作用域中的局部变量；
- 它实际上是一个编译器生成的函数对象。

---
## 三、什么是捕获列表？
普通函数不能直接访问另一个函数中的局部变量：
```cpp
void Func()
{
    int value = 10;

    // 普通外部函数无法直接访问这个 value
}
```
Lambda 可以通过捕获列表使用外层局部变量：
```cpp
void Func()
{
    int value = 10;

    auto print = [value]()
    {
        std::cout << value << '\n';
    };

    print();
}
```
这里：
```cpp
[value]
```
表示按值捕获局部变量 `value`。

捕获列表位于：
```cpp
[]
```
中。

---
## 四、不捕获任何变量：`[]`

```cpp
int value = 10;

auto func = []()
{
    std::cout << "Hello\n";

    // std::cout << value; // 错误，没有捕获
};
```
空捕获列表：
```cpp
[]
```
表示 Lambda 不从外围自动获取任何局部变量。

但是全局变量、静态变量不需要捕获：
```cpp
int globalValue = 10;

void Func()
{
    static int staticValue = 20;

    auto lambda = []()
    {
        globalValue = 100;
        staticValue = 200;
    };
}
```
原因是捕获机制主要针对具有自动存储期的外围局部变量。

---
## 五、按值捕获：`[value]`
```cpp
int value = 10;

auto func = [value]()
{
    std::cout << value << '\n';
};
```
按值捕获的核心是：
> Lambda 创建时，把外部变量当前的值复制进闭包对象。

例如：
```cpp
int value = 10;

auto func = [value]()
{
    std::cout << value << '\n';
};

value = 20;

func();
```
输出：
```text
10
```
因为捕获发生在 Lambda 对象创建时，而不是调用时。

概念上类似：
```cpp
class CompilerGeneratedLambda
{
private:
    int value;

public:
    explicit CompilerGeneratedLambda(int value)
        : value(value)
    {
    }

    void operator()() const
    {
        std::cout << value;
    }
};
```
所以按值捕获并不是每次调用都重新读取外部变量。

---
## 六、按引用捕获：`[&value]`

```cpp
int value = 10;

auto func = [&value]()
{
    value = 20;
};

func();
```
执行后，外部变量变为：
```cpp
value == 20
```
因为 Lambda 使用的是原变量，而不是副本。

再看：
```cpp
int value = 10;

auto func = [&value]()
{
    std::cout << value << '\n';
};

value = 20;

func();
```
输出：
```text
20
```
因为引用捕获会在调用时访问原对象当前的值。

---
## 七、按值捕获与按引用捕获对比
```cpp
int value = 10;

auto byValue = [value]()
{
    std::cout << value << '\n';
};

auto byReference = [&value]()
{
    std::cout << value << '\n';
};

value = 20;

byValue();      // 10
byReference();  // 20
```
区别：

|捕获形式|Lambda 内保存什么|外部修改后 Lambda 看到什么|能否修改外部变量|
|---|---|---|---|
|`[value]`|值的副本|创建时的旧值|默认不可以|
|`[&value]`|对原变量的引用关系|调用时的新值|可以|

---
## 八、默认按值捕获：`[=]`

```cpp
int a = 10;
int b = 20;

auto func = [=]()
{
    std::cout << a + b << '\n';
};
```
`[=]` 表示：
> 函数体中使用到的外围自动变量，默认按值捕获。

**注意，不是把作用域内所有变量全部复制进去，而是捕获 Lambda 实际使用的变量。**

---
## 九、默认按引用捕获：`[&]`

```cpp
int a = 10;
int b = 20;

auto func = [&]()
{
    a += 1;
    b += 1;
};
```

`[&]` 表示：
> Lambda 中使用到的外围自动变量，默认按引用捕获。

调用后会修改原变量。

## 十、混合捕获
### 1. 默认按值，个别按引用
```cpp
int a = 10;
int b = 20;

auto func = [=, &a]()
{
    a = 100;          // a 按引用捕获
    std::cout << b;   // b 按值捕获
};
```
规则：
```text
= 表示其他变量默认按值
&a 表示 a 特别按引用
```

---
### 2. 默认按引用，个别按值

```cpp
int a = 10;
int b = 20;

auto func = [&, b]()
{
    a = 100;          // a 按引用
    std::cout << b;   // b 按值
};
```

---
### 3. 显式捕获多个变量

```cpp
[a, &b]()
{
};
```

表示：
- `a` 按值捕获；
- `b` 按引用捕获。

## 十一、捕获列表常见形式总结

```cpp
[]          // 不捕获局部变量

[value]     // value 按值捕获
[&value]    // value 按引用捕获

[=]         // 使用到的局部变量默认按值捕获
[&]         // 使用到的局部变量默认按引用捕获

[=, &value] // 默认按值，value 按引用
[&, value]  // 默认按引用，value 按值

[a, &b]     // a 按值，b 按引用
[this]      // 捕获当前对象的 this 指针
```
**不能在默认捕获后重复写相同方式：**
```cpp
// [=, value]  // 通常属于重复按值捕获
// [&, &value] // 重复按引用捕获
```

---
## 十二、按值捕获为什么默认不能修改？
```cpp
int value = 10;

auto func = [value]()
{
    // value = 20; // 错误
};
```
原因是 Lambda 生成的函数调用运算符默认是 `const` 成员函数。

概念上相当于：
```cpp
class LambdaType
{
private:
    int value;

public:
    void operator()() const
    {
        // value = 20; // const 成员函数不能修改普通成员
    }
};
```
所以，按值捕获的变量会成为闭包对象内部的成员副本，而默认的 `operator()` 是 `const`。

---
## 十三、`mutable` 的作用

要修改按值捕获的副本，可以写：
```cpp
int value = 10;

auto func = [value]() mutable
{
    value += 1;
    std::cout << value << '\n';
};
```
连续调用：
```cpp
func(); // 11
func(); // 12
func(); // 13
```
外部变量仍然是：
```cpp
value == 10
```
因为修改的是 Lambda 内部保存的副本。

`mutable` 的含义是：
> 让 Lambda 生成的 `operator()` 不再默认是 `const`，从而允许修改按值捕获的成员副本。

它不是让原外部变量可以修改。

---
### 按引用捕获一般不需要 `mutable`
```cpp
int value = 10;

auto func = [&value]()
{
    value = 20;
};
```
这里即使 `operator()` 是 `const`，也可以通过引用修改外部对象。

可以类比：
```cpp
class LambdaType
{
private:
    int& value;

public:
    void operator()() const
    {
        value = 20;
    }
};
```
`const` 限制的是闭包对象自身的成员状态，不会自动把引用关联的外部对象变为 `const`。

---
## 十四、Lambda 的参数列表

Lambda 参数和普通函数参数基本一样：
```cpp
auto add = [](int a, int b)
{
    return a + b;
};
```

可以使用：
- 按值参数；
- 引用参数；
- `const` 引用参数；
- 指针参数；
- 默认参数的支持受具体标准规则影响。

例如修改参数对应对象：
```cpp
auto increase = [](int& value)
{
    ++value;
};
```
只读大型对象：
```cpp
auto print = [](const std::string& text)
{
    std::cout << text;
};
```

---
## 十五、返回类型

通常可以省略返回类型：
```cpp
auto add = [](int a, int b)
{
    return a + b;
};
```
编译器推导为 `int`。

也可以显式指定：
```cpp
auto divide = [](double a, double b) -> double
{
    return a / b;
};
```

返回类型写在参数列表后：
```cpp
-> double
```
这叫尾置返回类型。

当不同分支返回类型不容易统一时，显式指定更清楚：
```cpp
auto func = [](bool flag) -> double
{
    if (flag)
    {
        return 10;
    }

    return 3.14;
};
```
C++11 对 Lambda 返回类型自动推导的规则比后续标准更严格，复杂返回逻辑中显式写出返回类型更稳妥。

---
## 十六、Lambda 捕获 `this`

在成员函数中：
```cpp
class Player
{
private:
    int health = 100;

public:
    void Print()
    {
        auto func = [this]()
        {
            std::cout << health << '\n';
        };

        func();
    }
};
```
成员变量实际上通过：
```cpp
this->health
```
访问。

捕获：
```cpp
[this]
```
表示把当前对象的 `this` 指针捕获到 Lambda 中。

---
### C++11 中 `[this]` 捕获的是指针
它不是复制整个对象，而是复制 `this` 指针值。

概念上：
```text
Lambda 内保存 Player*
```

因此：
```cpp
class Player
{
private:
    int health = 100;

public:
    auto GetLambda()
    {
        return [this]()
        {
            return health;
        };
    }
};
```
如果 Lambda 被调用时原 `Player` 对象已经销毁，`this` 就成为悬空指针，调用产生未定义行为。

---
## 十七、`[=]` 在成员函数中与 `this`

在 C++11 成员函数里：
```cpp
[=]()
{
    std::cout << health;
}
```
因为访问成员需要 `this`，编译器会捕获 `this` 指针。

但这并不表示把整个对象按值复制。
因此即使写 `[=]`，仍然存在对象提前销毁导致悬空 `this` 的风险。

**C++17 增加了：**
```cpp
[*this]
```
用于按值捕获整个当前对象，但这不是 C++11 特性。

---
## 十八、引用捕获的生命周期陷阱

这是 Lambda 最重要的安全问题之一。
```cpp
auto CreateLambda()
{
    int value = 10;

    return [&value]()
    {
        return value;
    };
}
```
这里返回 Lambda 后：
```text
CreateLambda 结束
value 被销毁
Lambda 中的引用悬空
```
后续调用属于未定义行为：
```cpp
auto func = CreateLambda();
func(); // 危险
```
正确方式可以按值捕获：
```cpp
auto CreateLambda()
{
    int value = 10;

    return [value]()
    {
        return value;
    };
}
```
所以必须记住：
> 引用捕获不会延长被捕获局部变量的生命周期。

---
## 十九、异步任务中的捕获风险
例如：
```cpp
void StartTask()
{
    int value = 10;

    std::thread worker([&value]()
    {
        std::cout << value;
    });

    worker.detach();
}
```
线程被分离后，`StartTask()` 可能先结束，`value` 被销毁，而线程稍后才访问它。
这会产生悬空引用。
异步、线程、回调中通常需要特别谨慎：
```cpp
[value]()
{
    std::cout << value;
}
```
按值捕获更容易保证生命周期，但对于复杂对象还要考虑复制成本和共享状态需求。

---
## 二十、Lambda 的底层原理

Lambda 不是普通函数。

编译器会为每一个 Lambda 表达式生成一个匿名的类类型，也称：
```text
闭包类型 closure type
```

Lambda 表达式产生的对象称：
```text
闭包对象 closure object
```

例如：
```cpp
int value = 10;

auto func = [value](int number)
{
    return value + number;
};
```

概念上类似：
```cpp
class CompilerGeneratedLambda
{
private:
    int value;

public:
    explicit CompilerGeneratedLambda(int value)
        : value(value)
    {
    }

    int operator()(int number) const
    {
        return value + number;
    }
};
```

然后：
```cpp
CompilerGeneratedLambda func(value);
func(20);
```

之所以可以像函数一样调用：
```cpp
func(20)
```

是因为闭包类型重载了：
```cpp
operator()
```
所以 Lambda 的本质是：
> **编译器生成的匿名函数对象。**

---
## 二十一、每个 Lambda 的类型都不同

即使两个 Lambda 代码完全一样：
```cpp
auto f1 = []()
{
    return 10;
};

auto f2 = []()
{
    return 10;
};
```
`f1` 和 `f2` 的类型也不同。

每一个 Lambda 表达式都有唯一的闭包类型。

因此通常用：
```cpp
auto
```
接收 Lambda：
```cpp
auto func = []() {};
```
不能轻易手写它的真实类型，因为该类型由编译器生成且没有可直接书写的名称。

---
## 二十二、Lambda 对象的大小

闭包对象需要保存按值捕获的数据。
```cpp
int a = 10;
double b = 3.14;

auto func = [a, b]()
{
};
```
闭包对象中概念上会有：
```text
int a 的副本
double b 的副本
```
所以它通常不是零大小。

空捕获 Lambda：
```cpp
auto func = []() {};
```
对应空类对象，但 C++ 中普通完整对象大小至少通常为 1 字节，以保证不同对象具有不同地址。

实际大小还会受到：
- 数据成员大小；
- 内存对齐；
- 编译器实现；
影响。

---
### 二十三、无捕获 Lambda 与函数指针

无捕获 Lambda 可以转换为兼容的普通函数指针：
```cpp
int (*functionPointer)(int, int) =
    [](int a, int b)
    {
        return a + b;
    };
```
然后：
```cpp
int result = functionPointer(10, 20);
```
因为这个 Lambda 不依赖任何捕获状态。

---
### 有捕获 Lambda 通常不能转成普通函数指针
```cpp
int base = 10;

auto lambda = [base](int value)
{
    return base + value;
};

// int (*pointer)(int) = lambda; // 错误
```
普通函数指针只能保存函数地址，没有地方保存 `base` 这份额外状态。
而有捕获 Lambda 是带状态的函数对象。

---
## 二十四、Lambda 与 `std::function`
`std::function` 是一种通用的可调用对象包装器。
```cpp
#include <functional>

std::function<int(int, int)> func =
    [](int a, int b)
    {
        return a + b;
    };
```
也可以保存有捕获 Lambda：
```cpp
int base = 10;

std::function<int(int)> func =
    [base](int value)
    {
        return base + value;
    };
```
`std::function<int(int)>` 表示：
```text
接收一个 int
返回一个 int
```

它可以包装：
- 普通函数；
- 函数指针；
- Lambda；
- 函数对象；
- `std::bind` 结果。

---
### `auto` 和 `std::function` 的区别

```cpp
auto func = [base](int value)
{
    return base + value;
};
```

使用 `auto`：
- 保存具体闭包类型；
- 编译器知道准确类型；
- 通常更容易内联；
- 通常没有类型擦除额外成本。

使用：
```cpp
std::function<int(int)> func = ...;
```

优点：
- 类型统一；
- 便于作为成员、参数和容器元素；
- 可以在运行时替换不同种类的可调用对象。

代价可能包括：
- 类型擦除；
- 间接调用；
- 某些情况下动态内存分配；
- 优化空间减少。

所以：
> 局部使用时优先 `auto`；需要统一存储不同可调用对象时使用 `std::function`。

---
## 二十五、Lambda 与 STL 算法

Lambda 最常见的用途之一是给 STL 算法传递行为。
### 1. 自定义排序
```cpp
std::vector<int> values{3, 1, 5, 2, 4};

std::sort(
    values.begin(),
    values.end(),
    [](int left, int right)
    {
        return left > right;
    }
);
```
这表示降序排序。

比较器返回：
```cpp
left > right
```

意思是：
> `left` 是否应该排在 `right` 前面。

---
### 比较器必须满足严格弱序

错误示例：
```cpp
[](int left, int right)
{
    return left >= right;
}
```
不应该使用 `>=`。

因为当：
```cpp
left == right
```
时，比较器会返回 `true`，违反“一个元素不应小于自身”的要求。

正确：
```cpp
return left > right;
```

校招面试中可能追问：
> `std::sort` 的比较函数为什么不能写 `<=` 或 `>=`？

因为比较器必须满足严格弱序，否则算法行为可能不符合预期，严重时属于未定义行为范围。

---
### 2. 查找满足条件的元素
```cpp
std::vector<int> values{1, 2, 3, 4, 5};

auto it = std::find_if(
    values.begin(),
    values.end(),
    [](int value)
    {
        return value > 3;
    }
);
```
Lambda 在这里叫：
```text
谓词 predicate
```
即返回布尔结果，用来判断元素是否满足条件。

---
### 3. 捕获外部条件
```cpp
int threshold = 3;

auto it = std::find_if(
    values.begin(),
    values.end(),
    [threshold](int value)
    {
        return value > threshold;
    }
);
```
普通函数若要使用动态的 `threshold`，需要额外传参或定义函数对象；Lambda 可以直接捕获。

---
## 二十六、Lambda 作为函数参数
可以使用模板接收任意可调用对象：
```cpp
template <typename Func>
void Execute(Func func)
{
    func();
}
```
调用：
```cpp
int value = 10;

Execute([value]()
{
    std::cout << value;
});
```
这种模板方式保留具体 Lambda 类型，通常效率较好。

也可以使用 `std::function`：
```cpp
void Execute(const std::function<void()>& func)
{
    func();
}
```

模板方式：
- 可以内联；
- 无类型擦除；
- 但每种调用对象会实例化一份模板。

`std::function`：
- 接口类型统一；
- 适合长期存储；
- 有一定抽象开销。

---
## 二十七、Lambda 与函数对象的关系

传统函数对象：
```cpp
class Greater
{
public:
    bool operator()(int left, int right) const
    {
        return left > right;
    }
};
```
使用：
```cpp
std::sort(values.begin(), values.end(), Greater{});
```
Lambda：
```cpp
std::sort(
    values.begin(),
    values.end(),
    [](int left, int right)
    {
        return left > right;
    }
);
```
两者底层思想相同：

```text
都是具有 operator() 的可调用对象
```
Lambda 的优势是：
- 写法短；
- 逻辑就在使用位置；
- 捕获外部变量方便。

命名函数对象的优势是：
- 可重复使用；
- 复杂逻辑更容易测试；
- 类型和语义名称更明确。

---
## 二十八、C++14 的泛型 Lambda

下面写法不是 C++11，而是 C++14：
```cpp
auto add = [](auto a, auto b)
{
    return a + b;
};
```
调用：
```cpp
add(1, 2);
add(1.5, 2.5);
```
编译器生成的 `operator()` 概念上是函数模板。
C++11 Lambda 参数必须明确写类型：
```cpp
[](int a, int b)
{
    return a + b;
}
```
校招中要避免把泛型 Lambda 误说成 C++11。

---
## 二十九、C++14 的初始化捕获

下面也是 C++14：

```cpp
auto pointer = std::make_unique<int>(10);

auto func = [p = std::move(pointer)]()
{
    std::cout << *p;
};
```
这叫：
```text
初始化捕获 init-capture
```
它可以：
- 给捕获成员重新命名；
- 捕获表达式结果；
- 移动捕获 `unique_ptr`。

C++11 捕获列表主要捕获当前作用域中已有变量：
```cpp
[value]
[&value]
```
不能直接使用上述初始化捕获语法。

---
## 三十、Lambda 递归调用

Lambda 没有可以直接书写的自身类型和普通函数名，因此递归调用需要额外处理。

常见方式：
```cpp
std::function<int(int)> factorial;

factorial = [&factorial](int n) -> int
{
    if (n <= 1)
    {
        return 1;
    }

    return n * factorial(n - 1);
};
```
调用：
```cpp
std::cout << factorial(5); // 120
```
这里 Lambda 通过引用捕获 `factorial`，从而调用自己。
不过 `std::function` 带有类型擦除开销。现代 C++ 还有自传 Lambda 等方式，但不属于 C++11 基础高频内容。

---
## 三十一、捕获 `const` 变量
```cpp
const int value = 10;

auto func = [value]() mutable
{
    // value = 20;
};
```
这里需要注意类型推导和闭包成员的具体规则。对外应该保持最重要的理解：
> 按值捕获产生闭包内部的独立状态，是否能够修改由捕获变量的类型以及 Lambda 是否 `mutable` 共同决定。

对于普通非 `const` 局部变量：
```cpp
int value = 10;
```
按值捕获后加 `mutable`，可以修改闭包副本。

---
## 三十二、捕获数组

```cpp
int array[3]{1, 2, 3};

auto func = [array]()
{
    std::cout << array[0];
};
```
Lambda 捕获数组时的规则和普通按值参数的数组退化不完全相同，编译器会按照捕获规则保存对应元素状态。
不过实际工程中更推荐使用：
```cpp
std::array<int, 3>
std::vector<int>
```
因为它们具有更清晰的对象语义。

---
## 三十三、常见错误与陷阱
### 1. 误认为按值捕获会实时读取外部变量

```cpp
int value = 10;
auto func = [value]() { return value; };

value = 20;

func(); // 返回 10
```

按值捕获保存的是创建时的副本。

---
### 2. 误认为 `mutable` 修改外部变量

```cpp
int value = 10;

auto func = [value]() mutable
{
    value = 20;
};

func();
```

外部 `value` 仍是 10。

---
### 3. 返回引用捕获局部变量的 Lambda

```cpp
auto Func()
{
    int value = 10;
    return [&value]() { return value; };
}
```

返回后引用悬空。

---
### 4. 捕获 `this` 后对象提前销毁

```cpp
auto callback = object.GetCallback();

delete object;

callback(); // 可能访问悬空 this
```

回调、异步任务中必须考虑对象生命周期。

---
### 5. `std::sort` 比较器使用 `<=`

```cpp
[](int a, int b)
{
    return a <= b; // 错误设计
}
```
应该使用严格比较：
```cpp
return a < b;
```

---
### 6. 用 `[&]` 捕获所有变量后长期保存 Lambda
```cpp
std::function<void()> callback;

void Setup()
{
    int value = 10;

    callback = [&]()
    {
        std::cout << value;
    };
}
```
`Setup()` 结束后 `value` 销毁，回调中引用悬空。

不要为了方便无脑使用 `[&]`。

---
### 7. 误认为无捕获和有捕获 Lambda 都能转函数指针

只有无捕获 Lambda 可以隐式转换为兼容的函数指针。

有捕获 Lambda 需要保存状态，不能直接转换。

---
## 三十四、捕获方式如何选择？

一般原则：
### 只需要当前值

```cpp
[value]
```

### 需要修改原变量或观察它后续变化

```cpp
[&value]
```

但必须确保原变量生命周期覆盖 Lambda 使用期。

### Lambda 立即执行且作用域很短

可以适当使用：

```cpp
[&]
```

### Lambda 会被保存、异步执行或跨作用域使用

应该谨慎使用引用捕获和 `this` 捕获。

优先明确写出真正需要的变量：

```cpp
[value, count]
```

而不是无脑：

```cpp
[=]
[&]
```

明确捕获更容易审查生命周期与所有权。

---
## 三十五、面试高频问题
### 1. Lambda 的本质是什么？

Lambda 本质上是编译器生成的匿名闭包类对象，闭包类重载了 `operator()`，捕获的变量会作为闭包对象的成员保存。

---
### 2. 按值捕获和按引用捕获有什么区别？

按值捕获在 Lambda 创建时复制外部变量，之后外部变量改变不会影响副本。

按引用捕获关联原变量，Lambda 调用时访问原对象，可以修改原对象，但必须保证原对象仍然存活。

---
### 3. 为什么按值捕获默认不能修改？

因为编译器生成的闭包类型，其 `operator()` 默认是 `const` 成员函数。

加入 `mutable` 后，`operator()` 变为非 `const`，可以修改闭包内部的按值捕获副本。

---
### 4. `mutable` 会修改外部变量吗？

不会。

它只允许修改 Lambda 内部保存的按值捕获副本。

按引用捕获才会操作原变量。

---
### 5. 无捕获 Lambda 能转换为函数指针吗？

可以，只要函数签名兼容。

有捕获 Lambda 通常不能，因为普通函数指针无法保存捕获状态。

---
### 6. Lambda 和 `std::function` 的区别？

Lambda 是具体的闭包类型；`std::function` 是类型擦除后的统一可调用对象包装器。

`auto` 保存 Lambda 通常效率更高；`std::function` 适合统一存储不同类型的可调用对象，但可能有间接调用和动态分配开销。

---
### 7. `[=]` 是把所有局部变量都复制吗？

不是。

它表示 Lambda 中实际使用的外围自动变量默认按值捕获。

---
### 8. `[this]` 是复制整个对象吗？

C++11 中不是。

它捕获的是 `this` 指针。原对象销毁后，Lambda 再访问成员会产生悬空指针风险。

---
### 9. Lambda 的类型相同吗？

每一个 Lambda 表达式都有独立且唯一的闭包类型，即使代码形式完全相同，类型也不同。

---
### 10. C++11 支持泛型 Lambda 吗？

不支持 `[](auto value)` 这种泛型 Lambda，它是 C++14 引入的。

---
## 三十六、面试回答模板

面试官问：

> 什么是 Lambda 表达式？底层如何实现？

可以回答：

Lambda 表达式是 C++11 引入的一种匿名可调用对象语法，可以直接在使用位置定义一段函数逻辑，并通过捕获列表访问外围局部变量。

它的基本语法由捕获列表、参数列表、可选的 `mutable`、返回类型和函数体组成。捕获可以按值或按引用进行。按值捕获会在 Lambda 对象创建时复制变量，按引用捕获则访问原变量，因此必须注意生命周期问题。

Lambda 底层通常由编译器生成一个唯一的匿名闭包类，捕获变量作为闭包类的数据成员，函数体生成闭包类的 `operator()`。默认情况下，`operator()` 是 `const` 成员函数，所以按值捕获的副本不能修改；加上 `mutable` 后可以修改闭包内部副本。

无捕获 Lambda 可以转换成兼容的普通函数指针，有捕获 Lambda 因为需要保存状态，通常不能转换成普通函数指针。Lambda 可以通过具体类型由 `auto` 保存，也可以使用 `std::function` 进行类型擦除和统一存储。

```text
├── 捕获

│
├── 底层原理
│   ├── 编译器生成闭包类
│   ├── 捕获变量成为数据成员
│   └── 函数体成为 operator()
│
├── 类型
│   ├── 每个 Lambda 类型唯一

└── 风险
    ├── 引用捕获悬空
    ├── this 指针悬空
    ├── 异步任务生命周期

```

最核心的三句话：

> **Lambda 的本质是编译器生成的匿名函数对象。**

> **按值捕获保存创建时的副本，按引用捕获访问原对象。**

> **Lambda 是否安全，关键不只看语法，还要看被捕获对象的生命周期。**
