# 🐉版
## 类的新功能
### 默认成员函数
在C++11之前，一个类中有如下六个默认成员函数：
- 构造函数。
- 析构函数。
- 拷贝构造函数。
- 拷贝赋值函数。
- 取地址重载函数。
- const取地址重载函数。
其中前四个成员函数最重要，后面两个成员函数一般不会用到，这里“默认”的意思就是你不写编译器会自动生成。在C++11标准中又增加了两个默认成员函数，分别是移动构造函数和移动赋值重载函数。

#### 默认移动构造和移动赋值的生成条件
C++11中新增的移动构造函数和移动赋值函数的生成条件如下：
- 移动构造函数的生成条件：没有自己实现移动构造函数，并且没有自己实现析构函数、拷贝构造函数和拷贝赋值函数。
- 移动赋值重载函数的生成条件：没有自己实现移动赋值重载函数，并且没有自己实现析构函数、拷贝构造函数和拷贝赋值函数。
也就是说，移动构造和移动赋值的生成条件与之前六个默认成员函数不同，并不是单纯的没有实现移动构造和移动赋值编译器就会默认生成。

**特别注意：** 如果我们自己实现了移动构造或者移动赋值，就算没有实现拷贝构造和拷贝赋值，编译器也不会生成默认的拷贝构造和拷贝赋值。

#### 默认生成的移动构造和移动赋值会做什么？
- 默认生成的移动构造函数：对于内置类型的成员会完成值拷贝（浅拷贝），对于自定义类型的成员，如果该成员实现了移动构造就调用它的移动构造，否则就调用它的拷贝构造。
- 默认生成的移动赋值重载函数：对于内置类型的成员会完成值拷贝（浅拷贝），对于自定义类型的成员，如果该成员实现了移动赋值就调用它的移动赋值，否则就调用它的拷贝赋值。

#### 验证默认生成的移动构造和移动赋值所做的工作
要验证默认生成的移动构造和移动赋值确实做了上述工作，这里需要模拟实现一个简化版的string类，类当中只编写了几个我们需要用到的成员函数。

代码如下：
```cpp
namespace cl
{
	class string
	{
	public:
		//构造函数
		string(const char* str = "")
		{
			_size = strlen(str); //初始时，字符串大小设置为字符串长度
			_capacity = _size; //初始时，字符串容量设置为字符串长度
			_str = new char[_capacity + 1]; //为存储字符串开辟空间（多开一个用于存放'\0'）
			strcpy(_str, str); //将C字符串拷贝到已开好的空间
		}
		//交换两个对象的数据
		void swap(string& s)
		{
			//调用库里的swap
			::swap(_str, s._str); //交换两个对象的C字符串
			::swap(_size, s._size); //交换两个对象的大小
			::swap(_capacity, s._capacity); //交换两个对象的容量
		}
		//拷贝构造函数（现代写法）
		string(const string& s)
			:_str(nullptr)
			, _size(0)
			, _capacity(0)
		{
			cout << "string(const string& s) -- 深拷贝" << endl;

			string tmp(s._str); //调用构造函数，构造出一个C字符串为s._str的对象
			swap(tmp); //交换这两个对象
		}
		//移动构造
		string(string&& s)
			:_str(nullptr)
			, _size(0)
			, _capacity(0)
		{
			cout << "string(string&& s) -- 移动构造" << endl;
			swap(s);
		}
		//拷贝赋值函数（现代写法）
		string& operator=(const string& s)
		{
			cout << "string& operator=(const string& s) -- 深拷贝" << endl;

			string tmp(s); //用s拷贝构造出对象tmp
			swap(tmp); //交换这两个对象
			return *this; //返回左值（支持连续赋值）
		}
		//移动赋值
		string& operator=(string&& s)
		{
			cout << "string& operator=(string&& s) -- 移动赋值" << endl;
			swap(s);
			return *this;
		}
		//析构函数
		~string()
		{
			//delete[] _str;  //释放_str指向的空间
			_str = nullptr; //及时置空，防止非法访问
			_size = 0;      //大小置0
			_capacity = 0;  //容量置0
		}
	private:
		char* _str;
		size_t _size;
		size_t _capacity;
	};
}
```
然后再编写一个简单的Person类，Person类中的成员name的类型就是我们模拟实现的string 类。

代码如下：
```cpp
class Person
{
public:
	//构造函数
	Person(const char* name = "", int age = 0)
		:_name(name)
		, _age(age)
	{}
	//拷贝构造函数
	Person(const Person& p)
		:_name(p._name)
		, _age(p._age)
	{}
	//拷贝赋值函数
	Person& operator=(const Person& p)
	{
		if (this != &p)
		{
			_name = p._name;
			_age = p._age;
		}
		return *this;
	}
	//析构函数
	~Person()
	{}
private:
	cl::string _name; //姓名
	int _age;         //年龄
};
```
虽然Person类当中没有实现移动构造和移动赋值，但拷贝构造、拷贝赋值和析构函数Person类都实现了，因此Person类中不会生成默认的移动构造和移动赋值，可以通过下面的代码来验证：
```cpp
int main()
{
	Person s1("张三", 21);
	Person s2 = std::move(s1); //想要调用Person默认生成的移动构造

	return 0;
}
```
上述代码中用一个右值去构造s2对象，但由于Person类没有生成默认的移动构造函数，因此这里会调用Person的拷贝构造函数（拷贝构造既能接收左值也能接收右值），这时在Person的拷贝构造函数中就会调用string的拷贝构造函数对name成员进行深拷贝。

如果要让Person类生成默认的移动构造函数，就必须将Person类中的拷贝构造、拷贝赋值和析构函数全部注释掉，这时用右值去构造s2对象时就会调用Person默认生成的移动构造函数。

- Person默认生成的移动构造，对于内置类型成员age会进行值拷贝，而对于自定义类型成员name，因为我们的string类实现了移动构造函数，因此它会调用string的移动构造函数进行资源的转移。
- 而如果我们将string类当中的移动构造函数注释掉，那么Person默认生成的移动构造函数，就会调用string类中的拷贝构造函数对name成员进行深拷贝。

要验证Person类中默认生成的移动赋值函数可以用下面的代码，验证方式和上面验证移动构造的方式是一样的。
```cpp
int main()
{
	Person s1("张三", 21);
	Person s2;
	s2 = std::move(s1); //想要调用Person默认生成的移动赋值

	return 0;
}
```
**说明一下：**
- 我们在模拟实现的string类的拷贝构造、拷贝赋值、移动构造和移动赋值函数中都打印了一条提示语句，因此可以通过控制台输出判断是否调用了对应的函数。
- - 由于VS2013没有完全支持C++11，因此上述代码无法在VS2013当中验证，需要使用更新一点的编译器进行验证，比如VS2019。

### 类成员变量初始化
默认生成的构造函数，对于自定义类型的成员会调用其构造函数进行初始化，但并不会对内置类型的成员进行处理。于是C++11支持非静态成员变量在声明时进行初始化赋值，默认生成的构造函数会使用这些缺省值对成员进行初始化。比如：
```cpp
class Person
{
public:
	//...
private:
	//非静态成员变量，可以在成员声明时给缺省值
	cl::string _name = "张三"; //姓名
	int _age = 20;             //年龄
	static int _n; //静态成员变量不能给缺省值
};
```
**注意：** 这里不是初始化，而是给声明的成员变量一个缺省值。

### 强制生成默认函数的关键字default
C++11可以让我们更好的控制要使用的默认成员函数，假设在某些情况下我们需要使用某个默认成员函数，但是因为某些原因导致无法生成这个默认成员函数，这时可以使用default关键字强制生成某个默认成员函数。

例如，下面的Person类中实现了拷贝构造函数：
```cpp
class Person
{
public:
	//拷贝构造函数
	Person(const Person& p)
		:_name(p._name)
		, _age(p._age)
	{}
private:
	cl::string _name; //姓名
	int _age;         //年龄
};
```
这时如下代码就无法编译成功了，因为Person类中编写了拷贝构造函数，导致无法生成默认的构造函数，因为默认构造函数生成的条件是没有编写任意类型的构造函数，包括拷贝构造函数。
```cpp
int main()
{
	Person s; //没有合适的默认构造函数可用

	return 0;
}
```
这时我们就可以使用default关键字强制生成默认的构造函数，如下：
```cpp
class Person
{
public:
	Person() = default; //强制生成默认构造函数

	//拷贝构造函数
	Person(const Person& p)
		:_name(p._name)
		, _age(p._age)
	{}
private:
	cl::string _name; //姓名
	int _age;         //年龄
};
```
**说明一下：** 默认成员函数都可以用default关键字强制生成，包括移动构造和移动赋值。

### 禁止生成默认函数的关键字delete
当我们想要限制某些默认函数生成时，可以通过如下两种方式：
- 在C++98中，可以将该函数设置成私有，并且只用声明不用定义，这样当外部调用该函数时就会报错。
- 在C++11中，可以在该函数声明后面加上=delete，表示让编译器不生成该函数的默认版本，我们将=delete修饰的函数称为删除函数。

例如，要让一个类不能被拷贝，可以用=delete修饰将该类的拷贝构造和拷贝赋值。
```cpp
class CopyBan
{
public:
	CopyBan()
	{}
private:
	CopyBan(const CopyBan&) = delete;
	CopyBan& operator=(const CopyBan&) = delete;
};
```
**说明一下：** 被=delete修饰的函数可以设置为公有，也可以设置为私有，效果都一样。

### 继承和多态中final与override关键字
#### final修饰类
被final修饰的类叫做最终类，最终类无法被继承。比如：
```cpp
class NonInherit final //被final修饰，该类不能再被继承
{
	//...
};
```

#### final修饰虚函数
final修饰虚函数，表示该虚函数不能再被重写，如果子类继承后重写了该虚函数则编译报错。比如：
```cpp
//父类
class Person
{
public:
	virtual void Print() final //被final修饰，该虚函数不能再被重写
	{
		cout << "hello Person" << endl;
	}
};
//子类
class Student : public Person
{
public:
	virtual void Print() //重写，编译报错
	{
		cout << "hello Student" << endl;
	}
};
```

#### override修饰虚函数
override修饰子类的虚函数，检查子类是否重写了父类的某个虚函数，如果没有重写则编译报错。比如：
```cpp
//父类
class Person
{
public:
	virtual void Print()
	{
		cout << "hello Person" << endl;
	}
};
//子类
class Student : public Person
{
public:
	virtual void Print() override //检查子类是否重写了父类的某个虚函数
	{
		cout << "hello Student" << endl;
	}
};
```

# AI讲解C++11——类的新功能

C++11 对类最重要的改进可以归纳为三条主线：
1. **补全对象的移动能力**：增加移动构造和移动赋值。
2. **更明确地控制编译器行为**：`= default`、`= delete`、`override`、`final`。
3. **减少构造函数中的重复代码**：类内成员初始化、委托构造、继承构造函数。

- 显式类型转换函数；
- 成员函数引用限定符；
- 五法则与零法则。

## 一、默认成员函数

### 1. 什么是默认成员函数？

这里的“默认成员函数”不是指带默认参数的函数，而是：
> 当用户没有显式声明某些特殊成员函数时，编译器可能自动为类隐式声明并生成这些函数。

C++11 中通常讲六个特殊成员函数：
```cpp
class A
{
public:
    A();                              // 默认构造函数
    ~A();                             // 析构函数

    A(const A& other);                // 拷贝构造函数
    A& operator=(const A& other);     // 拷贝赋值运算符

    A(A&& other);                     // 移动构造函数
    A& operator=(A&& other);          // 移动赋值运算符
};
```
其中前四个在 C++98 中就有，C++11 新增：
```cpp
A(A&&);
A& operator=(A&&);
```

---
### 2. 六个特殊成员函数分别在什么时候调用？

```cpp
class Data
{
public:
    Data();
    ~Data();

    Data(const Data&);
    Data& operator=(const Data&);

    Data(Data&&) noexcept;
    Data& operator=(Data&&) noexcept;
};
```
使用：
```cpp
Data a;                    // 默认构造

Data b(a);                 // 拷贝构造
Data c = a;                // 拷贝构造

Data d(std::move(a));      // 移动构造

b = c;                     // 拷贝赋值

b = std::move(d);          // 移动赋值
```
最容易混淆的是构造和赋值：
```cpp
Data b = a;
```
虽然有等号，但这是在创建新对象，所以调用拷贝构造。
```cpp
Data b;
b = a;
```
`b` 已经存在，所以调用拷贝赋值。

---
### 3. “编译器生成”要准确理解
教材常说编译器自动生成默认成员函数，更准确地分为三步：
```text
隐式声明
    ↓
真正需要时按需定义
    ↓
如果无法正确生成，可能定义为 deleted
```
例如：
```cpp
class A
{
private:
    const int value = 10;
};
```
编译器可以生成拷贝构造，但默认的拷贝赋值可能不可用，因为：
```cpp
const int
```
不能被重新赋值。
```cpp
A a;
A b;

// b = a;  // 拷贝赋值可能被隐式删除
```
所以：
> 编译器“声明了”某个函数，不等于这个函数最终一定可以调用。

## 二、默认构造函数的生成规则

假设：
```cpp
class A
{
};
```
编译器可以隐式生成：
```cpp
A::A()
{
}
```
但只要用户声明了任何构造函数：
```cpp
class A
{
public:
    A(int value)
    {
    }
};
```
编译器通常就不会再自动提供无参默认构造函数。

因此：
```cpp
A a;       // 错误，没有 A()
A b(10);   // 正确
```
需要显式恢复：
```cpp
class A
{
public:
    A() = default;

    A(int value)
    {
    }
};
```
现在：
```cpp
A a;
A b(10);
```
都可以。

面试高频结论：
> 用户声明了其他构造函数后，编译器不再自动生成默认构造函数，但可以使用 `= default` 显式要求生成。

---
## 三、拷贝构造和拷贝赋值

编译器默认生成的拷贝操作通常执行：
> 对每个基类子对象和非静态数据成员逐个进行拷贝。

例如：
```cpp
class Player
{
private:
    std::string name;
    int level;
};
```
默认拷贝大致相当于：
```cpp
Player::Player(const Player& other)
    : name(other.name),
      level(other.level)
{
}
```
由于 `std::string` 自己支持正确拷贝，所以默认拷贝没有问题。

---
### 裸指针资源的问题
```cpp
class Buffer
{
private:
    int* data;
};
```
默认拷贝只会复制指针值：
```text
对象一 data ─┐
             ├── 指向同一块内存
对象二 data ─┘
```
如果两个对象都在析构时 `delete[] data`，就会重复释放。

因此管理独占资源的类不能盲目依赖默认拷贝，通常需要：
- 实现深拷贝；
- 禁止拷贝；
- 使用 `std::vector`、`std::unique_ptr` 等 RAII 类型。

## 四、C++11 新增：移动构造和移动赋值
### 1. 移动构造函数
```cpp
class Buffer
{
private:
    int* data = nullptr;
    std::size_t size = 0;

public:
    Buffer(Buffer&& other) noexcept
        : data(other.data),
          size(other.size)
    {
        other.data = nullptr;
        other.size = 0;
    }
};
```
作用是：
```text
不重新申请和复制资源
而是直接接管源对象资源
```

---
### 2. 移动赋值运算符

```cpp
Buffer& operator=(Buffer&& other) noexcept
{
    if (this != &other)
    {
        delete[] data;

        data = other.data;
        size = other.size;

        other.data = nullptr;
        other.size = 0;
    }

    return *this;
}
```

移动赋值和移动构造的区别：
```text
移动构造：
目标对象还不存在

移动赋值：
目标对象已经存在，必须先处理自己的旧资源
```

## 五、特殊成员函数之间的生成关系

这是面试中真正容易考的部分。
### 1. 声明其他构造函数
```cpp
A(int);
```
会阻止编译器隐式生成默认构造函数：
```cpp
A();
```
但它不等于自动禁止拷贝操作。

---
### 2. 用户声明了析构、拷贝操作

当类用户声明了以下函数之一：
```cpp
~A();
A(const A&);
A& operator=(const A&);
```
编译器通常不会再隐式生成移动构造和移动赋值。

例如：
```cpp
class A
{
public:
    ~A() = default;
};
```
即使析构函数只是 `= default`，它仍然属于**用户声明的析构函数**，会影响移动函数的隐式生成。

这是一个常见追问：
> 为什么我只写了析构函数，类就不自动移动了？

因为用户开始主动管理对象销毁行为后，编译器不会再轻易假设成员资源可以安全移动。

---
### 3. 用户声明移动操作
如果声明了移动构造或移动赋值：
```cpp
A(A&&);
A& operator=(A&&);
```
隐式拷贝操作通常会被定义为删除状态。
因此下面这种类可能只能移动、不能复制：
```cpp
class A
{
public:
    A(A&&) = default;
    A& operator=(A&&) = default;
};
```

---
### 4. 成员本身不可拷贝
```cpp
class A
{
private:
    std::unique_ptr<int> pointer;
};
```
`unique_ptr` 禁止拷贝，因此 `A` 的默认拷贝操作也会被隐式删除：
```cpp
A a;

// A b = a;  // 错误
```
但 `unique_ptr` 支持移动，所以 `A` 通常也可以移动：
```cpp
A b = std::move(a);
```

---
## 六、三法则、五法则和零法则

### 1. 三法则
C++98 中，如果类需要自己实现其中一个：
```text
析构函数
拷贝构造函数
拷贝赋值运算符
```
通常三个都需要认真考虑。
原因是类很可能直接管理资源。

---
### 2. 五法则
C++11 增加移动操作后，需要考虑五个：
```text
析构函数
拷贝构造
拷贝赋值
移动构造
移动赋值
```

---
### 3. 零法则

现代 C++ 最推荐的是零法则：
> 业务类不要直接管理裸资源，把资源交给已有 RAII 类型管理，从而不需要手写任何特殊成员函数。

例如：
```cpp
class Player
{
private:
    std::string name;
    std::vector<int> inventory;
    std::unique_ptr<Weapon> weapon;
};
```
这些成员会自己正确处理析构和移动，`Player` 通常不需要手写特殊成员函数。

面试表达：
> 三法则和五法则针对直接管理资源的类，现代 C++ 更推荐零法则，即通过 RAII 成员类型让编译器自动组合正确的资源管理行为。

---
## 七、类成员变量初始化
C++11 允许在类定义中直接为非静态数据成员提供默认初始化值。
```cpp
class Player
{
private:
    int health = 100;
    int level = 1;
    std::string name{"Unknown"};
    bool alive{true};
};
```
这叫：
```text
类内成员初始化
非静态数据成员默认初始化器
```

---
### 1. 它解决了什么问题？

C++11 以前，多个构造函数可能重复写初始化值：
```cpp
class Player
{
private:
    int health;
    int level;

public:
    Player()
        : health(100),
          level(1)
    {
    }

    Player(int level)
        : health(100),
          level(level)
    {
    }
};
```
其中：
```cpp
health(100)
```
重复了。

C++11 可以写：
```cpp
class Player
{
private:
    int health = 100;
    int level = 1;

public:
    Player() = default;

    explicit Player(int level)
        : level(level)
    {
    }
};
```

---
### 2. 构造函数初始化列表优先
```cpp
class Player
{
private:
    int health = 100;

public:
    Player()
        : health(200)
    {
    }
};
```
最终：
```cpp
health == 200
```

规则是：
> 如果构造函数初始化列表显式初始化了某成员，就使用初始化列表；否则使用类内默认初始化器。

---
### 3. 真正的初始化顺序
```cpp
class A
{
private:
    int first;
    int second;

public:
    A()
        : second(2),
          first(1)
    {
    }
};
```
虽然初始化列表先写 `second`，实际仍然按照类中成员声明顺序初始化：
```text
first
再 second
```
不是按照初始化列表书写顺序。

面试高频：
> **成员初始化顺序由成员在类中的声明顺序决定，与构造函数初始化列表中的排列顺序无关。**

因此初始化列表最好也按声明顺序书写，避免误导和警告。

---
### 4. `const` 和引用成员
```cpp
class A
{
private:
    const int value = 10;
    int& reference;

public:
    explicit A(int& object)
        : reference(object)
    {
    }
};
```
引用成员必须绑定对象，不能先默认构造后赋值。

类内初始化器可以为某些构造函数提供统一默认值，但引用往往仍需要由构造函数初始化列表指定。

---
### 5. 不能使用圆括号类内初始化
C++11 中常见形式是：
```cpp
int value = 10;
int number{20};
```
而不是：
```cpp
// int value(10);  // C++11 类内成员初始化不这样写
```

---
## 八、强制生成默认函数：`= default`
### 1. 基本作用
```cpp
class A
{
public:
    A() = default;
    ~A() = default;

    A(const A&) = default;
    A& operator=(const A&) = default;

    A(A&&) = default;
    A& operator=(A&&) = default;
};
```

含义是：
> 明确要求编译器按照默认规则生成该特殊成员函数。

---
### 2. 恢复默认构造函数
```cpp
class A
{
public:
    A() = default;

    explicit A(int value)
    {
    }
};
```
如果没有：
```cpp
A() = default;
```
因为已经声明了 `A(int)`，无参构造不会自动生成。

---
### 3. 虚析构函数常用写法

```cpp
class Base
{
public:
    virtual ~Base() = default;
};
```

它表达：
- 析构函数必须是虚函数；
- 不需要自定义析构逻辑；
- 使用编译器生成的默认实现。

---
### 4. `= default` 不保证函数一定可用
```cpp
class A
{
private:
    const int value = 10;

public:
    A& operator=(const A&) = default;
};
```
由于 `const` 成员不能被赋值，默认拷贝赋值仍然可能被定义为删除状态。

因此：
> `= default` 是请求编译器按默认规则生成，不是命令编译器无论如何都生成可调用函数。

---
### 5. 类内和类外 `= default`
类内：
```cpp
class A
{
public:
    A() = default;
};
```

类外：
```cpp
class A
{
public:
    A();
};

A::A() = default;
```
两种都可以。

加分点：
> 第一次声明时就在类内 `= default`，函数通常不是 user-provided；先声明、再在类外 `= default`，则属于 user-provided，可能影响函数是否平凡、是否可作为某些编译期操作使用。

普通面试说出前半部分即可，深入面试可以补充后半部分。

---
## 九、禁止生成或调用函数：`= delete`
### 1. 禁止拷贝
```cpp
class Resource
{
public:
    Resource() = default;

    Resource(const Resource&) = delete;
    Resource& operator=(const Resource&) = delete;
};
```
使用：
```cpp
Resource first;

// Resource second(first);  // 编译错误
// Resource third = first;  // 编译错误
```

常用于：
- 独占资源；
- 互斥锁包装；
- 单例；
- 不允许复制的系统对象。

---
### 2. 禁止移动
```cpp
class FixedObject
{
public:
    FixedObject(FixedObject&&) = delete;
    FixedObject& operator=(FixedObject&&) = delete;
};
```
表示对象不能被移动。

---
### 3. `= delete` 可以用于普通函数
它不只用于默认成员函数。

例如：
```cpp
void Process(int value)
{
}

void Process(double value) = delete;
```
调用：
```cpp
Process(10);     // 正确
// Process(3.14);   // 错误
```
这可以禁止某些不希望发生的隐式转换。

---
### 4. 被删除函数仍参与重载决议

```cpp
void Func(int);
void Func(double) = delete;
```
调用：
```cpp
Func(3.14);
```
编译器会先发现 `Func(double)` 是最佳匹配，然后报告：
```text
最佳匹配函数已被删除
```
而不是忽略它，再转去调用 `Func(int)`。

这是面试中的加分点：
> Deleted function 仍然参与名字查找和重载决议，只是在被选中后禁止调用。

---
### 5. 为什么比 `private` 更好？
C++11 以前常写：
```cpp
class Resource
{
private:
    Resource(const Resource&);
    Resource& operator=(const Resource&);
};
```
这样只能通过私有权限禁止外部调用，而且如果成员函数或友元误用，还可能在链接阶段报错。

C++11：
```cpp
Resource(const Resource&) = delete;
```

优点：
- 意图明确；
- 任何位置都不能调用；
- 编译阶段直接报错；
- 可以用于普通函数。

---
## 十、`override` 关键字
### 1. 作用
```cpp
class Base
{
public:
    virtual void Print() const
    {
    }
};

class Derived : public Base
{
public:
    void Print() const override
    {
    }
};
```
`override` 表示：
> 这个函数必须重写某个基类虚函数，否则编译失败。

---
### 2. 为什么需要它？
假设基类：
```cpp
class Base
{
public:
    virtual void Print() const
    {
    }
};
```
派生类漏写了 `const`：
```cpp
class Derived : public Base
{
public:
    void Print()
    {
    }
};
```
这不是重写，而是定义了另一个函数。
如果写：
```cpp
void Print() override
{
}
```
编译器会立即报错。

因此 `override` 可以检查：
- 函数名；
- 参数列表；
- `const`、`volatile` 限定；
- 引用限定；
- 返回类型是否兼容；
- 异常规范是否符合要求。

---
### 3. 派生类可以不写 `virtual` 吗？
可以：
```cpp
void Print() override;
```
基类函数一旦是虚函数，在后续派生链中始终保持虚函数性质。

推荐写法：
```cpp
void Print() override;
```
不必再重复写：
```cpp
virtual void Print() override;
```
两者都合法，但 `override` 已经清楚表达目的。

---
## 十一、`final` 关键字
`final` 有两个主要用途。
### 1. 禁止虚函数继续被重写
```cpp
class Base
{
public:
    virtual void Print()
    {
    }
};

class Derived : public Base
{
public:
    void Print() final
    {
    }
};
```
后续类不能继续重写：
```cpp
class MoreDerived : public Derived
{
public:
    // void Print() override;  // 编译错误
};
```
也可以写：
```cpp
void Print() override final;
```

表示：
- 这是对基类虚函数的重写；
- 不允许下一层继续重写。

---
### 2. 禁止类继续被继承
```cpp
class Boss final
{
};
```
下面错误：
```cpp
// class SuperBoss : public Boss
// {
// };
```

---
### 3. `final` 的设计意义

`final` 可以表达：
- 类层次到这里结束；
- 某个行为不允许再修改；
- 防止派生类破坏设计约束；
- 给编译器提供去虚拟化优化机会。

不过不要为了“可能优化”到处添加，首先应该表达正确的设计语义。

---
## 十二、`override` 与 `final` 对比

| 关键字          | 作用              |
| ------------ | --------------- |
| `override`   | 要求当前函数必须重写基类虚函数 |
| `final` 修饰函数 | 禁止后续派生类继续重写     |
| `final` 修饰类  | 禁止该类继续被继承       |

典型写法：
```cpp
class Base
{
public:
    virtual void Func() = 0;
    virtual ~Base() = default;
};

class Derived final : public Base
{
public:
    void Func() override final
    {
    }
};
```
这里类已经 `final`，函数再写 `final` 有些重复，但语法允许。

---
## 十三、补充一：委托构造函数
C++11 允许一个构造函数调用同一个类中的另一个构造函数。
```cpp
class Player
{
private:
    std::string name;
    int level;

public:
    Player(std::string name, int level)
        : name(std::move(name)),
          level(level)
    {
    }

    Player()
        : Player("Unknown", 1)
    {
    }
};
```
这里：
```cpp
Player()
```
委托给：
```cpp
Player(std::string, int)
```
执行顺序：
```text
先执行目标构造函数
再执行委托构造函数自己的函数体
```

---
### 为什么需要委托构造？

避免多个构造函数重复初始化：
```cpp
Player()
    : name("Unknown"),
      level(1)
{
    // 公共初始化逻辑
}

Player(std::string name)
    : name(std::move(name)),
      level(1)
{
    // 又写一次公共初始化逻辑
}
```
可以统一交给一个主构造函数。

---
### 重要限制
委托构造时，初始化列表中只能委托给另一个构造函数，不能再同时初始化成员：
```cpp
Player()
    : Player("Unknown", 1)
    // , level(10)  // 错误
{
}
```
因为目标构造函数已经负责初始化完整对象。

---
## 十四、补充二：继承构造函数

C++11 可以将基类构造函数引入派生类：
```cpp
class Base
{
public:
    Base(int value)
    {
    }

    Base(int value, std::string name)
    {
    }
};

class Derived : public Base
{
public:
    using Base::Base;
};
```
现在可以：
```cpp
Derived d1(10);
Derived d2(10, "hello");
```
不用为每个基类构造函数都写一层转发。

---
### 注意事项
```cpp
class Derived : public Base
{
private:
    int level = 1;

public:
    using Base::Base;
};
```
使用继承来的构造函数时：
- `Base` 部分由相应基类构造函数初始化；
- `Derived` 自己的成员使用类内默认初始化器或默认初始化。

继承构造函数不会让基类的拷贝构造直接变成派生类拷贝构造，派生类仍然遵守自己的特殊成员函数生成规则。

---
## 十五、补充三：`constexpr` 构造函数

C++11 允许构造函数成为 `constexpr`，使对象有机会在编译期构造。
```cpp
class Point
{
private:
    int x;
    int y;

public:
    constexpr Point(int x, int y)
        : x(x), y(y)
    {
    }

    constexpr int GetX() const
    {
        return x;
    }
};
```
使用：
```cpp
constexpr Point point(10, 20);
constexpr int x = point.GetX();
```

`point` 可以成为编译期常量对象。

面试意义：
- 支持编译期计算；
- 提高类型在常量表达式中的可用性；
- 是现代模板和高性能代码的重要基础。

C++11 对 `constexpr` 函数限制较严格，后续标准逐渐放宽。

---
## 十六、补充四：显式类型转换函数

C++11 允许对类型转换运算符使用 `explicit`。

```cpp
class FileHandle
{
private:
    void* handle = nullptr;

public:
    explicit operator bool() const
    {
        return handle != nullptr;
    }
};
```
使用：
```cpp
FileHandle file;

if (file)
{
    // 文件句柄有效
}
```
但不允许随意转换：
```cpp
// int value = file;  // 不允许
```
这解决了传统“安全布尔转换”问题。

注意：
> `explicit operator bool()` 虽然是显式转换函数，但在 `if`、`while`、逻辑非等需要布尔上下文的位置可以使用。

---
## 十七、补充五：成员函数引用限定符
C++11 可以根据调用对象是左值还是右值，限制成员函数调用。
```cpp
class Data
{
public:
    void Process() &
    {
        std::cout << "左值对象调用\n";
    }

    void Process() &&
    {
        std::cout << "右值对象调用\n";
    }
};
```
调用：
```cpp
Data data;

data.Process();          // 调用 & 版本
Data{}.Process();        // 调用 && 版本
```

它常用于：
- 防止对临时对象执行不合理操作；
- 为左值和右值对象提供不同资源处理方式；
- 标准库接口设计。

面试中不是最高频，但在右值引用、移动语义深入追问时是加分项。

---
## 十八、补充六：移动函数为什么常写 `noexcept`
```cpp
class Buffer
{
public:
    Buffer(Buffer&& other) noexcept;
    Buffer& operator=(Buffer&& other) noexcept;
};
```
例如 `std::vector` 扩容时需要把旧元素迁移到新内存。

如果移动构造可能抛异常，移动到一半失败可能破坏旧对象状态。为了保持强异常安全，容器可能改用拷贝。

如果移动构造声明：
```cpp
noexcept
```
容器通常更愿意使用高效的移动操作。

面试高频回答：
> 移动构造能够保证不抛异常时应声明 `noexcept`，否则标准容器在扩容时可能为了异常安全而选择拷贝而不是移动。

## 十九、综合示例

```cpp
#include <iostream>
#include <memory>
#include <string>
#include <utility>

class Character
{
protected:
    std::string name{"Unknown"};
    int health{100};

public:
    Character() = default;

    explicit Character(std::string name)
        : name(std::move(name))
    {
    }

    Character(std::string name, int health)
        : name(std::move(name)),
          health(health)
    {
    }

    Character(const Character&) = delete;
    Character& operator=(const Character&) = delete;

    Character(Character&&) noexcept = default;
    Character& operator=(Character&&) noexcept = default;

    virtual void Attack() const = 0;

    virtual ~Character() = default;
};

class Player final : public Character
{
private:
    std::unique_ptr<int> resource{
        std::make_unique<int>(10)
    };

public:
    using Character::Character;

    void Attack() const override
    {
        std::cout << name << " attacks\n";
    }
};
```
这段代码包含：
```text
类内成员初始化
默认构造函数 = default
禁止拷贝 = delete
默认移动操作
移动操作 noexcept
继承构造函数
纯虚函数
override
final
虚析构函数
RAII
```

由于 `Player` 含有 `unique_ptr`：
- 不能复制；
- 可以移动；
- 资源会自动释放。

## 二十、高频追问
### 1. C++11 后类有几个默认成员函数？

通常回答六个：
```text
默认构造函数
析构函数
拷贝构造函数
拷贝赋值运算符
移动构造函数
移动赋值运算符
```

准确说它们属于特殊成员函数，编译器会根据规则隐式声明、按需定义，也可能定义为删除。

---
### 2. 声明了带参构造函数，还有默认构造吗？

通常没有隐式默认构造函数。

需要：

```cpp
A() = default;
```

---
### 3. `= default` 和空函数体一样吗？

不完全一样。
```cpp
A() = default;
```

明确使用编译器默认语义，有机会保持函数的平凡性、`constexpr` 等属性。

```cpp
A()
{
}
```
是用户自定义函数，语义和类型特征可能不同。

---
### 4. `= default` 的函数一定能调用吗？
不一定。

如果成员或基类导致默认行为不可实现，该函数仍可能被定义为删除。

---
### 5. `= delete` 只能修饰默认成员函数吗？
不是。

任何函数都可以被删除，包括普通函数和特定重载。

---
### 6. `override` 和 `virtual` 有什么区别？

`virtual` 在基类中建立虚函数机制。

`override` 用于派生类，要求编译器检查当前函数确实重写了基类虚函数。

---
### 7. 派生类重写虚函数必须再写 `virtual` 吗？
不必须。

基类函数一旦是虚函数，在整个继承链中一直保持虚函数性质。

推荐写：
```cpp
void Func() override;
```

---
### 8. `final` 可以修饰什么？

可以修饰：
- 虚函数：禁止继续重写；
- 类：禁止继续继承。

---
### 9. 声明析构函数会影响移动函数吗？

会。

用户声明析构函数后，编译器通常不再隐式生成移动构造和移动赋值，即使析构函数写的是：

```cpp
~A() = default;
```

---

## 10. 类内默认初始化和初始化列表谁优先？
构造函数初始化列表优先。

没有在初始化列表中显式初始化的成员，才使用类内默认初始化器。

## 二十一、面试回答模板
面试官问：
> C++11 对类增加了哪些重要功能？

可以这样回答：

C++11 对类的增强主要包括几个方面。

首先，特殊成员函数从传统的默认构造、析构、拷贝构造和拷贝赋值，扩展为增加移动构造和移动赋值，从而支持资源所有权的高效转移。对于直接管理资源的类，需要考虑五法则；现代 C++ 更推荐使用 RAII 成员并遵循零法则。

其次，C++11 支持非静态数据成员的类内默认初始化，可以减少多个构造函数间的重复初始化代码。构造函数初始化列表会覆盖类内默认值，但实际初始化顺序仍由成员声明顺序决定。

另外，`= default` 可以显式要求编译器生成特殊成员函数，`= delete` 可以禁止函数调用，并且不仅适用于特殊成员函数，也适用于普通重载。

在继承和多态方面，`override` 可以让编译器检查虚函数是否真正重写，`final` 可以禁止虚函数继续重写或禁止类继续被继承。

C++11 还增加了委托构造函数、继承构造函数、`constexpr` 构造函数、显式类型转换运算符以及成员函数引用限定符等类相关功能。
