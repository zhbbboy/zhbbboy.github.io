# 🐉版
## C语言中的类型转换
```
C语言和C++都是强类型语言，如果赋值运算符左右两侧变量的类型不同，或形参与实参的类型不匹配，或返回值类型与接收返回值的变量类型不一致，那么就需要进行类型转换。
```

C语言中有两种形式的类型转换，分别是隐式类型转换和显式类型转换：
- 隐式类型转换：编译器在编译阶段自动进行，能转就转，不能转就编译失败。
- 显式类型转换：需要用户自己处理，以`(指定类型)变量`的方式进行类型转换。

需要注意的是，只有相近类型之间才能发生隐式类型转换，比如int和double 表示的都是数值，只不过它们表示的范围和精度不同。而指针类型表示的是地址编号，因此整型和指针类型之间不会进行隐式类型转换，如果需要转换则只能进行显式类型转换。比如：
```cpp
int main()
{
	//隐式类型转换
	int i = 1;
	double d = i;
	cout << i << endl;
	cout << d << endl;

	//显式类型转换
	int* p = &i;
	int address = (int)p;
	cout << p << endl;
	cout << address << endl;
	return 0;
}
```
## 为什么C++需要四种类型转换

C风格的转换格式虽然很简单，但也有很多缺点：

- 隐式类型转换在某些情况下可能会出问题，比如数据精度丢失。
- 显式类型转换将所有情况混合在一起，转换的可视性比较差。

因此C++为了加强类型转换的可视性，引入了四种命名的强制类型转换操作符，分别是static_cast、reinterpret_cast、const_cast和dynamic_cast。

## C++强制类型转换

### static_cast

static_cast用于相近类型之间的转换，编译器隐式执行的任何类型转换都可用static_cast，但它不能用于两个不相关类型之间转换。比如：
```cpp
int main()
{
	double d = 12.34;
	int a = static_cast<int>(d);
	cout << a << endl;

	int* p = &a;
	// int address = static_cast<int>(p); //error
	return 0;
}
```

### reinterpret_cat

reinterpret_cast用于两个不相关类型之间的转换。比如：
```cpp
int main()
{
	int a = 10;
	int* p = &a;
	int address = reinterpret_cast<int>(p);
	cout << address << endl;
	return 0;
}
```
reinterpret_cast还有一个非常bug 的用法，比如在下面的代码中将带参带返回值的函数指针转换成了无参无返回值的函数指针，并且还可以用转换后函数指针调用这个函数。
```cpp
typedef void(*FUNC)();
int DoSomething(int i)
{
	cout << "DoSomething: " << i << endl;
	return 0;
}
int main()
{
	FUNC f = reinterpret_cast<FUNC>(DoSomething);
	f();
	return 0;
}
```
**说明一下：** 用转换后的函数指针调用该函数时没有传入参数，因此这里打印出参数`i`的值是一个随机值。

### const_cast

const_cast用于删除变量的const属性，转换后就可以对const变量的值进行修改。比如：
```cpp
int main()
{
	const int a = 2;
	int* p = const_cast<int*>(&a);
	*p = 3;
	cout << a << endl;  //2
	cout << *p << endl; //3
	return 0;
}
```
**说明一下：**
- 代码中用const_cast删除了变量a的地址的const属性，这时就可以通过这个指针来修改变量a的值。
- 由于编译器认为const修饰的变量是不会被修改的，因此会将const修饰的变量存放到寄存器当中，当需要读取const变量时就会直接从寄存器中进行读取，而我们修改的实际上是内存中的a的值，因此最终打印出a的值是未修改之前的值。
- 如果不想让编译器将const变量优化到寄存器当中，可以用volatile关键字对const变量进行修饰，这时当要读取这个const变量时编译器就会从内存中进行读取，即保持了该变量在内存中的可见性。

### dynamic_cast

dynamic_cast用于将父类的指针（或引用）转换成子类的指针（或引用）。

**向上转型与向下转型**

**向上转型：** 子类的指针（或引用）→ 父类的指针（或引用）。
**向下转型：** 父类的指针（或引用）→ 子类的指针（或引用）。

其中，向上转型就是所说的切割/切片，是语法天然支持的，不需要进行转换，而向下转型是语法不支持的，需要进行强制类型转换。

向下转型分为两种情况：

1. 如果父类的指针（或引用）指向的是一个父类对象，那么将其转换为子类的指针（或引用）是不安全的，因为转换后可能会访问到子类的资源，而这个资源是父类对象所没有的。
2. 如果父类的指针（或引用）指向的是一个子类对象，那么将其转换为子类的指针（或引用）则是安全的。

使用C风格的强制类型转换进行向下转型是不安全的，因为此时无论父类的指针（或引用）指向的是父类对象还是子类对象都会进行转换。而使用dynamic_cast进行向下转型则是安全的，如果父类的指针（或引用）指向的是子类对象那么dynamic_cast会转换成功，但如果父类的指针（或引用）指向的是父类对象那么dynamic_cast会转换失败并返回一个空指针。比如：
```cpp
class A
{
public:
	virtual void f()
	{}
};
class B : public A
{};
void func(A* pa)
{
	B* pb1 = (B*)pa;               //不安全
	B* pb2 = dynamic_cast<B*>(pa); //安全

	cout << "pb1: " << pb1 << endl;
	cout << "pb2: " << pb2 << endl;
}
int main()
{
	A a;
	B b;
	func(&a);
	func(&b);
	return 0;
}
```

上述代码中，如果传入func函数的是子类对象的地址，那么在转换后pb1和pb2都会有对应的地址，但如果传入func函数的是父类对象的地址，那么转换后pb1会有对应的地址，而pb2则是一个空指针。

说明一下： dynamic_cast只能用于含有虚函数的类，因为运行时类型检查需要运行时的类型信息，而这个信息是存储 在虚函数表中的，只有定义了虚函数的类才有虚函数表。

### explicit

explicit用来修饰构造函数，从而禁止单参数构造函数的隐式转换。比如：
```cpp
class A
{
public:
	explicit A(int a)
	{
		cout << "A(int a)" << endl;
	}
	A(const A& a)
	{
		cout << "A(const A& a)" << endl;
	}
private:
	int _a;
};
int main()
{
	A a1(1);
	//A a2 = 1; //error
	return 0;
}
```
在语法上，代码中的A a2 = 1等价于以下两句代码：
```cpp
A tmp(1);  //先构造
A a2(tmp); //再拷贝构造
```

所以在早期的编译器中，当编译器遇到A a2 = 1这句代码时，会先构造一个临时对象，再用这个临时对象拷贝构造a2。但是现在的编译器已经做了优化，当遇到A a2 = 1这句代码时，会直接按照A a2(1)的方式进行处理，这也叫做隐式类型转换。

但对于单参数的自定义类型来说，A a2 = 1这种代码的可读性不是很好，因此可以用explicit修饰单参数的构造函数，从而禁止单参数构造函数的隐式转换。

## RTTI

**RTTI（Run-Time Type Identification）就是运行时类型识别。**

C++通过以下几种方式来支持RTTI：
1. typeid：在运行时识别出一个对象的类型。
2. dynamic_cast：在运行时识别出一个父类的指针（或引用）指向的是父类对象还是子类对象。
3. decltype：在运行时推演出一个表达式或函数返回值的类型。

常见面试题
**1、C++中的4种类型转换分别是：__ 、__ 、__ 、__。**

分别是static_cast、reinterpret_cast、const_cast和dynamic_cast。

**2、说说4种类型转换的应用场景。**

static_cast用于相近类型的类型之间的转换，编译器隐式执行的任何类型转换都可用static_cast。
reinterpret_cast用于两个不相关类型之间的转换。
const_cast用于删除变量的const属性，方便赋值。
dynamic_cast用于安全的将父类的指针（或引用）转换成子类的指针（或引用）。


# AI讲解版C++ 的类型转换

C++ 类型转换可以先分成两大类：

```
类型转换
├── 隐式类型转换
└── 显式类型转换
    ├── static_cast
    ├── dynamic_cast
    ├── const_cast
    └── reinterpret_cast
```

校招面试最重要的是后面四种。

---

## 1. 什么是隐式类型转换

编译器自动完成：

```
int a = 10;
double b = a;
```

这里：

```
int → double
```

由编译器自动转换。

常见隐式转换：

```
int → double
char → int
派生类指针 → 基类指针
非 const → const
```

---

## 2. 隐式转换可能有精度丢失

例如：

```
double value = 3.14;
int number = value;
```

结果：

```
number == 3
```

发生：

```
double → int
```

小数部分被截断。

所以：

> 隐式转换不代表一定安全。

---

## 3. 什么是显式类型转换

程序员主动告诉编译器：

> “我明确知道我要转换成什么类型。”

C 风格：

```
int value = (int)3.14;
```

C++ 风格：

```
int value = static_cast<int>(3.14);
```

现代 C++ 更推荐第二种。

---

## 4. 为什么不推荐 C 风格强转

例如：

```
(T)value
```

问题是：

> 它把多种完全不同的转换行为都混在一个语法里。

你看到：

```
(int*)pointer
```

很难立刻知道：

- 是普通类型转换？
- 去掉 const？
- 指针重新解释？
- 基类派生类转换？

而 C++ 四种 cast 把不同意图明确分开。

---

## 5. `static_cast`

`static_cast` 是最常用的显式转换。

适合：

- 基本类型转换；
- 相关类型之间转换；
- `void*` 与具体指针；
- 类层次中的向上/向下转换；
- 显式调用转换构造或转换函数。

例如：

```
double d = 3.14;

int value = static_cast<int>(d);
```

---

## 6. `static_cast` 的特点

它主要在：

```
编译期
```

完成类型检查。

例如：

```
int value = 10;

double d =
    static_cast<double>(value);
```

它不会进行复杂的运行时类型检查。

所以：

> `static_cast` 更快，但某些向下转换不安全。

---

## 7. 类继承中的向上转换

```
class Base
{
};

class Derived : public Base
{
};
```

派生类转基类：

```
Derived d;

Base* p = &d;
```

可以隐式转换。

也可以：

```
Base* p =
    static_cast<Base*>(&d);
```

这是：

> upcast 向上转换。

通常是安全的。

---

## 8. `static_cast` 向下转换

```
Base* base = ...;

Derived* derived =
    static_cast<Derived*>(base);
```

语法可能允许。

但是：

> 编译器不会检查 `base` 实际指向的是不是 `Derived`。

例如：

```
Base b;

Base* base = &b;

Derived* derived =
    static_cast<Derived*>(base);
```

虽然可能编译通过，但 `derived` 并没有真的指向一个 `Derived` 对象。

后续使用可能产生未定义行为。

所以：

> `static_cast` 向下转换靠程序员自己保证正确。

---

## 9. `dynamic_cast`

`dynamic_cast` 专门用于：

> **继承体系中的安全运行时类型转换。**

例如：

```
class Base
{
public:
    virtual ~Base() = default;
};

class Derived : public Base
{
};
```

使用：

```
Base* base = new Derived;

Derived* derived =
    dynamic_cast<Derived*>(base);
```

如果实际对象真是 `Derived`：

```
derived != nullptr
```

---

## 10. `dynamic_cast` 失败会怎么样

### 指针转换失败

```
Derived* derived =
    dynamic_cast<Derived*>(base);
```

失败：

```
derived == nullptr
```

### 引用转换失败

```
Derived& derived =
    dynamic_cast<Derived&>(baseRef);
```

失败会抛：

```
std::bad_cast
```

所以要记：

```
pointer dynamic_cast 失败 → nullptr
reference dynamic_cast 失败 → std::bad_cast
```

---

## 11. 为什么 `dynamic_cast` 要求多态基类

常见运行时向下转换：

```
dynamic_cast<Derived*>(base)
```

要求源类型通常是多态类型，也就是至少有一个虚函数。

例如：

```
class Base
{
public:
    virtual ~Base() = default;
};
```

原因是运行时需要：

```
RTTI
动态类型信息
```

来判断对象真实类型。

主流实现中 RTTI 常与虚表相关联，但标准并不规定必须通过虚表实现。

---

## 12. `static_cast` 和 `dynamic_cast` 区别

这是面试高频。

| 特点   | `static_cast` | `dynamic_cast`         |
| ---- | ------------- | ---------------------- |
| 检查时机 | 编译期为主         | 运行时                    |
| 向上转换 | 可以            | 可以                     |
| 向下转换 | 可以但不检查真实类型    | 会检查真实类型                |
| 失败检测 | 没有            | `nullptr` / `bad_cast` |
| RTTI | 不需要           | 通常需要                   |
| 性能   | 通常更低开销        | 有运行时检查成本               |

一句话：

> `static_cast` 相信程序员，`dynamic_cast` 帮程序员检查。

---

## 13. `const_cast`

`const_cast` 专门处理：

```
const / volatile
```

例如：

```
int value = 10;

const int* p1 = &value;

int* p2 =
    const_cast<int*>(p1);

*p2 = 20;
```

这里是合法的，因为原对象：

```
value
```

本来不是 const。

---

## 14. 修改真正的 const 对象是未定义行为

例如：

```
const int value = 10;

int* p =
    const_cast<int*>(&value);

*p = 20;
```

虽然可能编译通过，但：

> 修改原本真正声明为 const 的对象属于未定义行为。

所以要准确理解：

> `const_cast` 只是移除“类型层面的 const”，不会把真正的常量对象变成合法可写对象。

---

## 15. `const_cast` 常见用途

主要用于：

- 兼容旧 C 接口；
- 某些 const/non-const 接口复用；
- 处理历史 API；
- 移除不必要的 const 限定。

正常业务代码不应该大量使用。

---

## 16. `reinterpret_cast`

这是四种转换里最危险的。

它表示：

> **按照另一种类型重新解释当前比特/地址。**

例如：

```
int value = 10;

int* p = &value;

std::uintptr_t address =
    reinterpret_cast<std::uintptr_t>(p);
```

或者：

```
void* raw = ...;

SomeType* p =
    reinterpret_cast<SomeType*>(raw);
```

它几乎不做语义层面的安全检查。

---

## 17. `reinterpret_cast` 不会“真正转换对象”

这是一个重要理解。

例如：

```
float f = 3.14f;

int* p =
    reinterpret_cast<int*>(&f);
```

这不代表：

```
float 3.14
变成
int 3
```

而是：

> 把同一块内存地址当作 `int*` 来解释。

这种访问还可能违反严格别名规则、对齐要求，导致未定义行为。

所以它不是普通数值转换。

---

## 18. 四种 cast 的核心职责

可以直接这样记：

```
static_cast
→ 正常、相关类型转换

dynamic_cast
→ 多态继承中的安全运行时转换

const_cast
→ 添加/移除 const、volatile

reinterpret_cast
→ 底层地址/位级重新解释
```

---

## 19. 类类型转换：转换构造函数

例如：

```
class A
{
public:
    A(int value)
    {
    }
};
```

那么：

```
A a = 10;
```

可能发生：

```
int
↓
A(int)
↓
A 对象
```

这叫：

> converting constructor，转换构造函数。

为了禁止隐式转换：

```
class A
{
public:
    explicit A(int value)
    {
    }
};
```

这样：

```
A a = 10; // 错误
```

必须：

```
A a(10);
```

或者：

```
A a =
    static_cast<A>(10);
```

---

## 20. 类型转换运算符

类也可以定义：

```
operator 类型()
```

例如：

```
class Number
{
private:
    int value;

public:
    operator int() const
    {
        return value;
    }
};
```

于是：

```
Number n;

int x = n;
```

会调用：

```
operator int()
```

C++11 以后推荐对可能危险的转换使用：

```
explicit operator bool() const;
```

**关键**
```
operator T()
→ 类对象转换成 T

Number(int)
→ int 转换成 Number

explicit operator T()
→ 防止不必要的隐式转换
```

> **类型转换运算符用于定义类类型向其他类型的转换，C++11 可以使用 `explicit` 限制隐式转换**

## 高频追问

### 1. 四种 C++ 强制转换分别是什么？

回答：

`static_cast` 用于常规相关类型转换；`dynamic_cast` 用于多态继承中的运行时安全转换；`const_cast` 用于调整 const/volatile 属性；`reinterpret_cast` 用于低层地址或表示形式的重新解释。

---

### 2. `static_cast` 和 `dynamic_cast` 区别？

`static_cast` 主要在编译期检查，不验证对象运行时真实类型；`dynamic_cast` 会使用 RTTI 检查动态类型，因此安全但有运行时开销。

---

### 3. `dynamic_cast` 失败怎么办？

```
指针 → nullptr
引用 → 抛 std::bad_cast
```

---

### 4. 为什么 dynamic_cast 需要多态类？

因为运行时需要获得对象的动态类型信息，通常依赖 RTTI，而多态类提供这种运行时类型识别能力。

---

### 5. `const_cast` 后一定可以修改吗？

不一定。

如果原对象本来不是 const，只是通过 const 接口访问，可以合法移除 const 后修改。

如果原对象本身就是 const，修改属于未定义行为。

---

### 6. `reinterpret_cast` 为什么危险？

因为它主要改变编译器对同一地址/比特模式的解释方式，并不保证对象模型、对齐、别名规则等要求成立。

---

## 面试回答模板

面试官问：

> C++ 有哪些类型转换？

C++ 类型转换分为隐式转换和显式转换。显式转换中现代 C++ 主要提供四种 cast。

`static_cast` 用于基本类型和具有明确关系的类型之间转换，也可以进行类继承中的向下转换，但不会检查对象真实动态类型。

`dynamic_cast` 主要用于多态继承体系中的运行时安全转换，通常依赖 RTTI；指针转换失败返回 `nullptr`，引用转换失败抛 `std::bad_cast`。

`const_cast` 用于添加或移除 const/volatile 属性，但如果原对象本身就是 const，移除 const 后修改仍然属于未定义行为。

`reinterpret_cast` 用于底层指针、地址或表示形式的重新解释，安全性最低，应该谨慎使用。

现代 C++ 一般不推荐 C 风格强制转换，因为它无法清晰表达具体转换意图。

## 最后只背这 8 条

1. 隐式转换由编译器自动完成，但也可能丢精度。
2. 现代 C++ 优先使用四种命名 cast，而不是 C 风格强转。
3. `static_cast`：普通、相关类型转换。
4. `dynamic_cast`：多态运行时安全转换。
5. `dynamic_cast` 指针失败返回 `nullptr`，引用失败抛 `bad_cast`。
6. `const_cast`：调整 `const/volatile`。
7. 修改真正的 const 对象仍是未定义行为。
8. `reinterpret_cast` 最危险，只用于底层重新解释。
