## 多态的概念
```
多态就是函数调用的多种形态，使用多态能够使得不同的对象去完成同一件事时，产生不同的动作和结果。
```
例如，在现实生活当中，普通人买票是全价，学生买票是半价，而军人允许优先买票。不同身份的人去买票，所产生的行为是不同的，这就是所谓的多态。

## 多态的定义及实现
### 多态的构成条件
多态是指不同继承关系的类对象，去调用同一函数，产生了不同的行为。在继承中要想构成多态需要满足两个条件：
1. 必须通过基类的指针或者引用调用虚函数。
2. 被调用的函数必须是虚函数，且派生类必须对基类的虚函数进行重写。
### 虚函数
被virtual修饰的类成员函数被称为虚函数。
```cpp
class Person
{
public:
	//被virtual修饰的类成员函数
	virtual void BuyTicket()
	{
		cout << "买票-全价" << endl;
	}
};
```
**需要注意的是：**
1. 只有类的非静态成员函数前可以加virtual，普通函数前不能加virtual。
2. 虚函数这里的virtual和虚继承中的virtual是同一个关键字，但是它们之间没有任何关系。虚函数这里的virtual是为了实现多态，而虚继承的virtual是为了解决菱形继承的数据冗余和二义性。

### 虚函数的重写
虚函数的重写也叫做虚函数的覆盖，若派生类中有一个和基类完全相同的虚函数(返回值类型相同、函数名相同以及参数列表完全相同)，此时我们称该派生类的虚函数重写了基类的虚函数。

例如，我们以下Student和Soldier两个子类重写了父类Person的虚函数。
```cpp
//父类
class Person
{
public:
	//父类的虚函数
	virtual void BuyTicket()
	{
		cout << "买票-全价" << endl;
	}
};
//子类
class Student : public Person
{
public:
	//子类的虚函数重写了父类的虚函数
	virtual void BuyTicket()
	{
		cout << "买票-半价" << endl;
	}
};
//子类
class Soldier : public Person
{
public:
	//子类的虚函数重写了父类的虚函数
	virtual void BuyTicket()
	{
		cout << "优先-买票" << endl;
	}
};
```
现在我们就可以通过父类Person的指针或者引用调用虚函数BuyTicket，此时不同类型的对象，调用的就是不同的函数，产生的也是不同的结果，进而实现了函数调用的多种形态。
```cpp
void Func(Person& p)
{
	//通过父类的引用调用虚函数
	p.BuyTicket();
}
void Func(Person* p)
{
	//通过父类的指针调用虚函数
	p->BuyTicket();
}
int main()
{
	Person p;   //普通人
	Student st; //学生
	Soldier sd; //军人

	Func(p);  //买票-全价
	Func(st); //买票-半价
	Func(sd); //优先买票

	Func(&p);  //买票-全价
	Func(&st); //买票-半价
	Func(&sd); //优先买票
	return 0;
}
```
**注意：** 在重写基类虚函数时，派生类的虚函数不加virtual关键字也可以构成重写，主要原因是因为继承后基类的虚函数被继承下来了，在派生类中依旧保持虚函数属性。但是这种写法不是很规范，因此建议在派生类的虚函数前也加上virtual关键字。
### 虚函数重写的两个例外
```
协变（基类与派生类虚函数的返回值类型不同）
```
派生类重写基类虚函数时，与基类虚函数返回值类型不同。即基类虚函数返回基类对象的指针或者引用，派生类虚函数返回派生类对象的指针或者引用，称为协变。

例如，下列代码中基类Person当中的虚函数fun的返回值类型是基类A对象的指针，派生类Student当中的虚函数fun的返回值类型是派生类B对象的指针，此时也认为派生类Student的虚函数重写了基类Person的虚函数。
```cpp
//基类
class A
{};
//子类
class B : public A
{};
//基类
class Person
{
public:
	//返回基类A的指针
	virtual A* fun()
	{
		cout << "A* Person::f()" << endl;
		return new A;
	}
};
//子类
class Student : public Person
{
public:
	//返回子类B的指针
	virtual B* fun()
	{
		cout << "B* Student::f()" << endl;
		return new B;
	}
};
```
此时，我们通过父类Person的指针调用虚函数fun，父类指针若指向的是父类对象，则调用父类的虚函数，父类指针若指向的是子类对象，则调用子类的虚函数。
```cpp
int main()
{
	Person p;
	Student st;
	//父类指针指向父类对象
	Person* ptr1 = &p;
	//父类指针指向子类对象
	Person* ptr2 = &st;
	//父类指针ptr1指向的p是父类对象，调用父类的虚函数
	ptr1->fun(); //A* Person::f()
	//父类指针ptr2指向的st是子类对象，调用子类的虚函数
	ptr2->fun(); //B* Student::f()
	return 0;
}
```

**析构函数的重写（基类与派生类析构函数的名字不同）**
如果基类的析构函数为虚函数，此时派生类析构函数只要定义，无论是否加virtual关键字，都与基类的析构函数构成重写，虽然基类与派生类析构函数名字不同。

例如，下面代码中父类Person和子类Student的析构函数构成重写。
```cpp
//父类
class Person
{
public:
	virtual ~Person()
	{
		cout << "~Person()" << endl;
	}
};
//子类
class Student : public Person
{
public:
	virtual ~Student()
	{
		cout << "~Student()" << endl;
	}
};
```
那父类和子类的析构函数构成重写的意义何在呢？试想以下场景：分别new一个父类对象和子类对象，并均用父类指针指向它们，然后分别用delete调用析构函数并释放对象空间。
```cpp
int main()
{
	//分别new一个父类对象和子类对象，并均用父类指针指向它们
	Person* p1 = new Person;
	Person* p2 = new Student;

	//使用delete调用析构函数并释放对象空间
	delete p1;
	delete p2;
	return 0;
}
```
在这种场景下，若是父类和子类的析构函数没有构成重写就可能会导致内存泄漏，因为此时delete p1和delete p2都是调用的父类的析构函数，而我们所期望的是p1调用父类的析构函数，p2调用子类的析构函数，即我们期望的是一种多态行为。
此时只有父类和子类的析构函数构成了重写，才能使得delete按照我们的预期进行析构函数的调用，才能实现多态。因此，为了避免出现这种情况，比较建议将父类的析构函数定义为虚函数。

**知识扩展：**  
在继承当中，子类和的析构函数和父类的析构函数构成隐藏的原因就在这里，这里表面上看子类的析构函数和父类的析构函数的函数名不同，但是为了构成重写，编译后析构函数的名字会被统一处理成`destructor();`。
### C++11  override和final
从上面可以看出，C++对函数重写的要求比较严格，有些情况下由于疏忽可能会导致函数名的字母次序写反而无法构成重写，而这种错误在编译期间是不会报错的，直到在程序运行时没有得到预期结果再来进行调试会得不偿失，因此，C++11提供了final和override两个关键字，可以帮助用户检测是否重写。

**final：修饰虚函数，表示该虚函数不能再被重写。**

例如，父类Person的虚函数BuyTicket被final修饰后就不能再被重写了，子类若是重写了父类的BuyTicket函数则编译报错。
```cpp
//父类
class Person
{
public:
	//被final修饰，该虚函数不能再被重写
	virtual void BuyTicket() final
	{
		cout << "买票-全价" << endl;
	}
};
//子类
class Student : public Person
{
public:
	//重写，编译报错
	virtual void BuyTicket()
	{
		cout << "买票-半价" << endl;
	}
};
//子类
class Soldier : public Person
{
public:
	//重写，编译报错
	virtual void BuyTicket()
	{
		cout << "优先-买票" << endl;
	}
};
```

**override：检查派生类虚函数是否重写了基类的某个虚函数，如果没有重写则编译报错**

例如，子类Student和Soldier的虚函数BuyTicket被override修饰，编译时就会检查子类的这两个BuyTicket函数是否重写了父类的虚函数，如果没有则会编译报错。
```cpp
//父类
class Person
{
public:
	virtual void BuyTicket()
	{
		cout << "买票-全价" << endl;
	}
};
//子类
class Student : public Person
{
public:
	//子类完成了父类虚函数的重写，编译通过
	virtual void BuyTicket() override
	{
		cout << "买票-半价" << endl;
	}
};
//子类
class Soldier : public Person
{
public:
	//子类没有完成了父类虚函数的重写，编译报错
	virtual void BuyTicket(int i) override
	{
		cout << "优先-买票" << endl;
	}
};
```

## AI讲解C++ 多态的概念、定义与实现

先记住最核心的定义：
> **多态是指同一个接口，在面对不同对象时，可以表现出不同的行为。**

“多态”字面意思就是：
```text
多种形态
```
例如，游戏中不同角色都具有攻击行为：
```cpp
player.Attack();
enemy.Attack();
boss.Attack();
```
虽然调用的接口都叫：
```cpp
Attack()
```
但不同对象执行的行为不同：
```text
Player → 使用剑攻击
Enemy  → 普通攻击
Boss   → 释放特殊技能
```
这就是多态。

---
### 一、为什么需要多态？

假设有不同类型的角色：

```cpp
class Player
{
public:
    void Attack()
    {
        std::cout << "Player uses sword\n";
    }
};

class Enemy
{
public:
    void Attack()
    {
        std::cout << "Enemy attacks\n";
    }
};

class Boss
{
public:
    void Attack()
    {
        std::cout << "Boss uses fire skill\n";
    }
};
```
如果不使用多态，处理角色时可能需要判断类型：
```cpp
void ExecuteAttack(int type)
{
    if (type == 1)
    {
        // 玩家攻击
    }
    else if (type == 2)
    {
        // 敌人攻击
    }
    else if (type == 3)
    {
        // Boss 攻击
    }
}
```
随着角色类型增加：
```text
Player
Enemy
Boss
NPC
Summon
EliteEnemy
```
判断分支会越来越多。
使用多态后，可以设计一个统一接口：
```cpp
class Character
{
public:
    virtual void Attack() = 0;
};
```
不同派生类分别实现：
```cpp
class Player : public Character
{
public:
    void Attack() override
    {
        std::cout << "Player uses sword\n";
    }
};

class Boss : public Character
{
public:
    void Attack() override
    {
        std::cout << "Boss uses fire skill\n";
    }
};
```
处理函数只依赖统一接口：
```cpp
void ExecuteAttack(Character& character)
{
    character.Attack();
}
```
调用：
```cpp
Player player;
Boss boss;

ExecuteAttack(player);
ExecuteAttack(boss);
```
输出：
```text
Player uses sword
Boss uses fire skill
```
`ExecuteAttack` 不需要知道具体对象是玩家还是 Boss。

这就是多态的核心价值：
> **调用者面向统一接口编程，具体行为由实际对象决定。**

---
### 二、C++ 多态分为哪几类？
C++ 中通常把多态分为两类：
```text
编译时多态
运行时多态
```
也叫：
```text
静态多态
动态多态
```

---
### 三、编译时多态
编译时多态是指：
> 编译器在编译阶段就能确定具体调用哪个函数或生成哪份代码。

常见实现包括：
```text
函数重载
运算符重载
函数模板
类模板
```

---
#### 1. 函数重载
```cpp
void Print(int value)
{
    std::cout << "int: " << value << '\n';
}

void Print(double value)
{
    std::cout << "double: " << value << '\n';
}

void Print(const std::string& value)
{
    std::cout << "string: " << value << '\n';
}
```
调用：
```cpp
Print(10);
Print(3.14);
Print(std::string("hello"));
```
虽然函数名都是：
```cpp
Print
```
但编译器根据参数类型选择不同函数。

这是：
> 同一个函数名，对不同参数类型表现出不同形式。

编译时已经确定调用目标，所以叫编译时多态。

---
#### 2. 模板
```cpp
template <typename T>
T Add(const T& a, const T& b)
{
    return a + b;
}
```
使用：
```cpp
int a = Add(10, 20);
double b = Add(1.5, 2.5);
```
编译器根据类型实例化不同版本：
```cpp
Add<int>
Add<double>
```
模板也属于编译时多态。

---
### 四、运行时多态

运行时多态是指：
> 编译阶段只知道使用的是基类接口，程序运行时才根据对象的实际类型决定调用哪个函数。

C++ 中运行时多态通常通过：
```text
继承
虚函数
基类指针或引用
```
共同实现。

---
### 五、运行时多态的三个必要条件

经典情况下，需要满足三个条件：
#### 条件一：存在继承关系

```cpp
class Derived : public Base
{
};
```

---
#### 条件二：基类函数声明为 `virtual`

```cpp
class Base
{
public:
    virtual void Func()
    {
        std::cout << "Base::Func\n";
    }
};
```

---
#### 条件三：通过基类指针或引用调用虚函数
```cpp
Derived derived;

Base* pointer = &derived;
pointer->Func();
```
或者：
```cpp
Base& reference = derived;
reference.Func();
```
满足这三个条件时，调用的具体函数由对象的动态类型决定。

---
### 六、完整运行时多态示例

```cpp
#include <iostream>

class Character
{
public:
    virtual void Attack()
    {
        std::cout << "Character attack\n";
    }
};

class Player : public Character
{
public:
    void Attack() override
    {
        std::cout << "Player uses sword\n";
    }
};

class Boss : public Character
{
public:
    void Attack() override
    {
        std::cout << "Boss uses fire skill\n";
    }
};

void ExecuteAttack(Character& character)
{
    character.Attack();
}

int main()
{
    Player player;
    Boss boss;

    ExecuteAttack(player);
    ExecuteAttack(boss);
}
```
输出：
```text
Player uses sword
Boss uses fire skill
```
虽然函数参数类型始终是：
```cpp
Character&
```
但传入对象分别是：
```text
Player
Boss
```
所以最终调用不同版本。

---
### 七、静态类型和动态类型
理解多态，必须区分两个概念：
```text
静态类型
动态类型
```
例如：
```cpp
Player player;
Character* ptr = &player;
```
这里：
```text
ptr 的静态类型：Character*
ptr 指向对象的动态类型：Player
```

---
#### 静态类型

静态类型是编译时看到的类型。
```cpp
Character* ptr;
```
所以 `ptr` 的静态类型是：
```cpp
Character*
```

编译器根据静态类型判断：
- 可以访问哪些成员；
- 表达式是否合法；
- 是否存在对应函数。

---
#### 动态类型

动态类型是指针或引用实际绑定对象的真实类型。
```cpp
Character* ptr = &player;
```
实际对象是：
```cpp
Player
```
所以动态类型是 `Player`。

虚函数调用根据动态类型决定：
```cpp
ptr->Attack();
```
最终调用：
```cpp
Player::Attack()
```

---
### 八、没有 `virtual` 会怎样？

看下面代码：
```cpp
class Character
{
public:
    void Attack()
    {
        std::cout << "Character attack\n";
    }
};

class Player : public Character
{
public:
    void Attack()
    {
        std::cout << "Player attack\n";
    }
};
```
调用：
```cpp
Player player;
Character* ptr = &player;

ptr->Attack();
```
输出：
```text
Character attack
```

为什么？
因为 `Attack()` 不是虚函数，编译器按照指针的静态类型：
```cpp
Character*
```
在编译阶段就绑定到：
```cpp
Character::Attack()
```
这叫：
```text
静态绑定
早绑定
```

---
加入 `virtual`：
```cpp
class Character
{
public:
    virtual void Attack()
    {
        std::cout << "Character attack\n";
    }
};
```
再次调用：
```cpp
ptr->Attack();
```
输出：
```text
Player attack
```
此时程序运行时根据实际对象类型选择函数。

这叫：
```text
动态绑定
晚绑定
```

### 九、`override` 是什么？

派生类重写虚函数时，推荐加：
```cpp
override
```
例如：
```cpp
class Player : public Character
{
public:
    void Attack() override
    {
        std::cout << "Player attack\n";
    }
};
```
`override` 表示：
> 这个函数必须重写某个基类虚函数。

它可以帮助编译器发现错误。

例如基类：
```cpp
class Character
{
public:
    virtual void Attack(int damage)
    {
    }
};
```
派生类错误地写成：
```cpp
class Player : public Character
{
public:
    void Attack() override
    {
    }
};
```
编译器会报错，因为参数不同，实际上没有成功重写。
如果不写 `override`，这个错误可能被误认为只是定义了一个新的同名函数。

因此推荐：
> 派生类重写虚函数时始终使用 `override`。

---
### 十、什么叫虚函数重写？
基类：
```cpp
virtual void Attack();
```
派生类：
```cpp
void Attack() override;
```
派生类函数替换了基类虚函数在派生对象上的实际行为，这叫：
```text
重写
Override
```

要成功重写，通常要求：
- 函数名相同；
- 参数列表相同；
- `const` 限定相同；
- 引用限定等匹配；
- 返回类型相同或满足协变返回规则。

例如：
```cpp
class Base
{
public:
    virtual void Func() const
    {
    }
};

class Derived : public Base
{
public:
    void Func() const override
    {
    }
};
```
如果派生类漏掉 `const`：
```cpp
void Func() override;
```
就不是相同函数签名，`override` 会帮助发现问题。

---
### 十一、隐藏、重载和重写的区别

这三个概念很容易混淆。
#### 1. 重载 Overload
发生在同一作用域：
```cpp
void Func(int);
void Func(double);
```

特点：
- 函数名相同；
- 参数不同；
- 编译时决定。

---
#### 2. 重写 Override
发生在继承体系中：
```cpp
class Base
{
public:
    virtual void Func();
};

class Derived : public Base
{
public:
    void Func() override;
};
```

特点：
- 基类函数必须是虚函数；
- 派生类提供对应实现；
- 可形成运行时多态。

---
#### 3. 隐藏 Hide

派生类声明了同名成员，会隐藏基类同名成员：
```cpp
class Base
{
public:
    void Func();
};

class Derived : public Base
{
public:
    void Func(int);
};
```
虽然参数不同，`Derived::Func(int)` 仍会隐藏 `Base::Func()`。

总结：
```text
重载：同一作用域，参数不同
重写：继承关系，虚函数，多态
隐藏：派生类同名成员遮蔽基类成员
```

---
### 十二、为什么多态必须使用指针或引用？

下面会发生对象切片：
```cpp
void ExecuteAttack(Character character)
{
    character.Attack();
}

Player player;
ExecuteAttack(player);
```
参数按值传递，`Player` 对象的派生类部分被切掉，只剩下一个独立的 `Character` 对象。
所以不能保留动态类型信息。

正确写法：
```cpp
void ExecuteAttack(Character& character)
{
    character.Attack();
}
```
或者：
```cpp
void ExecuteAttack(Character* character)
{
    character->Attack();
}
```
因为指针和引用不会创建新的基类对象，不会发生对象切片。

因此：
```text
基类对象按值接收派生类 → 切片
基类引用绑定派生类     → 保留真实对象
基类指针指向派生类     → 保留真实对象
```

---
### 十三、纯虚函数

有些基类只想规定接口，不提供通用实现。
可以写纯虚函数：
```cpp
class Character
{
public:
    virtual void Attack() = 0;
};
```
其中：
```cpp
= 0
```
表示这是纯虚函数。

它的含义是：
> `Character` 要求派生类提供 `Attack()` 行为。

派生类实现：
```cpp
class Player : public Character
{
public:
    void Attack() override
    {
        std::cout << "Player attack\n";
    }
};
```

---
### 十四、抽象类

只要类中存在至少一个纯虚函数，这个类就是抽象类。
```cpp
class Character
{
public:
    virtual void Attack() = 0;
};
```
不能直接创建对象：
```cpp
// Character character; // 错误
```
因为“普通角色”没有确定的攻击行为。
但可以创建指针或引用：
```cpp
Character* pointer;
Character& reference = player;
```
抽象类的作用通常是：
```text
规定统一接口
建立类型体系
支持运行时多态
```

例如：
```cpp
class IDamageable
{
public:
    virtual void TakeDamage(float damage) = 0;
    virtual ~IDamageable() = default;
};
```
任何可受伤害对象都必须实现：
```cpp
TakeDamage()
```

---
### 十五、虚析构函数
只要一个类会被用作多态基类，通常应该让析构函数成为虚函数：
```cpp
class Character
{
public:
    virtual ~Character() = default;

    virtual void Attack() = 0;
};
```

为什么？

看下面代码：
```cpp
class Base
{
public:
    ~Base()
    {
        std::cout << "Base destructor\n";
    }
};

class Derived : public Base
{
public:
    ~Derived()
    {
        std::cout << "Derived destructor\n";
    }
};
```
使用：
```cpp
Base* ptr = new Derived;
delete ptr;
```
如果基类析构函数不是虚函数，通过基类指针删除派生对象会产生未定义行为，常见表现是派生类析构函数未被正确调用。

可能只输出：
```text
Base destructor
```
派生类资源没有释放。

正确写法：
```cpp
class Base
{
public:
    virtual ~Base()
    {
        std::cout << "Base destructor\n";
    }
};
```
此时：
```cpp
delete ptr;
```
会正确执行：
```text
Derived destructor
Base destructor
```

所以必须记住：
> **多态基类应当具有虚析构函数。**

---
### 十六、虚函数的底层实现

C++ 标准并没有强制编译器必须使用某一种底层实现，但主流编译器通常使用：

```text
虚函数表 vtable
虚函数表指针 vptr
```

---
#### 1. 虚函数表 `vtable`
如果类中存在虚函数，编译器通常会为该类生成一张虚函数表。

例如：
```cpp
class Character
{
public:
    virtual void Attack();
    virtual void Move();
};
```
概念上可能有一张表：
```text
Character vtable
├── Character::Attack
└── Character::Move
```
派生类：
```cpp
class Player : public Character
{
public:
    void Attack() override;
};
```
对应的虚函数表可能是：
```text
Player vtable
├── Player::Attack
└── Character::Move
```
因为 `Player` 重写了 `Attack()`，所以表中的函数地址被替换。

---
#### 2. 虚函数表指针 `vptr`
含有虚函数的对象通常会额外包含一个隐藏指针：
```text
vptr
```
它指向该对象所属动态类型的虚函数表。
概念上：
```text
Player 对象
├── vptr ─────→ Player vtable
├── Character 基类成员
└── Player 自己的成员
```

---
#### 3. 虚函数调用过程
代码：
```cpp
Character* ptr = new Player;
ptr->Attack();
```
大致执行：
```text
1. ptr 找到实际对象
2. 从对象中取得 vptr
3. 通过 vptr 找到 Player 的 vtable
4. 在表中查找 Attack 对应函数地址
5. 调用 Player::Attack()
```
所以最终行为由对象的实际类型决定。

---
### 十七、普通函数调用和虚函数调用对比
#### 普通函数
```cpp
ptr->NormalFunc();
```
编译器通常根据静态类型直接决定目标：
```text
Character::NormalFunc
```
这叫静态绑定。

---
#### 虚函数
```cpp
ptr->VirtualFunc();
```
程序运行时通过对象的虚函数机制决定目标：
```text
Player::VirtualFunc
```
这叫动态绑定。

---
### 十八、虚函数的开销

运行时多态通常会带来一些额外成本：

1. 对象中可能增加一个 `vptr`；
2. 每个多态类通常有一张虚函数表；
3. 虚函数调用通常需要一次间接寻址；
4. 某些情况下不容易内联；
5. 虚继承、多继承下对象布局和指针调整更复杂。

但这些开销通常很小。
在需要灵活扩展和统一接口时，多态带来的设计价值通常更重要。

游戏开发中，虚函数很常见，但在极端高频路径中也要考虑：
- 缓存局部性；
- 分支预测；
- 间接调用；
- 对象分散；
- 数据导向设计。

---
### 十九、构造函数和析构函数中的虚函数调用

这是一个重要细节。

假设：
```cpp
class Base
{
public:
    Base()
    {
        Func();
    }

    virtual void Func()
    {
        std::cout << "Base::Func\n";
    }
};

class Derived : public Base
{
public:
    void Func() override
    {
        std::cout << "Derived::Func\n";
    }
};
```
创建：
```cpp
Derived object;
```
在 `Base` 构造函数中调用 `Func()`，通常调用的是：
```cpp
Base::Func()
```
而不是 `Derived::Func()`。

原因是：
> 构造基类时，派生类部分还没有构造完成。

析构过程中同理：
> 派生类部分已经开始销毁后，不会再把对象当作完整派生类进行虚调用。

因此一般不建议在构造函数和析构函数中依赖虚函数多态行为。

### 二十、`final`

**`final` 可以阻止继续重写或继续继承。**
#### 阻止函数继续重写
```cpp
class Base
{
public:
    virtual void Func()
    {
    }
};

class Derived : public Base
{
public:
    void Func() final
    {
    }
};
```
再派生：
```cpp
class MoreDerived : public Derived
{
public:
    // void Func() override; // 错误
};
```

---
#### 阻止类继续被继承
```cpp
class Boss final : public Character
{
};
```
不能再写：
```cpp
// class SuperBoss : public Boss {};
```

### 二十一、一个完整的游戏示例

```cpp
#include <iostream>
#include <memory>
#include <vector>

class Character
{
public:
    virtual void Attack() const = 0;

    virtual ~Character() = default;
};

class Player final : public Character
{
public:
    void Attack() const override
    {
        std::cout << "Player uses sword\n";
    }
};

class Enemy : public Character
{
public:
    void Attack() const override
    {
        std::cout << "Enemy performs normal attack\n";
    }
};

class Boss : public Enemy
{
public:
    void Attack() const override
    {
        std::cout << "Boss casts fire storm\n";
    }
};

int main()
{
    std::vector<std::unique_ptr<Character>> characters;

    characters.push_back(std::make_unique<Player>());
    characters.push_back(std::make_unique<Enemy>());
    characters.push_back(std::make_unique<Boss>());

    for (const auto& character : characters)
    {
        character->Attack();
    }
}
```
输出：
```text
Player uses sword
Enemy performs normal attack
Boss casts fire storm
```
容器中存放的统一类型是：
```cpp
std::unique_ptr<Character>
```
但每个对象的动态类型不同：
```text
Player
Enemy
Boss
```
虚函数让它们通过统一接口执行各自行为。

### 二十二、多态的优点

多态可以：
- 统一不同对象的调用接口；
- 减少大量类型判断；
- 降低调用者和具体类型之间的耦合；
- 提高系统扩展性；
- 支持面向接口编程；
- 满足开闭原则；
- 方便实现插件、事件、角色、渲染对象等系统。

例如新增一个敌人：
```cpp
class IceBoss : public Character
{
public:
    void Attack() const override
    {
        std::cout << "IceBoss casts ice skill\n";
    }
};
```
原来的处理函数：
```cpp
void ExecuteAttack(Character& character)
{
    character.Attack();
}
```
完全不用修改。

---
### 二十三、多态的缺点

运行时多态也有代价：
- 类之间产生继承耦合；
- 对象布局更复杂；
- 虚函数调用有少量间接调用开销；
- 调试调用目标有时不够直观；
- 基类设计错误会影响所有派生类；
- 容易形成过深的继承树；
- 按值使用时容易发生对象切片。

因此现代设计通常强调：
```text
合理使用继承和多态
优先考虑组合
避免过深的继承体系
```

### 二十四、编译时多态与运行时多态对比

|对比项|编译时多态|运行时多态|
|---|---|---|
|决定时间|编译阶段|程序运行阶段|
|常见机制|重载、模板|继承、虚函数|
|是否需要继承|不一定|通常需要|
|性能|通常更容易优化|有间接调用开销|
|灵活性|类型编译时确定|运行时可替换对象|
|典型例子|`Print(int)`、模板|`Base*` 调用派生类虚函数|

### 二十五、常见错误
#### 1. 忘记把基类函数声明为 `virtual`
```cpp
class Base
{
public:
    void Func();
};
```
通过基类指针调用时不会形成动态多态。

---
#### 2. 按值传递基类对象
```cpp
void Process(Base object);
```
传入派生类会发生对象切片。

推荐：
```cpp
void Process(Base& object);
void Process(const Base& object);
```

---
#### 3. 多态基类没有虚析构函数
```cpp
class Base
{
public:
    ~Base() = default;
};
```
如果通过 `Base*` 删除派生对象，会产生未定义行为。

推荐：
```cpp
virtual ~Base() = default;
```

---
#### 4. 派生类重写函数时不写 `override`
容易因参数或 `const` 不匹配而没有真正重写。

推荐：
```cpp
void Func() override;
```

---
#### 5. 把同名函数隐藏当作重写
```cpp
class Base
{
public:
    virtual void Func(int);
};

class Derived : public Base
{
public:
    void Func();
};
```
参数不同，不是重写。

### 二十六、面试回答版本

面试官问：
> 什么是 C++ 多态？如何实现？

可以这样回答：

多态是指同一个接口作用于不同类型对象时，可以表现出不同的行为。C++ 多态通常分为编译时多态和运行时多态。

编译时多态在编译阶段确定调用目标，常见实现包括函数重载、运算符重载和模板。

运行时多态通过公有继承、虚函数以及基类指针或引用实现。基类将成员函数声明为 `virtual`，派生类使用 `override` 重写该函数。当基类指针或引用绑定到派生类对象并调用虚函数时，程序会根据对象的动态类型选择派生类版本。

主流编译器通常通过虚函数表和虚函数表指针实现动态分派。对象中的虚表指针指向对应动态类型的虚函数表，虚函数调用时通过虚表找到实际函数地址。

多态基类通常还应提供虚析构函数，以保证通过基类指针删除派生对象时能正确执行完整析构过程。

---
### 二十七、最终总结

必须记住：
```text
多态：
同一个接口，不同对象产生不同结果
```

C++ 两类多态：
```text
编译时多态：
重载、模板

运行时多态：
继承、虚函数、基类指针或引用
```

运行时多态三个核心条件：
```text
1. 有继承关系
2. 基类函数是 virtual
3. 通过基类指针或引用调用
```

底层常见实现：
```text
对象中的 vptr
        ↓
类对应的 vtable
        ↓
派生类实际虚函数
```

最核心的一句话：
> **C++ 运行时多态就是通过基类指针或引用调用虚函数，在运行时根据对象的真实类型选择对应的派生类实现。**
