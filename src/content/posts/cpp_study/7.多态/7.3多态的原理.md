## 多态的原理
### 虚函数表

**下面是一道常考的笔试题：Base类实例化出对象的大小是多少？**
```cpp
class Base
{
public:
	virtual void Func1()
	{
		cout << "Func1()" << endl;
	}
private:
	int _b = 1;
};
```
通过观察测试，我们发现Base类实例化的对象b的大小是8个字节。
```cpp
int main()
{
	Base b;
	cout << sizeof(b) << endl; //8
	return 0;
}
```
b对象当中除了_b成员外，实际上还有一个_vfptr放在对象的前面（有些平台可能会放到对象的最后面，这个跟平台有关）。
![](../../_Pasted_Image/Pasted%20image%2020260730145118.png)
对象中的这个指针叫做虚函数表指针，简称虚表指针，虚表指针指向一个虚函数表，简称虚表，每一个含有虚函数的类中都至少有一个虚表指针。

**虚函数表中到底放的是什么？**
下面Base类当中有三个成员函数，其中Func1和Func2是虚函数，Func3是普通成员函数，子类Derive当中仅对父类的Func1函数进行了重写。
```cpp
#include <iostream>
using namespace std;
//父类
class Base
{
public:
	//虚函数
	virtual void Func1()
	{
		cout << "Base::Func1()" << endl;
	}
	//虚函数
	virtual void Func2()
	{
		cout << "Base::Func2()" << endl;
	}
	//普通成员函数
	void Func3()
	{
		cout << "Base::Func3()" << endl;
	}
private:
	int _b = 1;
};
//子类
class Derive : public Base
{
public:
	//重写虚函数Func1
	virtual void Func1()
	{
		cout << "Derive::Func1()" << endl;
	}
private:
	int _d = 2;
};
int main()
{
	Base b;
	Derive d;
	return 0;
}
```
通过调试可以发现，父类对象b和基类对象d当中除了自己的成员变量之外，父类和子类对象都有一个虚表指针，分别指向属于自己的虚表。
![](../../_Pasted_Image/Pasted%20image%2020260730145407.png)
实际上虚表当中存储的就是虚函数的地址，因为父类当中的Func1和Func2都是虚函数，所以父类对象b的虚表当中存储的就是虚函数Func1和Func2的地址。

而子类虽然继承了父类的虚函数Func1和Func2，但是子类对父类的虚函数Func1进行了重写，因此，子类对象d的虚表当中存储的是父类的虚函数Func2的地址和重写的Func1的地址。这就是为什么虚函数的重写也叫做覆盖，覆盖就是指虚表中虚函数地址的覆盖，重写是语法的叫法，覆盖是原理层的叫法。

其次需要注意的是：Func2是虚函数，所以继承下来后放进了子类的虚表，而Func3是普通成员函数，继承下来后不会放进子类的虚表。此外，**虚函数表本质是一个存虚函数指针的指针数组**，一般情况下会在这个数组最后放一个nullptr。

**总结一下，派生类的虚表生成步骤如下：**
1. 先将基类中的虚表内容拷贝一份到派生类的虚表。
2. 如果派生类重写了基类中的某个虚函数，则用派生类自己的虚函数地址覆盖虚表中基类的虚函数地址。
3. 派生类自己新增加的虚函数按其在派生类中的声明次序增加到派生类虚表的最后。

**虚表是什么阶段初始化的？虚函数存在哪里？虚表存在哪里？**
虚表实际上是在构造函数初始化列表阶段进行初始化 的，注意虚表当中存的是虚函数的地址不是虚函数，虚函数和普通函数一样，都是存在代码段的，只是他的地址又存到了虚表当中。另外，对象中存的不是虚表而是指向虚表的指针。
至于虚表是存在哪里的，我们可以通过以下这段代码进行判断。
```cpp
int j = 0;
int main()
{
	Base b;
	Base* p = &b;
	printf("vfptr:%p\n", *((int*)p)); //000FDCAC
	int i = 0;
	printf("栈上地址:%p\n", &i);       //005CFE24
	printf("数据段地址:%p\n", &j);     //0010038C

	int* k = new int;
	printf("堆上地址:%p\n", k);       //00A6CA00
	char* cp = "hello world";
	printf("代码段地址:%p\n", cp);    //000FDCB4
	return 0;
}
```
代码当中打印了对象b当中的虚表指针，也就是虚表的地址，可以发现虚表地址与代码段的地址非常接近，由此我们可以得出**虚表实际上是存在代码段的。**

### 多态的原理
**那到底多态的原理是什么？**
例如，下面代码中，为什么当父类Person指针指向的是父类对象Mike时，调用的就是父类的BuyTicket，当父类Person指针指向的是子类对象Johnson时，调用的就是子类的BuyTicket?
```cpp
#include <iostream>
using namespace std;
//父类
class Person
{
public:
	virtual void BuyTicket()
	{
		cout << "买票-全价" << endl;
	}
	int _p = 1;
};
//子类
class Student : public Person
{
public:
	virtual void BuyTicket()
	{
		cout << "买票-半价" << endl;
	}
	int _s = 2;
};
int main()
{
	Person Mike;
	Student Johnson;
	Johnson._p = 3; //以便观察是否完成切片
	Person* p1 = &Mike;
	Person* p2 = &Johnson;
	p1->BuyTicket(); //买票-全价
	p2->BuyTicket(); //买票-半价
	return 0;
}
```
通过调试可以发现，对象Mike中包含一个成员变量_p和一个虚表指针，对象Johnson中包含两个成员变量_p和_s以及一个虚表指针，这两个对象当中的虚表指针分别指向自己的虚表。
![](../../_Pasted_Image/Pasted%20image%2020260730150043.png)
围绕此图分析便可得到多态的原理：
1. 父类指针p1指向Mike对象，p1->BuyTicket在Mike的虚表中找到的虚函数就是Person::BuyTicket。
2. 父类指针p2指向Johnson对象，p2>BuyTicket在Johnson的虚表中找到的虚函数就是Student::BuyTicket。

这样就实现出了不同对象去完成同一行为时，展现出不同的形态。
```
现在想想多态构成的两个条件，一是完成虚函数的重写，二是必须使用父类的指针或者引用去调用虚函数。必须完成虚函数的重写是因为我们需要完成子类虚表当中虚函数地址的覆盖，那为什么必须使用父类的指针或者引用去调用虚函数呢？为什么使用父类对象去调用虚函数达不到多态的效果呢？
```

```cpp
Person* p1 = &Mike;
Person* p2 = &Johnson;
```
使用父类指针或者引用时，实际上是一种切片行为，切片时只会让父类指针或者引用得到父类对象或子类对象中切出来的那一部分。
![](../../_Pasted_Image/Pasted%20image%2020260730150303.png)
因此，我们后序用p1和p2调用虚函数时，p1和p2通过虚表指针找到的虚表是不一样的，最终调用的函数也是不一样的。
```cpp
Person p1 = Mike;
Person p2 = Johnson;
```
使用父类对象时，切片得到部分成员变量后，会调用父类的拷贝构造函数对那部分成员变量进行拷贝构造，而拷贝构造出来的父类对象p1和p2当中的虚表指针指向的都是父类对象的虚表。因为同类型的对象共享一张虚表，他们的虚表指针指向的虚表是一样的。
![](../../_Pasted_Image/Pasted%20image%2020260730150325.png)
因此，我们后序用p1和p2调用虚函数时，p1和p2通过虚表指针找到的虚表是一样的，最终调用的函数也是一样的，也就无法构成多态。

**总结一下：**
1. 构成多态，指向谁就调用谁的虚函数，跟对象有关。
2. 不构成多态，对象类型是什么就调用谁的虚函数，跟类型有关。

### 动态绑定和静态绑定
**静态绑定：** 静态绑定又称为前期绑定(早绑定)，在程序编译期间确定了程序的行为，也成为静态多态，比如：函数重载。

**动态绑定：** 动态绑定又称为后期绑定(晚绑定)，在程序运行期间，根据具体拿到的类型确定程序的具体行为，调用具体的函数，也称为动态多态。

我们可以通过查看汇编的方式进一步理解静态绑定和动态绑定。
对于下列代码：
```cpp
//父类
class Person
{
public:
	virtual void BuyTicket()
	{
		cout << "买票-全价" << endl;
	}
};
//子类
class Student : public Person
{
public:
	virtual void BuyTicket()
	{
		cout << "买票-半价" << endl;
	}
};
```
我们若是按照如下方式调用BuyTicket函数，则不构成多态，函数的调用是在编译时确定的。
```cpp
int main()
{
	Student Johnson;
	Person p = Johnson; //不构成多态
	p.BuyTicket();
	return 0;
}
```
将调用函数的那句代码翻译成汇编就只有以下两条汇编指令，也就是直接调用的函数。
![](../../_Pasted_Image/Pasted%20image%2020260730151813.png)
而我们若是按照如下方式调用BuyTicket函数，则构成多态，函数的调用是在运行时确定的。
```cpp
int main()
{
	Student Johnson;
	Person& p = Johnson; //构成多态
	p.BuyTicket();
	return 0;
}
```
相比不构成多态时的代码，构成多态时调用函数的那句代码翻译成汇编后就变成了八条汇编指令，主要原因就是我们需要在运行时，先到指定对象的虚表中找到要调用的虚函数，然后才能进行函数的调用。
![](../../_Pasted_Image/Pasted%20image%2020260730151836.png)
这样就很好的体现了静态绑定是在编译时确定的，而动态绑定是在运行时确定的。

## 单继承和多继承关系的虚函数表
### 单继承中的虚函数表
以下列单继承关系为例，我们来看看基类和派生类的虚表模型。
```cpp
//基类
class Base
{
public:
	virtual void func1() { cout << "Base::func1()" << endl; }
	virtual void func2() { cout << "Base::func2()" << endl; }
private:
	int _a;
};
//派生类
class Derive : public Base
{
public:
	virtual void func1() { cout << "Derive::func1()" << endl; }
	virtual void func3() { cout << "Derive::func3()" << endl; }
	virtual void func4() { cout << "Derive::func4()" << endl; }
private:
	int _b;
};
```
其中，基类和派生类对象的虚表模型如下：
![](../../_Pasted_Image/Pasted%20image%2020260730160810.png)

在单继承关系当中，派生类的虚表生成过程如下：
1. 继承基类的虚表内容到派生类的虚表。
2. 对派生类重写了的虚函数地址进行覆盖，比如func1。
3. 虚表当中新增派生类当中新的虚函数地址，比如func3和func4。

```
在调试过程中，某些编译器的监视窗口当中看不到虚表当中的func3和func4，可能是编译器的监视窗口故意隐藏了这两个函数，也可以认为这是一个小bug，此时如果我们想要看到派生类对象完整的虚表有两个方法。
```
**一、使用内存监视窗口**  
使用内存监视窗口看到的内容是最真实的，我们调出内存监视窗口，然后输入派生类对象当中的虚表指针，即可看到虚表当中存储的四个虚函数地址。
![](../../_Pasted_Image/Pasted%20image%2020260730160944.png)

**二、使用代码打印虚表内容**  
我们可以使用以下代码，打印上述基类和派生类对象的虚表内容，在打印过程中可以顺便用虚函数地址调用对应的虚函数，从而打印出虚函数的函数名，这样可以进一步确定虚表当中存储的是哪一个函数的地址。
```cpp
typedef void(*VFPTR)(); //虚函数指针类型重命名
//打印虚表地址及其内容
void PrintVFT(VFPTR* ptr)
{
	printf("虚表地址:%p\n", ptr);
	for (int i = 0; ptr[i] != nullptr; i++)
	{
		printf("ptr[%d]:%p-->", i, ptr[i]); //打印虚表当中的虚函数地址
		ptr[i](); //使用虚函数地址调用虚函数
	}
	printf("\n");
}
int main()
{
	Base b;
	PrintVFT((VFPTR*)(*(int*)&b)); //打印基类对象b的虚表地址及其内容
	Derive d;
	PrintVFT((VFPTR*)(*(int*)&d)); //打印派生类对象d的虚表地址及其内容
	return 0;
}
```

### 多继承中的虚函数表
以下列多继承关系为例，我们来看看基类和派生类的虚表模型。

```cpp
class Base1
{

	virtual void func2() { cout << "Base1::func2()" << endl; }

	int _b1;
};
//基类2
class Base2
{
public:
	virtual void func1() { cout << "Base2::func1()" << endl; }

	int _b2;
};
//多继承派生类
class Derive : public Base1, public Base2
{
public:
	virtual void func1() { cout << "Derive::func1()" << endl; }
	virtual void func3() { cout << "Derive::func3()" << endl; }

	int _d1;
};
```
其中，两个基类的虚表模型如下：
![](../../_Pasted_Image/Pasted%20image%2020260730161243.png)

在多继承关系当中，派生类的虚表生成过程如下：
1. 分别继承各个基类的虚表内容到派生类的各个虚表当中。
2. 对派生类重写了的虚函数地址进行覆盖(派生类中的各个虚表中存有该被重写虚函数地址的都需要进行覆盖)，比如func1。
3. 在派生类第一个继承基类部分的虚表当中新增派生类当中新的虚函数地址，比如func3。

**这里在调试时，在某些编译器下也会出现显示不全的问题，此时如果我们想要看到派生类对象完整的虚表也是用那两种方法。**

**1、使用内存监视窗口**
![](../../_Pasted_Image/Pasted%20image%2020260730161626.png)

**二、使用代码打印虚表内容**  
需要注意的是，我们在派生类第一个虚表地址的基础上，向后移`sizeof(Base1)`个字节即可得到第二个虚表的地址。

```cpp
void PrintVFT(VFPTR* ptr)

	for (int i = 0; ptr[i] != nullptr; i++)
	{
		printf("ptr[%d]:%p-->", i, ptr[i]); //打印虚表当中的虚函数地址
		ptr[i](); //使用虚函数地址调用虚函数
	}
	printf("\n");
}
int main()
{
	Base1 b1;
	Base2 b2;
	PrintVFT((VFPTR*)(*(int*)&b1)); //打印基类对象b1的虚表地址及其内容
	PrintVFT((VFPTR*)(*(int*)&b2)); //打印基类对象b2的虚表地址及其内容

	PrintVFT((VFPTR*)(*(int*)&d)); //打印派生类对象d的第一个虚表地址及其内容

}
```

### 菱形继承、菱形虚拟继承
以下列菱形虚拟继承关系为例，我们来看看基类和派生类的虚表模型。
```cpp
class A
{
public:
	virtual void funcA()
	{
		cout << "A::funcA()" << endl;
	}
private:
	int _a;
};
class B : virtual public A
{
public:
	virtual void funcA()
	{
		cout << "B::funcA()" << endl;
	}
	virtual void funcB()
	{
		cout << "B::funcB()" << endl;
	}
private:
	int _b;
};
class C : virtual public A
{
public:
	virtual void funcA()
	{
		cout << "C::funcA()" << endl;
	}
	virtual void funcC()
	{
		cout << "C::funcC()" << endl;
	}
private:
	int _c;
};
class D : public B, public C
{
public:
	virtual void funcA()
	{
		cout << "D::funcA()" << endl;
	}
	virtual void funcD()
	{
		cout << "D::funcD()" << endl;
	}
private:
	int _d;
};
```
代码当中的继承关系图如下：
![](../../_Pasted_Image/Pasted%20image%2020260730161733.png)
其中，A类当中有一个虚函数funcA，B类当中有一个虚函数funcB，C类当中有一个虚函数funcC，D类当中有一个虚函数funcD。此外B类、C类和D类当中均对A类当中的funcA进行了重写。

**A类对象当中的成员及其分布情况。**

A类对象的成员包括一个虚表指针和成员变量_a，虚表指针指向的虚表当中存储的是A类虚函数funcA的地址。
![](../../_Pasted_Image/Pasted%20image%2020260730161755.png)

**B类对象当中的成员及其分布情况。**
B类由于是虚拟继承的A类，所以B类对象当中将A类继承下来的成员放到了最后，除此之外，B类对象的成员还包括一个虚表指针、一个虚基表指针和成员变量_b，虚表指针指向的虚表当中存储的是B类虚函数funcB的地址。
虚基表当中存储的是两个偏移量，第一个是虚基表指针距离B虚表指针的偏移量，第二个是虚基表指针距离虚基类A的偏移量。
![](../../_Pasted_Image/Pasted%20image%2020260730161823.png)

**C类对象当中的成员及其分布情况。**
C类对象当中的成员分布情况与B类对象当中的成员分布情况相同。C类也是虚拟继承的A类，所以C类对象当中将A类继承下来的成员放到了最后，除此之外，C类对象的成员还包括一个虚表指针、一个虚基表指针和成员变量_c，虚表指针指向的虚表当中存储的是C类虚函数funcC的地址。
虚基表当中存储的是两个偏移量，第一个是虚基表指针距离C虚表指针的偏移量，第二个是虚基表指针距离虚基类A的偏移量。
![](../../_Pasted_Image/Pasted%20image%2020260730161842.png)

**D类对象当中的成员及其分布情况。**
D类对象当中成员的分布情况较为复杂，D类的继承方式是菱形虚拟继承，在D类对象当中，将A类继承下来的成员放到了最后，除此之外，D类对象的成员还包括从B类继承下来的成员、从C类继承下来的成员和成员变量_d。  
需要注意的是，D类对象当中的虚函数funcD的地址是存储到了B类的虚表当中。
![](../../_Pasted_Image/Pasted%20image%2020260730161903.png)
**友情提示：**  
实际中我们不建议设计出菱形继承及菱形虚拟继承，一方面太复杂容易出问题，另一方面使用这样的模型访问基类成员有一定的性能损耗。


## AI讲解C++ 多态的底层原理

先记住一句话：
> **运行时多态的本质，是程序通过对象的实际类型，在运行时找到应该调用的虚函数。**

C++ 标准只规定“必须表现出多态行为”，并没有强制编译器一定使用某种实现。不过主流编译器通常通过：
```text
虚函数表 vtable
+
虚函数表指针 vptr
```
来实现运行时多态。

---
### 一、为什么普通成员函数不能实现运行时多态？

先看没有 `virtual` 的情况：
```cpp
#include <iostream>

class Base
{
public:
    void Func()
    {
        std::cout << "Base::Func\n";
    }
};

class Derived : public Base
{
public:
    void Func()
    {
        std::cout << "Derived::Func\n";
    }
};

int main()
{
    Derived object;
    Base* pointer = &object;

    pointer->Func();
}
```
输出：
```text
Base::Func
```
原因是编译器看到：
```cpp
Base* pointer
```
`pointer` 的静态类型是 `Base*`。

由于 `Func()` 不是虚函数，编译器在编译阶段就确定：
```cpp
pointer->Func();
```
调用的是：
```cpp
Base::Func()
```
这叫：
```text
静态绑定
早绑定
```
概念上，编译器可以直接生成类似：
```cpp
Base::Func(pointer);
```
不需要在运行时判断对象到底是什么类型。

---
### 二、加入 `virtual` 后发生了什么？
```cpp
class Base
{
public:
    virtual void Func()
    {
        std::cout << "Base::Func\n";
    }
};

class Derived : public Base
{
public:
    void Func() override
    {
        std::cout << "Derived::Func\n";
    }
};
```
调用：
```cpp
Derived object;
Base* pointer = &object;

pointer->Func();
```
输出：
```text
Derived::Func
```
这里有两个类型：
```text
pointer 的静态类型：Base*
实际对象的动态类型：Derived
```
因为 `Func()` 是虚函数，所以程序不能只根据 `Base*` 决定调用目标。
它需要在运行时查看：
> `pointer` 当前真正指向的是哪一种对象？

然后发现实际对象是 `Derived`，于是调用：
```cpp
Derived::Func()
```
这叫：
```text
动态绑定
晚绑定
虚函数分派
```

---
### 三、什么是虚函数表 `vtable`？
只要一个类拥有虚函数，主流编译器通常会为这个类生成一张虚函数表。

例如：
```cpp
class Base
{
public:
    virtual void Func1();
    virtual void Func2();
};
```
编译器可能生成类似的表：
```text
Base 的虚函数表

索引 0 → Base::Func1
索引 1 → Base::Func2
```
可以抽象成：
```text
Base vtable
┌───────────────────┐
│ &Base::Func1      │
├───────────────────┤
│ &Base::Func2      │
└───────────────────┘
```
表中主要保存虚函数对应的地址。
真实虚表中还可能保存：
- RTTI 类型信息；
- 基类偏移信息；
- 析构函数入口；
- 指针调整信息。

具体内容由编译器和 ABI 决定。

---
### 四、派生类的虚函数表
假设：
```cpp
class Derived : public Base
{
public:
    void Func1() override;
};
```
`Derived` 重写了 `Func1()`，但没有重写 `Func2()`。
它的虚函数表概念上可能是：
```text
Derived vtable
┌───────────────────┐
│ &Derived::Func1   │
├───────────────────┤
│ &Base::Func2      │
└───────────────────┘
```
也就是说：
```text
重写的虚函数
→ 替换虚表中对应位置的函数地址

没有重写的虚函数
→ 继续使用基类版本
```

注意：
> 重写不是简单地向虚表末尾添加函数，而是替换继承而来的相应虚函数槽位。

---
### 五、什么是虚函数表指针 `vptr`？
有虚函数的对象中，编译器通常会添加一个隐藏指针：
```text
vptr
```
它指向该对象所属类型的虚函数表。

例如 `Base` 对象：
```text
Base 对象
┌───────────────────┐
│ vptr ─────────────┼──→ Base vtable
├───────────────────┤
│ Base 的成员变量    │
└───────────────────┘
```
`Derived` 对象：
```text
Derived 对象
┌───────────────────┐
│ vptr ─────────────┼──→ Derived vtable
├───────────────────┤
│ Base 基类部分      │
├───────────────────┤
│ Derived 自身成员   │
└───────────────────┘
```
虽然：
```cpp
Base* pointer = &derivedObject;
```
指针类型是 `Base*`，但它指向的对象内部的 `vptr` 指向的是：
```text
Derived vtable
```
所以虚函数调用最终能找到 `Derived::Func()`。

---
### 六、一次虚函数调用的完整过程

代码：
```cpp
Base* pointer = new Derived;
pointer->Func1();
```
主流实现下，过程大致是：
```text
1. pointer 找到实际对象
2. 从对象中取出 vptr
3. vptr 找到该对象对应的 vtable
4. 根据 Func1 的固定槽位找到函数地址
5. 调用该地址对应的函数
```
图解：
```text
Base* pointer
      │
      ▼
Derived 对象
┌────────────────────┐
│ vptr ───────────────┼─────────┐
│ Base 部分           │         │
│ Derived 部分        │         │
└────────────────────┘         │
                               ▼
                        Derived vtable
                    ┌────────────────────┐
Func1 的固定槽位 → │ &Derived::Func1    │
                    ├────────────────────┤
                    │ &Base::Func2       │
                    └────────────────────┘
```
最终调用：
```cpp
Derived::Func1()
```

---
### 七、虚函数调用可以粗略理解成什么？
源码：
```cpp
pointer->Func1();
```
可以粗略想象成：
```cpp
pointer->vptr[Func1对应的槽位](pointer);
```
更概念化地说：
```cpp
函数地址 = pointer指向对象的虚表[Func1槽位];
函数地址(pointer);
```
当然，`vptr` 和 `vtable` 一般是编译器生成的隐藏结构，不能直接这样访问。
这里是为了帮助理解。

---
### 八、为什么编译器知道查虚表的哪个位置？
假设：
```cpp
class Base
{
public:
    virtual void Func1();
    virtual void Func2();
};
```
编译器在编译阶段已经知道：
```text
Func1 位于虚表槽位 0
Func2 位于虚表槽位 1
```
因此：
```cpp
pointer->Func2();
```
虽然不知道最终调用哪个类的 `Func2()`，但它知道：
> 到对象对应虚表中的槽位 1 取函数地址。

也就是说：
```text
编译阶段确定：
查虚表的哪个位置

运行阶段确定：
这个位置里存的是哪个具体函数地址
```
这就是运行时多态的核心。

---
### 九、静态类型和动态类型分别负责什么？
```cpp
Derived object;
Base* pointer = &object;
```
#### 静态类型
```text
Base*
```

编译器根据静态类型判断：
- 当前能否访问某个成员；
- 基类中是否声明了这个函数；
- 函数调用语法是否合法；
- 虚函数位于虚表哪个槽位。

例如：
```cpp
pointer->DerivedOnlyFunc();
```
即使实际对象是 `Derived`，也不能调用，因为 `Base` 接口中没有这个函数。

---
#### 动态类型
```text
Derived
```

运行时根据动态类型决定：
- 虚表指针指向哪张虚表；
- 最终调用哪个虚函数实现。

所以可以总结为：
> 静态类型决定“允许调用什么接口”，动态类型决定“虚接口最终执行哪个实现”。

---
### 十、为什么必须使用基类指针或引用？
严格来说，虚函数对对象调用也仍然具有虚函数语义，但要体现“同一个基类接口调用不同派生类行为”，通常需要使用基类指针或引用。

例如：
```cpp
Derived object;
Base& reference = object;

reference.Func();
```
`reference` 不会创建新对象，所以原来的 `Derived` 对象完整存在：
```text
Base& reference
       │
       ▼
Derived 对象
├── Base 部分
└── Derived 部分
```
可以根据对象的动态类型调用派生类虚函数。

---
#### 按值传递为什么不行？
```cpp
void Execute(Base object)
{
    object.Func();
}

Derived derived;
Execute(derived);
```
这里会创建一个新的 `Base` 对象，只复制 `Derived` 中的基类部分。
发生：
```text
对象切片
```
转换后参数 `object` 是一个真正的 `Base` 对象：
```text
Derived 原对象
├── Base 部分 ──复制──→ Base 参数对象
└── Derived 部分          被切掉
```
此时动态类型已经是 `Base`，所以调用：
```cpp
Base::Func()
```
因此多态接口一般使用：
```cpp
void Execute(Base& object);
void Execute(const Base& object);
void Execute(Base* object);
```

---
### 十一、虚函数重写为什么要求签名匹配？
假设基类：
```cpp
class Base
{
public:
    virtual void Func() const;
};
```
派生类写成：
```cpp
class Derived : public Base
{
public:
    void Func();
};
```
这里少了 `const`，实际上是两个不同函数。

基类虚表中对应的是：
```cpp
void Func() const
```
派生类的：
```cpp
void Func()
```
不能替换这个虚表槽位。

所以推荐写：
```cpp
void Func() const override;
```
`override` 会让编译器验证：
> 这个函数是否真的覆盖了基类虚函数。

---
### 十二、虚析构函数的原理

假设：
```cpp
class Base
{
public:
    virtual ~Base() = default;
};

class Derived : public Base
{
public:
    ~Derived()
    {
        // 释放派生类资源
    }
};
```
使用：
```cpp
Base* pointer = new Derived;
delete pointer;
```
因为析构函数是虚函数，程序通过对象的虚函数机制找到：
```cpp
Derived::~Derived()
```
然后析构顺序为：
```text
Derived 析构
    ↓
Base 析构
```
这样整个对象都能正确销毁。

---
#### 基类析构函数不是虚函数会怎样？
```cpp
class Base
{
public:
    ~Base() = default;
};
```
然后：
```cpp
Base* pointer = new Derived;
delete pointer;
```
通过基类指针删除派生对象属于未定义行为。
原因是删除过程无法通过虚分派正确确定完整对象的析构方式，派生类部分可能没有正确销毁。

所以：
> 只要一个基类可能通过基类指针删除派生对象，它的析构函数就应该是虚函数。

---
### 十三、构造函数为什么不能是虚函数？
创建对象时：
```cpp
new Derived;
```

编译器必须先知道要创建的具体类型，才能：
- 确定对象大小；
- 分配内存；
- 选择构造函数；
- 初始化虚表指针。

而虚函数分派本身又依赖对象内部已经建立好的 `vptr`。
构造之前，对象还没有完整形成，不能依赖尚未建立好的动态类型机制来选择构造函数。
因此：
```cpp
virtual Derived();
```
是不允许的。

简单说：
> 虚函数依赖对象已经存在，而构造函数负责让对象开始存在。

---
### 十四、构造函数中调用虚函数为什么不表现为派生类版本？
```cpp
class Base
{
public:
    Base()
    {
        Func();
    }

    virtual void Func()
    {
        std::cout << "Base::Func\n";
    }
};

class Derived : public Base
{
public:
    void Func() override
    {
        std::cout << "Derived::Func\n";
    }
};
```
创建：
```cpp
Derived object;
```
在 `Base` 构造函数内部调用 `Func()` 时，会调用：
```cpp
Base::Func()
```
原因是构造过程：
```text
1. 构造 Base 部分
2. 构造 Derived 部分
```
执行 `Base` 构造函数时，`Derived` 部分还没有构造完成。
此时不能调用依赖派生类状态的函数。
主流实现中，在构造 `Base` 部分期间，虚表指针会表现为指向当前正在构造层次对应的虚表。
所以：
```text
Base 构造期间 → 按 Base 身份进行虚调用
Derived 构造完成后 → 按 Derived 身份进行虚调用
```
析构过程同理。

---
### 十五、析构函数中调用虚函数

析构顺序：
```text
Derived 析构
    ↓
Base 析构
```
进入 `Base` 析构函数时，`Derived` 部分已经被销毁。

此时在 `Base` 析构函数中调用虚函数，通常调用的是：
```cpp
Base
```
版本，而不是派生类版本。

所以：
> 不应在构造函数和析构函数中依赖完整的运行时多态行为。

---
### 十六、使用作用域限定符会关闭虚分派
假设：
```cpp
Base* pointer = new Derived;
```
普通调用：
```cpp
pointer->Func();
```
会发生虚函数分派，调用：
```cpp
Derived::Func()
```
但是显式指定：
```cpp
pointer->Base::Func();
```
会直接调用：
```cpp
Base::Func()
```
因为作用域限定符明确告诉编译器：
> 不要动态选择，我明确要求调用基类版本。

所以：
```text
pointer->Func()
→ 动态分派

pointer->Base::Func()
→ 静态指定 Base 版本
```

---
### 十七、纯虚函数在虚表中的作用

```cpp
class Base
{
public:
    virtual void Func() = 0;
};
```
`Base` 仍然需要在虚函数体系中为 `Func()` 保留相应位置。
但因为它没有一个可供普通基类对象使用的完整实现，所以 `Base` 不能被实例化。

派生类：
```cpp
class Derived : public Base
{
public:
    void Func() override
    {
    }
};
```
会在自己的虚表对应位置放入：
```cpp
Derived::Func
```
抽象类不能实例化，不等于它没有虚函数表体系；它仍然要支持派生类的虚函数布局和多态接口。

---
### 十八、一个完整虚表模型
```cpp
class Character
{
public:
    virtual void Attack();
    virtual void Move();
    virtual ~Character();
};

class Player : public Character
{
public:
    void Attack() override;
    ~Player() override;
};
```
可以概念化为：
#### `Character` 的虚表
```text
Character vtable

槽位 0 → Character::Attack
槽位 1 → Character::Move
槽位 2 → Character::~Character
```
#### `Player` 的虚表
```text
Player vtable

槽位 0 → Player::Attack
槽位 1 → Character::Move
槽位 2 → Player::~Player
```
`Player` 没有重写 `Move()`，所以继续使用基类版本。

---
### 十九、多继承中的虚函数原理
假设：
```cpp
class A
{
public:
    virtual void FuncA();
};

class B
{
public:
    virtual void FuncB();
};

class C : public A, public B
{
public:
    void FuncA() override;
    void FuncB() override;
};
```
`C` 对象中包含：
```text
C 对象
├── A 基类子对象
├── B 基类子对象
└── C 自身部分
```
主流实现中，可能因为有多个多态基类子对象而存在多个 `vptr`：
```text
C 对象
├── A 部分
│   └── vptr_A
│
├── B 部分
│   └── vptr_B
│
└── C 自身成员
```
例如：
```cpp
C object;

A* a = &object;
B* b = &object;
```
`a` 和 `b` 可能保存不同的地址，因为它们分别指向 `C` 对象中的不同基类子对象。

调用：
```cpp
a->FuncA();
b->FuncB();
```
仍然可以正确调用 `C` 中的重写版本。
编译器必要时还会调整 `this` 指针，使函数接收到完整 `C` 对象的正确地址。
这也是多继承对象布局比单继承复杂的原因之一。

---
### 二十、虚继承中的多态布局更复杂
菱形虚继承中：
```cpp
class Base
{
public:
    virtual void Func();
};

class Left : virtual public Base {};
class Right : virtual public Base {};

class Derived : public Left, public Right {};
```
`Derived` 中只有一份共享的 `Base` 虚基类子对象。
为了在运行时定位这份共享基类，编译器通常需要维护额外的偏移和指针调整信息。

因此虚继承可能带来：
- 更复杂的对象布局；
- 更多指针调整；
- 更复杂的构造过程；
- 更高的理解成本。

但这属于虚继承，不要与普通虚函数混淆。

---
### 二十一、虚函数的性能开销

虚函数通常有以下开销。
#### 1. 对象空间开销
对象中通常多一个 `vptr`。
在 64 位程序中，一个指针一般占 8 字节，但实际对象大小还会受到对齐影响。
例如：
```cpp
class A
{
public:
    int value;
};
```
和：
```cpp
class B
{
public:
    virtual void Func();
    int value;
};
```
`B` 通常会比 `A` 更大，因为可能包含隐藏的 `vptr`。

---
#### 2. 间接调用开销
普通函数可能直接调用：
```text
call Base::Func
```
虚函数通常需要：
```text
读取 vptr
读取虚表中的函数地址
间接调用函数
```

---
#### 3. 可能影响内联
编译器如果无法确定运行时目标，就不容易直接内联虚函数。
不过现代编译器可能进行：
```text
去虚拟化 devirtualization
```
当编译器能证明对象真实类型时，即使函数是虚函数，也可能把调用优化成直接调用甚至内联。

例如：
```cpp
Derived object;
object.Func();
```
编译器明确知道对象就是 `Derived`，通常有机会直接调用：
```cpp
Derived::Func()
```
所以：
> 虚函数语义是动态分派，但具体机器代码是否真的经过虚表，可能受到编译器优化影响。

---
### 二十二、`dynamic_cast` 和 RTTI 为什么需要多态类？

```cpp
Base* pointer = new Derived;

Derived* derived =
    dynamic_cast<Derived*>(pointer);
```
`dynamic_cast` 需要在运行时知道对象的真实类型。
主流实现通常利用多态类附带的 RTTI 信息完成类型检查。
所以对于指针或引用的运行时向下转换，源类型通常需要是多态类型，也就是至少包含一个虚函数。

常见做法：
```cpp
class Base
{
public:
    virtual ~Base() = default;
};
```
虚析构函数不仅保证正确析构，也使 `Base` 成为多态类型。

---
### 二十三、虚函数表属于对象还是类？
通常：
```text
vtable：每个类通常一份
vptr：每个多态对象或多态基类子对象中一份
```
例如：
```cpp
Derived d1;
Derived d2;
Derived d3;
```
三个对象通常拥有各自的 `vptr`：
```text
d1.vptr ─┐
d2.vptr ─┼──→ 同一张 Derived vtable
d3.vptr ─┘
```
所以：
- 虚表不需要每个对象复制一份；
- 每个对象只保存指向虚表的指针。

---
### 二十四、虚函数本身存在哪里？

虚函数的机器代码通常位于程序的代码区。
虚函数表保存的是函数地址，不是函数代码本身。
可以概念化为：
```text
代码区：
Base::Func 的机器指令
Derived::Func 的机器指令

只读数据等区域：
Base vtable
Derived vtable

对象内存：
vptr
普通成员变量
```
具体存储段由平台、编译器和链接器决定。

---
### 二十五、完整调用示例

```cpp
#include <iostream>

class Base
{
public:
    virtual void Func()
    {
        std::cout << "Base::Func\n";
    }

    virtual ~Base() = default;
};

class Derived : public Base
{
public:
    void Func() override
    {
        std::cout << "Derived::Func\n";
    }
};

void Execute(Base& object)
{
    object.Func();
}

int main()
{
    Base base;
    Derived derived;

    Execute(base);
    Execute(derived);
}
```
执行第一次：
```cpp
Execute(base);
```

```text
object 引用 Base 对象
    ↓
Base 对象的 vptr
    ↓
Base vtable
    ↓
Base::Func
```
执行第二次：
```cpp
Execute(derived);
```

```text
object 引用 Derived 对象
    ↓
Derived 对象的 vptr
    ↓
Derived vtable
    ↓
Derived::Func
```
同一个表达式：
```cpp
object.Func();
```
根据实际对象产生不同结果。
这就是运行时多态。

### 二十六、面试回答版本

面试官问：
> C++ 多态的底层原理是什么？

可以这样回答：

C++ 标准只规定运行时多态的行为，并没有强制具体实现。主流编译器通常通过虚函数表 `vtable` 和虚函数表指针 `vptr` 实现。

包含虚函数的类通常拥有一张虚函数表，表中保存各个虚函数对应的函数地址。多态对象中通常包含一个隐藏的虚表指针，指向对象动态类型对应的虚函数表。

当基类指针或引用调用虚函数时，程序会从实际对象中取得虚表指针，再根据该虚函数对应的固定槽位，从虚表中获得最终函数地址并进行间接调用。因此即使指针的静态类型是基类，只要实际对象是派生类，就能调用派生类重写的版本。

派生类重写虚函数时，会替换其虚表中对应槽位的函数地址。没有重写的虚函数则继续指向基类实现。

此外，多态基类通常需要虚析构函数，以保证通过基类指针删除派生对象时能够根据动态类型调用完整的析构链。

### 二十七、最终总结

运行时多态的调用链：
```text
基类指针或引用
        ↓
实际派生类对象
        ↓
对象内部的 vptr
        ↓
派生类对应的 vtable
        ↓
虚函数对应槽位
        ↓
调用派生类重写函数
```

必须记住：
```text
1. virtual 让函数参与动态绑定。
2. 派生类重写会替换虚表对应槽位。
3. 对象通常通过 vptr 找到所属类型的虚表。
4. 虚函数调用通过虚表间接找到实际函数。
5. 静态类型决定可使用的接口。
6. 动态类型决定最终调用的虚函数实现。
7. 按值传递会切片，指针和引用保留动态类型。
8. 多态基类通常需要虚析构函数。
9. 构造和析构过程中不会分派到尚未构造或已经销毁的派生部分。
10. vtable/vptr 是主流实现方式，但不是 C++ 标准强制规定。
```

最核心的一句话：
> **多态的原理，就是对象通过隐藏的虚表指针找到其动态类型对应的虚函数表，再从表中取出真正需要执行的函数地址。**
