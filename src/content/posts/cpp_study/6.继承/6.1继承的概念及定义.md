## 继承的概念及定义

### 继承的概念
继承（inheritance）机制是面向对象程序设计使代码可以复用的重要的手段，它允许程序员在保持原有类特性的基础上进行扩展，增加功能，这样产生新的类，称为派生类。
继承呈现了面向对象程序设计的层次结构，体现了由简单到复杂的认知过程。以前我们接触的复用都是函数复用，而继承便是类设计层次的复用。

例如，以下代码中Student类和Teacher类就继承了Person类。
```cpp
//父类
class Person
{
public:
	void Print()
	{
		cout << "name:" << _name << endl;
		cout << "age:" << _age << endl;
	}
protected:
	string _name = "张三"; //姓名
	int _age = 18;     //年龄
};
//子类
class Student : public Person
{
protected:
	int _stuid;   //学号
};
//子类
class Teacher : public Person
{
protected:
	int _jobid;   //工号
};
```
![](../../_Pasted_Image/Pasted%20image%2020260729115913.png)
继承后，父类Person的成员，包括成员函数和成员变量，都会变成子类的一部分，也就是说，子类Student和Teacher复用了父类Person的成员。
### 继承的定义
#### 定义格式
继承的定义格式如下：
![](../../_Pasted_Image/Pasted%20image%2020260729115952.png)
**说明：** 在继承当中，父类也称为基类，子类是由基类派生而来的，所以子类又称为派生类。
#### 继承方式和访问限定符
我们知道，访问限定符有以下**三种：**
1. public访问
2. protected访问
3. private访问
而继承的方式也有类似的**三种：**
    public继承
	protected继承
	private继承
#### 继承基类成员访问方式的变化
基类当中被不同访问限定符修饰的成员，以不同的继承方式继承到派生类当中后，该成员最终在派生类当中的访问方式将会发生变化。
![](../../_Pasted_Image/Pasted%20image%2020260729120151.png)
稍作观察，实际上基类成员访问方式的变化规则也不是无迹可寻的，我们可以认为三种访问限定符的权限大小为：public > protected > private，基类成员访问方式的变化规则如下：
1. 在基类当中的访问方式为public或protected的成员，在派生类当中的访问方式变为：Min(成员在基类的访问方式，继承方式)。
2. 在基类当中的访问方式为private的成员，在派生类当中都是不可见的。

```
基类的private成员在派生类当中不可见是什么意思？
```
这句话的意思是，我们无法在派生类当中访问基类的private成员。例如，虽然Student类继承了Person类，但是我们无法在Student类当中访问Person类当中的private成员_name。
```cpp
//基类
class Person
{
private:
	string _name = "张三"; //姓名
};
//派生类
class Student : public Person
{
public:
	void Print()
	{
		//在派生类当中访问基类的private成员，error!
		cout << _name << endl; 
	}
protected:
	int _stuid;   //学号
};
```
也就是说，基类的private成员无论以什么方式继承，在派生类中都是不可见的，这里的不可见是指基类的私有成员虽然被继承到了派生类对象中，但是语法上限制派生类对象不管在类里面还是类外面都不能去访问它。

因此，基类的private成员在派生类中是不能被访问的，如果基类成员不想在类外直接被访问，但需要在派生类中能访问，就需要定义为protected，由此可以看出，protected限定符是因继承才出现的。
#### 默认继承方式
在使用继承的时候也可以不指定继承方式，使用关键字class时默认的继承方式是private，使用struct 时默认的继承方式是public。

例如，在关键字为class的派生类当中，所继承的基类成员_name的访问方式变为private。
```cpp
//基类
class Person
{
public:
	string _name = "张三"; //姓名
};
//派生类
class Student : Person //默认为private继承
{
protected:
	int _stuid;   //学号
};
```
而在关键字为struct的派生类当中，所继承的基类成员_name的访问方式仍为public。
```cpp
//基类
class Person
{
public:
	string _name = "张三"; //姓名
};
//派生类
struct Student : Person //默认为public继承
{
protected:
	int _stuid;   //学号
};
```
**注意：** 虽然继承时可以不指定继承方式而采用默认的继承方式，但还是最好显示的写出继承方式。

## AI讲解C++ 继承的概念及定义

继承是 C++ 面向对象编程中的重要机制。
先记住最核心的定义：
> **继承允许一个新类在已有类的基础上，复用已有类的数据和功能，并增加或修改自己的功能。**

已有的类称为：
```text
基类、父类、Base Class
```
新创建的类称为：
```text
派生类、子类、Derived Class
```

例如：
```cpp
class Animal
{
public:
    void Eat()
    {
        std::cout << "Animal is eating\n";
    }
};

class Dog : public Animal
{
public:
    void Bark()
    {
        std::cout << "Dog is barking\n";
    }
};
```
其中：
```text
Animal：基类
Dog：派生类
```
`Dog` 在 `Animal` 的基础上增加了 `Bark()` 功能。
因此：
```cpp
Dog dog;

dog.Eat();   // 从 Animal 继承
dog.Bark();  // Dog 自己定义
```

### 一、为什么需要继承？
假设我们要设计游戏中的多个角色：
```text
玩家
敌人
NPC
Boss
```
它们都可能具有：
```text
名字
生命值
位置
移动
受到伤害
死亡
```
如果不使用继承，可能会写出：
```cpp
class Player
{
private:
    std::string name;
    int health;

public:
    void Move();
    void TakeDamage();
};

class Enemy
{
private:
    std::string name;
    int health;

public:
    void Move();
    void TakeDamage();
};

class Boss
{
private:
    std::string name;
    int health;

public:
    void Move();
    void TakeDamage();
};
```
很多代码重复。
可以把共同部分抽取成基类：
```cpp
class Character
{
protected:
    std::string name;
    int health;

public:
    void Move()
    {
        std::cout << name << " moves\n";
    }

    void TakeDamage(int damage)
    {
        health -= damage;
    }
};
```

然后派生：

```cpp
class Player : public Character
{
public:
    void UseSkill()
    {
        std::cout << "Player uses skill\n";
    }
};

class Enemy : public Character
{
public:
    void Attack()
    {
        std::cout << "Enemy attacks\n";
    }
};
```
这样：
```text
Character 保存共同能力
Player 添加玩家特有能力
Enemy 添加敌人特有能力
```

继承的主要作用包括：
1. 复用已有代码；
2. 表达类之间的层次关系；
3. 扩展已有类；
4. 为运行时多态提供基础。

### 二、继承的基本语法
基本格式：
```cpp
class 派生类名 : 继承方式 基类名
{
    // 派生类成员
};
```
例如：
```cpp
class Dog : public Animal
{
};
```
拆解：
```text
Dog       派生类名
public    继承方式
Animal    基类名
```
常见继承方式：
```cpp
public
protected
private
```
后面会详细解释。

### 三、继承后，派生类得到了什么？
假设：
```cpp
class Base
{
public:
    int publicValue;

protected:
    int protectedValue;

private:
    int privateValue;
};

class Derived : public Base
{
};
```
一个 `Derived` 对象内部，概念上包含一个 `Base` 子对象：
```text
Derived 对象
├── Base 基类部分
│   ├── publicValue
│   ├── protectedValue
│   └── privateValue
│
└── Derived 自己新增的部分
```

所以更准确地说：
> 派生类对象中包含一个基类子对象。

**注意**，基类的私有成员也存在于派生类对象的基类部分中，只是派生类不能直接访问它们。

---
### 四、私有成员到底有没有被继承？
这是一个容易产生争议的问题。
例如：
```cpp
class Base
{
private:
    int value;
};

class Derived : public Base
{
public:
    void Func()
    {
        // value = 10;  // 错误
    }
};
```
派生类不能直接访问：
```cpp
value
```

但不代表 `value` 不存在。
`Derived` 对象内部仍然包含 `Base` 子对象，而 `Base` 子对象内部仍然有 `value`。
只是：
> `value` 的访问权限属于 `Base`，只能由 `Base` 自己的成员函数或友元直接访问。

例如：
```cpp
class Base
{
private:
    int value = 10;

public:
    int GetValue() const
    {
        return value;
    }
};

class Derived : public Base
{
public:
    void Print()
    {
        std::cout << GetValue() << '\n';
    }
};
```
派生类不能直接访问 `value`，但可以调用基类的公共接口：
```cpp
GetValue()
```

因此更准确的表达是：
> 基类私有成员存在于派生类对象的基类子对象中，但派生类成员函数不能直接访问。

### 五、继承表达的是“is-a”关系
公有继承通常表达：
> 派生类是基类的一种。

例如：
```text
Dog is an Animal
狗是一种动物
```
所以可以写：
```cpp
class Dog : public Animal
{
};
```
再例如：
```text
Player is a Character
玩家是一种角色

Boss is an Enemy
Boss 是一种敌人
```
因此：
```cpp
class Player : public Character
{
};

class Boss : public Enemy
{
};
```

这种关系称为：
```text
is-a 关系
```

---
#### 不符合 is-a 的情况

例如：
```text
Car has an Engine
汽车拥有一个发动机
```
汽车不是发动机，所以一般不应该写：
```cpp
class Car : public Engine
{
};
```
更合理的是组合：
```cpp
class Car
{
private:
    Engine engine;
};
```

这种关系叫：
```text
has-a 关系
```

所以：
```text
继承：is-a
组合：has-a
```
这是面试中的重要判断标准。

### 六、派生类可以直接使用基类成员函数

```cpp
#include <iostream>

class Animal
{
public:
    void Eat()
    {
        std::cout << "Animal eats\n";
    }
};

class Dog : public Animal
{
public:

        std::cout << "Dog barks\n";

{

```
`Dog` 自己没有定义 `Eat()`，但通过公有继承可以使用基类的公共成员函数。
执行：
```cpp
dog.Eat();
```
本质上是对 `Dog` 对象内部的 `Animal` 基类部分调用 `Eat()`。

### 八、`public`、`protected`、`private` 成员访问权限
类成员本身有三种访问权限。
#### 1. `public`
```cpp
public:
```
表示：
- 类内部可以访问；
- 派生类可以访问；
- 类外对象可以访问。

```cpp
class Base
{
public:
    int x;
};

Base base;
base.x = 10;
```

---
#### 2. `protected`
```cpp
protected:
```
表示：
- 基类内部可以访问；
- 派生类内部可以访问；
- 类外不能直接访问。

```cpp
class Base
{
protected:
    int health;
};

class Player : public Base
{
public:
    void SetHealth(int value)
    {
        health = value; // 可以
    }
};

int main()
{
    Player player;

    // player.health = 100; // 错误
}
```

`protected` 通常用于：
> 希望派生类能够使用，但不希望外部直接访问的成员。

---
#### 3. `private`
```cpp
private:
```

表示：
- 基类内部可以访问；
- 基类友元可以访问；
- 派生类不能直接访问；
- 类外不能直接访问。

```cpp
class Base
{
private:
    int secret;
};

class Derived : public Base
{
public:
    void Func()
    {
        // secret = 10; // 错误
    }
};
```

---
### 九、成员访问权限和继承方式不是一回事
下面两个概念不要混淆。

成员访问权限：
```cpp
public:
protected:
private:
```
写在类内部，控制成员本身的访问权限。

继承方式：
```cpp
class Derived : public Base
```
写在类名后面，控制基类成员进入派生类后表现为什么权限。
虽然关键字相同，但作用不同。

---
### 十、三种继承方式
#### 1. 公有继承
```cpp
class Derived : public Base
{
};
```
基类成员在派生类中的权限变化：

|基类成员权限|公有继承后|
|---|---|
|`public`|仍是 `public`|
|`protected`|仍是 `protected`|
|`private`|派生类不能直接访问|
这是最常见的继承方式，通常表达 `is-a` 关系。

---
#### 2. 保护继承
```cpp
class Derived : protected Base
{
};
```

|基类成员权限|保护继承后|
|---|---|
|`public`|变为 `protected`|
|`protected`|仍是 `protected`|
|`private`|派生类不能直接访问|
外部对象不能再通过派生类访问原来基类的公共成员。

---
#### 3. 私有继承
```cpp
class Derived : private Base
{
};
```

|基类成员权限|私有继承后|
|---|---|
|`public`|变为 `private`|
|`protected`|变为 `private`|
|`private`|派生类不能直接访问|
私有继承更接近：
> 利用基类的实现细节，而不是公开表达“派生类是一种基类”。

---
### 十一、继承权限完整表

|基类成员|`public` 继承|`protected` 继承|`private` 继承|
|---|---|---|---|
|`public`|`public`|`protected`|`private`|
|`protected`|`protected`|`protected`|`private`|
|`private`|不可直接访问|不可直接访问|不可直接访问|
可以用一句规则记住：
> 继承方式决定基类的 `public` 和 `protected` 成员，在派生类中能够保持到什么最高权限。

例如私有继承最多只能是 `private`。

---
### 十二、公有继承示例

```cpp
#include <iostream>

class Base
{
public:
    int publicValue = 10;

protected:
    int protectedValue = 20;

private:
    int privateValue = 30;
};

class Derived : public Base
{
public:
    void Print()
    {
        std::cout << publicValue << '\n';
        std::cout << protectedValue << '\n';

        // std::cout << privateValue; // 错误
    }
};

int main()
{
    Derived object;

    std::cout << object.publicValue << '\n';

    // object.protectedValue; // 错误
    // object.privateValue;   // 错误

    object.Print();
}
```

这里：
- `publicValue`：外部和派生类都能访问；
- `protectedValue`：只有类内部和派生类能访问；
- `privateValue`：只有 `Base` 自己能直接访问。

### 十三、基类构造函数与派生类构造函数
创建派生类对象时，必须先构造它内部的基类部分。

例如：
```cpp
#include <iostream>

class Base
{
public:
    Base()
    {
        std::cout << "Base constructor\n";
    }
};

class Derived : public Base
{
public:
    Derived()
    {
        std::cout << "Derived constructor\n";
    }
};

int main()
{
    Derived object;
}
```
输出：
```text
Base constructor
Derived constructor
```
构造顺序：
```text
先构造基类
再构造派生类
```

原因是：
> 派生类是在基类基础上建立的，必须先把基类部分构造好，才能构造派生类自己的部分。

---
### 十四、析构顺序

对象销毁时顺序相反：
```cpp
class Base
{
public:
    ~Base()
    {
        std::cout << "Base destructor\n";
    }
};

class Derived : public Base
{
public:
    ~Derived()
    {
        std::cout << "Derived destructor\n";
    }
};
```
销毁 `Derived`：
```text
先析构 Derived
再析构 Base
```
所以：
```text
构造：基类 → 派生类
析构：派生类 → 基类
```

### 十五、如何调用基类带参数构造函数？
```cpp
class Character
{
protected:
    std::string name;

public:
    Character(const std::string& name)
        : name(name)
    {
    }
};
```
派生类需要在初始化列表中调用基类构造函数：
```cpp
class Player : public Character
{
private:
    int level;

public:
    Player(const std::string& name, int level)
        : Character(name),
          level(level)
    {
    }
};
```
这里：
```cpp
Character(name)
```
用于构造 `Player` 对象内部的 `Character` 基类部分。

完整过程：
```text
Player("Alice", 10)
    ↓
先调用 Character("Alice")
    ↓
再初始化 level
    ↓
最后执行 Player 构造函数体
```

### 十六、基类构造函数会自动继承吗？

一般情况下，派生类不会自动获得基类构造函数。
```cpp
class Base
{
public:
    Base(int value)
    {
    }
};

class Derived : public Base
{
};
```
此时：
```cpp
Derived object(10);
```
通常不能直接使用，因为 `Derived` 没有对应构造函数，并且基类又没有默认构造函数。

需要自己写：
```cpp
class Derived : public Base
{
public:
    Derived(int value)
        : Base(value)
    {
    }
};
```
C++11 以后也可以显式继承构造函数：
```cpp
class Derived : public Base
{
public:
    using Base::Base;
};
```
但这属于后续知识。

### 十七、派生类中的同名成员
```cpp
class Base
{
public:
    void Print()
    {
        std::cout << "Base::Print\n";
    }
};

class Derived : public Base
{
public:
    void Print()
    {
        std::cout << "Derived::Print\n";
    }
};
```
调用：
```cpp
Derived object;
object.Print();
```
输出：
```text
Derived::Print
```
派生类中的同名成员会隐藏基类中的同名成员。

要调用基类版本，可以写：
```cpp
object.Base::Print();
```
或者在派生类内部：
```cpp
Base::Print();
```
注意：

> 同名隐藏不完全等于虚函数重写。

虚函数重写要求基类函数是 `virtual`，并满足相应函数签名规则。后面学习多态时会详细讨论。

### 十八、派生类对象可以转换为基类对象吗？

在公有继承下：
```cpp
class Animal
{
};

class Dog : public Animal
{
};
```
可以把 `Dog` 对象当作 `Animal` 使用：
```cpp
Dog dog;

Animal* animalPointer = &dog;
Animal& animalReference = dog;
```
因为：
```text
Dog 是一种 Animal
```
这称为：
```text
向上转换
Upcasting
```
通常是安全的。

但反过来：
```cpp
Animal animal;

// Dog* dogPointer = &animal; // 不允许直接转换
```
因为不是每个 `Animal` 都一定是 `Dog`。

---
### 十九、继承与多态的关系

继承本身解决的是：
```text
类之间建立父子关系
代码复用
接口层次
```
多态解决的是：
```text
通过基类指针或引用
调用派生类的实际行为
```

例如：
```cpp
class Character
{
public:
    virtual void Attack()
    {
        std::cout << "Character attack\n";
    }
};

class Player : public Character
{
public:
    void Attack() override
    {
        std::cout << "Player attack\n";
    }
};
```

调用：

```cpp
Player player;
Character* character = &player;

character->Attack();
```
输出：
```text
Player attack
```
继承为多态提供类层次，而 `virtual` 实现动态绑定。

但要注意：

> 有继承不一定有运行时多态，只有虚函数调用等机制参与时才形成动态多态。

---
### 二十、继承有哪些形式？
#### 1. 单继承
一个派生类只有一个直接基类：
```cpp
class Dog : public Animal
{
};
```

---
#### 2. 多继承

一个派生类同时继承多个基类：
```cpp
class FlyingAnimal
{
};

class SwimmingAnimal
{
};

class Duck : public FlyingAnimal,
             public SwimmingAnimal
{
};
```
`Duck` 同时拥有两个基类部分。

---
#### 3. 多层继承
```cpp
class Animal
{
};

class Mammal : public Animal
{
};

class Dog : public Mammal
{
};
```

关系：

```text
Animal
  ↓
Mammal
  ↓
Dog
```

---
#### 4. 菱形继承

```cpp
class Animal
{
};

class FlyingAnimal : public Animal
{
};

class SwimmingAnimal : public Animal
{
};

class Duck : public FlyingAnimal,
             public SwimmingAnimal
{
};
```
形成：
```text
       Animal
       /    \
FlyingAnimal SwimmingAnimal
       \    /
        Duck
```
这可能导致 `Duck` 中存在两份 `Animal` 基类子对象。

可以通过虚继承解决：
```cpp
class FlyingAnimal : virtual public Animal
{
};

class SwimmingAnimal : virtual public Animal
{
};
```
这是继承的进阶内容。

### 二十一、继承与组合应该选哪个？

继承：
```cpp
class Player : public Character
{
};
```
表示：
```text
Player 是一种 Character
```

组合：
```cpp
class Player
{
private:
    Weapon weapon;
};
```

表示：
```text
Player 拥有一个 Weapon
```

判断原则：
```text
is-a  → 考虑继承
has-a → 考虑组合
```

现代 C++ 设计中通常强调：
> 优先使用组合，谨慎使用继承。

原因是组合：
- 耦合更低；
- 更容易替换组件；
- 更灵活；
- 不容易破坏封装。

但当确实存在稳定的 `is-a` 关系，并且需要多态接口时，公有继承非常合适。

### 二十二、游戏开发中的继承例子

例如设计角色体系：
```cpp
class Character
{
protected:
    float health;

public:
    virtual void Attack() = 0;

    virtual ~Character() = default;
};
```

玩家：
```cpp
class PlayerCharacter : public Character
{
public:
    void Attack() override
    {
        std::cout << "Player uses sword\n";
    }
};
```

敌人：
```cpp
class EnemyCharacter : public Character
{
public:
    void Attack() override
    {
        std::cout << "Enemy attacks player\n";
    }
};
```

Boss：
```cpp
class BossCharacter : public EnemyCharacter
{
public:
    void Attack() override
    {
        std::cout << "Boss uses special skill\n";
    }
};
```

层次关系：
```text
Character
├── PlayerCharacter
└── EnemyCharacter
      └── BossCharacter
```
但实际游戏引擎开发中，不应该把所有能力都堆进深层继承树。

例如：
```text
生命系统
技能系统
背包系统
武器系统
AI 系统
```
往往更适合通过组件组合。

### 二十三、继承的底层理解

假设：
```cpp
class Base
{
public:
    int a;
};

class Derived : public Base
{
public:
    int b;
};
```

一个 `Derived` 对象在概念上包含：
```text
Derived 对象
├── Base 子对象
│   └── int a
└── Derived 自己部分
    └── int b
```
因此：
```cpp
Derived object;
```
`object` 不只是包含 `b`，还包含完整的基类部分。

访问：
```cpp
object.a
```
实际上是在访问 `Derived` 对象内部的 `Base` 子对象成员。

具体内存布局由 ABI、编译器、对齐、虚函数等因素决定，不能简单保证基类成员永远位于某个绝对位置，但“派生对象包含基类子对象”是正确的语言模型。

---
### 二十四、继承的优点

继承可以：
1. 减少共同代码重复；
2. 建立统一接口；
3. 表达类型层次；
4. 支持基类指针和引用；
5. 实现运行时多态；
6. 扩展已有类。

---
### 二十五、继承的缺点

滥用继承会导致：
1. 基类和派生类高度耦合；
2. 基类修改影响所有派生类；
3. 继承层次过深，难以理解；
4. 容易破坏封装；
5. 多继承可能产生歧义；
6. 错误的 `is-a` 设计导致结构僵化；
7. 基类接口过大，派生类被迫继承无关功能。

所以继承不是单纯为了少写代码。
更重要的是：
> 类之间是否真的存在稳定、合理的抽象关系。

### 二十六、常见错误
#### 错误一：认为派生类可以访问基类所有成员
```cpp
class Base
{
private:
    int value;
};

class Derived : public Base
{
public:
    void Func()
    {
        // value = 10; // 错误
    }
};
```
基类私有成员不能被派生类直接访问。

---
#### 错误二：把 `private` 成员理解为不存在
私有成员仍然存在于基类子对象中，只是不能直接访问。

---
#### 错误三：混淆成员权限和继承方式

```cpp
protected:
```
是成员权限。

```cpp
class Derived : protected Base
```
是继承方式。

---
#### 错误四：认为继承只是复制代码
继承并不是把基类源代码复制到派生类中。
更准确的模型是：
```text
派生类对象中包含基类子对象
```

---
#### 错误五：为了复用代码就使用继承
如果只是“拥有某个功能”，通常组合更合适。
例如玩家拥有武器：
```cpp
class Player
{
    Weapon weapon;
};
```
而不是：
```cpp
class Player : public Weapon
{
};
```

### 二十七、面试回答版本

面试官问：

> 什么是继承？

可以这样回答：

继承是 C++ 面向对象中的一种类复用和类型扩展机制。派生类可以在基类的基础上复用其可访问成员，并增加新的数据和行为。派生类对象内部包含一个基类子对象。

继承语法为：
```cpp
class Derived : public Base
{
};
```

基类成员有 `public`、`protected` 和 `private` 三种访问权限。派生类可以直接访问基类的 `public` 和 `protected` 成员，但不能直接访问基类的 `private` 成员。

继承方式分为 `public`、`protected` 和 `private`。公有继承通常表达 `is-a` 关系，并支持派生类对象向基类指针或引用的安全向上转换。

构造派生类对象时先构造基类部分，再构造派生类部分；析构顺序相反。继承也是实现运行时多态的基础，但只有配合虚函数和基类指针或引用时，才会产生动态多态。

---
### 二十八、复习总结

核心语法：
```cpp
class Derived : public Base
{
};
```

核心概念：
```text
Base：基类、父类
Derived：派生类、子类
```

必须记住：
```text
1. 继承允许派生类复用和扩展基类。
2. 派生类对象内部包含基类子对象。
3. 基类 private 成员存在，但派生类不能直接访问。
4. protected 成员可以被派生类访问，但类外不能访问。
5. public 继承通常表达 is-a 关系。
6. 组合表达 has-a 关系。
7. 构造顺序是基类到派生类。
8. 析构顺序是派生类到基类。
9. 公有继承下，派生类可以安全向上转换为基类。
10. 继承是多态的基础，但继承本身不等于多态。
```

最核心的一句话：

> **继承不是简单地复制基类代码，而是在派生类对象中建立一个基类子对象，并在这个基础上扩展新的类型和行为。**
