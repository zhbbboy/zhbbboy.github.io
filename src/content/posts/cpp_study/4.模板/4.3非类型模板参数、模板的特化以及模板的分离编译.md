## 非类型模板参数

模板参数可分为类型形参和非类型形参。  
	**类型形参：** 出现在模板参数列表中，跟在class或typename关键字之后的参数类型名称。  
	**非类型形参：** 用一个常量作为类（函数）模板的一个参数，在类（函数）模板中可将该参数当成常量来使用。

例如，我们要实现一个静态数组的类，就需要用到非类型模板参数。
```cpp
template<class T, size_t N> //N：非类型模板参数
class StaticArray
{
public:
	size_t arraysize()
	{
		return N;
	}
private:
	T _array[N]; //利用非类型模板参数指定静态数组的大小
};

```
使用非类型模板参数后，我们就可以在实例化对象的时候指定所要创建的静态数组的大小了。
```cpp
int main()
{
	StaticArray<int, 10> a1; //定义一个大小为10的静态数组
	cout << a1.arraysize() << endl; //10
	StaticArray<int, 100> a2; //定义一个大小为100的静态数组
	cout << a2.arraysize() << endl; //100
	return 0;
}

```
**注意：**
1. 非类型模板参数只允许使用整型家族，但浮点数、类对象以及字符串是不允许作为非类型模板参数的。
2. 非类型的模板参数在编译期就需要确认结果，因为编译器在编译阶段就需要根据传入的非类型模板参数生成对应的类或函数。

## AI讲解非类型模板参数

前面学的模板大多是这样的：
```cpp
template <typename T>
class Box
{
    T value;
};
```
这里的 `T` 代表一个**类型**，例如：
```cpp
Box<int>
Box<double>
```
但模板参数不一定只能代表类型，也可以代表一个**编译期确定的常量值**。
例如：
```cpp
template <typename T, std::size_t N>
class Array
{
    T data[N];
};
```
这里：
- `T` 是**类型模板参数**；
- `N` 是**非类型模板参数**。
使用时：
```cpp
Array<int, 10> arr;
```
表示：
```text
T = int
N = 10
```
你可以先记住：

> **类型模板参数用来传递类型，非类型模板参数用来传递编译期常量。**

---
### 1. 为什么需要非类型模板参数？
假设我们要写一个固定大小的数组类。
如果只使用类型模板参数：
```cpp
template <typename T>
class Array
{
private:
    T* data;
    std::size_t size;
};
```
数组大小需要在运行时保存。
但有些数组的大小在编译时就已经确定，例如：
```cpp
int arr[10];
```
其中的 `10` 是类型结构的一部分。

我们希望模板不仅能接收元素类型，还能接收数组长度：
```cpp
template <typename T, std::size_t N>
class Array
{
private:
    T data[N];
};
```
这样就可以生成：
```cpp
Array<int, 5>
Array<int, 10>
Array<double, 20>
```

---
### 2. 基本语法

非类型模板参数的一般形式：
```cpp
template <typename T, std::size_t N>
class Array
{
};
```
其中：
```cpp
typename T
```
表示 `T` 是一个类型。
而：
```cpp
std::size_t N
```
表示 `N` 是一个 `std::size_t` 类型的编译期常量。
也可以写在函数模板中：
```cpp
template <int N>
void PrintNumber()
{
    std::cout << N << '\n';
}
```
调用：
```cpp
PrintNumber<10>();
PrintNumber<20>();
```
编译器会分别生成类似：
```cpp
void PrintNumber<10>()
{
    std::cout << 10 << '\n';
}
```
和：
```cpp
void PrintNumber<20>()
{
    std::cout << 20 << '\n';
}
```

---
### 3. 完整的固定数组类模板

```cpp
#include <cstddef>
#include <iostream>
#include <stdexcept>

template <typename T, std::size_t N>
class Array
{
private:
    T data[N]{};

public:
    constexpr std::size_t Size() const
    {
        return N;
    }

    T& operator[](std::size_t index)
    {
        return data[index];
    }

    const T& operator[](std::size_t index) const
    {
        return data[index];
    }

    T& At(std::size_t index)
    {
        if (index >= N)
        {
            throw std::out_of_range("Array index out of range");
        }

        return data[index];
    }
};

int main()
{
    Array<int, 5> arr;

    for (std::size_t i = 0; i < arr.Size(); ++i)
    {
        arr[i] = static_cast<int>(i * 10);
    }

    for (std::size_t i = 0; i < arr.Size(); ++i)
    {
        std::cout << arr[i] << ' ';
    }
}
```
这里的数组长度：
```cpp
N
```
不是对象运行时才保存进去的普通变量，而是模板实例化时已经确定的编译期常量。
当使用：
```cpp
Array<int, 5>
```
时，编译器可以粗略理解为生成：
```cpp
class Array_int_5
{
private:
    int data[5];
};
```
当使用：
```cpp
Array<double, 10>
```
时，生成的是另一个类型：
```cpp
class Array_double_10
{
private:
    double data[10];
};
```

---
### 4. `Array<int, 5>` 和 `Array<int, 10>` 是不同类型

这是非类型模板参数最重要的特点之一。
```cpp
Array<int, 5> a;
Array<int, 10> b;
```
虽然元素类型都是 `int`，但它们不是同一种类型。
因为模板实参不同：
```text
Array<int, 5>
Array<int, 10>
```
编译器会生成两个不同的类。
因此通常不能这样赋值：
```cpp
a = b; // 错误：类型不同
```
函数参数也一样：
```cpp
void Func(const Array<int, 5>& arr)
{
}
```
只能直接接收：
```cpp
Array<int, 5>
```
不能接收：
```cpp
Array<int, 10>
```
所以：
> **非类型模板参数的值会参与构成最终的类型。**
标准库中的：
```cpp
std::array<int, 5>
std::array<int, 10>
```
也属于两个不同类型。

---
### 5. 为什么必须是编译期常量？
模板实例化发生在编译期。
编译器看到：
```cpp
Array<int, 10>
```
必须在编译阶段就知道要生成一个含有多少个元素的数组类。
因此下面代码不行：
```cpp
int n;
std::cin >> n;

Array<int, n> arr; // 错误
```
因为 `n` 的值只有程序运行后、用户输入时才知道。
编译器在编译阶段不知道：
```text
n 到底是 5、10 还是 100
```
因此无法确定要生成：
```cpp
Array<int, ?>
```
中的哪个具体类型。

---
#### 正确写法：使用编译期常量

```cpp
constexpr std::size_t size = 10;

Array<int, size> arr;
```
因为：
```cpp
constexpr
```
表示这个值可以在编译期确定。
也可以直接写：
```cpp
Array<int, 10> arr;
```

---
### 6. `const` 变量一定可以吗？

例如：
```cpp
const int n = 10;
Array<int, n> arr;
```
这个例子通常可以，因为 `n` 使用常量表达式初始化，并且它的值在编译期可确定。
但为了明确表达“这是编译期常量”，现代 C++ 更建议写：
```cpp
constexpr int n = 10;
```
两者的核心区别是：
- `const` 主要表示变量不能被修改；
- `constexpr` 明确表示值可以在编译期求出。
例如：
```cpp
int GetSize()
{
    return 10;
}

const int n = GetSize();

Array<int, n> arr; // 不行，n 的值不是编译期常量
```
虽然 `n` 是 `const`，不能修改，但它的初始值来自普通函数调用，需要运行时才能确定。
如果函数是可用于常量表达式的 `constexpr`：
```cpp
constexpr int GetSize()
{
    return 10;
}

constexpr int n = GetSize();

Array<int, n> arr;
```
则可以。
所以真正的要求不是“必须写 `const`”，而是：
> **非类型模板实参必须满足编译期常量表达式的要求。**

### 7. 模板参数和模板实参
看下面代码：
```cpp
template <typename T, std::size_t N>
class Array
{
};
```
其中：
```cpp
T
N
```
叫做**模板参数**。
使用：
```cpp
Array<int, 10>
```
其中：
```cpp
int
10
```
叫做**模板实参**。
对应关系：
```text
T ← int
N ← 10
```
因此：
- `T` 是类型模板参数；
- `int` 是类型模板实参；
- `N` 是非类型模板参数；
- `10` 是非类型模板实参。

---
### 8. 非类型模板参数可以在类中直接使用
因为 `N` 是编译期常量，所以可以用在很多要求常量表达式的地方。
#### 用作数组长度

```cpp
template <typename T, std::size_t N>
class Array
{
    T data[N];
};
```
#### 用作循环边界

```cpp
template <std::size_t N>
void Print()
{
    for (std::size_t i = 0; i < N; ++i)
    {
        std::cout << i << ' ';
    }
}
```
#### 用在 `static_assert`

```cpp
template <typename T, std::size_t N>
class Array
{
    static_assert(N > 0, "N must be greater than zero");

    T data[N];
};
```
当使用：
```cpp
Array<int, 0> arr;
```
编译器会直接报错。
#### 用于条件编译逻辑

```cpp
template <std::size_t N>
void Process()
{
    if constexpr (N > 100)
    {
        std::cout << "large\n";
    }
    else
    {
        std::cout << "small\n";
    }
}
```

这里的判断发生在编译期。

---
### 9. 非类型模板参数的默认值
和类型模板参数一样，非类型模板参数也可以设置默认值：
```cpp
template <typename T, std::size_t N = 10>
class Array
{
private:
    T data[N]{};
};
```
使用：
```cpp
Array<int> arr1;
```
等价于：
```cpp
Array<int, 10> arr1;
```
也可以显式指定：
```cpp
Array<int, 20> arr2;
```

---
### 10. 多个非类型模板参数

可以同时传入多个编译期常量。
例如矩阵：
```cpp
template <typename T, std::size_t Rows, std::size_t Cols>
class Matrix
{
private:
    T data[Rows][Cols]{};

public:
    constexpr std::size_t RowCount() const
    {
        return Rows;
    }

    constexpr std::size_t ColumnCount() const
    {
        return Cols;
    }
};
```
使用：
```cpp
Matrix<int, 3, 4> matrix;
```
表示：
```text
元素类型：int
行数：3
列数：4
```
编译器生成的类中，数组大小就是：
```cpp
int data[3][4];
```
而：
```cpp
Matrix<int, 3, 4>
Matrix<int, 4, 3>
```
也是两种不同类型。
这有一个好处：维度错误可以在编译期发现。

例如一个只接收 `3 × 4` 矩阵的函数：
```cpp
void Process(const Matrix<int, 3, 4>& matrix)
{
}
```
传入：
```cpp
Matrix<int, 4, 3>
```
会在编译期报错。

---
### 11. 在函数模板中使用数组长度

非类型模板参数可以从数组实参中自动推导。
例如：
```cpp
#include <cstddef>
#include <iostream>

template <typename T, std::size_t N>
void PrintArray(const T (&arr)[N])
{
    for (std::size_t i = 0; i < N; ++i)
    {
        std::cout << arr[i] << ' ';
    }

    std::cout << '\n';
}
```
调用：
```cpp
int arr[5] = {1, 2, 3, 4, 5};

PrintArray(arr);
```
编译器自动推导：
```text
T = int
N = 5
```
这里的参数：
```cpp
const T (&arr)[N]
```
表示：
> `arr` 是一个对“包含 N 个 T 元素的数组”的引用。

因为使用了数组引用，所以数组不会退化为普通指针，编译器能够保留并推导数组长度。

---
#### 拆解这个复杂类型
```cpp
const T (&arr)[N]
```
从变量名向外看：
```text
arr
(&arr)        arr 是引用
(&arr)[N]     arr 引用一个长度为 N 的数组
T (&arr)[N]   数组元素类型是 T
const T ...   不能通过 arr 修改元素
```
所以：
```cpp
template <typename T, std::size_t N>
void PrintArray(const T (&arr)[N]);
```
可以同时推导元素类型和数组长度。

---
### 12. 与普通函数参数的区别

普通数组参数：
```cpp
void Func(int arr[])
```
实际会退化成：
```cpp
void Func(int* arr)
```
函数内部无法从 `arr` 指针本身知道数组长度。
而模板数组引用：
```cpp
template <std::size_t N>
void Func(const int (&arr)[N])
```
保留了数组类型中的长度信息。
调用：
```cpp
int arr[10];
Func(arr);
```
编译器推导：
```cpp
N = 10
```
这就是非类型模板参数的典型应用。

---

### 13. `std::array` 就使用了非类型模板参数

标准库中：
```cpp
std::array<int, 5> arr;
```
它的模板结构可以粗略理解为：
```cpp
template <typename T, std::size_t N>
class array
{
    T elements[N];
};
```
这里：
- `T` 决定元素类型；
- `N` 决定数组大小。
所以：
```cpp
std::array<int, 5>
std::array<int, 10>
```
是两个不同类型。
相比普通数组：
```cpp
int arr[5];
```
`std::array` 具有容器接口：
```cpp
arr.size();
arr.begin();
arr.end();
arr.at(0);
```
但大小依然是在编译期确定的。

### 14. `std::bitset` 也使用了非类型模板参数

```cpp
std::bitset<32> bits;
```
这里的：
```cpp
32
```
就是非类型模板实参，表示保存 32 个二进制位。
又例如：
```cpp
std::bitset<64>
```
是另外一种类型。

### 15. 非类型模板参数可以是哪些类型？
在传统和常见的 C++ 模板学习中，最常用的是：
```cpp
template <int N>
template <std::size_t N>
template <bool Flag>
template <char C>
```
也就是整型、枚举等编译期常量类型。
例如：
```cpp
template <bool Debug>
class Logger
{
};
```

```cpp
Logger<true> debugLogger;
Logger<false> releaseLogger;
```
也可以使用指针、引用或枚举作为非类型模板参数，但有更严格的常量表达式和链接等限制，入门阶段使用得较少。
现代 C++ 对非类型模板参数允许的类型范围有所扩展，但八股和实际工程中最常见的仍然是：
```text
整数
bool
枚举
数组长度
容量
维度
标志位
指针或成员指针
```

### 16. `auto` 非类型模板参数

从 C++17 开始，可以让编译器自动推导非类型模板参数本身的类型：
```cpp
template <auto Value>
void PrintValue()
{
    std::cout << Value << '\n';
}
```
调用：
```cpp
PrintValue<10>();     // Value 是 int
PrintValue<'A'>();    // Value 是 char
PrintValue<true>();   // Value 是 bool
```
也可以这样写类模板：
```cpp
template <auto Value>
class Constant
{
public:
    static constexpr auto value = Value;
};
```
使用：
```cpp
Constant<10> c1;
Constant<'A'> c2;
```
其中：
```cpp
Constant<10>
Constant<'A'>
```

是不同类型。

### 17. 非类型模板参数包
还可以接收任意数量的编译期常量：
```cpp
template <int... Values>
void PrintValues()
{
    ((std::cout << Values << ' '), ...);
}
```
调用：
```cpp
PrintValues<1, 2, 3, 4, 5>();
```
这里：
```cpp
int... Values
```
是非类型模板参数包。
这属于可变参数模板内容，先了解即可。

### 18. 非类型模板参数参与模板特化
例如：
```cpp
template <int N>
class NumberInfo
{
public:
    static void Print()
    {
        std::cout << "普通数字：" << N << '\n';
    }
};
```
针对 `0` 进行特化：
```cpp
template <>
class NumberInfo<0>
{
public:
    static void Print()
    {
        std::cout << "这是零\n";
    }
};
```
使用：
```cpp
NumberInfo<10>::Print();
NumberInfo<0>::Print();
```
编译器会选择不同版本。

---
### 19. 非类型模板参数和普通构造函数参数的区别
看两个类。
#### 运行时大小
```cpp
class DynamicArray
{
private:
    std::size_t size;

public:
    explicit DynamicArray(std::size_t n)
        : size(n)
    {
    }
};
```
使用：
```cpp
std::size_t n;
std::cin >> n;

DynamicArray arr(n);
```
`n` 可以在运行时确定。

---
#### 编译期大小
```cpp
template <std::size_t N>
class FixedArray
{
private:
    int data[N];
};
```
使用：
```cpp
FixedArray<10> arr;
```
`N` 必须在编译期确定。

|对比|模板参数 `N`|构造函数参数 `n`|
|---|---|---|
|确定时间|编译期|运行期|
|是否构成类型|是|否|
|能否使用用户输入|不能|可以|
|不同值是否是不同类型|是|不是|
|灵活性|较低|较高|
|编译期检查能力|更强|较弱|

例如：
```cpp
FixedArray<5>
FixedArray<10>
```
是不同类型。

但是：
```cpp
DynamicArray a(5);
DynamicArray b(10);
```
`a` 和 `b` 仍然是同一种类型：
```cpp
DynamicArray
```
只是对象内部保存的大小不同。

### 20. 使用非类型模板参数有什么好处？
#### 1. 编译期检查
矩阵尺寸可以成为类型的一部分：
```cpp
Matrix<int, 3, 4>
```
传错尺寸时，编译器直接报错。

---
#### 2. 不需要额外保存某些数据
例如：
```cpp
template <std::size_t N>
class Array
{
    int data[N];
};
```
`N` 已经包含在类型中，很多情况下不需要对象内部再保存一个 `size` 成员。

---
#### 3. 编译器更容易优化

因为 `N` 在编译期已知，编译器可能：
- 展开循环；
- 消除条件判断；
- 计算固定内存布局；
- 进行常量传播。

例如：
```cpp
template <std::size_t N>
int Sum(const int (&arr)[N])
{
    int result = 0;

    for (std::size_t i = 0; i < N; ++i)
    {
        result += arr[i];
    }

    return result;
}
```
编译器知道 `N` 的具体值，有机会生成更有针对性的代码。

---
#### 4. 实现零成本抽象

模板参数在编译期确定，不需要运行时查询类型和大小。
这符合 C++ 常说的：
> 不为没有使用的抽象付出运行时成本。

---
### 21. 它也有什么缺点？
#### 1. 不够灵活
运行时用户输入的大小不能直接作为模板实参：
```cpp
int n;
std::cin >> n;

Array<int, n> arr; // 不行
```
这种情况应该使用：
```cpp
std::vector<int> arr(n);
```

---
#### 2. 不同参数会产生不同类型
```cpp
Array<int, 5>
Array<int, 10>
```
无法直接放进同一个只接受单一具体类型的容器里。

---
#### 3. 可能导致代码膨胀

如果大量不同参数都被实例化：

```cpp
Array<int, 1>
Array<int, 2>
Array<int, 3>
// ...
Array<int, 1000>
```
编译器可能为不同实例生成多份代码，增加编译时间和程序体积。

---
### 22. 常见错误
#### 错误一：使用运行时变量
```cpp
int n = GetUserInput();

Array<int, n> arr; // 错误
```
原因：`n` 不是编译期常量。

---
#### 错误二：认为 `Array<int, 5>` 和 `Array<int, 10>` 是相同类型

```cpp
Array<int, 5> a;
Array<int, 10> b;

a = b; // 错误
```
因为模板实参不同。

---
#### 错误三：模板参数类型不适合表示大小
```cpp
template <int N>
class Array
{
};
```
虽然可用，但数组大小一般更推荐：
```cpp
template <std::size_t N>
```
因为 `std::size_t` 就是标准库用来表示对象大小和数组长度的无符号整数类型。

---
#### 错误四：使用负数作为数组长度
```cpp
Array<int, -1> arr;
```
如果模板参数是 `std::size_t`，`-1` 还可能转换成一个非常大的无符号数，导致错误信息很奇怪。
可以增加限制：
```cpp
template <typename T, std::size_t N>
class Array
{
    static_assert(N > 0, "N must be greater than zero");

    T data[N];
};
```

---
#### 错误五：错误理解为对象成员变量
```cpp
template <std::size_t N>
class Array
{
};
```
这里的 `N` 不是每个对象内部自动保存的一份普通成员变量。
它是模板实例化时确定的编译期值。
当然，你可以显式把它暴露出来：
```cpp
template <std::size_t N>
class Array
{
public:
    static constexpr std::size_t size = N;
};
```
使用：
```cpp
std::cout << Array<10>::size;
```

---
### 23. 编译器如何处理非类型模板参数？
假设：
```cpp
template <std::size_t N>
class Buffer
{
private:
    char data[N];
};
```
使用：
```cpp
Buffer<1024> buffer1;
Buffer<2048> buffer2;
```
编译器大致会经历：
```text
1. 读取 Buffer 类模板
2. 看到 Buffer<1024>
3. 把模板参数 N 替换为 1024
4. 生成包含 char data[1024] 的具体类
5. 进行类型检查和代码生成
6. 看到 Buffer<2048>
7. 再生成包含 char data[2048] 的另一个类
```
所以运行时并不是：
```text
Buffer 对象保存一个 N，然后判断 N 是多少
```
而是编译期已经生成了两个不同的具体类型。

---
### 24. 面试回答版本
面试官问：
> 什么是非类型模板参数？

可以这样回答：
非类型模板参数是指模板参数不是一个类型，而是一个编译期常量值。例如：

```cpp
template <typename T, std::size_t N>
class Array
{
    T data[N];
};
```

其中 `T` 是类型模板参数，`N` 是非类型模板参数。使用 `Array<int, 10>` 时，编译器将 `T` 替换为 `int`，将 `N` 替换为 `10`，实例化出一个包含 10 个 `int` 的具体类。

非类型模板实参必须能够在编译期确定，因为模板实例化发生在编译期。不同的非类型模板实参会形成不同类型，例如 `Array<int, 5>` 和 `Array<int, 10>` 是两个不同类型。

非类型模板参数常用于表示数组长度、容量、矩阵维度、标志位等。标准库中的 `std::array<T, N>` 和 `std::bitset<N>` 就使用了非类型模板参数。

---
### 25. 最后总结
基本语法：
```cpp
template <typename T, std::size_t N>
class Array
{
    T data[N];
};
```
使用：
```cpp
Array<int, 10> arr;
```
需要记住：
```text
1. T 代表类型，N 代表编译期常量。
2. 非类型模板实参必须在编译期确定。
3. Array<int, 5> 和 Array<int, 10> 是不同类型。
4. 非类型模板参数的值会成为类型的一部分。
5. 常见用途是数组长度、容量、矩阵维度和标志位。
6. std::array<T, N> 和 std::bitset<N> 是典型应用。
7. 运行时才能确定的大小应使用 vector 等动态容器。
```
最核心的一句话：
> **非类型模板参数，就是把一个编译期常量作为模板的一部分，让编译器根据不同的常量值生成不同的函数或类。**

## 模板的特化

### 概念

这里举一个简单的例子来说明什么是特化，下面是用于比较两个任意相同类型的数据是否相等的函数模板。
```cpp
template<class T>
bool IsEqual(T x, T y)
{
	return x == y;
}
```
我们大概会这样使用该函数模板：
```cpp
cout << IsEqual(1, 1) << endl; //1
cout << IsEqual(1.1, 2.2) << endl; //0
```
这样使用是没有问题的，它的判断结果也是我们所预期的，但是我们也可能会这样去使用该函数模板：
```cpp
char a1[] = "2021dragon";
char a2[] = "2021dragon";
cout << IsEqual(a1, a2) << endl; //0
```
判断结果是这两个字符串不相等，这很好理解，因为我们希望的是该函数能够判断两个字符串的内容是否相等，而该函数实际上判断是确实这两个字符串所存储的地址是否相同，这是两个存在于栈区的字符串，其地址显然是不同的。
类似于上述实例，使用模板可以实现一些与类型无关的代码，但对于一些特殊的类型可能会得到一些错误的结果，此时就需要对模板进行特化，即在原模板的基础上，针对特殊类型进行特殊化的实现方式
### 函数模板特化
对于上述实例，我们知道当传入的类型是char*时，应该依次比较各个字符的ASCII码值进而判断两个字符串是否相等，或是直接调用strcmp函数进行字符串比较，那么此时我们就可以对char*类型进行特殊化的实现。
**函数模板的特化步骤：**
1. 首先必须要有一个基础的函数模板。
2. 关键字template后面接一对空的尖括号<>。
3. 函数名后跟一对尖括号，尖括号中指定需要特化的类型。
4. 函数形参表必须要和模板函数的基础参数类型完全相同，否则不同的编译器可能会报一些奇怪的错误。
对于上述实例char* 类型的特化如下：
```cpp
//基础的函数模板
template<class T>
bool IsEqual(T x, T y)
{
	return x == y;
}
//对于char*类型的特化
template<>
bool IsEqual<char*>(char* x, char* y)
{
	return strcmp(x, y) == 0;
}
```
**注意：** 一般情况下，如果函数模板遇到不能处理或者处理有误的类型，为了实现简单通常都是将该函数直接给出。例如，上述实例char* 类型的特化还可以这样给出：
```cpp
//基础的函数模板
template<class T>
bool IsEqual(T x, T y)
{
	return x == y;
}
//对于char*类型的特化
bool IsEqual(char* x, char* y)
{
	return strcmp(x, y) == 0;
}
```
### 类模板特化
不仅函数模板可以进行特化，类模板也可以针对特殊类型进行特殊化实现，并且类模板的特化又可分为全特化和偏特化（半特化）。
#### 全特化
```
全特化即是将模板参数列表中所有的参数都确定化。
```
例如，对于以下类模板：
```cpp
template<class T1, class T2>
class Dragon
{
public:
	//构造函数
	Dragon()
	{
		cout << "Dragon<T1, T2>" << endl;
	}
private:
	T1 _D1;
	T2 _D2;
};
```
当T1和T2分别是double和int时，我们若是想对实例化的类进行特殊化处理，那么我们就可以对T1和T2分别是double和int时的模板进行特化。
**类模板的特化步骤：**
1. 首先必须要有一个基础的类模板。
2. 关键字template后面接一对空的尖括号<>。
3. 类名后跟一对尖括号，尖括号中指定需要特化的类型。

对于T1是double，T2是int的特化如下：
```cpp
//对于T1是double，T2是int时进行特化
template<>
class Dragon<double, int>
{
public:
	//构造函数
	Dragon()
	{
		cout << "Dragon<double, int>" << endl;
	}
private:
	double _D1;
	int _D2;
};
```
那么如何证明当T1是double，T2是int时，使用的就是我们自己特化的类模板呢？
当我们实例化一个对象时，编译器会自动调用其默认构造函数，我们若是在构造函数当中打印适当的提示信息，那么当我们实例化对象后，通过观察控制台上打印的结果，即可确定实例化该对象时调用的是不是我们自己特化的类模板了。
![](../../_Pasted_Image/Pasted%20image%2020260722155707.png)

#### 偏特化
```
偏特化是指任何针对模板参数进一步进行条件限制设计的特化版本。
```
例如，对于以下类模板：
```cpp
template<class T1, class T2>
class Dragon
{
public:
	//构造函数
	Dragon()
	{
		cout << "Dragon<T1, T2>" << endl;
	}
private:
	T1 _D1;
	T2 _D2;
};
```
偏特化又可分为以下两种表现形式：  
**1、部分特化**  
我们可以仅对模板参数列表中的部分参数进行确定化。  
例如，我们可以对T1为int类型的类进行特殊化处理。
```cpp
//对T1为int的类进行特化
template<class T2>
class Dragon<int, T2>
{
public:
	//构造函数
	Dragon()
	{
		cout << "Dragon<int, T2>" << endl;
	}
private:
	int _D1;
	T2 _D2;
};
```
**2、参数更进一步的限制**  
偏特化并不仅仅是指特化部分参数，而是针对模板参数进一步的条件限制所设计出来的一个特化版本。  
例如，我们还可以指定当T1和T2为某种类型时，使用我们特殊化的类模板。
```cpp
//两个参数偏特化为指针类型
template<class T1, class T2>
class Dragon<T1*, T2*>
{
public:
	//构造函数
	Dragon()
	{
		cout << "Dragon<T1*, T2*>" << endl;
	}
private:
	T1 _D1;
	T2 _D2;
};
//两个参数偏特化为引用类型
template<class T1, class T2>
class Dragon<T1&, T2&>
{
public:
	//构造函数
	Dragon()
	{
		cout << "Dragon<T1&, T2&>" << endl;
	}
private:
	T1 _D1;
	T2 _D2;
};
```
此时，当实例化对象的T1和T2同时为指针类型或同时为引用类型时，就会分别调用我们特化的两个类模板。

### 模板总结

**优点：**
1. 模板复用了代码，节省资源，更快的迭代开发，C++的标准模板库（STL）因此而产生。
2. 增强了代码的灵活性。

**缺陷：**
1. 模板会导致代码膨胀问题，也会导致编译时间变长。
2. 出现模板编译错误时，错误信息非常凌乱，不易定位错误。


## ai讲解模板的特化

模板的作用是为不同类型提供一份通用代码：

```cpp
template <typename T>
class Printer
{
public:
    void Print(const T& value)
    {
        std::cout << value << '\n';
    }
};
```
这份代码可能适用于 `int`、`double`、`std::string` 等很多类型。

但是，有时通用模板对某个特殊类型：

- 无法使用；
- 处理方式不正确；
- 可以有更高效的实现；
- 需要完全不同的行为。

这时就需要使用**模板特化**。

> 模板特化就是：为模板的某个具体类型，或者某一类特殊类型，提供专门实现。

---

### 1. 为什么需要模板特化？

假设我们写一个通用比较器：
```cpp
template <typename T>
bool IsEqual(const T& left, const T& right)
{
    return left == right;
}
```
对于整数：
```cpp
IsEqual(10, 10);
```
没有问题。
但是对于 C 风格字符串：
```cpp
const char* str1 = "hello";
const char* str2 = "hello";

IsEqual(str1, str2);
```
模板实例化后大致是：
```cpp
bool IsEqual<const char*>(
    const char* const& left,
    const char* const& right)
{
    return left == right;
}
```
这里比较的是两个指针保存的**地址**，而不是字符串内容。
如果我们希望 `const char*` 比较字符串内容，就需要单独处理：
```cpp
std::strcmp(left, right) == 0
```
这就是模板特化的使用场景。

---

### 2. 什么是主模板？

在讨论特化之前，先认识**主模板**，也叫原始模板、primary template。
```cpp
template <typename T>
class TypeInfo
{
public:
    static void Print()
    {
        std::cout << "普通类型\n";
    }
};
```
这就是主模板。
它定义了默认的通用实现。
使用：
```cpp
TypeInfo<int>::Print();
TypeInfo<double>::Print();
TypeInfo<std::string>::Print();
```
如果没有更加匹配的特化版本，编译器就使用主模板。

可以理解成：
```text
主模板 = 默认方案
特化版本 = 特殊情况的专用方案
```

---

# 3. 模板特化的主要分类

模板特化主要分为：
```text
模板特化
├── 全特化
└── 偏特化
```

其中：
- 类模板支持全特化；
- 类模板支持偏特化；
- 函数模板支持全特化；
- 函数模板不能直接偏特化，通常使用函数重载代替。

这是面试高频结论。

---

### 4. 类模板全特化

#### 4.1 什么是全特化？

全特化指的是：
> 把模板的全部模板参数都指定为确定的类型或值，并为它提供专门实现。

先定义主模板：
```cpp
#include <iostream>
using namespace std;

template <typename T>
class TypeInfo
{
public:
    static void Print()
    {
        cout << "普通类型\n";
    }
};
```

然后针对 `int` 完全特化：

```cpp
template <>
class TypeInfo<int>
{
public:
    static void Print()
    {
        cout << "int 类型\n";
    }
};
```

使用：

```cpp
int main()
{
    TypeInfo<double>::Print();
    TypeInfo<int>::Print();
}
```

输出：

```text
普通类型
int 类型
```

---

#### 4.2 全特化语法
```cpp
template <>
class 模板名<具体类型>
{
    // 专门实现
};
```
例如：
```cpp
template <>
class TypeInfo<int>
{
};
```
这里：
```cpp
template <>
```
表示这不是一个新的普通类，而是某个模板的显式全特化。

而：
```cpp
TypeInfo<int>
```
表示针对 `T = int`。

---

#### 4.3 编译器如何选择？
当编译器看到：
```cpp
TypeInfo<double>
```
没有 `double` 的专门实现，于是使用主模板。

当编译器看到：
```cpp
TypeInfo<int>
```
发现存在精确的 `int` 全特化版本，于是优先使用全特化。

选择过程可以理解为：
```text
TypeInfo<int>
    ↓
是否有 int 的全特化？
    ↓ 有
使用 TypeInfo<int> 特化版本
```

---

### 5. 全特化可以完全改变类结构

特化版本不需要和主模板拥有相同的成员。
例如主模板：
```cpp
template <typename T>
class Storage
{
private:
    T value;

public:
    void Set(const T& value)
    {
        this->value = value;
    }

    const T& Get() const
    {
        return value;
    }
};
```

针对 `bool` 特化：
```cpp
template <>
class Storage<bool>
{
private:
    unsigned char value : 1;

public:
    void Set(bool value)
    {
        this->value = value;
    }

    bool Get() const
    {
        return value != 0;
    }

    void PrintBoolean() const
    {
        std::cout << (Get() ? "true" : "false") << '\n';
    }
};
```
`Storage<bool>` 可以有完全不同的数据结构和成员函数。

因此：
> 类模板特化不是简单地替换 `T`，而是可以重新编写整个类。

---

### 6. 类模板偏特化

#### 6.1 什么是偏特化？

偏特化指的是： 没有把所有模板参数完全确定下来，而是为满足某种形式的一类模板实参提供特殊实现。
例如，我们希望所有普通类型使用主模板，但所有指针类型使用特殊版本。

主模板：
```cpp
template <typename T>
class TypeInfo
{
public:
    static void Print()
    {
        std::cout << "普通类型\n";
    }
};
```

指针类型偏特化：

```cpp
template <typename T>
class TypeInfo<T*>
{
public:
    static void Print()
    {
        std::cout << "指针类型\n";
    }
};
```

使用：

```cpp
TypeInfo<int>::Print();
TypeInfo<int*>::Print();
TypeInfo<double*>::Print();
```
输出：
```text
普通类型
指针类型
指针类型
```
这里的偏特化不是只针对：
```cpp
int*
```
而是针对所有：
```cpp
T*
```
形式的类型。
因此：
```cpp
int*
double*
std::string*
Player*
```
都会匹配该偏特化。

---
#### 6.2 为什么叫“偏”特化？
因为它只固定了一部分特征：
```cpp
T*
```
固定的是：类型必须是指针。
但没有固定指针指向的具体类型：
```cpp
T
```
仍然由编译器推导。
所以：
```text
全特化：TypeInfo<int>
         所有参数都确定

偏特化：TypeInfo<T*>
         确定是指针，但 T 仍然未知
```

---
### 7. 多个模板参数的偏特化

假设主模板有两个参数：
```cpp
template <typename T1, typename T2>
class PairInfo
{
public:
    static void Print()
    {
        std::cout << "普通组合\n";
    }
};
```
可以固定第二个类型为 `int`：
```cpp
template <typename T>
class PairInfo<T, int>
{
public:
    static void Print()
    {
        std::cout << "第二个类型是 int\n";
    }
};
```
使用：
```cpp
PairInfo<double, double>::Print();
PairInfo<double, int>::Print();
PairInfo<std::string, int>::Print();
```
其中：
```cpp
PairInfo<double, int>
PairInfo<std::string, int>
```
都会匹配偏特化：
```cpp
PairInfo<T, int>
```

---
#### 固定两个参数相同
还可以写：
```cpp
template <typename T>
class PairInfo<T, T>
{
public:
    static void Print()
    {
        std::cout << "两个类型相同\n";
    }
};
```

那么：

```cpp
PairInfo<int, int>
PairInfo<double, double>
```
都匹配这个版本。
而：
```cpp
PairInfo<int, double>
```
不匹配。

---
### 8. 非类型模板参数的特化
你前面学习了非类型模板参数，也可以对它进行特化。
主模板：
```cpp
template <int N>
class NumberInfo
{
public:
    static void Print()
    {
        std::cout << "普通数字：" << N << '\n';
    }
};
```
针对 `0` 全特化：
```cpp
template <>
class NumberInfo<0>
{
public:
    static void Print()
    {
        std::cout << "这是零\n";
    }
};
```
使用：
```cpp
NumberInfo<10>::Print();
NumberInfo<0>::Print();
```
编译器会分别选择：
```text
NumberInfo<10> → 主模板
NumberInfo<0>  → 全特化
```

---
#### 多个参数的偏特化
```cpp
template <typename T, std::size_t N>
class ArrayInfo
{
public:
    static void Print()
    {
        std::cout << "普通数组\n";
    }
};
```
针对长度为 `0` 的情况特化：
```cpp
template <typename T>
class ArrayInfo<T, 0>
{
public:
    static void Print()
    {
        std::cout << "长度为零\n";
    }
};
```

这里：
- `N` 被固定成 `0`；
- `T` 仍然未知。
所以这是偏特化。

---
### 9. 多个偏特化同时匹配时怎么办？

假设有主模板：
```cpp
template <typename T>
class TypeInfo
{
public:
    static void Print()
    {
        std::cout << "普通类型\n";
    }
};
```
一个指针偏特化：
```cpp
template <typename T>
class TypeInfo<T*>
{
public:
    static void Print()
    {
        std::cout << "指针类型\n";
    }
};
```
一个 `const` 偏特化：
```cpp
template <typename T>
class TypeInfo<const T>
{
public:
    static void Print()
    {
        std::cout << "const 类型\n";
    }
};
```
现在：
```cpp
TypeInfo<int*>
```
匹配指针偏特化。
```cpp
TypeInfo<const int>
```
匹配 `const` 偏特化。

但：
```cpp
TypeInfo<const int*>
```
要注意它表示：
```cpp
指向 const int 的指针
```
它可以匹配：
```cpp
TypeInfo<T*>
```
其中：
```cpp
T = const int
```
但它不匹配：
```cpp
TypeInfo<const T>
```
因为整个类型最外层是指针，不是 `const`。
如果是：
```cpp
int* const
```
表示指针本身为 `const`，类型结构又不一样。
模板匹配本质上是按照完整类型形式进行匹配。

---
#### 更特殊的版本优先
例如：
```cpp
template <typename T>
class TypeInfo<T*>
{
public:
    static void Print()
    {
        std::cout << "任意指针\n";
    }
};
```
再提供：
```cpp
template <typename T>
class TypeInfo<const T*>
{
public:
    static void Print()
    {
        std::cout << "指向 const 对象的指针\n";
    }
};
```
调用：
```cpp
TypeInfo<int*>::Print();
```
匹配：
```cpp
TypeInfo<T*>
```
调用：
```cpp
TypeInfo<const int*>::Print();
```
两个偏特化都有可能匹配，但：
```cpp
TypeInfo<const T*>
```
限制更具体，因此编译器选择更特殊的版本。
大致选择优先级：
```text
全特化
   ↓
最匹配、最特殊的偏特化
   ↓
主模板
```
但全特化和偏特化的选择规则严格来说由模板匹配和偏序规则决定，不要简单机械地认为任何全特化都无条件优于一切，核心是当前模板实参匹配哪个已声明的最佳候选。

---

### 10. 函数模板全特化
函数模板可以全特化。
主模板：
```cpp
#include <cstring>
#include <iostream>

template <typename T>
bool IsEqual(const T& left, const T& right)
{
    std::cout << "主模板\n";
    return left == right;
}
```

针对 `const char*` 全特化：

```cpp
template <>
bool IsEqual<const char*>(
    const char* const& left,
    const char* const& right)
{
    std::cout << "const char* 特化\n";
    return std::strcmp(left, right) == 0;
}
```
使用：
```cpp
int main()
{
    std::cout << IsEqual(10, 10) << '\n';

    const char* s1 = "hello";
    const char* s2 = "hello";

    std::cout << IsEqual(s1, s2) << '\n';
}
```

---

### 11. 为什么参数看起来是 `const char* const&`？

主模板的参数是：
```cpp
const T& left
```
当：
```cpp
T = const char*
```
代入后是：
```cpp
const T&
```
注意，外层的 `const` 修饰的是 `T` 本身。
`T` 本身是：
```cpp
const char*
```
给这个指针类型再加顶层 `const`，得到：
```cpp
const char* const
```
再加引用：
```cpp
const char* const&
```

意思是：对一个常量指针的引用，这个指针指向 const char。

这也说明模板替换时要把 `T` 当成一个整体代入，不能只靠直觉拼接。

---
### 12. 函数模板不能偏特化
假设主模板：
```cpp
template <typename T>
void Print(T value)
{
}
```
你可能想为所有指针类型写偏特化：
```cpp
template <typename T>
void Print<T*>(T* value) // 错误：函数模板不能这样偏特化
{
}
```

这是不允许的。

面试必须记住：
> **类模板可以偏特化，函数模板不能直接偏特化。**

---
### 13. 函数模板为什么用重载代替偏特化？
对于指针类型，可以直接写函数模板重载：
```cpp
template <typename T>
void Print(const T& value)
{
    std::cout << "普通版本：" << value << '\n';
}
```
再添加一个指针版本：
```cpp
template <typename T>
void Print(T* value)
{
    std::cout << "指针版本\n";
}
```
调用：
```cpp
int number = 10;

Print(number);
Print(&number);
```
编译器通过函数重载决议选择合适版本。
因此函数模板通常采用：
```text
主函数模板
+
函数模板重载
```
来处理不同类型形式。

---

### 14. 函数模板特化和函数重载的区别
这是非常容易混淆的地方。

#### 函数模板特化
```cpp
template <typename T>
void Print(T value)
{
    std::cout << "主模板\n";
}

template <>
void Print<int>(int value)
{
    std::cout << "int 特化\n";
}
```
`Print<int>` 是主模板的特殊实现。
它依赖于主模板存在。

---
#### 普通函数重载
```cpp
template <typename T>
void Print(T value)
{
    std::cout << "模板版本\n";
}

void Print(int value)
{
    std::cout << "普通函数版本\n";
}
```
这里的：
```cpp
void Print(int)
```
是一个独立的普通函数，不是模板特化。

---

#### 函数模板重载
```cpp
template <typename T>
void Print(T value)
{
    std::cout << "按值版本\n";
}

template <typename T>
void Print(T* value)
{
    std::cout << "指针版本\n";
}
```
这里是两个不同的函数模板，形成重载关系。

---

### 15. 实际开发中，函数模板常优先使用重载

对于函数模板，通常建议：
> 能用重载表达的特殊行为，优先使用重载，而不是显式特化。

原因包括：
1. 函数模板特化会参与一套较复杂的模板与重载规则；
2. 特化不是一个独立重载候选；
3. 重载通常更直观；
4. 可以处理一类类型，而不只是一个具体类型；
5. 更容易配合约束、Concepts 和类型特征。

例如 C 字符串比较，更直接的写法是普通函数重载：
```cpp
template <typename T>
bool IsEqual(const T& left, const T& right)
{
    return left == right;
}

bool IsEqual(const char* left, const char* right)
{
    return std::strcmp(left, right) == 0;
}
```
调用时，普通函数版本会参与重载决议。

---
### 16. 类模板成员函数的特化
可以只特化类模板中的某个成员函数，而不是特化整个类。
主模板：
```cpp
template <typename T>
class Printer
{
public:
    void Print(const T& value)
    {
        std::cout << "普通打印：" << value << '\n';
    }
};
```
只特化 `Printer<const char*>::Print`：
```cpp
template <>
void Printer<const char*>::Print(const char* const& value)
{
    std::cout << "C 字符串打印：" << value << '\n';
}
```
使用：
```cpp
Printer<int> p1;
p1.Print(10);

Printer<const char*> p2;
p2.Print("hello");
```
此时只改变了 `Print` 成员函数的实现，类的其他结构仍然来自主模板。

---

### 17. 全特化整个类后，成员不再自动来自主模板

假设主模板：
```cpp
template <typename T>
class Test
{
public:
    void Func1()
    {
    }

    void Func2()
    {
    }
};
```

全特化：
```cpp
template <>
class Test<int>
{
public:
    void Func1()
    {
    }
};
```
那么：
```cpp
Test<int>
```
只有特化版本中明确声明的成员。
它不会自动继承主模板中的 `Func2`。
```cpp
Test<int> t;
t.Func1();
// t.Func2(); // 错误
```
因为完整类特化相当于重新定义了这个具体类。

---
### 18. 偏特化和继承无关
看到：
```cpp
template <typename T>
class TypeInfo<T*>
{
};
```
不要认为它继承了：
```cpp
TypeInfo<T>
```
特化和继承是不同机制。
主模板与特化版本之间不存在自动继承关系。
如果特化版本需要复用主模板代码，必须显式组织，例如通过继承辅助基类或提取公共实现。

---
### 19. 特化必须在主模板之后声明
错误顺序：
```cpp
template <>
class TypeInfo<int>
{
};

template <typename T>
class TypeInfo
{
};
```
编译器还不知道 `TypeInfo` 是什么模板，不能先特化。
正确顺序：
```cpp
template <typename T>
class TypeInfo
{
};

template <>
class TypeInfo<int>
{
};
```
所以：
> 必须先有主模板，才能对它进行特化。

---
### 20. 特化要在首次实例化之前可见
假设先使用：
```cpp
TypeInfo<int> object;
```
编译器可能已经根据主模板实例化了 `TypeInfo<int>`。
之后再声明：
```cpp
template <>
class TypeInfo<int>
{
};
```
就太晚了，可能导致编译错误或跨翻译单元的不一致问题。
因此：
> 显式特化应当在第一次会导致对应隐式实例化的使用之前声明，并且相关翻译单元应看到一致的声明。

实际工程中，通常把主模板和特化声明放在头文件里。

---
### 21. 特化和命名空间
假设主模板定义在命名空间中：
```cpp
namespace MyLib
{
    template <typename T>
    class TypeInfo
    {
    };
}
```
其显式特化需要在允许的命名空间作用域中声明，常见写法：
```cpp
namespace MyLib
{
    template <>
    class TypeInfo<int>
    {
    };
}
```
不能随意在无关作用域中创建一个看似同名的特化。

### 22. 类模板偏特化的完整示例
```cpp
#include <iostream>
using namespace std;

// 主模板
template <typename T1, typename T2>
class TypeRelation
{
public:
    static void Print()
    {
        cout << "两个普通类型\n";
    }
};

// 两个类型相同的偏特化
template <typename T>
class TypeRelation<T, T>
{
public:
    static void Print()
    {
        cout << "两个类型相同\n";
    }
};

// 第二个类型是指针的偏特化
template <typename T1, typename T2>
class TypeRelation<T1, T2*>
{
public:
    static void Print()
    {
        cout << "第二个类型是指针\n";
    }
};

// int 和 int 的全特化
template <>
class TypeRelation<int, int>
{
public:
    static void Print()
    {
        cout << "两个类型都是 int\n";
    }
};

int main()
{
    TypeRelation<int, double>::Print();
    TypeRelation<double, double>::Print();
    TypeRelation<int, double*>::Print();
    TypeRelation<int, int>::Print();
}
```
大致输出：
```text
两个普通类型
两个类型相同
第二个类型是指针
两个类型都是 int
```
对应选择：
```text
TypeRelation<int, double>
→ 主模板

TypeRelation<double, double>
→ TypeRelation<T, T> 偏特化

TypeRelation<int, double*>
→ TypeRelation<T1, T2*> 偏特化

TypeRelation<int, int>
→ int,int 全特化
```

---
### 23. 模板特化的底层理解
假设：
```cpp
template <typename T>
class TypeInfo
{
public:
    static void Print()
    {
        std::cout << "普通类型\n";
    }
};

template <>
class TypeInfo<int>
{
public:
    static void Print()
    {
        std::cout << "int 类型\n";
    }
};
```
当编译器遇到：
```cpp
TypeInfo<double>
```
它会寻找：
1. 有没有精确的全特化；
2. 有没有能够匹配的偏特化；
3. 如果都没有，使用主模板。

当遇到：
```cpp
TypeInfo<int>
```
它发现存在对应全特化，于是直接采用专门定义。
所以模板特化不是运行时的：
```cpp
if (type == int)
```
而是编译期选择不同模板定义。
运行时并不存在这样的判断：
```text
如果对象类型是 int，就进入特化分支
```
编译器已经在编译期间生成了相应的具体代码。

### 24. 特化和 `if constexpr` 的区别
有时不用特化，也可以在模板内部写：
```cpp
#include <type_traits>

template <typename T>
void Print(const T& value)
{
    if constexpr (std::is_pointer_v<T>)
    {
        std::cout << "指针类型\n";
    }
    else
    {
        std::cout << "普通类型：" << value << '\n';
    }
}
```
`if constexpr` 会在编译期选择分支，未选择分支不会按普通运行时分支那样参与最终代码生成。

对比：
#### 模板特化
```cpp
template <typename T>
class TypeInfo
{
};

template <typename T>
class TypeInfo<T*>
{
};
```

适合：
- 类型结构或类布局完全不同；
- 不同类型需要完全不同的实现；
- 类型特征元编程；
- 需要为一类模板参数提供独立定义。

#### `if constexpr`
```cpp
if constexpr (condition)
{
}
else
{
}
```

适合：
- 大部分代码相同；
- 只有局部逻辑不同；
- 希望把实现集中在一个模板中。

# 25. C++20 Concepts 和特化的关系
现代 C++ 还可以用 Concepts 限制模板。
例如：
```cpp
#include <concepts>
#include <iostream>

template <typename T>
requires std::integral<T>
void Print(T value)
{
    std::cout << "整数：" << value << '\n';
}

template <typename T>
requires std::floating_point<T>
void Print(T value)
{
    std::cout << "浮点数：" << value << '\n';
}
```
这属于受约束的函数模板重载，不是显式特化。
它表达的是：
```text
满足 integral 的类型使用一个版本
满足 floating_point 的类型使用另一个版本
```
在现代 C++ 中，很多“针对一类类型提供不同函数行为”的场景，会优先使用：
- 函数重载；
- Concepts；
- `if constexpr`；
- 类型特征。
而类模板的布局和结构差异，仍然很常使用偏特化。

### 26. 常见错误
#### 错误一：函数模板偏特化
```cpp
template <typename T>
void Func(T value)
{
}

template <typename T>
void Func<T*>(T* value) // 错误
{
}
```
应改为重载：
```cpp
template <typename T>
void Func(T value)
{
}

template <typename T>
void Func(T* value)
{
}
```

---
#### 错误二：忘记 `template <>`
错误：
```cpp
class TypeInfo<int>
{
};
```
正确：
```cpp
template <>
class TypeInfo<int>
{
};
```

---
#### 错误三：特化写在主模板之前
必须先声明或定义主模板，再提供特化。

---
#### 错误四：认为特化版本继承主模板成员
完整类特化是重新定义具体类，不会自动获得主模板成员。

---
#### 错误五：在特化声明前已经实例化
特化应在首次导致隐式实例化之前可见。

---
#### 错误六：把函数重载称为函数模板特化
```cpp
void Print(int);
```
如果没有：
```cpp
template <>
```
它通常只是普通函数重载，不是模板特化。

### 27. 面试回答版本

面试官问：

> 什么是模板特化？

可以这样回答：

模板特化是指在已有主模板的基础上，为某个具体模板实参，或者满足某种形式的一类模板实参提供专门实现。

全特化会确定全部模板参数，例如 `TypeInfo<int>`；偏特化只限定部分模板参数或类型形式，例如 `TypeInfo<T*>`，它可以匹配所有指针类型。

类模板既支持全特化，也支持偏特化；函数模板支持全特化，但不支持直接偏特化，函数模板通常通过重载实现类似效果。

编译器会在编译期根据模板实参选择最匹配的版本：如果有合适的特化，就使用特化；否则使用主模板。特化必须在主模板之后声明，并且应在对应模板第一次隐式实例化之前可见。

### 28. 最后总结
基本结构：
```cpp
// 主模板
template <typename T>
class TypeInfo
{
};
```
全特化：
```cpp
template <>
class TypeInfo<int>
{
};
```
偏特化：
```cpp
template <typename T>
class TypeInfo<T*>
{
};
```
核心结论：
```text
1. 主模板是默认实现。
2. 全特化针对一个完全确定的模板实参组合。
3. 偏特化针对满足某种形式的一类模板实参。
4. 类模板支持全特化和偏特化。
5. 函数模板支持全特化，但不能直接偏特化。
6. 函数模板通常使用重载代替偏特化。
7. 特化在编译期进行选择，不是运行时判断。
8. 特化必须建立在已有主模板之上。
9. 完整类特化可以完全改变类的结构。
10. 特化版本不会自动继承主模板中的成员。
```
最核心的一句话：
> **模板是通用方案，特化是在编译期为特殊类型或特殊参数形式提供的专用方案。**
