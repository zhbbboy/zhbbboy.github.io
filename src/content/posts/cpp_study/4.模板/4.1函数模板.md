## 泛型编程引入

在学习 C++ 模板之前，我们可以先思考一个问题：如果现在需要编写一个函数，用来交换两个变量的值，应该怎么实现？

在 C 语言中，如果我们要交换两个整型变量，可以这样写：

```cpp
// 交换两个整型
void Swapi(int* p1, int* p2)
{
    int tmp = *p1;
    *p1 = *p2;
    *p2 = tmp;
}
```

如果要交换两个 `double` 类型变量，又需要再写一个函数：

```cpp
// 交换两个双精度浮点型
void Swapd(double* p1, double* p2)
{
    double tmp = *p1;
    *p1 = *p2;
    *p2 = tmp;
}
```

由于 C 语言不支持函数重载，所以不同类型的交换函数不能使用完全相同的函数名。并且为了真正修改实参的值，通常需要通过指针进行地址传递。

这种写法虽然可以解决问题，但存在明显缺点：如果以后还要交换 `char`、`float`、`long` 或者自定义类型对象，就需要继续编写新的函数。也就是说，虽然这些函数的逻辑完全相同，都是“交换两个变量的值”，但由于变量类型不同，我们不得不重复编写大量相似代码。

学习了 C++ 的函数重载和引用之后，我们可以把代码改写得更自然一些：

```cpp
// 交换两个整型
void Swap(int& x, int& y)
{
    int tmp = x;
    x = y;
    y = tmp;
}

// 交换两个双精度浮点型
void Swap(double& x, double& y)
{
    double tmp = x;
    x = y;
    y = tmp;
}
```

相比 C 语言的写法，这种方式有两个优点：

第一，C++ 支持函数重载，所以不同类型的交换函数可以使用相同的函数名 `Swap`。

第二，C++ 支持引用传参，所以不需要显式传指针，代码看起来更加简洁、直观。

但是，这种写法仍然没有从根本上解决问题。因为这些重载函数除了类型不同以外，函数体的逻辑几乎完全一样。只要出现一种新的类型，就需要新增一个对应的重载函数。

例如：

```cpp
void Swap(char& x, char& y);
void Swap(float& x, float& y);
void Swap(long& x, long& y);
```

如果类型越来越多，代码就会越来越冗余，可维护性也会变差。更严重的是，如果交换逻辑本身需要修改，那么所有重载版本都可能要同步修改，这就增加了出错的可能性。

因此，我们希望能有一种机制：只写一份通用的交换逻辑，而不关心具体的数据类型。当真正使用这个函数时，再让编译器根据传入的类型自动生成对应类型的函数代码。

也就是说，我们希望告诉编译器：

> 我先给你一个通用的函数模子，至于具体类型是什么，等使用的时候你再根据实际类型去生成对应代码。

这就像做月饼的模具一样。模具本身决定了月饼的形状，但放入不同的材料，就可以做出不同口味的月饼。类似地，在 C++ 中，我们可以先写出一个通用的代码模板，然后让编译器根据不同的类型生成对应的函数。

这就是 C++ 模板要解决的问题。

例如，使用函数模板可以这样实现通用交换函数：

```cpp
template <class T>
void Swap(T& x, T& y)
{
    T tmp = x;
    x = y;
    y = tmp;
}
```

这样一来，无论是 `int`、`double`，还是其他支持赋值操作的类型，都可以使用同一个 `Swap` 模板：

```cpp
int a = 10, b = 20;
Swap(a, b);

double x = 1.1, y = 2.2;
Swap(x, y);
```

编译器会根据实参类型自动推导出模板参数 `T` 的具体类型。比如调用 `Swap(a, b)` 时，`T` 会被推导为 `int`；调用 `Swap(x, y)` 时，`T` 会被推导为 `double`。

所以，模板的本质可以理解为：

> 模板不是一个具体的函数，而是编译器用来生成具体函数的一套规则。

通过模板，我们可以编写与具体类型无关的通用代码，从而提高代码复用性，减少重复代码。

这就是泛型编程的思想。

泛型编程指的是：编写与具体类型无关的通用代码，使同一套逻辑可以适用于多种不同的数据类型。模板是 C++ 实现泛型编程的基础。

## 函数模板

### 函数模板的概念

 函数模板代表了一个函数家族，该函数模板与类型无关，在使用时被参数化，根据实参类型产生函数的特定类型版本。
 ### 函数模板的格式
```cpp
 template<typename T1,typename T2,…,typename Tn>  
 返回类型 函数名(参数列表)  
 {  
   //函数体  
 }
```
例如：
```cpp
template<typename T>
void Swap(T& x, T& y)
{
	T tmp = x;
	x = y;
	y = tmp;
}
```
**注意**：typename是用来定义模板参数的关键字，也可以用class代替，但是不能用struct代替。

### 函数模板的原理

那么函数模板的底层原理是什么呢？大家都知道，瓦特改良蒸汽机，人类开始了工业革命，解放了生产力。机器生产淘汰掉了很多手工产品。其本质就是将重复的工作交给了机器去完成。有人给出了论调：懒人创造世界！

函数模板是一个蓝图，它本身并不是函数。是编译器产生特定具体类型函数的模具。所以其实模板就是将本来应该我们做的重复的事情交给了编译器。
![](../../_Pasted_Image/Pasted%20image%2020260718143958.png)
在编译器编译阶段，对于函数模板的使用，编译器需要根据传入的实参类型来推演生成对应类型的函数以供调用。比如，当用int类型使用函数模板时，编译器通过对实参类型的推演，将T确定为int类型，然后产生一份专门处理int类型的代码，对于double类型也是如此。

### 函数模板的实例化

 **用不同类型的参数使用模板时，称为模板的实例化**。模板实例化分为隐式实例化和显示实例化。
#### 一、隐式实例化：让编译器根据实参推演模板参数的实际类型
```cpp
#include <iostream>
using namespace std;
template<typename T>
T Add(const T& x, const T& y)
{
	return x + y;
}
int main()
{
	int a = 10, b = 20;
	int c = Add(a, b); //编译器根据实参a和b推演出模板参数为int类型
	return 0;
}
```
**特别注意**：使用模板时，编译器一般不会进行类型转换操作。所以，以下代码将不能通过编译：

```cpp
	int a = 10;
	double b = 1.1;
	int c = Add(a, b);
```
因为在编译期间，编译器根据实参推演模板参数的实际类型时，根据实参a将T推演为int，根据实参b将T推演为double，但是模板参数列表中只有一个T，编译器无法确定此处应该将T确定为int还是double。
此时，我们有两种处理方式，第一种就是我们在传参时将b强制转换为int类型，第二种就是使用下面说到的显示实例化。
#### 二、显示实例化：在函数名后的<>中指定模板参数的实际类型
```cpp
#include <iostream>
using namespace std;
template<typename T>
T Add(const T& x, const T& y)
{
	return x + y;
}
int main()
{
	int a = 10;
	double b = 1.1;
	int c = Add<int>(a, b); //指定模板参数的实际类型为int
	return 0;
}

```
**注意**：使用显示实例化时，如果传入的参数类型与模板参数类型不匹配，编译器会尝试进行隐式类型转换，如果无法转换成功，则编译器将会报错。

### 函数模板的匹配原则

#### 一、一个非模板函数可以和一个同名的函数模板同时存在，而且该函数模板还可以被实例化为这个非模板函数
```cpp
#include <iostream>
using namespace std;
//专门用于int类型加法的非模板函数
int Add(const int& x, const int& y)
{
	return x + y;
}
//通用类型加法的函数模板
template<typename T>
T Add(const T& x, const T& y)
{
	return x + y;
}
int main()
{
	int a = 10, b = 20;
	int c = Add(a, b); //调用非模板函数，编译器不需要实例化
	int d = Add<int>(a, b); //调用编译器实例化的Add函数
	return 0;
}

```
#### 二、对于非模板函数和同名的函数模板，如果其他条件都相同，在调用时会优先调用非模板函数，而不会从该模板产生出一个实例。如果模板可以产生一个具有更好匹配的函数，那么选择模板
```cpp
#include <iostream>
using namespace std;
//专门用于int类型加法的非模板函数
int Add(const int& x, const int& y)
{
	return x + y;
}
//通用类型加法的函数模板
template<typename T1, typename T2>
T1 Add(const T1& x, const T2& y)
{
	return x + y;
}
int main()
{
	int a = Add(10, 20); //与非模板函数完全匹配，不需要函数模板实例化
	int b = Add(2.2, 2); //函数模板可以生成更加匹配的版本，编译器会根据实参生成更加匹配的Add函数
	return 0;
}
```
#### 三、模板函数不允许自动类型转换，但普通函数可以进行自动类型转换
```cpp
#include <iostream>
using namespace std;
template<typename T>
T Add(const T& x, const T& y)
{
	return x + y;
}
int main()
{
	int a = Add(2, 2.2); //模板函数不允许自动类型转换，不能通过编译
	return 0;
}

```
因为模板函数不允许自动类型转换，所以不会将2自动转换为2.0，或是将2.2自动转换为2。

## AI讲解的函数模板

前面我们已经知道，函数重载虽然可以让不同类型使用相同的函数名，但是仍然需要重复编写逻辑相同的函数：

```cpp
void Swap(int& x, int& y)
{
    int tmp = x;
    x = y;
    y = tmp;
}

void Swap(double& x, double& y)
{
    double tmp = x;
    x = y;
    y = tmp;
}
```

这两个函数的逻辑完全相同，只是处理的数据类型不同。

为了解决这种代码重复问题，C++ 提供了**函数模板**。

> 函数模板是一份与具体类型无关的函数代码。编译器可以根据调用时的实际类型，生成对应类型的具体函数。

---

### 1. 函数模板的基本语法

函数模板的一般格式：

```cpp
template <typename T>
返回值类型 函数名(参数列表)
{
    函数体;
}
```

例如交换函数：

```cpp
template <typename T>
void Swap(T& x, T& y)
{
    T tmp = x;
    x = y;
    y = tmp;
}
```

这里的 `T` 不是某个具体类型，而是一个**模板类型参数**，可以把它理解为一个类型占位符。

调用时：
```cpp
int a = 10;
int b = 20;
Swap(a, b);
```

编译器发现两个实参都是 `int`，于是将 `T` 推导为 `int`，并生成一个类似这样的函数：

```cpp
void Swap(int& x, int& y)
{
    int tmp = x;
    x = y;
    y = tmp;
}
```

再调用：

```cpp
double x = 1.1;
double y = 2.2;
Swap(x, y);
```

编译器会将 `T` 推导为 `double`，生成：

```cpp
void Swap(double& x, double& y)
{
    double tmp = x;
    x = y;
    y = tmp;
}
```

因此，函数模板可以理解为：

```text
函数模板 + 具体类型
          ↓
编译器生成具体函数
```

---

### 2. `typename` 的含义

```cpp
template <typename T>
```

这里：

- `template` 表示接下来声明或定义的是一个模板；
    
- 尖括号中是模板参数列表；
    
- `typename` 表示后面的 `T` 是一个类型参数；
    
- `T` 是人为起的名字，可以换成其他合法标识符。
    

例如：

```cpp
template <typename Type>
void Swap(Type& x, Type& y)
{
    Type tmp = x;
    x = y;
    y = tmp;
}
```

这和：

```cpp
template <typename T>
void Swap(T& x, T& y)
```

没有本质区别。

但习惯上，简单的模板类型参数通常命名为：

```cpp
T
U
Type
ValueType
```

---

### 3. `typename` 和 `class`

函数模板还可以写成：

```cpp
template <class T>
void Swap(T& x, T& y)
{
    T tmp = x;
    x = y;
    y = tmp;
}
```

在模板参数列表中，下面两种写法基本等价：

```cpp
template <typename T>
```

```cpp
template <class T>
```

这里的 `class` 并不表示 `T` 必须是类类型。

例如：

```cpp
template <class T>
void Print(T value)
{
    cout << value << endl;
}
```

照样可以传入 `int`：

```cpp
Print(10);
```

所以：

> 在模板参数声明中，`typename T` 和 `class T` 都表示“`T` 是一个类型参数”。

现代 C++ 中，很多人更喜欢使用 `typename`，因为它表达得更直接。

---

### 4. 函数模板不是具体函数

这个概念非常重要。

下面这段代码：

```cpp
template <typename T>
void Swap(T& x, T& y)
{
    T tmp = x;
    x = y;
    y = tmp;
}
```

它本身不是一个只能直接执行的普通函数，而是一份**生成函数的规则**。

只有当程序真正使用它时，编译器才会根据具体类型生成相应函数。

例如：

```cpp
int a = 1;
int b = 2;
Swap(a, b);
```

编译器生成 `int` 版本。

```cpp
double x = 1.1;
double y = 2.2;
Swap(x, y);
```

编译器生成 `double` 版本。

如果程序中从来没有使用 `char` 类型调用 `Swap`，通常就不会生成 `char` 版本。

---

### 5. 模板实例化

编译器根据模板和具体类型生成具体函数的过程，称为：

> **模板实例化。**

函数模板实例化主要有两种方式：

1. 隐式实例化；
    
2. 显式实例化。
    

---

#### 5.1 隐式实例化

让编译器根据实参自动推导模板参数类型：

```cpp
int a = 10;
int b = 20;

Swap(a, b);
```

编译器根据 `a` 和 `b` 推导：

```cpp
T = int
```

然后生成 `int` 版本的 `Swap`。

这叫隐式实例化，因为我们没有明确写出 `T` 是什么。

完整例子：

```cpp
#include <iostream>
using namespace std;

template <typename T>
void Swap(T& x, T& y)
{
    T tmp = x;
    x = y;
    y = tmp;
}

int main()
{
    int a = 10;
    int b = 20;

    Swap(a, b);

    cout << a << " " << b << endl;
    return 0;
}
```

输出：

```text
20 10
```

---

#### 5.2 显式指定模板参数

也可以直接告诉编译器 `T` 是什么：

```cpp
Swap<int>(a, b);
```

这里尖括号中的 `int` 就是显式指定的模板实参。

例如：

```cpp
int a = 10;
int b = 20;

Swap<int>(a, b);
```

编译器不需要通过参数推导，因为我们已经明确指定：

```cpp
T = int
```

再例如：

```cpp
double x = 1.1;
double y = 2.2;

Swap<double>(x, y);
```

---

### 6. 模板参数和模板实参

这两个词需要区分。

定义模板时的 `T` 称为**模板参数**：

```cpp
template <typename T>
void Print(T value)
{
    cout << value << endl;
}
```

这里的 `T` 是模板参数。

使用模板时填入的具体类型称为**模板实参**：

```cpp
Print<int>(10);
```

这里的 `int` 是模板实参。

类似于普通函数：

```cpp
void func(int x);
func(10);
```

- 定义中的 `x` 是形参；
    
- 调用中的 `10` 是实参。
    

模板中：

- 定义中的 `T` 是模板参数；
    
- 使用时的 `int` 是模板实参。
    

---

### 7. 函数模板的参数推导

函数模板调用时，编译器会根据函数实参推导模板参数。

例如：

```cpp
template <typename T>
void Print(T value)
{
    cout << value << endl;
}
```

调用：

```cpp
Print(10);
```

因为 `10` 是 `int`，所以：

```cpp
T = int
```

调用：

```cpp
Print(3.14);
```

因为 `3.14` 默认是 `double`，所以：

```cpp
T = double
```

调用：

```cpp
Print('A');
```

所以：

```cpp
T = char
```

---

### 8. 同一个模板参数通常必须推导出一致类型

看下面的模板：

```cpp
template <typename T>
T Add(T x, T y)
{
    return x + y;
}
```

调用：

```cpp
Add(10, 20);
```

两个参数都是 `int`，所以：

```cpp
T = int
```

没有问题。

调用：

```cpp
Add(1.1, 2.2);
```

两个参数都是 `double`，所以：

```cpp
T = double
```

也没有问题。

但是：

```cpp
Add(10, 2.5);
```

第一个参数要求：

```cpp
T = int
```

第二个参数要求：

```cpp
T = double
```

同一个 `T` 被推导成了两种不同类型，编译器无法决定，所以通常会编译失败。

---

#### 解决方法一：显式指定类型

```cpp
Add<double>(10, 2.5);
```

当显式指定：

```cpp
T = double
```

以后，`10` 可以发生普通的隐式类型转换，转换为 `double`。

于是相当于调用：

```cpp
Add<double>(10.0, 2.5);
```

---

#### 解决方法二：使用两个模板类型参数

```cpp
template <typename T1, typename T2>
auto Add(T1 x, T2 y)
{
    return x + y;
}
```

调用：

```cpp
auto result = Add(10, 2.5);
```

此时：

```cpp
T1 = int
T2 = double
```

返回值由 `x + y` 的结果类型决定，通常是 `double`。

这是现代 C++ 中更灵活的写法。

---

### 9. 多个模板参数

函数模板可以有多个模板参数：

```cpp
template <typename T1, typename T2>
void Print(T1 x, T2 y)
{
    cout << x << " " << y << endl;
}
```

调用：

```cpp
Print(10, 3.14);
```

编译器推导：

```cpp
T1 = int
T2 = double
```

也可以显式指定：

```cpp
Print<int, double>(10, 3.14);
```

---

### 10. 函数模板可以处理自定义类型吗？

可以，但模板中的操作必须对该类型有效。

例如：

```cpp
template <typename T>
void Swap(T& x, T& y)
{
    T tmp = x;
    x = y;
    y = tmp;
}
```

对于自定义类型：

```cpp
class Date
{
public:
    int year;
    int month;
    int day;
};
```

可以调用：

```cpp
Date d1{2025, 1, 1};
Date d2{2026, 2, 2};

Swap(d1, d2);
```

因为 `Date` 类型默认支持：

```cpp
T tmp = x; // 拷贝构造
x = y;     // 拷贝赋值
y = tmp;   // 拷贝赋值
```

所以模板可以正常实例化。

但是模板并不是对所有类型都天然有效。

比如：

```cpp
template <typename T>
T Add(T x, T y)
{
    return x + y;
}
```

如果某个自定义类型没有定义 `operator+`：

```cpp
class Person
{
};
```

调用：

```cpp
Person p1;
Person p2;

Add(p1, p2);
```

就会编译失败，因为编译器生成的代码中包含：

```cpp
p1 + p2
```

但 `Person` 不支持加法。

所以更准确地说：

> 函数模板不是可以无条件地处理任何类型，而是可以处理所有满足模板中操作要求的类型。

---

### 11. 模板是在编译期工作的

函数模板属于编译期机制。

例如：

```cpp
Swap(a, b);
```

编译器在编译阶段就要确定：

1. `T` 是什么类型；
    
2. 应该生成哪个具体函数；
    
3. 模板中的操作是否合法。
    

因此模板不是运行时才动态判断类型。

它与运行时多态不同：

```text
函数模板：编译期多态
虚函数：运行时多态
```

函数模板通常也被称为**静态多态**的一种实现方式。

---

### 12. 函数模板和函数重载的关系

函数模板并不是要完全替代函数重载。

它们可以同时存在。

例如：

```cpp
template <typename T>
void Print(T value)
{
    cout << "模板版本：" << value << endl;
}

void Print(int value)
{
    cout << "普通 int 版本：" << value << endl;
}
```

调用：

```cpp
Print(10);
```

普通函数和模板函数都可以匹配。

一般情况下，如果普通函数和函数模板匹配程度相同，编译器会优先选择普通函数。

可能输出：

```text
普通 int 版本：10
```

调用：

```cpp
Print(3.14);
```

普通 `int` 版本需要把 `double` 转换成 `int`，而模板可以直接生成 `double` 版本，所以模板版本匹配得更好。

可能输出：

```text
模板版本：3.14
```

因此，函数模板也会参与函数重载决议。

---

### 13. `Swap` 模板还可以改进

最基础的写法：

```cpp
template <typename T>
void Swap(T& x, T& y)
{
    T tmp = x;
    x = y;
    y = tmp;
}
```

会执行：

1. 一次拷贝构造；
    
2. 两次拷贝赋值。
    

现代 C++ 可以利用移动语义：

```cpp
#include <utility>

template <typename T>
void Swap(T& x, T& y)
{
    T tmp = std::move(x);
    x = std::move(y);
    y = std::move(tmp);
}
```

这对于拥有大量资源的对象可能更高效。

实际上，标准库已经提供了：

```cpp
std::swap(x, y);
```

所以工程中一般不需要自己实现基础的 `Swap`。

不过用 `Swap` 学习函数模板非常合适。

---

### 14. 模板定义为什么通常放在头文件？

普通函数可以这样组织：

```cpp
// add.h
int Add(int x, int y);
```

```cpp
// add.cpp
int Add(int x, int y)
{
    return x + y;
}
```

但是模板通常写成：

```cpp
// add.h
template <typename T>
T Add(T x, T y)
{
    return x + y;
}
```

也就是声明和定义都放在头文件中。

原因是：

> 编译器实例化模板时，不仅要看到模板声明，还必须看到完整的模板定义。

假设在某个 `.cpp` 中调用：

```cpp
Add<int>(1, 2);
```

编译器需要根据完整模板函数体生成 `int` 版本。如果只能看到声明、看不到定义，它就无法生成代码。

所以模板通常采用“头文件包含定义”的方式。

更准确地说，并不是模板语法强制必须放头文件，而是普通的分离编译机制下，为了让每个使用模板的翻译单元看到完整定义，通常把模板定义放在头文件中。

---

### 15. 函数模板的显式实例化

除了调用时自动实例化，也可以明确要求编译器生成某个版本：

```cpp
template <typename T>
void Print(T value)
{
    cout << value << endl;
}

template void Print<int>(int);
```

这一句：

```cpp
template void Print<int>(int);
```

表示显式实例化 `Print<int>`。

也就是明确让编译器生成：

```cpp
void Print<int>(int);
```

这部分在普通入门阶段了解即可，之后学习模板的声明与定义分离时会更加重要。

---

### 16. 非类型模板参数

模板参数不一定都是类型，也可以是编译期常量。

例如：

```cpp
template <typename T, size_t N>
void PrintArray(const T (&arr)[N])
{
    for (size_t i = 0; i < N; ++i)
    {
        cout << arr[i] << " ";
    }
    cout << endl;
}
```

调用：

```cpp
int arr[5] = {1, 2, 3, 4, 5};

PrintArray(arr);
```

编译器推导：

```cpp
T = int
N = 5
```

这里：

- `T` 是类型模板参数；
    
- `N` 是非类型模板参数。
    

在这个函数里，数组大小不会退化丢失，因为参数类型是数组引用：

```cpp
const T (&arr)[N]
```

这属于函数模板的进阶应用。

---

### 17. 函数模板的常见错误

#### 错误一：同一个 `T` 推导出不同类型

```cpp
template <typename T>
T Add(T x, T y)
{
    return x + y;
}

Add(10, 2.5); // 可能推导失败
```

原因：

```cpp
第一个参数推导 T = int
第二个参数推导 T = double
```

解决：

```cpp
Add<double>(10, 2.5);
```

或者：

```cpp
template <typename T1, typename T2>
auto Add(T1 x, T2 y)
{
    return x + y;
}
```

---

#### 错误二：模板中的操作不支持

```cpp
template <typename T>
T Max(T x, T y)
{
    return x > y ? x : y;
}
```

这个模板要求类型 `T` 支持：

```cpp
operator>
```

如果传入的类型不支持比较，就会编译失败。

---

#### 错误三：认为模板能生成所有类型代码

编译器一般只为真正使用到的类型实例化模板。

```cpp
Swap(1, 2); // 注意：这里还会因为不能绑定到非常量引用而失败
```

正确例子：

```cpp
int a = 1;
int b = 2;
Swap(a, b);
```

才会实例化 `Swap<int>`。

---

#### 错误四：模板定义只放在 `.cpp`

如果其他文件要使用模板，但只能看到声明、看不到定义，可能产生链接错误。

因此模板定义通常放在 `.h` 或 `.hpp` 文件中。

---

### 18. `Swap(1, 2)` 为什么不能调用？

模板定义：

```cpp
template <typename T>
void Swap(T& x, T& y)
```

调用：

```cpp
Swap(1, 2);
```

会失败。

因为 `1` 和 `2` 是临时值，也就是右值，而普通的非常量左值引用：

```cpp
T&
```

不能绑定到右值。

而且即使允许交换两个临时值，也没有实际意义，因为临时值很快就会销毁。

正确调用：

```cpp
int a = 1;
int b = 2;

Swap(a, b);
```

### 19. 函数模板的完整示例

```cpp
#include <iostream>
#include <string>
#include <utility>
using namespace std;

template <typename T>
void Swap(T& x, T& y)
{
    T tmp = std::move(x);
    x = std::move(y);
    y = std::move(tmp);
}

int main()
{
    int a = 10;
    int b = 20;

    Swap(a, b);
    cout << a << " " << b << endl;

    double x = 1.1;
    double y = 2.2;

    Swap(x, y);
    cout << x << " " << y << endl;

    string s1 = "hello";
    string s2 = "world";

    Swap(s1, s2);
    cout << s1 << " " << s2 << endl;

    return 0;
}
```

可能输出：

```text
20 10
2.2 1.1
world hello
```

同一份模板代码分别生成了：

```cpp
Swap<int>
Swap<double>
Swap<std::string>
```

三个具体函数版本。

### 20. 函数模板的底层理解

当你写：

```cpp
template <typename T>
void Swap(T& x, T& y)
{
    T tmp = x;
    x = y;
    y = tmp;
}
```

编译器不会把 `T` 当成运行时变量。

当调用：

```cpp
int a = 1;
int b = 2;
Swap(a, b);
```

编译器大致生成：

```cpp
void Swap<int>(int& x, int& y)
{
    int tmp = x;
    x = y;
    y = tmp;
}
```

当调用：

```cpp
double x = 1.1;
double y = 2.2;
Swap(x, y);
```

编译器又生成：

```cpp
void Swap<double>(double& x, double& y)
{
    double tmp = x;
    x = y;
    y = tmp;
}
```

因此，模板带来的代码复用主要发生在**源码层面**。

对于不同类型，编译器仍然可能生成多份机器代码。这种现象有时被称为模板代码膨胀。

### 21. 面试回答版本

面试官问：

> 什么是函数模板？

可以这样回答：

函数模板是一种与具体类型无关的函数定义方式。我们可以在模板参数列表中使用类型参数作为占位符，只编写一份通用逻辑。当使用不同类型调用函数模板时，编译器会通过模板参数推导或者显式指定模板参数，生成对应类型的具体函数，这个过程叫模板实例化。

例如：

```cpp
template <typename T>
void Swap(T& x, T& y)
{
    T tmp = x;
    x = y;
    y = tmp;
}
```

调用 `Swap` 处理 `int` 时，编译器会实例化出 `int` 版本；处理 `double` 时，会实例化出 `double` 版本。

函数模板属于编译期机制，可以提高源码复用率，但模板中的操作必须对实际类型有效。由于模板实例化时编译器需要看到完整定义，所以模板定义通常放在头文件中。

### 22. 这一节最需要记住的内容

```cpp
template <typename T>
void Func(T value)
{
}
```

核心概念：

```text
1. T 是类型占位符。
2. 函数模板不是一个具体函数，而是生成函数的规则。
3. 编译器根据实际类型生成具体函数。
4. 生成具体函数的过程叫模板实例化。
5. 可以自动推导类型，也可以显式指定类型。
6. 同一个模板参数通常必须推导出一致类型。
7. 模板中的操作必须被实际类型支持。
8. 函数模板属于编译期机制。
9. 模板定义通常放在头文件中。
```

最核心的一句话：

> **函数模板是编译器生成具体函数的模具，而不是一个运行时接收任意类型的万能函数。**
