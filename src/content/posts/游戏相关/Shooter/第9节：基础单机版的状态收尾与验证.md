这一节记录2026-10-20基础单机射击版的完善。前面从单发、连射、换弹、动画到胜负的过程全部保留；本阶段重点是让这些功能在同一局游戏里正确配合，尤其是取消、迟到回调、初始化顺序和异常配置。

当前工程是UE 5.4。完整函数从这次源码提取，省略注释、调整排版；伪代码用于解释执行链。第7节末尾详细补充新版攻击判定，第8节末尾补充已经接通的回弹与摆动。本节连接一局游戏的状态、刷怪、HUD和验证结果。

## 1. 先从旧问题推导这次的设计

原来“能开枪、能受伤、能赢”已经存在，但每条流程都可能留有后续工作。例如开始换弹后有Timer，开始攻击后有动画事件，子弹生成后仍独立飞行。只显示GameOver文字，不能让它们自己停止。

这次把设计拆成三层：

| 层次 | 本次做法 | 解决的问题 |
| --- | --- | --- |
| 入口是否允许 | IsGameplayActive、CanUseWeapon、bCombatStopped | 已结束时拒绝新动作与伤害 |
| 已开始的工作怎样收尾 | StopRoundGameplay、StopCombat、CancelReload、FinishAttack | 清旧输入、攻击态、Timer和在途子弹 |
| 对象离开场景怎样清理 | 各类EndPlay | 重开/退出时清理持有对象与界面 |

因此，本阶段的核心学习点是：**一个状态改变后，入口判断、正在运行的流程和资源生命周期要一起处理。**

## 2. 用统一查询表达“玩家还在进行这一局”

玩家头文件增加：

```cpp
bool IsGameplayActive() const
{
    return !bIsDead && !bHasWon && !IsActorBeingDestroyed();
}
```

这是无副作用的查询，不是一个会自动清理其他对象的事件。它把“没死、没赢、没在销毁”组合成一个条件，供移动、视角、冲刺、跳跃、伤害与其他对象检查。

| 调用处 | 现在如何使用 |
| --- | --- |
| Move、Look、Dash | 结束后不继续提交对应动作 |
| Jump重写 | 只有活动中才调用Super::Jump |
| ReceiveEnemyDamage | 同时检查活动状态、伤害有限且为正 |
| Weapon.CanUseWeapon | 自己未停战、Owner有效、Owner活动中 |
| AI与Spawner | 玩家结束后停止自己的战斗/刷怪流程 |

StartFireInput与ReloadInput仍保留 `bIsDead || bHasWon` 的入口检查；武器内部又用CanUseWeapon复查。不要把它们记成源码里所有函数都已替换为同一行判断。

输入的 `Canceled` 绑定本次也接到清理入口：Move取消清MovementVector，Fire取消StopFire，Jump取消StopJumping。取消和正常Completed都可能结束一次操作，因此保存“按住”的状态不能只依赖正常松键。第1节末尾补了输入部分。

## 3. 胜利和死亡共用StopRoundGameplay

### 3.1 先记录结果，再停止整局行为

最新胜利函数，位置：`Source/MyArenaShooter/Private/MyArenaShooterCharacter.cpp:368`。

```cpp
void AMyArenaShooterCharacter::WinGame()
{
    if (bIsDead || bHasWon)
    {
        return;
    }

    bHasWon = true;
    StopRoundGameplay();

    if (HUDWidget)
    {
        HUDWidget->ShowVictory();
    }
}
```

最新死亡函数，位置：`Source/MyArenaShooter/Private/MyArenaShooterCharacter.cpp:391`。

```cpp
void AMyArenaShooterCharacter::Die()
{
    if (!IsGameplayActive())
    {
        return;
    }
    bIsDead = true;
    StopRoundGameplay();

    if (HUDWidget)
    {
        HUDWidget->ShowGameOver();
    }

    UE_LOG(LogTemp, Warning, TEXT("Player Dead"));
}
```

先设置bHasWon或bIsDead，使后续查询立即发现终局，再进入统一收尾，最后显示对应文字。死亡入口自身新增了活动状态判断，胜利入口仍拒绝已经死亡或已经胜利的情况。

### 3.2 统一收尾完整实现

位置：`Source/MyArenaShooter/Private/MyArenaShooterCharacter.cpp:441`。

```cpp
void AMyArenaShooterCharacter::StopRoundGameplay()
{
    MovementVector = FVector2D::ZeroVector;
    bCanDash = false;
    StopJumping();
    GetCharacterMovement()->StopMovementImmediately();
    GetCharacterMovement()->DisableMovement();
    if (IsValid(CurrentWeapon))
    {
        CurrentWeapon->StopCombat();
    }

    for (TActorIterator<AMyEnemySpawner> It(GetWorld()); It; ++It)
    {
        It->StopSpawning();
    }
    for (TActorIterator<AMyEnemyCharacter> It(GetWorld()); It; ++It)
    {
        It->StopCombat();
    }
    for (TActorIterator<AMyProjectile> It(GetWorld()); It; ++It)
    {
        It->Destroy();
    }
}
```

按“清当前玩家 → 清玩家武器 → 清世界里的相关对象”的方向读：

1. 清MovementVector、禁用冲刺资格、StopJumping。
2. StopMovementImmediately清当前速度，再DisableMovement禁用移动模式。
3. 当前武器StopCombat，取消持续开火和换弹，复位姿态。
4. 遍历刷怪器StopSpawning。
5. 遍历敌人StopCombat。
6. 遍历已有Projectile并请求Destroy。

这比第6节旧阶段只调用StopFire和DisableMovement更完整。第6节原文继续代表当时的学习过程，现在还会处理在途子弹、AI与换弹回调。

### 3.3 第一次使用TActorIterator

```cpp
for (TActorIterator<AMyEnemySpawner> It(GetWorld()); It; ++It)
{
    It->StopSpawning();
}
```

它在指定World里遍历匹配类型的Actor，包含相应派生实例；`It`作为条件表示还有有效项，`++It`找下一项，`It->`访问当前项。类型参数限定要找哪类对象，GetWorld限定查找范围。头文件是 `EngineUtils.h`，参考 [TActorIterator构造参数](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/TActorIterator/__ctor)。

当前是单机回合规则，所以它会影响这个World内匹配类型的刷怪器、敌人和子弹，而不仅是当前玩家发射的某颗子弹。把这条全局规则暂放在玩家Character是现阶段的实现选择；当前没有因此完成服务器GameMode权威、多玩家结算或RPC同步。

收尾也没有调用SetGamePaused：世界仍运行，界面与必要的死亡清理Timer仍可继续。停止战斗不要求把世界所有Tick和所有Timer一概清除。

## 4. 武器为什么同时取消Timer和复查回调

武器内部的CanUseWeapon把自身停战状态与Owner状态合起来。完整函数已追加在第2节，这里先看两条互补链：

```text
主动取消：StopCombat → CancelReload → ClearTimer
    → bIsReloading=false，ReloadElapsed=0

回调复查：FinishReload
    → 没在换弹，或武器已经不能用？
    → CancelReload并return
    → 通过检查才转移弹药并更新HUD
```

前一条清理已经注册的工作；后一条避免过期/额外调用在错误状态下补弹。不是只有按键入口检查一次就足够。

CancelReload不会补弹，也不会扣备用弹药；转移弹药仍只在合法FinishReload中执行。正常换弹继续使用 `Min(缺少数量, 备用弹药)`，保持弹匣容量与弹药守恒。

`ClearTimer(Handle)` 通过句柄清除对应计时任务，不等于停止同一对象的所有音效、特效或所有Timer。调用 `SetActorTickEnabled(false)` 也不会自行替代ClearTimer，TimerManager与Actor自己的Tick是不同调度来源。参见 [Gameplay Timers](https://dev.epicgames.com/documentation/en-us/unreal-engine/gameplay-timers-in-unreal-engine?application_version=5.4)。

## 5. 敌人攻击现在有明确的开始、命中窗口和结束

第7节末尾提供最新TryAttack、ApplyAttackDamage和FinishAttack的完整代码。先记这组数据：

| 状态 | 回答的问题 |
| --- | --- |
| bIsAttacking | 现在是否已处于一次攻击中？ |
| AttackTarget | 本次起手选择的是哪个玩家对象？ |
| bAttackDamageApplied | 本次命中窗口是否已经消费？ |
| NextAttackTime | 按World游戏时间，最早什么时候允许下一次起手？ |
| bCombatStopped / bIsDead | 是否永久停止本次对象的战斗，或已经死亡？ |

```text
AI进范围并朝向玩家 → TryAttack(Target)
    → 拒绝死亡/停战/重叠起手/冷却未到
    → 验证目标活动与动画实例
    → 缓存弱目标，窗口设未消费，攻击态设true
    → 播放蒙太奇；失败则FinishAttack还原
    → 成功后设置NextAttackTime
    → 注册动画结束委托 + 兜底Timer

Notify → ApplyAttackDamage
    → 必须仍处于这次攻击、目标有效、窗口没消费、动作仍在播放
    → 先消费窗口
    → 再检查距离、朝向、Visibility遮挡
    → 全通过才请求玩家受伤

动画结束/中断，或兜底Timer
    → FinishAttack清Timer、攻击态与目标
```

旧StartAttack现在直接转发TryAttack，AI旧冷却成员已移除，使用Enemy的AttackCooldown（默认1.5秒）。这次结束委托用于**攻击蒙太奇**；死亡蒙太奇仍使用播放长度Timer，不能把两条动画结束实现混写。

## 6. 伤害与重复事件的统一含义

### 6.1 致死伤害重新返回true

Enemy.TakeProjectileDamage现在会在执行Die后返回true。这表示“本次伤害已被接受”，而不是“敌人还活着”或“是否击杀”。击杀那一发重新进入子弹的NotifyEnemyHit通知分支。

玩家和敌人都拒绝非有限或非正伤害。BeginPlay也给生命、攻击参数做有限值与范围兜底，避免蓝图异常配置进入后续计算。

### 6.2 子弹一生只处理首次碰撞结算

OnProjectileHit开头新增：

```cpp
if (bHitProcessed || IsActorBeingDestroyed())
{
    return;
}
bHitProcessed = true;
```

先记已处理，再进入扣血与反馈。Destroy不是所有调用栈立刻消失的同义词，重复碰撞回调也不能被当成必然不会发生。因此使用明确状态挡住重复处理，而不依赖“末尾马上会Destroy”的假设。

这里与敌人的一次命中窗口是不同粒度：前者限制一颗Projectile的处理次数，后者限制一轮近战攻击的接触结算次数。

## 7. 波次推进必须分清“空波”“错误”和“成功结束”

### 7.1 最新SpawnWave完整实现

位置：`Source/MyArenaShooter/Private/MyEnemySpawner.cpp:52`。

```cpp
void AMyEnemySpawner::SpawnWave()
{
    if (bSpawningStopped)
    {
        return;
    }
    if (Waves.IsEmpty())
    {
        FailSpawning(TEXT("Waves is empty"));
        return;
    }

    while (Waves.IsValidIndex(CurrentWaveIndex) && Waves[CurrentWaveIndex].EnemyCount == 0)
    {
        ++CurrentWaveIndex;
    }
    if (CurrentWaveIndex >= Waves.Num())
    {
        UpdateWaveHUD();
        return;
    }
    if (Waves[CurrentWaveIndex].EnemyCount < 0)
    {
        FailSpawning(TEXT("EnemyCount cannot be negative"));
        return;
    }
    if (!EnemyClass || EnemyClass->HasAnyClassFlags(CLASS_Abstract))
    {
        FailSpawning(TEXT("EnemyClass is missing or abstract"));
        return;
    }
    TArray<AActor*> ValidPoints;
    for (AActor* Point : SpawnPoints)
    {
        if (IsValid(Point))
        {
            ValidPoints.Add(Point);
        }
    }
    if (ValidPoints.IsEmpty())
    {
        FailSpawning(TEXT("No valid spawn point"));
        return;
    }
    CurrentWaveEnemies.Empty();
    const int32 RequestedCount = Waves[CurrentWaveIndex].EnemyCount;
    for (int32 Index = 0; Index < RequestedCount; ++Index)
    {
        AActor* Point = ValidPoints[Index % ValidPoints.Num()];
        FActorSpawnParameters Params;
        Params.SpawnCollisionHandlingOverride = ESpawnActorCollisionHandlingMethod::AdjustIfPossibleButAlwaysSpawn;
        AMyEnemyCharacter* Enemy = GetWorld()->SpawnActor<AMyEnemyCharacter>(EnemyClass,
            Point->GetActorLocation() + FVector(0.0f, 0.0f, 100.0f), Point->GetActorRotation(), Params);
        if (IsValid(Enemy) && !Enemy->IsActorBeingDestroyed() && !Enemy->IsDead())
        {
            CurrentWaveEnemies.Add(Enemy);
        }
    }
    bWaveActive = !CurrentWaveEnemies.IsEmpty();
    if (!bWaveActive)
    {
        FailSpawning(TEXT("All enemy spawns failed"));
        return;
    }
    if (CurrentWaveEnemies.Num() != RequestedCount)
    {
        UE_LOG(LogTemp, Warning, TEXT("%s wave %d: spawned %d/%d enemies"), *GetName(), CurrentWaveIndex + 1, CurrentWaveEnemies.Num(), RequestedCount);
    }
    UpdateWaveHUD();
    UE_LOG(LogTemp, Log, TEXT("%s wave %d started, enemies: %d"), *GetName(), CurrentWaveIndex + 1, CurrentWaveEnemies.Num());
}
```

从前往后看，它把配置分成三类：

| 情况 | 当前处理 |
| --- | --- |
| 非空Waves中的EnemyCount=0 | 用while迭代跳过，再处理下一行 |
| Waves为空、负数量、敌人类缺失/抽象、无有效出生点 | FailSpawning进入显式错误停止 |
| 请求生成后一个都未登记成功 | FailSpawning，全生成失败 |
| 一部分成功 | 记录Warning，按实际成功登记数量继续这一波 |
| 合法波次都已推进完 | 返回Tick的最终胜利检查 |

注意“配置了0个敌人的一波”是允许跳过；“根本没有任何波次配置”是错误。非空数组如果每一波都为0，while会走到数组末尾，后续Tick可以结算完成；空数组不会因此误判胜利。

### 7.2 为什么先筛有效出生点再取模

旧阶段直接对原始SpawnPoints取模，碰到无效项就continue，可能减少实际生成次数。现在先形成ValidPoints，再用 `Index % ValidPoints.Num()` 轮流选有效点。

例如请求3个敌人，原出生点是 `[nullptr, PointA]`。新实现得到 `[PointA]`，三个请求都能使用这个有效点。实际生成仍可能失败，代码只登记有效、没在销毁且没逻辑死亡的Enemy；不会把“想生成几个”直接当成“现在还活着几个”。

### 7.3 显式错误态不等于玩家失败或胜利

位置：`Source/MyArenaShooter/Private/MyEnemySpawner.cpp:175`。

```cpp
void AMyEnemySpawner::FailSpawning(const TCHAR* Reason)
{
    bSpawnError = true;
    UE_LOG(LogTemp, Error, TEXT("%s: wave configuration/spawn error: %s"), *GetName(), Reason);
    StopSpawning();
    UpdateWaveHUD();
}
```

`bSpawnError=true` 用于查询错误，日志Error给出原因，然后StopSpawning、更新HUD。它没有直接调用玩家Die或WinGame，也没有新增配置错误弹窗，因此不能把错误停止记成玩家输掉一局。

## 8. Tick怎样等玩家就绪并避免漏掉最终胜利

位置：`Source/MyArenaShooter/Private/MyEnemySpawner.cpp:17`。

```cpp
void AMyEnemySpawner::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);
    if (bSpawningStopped)
    {
        return;
    }
    if (!IsValid(PlayerCharacter))
    {
        PlayerCharacter = Cast<AMyArenaShooterCharacter>(UGameplayStatics::GetPlayerCharacter(GetWorld(), 0));
    }
    if (IsValid(PlayerCharacter) && !PlayerCharacter->IsGameplayActive())
    {
        StopSpawning();
        return;
    }
    UpdateWaveHUD();
    if (bWaveActive)
    {
        CleanupDeadEnemies();
        if (CurrentWaveEnemies.IsEmpty())
        {
            bWaveActive = false;
            ++CurrentWaveIndex;
            SpawnWave();
        }
    }

    if (!bSpawningStopped && !bWaveActive && CurrentWaveIndex >= Waves.Num() && !Waves.IsEmpty() && IsValid(PlayerCharacter))
    {
        PlayerCharacter->WinGame();
        StopSpawning();
    }
}
```

与旧阶段相比有两个重要变化：

1. 玩家缓存无效时会重新获取；最终胜利检查位于后续Tick中，不是一次失败后就永远失去通知机会。
2. `!bWaveActive` 不再直接使整个函数返回。活动波次做清理/推进，已经结束的波次仍可走最终检查。

```text
Tick开始
    → 已停止刷怪？是则返回
    → 尝试补取Player
    → Player已终局？StopSpawning并返回
    → 尝试更新HUD
    → 若本波活动：清理死亡 → 数组空则推进索引并SpawnWave
    → 最后：未停止、没有活动波、非空配置已走完、玩家有效？
    → WinGame，再StopSpawning
```

最终胜利只依赖有效玩家，不要求HUD一定存在；HUD不就绪不会阻止玩家记录胜利。代码也没有在之后HUD出现时自动重放VictoryText通知。等待HUD的补发主要用于下一节的波次数字显示，不应扩展成所有终局显示都有重试。

## 9. HUD等待就绪，并且仅在数据改变时发送

位置：`Source/MyArenaShooter/Private/MyEnemySpawner.cpp:141`。

```cpp
void AMyEnemySpawner::UpdateWaveHUD()
{
    if (!IsValid(PlayerCharacter))
    {
        PlayerCharacter = Cast<AMyArenaShooterCharacter>(UGameplayStatics::GetPlayerCharacter(GetWorld(), 0));
    }
    if (!IsValid(PlayerCharacter) || !PlayerCharacter->IsHUDReady())
    {
        return;
    }
    const int32 WaveNumber = FMath::Min(CurrentWaveIndex + 1, Waves.Num());
    if (HUDPlayer.Get() != PlayerCharacter || DisplayedWave != WaveNumber || DisplayedEnemies != CurrentWaveEnemies.Num())
    {
        PlayerCharacter->UpadteWaveHUD(WaveNumber, Waves.Num(), CurrentWaveEnemies.Num());
        HUDPlayer = PlayerCharacter;
        DisplayedWave = WaveNumber;
        DisplayedEnemies = CurrentWaveEnemies.Num();
    }
}
```

先取得玩家，再要求 `IsHUDReady()`。这里该查询实际是 `HUDWidget != nullptr`，只描述引用是否已建立；它不保证蓝图所有BindWidget都正确，也不代表人工视觉检查已经完成。

满足条件后才比较三项：玩家接收者是否换了、本次显示波数是否改变、剩余数量是否改变。发生变化才调用 `UpadteWaveHUD()` 并更新缓存。

```text
HUD未就绪：返回，不更新Displayed缓存
下一帧HUD就绪：仍与旧缓存不同 → 首次发送
同一个玩家且数字相同：跳过重复发送
玩家换成新对象：即使数字相同，也为新接收者发送
```

HUDPlayer是弱引用，用于识别这次缓存对应的接收者。`WaveNumber = Min(Index+1, Waves.Num())` 避免结束后显示成第4/3波。CleanupDeadEnemies也改成循环完成后只发一次更新请求，UpdateWaveHUD再进行数据去重。

## 10. 重开与EndPlay：对象结束时清理

玩家最新EndPlay，位置：`Source/MyArenaShooter/Private/MyArenaShooterCharacter.cpp:467`。

```cpp
void AMyArenaShooterCharacter::EndPlay(const EEndPlayReason::Type EndPlayReason)
{
    if (IsValid(CurrentWeapon))
    {
        CurrentWeapon->StopCombat();
        CurrentWeapon->Destroy();
    }
    if (IsValid(HUDWidget))
    {
        HUDWidget->RemoveFromParent();
    }
    Super::EndPlay(EndPlayReason);
}
```

玩家退出世界时停止并销毁自己持有的武器，RemoveFromParent移除HUD，再调用父类EndPlay。武器EndPlay调用StopCombat清换弹；Enemy.EndPlay停止攻击、清DeathTimer，然后调用父类。

```text
终局后RestartAction → RestartGame → OpenLevel当前地图
    → 旧Actor进入EndPlay清理
    → 新地图的Actor与玩家重新初始化
    → 新血量、弹药、波次、HUD
```

EndPlay不只是玩家死亡事件，也会发生在Actor销毁、关卡切换、停止Play等生命周期结束情形。敌人逻辑死亡不必立即EndPlay：仍可以保留尸体播放动画。参见 [Actor Lifecycle](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-actor-lifecycle)。

## 11. 已有自动化报告怎样作为学习证据

## 12. 用一局游戏串起当前完整执行链

```text
开局：玩家BeginPlay → 血量校验 → HUD → Enhanced Input → 武器
      Spawner.BeginPlay → 校验波次/类/出生点 → 只登记成功生成者
      HUD晚就绪时由后续Tick补发数字

射击：Started → StartFire → CanUseWeapon → Fire
      相机选点 → 枪口方向 → 生成检查 → 后坐力/反馈/扣弹
      Tick按住连射，FInterpTo恢复后坐力与摆动
      Completed或Canceled → StopFire

实体命中：Projectile首次结算标记
      Enemy接受伤害 → 致死也返回true → 命中标记
      接触特效/声音 → 销毁子弹
      Enemy逻辑死亡 → StopCombat → 死亡动画或失败兜底销毁

敌人攻击：AI朝向并TryAttack(Target)
      缓存目标/窗口/冷却 → 动画事件
      消费一次窗口 → 距离/朝向/遮挡 → 玩家受伤
      结束/中断委托或Timer → FinishAttack

波次：清理无效或IsDead引用 → 统一更新HUD
      本波清空 → 推进并跳过0数量波
      还有合法波 → 继续生成
      全部完成且玩家有效 → WinGame
      配置错误 → FailSpawning，停止但不宣告胜利

终局：WinGame或Die先写结果
      StopRoundGameplay → 玩家动作/武器/刷怪/敌人/在途子弹收尾
      显示Victory或GameOver
      迟到Timer/Notify再次检查状态，不再伤害或补弹

重开：RestartGame → OpenLevel → 旧对象EndPlay → 新一局初始化
```

配套可编辑图纸位于博客仓库 `draw/MyArena/MyArena-基础单机闭环-20261020.drawio`，包含攻击窗口、终局收尾、刷怪与HUD三页，附当前源码行号。旧图纸按核对日期保留为历史阶段。
