## 1. 功能

等待本地角色/输入/HUD/武器就绪后开始回合，结束时停战，由主机请求服务器重开。

## 3. 入口

Waiting阶段本地 `PlayerController::PlayerTick` 检查准备；重开从 `RestartAction → Character::RestartGame` 开始。

## 4. 调用链

```text
本地PlayerTick → TryPrePareLocalRound检查本地输入/HUD和角色武器关系
→ ServerReportReady(Pawn) → 服务器核对Pawn/Controller与对象准备
→ GameMode统计确认人数 → 满足要求才StartSpawning
→ 服务器判定Victory / Defeat / ConfigurationError → GameState复制
→ StopRoundActors停止Spawner、Enemy、刷新玩家状态并销毁服务器World中的Projectile
→ 本地RestartGame → Controller.RequestRestartRound（0.5秒节流）
→ ServerRequestRestartRound → GameMode检查请求者/主机/阶段/重复请求
→ ServerTravel(?Restart)；失败则解除pending
```

## 5. 核心机制

就绪确认绑定具体Pawn，服务器复查拥有与对象状态；本地Ready检查还包括HUD、EnhancedInputComponent和MappingContext。服务器终局逻辑在GameMode，Character::RefreshRoundState处理本地停止与HUD。重开只允许Victory/Defeat且服务器判断请求Controller是本地控制器，当前是Listen Server主机重开设计；ConfigurationError虽属终局但不允许该重开分支。

## 6. 关键设计问题

**为什么等待Ready而不是BeginPlay立刻开打？**

网络复制、Pawn持有、武器、输入与HUD可能先后到达；明确检查并报告，避免其中一端尚未准备好就开始。

**为什么重开用ServerTravel？**

由服务器发起整局地图切换，配合当前非无缝旅行设置；服务器也负责只接受主机和合法终局的请求。

**为什么不要把单人旧笔记当成当前终局链？**

旧阶段由Character遍历世界并OpenLevel；当前主要通过GameMode、复制的GameState和PlayerController请求管理回合。
