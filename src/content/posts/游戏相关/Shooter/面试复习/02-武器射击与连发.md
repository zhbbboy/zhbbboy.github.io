## 1. 功能

按住自动射击、限制射速、生成服务器真实子弹并消耗弹药。

## 2. 相关类和源码位置

`AMyArenaShooterCharacter`、`AMyWeapon`、`AMyProjectile`。武器由服务器生成，Owner 和 Instigator 指向玩家，并复制 CurrentWeapon。

- `Source/MyArenaShooter/Private/MyArenaShooterCharacter.cpp:396`（`::ServerSetFirePressed_Implementation(`）

## 3. 入口

`IA_Fire Started → Character::StartFireInput`；Completed / Canceled → `StopFireInput`。

## 4. 调用链

```text
本地 StartFireInput：递增 LocalFireSequenceId → 尝试首发本地预测
→ ServerSetFirePressed(true, SequenceId, PredictionId) [Server Reliable]
→ 服务器 StartFire：检查权威/状态/批次/换弹/弹药/冷却
→ 可立即开火时 Fire → CalculateAimPoint → 枪口 SpawnActor真实子弹
→ 成功才扣弹、更新HUD、ClientConfirmShot、MulticastPlayFireEffects
→ Weapon Tick 按 bFirePressed 与 FireCooldown 继续 Fire
→ 松开/取消发送 ServerSetFirePressed(false) → StopFire
```

## 5. 核心机制

`CanUseWeapon()` 要求服务器权威、武器未停战、Owner有效且玩家活动。`FireInterval` 默认0.15秒；Tick扣减冷却，阻止按住时每帧都生成子弹。`StartFire` 先设置按住状态；若正在换弹或冷却中，立即开火可失败，但按住状态仍可能让后续Tick继续。拒绝立即首发时 Character 会取消对应的本地预测。

## 6. 关键设计问题

**为什么要有FireCooldown？**

帧率不同会导致每秒Tick次数不同；按时间间隔限制请求，才能让射速与帧率解耦。实际仍受服务器帧调度影响。

**为什么角色和武器分开？**

Character负责输入与角色状态，Weapon负责射速、弹药和生成；职责更清楚，也便于未来替换武器。当前项目并不因此自动拥有数据驱动或多武器系统。

**为什么松开也要通知服务器？**

服务器保存bFirePressed并负责连续发射；本地停止输入不足以清除服务器上的按住状态。
