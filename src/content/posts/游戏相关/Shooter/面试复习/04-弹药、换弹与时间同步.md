## 1. 功能

服务器管理弹匣和备用弹药，通过复制同步数据，以服务器时间计算各端换弹表现。

## 3. 入口

`IA_Reload → ReloadInput → ServerRequestReload → Weapon::StartReload`；弹匣耗尽也会请求StartReload。

## 4. 调用链

```text
服务器 StartReload：检查可用性、状态、弹匣与备用
→ 递增 ReloadId，记录 bIsReloading / StartServerTime / Duration
→ OnRep_ReloadState 更新本端表现；Timer安排 FinishReload
→ FinishReload 按 Min(弹匣缺额, 备用弹药) 转移弹药
→ 弹药 / ReloadState 复制到客户端 → OnRep 更新显示
→ 终局 StopCombat → CancelReload 清Timer并复位状态
```

## 5. 核心机制

`CurrentAmmo`、`ReserveAmmo` 与 `ReloadState` 通过DOREPLIFETIME注册。表现进度由服务器时间减去StartServerTime计算；本地玩家按ReloadId避免重复播放换弹音，并以已过去时间作为播放起点。Tick通过Sin半周期合成下沉和倾斜。

## 6. 关键设计问题

**为什么不能只在客户端扣弹和换弹？**

弹药属于影响玩法的权威状态；服务器统一计算可以避免各端各算一份而产生分歧，客户端显示复制结果。

**为什么既清Timer又在FinishReload复查？**

清Timer处理已注册任务；回调中的状态检查为额外或迟到调用提供第二道保护。

**为什么复制开始时间与持续时间？**

接收端可以按同步服务器时间计算当前进度，不必假设各端在同一帧收到换弹开始。
