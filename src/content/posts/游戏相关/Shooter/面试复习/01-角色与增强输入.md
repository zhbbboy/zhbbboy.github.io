## 1. 功能

接收本地输入，驱动角色移动、视角、跳跃和冲刺；回合未开始或结束时限制玩法动作。

## 2. 相关类和源码位置

`AMyArenaShooterCharacter`、`AMyArenaShooterPlayerController`、`UEnhancedInputLocalPlayerSubsystem`、`UCharacterMovementComponent`。

- `Source/MyArenaShooter/Private/MyArenaShooterCharacter.cpp:107`（`::SetupPlayerInputComponent(`）
- `Source/MyArenaShooter/Private/MyArenaShooterCharacter.cpp:420`（`::ServerRequestDash_Implementation(`）

## 3. 入口

`PawnClientRestart / BeginPlay → TryInitializeLocalInput → AddMappingContext`；输入由 `SetupPlayerInputComponent` 绑定。

## 4. 调用链

```text
IMC_Player 映射 IA_Move / IA_Look / IA_Jump / IA_Dash
→ 本地 Character 接收 Triggered / Started / Completed / Canceled
→ Move / Look 提交输入，Jump 调用父类移动能力
→ Dash 发送 ServerRequestDash(方向)
→ 服务器验证状态、冷却资格和方向，归一化后 LaunchCharacter
→ 服务器 Landed 时恢复 bCanDash
```

## 5. 核心机制

`IsLocallyControlled()` 判断是不是本机控制；`HasAuthority()` 判断是否有权威，两者不是同一概念，Listen Server 的主机角色可以同时为真。移动和跳跃依赖 CharacterMovement 的机制；Dash 显式走 Server RPC。`IsGameplayActive()` 还要求回合处于 Playing。

## 6. 关键设计问题

**为什么 Mapping Context 要在本地玩家上添加？**

映射属于本地输入环境；远端角色不应为本机重复注册自己的按键。初始化函数还检查已有映射，支持生命周期顺序变化。

**为什么冲刺要由服务器验证？**

客户端提供意图方向，服务器复查游戏状态、冲刺资格和方向，并决定 LaunchCharacter；不能把客户端请求当成已执行的事实。
