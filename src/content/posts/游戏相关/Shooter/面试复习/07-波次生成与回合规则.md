## 1. 功能

服务器等待玩家准备、管理波次并统一判定胜利、失败与配置错误。

## 2. 相关类和源码位置

`AMyArenaShooterGameMode`、`AMyEnemySpawner`、`AMyArenaShooterGameState`。

- `Source/MyArenaShooter/Private/MyArenaShooterGameMode.cpp:37`（`::Tick(`）
- `Source/MyArenaShooter/Private/MyEnemySpawner.cpp:160`（`::StartSpawning(`）
- `Source/MyArenaShooter/Private/MyEnemySpawner.cpp:46`（`::SpawnWave(`）
- `Source/MyArenaShooter/Private/MyArenaShooterGameState.cpp:14`（`::SetRoundState(`）

## 3. 入口

服务器 `GameMode::Tick`；Spawner在BeginPlay等待 `StartSpawning`。

## 4. 调用链

```text
GameMode每0.1秒统计连接数、已确认就绪数、存活玩家和Spawner数量
→ 仅一个Spawner；Standalone要求1人，非Standalone要求2人
→ 等待连接数和就绪数都等于要求数 → Spawning → StartSpawning
→ Spawner跳过0数量波、筛选有效出生点、登记成功生成的敌人
→ Tick清理无效/IsDead敌人并推进下一波
→ GameMode按配置错误、全员死亡、所有波次清空的顺序决定结果
→ GameState.SetRoundState复制状态；终局后StopRoundActors
```

## 5. 核心机制

GameMode在服务器掌握规则；GameState复制RoundState结构，包含Phase、波次、剩余数、就绪数和Revision。空Waves/负数/无有效点/全生成失败为ConfigurationError；非空配置里的0数量波可跳过。当前要求精确连接人数且只允许一个Spawner。

## 6. 关键设计问题

**为什么GameMode不直接当客户端共享数据源？**

GameMode实例只存在服务器；需要让客户端读到的回合结果放在可复制的GameState。

**为什么逻辑死亡后就能推进波次？**

Spawner按IsDead清理战斗数组，死亡动画和Actor销毁可以稍后完成，避免玩家等待尸体消失才推进。

**空波和空配置一样吗？**

不一样。非空配置中的0数量波可跳过；整个Waves为空会进入错误态，不应当成通关。
