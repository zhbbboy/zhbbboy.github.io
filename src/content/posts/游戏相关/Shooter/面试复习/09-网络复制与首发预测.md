## 1. 功能

服务器决定真实射击与伤害；本地立即生成首发表现弹，并用编号协调服务器后的表现事件。

## 3. 入口

本地 `StartFireInput` 先尝试 `TryPredictFirstShot`，然后发送Server RPC。

## 4. 调用链

```text
本地按下 → SequenceId递增 → 预测条件通过则生成VisualOnly首发并记录PredictionId
→ ServerSetFirePressed → 服务器StartFire / Fire生成真实子弹
→ 服务器拒绝立即开火：ClientCancelFirstShotPrediction销毁记录中的表现弹
→ 服务器成功：ClientConfirmShot记录日志；MulticastPlayFireEffects分发开火表现
→ 本地射手若已有同PredictionId则跳过重复表现弹；否则可生成本地表现弹
→ 真实子弹对Owner隐藏网格，其他端接收服务器复制的位置
→ 实际碰撞/伤害由服务器真实子弹决定
```

## 5. 核心机制

预测弹使用SpawnActorDeferred，FinishSpawning前InitializeVisualOnly；不复制，关闭实体碰撞和ProjectileMovement，用Tick与Sweep做本地结束显示，不产生伤害。最近预测编号记录最多64项。`ClientConfirmShot` 当前只输出确认日志；没有实现完整的位置回滚、伤害预测或通用校正系统。

## 6. 关键设计问题

**为什么客户端要预测首发？**

减少等待服务器往返时看到第一颗表现弹的延迟；服务器仍是子弹与伤害的权威。当前代码的提前预测是表现弹，枪焰/声音和后坐力由后续Multicast路径处理。

**为什么要传PredictionId？**

用于把服务器的事件与本地已生成的首发表现对应起来，避免拥有者再生成一颗重复表现弹，也能在拒绝时取消。

**Client RPC、Server RPC与Multicast有何区别？**

本项目Server RPC将拥有者请求送服务器；Client RPC给拥有连接；服务器调用Multicast向相关端传播瞬时表现，具体执行受所有权和网络相关性约束。
