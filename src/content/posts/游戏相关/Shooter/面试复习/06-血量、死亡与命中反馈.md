## 1. 功能

服务器处理玩家与敌人伤害，复制持久状态，并将短暂反馈送到对应客户端。

## 2. 相关类和源码位置

`AMyProjectile`、`AMyEnemyCharacter`、`AMyArenaShooterCharacter`、`UMyHUDWidget`。

- `Source/MyArenaShooter/Private/MyProjectile.cpp:197`（`::OnProjectileHit(`）
- `Source/MyArenaShooter/Private/MyEnemyCharacter.cpp:103`（`::TakeProjectileDamage(`）
- `Source/MyArenaShooter/Private/MyArenaShooterCharacter.cpp:308`（`::ReceiveEnemyDamage(`）
- `Source/MyArenaShooter/Private/MyArenaShooterCharacter.cpp:858`（`::ClientNotifyEnemyHit_Implementation(`）

## 3. 入口

实体子弹服务器碰撞调用 `Enemy::TakeProjectileDamage`；敌人有效近战调用玩家 `ReceiveEnemyDamage`。

## 4. 调用链

```text
服务器碰撞 → bHitProcessed 防重复
→ 敌人校验权威、有限正伤害及状态 → Clamp扣血
→ 存活：Multicast受击表现；致死：Die / 复制死亡 / 死亡表现与销毁
→ 接受伤害（含致死）返回true → 玩家 NotifyEnemyHit → ClientNotifyEnemyHit → 本地HitMarker
玩家受伤：服务器扣血 → OnRep_CurrentHealth / 复制 → 本地血条
→ ClientPlayDamageFeedback → 本地闪红和声音 → 致死时复制bIsDead
```

## 5. 核心机制

血量和死亡是持续状态，使用复制与OnRep；命中标记、受击声音/闪红等是短暂反馈，使用Client RPC或Multicast。服务器C++直接赋值不会自动在服务器执行自己的RepNotify，因此源码显式调用相应OnRep。

## 6. 关键设计问题

**为什么致死伤害仍返回true？**

返回值表达是否接受本次伤害，不表达是否存活；致死也应允许调用方触发命中确认。

**为什么血量和命中特效用不同同步方式？**

晚到客户端需要最新血量状态；一次火花是瞬时事件。Unreliable可能丢失，不能作为血量正确性的唯一来源。

**为什么服务器要显式调用本地OnRep？**

C++在服务器赋值本身不会自动触发服务器自己的RepNotify；本项目显式调用以刷新服务器本地表现。
