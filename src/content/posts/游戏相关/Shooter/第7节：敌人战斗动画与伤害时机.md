本节记录最新的攻击、受击、死亡动画接入。第3节最初的“AI进范围直接扣血”和后续波次过程继续保留；现在新增的是“AI决定攻击 → 敌人播放动作 → 动画事件在指定时刻请求伤害”。示例依据当前 UE 5.4 C++ 源码，完整函数省略注释并调整排版。

动画蓝图和蒙太奇是 `.uasset` 资源。本次已确认相关资源文件存在，未读取编辑器内部连线；下文的Notify和Slot步骤是要核对的连接方式，不把资源存在等同于已经接通。未实现的建议单独标明。

## 1. 为什么要把“开始动作”和“造成伤害”分开

原来的过程是：AI每帧检查距离，进入攻击范围且冷却结束，立即调用 `ReceiveEnemyDamage()`。这能完成战斗逻辑，但没有描述动作何时接触玩家。

当前C++已经拆出两个入口：

| 入口 | 谁调用 | 它回答的问题 |
| --- | --- | --- |
| `TryAttack()` | AIController | 现在能不能成功开始攻击动作？ |
| `ApplyAttackDamage()` | 需要由动画事件等外部入口调用 | 到攻击判定时刻时，还能不能打到玩家？ |

```text
AI Tick决定开始攻击
    → TryAttack播放AttackMontage
    → 动画继续推进
    → 到达攻击接触时刻的Notify【蓝图连接需核对】
    → ApplyAttackDamage重新检查死亡、玩家、距离
    → 玩家ReceiveEnemyDamage
```

这条链跨越AI的Tick和后来的动画事件，不是 `TryAttack()` 返回后立刻顺序调用伤害函数。当前整个C++目录没有直接调用 `ApplyAttackDamage()` 的位置；`UFUNCTION(BlueprintCallable)` 只是开放蓝图调用能力，不会自动生成调用。

## 2. 先区分Sequence、Montage、AnimInstance与Slot

| 名称 | 在本项目中的用途 |
| --- | --- |
| Animation Sequence | 一个具体动作的动画资源，例如攻击、受击、关闭/死亡动作 |
| `UAnimMontage` | 可由游戏逻辑播放的一段动作安排，当前作为攻击、受击、死亡的资源引用 |
| Animation Blueprint | 驱动敌人骨骼网格的动画逻辑与最终姿态图 |
| `UAnimInstance` | 骨骼网格运行时使用的动画实例，C++通过它检查蒙太奇是否在播放 |
| Slot节点 | 在AnimGraph里把蒙太奇姿态接到最终输出中的入口 |

新头文件通过 `class UAnimMontage;` 做前置声明，成员用 `UPROPERTY(EditDefaultsOnly, Category = "Combat")` 让敌人蓝图类默认值可以选择资源。

已经存在的资源包括 `ABP_MyEnemy`、`BS_EnemyLocomotion`、`AM_Enemy_Attack`、`AM_Enemy_Hit`、`AM_Enemy_Death`，位于 `Content/Art/SciFi/Enemies/QuadShell/`。只凭这些文件名，不能推断Blend Space的轴、Slot名称、Notify位置或动画蓝图的变量计算。

参考 [Animation Montage概念](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-montage-in-unreal-engine) 与 [Animation Slots](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-slots-in-unreal-engine)。

## 3. AI只决定追击或尝试开始攻击

源码位置：`Source/MyArenaShooter/Private/MyEnemyAIController.cpp:22`。

```cpp
void AMyEnemyAIController::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);

    if (!IsValid(PlayerCharacter))
    {
        return;
    }

    CurrentAttackCooldown = FMath::Max(CurrentAttackCooldown - DeltaTime, 0.0f);

    AMyEnemyCharacter* Enemy = Cast<AMyEnemyCharacter>(GetPawn());

    if (!IsValid(Enemy) || Enemy->IsDead())
    {
        return;
    }

    float DistanceToPlayer = FVector::Distance(
        Enemy->GetActorLocation(),
        PlayerCharacter->GetActorLocation()
    );

    if (DistanceToPlayer > Enemy->GetAttackRange())
    {
        MoveToActor(PlayerCharacter, 50.0f);
    }
    else
    {
        StopMovement();

        if (CurrentAttackCooldown <= 0.0f)
        {
            if (Enemy->TryAttack())
            {
                CurrentAttackCooldown = AttackCooldown;
            }
        }
    }
}
```

按这几个层次读：

1. 玩家引用无效，停止本次更新。
2. 攻击冷却按 `DeltaTime` 减少并限制到非负。
3. 取得被AI控制的Pawn，再转成 `AMyEnemyCharacter`。
4. 敌人引用无效或已逻辑死亡，停止本次更新。
5. 在范围外，`MoveToActor(PlayerCharacter, 50.0f)` 继续追击。
6. 在范围内，先 `StopMovement()`；冷却结束时尝试 `Enemy->TryAttack()`。
7. **只有TryAttack返回true，才把AI冷却重置为AttackCooldown。**

旧实现用AIController自己的 `AttackRange`、`AttackDamage` 直接扣血。现在距离用 `Enemy->GetAttackRange()`，伤害由Enemy的 `ApplyAttackDamage()` 使用。AI头文件里旧的 `AttackRange`、`MoveAcceptanceRadius`、`AttackDamage` 还在，但当前Tick不再读取它们；移动接受半径直接写成50。

AI的 `AttackCooldown` 默认1秒，决定下一次允许尝试的时间。Enemy还保留另一套默认1.5秒的 `StartAttack()` 冷却，当前AI并不使用它，不能把两套数值当成同一个生效参数。

## 4. TryAttack：状态检查和“开始成功”结果

源码位置：`Source/MyArenaShooter/Private/MyEnemyCharacter.cpp:124`。

```cpp
bool AMyEnemyCharacter::TryAttack()
{
    if (bIsDead)
    {
        return false;
    }

    if (!AttackMontage)
    {
        return false;
    }

    UAnimInstance* AnimInstance = GetMesh()->GetAnimInstance();

    if (!AnimInstance)
    {
        return false;
    }

    if (AnimInstance->Montage_IsPlaying(AttackMontage))
    {
        return false;
    }

    if (HitMontage && AnimInstance->Montage_IsPlaying(HitMontage))
    {
        return false;
    }

    return PlayAnimMontage(AttackMontage) > 0.0f;
}
```

完整函数依次拒绝这些情况：

| 拒绝条件 | 为什么要拒绝 |
| --- | --- |
| `bIsDead` | 死亡后不再开始新攻击 |
| 没有AttackMontage | 没有可以播放的攻击资源 |
| 没有AnimInstance | 网格没有可用动画实例 |
| 攻击蒙太奇正在播放 | 避免重复开始同一次动作 |
| 受击蒙太奇正在播放 | 避免受击动作中又立刻开始攻击 |

通过检查后：

```cpp
return PlayAnimMontage(AttackMontage) > 0.0f;
```

返回true代表这次开始播放的调用获得了正返回值。它不是“打中了玩家”，也不是“动作已经结束”。本地UE 5.4的 `ACharacter::PlayAnimMontage()` 会取得网格动画实例并调用 `Montage_Play()`；不能播放时返回0。官方声明见 [PlayAnimMontage](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/ACharacter/PlayAnimMontage?lang=en-US)。

`GetMesh()->GetAnimInstance()` 取得的是敌人骨骼网格的运行时动画实例，不是蒙太奇资源本身。`Montage_IsPlaying(AttackMontage)` 查询指定蒙太奇当前是否在播放；查询不会开始或停止动画。参见 [Montage_IsPlaying](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UAnimInstance/Montage_IsPlaying)。

### 4.1 冷却和播放状态为什么都要检查

假设AI冷却1秒、攻击动作持续1.2秒。冷却先归零，但动作仍在播放，`TryAttack()` 仍返回false；直到动作不再播放，下一次Tick才有机会开始下一次攻击。

反过来，动作如果只持续0.6秒，播放结束也不会自动跳过AI剩余的0.4秒冷却。两个条件分别控制“间隔”和“动作是否占用当前状态”。这两个数值是理解用的例子，不是从蒙太奇资产读取的实际长度。

## 5. 动画怎样在接触时刻调用伤害

### 5.1 C++提供可从蓝图调用的入口

头文件对应声明：

```cpp
UFUNCTION(BlueprintCallable, Category = "Combat")
void ApplyAttackDamage();
```

源码位置：`Source/MyArenaShooter/Private/MyEnemyCharacter.cpp:156`。

```cpp
void AMyEnemyCharacter::ApplyAttackDamage()
{
    if (bIsDead)
    {
        return;
    }

    AMyArenaShooterCharacter* Player = Cast<AMyArenaShooterCharacter>(UGameplayStatics::GetPlayerCharacter(GetWorld(), 0));

    if (!IsValid(Player))
    {
        return;
    }

    float Distance = FVector::Distance(
        GetActorLocation(),
        Player->GetActorLocation()
    );

    if (Distance > AttackRange + 20.0f)
    {
        return;
    }

    Player->ReceiveEnemyDamage(AttackDamage);

    UE_LOG(
        LogTemp,
        Warning,
        TEXT("Enemy Attack Hit! Damage = %.1f"),
        AttackDamage
    );
}
```

它会重新取索引0的玩家并计算当前两个Actor位置间的距离。如果超过 `AttackRange + 20.0f` 就放弃本次伤害。默认150范围对应170的伤害判定上限，20是额外容差。

为什么重查距离？开始攻击时玩家在附近，但动作进行到接触时玩家可能已经跑开。不能因为“动作起手时在范围内”就保证之后必定扣血。

当前判定是**Actor中心距离检查**，没有新增武器形状Sweep、重叠区域、视线遮挡或朝向检查。它也没有“本次攻击已经扣过一次”的标志；若蓝图一轮动作调用两次这个入口，满足条件时会提出两次伤害请求。

玩家仍通过 `ReceiveEnemyDamage()` 检查死亡、胜利与伤害值。函数末尾打印 `Enemy Attack Hit!`，只证明敌人提出过请求，不保证玩家一定接受并扣血。

### 5.2 用普通命名Notify连接的核对步骤

下面是可采用的蓝图连接例子，名字 `AttackHit` 是说明用名称，未断言现有资产已经使用它：

1. 在攻击动作的Notifies轨道接触帧添加一个普通命名/Skeleton Notify，例如 `AttackHit`。
2. 在 `ABP_MyEnemy` 的Event Graph添加对应 `AnimNotify_AttackHit` 事件。
3. 从事件取得动画拥有的Pawn，例如 `Try Get Pawn Owner`。
4. `Cast To MyEnemyCharacter`，转换成功后调用 `ApplyAttackDamage`。
5. 一轮动作只在预期接触点触发一次，并在Play中用日志与血量一起核对。

```text
攻击动画推进到AttackHit
    → AnimNotify_AttackHit事件
    → Try Get Pawn Owner
    → Cast To MyEnemyCharacter
    → ApplyAttackDamage
    → 当前死亡/玩家/距离检查
    → ReceiveEnemyDamage
```

这条外部事件链不在当前C++调用点中，必须由资产连接提供。普通命名Notify事件与 `Play Montage` 蓝图节点的 `On Notify Begin` 回调是不同接法；官方的Montage Notify回调方式要求相应的Play Montage节点，不能直接套到这里的C++ `PlayAnimMontage()` 上。参考 [Animation Notifies](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-notifies-in-unreal-engine) 与 [Animation Blueprint事件节点](https://dev.epicgames.com/documentation/unreal-engine/animation-blueprint-event-nodes-in-unreal-engine)。

### 5.3 蒙太奇实际显示还依赖Slot

核对敌人Mesh是否使用Animation Blueprint、Anim Class是否指向正确的动画蓝图、动画蓝图的AnimGraph是否把相同Slot接到Output Pose。常见连接思路是“移动姿态 → 对应Slot → Output Pose”，具体Slot名称要与蒙太奇一致。

蒙太奇对象不为空，不等于最终姿态一定能在角色身上看到。`TryAttack()` 返回true也不能替代对Slot和最终姿态输出的核对。

## 6. 受击：扣血后尝试播放HitMontage

源码位置：`Source/MyArenaShooter/Private/MyEnemyCharacter.cpp:98`。

```cpp
bool AMyEnemyCharacter::TakeProjectileDamage(float Damage)
{
    if (IsActorBeingDestroyed()
        || CurrentHealth <= 0.0f
        || !FMath::IsFinite(Damage)
        || Damage <= 0.0f)
    {
        return false;
    }

    CurrentHealth = FMath::Clamp(CurrentHealth - Damage, 0.0f, MaxHealth);

    UE_LOG(
        LogTemp,
        Warning,
        TEXT("Enemy Took Damage: %f, Current Health: %f"),
        Damage,
        CurrentHealth
    );

    if (CurrentHealth <= 0.0f)
    {
        Die();
        return false;
    }
    PlayHitReaction();
    return true;
}
```

本次新增分支：

```text
有效伤害
    → 限制血量范围并扣血
    → 血量归零？
        是：Die，然后return false
        否：PlayHitReaction，然后return true
```

这里与2026-10-09阶段发生了变化：**致死伤害现在返回false**。false既可能表示一开始拒绝伤害，也可能表示已经接受并执行了致死伤害，因此不能再完整解释为“false就是没有接受伤害”。

子弹仍只在返回true时调用 `NotifyEnemyHit()`，所以普通伤害可以显示命中标记，击杀那一发会跳过标记。碰撞特效与声音在该判断之外，仍按 `Hit.bBlockingHit` 与资源引用执行。若后续希望返回值统一表示“伤害被接受”，致死分支应继续返回true；这是待完善建议，本次没有修改源码。

### 6.1 PlayHitReaction为何有时不播放

源码位置：`Source/MyArenaShooter/Private/MyEnemyCharacter.cpp:75`。

```cpp
void AMyEnemyCharacter::PlayHitReaction()
{
    if (!HitMontage)
    {
        return;
    }

    UAnimInstance* AnimInstance = GetMesh()->GetAnimInstance();

    if (!AnimInstance)
    {
        return;
    }

    if (AttackMontage && AnimInstance->Montage_IsPlaying(AttackMontage))
    {
        return;
    }

    PlayAnimMontage(HitMontage);
}
```

没有HitMontage或动画实例就跳过；攻击蒙太奇正在播放时也跳过。这一阶段的策略是让攻击动作进行时不被受击蒙太奇打断。

它只控制受击表现，伤害已经在调用前扣除。因此“看不到受击动作”不能直接判断“没有受到伤害”。另外函数没有拒绝已经在播放的HitMontage；重复命中时可能再次请求播放，实际姿态还依赖资源与蒙太奇设置。

## 7. 死亡拆成“停止战斗”和“之后销毁”

源码位置：`Source/MyArenaShooter/Private/MyEnemyCharacter.cpp:190`。

```cpp
void AMyEnemyCharacter::Die()
{
    if (bIsDead)
    {
        return;
    }

    bIsDead = true;

    if (AAIController* AIController = Cast<AAIController>(GetController()))
    {
        AIController->StopMovement();
    }

    GetCharacterMovement()->DisableMovement();

    GetCapsuleComponent()->SetCollisionEnabled(ECollisionEnabled::NoCollision);

    if (DeathMontage)
    {
        float Duration = PlayAnimMontage(DeathMontage);

        if (Duration > 0.0f)
        {
            GetWorldTimerManager().SetTimer(
                DeathTimerHandle,
                this,
                &AMyEnemyCharacter::FinishDeath,
                Duration,
                false
            );
        }
        return;
    }

    FinishDeath();
}
```

第一阶段 `Die()` 立即做：

1. 用 `bIsDead` 拒绝重复执行，再设为true。
2. 取得AIController并 `StopMovement()`，停止寻路移动。
3. `DisableMovement()` 禁用角色移动组件。
4. 将Capsule碰撞设为NoCollision。
5. 尝试播放DeathMontage，成功返回正长度时注册一次性销毁定时器。

这里关闭的是胶囊组件碰撞，没有逐个关闭所有网格或子组件碰撞。AI的Tick也没有被关闭，只是在下一次Tick发现 `IsDead()` 后返回，不再继续追击/开始攻击。

### 7.1 Timer回调不是动画结束委托

源码位置：`Source/MyArenaShooter/Private/MyEnemyCharacter.cpp:233`。

```cpp
void AMyEnemyCharacter::FinishDeath()
{
    UE_LOG(
        LogTemp,
        Warning,
        TEXT("Enemy Death Finished!")
    );

    Destroy();
}
```

当前死亡成功播放后，用 `PlayAnimMontage()` 的返回值 `Duration` 作为定时器时长。到时间后调用 `FinishDeath()`，再请求 `Destroy()`。

```text
Die立即记录死亡
    → PlayAnimMontage返回正值
    → SetTimer注册Duration秒后执行
    → 当前调用结束，世界继续运行
    → 时间到达：FinishDeath
    → Destroy
```

它没有监听“蒙太奇实际结束/被中断”的委托；不能把固定Timer理解成已经与所有动画中断、变速和暂停情况同步。当前播放使用默认速率，但之后扩展时仍应区分“按时间估计”与“收到动画结束事件”。定时器原理可复习 [Gameplay Timers](https://dev.epicgames.com/documentation/en-us/unreal-engine/gameplay-timers-in-unreal-engine?application_version=5.4)。

### 7.2 当前播放失败分支有一处漏接

真实顺序是：只要 `DeathMontage` 指针不为空，就进入if；无论 `Duration` 是否大于0，最后都会执行if内部的 `return`。

| 当前情况 | 实际结果 |
| --- | --- |
| 没有DeathMontage | 走if外的FinishDeath，直接请求销毁 |
| 有DeathMontage且播放返回正值 | 注册定时器，之后FinishDeath |
| 有DeathMontage但播放返回0 | 没有注册定时器，也没有执行FinishDeath，Actor可能一直留在地图中 |

源码注释说“没有死亡动画或播放失败时直接销毁”，但当前控制流只实现了“没有资源”时的兜底。不能按注释把失败分支记成已经完成。

待完善逻辑可以这样写成伪代码：

```text
如果配置了死亡蒙太奇且成功播放：
    注册之后销毁的定时器
    返回
其他情况：
    直接FinishDeath
```

## 8. 波次按逻辑死亡推进，不等尸体消失

Spawner最新清理函数源码位置：`Source/MyArenaShooter/Private/MyEnemySpawner.cpp:146`。

```cpp
void AMyEnemySpawner::CleanupDeadEnemies()
{
    int32 PreviousEnemyCount = CurrentWaveEnemies.Num();

    for (int32 i = CurrentWaveEnemies.Num() - 1; i >= 0; --i)
    {
        AMyEnemyCharacter* Enemy = CurrentWaveEnemies[i];

        if (!IsValid(Enemy) || Enemy->IsDead())
        {
            CurrentWaveEnemies.RemoveAt(i);
        }

        if (CurrentWaveEnemies.Num() != PreviousEnemyCount)
        {
            if (IsValid(PlayerCharacter))
            {
                PlayerCharacter->UpadteWaveHUD(
                    CurrentWaveIndex + 1,
                    Waves.Num(),
                    CurrentWaveEnemies.Num()
                );
            }
        }
    }
}
```

本次数组删除条件由“引用无效”变为“引用无效 **或** Enemy已经逻辑死亡”。`||` 短路求值，引用无效时不会继续调用 `Enemy->IsDead()`。

```text
Enemy.Die → bIsDead=true，死亡动画开始
    → Spawner后续Tick清理
    → 即使Actor还存在，IsDead也使引用从本波数组移除
    → 更新剩余数量
    → 数组为空：开始下一波或通知胜利
    → 尸体自己的Timer之后才FinishDeath / Destroy
```

这样战斗进度不用等待死亡动画完成。HUD剩余数量代表本波仍参与战斗的敌人，不能再解释为“地图中仍存在的Enemy Actor总数”。最后一波可能在尸体动画尚未结束时显示胜利。

当前 `PreviousEnemyCount` 放在循环外，但更新HUD的判断仍位于循环内。一旦发生一次删除，后续迭代中数量都不同于原始数量，可能重复发送相同HUD更新。它没有影响删除条件，但若后续整理，可把最终更新移到循环之后；这不是已完成的优化。

## 9. 旧StartAttack与当前TryAttack不要混用

`StartAttack()`、`bIsAttacking`、`ISAttacking()`、`AttackTimerHandle` 仍保留在Enemy中，但当前AI只调用 `TryAttack()`。

旧StartAttack的思路是先设 `bIsAttacking=true`，尝试播放蒙太奇，再注册一个捕获 `[this]` 的Lambda，固定时间后把标志复位。`[this]` 让回调可以访问这个对象的成员。这种标志冷却不等于蒙太奇实际播放状态。

当前TryAttack直接查询 `Montage_IsPlaying`，并不设置 `bIsAttacking`。所以 `ISAttacking()` 返回false，也不能据此判断当前没有攻击动作。两套方法的关系应记为“旧入口保留、当前C++主链使用新入口”，不要画成AI同时使用两套流程。

## 10. 完整执行链与验证顺序

```text
攻击：AI Tick
    → Enemy有效且活着 → 距离进范围 → StopMovement
    → AI冷却归零 → TryAttack检查资源和蒙太奇状态
    → 成功开始AttackMontage → 重置AI冷却
    → 动画Notify【需蓝图接通】→ ApplyAttackDamage
    → 重新判断玩家/距离 → 玩家受伤反馈与死亡判断

受击：Projectile.OnProjectileHit
    → Enemy.TakeProjectileDamage
    → 存活：PlayHitReaction（攻击中则跳过表现）→ return true
    → 子弹通知Hit Marker → 接触特效/声音 → 销毁子弹

致死：Projectile.OnProjectileHit
    → Enemy血量归零 → Die设bIsDead
    → 停寻路/移动/胶囊碰撞 → 死亡蒙太奇/定时销毁
    → 当前return false → 这发跳过Hit Marker
    → Spawner按IsDead移除引用 → 下一波/胜利
    → 尸体之后FinishDeath → Destroy
```

验证时依次观察：AI是否进入范围；TryAttack是否成功；动作是否显示；Notify是否触发；ApplyAttackDamage是否发出请求；玩家是否接受伤害。死亡则分别看 `IsDead()`、剩余数量与Actor消失时间，不把它们当成同一事件。

配套可编辑图纸见仓库 `draw/MyArena/MyArena-战斗动画与武器表现-20261013.drawio` 的第1页，预览和学习说明在同一图纸目录。此前总框架图核对日期为2026-10-11，复习本次变化时以本节及这份追加图为准。
