这一节记录 2026-10-08 已完成的“相机射线选点 → 枪口生成实体子弹 → 实际碰撞 → 命中反馈”，重点解释射击追踪的思路与执行链。第 2 节的单发、连射、换弹过程继续保留；本节是建立在这些功能之上的新学习阶段。

当前项目是 UE 5.4。代码示例取自 MyWeapon、MyProjectile、MyArenaShooterCharacter、MyHUDWidget 的这次实现。完整函数省略源码注释，逻辑保持一致；其他片段会说明放在哪里。学习时不要在项目里同时复制两个同名 Fire。

## 1. 先理解需求：我要看向哪里，子弹就朝哪里飞

### 1.1 原来已经解决了“从哪里生成子弹”

第 2 节最初的 Fire 使用枪口位置和枪口旋转生成子弹：

```cpp
MuzzleLocation->GetComponentLocation()
MuzzleLocation->GetComponentRotation()
```

这让子弹从枪口朝枪口前向飞。枪和相机之间有偏移，即使两者朝向相同，从不同位置发出的平行线也不会自动交在同一个目标上；近处的偏差通常更明显。

现在仍让子弹从枪口出生，但增加一件事：先确定视角前方具体瞄准哪个世界坐标，再让枪口朝这个坐标发射。

![相机射线确定瞄准点，枪口到瞄准点决定子弹方向](/images/arena/arena-camera-muzzle-aim.png)

图里 C 是相机、M 是枪口、A 是选中的瞄准点。绿色 C → A 回答“视角看向哪里”，黄色 M → A 回答“子弹从枪口朝哪里飞”。图是俯视示意，省略高度，不按实际距离比例绘制。

### 1.2 本次“追踪”是哪种实现

| 阶段 | 发生什么 | 是否在这里造成伤害 |
| --- | --- | --- |
| 相机射线查询 | 立刻检测线段上的符合条件的物体，取得瞄准点 | 否 |
| 枪口生成子弹 | 根据枪口到瞄准点的方向，创建 Projectile | 否 |
| 子弹实际飞行和碰撞 | ProjectileMovement 移动碰撞球，命中后进入 OnProjectileHit | 在这里调用敌人受伤函数 |

当前仍是实体子弹射击。Line Trace 在这一阶段用于选点，不直接替代子弹造成伤害。子弹也没有启用跟踪移动目标的 Homing 配置；出膛后没有不断重新寻找敌人。

每次允许执行 Fire，都重新读取相机并做一次查询。连续射击时，新的一颗按这一次视角选点；已经飞出的上一颗继续自己的飞行。瞄准敌人后敌人移动，子弹仍可能落空。

### 1.3 一个必须先记住的公式

```text
相机射线终点 = 相机位置 + 相机前向单位向量 × 查询长度
瞄准点 = 查询有命中 ? 接触点 : 射线终点
子弹方向 = Normalize(瞄准点 - 枪口位置)
生成旋转 = 子弹方向.Rotation()
```

前三行依次得到“查哪里”“选哪个点”“朝哪个方向”，最后一行转换成 SpawnActor 接收的旋转。后面的代码就是把这四行需要的数据准备出来。

## 2. 射击入口没换：在原有 Fire 内增加瞄准计算

```text
左键 → IMC_Player → IA_Fire Started
→ Character.StartFireInput：存活且武器有效
→ Weapon.StartFire：记住按住，检查换弹、弹药和冷却
→ 条件允许时 Weapon.Fire

保持按住：Weapon.Tick 减少冷却
→ 仍按住、未换弹、冷却结束 → 再次 Fire

松开：Completed → StopFireInput → Weapon.StopFire
```

连射和换弹仍沿用第 2 节后续记录。新增相机射线在 Fire 里，因此资源缺失、换弹中、弹匣空等提前返回时，不会完整执行下面的追踪与生成链。

本次 Fire 还要求武器 Owner 属于自己的玩家角色，并且这个角色的相机组件有效。不是在世界里放任意一个 Weapon Actor，点鼠标就自然能查到正确视角。

## 3. 第一步：从武器找到玩家，再取得相机

### 3.1 为什么 GetOwner 可以取得玩家

生成武器时，角色已经在 BeginPlay 设置：

```cpp
SpawnParams.Owner = this;
SpawnParams.Instigator = this;
```

此处 this 是 Character。新武器的 Owner 因而指向这个角色；这是 Actor 关系，不是因为枪挂在相机下就自动得到的。

Fire 中读取它并确认类型：

```cpp
AMyArenaShooterCharacter* Player = Cast<AMyArenaShooterCharacter>(GetOwner());
if (!IsValid(Player))
{
    return;
}

UCameraComponent* Camera = Player->GetFirstPersonCameraComponent();
if (!IsValid(Camera))
{
    return;
}
```

GetOwner 是引擎 API；GetFirstPersonCameraComponent 是本次自己添加的公开 getter。在玩家头文件 public 区段中：

```cpp
UCameraComponent* GetFirstPersonCameraComponent() const
{
    return FirstPersonCameraComponent;
}
```

相机成员继续留在角色内部，武器通过 getter 读取引用。const 表示这次读取不修改角色自身成员；不表示取得的相机对象从此不能被修改。

### 3.2 为什么取相机而不是角色前向

FirstPersonCameraComponent 使用 bUsePawnControlRotation，能跟随玩家视角的水平和俯仰变化。读取 Camera 的世界前向，就包括抬头和低头；若只按角色身体的前向生成，不能完整表达当前视线。

当前从相机组件前向取方向；没有通过鼠标屏幕坐标反投影。把准星摆在当前视图中心时，这条前向可以作为中心瞄准方向；把准星随意摆到屏幕其他位置不会自动改变查询方向。

## 4. 第二步：把位置和前向组成一条有限线段

```cpp
const FVector CameraStart = Camera->GetComponentLocation();
const FVector CameraEnd = CameraStart + Camera->GetForwardVector() * 10000.0f;
```

| 数据 | 类型含义 | 在这一步的作用 |
| --- | --- | --- |
| CameraStart | 世界空间中的一个位置 | 查询起点 |
| GetForwardVector() | 世界空间中的前向单位向量 | 查询往哪个方向 |
| 10000.0f | 长度 | 从起点向前查多远 |
| CameraEnd | 世界空间中的一个位置 | 查询终点 |

位置和方向都用 FVector 表示，业务意义却不同。前向向量长度约为1，乘10000后是长10000的位移；加上起点，才得到终点。

默认距离单位为厘米，所以10000单位约为100米，不是屏幕上的10000像素。两组仅用于理解的例子：

```text
相机 C = (200, 300, 100)，前向 F = (1, 0, 0)
10000 × F = (10000, 0, 0)
终点 E = C + 10000 × F = (10200, 300, 100)

相机仍在 C，转向后 F = (0, 1, 0)
终点变成 E = (200, 10300, 100)
```

如果只写 F × 10000，就把终点放在世界原点附近对应的方向上，丢失了当前相机位置。const 表示在这次 Fire 的后续计算里不再改这两个局部值，不是把相机位置永久固定。

10000只是选点查询长度。子弹没有“到达 CameraEnd 就自动销毁”的代码；没有撞到物体时仍按速度飞到寿命到期。默认3000单位/秒、5秒寿命，理想直线飞行距离约15000单位，即150米，这与相机查询的100米是两个规则。

## 5. 第三步：先明确查谁、忽略谁，再执行查询

### 5.1 FCollisionQueryParams 管理这一次查询的附加规则

```cpp
FCollisionQueryParams QueryParams;
QueryParams.AddIgnoredActor(Player);
QueryParams.AddIgnoredActor(this);
```

Player 是玩家；这里 this 是当前武器。相机处于玩家附近，枪也在视野前方，因此查询要排除这两个 Actor，避免把自己当成想瞄准的表面。

AddIgnoredActor 只修改这份查询参数；它不会修改玩家碰撞预设，也不会让之后生成的子弹自动忽略玩家。子弹忽略发射者是第8节里的另一段代码。[FCollisionQueryParams 官方说明](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/FCollisionQueryParams)

当前采用默认构造，未显式启用 bTraceComplex；本地UE 5.4中该默认值为false。要理解为按默认简单碰撞查询设置执行，不是自动精确查询每个可见三角形；具体使用的几何还受目标资源的碰撞配置影响。

### 5.2 FCollisionObjectQueryParams 指定对象类型

```cpp
FCollisionObjectQueryParams ObjectTypes;
ObjectTypes.AddObjectTypesToQuery(ECC_Pawn);
ObjectTypes.AddObjectTypesToQuery(ECC_WorldStatic);
```

| 对象类型 | 当前为什么加入 |
| --- | --- |
| ECC_Pawn | 查询角色等Pawn类型的碰撞组件，当前Enemy胶囊通常属于这一类 |
| ECC_WorldStatic | 查询墙壁、地面等WorldStatic类型的碰撞组件，让遮挡也能成为瞄准点 |

这里看的是组件配置的 Collision Object Type，不是只按 C++ 类名判断。继承 AActor 的物体也可能配置成 Pawn 对象类型；一个 Enemy 的不同组件也可能有不同类型。[FCollisionObjectQueryParams 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/FCollisionObjectQueryParams)

当前没有把 ECC_WorldDynamic 加入列表，动态物体可能不参与相机选点；子弹球却仍对通道设置 Block，所以实际子弹仍可能被这些物体挡住。

本次是 ByObjectType，不是 ByChannel。不要把“加入Pawn对象类型”理解成“使用Visibility通道”：本次按所选对象类型筛选，不需要以目标的Visibility响应作为这条查询的筛选规则；组件仍需启用查询碰撞，并具有可被检测的碰撞几何。可结合[官方 Trace 分类说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/traces-with-raycasts-in-unreal-engine)理解两种查询。

### 5.3 LineTraceSingleByObjectType 的返回值和输出参数

```cpp
FHitResult Hit;

bool bHit = GetWorld()->LineTraceSingleByObjectType(
    Hit,
    CameraStart,
    CameraEnd,
    ObjectTypes,
    QueryParams
);
```

可以把调用读成：在当前世界，从CameraStart查到CameraEnd，只考虑列表中的对象类型，排除指定Actor，返回这一条查询的第一个符合条件的阻挡命中。

| 部分 | 接收或提供什么 |
| --- | --- |
| bool返回值 bHit | 本次是否找到了命中 |
| Hit | 引擎写入命中详情的输出结构体 |
| CameraStart / CameraEnd | 线段起点与终点 |
| ObjectTypes | 要检测的对象类型集合 |
| QueryParams | 本次查询的忽略等附加条件 |

函数签名的OutHit使用FHitResult&，所以它能修改调用者的Hit。函数不是把一个“命中对象”返回给bool；bool和详情分别通过返回值与引用参数传回来。[LineTraceSingleByObjectType 参数说明](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/Engine/UWorld/LineTraceSingleByObjectType?application_version=5.5)与本地UE 5.4的World.h声明一致。

Line Trace 是这次调用立即完成的一次查询，没有真的生成一根会飞行的射线Actor。它也不会只因为查询命中就触发当前子弹的OnProjectileHit；子弹的碰撞是后续独立过程。[UE 5.4 Trace 概述](https://dev.epicgames.com/documentation/en-us/unreal-engine/traces-in-unreal-engine---overview?application_version=5.4)

## 6. 第四步：有命中选接触点，没有命中选远端

```cpp
FVector AimPoint = bHit ? Hit.ImpactPoint : CameraEnd;
```

这是三元表达式。可以用伪代码展开：

```text
如果 bHit 为true：
    AimPoint = 本次查询命中的实际接触点
否则：
    AimPoint = 相机前方的查询终点
```

| 查询结果 | AimPoint来自哪里 | 后续是否仍尝试生成子弹 |
| --- | --- | --- |
| 先遇到Enemy | Enemy碰撞表面的接触点 | 是 |
| 先遇到墙 | 墙面的接触点 | 是，瞄准点变成墙面 |
| 什么也没有遇到 | CameraEnd | 是，向远方射击 |

bHit只表示查询有命中，不表示“已经打中Enemy”。墙、地面、其他符合类型的物体也可以让它为true；本次没有在这里扣敌人血量。

Hit.ImpactPoint 是世界坐标中的接触位置，不是Enemy Actor的原点。例如胶囊中心与表面是不同位置，直接用ActorLocation会丢失“视线碰到哪个位置”的信息。

FHitResult里还有GetActor、GetComponent、ImpactNormal等可用于调试或其他功能的成员。这里选点只读取ImpactPoint，并且只在bHit为true的分支读取，不用无命中的默认值代替远端。[FHitResult 官方说明](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/FHitResult)

## 7. 第五步：从枪口指向这个点，再转成旋转

### 7.1 两个世界位置相减，得到从起点到终点的位移

```cpp
const FVector MuzzlePosition = MuzzleLocation->GetComponentLocation();
FVector ShootDirection = (AimPoint - MuzzlePosition).GetSafeNormal();
```

“目标减起点”得到起点朝目标的向量。不是把两个位置相加，也不是直接把AimPoint当作方向。

下面是简化坐标例子，不代表蓝图真实枪口偏移：

```text
相机 C = (0, 0, 0)
枪口 M = (30, 10, -10)
瞄准点 A = (1000, 0, 0)

A - M = (970, -10, 10)
含义：从枪口向前970、向Y负方向10、向上10，才能到这个点。

反过来 M - A = (-970, 10, -10)
会朝远离瞄准点的方向。
```

AimPoint与MuzzlePosition都在世界空间，才能直接相减。若误用枪口相对坐标与世界瞄准点相减，就是把两个不同基准混在一起。

### 7.2 GetSafeNormal 保留方向，去掉距离

`GetSafeNormal()` 返回安全归一化后的向量。非零向量会变为约单位长度；太小、无法可靠归一化时默认返回零向量。这里要的是“朝哪边”，而不是把970多单位的距离当作速度大小。[GetSafeNormal 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/TVector/GetSafeNormal)

```text
位移约(970, -10, 10)，长度约970.103
→ 单位方向约(0.999894, -0.010308, 0.010308)
```

当前子弹速度由ProjectileMovement的InitialSpeed决定，所以目标离得更远并不会因位移向量变长而让子弹自动更快。

### 7.3 处理近零方向，再用 Rotation 得到朝向

```cpp
if (ShootDirection.IsNearlyZero())
{
    ShootDirection = Camera->GetForwardVector();
}

FRotator ShootRotation = ShootDirection.Rotation();
```

若瞄准点几乎等于枪口位置，相减结果接近零，归一化后仍不能提供稳定方向。IsNearlyZero判断这种情况，后备方案使用相机前向。

FVector::Rotation把方向转换为Pitch、Yaw，Roll设为0，得到FRotator，让局部前向与该方向对应；SpawnActor的旋转参数接收FRotator，不直接接收FVector。注意Rotation不会把子弹移到目标点，也不会让子弹沿途自动转向。[Rotation 官方说明](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Core/TVector/Rotation?lang=en-US)

## 8. 第六步：按新朝向生成，让移动组件沿局部前向飞

### 8.1 本次出生位置保留枪口，出生旋转换成计算结果

```cpp
FActorSpawnParameters SpawnParams;
SpawnParams.Owner = this;
SpawnParams.Instigator = GetInstigator();
SpawnParams.SpawnCollisionHandlingOverride = ESpawnActorCollisionHandlingMethod::AlwaysSpawn;

AMyProjectile* SpawnedProjectile = GetWorld()->SpawnActor<AMyProjectile>(
    ProjectileClass,
    MuzzlePosition,
    ShootRotation,
    SpawnParams
);
```

本次this仍是Weapon，所以Projectile的Owner为Weapon、Instigator仍为玩家Pawn。Instigator随后既用于排除发射者，又用于把命中反馈发回正确的玩家。

AlwaysSpawn表示生成阶段遇到出生碰撞时仍尝试按该策略生成Actor，不自动等于“已经忽略玩家”或“出生后不会碰撞”。当前保存了SpawnedProjectile指针，但后面没有检查这个返回值再决定特效或弹药扣除；这段行为仍要按真实代码理解。

### 8.2 为什么给Actor旋转，就能决定子弹的初始飞行方向

Projectile构造函数本次明确增加：

```cpp
ProjectileMovement->bInitialVelocityInLocalSpace = true;
ProjectileMovement->Velocity = FVector(1.0f, 0.0f, 0.0f);
```

结合原来的InitialSpeed = 3000，可以按下面读：

```text
局部Velocity=(1,0,0)：子弹自身的+X前向
→ 移动组件初始化时按InitialSpeed缩放为3000
→ bInitialVelocityInLocalSpace把局部速度按子弹组件朝向转换为世界速度
→ 生成时的ShootRotation已经对准AimPoint
→ 世界速度沿ShootDirection，以默认3000单位/秒飞行
```

对应本地UE 5.4的ProjectileMovementComponent.cpp初始化逻辑。模型的视觉朝向、Actor的朝向和移动速度方向需要分别理解；模型资源若自身轴向不同，可表现为“看着侧着飞”，但不必然是方向计算错了。

### 8.3 本次子弹开始忽略发射者

```cpp
void AMyProjectile::BeginPlay()
{
    Super::BeginPlay();

    CollisionComponent->OnComponentHit.AddDynamic(this, &AMyProjectile::OnProjectileHit);

    if (IsValid(GetInstigator()))
    {
        CollisionComponent->IgnoreActorWhenMoving(
            GetInstigator(),
            true
        );
    }
}
```

IgnoreActorWhenMoving(GetInstigator(), true)让子弹碰撞球主动移动扫掠时忽略发射Pawn。它与相机查询的AddIgnoredActor是两个独立忽略列表，也与AlwaysSpawn策略不同。

当前只设置子弹这一侧，未给玩家移动组件设置反向忽略，也没有在这里排除武器或其他所有Pawn。API不作用于该组件模拟物理时的移动；本项目当前由ProjectileMovement驱动碰撞球。[IgnoreActorWhenMoving 官方说明](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Engine/UPrimitiveComponent/IgnoreActorWhenMoving)

## 9. 把前面的步骤放回当前完整 Fire

以下是这次MyWeapon.cpp中的完整Fire逻辑，调试画线目前被注释，所以不包含在这个运行代码示例中：

```cpp
void AMyWeapon::Fire()
{
    if (bIsReoloading)
    {
        return;
    }

    if (CurrentAmmo <= 0)
    {
        StartReload();
        return;
    }

    if (!MuzzleLocation || !ProjectileClass)
    {
        return;
    }

    AMyArenaShooterCharacter* Player =
        Cast<AMyArenaShooterCharacter>(GetOwner());

    if (!IsValid(Player))
    {
        return;
    }

    UCameraComponent* Camera = Player->GetFirstPersonCameraComponent();

    if (!IsValid(Camera))
    {
        return;
    }

    const FVector CameraStart = Camera->GetComponentLocation();
    const FVector CameraEnd = CameraStart
        + Camera->GetForwardVector() * 10000.0f;

    FCollisionQueryParams QueryParams;

    QueryParams.AddIgnoredActor(Player);
    QueryParams.AddIgnoredActor(this);

    FCollisionObjectQueryParams ObjectTypes;

    ObjectTypes.AddObjectTypesToQuery(ECC_Pawn);
    ObjectTypes.AddObjectTypesToQuery(ECC_WorldStatic);

    FHitResult Hit;

    bool bHit = GetWorld()->LineTraceSingleByObjectType(
        Hit,
        CameraStart,
        CameraEnd,
        ObjectTypes,
        QueryParams
    );

    FVector AimPoint = bHit ? Hit.ImpactPoint : CameraEnd;

    const FVector MuzzlePosition = MuzzleLocation->GetComponentLocation();

    FVector ShootDirection = (AimPoint - MuzzlePosition).GetSafeNormal();

    if (ShootDirection.IsNearlyZero())
    {
        ShootDirection = Camera->GetForwardVector();
    }

    FRotator ShootRotation = ShootDirection.Rotation();

    FActorSpawnParameters SpawnParams;
    SpawnParams.Owner = this;
    SpawnParams.Instigator = GetInstigator();

    SpawnParams.SpawnCollisionHandlingOverride = ESpawnActorCollisionHandlingMethod::AlwaysSpawn;

    AMyProjectile* SpawnedProjectile = GetWorld()->SpawnActor<AMyProjectile>(
        ProjectileClass,
        MuzzlePosition,
        ShootRotation,
        SpawnParams
    );

    if (MuzzleFlashEffect)
    {
        UNiagaraFunctionLibrary::SpawnSystemAttached(
            MuzzleFlashEffect,
            MuzzleLocation,
            NAME_None,
            FVector::ZeroVector,
            FRotator::ZeroRotator,
            EAttachLocation::KeepRelativeOffset,
            true
        );
    }

    if (FireSound)
    {
        UGameplayStatics::PlaySoundAtLocation(
            this,
            FireSound,
            MuzzleLocation->GetComponentLocation()
        );
    }

    --CurrentAmmo;

    UpdateAmmoHUD();

    if (CurrentAmmo <= 0)
    {
        StartReload();
    }
}
```

读完后先找到七段：前提判断、取得玩家和相机、建立射线、查询并选点、计算枪口方向、生成子弹、播放反馈并扣弹药。不要只盯着LineTrace一行；它的输入来自前面，输出服务于后面的出生旋转。

## 10. 本次枪口与命中特效怎样接入

### 10.1 新成员和Niagara模块

MyWeapon.h新增资源类型的前置声明，并在已有类的private区段保存：

MyProjectile.h新增：

UNiagaraSystem代表特效系统资产；UNiagaraFunctionLibrary提供生成特效的方法。USoundBase代表声音资源类型，不是已经在播放的声音实例。

当前Build.cs已在PublicDependencyModuleNames加入Niagara。相关.cpp包含NiagaraFunctionLibrary.h、NiagaraSystem.h；声音函数来自Kismet/GameplayStatics.h。模块依赖解决构建链接，include提供C++定义；仍需要在蓝图给对应资源属性赋值。

本项目已有Content/Effects/NS_MuzzleFlash与NS_Impact资产。可以分别核对武器和子弹蓝图Effects分类的对应属性；仅仅目录里存在资源，不会按名称自动赋给指针。

### 10.2 SpawnSystemAttached：枪焰挂到枪口

Fire调用SpawnSystemAttached时传入MuzzleFlashEffect、MuzzleLocation、NAME_None、零位置与零旋转、KeepRelativeOffset以及true。

| 参数 | 本次含义 |
| --- | --- |
| MuzzleFlashEffect | 要生成的Niagara系统资产 |
| MuzzleLocation | 附加到的组件 |
| NAME_None | 不额外指定命名插槽 |
| ZeroVector / ZeroRotator | 在父组件处不增加相对位置、旋转偏移 |
| KeepRelativeOffset | 使用这里给出的相对偏移 |
| true | bAutoDestroy：系统播放完成后自动销毁组件 |

这是依附枪口的效果，跟随父组件变换。bAutoDestroy不等于固定几秒结束；系统需要能播放完成，一次枪焰的Niagara资源应有相应的生命周期设置。当前未保存返回的NiagaraComponent来手动停止它。[SpawnSystemAttached 官方说明](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/Niagara/UNiagaraFunctionLibrary/SpawnSystemAttached?lang=en-US)

### 10.3 PlaySoundAtLocation：在这次枪口位置播放声音

FireSound非空时，调用PlaySoundAtLocation(this, FireSound, 枪口世界位置)。this用于提供世界上下文，声音位置是枪口。

这是在给定位置发起的一次播放，播放点不会自动跟着之后移动的枪。实际距离衰减取决于声音与衰减设置，不能仅凭这个函数名就认定所有声音资源都有相同的远近效果。[PlaySoundAtLocation 官方说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UGameplayStatics/PlaySoundAtLocation)

## 11. 子弹实际命中：伤害、命中标记与命中特效

### 11.1 当前完整命中回调

```cpp
void AMyProjectile::OnProjectileHit(
    UPrimitiveComponent* HitComponent,
    AActor* OtherActor,
    UPrimitiveComponent* OtherComponent,
    FVector NormalImpulse,
    const FHitResult& Hit
)
{

    if (AMyEnemyCharacter* Enemy = Cast<AMyEnemyCharacter>(OtherActor))
    {
        Enemy->TakeProjectileDamage(Damage);

        if (AMyArenaShooterCharacter* Player = Cast<AMyArenaShooterCharacter>(GetInstigator()))
        {
            Player->NotifyEnemyHit();
        }
    }

    if (ImpactEffect && Hit.bBlockingHit)
    {
        UNiagaraFunctionLibrary::SpawnSystemAtLocation(
            GetWorld(),
            ImpactEffect,
            Hit.ImpactPoint,
            Hit.ImpactNormal.Rotation()
        );
    }

    Destroy();
}
```

这里有三段顺序：Enemy则扣血并通知发射玩家 → 有资源且为阻挡命中则生成命中特效 → 销毁子弹。撞墙时不执行敌人伤害和Hit Marker，仍可能生成ImpactEffect并销毁。

敌人扣血归零后可能在受伤函数中Destroy。当前随后依靠子弹自己保存的Instigator通知玩家，不需要继续从已经销毁的Enemy查询HUD。

### 11.2 两个叫Hit的变量，属于不同事件

| Hit来自哪里 | 何时产生 | 当前读取什么 |
| --- | --- | --- |
| Weapon.Fire里的FHitResult Hit | 射击时的相机查询 | ImpactPoint，选定瞄准点 |
| OnProjectileHit参数const FHitResult& Hit | 子弹实际碰撞时的事件数据 | bBlockingHit、ImpactPoint、ImpactNormal，生成命中特效 |

它们只是同名，既不是共享变量，也没有把相机的Hit保存进子弹。当子弹飞行一段时间后撞墙，第二份Hit描述的就是那面墙，哪怕第一份Hit之前选中了Enemy。

### 11.3 ImpactPoint与ImpactNormal为什么用于命中特效

```cpp
UNiagaraFunctionLibrary::SpawnSystemAtLocation(
    GetWorld(),
    ImpactEffect,
    Hit.ImpactPoint,
    Hit.ImpactNormal.Rotation()
);
```

ImpactPoint是实际接触的世界位置；ImpactNormal是被撞表面朝外的法线方向。后者转成旋转，可以让资源按表面方向展开，而不是所有火花永远朝同一个世界方向。

例如正对玩家的墙面，表面法线可能朝回玩家；它与子弹飞向墙的方向并不是同一个向量。具体特效的喷射轴是否对应这个旋转，要结合Niagara资源自身的轴向设置。

当前用独立世界位置生成，未挂在子弹下面，所以随后Destroy子弹不等于把该效果当作子弹组件一起删除。未指定的缩放、自动激活与自动销毁等参数使用本地NiagaraFunctionLibrary.h的默认值。[Niagara生成API说明](https://dev.epicgames.com/documentation/unreal-engine/API/Plugins/Niagara/UNiagaraFunctionLibrary?lang=en-US)

子弹有半径5的球形碰撞。碰撞事件中的Location可表示球中心最终位置，ImpactPoint表示表面接触位置，二者可能不同；生成火花使用接触点更符合这次需求。

### 11.4 NotifyEnemyHit到Hit Marker

```text
Projectile实际撞到Enemy
→ Enemy.TakeProjectileDamage(Damage)
→ 从Projectile.GetInstigator取得发射者，Cast为自己的玩家角色
→ Player.NotifyEnemyHit
→ HUDWidget.ShowHitMarker
→ HitMarkerText显示
→ 0.15秒定时器到期，HideHitMarker隐藏
```

命中标记表达“这颗子弹实际碰到了Enemy”。当前不是相机选中Enemy就显示，也不区分普通命中与击杀。控件绑定、重复命中如何延长显示时间，以及玩家受伤闪红和受伤音效，在第4节本次后续记录中详细展开。

### 13.3 当前已知的实现范围

- 相机查询只用于选一个点，不锁定敌人，也不自动预判移动目标。
- 枪口仍有位置偏移；枪口路径上的近墙与动态遮挡可以使实际碰撞不同于相机查询。
- 当前生成策略为AlwaysSpawn，未通过它消除所有出生重叠或穿墙情况。
- SpawnedProjectile虽已保存，仍未作为特效与扣弹药的成功条件。
- 调试线默认关闭；Hit Marker来源于实际Enemy碰撞。

### 15.3 最新完整实际碰撞回调

```cpp
void AMyProjectile::OnProjectileHit(
    UPrimitiveComponent* HitComponent,
    AActor* OtherActor,
    UPrimitiveComponent* OtherComponent,
    FVector NormalImpulse,
    const FHitResult& Hit
)
{
    if (AMyEnemyCharacter* Enemy = Cast<AMyEnemyCharacter>(OtherActor))
    {
        if (IsValid(Enemy) && Enemy->TakeProjectileDamage(Damage))
        {
            if (AMyArenaShooterCharacter* Player = Cast<AMyArenaShooterCharacter>(GetInstigator()))
            {
                Player->NotifyEnemyHit();
            }
        }
    }

    if (ImpactEffect && Hit.bBlockingHit)
    {
        UNiagaraFunctionLibrary::SpawnSystemAtLocation(
            GetWorld(),
            ImpactEffect,
            Hit.ImpactPoint,
            Hit.ImpactNormal.Rotation()
        );
    }

    if (ImpactSound && Hit.bBlockingHit)
    {
        UGameplayStatics::PlaySoundAtLocation(
            this,
            ImpactSound,
            Hit.ImpactPoint
        );
    }

    Destroy();
}
```

这一版相比第11节的阶段代码有两个变化：

1. `TakeProjectileDamage` 返回bool，只有引用有效且返回true才通知玩家命中标记。
2. `ImpactSound` 在实际阻挡接触点播放，与命中特效一起位于子弹销毁之前。

`TakeProjectileDamage` 的true表示接受了伤害，致死伤害也包含在内；false表示拒绝这次伤害。它没有回答“是否击杀”。详细条件见第3节本次追加记录。

```text
实际撞到Enemy
    → Enemy有效且接受伤害？
        是：通知玩家Hit Marker
        否：跳过Hit Marker
    → ImpactEffect已配置且为阻挡命中：生成接触特效
    → ImpactSound已配置且为阻挡命中：播放接触声音
    → Destroy子弹
```

特效与声音使用的是碰撞回调中的 `Hit.ImpactPoint`，不会改用相机之前算出的 `AimPoint`。相机看到的点与实际接触点仍可能不同，例如枪口路径被近处障碍挡住。

源码把ImpactSound附近注释写成“添加开枪声音”，实际调用发生在子弹碰撞回调，位置也是命中点，故应按命中声音理解。`ImpactSound` 是子弹的 `EditDefaultsOnly` 资源属性，需要在相应子弹蓝图中指定声音。

### 15.4 从最后一发命中继续连接到胜利

```text
相机选点 → 枪口方向 → 成功生成子弹
    → 子弹飞行 → 实际碰撞Enemy
    → Enemy接受伤害并归零 → 请求销毁Enemy
    → 命中标记、接触特效/声音 → 请求销毁子弹
    → Spawner后续清理失效Enemy引用
    → 本波数组清空 → 推进波次索引
    → 全部波次完成 → Player.WinGame
    → StopFire → 禁用移动 → ShowVictory
```

这不是把胜利判断塞进相机射线或某一颗子弹中。子弹负责一次碰撞，Enemy负责自己生命值，Spawner结合所有波次判断完成，玩家记录胜利并通知HUD。第6节《胜负状态与重新开始》详细记录了最后这段链以及重开地图。
