这节记录我第一次使用 UE 5.4 和 C++ 制作第一人称角色的过程：创建 Character、GameMode 和相机，再通过增强输入实现 WASD 移动。

完成后的目标是：点击 Play，地图生成 `BP_MyArenaShooterCharacter`，玩家通过角色的相机观察场景，并能使用 WASD 移动。鼠标转向、跳跃、武器和人物模型留到后面实现。

## 1. 创建 Character 类

在编辑器中创建继承自 `Character` 的 C++ 类，命名为 `MyArenaShooterCharacter`。生成的 C++ 类名是 `AMyArenaShooterCharacter`。

```text
AActor
  ↓
APawn
  ↓
ACharacter
  ↓
AMyArenaShooterCharacter
```

- `AActor`：可以放进场景的对象基类。
- `APawn`：可以被 Controller 控制的对象，例如人物、车辆、飞机。
- `ACharacter`：带有角色移动功能的 Pawn，自带胶囊体、骨骼网格体组件和角色移动组件。
- `AMyArenaShooterCharacter`：我自己写的角色类，在已有功能上增加相机和输入逻辑。

这里的 `A` 是 UE 对 Actor 派生类的命名前缀。后面出现的 `UCameraComponent`、`UInputAction` 等 UObject 类型使用 `U` 前缀。

### 1.1 角色中几个常见函数的职责

| 函数 | 本节中的用途 |
| --- | --- |
| 构造函数 | 创建相机组件，设置默认属性 |
| `BeginPlay()` | 游戏开始时，为本地玩家添加输入映射上下文 |
| `Tick()` | 每帧执行；本节还没有需要放进去的逻辑 |
| `SetupPlayerInputComponent()` | 将输入操作绑定到角色的处理函数 |
| `Move()` | 读取移动输入，向角色移动系统提交移动方向 |

这些函数的职责不能当成一条固定的调用顺序。特别是 `BeginPlay()` 和输入初始化的先后，可能随角色生成、控制器接管方式而变化。

`Super::BeginPlay()`、`Super::SetupPlayerInputComponent(...)` 表示先执行父类的对应实现，让父类完成它自己的初始化。

### 1.2 角色类、角色蓝图和角色实例

第一次学习时，这三个东西容易混在一起：

```text
AMyArenaShooterCharacter：C++ 类，定义组件和功能
        ↓ 作为父类
BP_MyArenaShooterCharacter：角色蓝图，保存本项目的默认配置
        ↓ 游戏运行时生成
BP_MyArenaShooterCharacter_C_0：地图里的一个角色实例
```

C++ 类可以理解为基础设计，蓝图在这个设计上指定资源，例如输入资产和以后的人物模型。Play 时，GameMode 根据指定的角色类生成实例，再由 PlayerController 接管它。

**把蓝图放在内容浏览器里，不等于地图已经生成了这个角色。**

## 2. 创建 GameMode 类

本项目创建继承自 `GameModeBase` 的 C++ 类，命名为 `MyArenaShooterGameMode`，对应 `AMyArenaShooterGameMode`。

GameMode 用来定义一局游戏的规则和默认类。本节首先用它指定玩家出生时生成哪一种角色。

| 配置或职责 | 用途 |
| --- | --- |
| `DefaultPawnClass` | 默认生成的玩家角色类 |
| `PlayerControllerClass` | 使用哪一种玩家控制器 |
| `HUDClass` | 使用哪一种 HUD |
| `GameStateClass` | 使用哪一种游戏状态类 |
| 玩家出生、重生 | 决定何时、在哪里生成角色 |
| 胜负规则 | 例如先达到 20 次击杀的一方获胜 |

多人游戏中的 GameMode 实例只存在于服务器端，需要向客户端同步的比赛状态通常放在 GameState 中。本节先做单人移动，不展开网络部分。

**增强输入处理玩家的操作；GameMode 配置角色的生成。** 创建好输入资产以后，还需要把默认 Pawn 指向配置了这些资产的角色蓝图。具体配置放在第 5 节。

## 3. 给 Character 创建相机组件

### 3.1 在头文件中声明相机

在 `MyArenaShooterCharacter.h` 中前置声明组件类型：

```cpp
class UCameraComponent;
```

然后在角色类内部声明属性：

```cpp
private:
    UPROPERTY(VisibleAnywhere, Category = "Camera")
    UCameraComponent* FirstPersonCameraComponent = nullptr;
```

`UCameraComponent*` 是一个指向相机组件的指针。**声明指针本身不会创建相机**，还需要在构造函数中创建组件。

`nullptr` 表示指针暂时没有指向任何对象。

`UPROPERTY` 让 UE 的反射系统认识这个属性。这里的 `VisibleAnywhere` 允许在编辑器中查看这个组件引用，但不能随意把引用替换成另一个组件；组件自身的可编辑参数仍然可以在细节面板中调整。

### 3.2 在构造函数中创建相机

在 `MyArenaShooterCharacter.cpp` 中包含需要使用的组件定义：

```cpp
#include "Camera/CameraComponent.h"
#include "Components/CapsuleComponent.h"
```

构造函数中的代码：

```cpp
AMyArenaShooterCharacter::AMyArenaShooterCharacter()
{
    PrimaryActorTick.bCanEverTick = true;

    FirstPersonCameraComponent =
        CreateDefaultSubobject<UCameraComponent>(TEXT("FirstPersonCamera"));

    FirstPersonCameraComponent->SetupAttachment(GetCapsuleComponent());
    FirstPersonCameraComponent->SetRelativeLocation(
        FVector(-10.0f, 0.0f, 60.0f)
    );
    FirstPersonCameraComponent->bUsePawnControlRotation = true;
}
```

逐句理解：

| 代码 | 含义 |
| --- | --- |
| `PrimaryActorTick.bCanEverTick = true` | 允许这个 Actor 执行 Tick；WASD 移动本身不需要我在 Tick 中重复处理 |
| `CreateDefaultSubobject<UCameraComponent>(...)` | 创建角色的默认相机组件 |
| `TEXT("FirstPersonCamera")` | 指定组件的内部名称；`TEXT` 用于构造 UE 使用的字符字面量 |
| `SetupAttachment(GetCapsuleComponent())` | 把相机挂到角色的胶囊体组件上 |
| `SetRelativeLocation(...)` | 设置相机相对于父组件的位置 |
| `bUsePawnControlRotation = true` | 让相机使用 Pawn 的控制朝向，为后面的鼠标视角控制做准备 |

UE 默认长度单位是厘米。这里的 `X = -10`、`Y = 0`、`Z = 60` 是相对于胶囊体的位置，大致把相机抬到头部附近，并稍微后移。

```text
角色的 Capsule Component（胶囊体）
├─ Mesh（骨骼网格体组件）
└─ FirstPersonCamera（我添加的相机）

CharacterMovement Component 负责角色移动
```

胶囊体移动时，挂在下面的相机也跟着移动。`bUsePawnControlRotation` 不会自动实现鼠标转向；后面仍然要绑定 Look 输入，并更新控制器旋转。

## 4. 使用增强输入实现 WASD 移动

### 4.1 先理解完整的数据流

```text
W / A / S / D
      ↓
IMC_Player：把按键映射到 IA_Move，并转换轴值
      ↓
IA_Move：得到一个二维移动输入
      ↓
BindAction：将这个操作的 Triggered 事件绑定到 Move()
      ↓
Move()：读取 X、Y，计算世界中的移动方向
      ↓
AddMovementInput()：提交移动输入
      ↓
CharacterMovementComponent：处理速度、碰撞、重力等
      ↓
角色移动
```

本节涉及几个不同的概念：

| 名称                                    | 本项目中的对象        | 可以先这样理解               |
| ------------------------------------- | -------------- | --------------------- |
| Input Action                          | `IA_Move`      | 定义“移动”这个操作，以及它输出的数据类型 |
| Input Mapping Context                 | `IMC_Player`   | 规定哪些按键触发操作，以及如何转换输入值  |
| Input Modifier                        | Negate、Swizzle | 在输入到达处理函数前，调整输入值      |
| Input Trigger                         | 本节使用默认触发行为     | 决定输入何时被视为触发，例如长按、连按   |
| Enhanced Input Component              | 角色的输入组件        | 把操作事件绑定到 C++ 函数       |
| Enhanced Input Local Player Subsystem | 本地玩家的输入子系统     | 管理当前玩家启用的输入映射上下文      |

`IA_`、`IMC_` 是帮助识别资产用途的命名习惯，资产叫什么不会自动绑定到同名 C++ 变量。

### 4.2 检查插件、模块依赖和输入类

在编辑器的插件列表中确认 **Enhanced Input（增强输入）** 已启用。

在 `MyArenaShooter.Build.cs` 中加入模块依赖。本项目已经包含：

```csharp
PublicDependencyModuleNames.AddRange(new string[]
{
    "Core",
    "CoreUObject",
    "Engine",
    "InputCore",
    "EnhancedInput"
});
```

插件提供增强输入功能，模块依赖让我的 C++ 模块能够使用它的类型和函数。

在 **项目设置 → 输入 → 默认类** 中确认：

- Default Player Input Class：`EnhancedPlayerInput`。
- Default Input Component Class：`EnhancedInputComponent`。

对应的 `Config/DefaultInput.ini` 配置是：

```ini
[/Script/Engine.InputSettings]
DefaultPlayerInputClass=/Script/EnhancedInput.EnhancedPlayerInput
DefaultInputComponentClass=/Script/EnhancedInput.EnhancedInputComponent
```

编辑器名称可能随界面语言不同而变化，可以用英文名称辅助查找。

### 4.3 创建 IA_Move

在 `Content/Input` 中创建 **Input Action** 资产，命名为 `IA_Move`。

打开它，将 **Value Type（值类型）** 设置为 **Axis2D / Vector2D**，然后保存。

这里选择二维输入，是因为移动需要同时表示两个方向：

```text
输入 X：左右，A / D
输入 Y：前后，W / S
```

单独按一个键时，希望得到：

| 按键 | 输入向量 `(X, Y)` | 角色移动方向 |
| --- | --- | --- |
| W | `(0, 1)` | 向前 |
| S | `(0, -1)` | 向后 |
| A | `(-1, 0)` | 向左 |
| D | `(1, 0)` | 向右 |

**这个 X、Y 是输入空间中的轴，不直接等于 UE 世界坐标的 X、Y。** 后面的 `Move()` 会把它转换成角色的前方向和右方向。

### 4.4 创建 IMC_Player，并设置按键与 Modifier

在同一个目录创建 **Input Mapping Context**，命名为 `IMC_Player`。

打开它，添加四条映射，四条都选择同一个 `IA_Move`，按键分别选择 W、A、S、D。

键盘单个按键的输入可以先理解成：按下时向 X 轴提供 `1`。要得到前面的二维向量，需要使用 Modifier 转换。

| 按键 | Modifiers 设置 | 处理结果 |
| --- | --- | --- |
| D | 不添加 | `(1, 0)` |
| A | `Negate`，反转 X 轴 | `(-1, 0)` |
| W | `Swizzle Input Axis Values`，Order 选择 `YXZ` | `(0, 1)` |
| S | 先 `Negate`，再 `Swizzle Input Axis Values`，Order 选择 `YXZ` | `(0, -1)` |

`Negate` 是取反：把 `1` 变成 `-1`。这里可以保留默认取反轴设置，只要 X 轴取反已经启用。

`Swizzle Input Axis Values` 是交换轴的位置。选择 `YXZ` 后，可以把键盘原本放在 X 轴上的值转到 Y 轴。

例如 S 的转换过程：

```text
按下 S
  ↓
原始值 (1, 0)
  ↓ Negate
(-1, 0)
  ↓ Swizzle，YXZ
(0, -1)
```

本节使用普通的按住移动，不需要额外添加长按或连按 Trigger。完成映射后保存资产。这个设置方式也可以对照 [Epic 的增强输入说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/enhanced-input?application_version=5.4)。

### 4.5 在角色头文件中声明输入属性和函数

在 `MyArenaShooterCharacter.h` 中加入前置声明：

```cpp
class UInputMappingContext;
class UInputAction;
struct FInputActionValue;
```

前置声明先告诉编译器“存在这些类型”。头文件目前只保存它们的指针或声明引用参数，类型的具体定义可以在 `.cpp` 中通过 `#include` 引入。`MyArenaShooterCharacter.generated.h` 仍然应放在头文件的最后一个 `#include` 位置。

以下属性和函数声明放在已有的 `AMyArenaShooterCharacter` 类内部，不需要再创建一个类：

```cpp
private:
    UPROPERTY(EditDefaultsOnly, Category = "Input")
    UInputMappingContext* DefaultMappingContext = nullptr;

    UPROPERTY(EditDefaultsOnly, Category = "Input")
    UInputAction* MoveAction = nullptr;

public:
    void Move(const FInputActionValue& Value);
```

对应关系：

| C++ 成员 | 在蓝图中指定的内容 |
| --- | --- |
| `DefaultMappingContext` | `IMC_Player` |
| `MoveAction` | `IA_Move` |
| `Move()` | 输入触发后执行的 C++ 函数，无需在蓝图中填写 |

这里还需要使用角色类里已有的两个函数声明：

```cpp
protected:
    virtual void BeginPlay() override;

public:
    virtual void SetupPlayerInputComponent(
        UInputComponent* PlayerInputComponent
    ) override;
```

`override` 表示重写父类的虚函数，也让编译器检查我是否写对了函数签名。如果这些声明已经存在，就修改对应实现，不要重复声明或定义。

`EditDefaultsOnly` 表示在类默认值中编辑，所以应打开角色蓝图的 **Class Defaults（类默认值）** 配置资产。`Category = "Input"` 只是细节面板中的分类，并不会自动启用输入。

`private` 控制 C++ 中的访问权限。当前声明不使用 `BlueprintReadOnly`，但仍可通过 `EditDefaultsOnly` 在细节面板配置；它不因此自动变成蓝图事件图中可读取的变量。

如果以后想在蓝图事件图中读取这个私有属性，可以增加 `BlueprintReadOnly` 和 `meta = (AllowPrivateAccess = "true")`。本节只在蓝图里指定资产，不需要为了显示属性额外增加它们。

### 4.6 在 BeginPlay 中启用输入映射

在 `MyArenaShooterCharacter.cpp` 中增加头文件：

```cpp
#include "EnhancedInputComponent.h"
#include "EnhancedInputSubsystems.h"
#include "InputActionValue.h"
#include "GameFramework/PlayerController.h"
```

当前项目的 `BeginPlay()` 实现：

```cpp
void AMyArenaShooterCharacter::BeginPlay()
{
    Super::BeginPlay();

    if (APlayerController* PlayerController = Cast<APlayerController>(Controller))
    {
        if (UEnhancedInputLocalPlayerSubsystem* Subsystem =
            ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(
                PlayerController->GetLocalPlayer()
            ))
        {
            if (DefaultMappingContext)
            {
                Subsystem->AddMappingContext(DefaultMappingContext, 0);
            }
        }
    }
}
```

逐层理解：

1. `Controller` 是当前控制这个角色的控制器。
2. `Cast<APlayerController>(Controller)` 尝试取得玩家控制器；类型不匹配或没有控制器时，结果为空。
3. `GetLocalPlayer()` 取得对应的本地玩家。
4. `GetSubsystem<...>()` 取得该本地玩家的增强输入子系统。
5. `if (DefaultMappingContext)` 检查蓝图是否已经指定了映射资产。
6. `AddMappingContext(DefaultMappingContext, 0)` 启用 `IMC_Player`；第二个参数 `0` 是优先级，多个上下文竞争同一输入时优先级会参与处理。

**创建并保存 IMC 资产，并不代表它已经对玩家生效。** 还必须将它添加到本地玩家的子系统中。

本节的实现用于目前的本地玩家角色初始化流程。如果以后增加联机、运行时换角色或较晚才接管的 Pawn，要重新检查控制器何时可用，不能假定所有角色都在 `BeginPlay()` 时已经被玩家控制。

### 4.7 在 SetupPlayerInputComponent 中绑定操作

```cpp
void AMyArenaShooterCharacter::SetupPlayerInputComponent(
    UInputComponent* PlayerInputComponent
)
{
    Super::SetupPlayerInputComponent(PlayerInputComponent);

    if (UEnhancedInputComponent* EnhancedInputComponent =
        Cast<UEnhancedInputComponent>(PlayerInputComponent))
    {
        if (MoveAction)
        {
            EnhancedInputComponent->BindAction(
                MoveAction,
                ETriggerEvent::Triggered,
                this,
                &AMyArenaShooterCharacter::Move
            );
        }
    }
}
```

`BindAction` 的参数可以这样读：

```text
MoveAction                         → 监听哪个操作：IA_Move
ETriggerEvent::Triggered            → 监听该操作的触发状态
this                               → 在当前角色对象上调用
&AMyArenaShooterCharacter::Move      → 调用哪个成员函数：Move()
```

普通移动操作使用默认触发行为时，按住按键会持续产生 `Triggered` 事件，因此可以持续提交移动输入。`Started` 主要表示操作开始的时刻，不能把它当作持续移动的逐帧回调。

`this` 是当前角色对象的指针；`&AMyArenaShooterCharacter::Move` 是成员函数指针，用来告诉输入系统稍后调用哪个函数。这里不是立即执行一次 `Move()`。

**添加 Mapping Context 和绑定 Action 要分别完成：前者让按键映射生效，后者让输入操作调用我的函数。**

### 4.8 在 Move 中读取轴值并提交移动输入

```cpp
void AMyArenaShooterCharacter::Move(const FInputActionValue& Value)
{
    FVector2D MovementVector = Value.Get<FVector2D>();

    AddMovementInput(
        GetActorForwardVector(),
        MovementVector.Y
    );

    AddMovementInput(
        GetActorRightVector(),
        MovementVector.X
    );
}
```

`const FInputActionValue& Value` 是输入系统传来的操作值。`&` 表示通过引用传递，`const` 表示函数不会通过这个参数修改原值。

`Value.Get<FVector2D>()` 按二维向量读取输入，所以 `IA_Move` 的 Value Type 必须设置为 Axis2D，与代码中的读取类型一致。

| 代码 | 作用 |
| --- | --- |
| `GetActorForwardVector()` | 角色在世界中的前方向 |
| `MovementVector.Y` | 前后输入的大小和正负 |
| `GetActorRightVector()` | 角色在世界中的右方向 |
| `MovementVector.X` | 左右输入的大小和正负 |

例如按 W，收到 `(0, 1)`，相当于沿角色前方向提交 `+1` 的移动输入。按 A，收到 `(-1, 0)`，相当于沿角色右方向提交 `-1` 的移动输入，也就是向左移动。

`AddMovementInput()` 的第一个参数是世界中的方向，第二个参数是输入缩放值。它提交的是移动意图，CharacterMovementComponent 再根据速度、加速度、碰撞等处理实际位移。

因此这里不需要手动改角色位置，也不需要额外乘一次 `DeltaTime`。第二个参数的 `1` 也不是“直接移动 1 厘米”。

当前代码按角色 Actor 的朝向移动。以后实现鼠标转向时，要保证角色朝向与控制朝向的关系符合设计；如果要按控制器的水平朝向移动，可以再改成根据 Controller 的 Yaw 计算方向。

## 5. 配置角色蓝图，并让 GameMode 生成它

### 5.1 创建并配置角色蓝图

根据 `AMyArenaShooterCharacter` 创建蓝图，命名为 `BP_MyArenaShooterCharacter`。本项目资产路径是：

```text
Content/BluePrints/BP_MyArenaShooterCharacter.uasset
```

打开蓝图，确认父类为 `MyArenaShooterCharacter`，点击 **类默认值**，配置：

| 属性 | 指定资产 |
| --- | --- |
| Default Mapping Context | `IMC_Player` |
| Move Action | `IA_Move` |

中文界面可能把 `Input` 分类显示成“输入”。可以先清空细节面板的搜索框，或搜索 `Default`、`Move` 查找具体属性。完成后编译并保存蓝图。

这个蓝图的“纯数据蓝图”提示是正常的：它目前主要保存组件和属性配置，没有添加事件图逻辑。

### 5.2 为什么 DefaultPawnClass 要指向蓝图

最初可以这样让 GameMode 使用 C++ 角色类：

```cpp
DefaultPawnClass = AMyArenaShooterCharacter::StaticClass();
```

但本节是在 `BP_MyArenaShooterCharacter` 中指定 `IMC_Player` 和 `IA_Move`。直接生成 C++ 基类，不会自动取得派生蓝图里保存的默认值；这里的两个输入指针在 C++ 中仍然默认为空。

因此，要让 GameMode 生成这个已经配置好输入的蓝图类。

`MyArenaShooterGameMode.cpp` 当前实现：

```cpp
#include "MyArenaShooterGameMode.h"
#include "UObject/ConstructorHelpers.h"

AMyArenaShooterGameMode::AMyArenaShooterGameMode()
{
    static ConstructorHelpers::FClassFinder<APawn> PlayerPawnClassFinder(
        TEXT("/Game/BluePrints/BP_MyArenaShooterCharacter")
    );

    if (PlayerPawnClassFinder.Class)
    {
        DefaultPawnClass = PlayerPawnClassFinder.Class;
    }
}
```

`FClassFinder<APawn>` 根据资产路径查找 Pawn 派生类。找到蓝图生成的类后，把它赋给 `DefaultPawnClass`，作为默认玩家角色。

注意路径的写法：

```text
磁盘：Content/BluePrints/BP_MyArenaShooterCharacter.uasset
UE：  /Game/BluePrints/BP_MyArenaShooterCharacter
```

`/Game` 对应项目的 `Content` 内容根目录。不能遗漏开头的 `/`，目录拼写也应与实际资产一致。这里的 `FClassFinder` 支持直接填写蓝图资产路径，不需要加 `.uasset`。

`DefaultPawnClass` 保存的是“角色类”，不是一个已经生成的角色实例。

### 5.3 项目与地图的 GameMode 配置

在 **项目设置 → 地图和模式（Maps & Modes）** 中，将默认 GameMode 设置为 `MyArenaShooterGameMode`。

对应的 `Config/DefaultEngine.ini` 配置项：

```ini
[/Script/EngineSettings.GameMapsSettings]
GlobalDefaultGameMode=/Script/MyArenaShooter.MyArenaShooterGameMode
```

这是现有配置节中的一项，不需要重复创建相同配置节，也不用删除已有的地图配置。

打开当前地图的 **世界设置（World Settings）**，检查 **GameMode Override**：

- 设为 `None` 时，使用项目默认 GameMode。
- 指定某个 GameMode 时，当前地图使用该覆盖设置。

本项目的 `Test` 地图已经指定 `MyArenaShooterGameMode`。如果创建新地图，也要注意它的覆盖设置。项目默认地图与默认 GameMode 是两个不同的配置，不能互相代替。具体入口可参考 [Epic 的 GameMode 配置说明](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-a-game-mode-in-unreal-engine?application_version=5.4)。

### 5.4 放置 PlayerStart，再验证生成结果

在地图里放置 PlayerStart，让出生位置位于地面上方，避免胶囊体与地面或墙体重叠。

本节使用 GameMode 自动生成角色，测试时不需要再手动向地图拖入第二个角色蓝图，否则可能出现两个角色，让排查变得混乱。

正常 Play 时，可以在运行中的场景大纲里查找：

```text
BP_MyArenaShooterCharacter
```

运行时名称可能带有 `_C_0` 等后缀，完整编号不必完全一致。

相机和碰撞体可以在没有人物模型的情况下工作。`ACharacter` 自带 Mesh 组件，但它不会自动带上一个可见的人物模型；第一人称看不到身体，也不能直接判定角色没生成。

## 6. 这次遇到的问题与排查记录

### 6.1 在细节面板中找不到两个输入变量

现象：声明了 `DefaultMappingContext` 和 `MoveAction`，但搜索 `Input` 时没有看到它们。

排查顺序：

1. 确认打开的是 `BP_MyArenaShooterCharacter`，父类正确。
2. 点击 **类默认值**；两个属性使用 `EditDefaultsOnly`，不能只看关卡实例。
3. 清空搜索，或搜索具体属性名 `Default`、`Move`。
4. 中文界面将顶层 `Input` 分类显示成“输入”，英文搜索可能过滤掉它们。
5. 确认 C++ 修改已经编译并被编辑器加载，再检查是否有额外过滤选项。

本次在“输入”分类中找到了这两个属性，最终指定为 `IMC_Player` 和 `IA_Move`。**无需为了这个显示问题把属性改成 `EditAnywhere`。**

下面的 `Pawn → Input` 是另一个子分类，不代表我写的 `Category = "Input"` 一定会显示在那里。

### 6.2 Play 时场景大纲里没有角色蓝图

本次发现的问题：

- GameMode 中的路径曾写成 `Game/Blueprints/...`，遗漏 `/`，也没有沿用实际目录 `BluePrints` 的拼写。
- GameMode 构造函数修改之后尚未完成新的完整编译，运行中的编辑器没有使用这次修改。
- 项目默认 GameMode 未指定；不同地图可能使用不同 GameMode，不能只确认某一张地图。

处理方法：修正资源路径，设置默认 GameMode，保存资产并关闭编辑器，完整构建 `MyArenaShooterEditor / Win64 / Development`，再重新打开项目。

验证结果：完整编译通过，随后启动 `Test` 地图，运行日志中确认生成了 `BP_MyArenaShooterCharacter_C_0`。

Live Coding 可以用于许多代码迭代，但遇到构造函数默认值、反射属性等修改后，已经存在的对象和默认对象不一定完全按新配置更新。这类问题先用关闭编辑器、完整编译、重新打开来确认，不要把蓝图上的“编译”按钮当作 C++ 项目的完整构建。

### 6.3 如果角色已经生成，但 WASD 仍然不生效

按数据经过的顺序检查，比同时修改多个地方容易定位：

| 检查位置 | 要确认的内容 |
| --- | --- |
| Play 模式 | 使用正常 Play，点击游戏视口让它取得键盘焦点；仅 Simulate 时不会按同样方式接管玩家角色 |
| 角色与控制器 | 玩家实际控制的是 `BP_MyArenaShooterCharacter`，不是另一个 Pawn |
| 蓝图默认值 | 两个输入资产已指定、编译、保存 |
| `BeginPlay()` | 成功取得本地玩家子系统，并添加 `IMC_Player` |
| `SetupPlayerInputComponent()` | 输入组件转换为 `UEnhancedInputComponent` 成功，并绑定 `IA_Move` |
| `IA_Move` | Value Type 为 Axis2D |
| `IMC_Player` | 四条映射使用同一个 `IA_Move`，Modifier 正确 |
| `Move()` | 函数被调用，读取到正确的 X、Y |
| 角色移动 | 没有被碰撞卡住，CharacterMovement 的移动模式和速度设置正常 |

需要定位输入值时，可以临时在 `Move()` 中加入日志：

```cpp
UE_LOG(LogTemp, Log, TEXT("Move: X=%.2f, Y=%.2f"),
    MovementVector.X, MovementVector.Y);
```

在输出日志中观察 W、A、S、D 对应的数值。持续按住按键会反复输出，确认后删掉这段临时日志。

- 没有日志：先排查输入是否启用、是否绑定、角色是否被接管。
- 有日志但数值方向不对：检查 IMC 的按键和 Modifier。
- 有正确日志但角色不动：再检查移动组件、移动模式与碰撞。
