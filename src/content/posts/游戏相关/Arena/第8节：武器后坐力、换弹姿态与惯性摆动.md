本节记录最新 `AMyWeapon` 的表现层代码。原来的单发、连射、弹药、换弹计时和相机选点继续使用；新增的是用武器网格的相对位置/旋转表现后坐力与换弹，并计算相机转动引起的惯性摆动目标。

当前代码里，后坐力已经累加并应用、换弹姿态已经按进度应用，但**后坐力回零和摆动写回尚未接通**。下文先按当前实现解释，再单列补全思路，避免把声明了参数当成已经生效。完整函数省略注释，逻辑与源码一致。

## 1. 先分清改变的是哪个组件

当前结构与挂接关系：

```text
玩家FirstPersonCameraComponent
    └─ Weapon Actor的Root
         └─ WeaponMesh
              └─ MuzzleLocation
```

玩家仍把Weapon挂到相机，并给Weapon Actor设置相对偏移 `(30, 10, -10)`。这次Tick改变的是 **WeaponMesh相对于Root的变换**，不是覆盖Weapon Actor的相机挂接偏移。

因此分三层读坐标：

| 层次 | 谁控制 | 本次用途 |
| --- | --- | --- |
| Weapon Actor相对相机 | 玩家BeginPlay | 武器总体摆放 |
| WeaponMesh相对Root | 武器Tick | 后退、上抬、换弹下沉与倾斜 |
| MuzzleLocation相对WeaponMesh | 组件/蓝图配置 | 枪口位置，随父组件变换到世界坐标 |

本次没有调用 `AddControllerPitchInput()` 制造相机后坐力，也没有修改子弹为散射。网格上抬属于武器表现；射击仍以相机查询选点，再从实际枪口位置计算方向。

## 2. BeginPlay保存原本的相对变换

源码位置：`Source/MyArenaShooter/Private/MyWeapon.cpp:25`。

```cpp
void AMyWeapon::BeginPlay()
{
    Super::BeginPlay();

    CurrentAmmo = MagazineSize;
    ReserveAmmo = StartingReserveAmmo;

    DefaultMeshLocation = WeaponMesh->GetRelativeLocation();
    DefaultMeshRotation = WeaponMesh->GetRelativeRotation();
}
```

`GetRelativeLocation()`、`GetRelativeRotation()` 取的是相对于父组件的变换。保存为 `DefaultMeshLocation` 与 `DefaultMeshRotation`，后续每帧都从同一个基准加偏移。

如果每帧把偏移加到上一帧已经偏移过的位置上，即使当前效果值没有增加，位置也会持续漂移。当前思路是：

```text
当前最终变换 = 固定初始变换 + 当前效果偏移
```

基准不是一定为零。若蓝图已调整WeaponMesh位置和旋转，BeginPlay会保存运行时取得的值，后续效果在它上面叠加。

## 3. 参数怎样分成“配置”与“运行时状态”

| 参数组 | C++默认值 | 用途与当前情况 |
| --- | --- | --- |
| RecoilBackDistance / RecoilPitchPerShot | 3 / 2 | 每次成功取得子弹实例后增加的后退距离、上抬角度 |
| MaxRecoilBack / MaxRecoilPitch | 8 / 8 | 后坐力状态的上限 |
| RecoilRecoverySpeed | 12 | 已声明，当前没有参与回零计算 |
| CurrentRecoilBack / CurrentRecoilPitch | 0 / 0 | 后坐力当前累计状态，Fire增加、Tick读取 |
| SwaySensitivity / MaxSwayAngle | 0.015 / 3 | 角速度转摆动目标的比例与角度上限 |
| SwayInterpSpeed | 10 | 已声明，当前未用于插值 |
| CurrentSwayYaw / CurrentSwayPitch | 0 / 0 | Tick用于最终旋转，但当前没有更新赋值链 |
| ReloadLowerDistance / ReloadTiltAngle | 15 / 25 | 换弹最大下沉距离、Roll倾斜角 |
| ReloadElapsed | 0 | 当前换弹表现经过的时间 |
| LastCameraRotation / bHasLastCameraRotation | 零旋转 / false | 记录上一帧视角并判断是否已有历史样本 |

可编辑配置使用 `EditDefaultsOnly`，实际蓝图可能覆盖这些默认值。`Current...`、`ReloadElapsed`等是运行时变量，配置值相同也可以因为当前状态不同而显示不同姿态。

武器换弹标志这次统一拼写为 `bIsReloading`。旧学习阶段里的 `bIsReoloading` 原文保留，是当时的拼写；读最新源码时使用新名称。

## 4. Fire成功后积累后坐力

源码位置：`Source/MyArenaShooter/Private/MyWeapon.cpp:247`。

在生成检查通过后，本次新增：

```cpp
CurrentRecoilBack = FMath::Min(
    CurrentRecoilBack + RecoilBackDistance,
    MaxRecoilBack
);
CurrentRecoilPitch = FMath::Min(
    CurrentRecoilPitch + RecoilPitchPerShot,
    MaxRecoilPitch
);
```

`FMath::Min` 在“原值加本次增量”与“上限”之间取较小值。默认配置下：

```text
成功第1发：后退3，上抬2
成功第2发：后退6，上抬4
成功第3发：后退8，上抬6
成功第4发：后退8，上抬8
之后继续射击：都保持在上限8
```

由于当前没有回零赋值，松开开火键后它们不会自动恢复为0。`RecoilRecoverySpeed`存在，也不能让变量自行减少。

完整发射链的新增位置是：

```text
Fire检查换弹、弹药与资源
    → 相机选点 → 枪口方向
    → SpawnActor → IsValid检查
    → 增加CurrentRecoilBack / Pitch
    → 枪口特效与声音
    → 扣弹药与HUD更新
    → 后续Tick把后坐力状态写入网格变换
```

这里累加的是可用子弹实例后的效果值，未播放动画蒙太奇。第7节敌人使用Montage，本节武器使用数值驱动组件变换，是两种实现方式。

## 5. Tick先读状态，再统一写最终变换

源码位置：`Source/MyArenaShooter/Private/MyWeapon.cpp:36`。

```cpp
void AMyWeapon::Tick(float DeltaTime)
{
    Super::Tick(DeltaTime);

    FireCooldown -= DeltaTime;

    if (FireCooldown < 0.0f)
    {
        FireCooldown = 0.0f;
    }

    if (bFirePressed && !bIsReloading && FireCooldown <= 0.0f)
    {
        Fire();

        FireCooldown = FireInterval;
    }

    float ReloadAlpha = 0.0f;
    if (bIsReloading)
    {
        ReloadElapsed += DeltaTime;

        float ReloadProgress = FMath::Clamp(
            ReloadElapsed / FMath::Max(ReloadTime, 0.01f),
            0.0f,
            1.0f
        );

        ReloadAlpha = FMath::Sin(ReloadProgress * PI);
    }

    float TargetSwayYaw = 0.0f;
    float TargetSwayPitch = 0.0f;

    AMyArenaShooterCharacter* Player = Cast<AMyArenaShooterCharacter>(GetOwner());
    if (IsValid(Player))
    {
        UCameraComponent* Camera = Player->GetFirstPersonCameraComponent();
        if (IsValid(Camera))
        {
            FRotator CameraRotation = Camera->GetComponentRotation();

            if (bHasLastCameraRotation && DeltaTime > SMALL_NUMBER)
            {
                float YawSpeed = FMath::FindDeltaAngleDegrees(
                    LastCameraRotation.Yaw,
                    CameraRotation.Yaw
                ) / DeltaTime;

                float PitchSpeed = FMath::FindDeltaAngleDegrees(
                    LastCameraRotation.Pitch,
                    CameraRotation.Pitch
                ) / DeltaTime;

                TargetSwayPitch = FMath::Clamp(
                    -PitchSpeed * SwaySensitivity,
                    -MaxSwayAngle,
                    MaxSwayAngle
                );
            }
            LastCameraRotation = CameraRotation;
            bHasLastCameraRotation = true;
        }
    }

    FVector RecoilOffset(
        -CurrentRecoilBack,
        0.0f,
        0.0f
    );

    FVector ReloadOffset(
        0.0f,
        0.0f,
        -ReloadLowerDistance * ReloadAlpha
    );

    FVector FinalLocation =
        DefaultMeshLocation +
        RecoilOffset +
        ReloadOffset;

    FRotator RecoilSwayRotation(
        CurrentRecoilPitch + CurrentSwayPitch,
        CurrentSwayYaw,
        0.0f
    );

    FRotator ReloadRotation(
        0.0f,
        0.0f,
        ReloadTiltAngle * ReloadAlpha
    );

    FRotator FinalRotation =
        DefaultMeshRotation +
        RecoilSwayRotation +
        ReloadRotation;

    WeaponMesh->SetRelativeLocation(FinalLocation);
    WeaponMesh->SetRelativeRotation(FinalRotation);
}
```

读这个完整函数时按五段分开：

1. 更新开火冷却，按住且非换弹时继续射击。
2. 正在换弹时累加经过时间，计算换弹进度与姿态权重。
3. 获取相机旋转，计算相邻帧角速度和垂直摆动目标。
4. 从基准叠加后坐力、当前摆动和换弹偏移。
5. 一次性调用SetRelativeLocation和SetRelativeRotation写到WeaponMesh。

注意第3段目前只有目标计算，没有把目标送入 `CurrentSway...`。第4段读到的仍是初始化为0且没有更新过的当前摆动状态。

## 6. 换弹姿态：把时间映射成“下沉再抬回”

### 6.1 StartReload增加声音和时间清零

源码位置：`Source/MyArenaShooter/Private/MyWeapon.cpp:336`。

```cpp
void AMyWeapon::StartReload()
{
    if (bIsReloading)
    {
        return;
    }

    if (CurrentAmmo >= MagazineSize)
    {
        return;
    }

    if (ReserveAmmo <= 0)
    {
        return;
    }

    bIsReloading = true;
    ReloadElapsed = 0.0f;

    if (ReloadSound)
    {
        UGameplayStatics::PlaySound2D(
            this,
            ReloadSound
        );
    }

    GetWorldTimerManager().SetTimer(
        ReloadTimerHandle,
        this,
        &AMyWeapon::FinishReload,
        ReloadTime,
        false
    );
}
```

通过原有三个拒绝条件后，先设换弹状态true，把 `ReloadElapsed` 清为0；配置了 `ReloadSound` 时用 `PlaySound2D` 播放一次声音；仍使用Timer在 `ReloadTime` 后调用 `FinishReload()`。

`PlaySound2D` 不需要枪口世界位置，适合这一阶段的本地换弹提示。当前这里没有像玩家受伤声音那样检查 `IsLocallyControlled()`，也没有新增网络同步逻辑。参见 [PlaySound2D](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Engine/UGameplayStatics/PlaySound2D)。

### 6.2 ReloadProgress是0到1，ReloadAlpha是0到1再到0

```cpp
ReloadElapsed += DeltaTime;
float ReloadProgress = FMath::Clamp(
    ReloadElapsed / FMath::Max(ReloadTime, 0.01f),
    0.0f,
    1.0f
);
ReloadAlpha = FMath::Sin(ReloadProgress * PI);
```

分母用 `FMath::Max` 至少取0.01，避免姿态计算除以零；`Clamp` 把进度限制在0～1；乘以PI后，Sin走半个周期。

默认换弹时间1.5秒的理想例子：

| 经过时间 | 进度 | Sin权重约值 | Z下沉 | Roll倾斜 |
| --- | --- | --- | --- | --- |
| 0秒 | 0 | 0 | 0 | 0° |
| 0.375秒 | 0.25 | 0.707 | -10.61 | 17.68° |
| 0.75秒 | 0.5 | 1 | -15 | 25° |
| 1.125秒 | 0.75 | 0.707 | -10.61 | 17.68° |
| 1.5秒 | 1 | 0 | 0 | 0° |

所以是先下沉/倾斜，再回到当前基础姿态。Tick的累积时间与Timer回调不是严格逐帧同步的同一个时钟读数，表格帮助理解曲线，不要求真实帧在这些时刻精确取到表中数值。

**姿态分母的保护没有修改Timer的ReloadTime参数**。如果把ReloadTime配成非正数，不能据此理解为换弹计时也被自动修正；正常链仍要求配置正的换弹耗时。

### 6.3 FinishReload负责弹药，Tick负责外观

源码位置：`Source/MyArenaShooter/Private/MyWeapon.cpp:373`。

```cpp
void AMyWeapon::FinishReload()
{
    int32 NeededAmmo = MagazineSize - CurrentAmmo;

    int32 AmmoToReload = FMath::Min(NeededAmmo, ReserveAmmo);

    CurrentAmmo += AmmoToReload;
    ReserveAmmo -= AmmoToReload;

    bIsReloading = false;
    ReloadElapsed = 0.0f;

    UpdateAmmoHUD();
}
```

```text
StartReload
    → bIsReloading=true，ReloadElapsed=0，播放声音
    → 注册一次性Timer
    → 每帧Tick计算下沉/倾斜
    → Timer到时FinishReload补弹药
    → bIsReloading=false，ReloadElapsed=0，更新HUD
    → 后续Tick的ReloadAlpha回到0
```

动画曲线不会自行完成补弹药；`FinishReload()` 也不直接调用SetRelativeLocation恢复网格，而是让后续Tick按新状态重新合成姿态。

## 7. 惯性摆动：先理解角差，再理解角速度

### 7.1 两帧相机旋转相减要处理角度绕回

使用 `FMath::FindDeltaAngleDegrees(Last, Current)` 取得两次方向间的较小角差。例子：相机Yaw从179°变成-179°，直接相减得到-358°，但实际小幅转动是+2°。

再除以 `DeltaTime`，把“每帧变化的度数”变为“每秒变化的度数”。例如2°发生在0.02秒内，就是100°/秒。`DeltaTime > SMALL_NUMBER` 避免拿极小时间做除法。

第一次还没有历史旋转时，不计算速度，只保存当前旋转并设置 `bHasLastCameraRotation=true`。这样不会把默认零旋转与第一次真实视角当成一次用户转动。

官方定义见 [FindDeltaAngleDegrees](https://dev.epicgames.com/documentation/unreal-engine/API/Runtime/Core/Math/FMath/FindDeltaAngleDegrees?application_version=5.5)，角差语义也已与本地UE 5.4的实现核对。

### 7.2 反向比例与Clamp

当前只计算了：

```cpp
TargetSwayPitch = FMath::Clamp(
    -PitchSpeed * SwaySensitivity,
    -MaxSwayAngle,
    MaxSwayAngle
);
```

负号让武器摆动目标与视角变化方向相反，灵敏度把角速度缩放为小角度，上限防止快速甩视角时姿态过大。假设PitchSpeed=100°/秒，默认目标=-1.5°；若速度达到400°/秒，原目标=-6°，Clamp后为-3°。

当前 `YawSpeed` 虽然计算出来，但没有赋给 `TargetSwayYaw`。两个Target本身也没有赋回/插值到Current，因此本次实际没有产生这一层惯性摆动。

### 7.3 未接通部分的补全示例

以下是**后续可以补的示例，尚未写入项目**：在计算YawSpeed、PitchSpeed的同一分支里增加水平目标；在相机检测块之后、合成最终变换之前，让当前状态向目标插值，并让后坐力向0插值。

```cpp
// 放在计算YawSpeed的同一个作用域内：
TargetSwayYaw = FMath::Clamp(
    -YawSpeed * SwaySensitivity,
    -MaxSwayAngle,
    MaxSwayAngle
);

// 放在相机检测块之后、合成最终姿态之前：
CurrentSwayYaw = FMath::FInterpTo(
    CurrentSwayYaw, TargetSwayYaw, DeltaTime, SwayInterpSpeed
);
CurrentSwayPitch = FMath::FInterpTo(
    CurrentSwayPitch, TargetSwayPitch, DeltaTime, SwayInterpSpeed
);
CurrentRecoilBack = FMath::FInterpTo(
    CurrentRecoilBack, 0.0f, DeltaTime, RecoilRecoverySpeed
);
CurrentRecoilPitch = FMath::FInterpTo(
    CurrentRecoilPitch, 0.0f, DeltaTime, RecoilRecoverySpeed
);
```

`FInterpTo(Current, Target, DeltaTime, InterpSpeed)` 返回这帧向目标靠近后的数值，**必须把返回值写回状态**。正速度下常用更新部分可理解为：

```text
新值 = 当前值 + (目标 - 当前值) × Clamp(DeltaTime × 速度, 0, 1)
```

例如当前后退8，目标0，DeltaTime=1/60，速度12，则这帧约回到6.4。它不是“必定12秒恢复”，速度是插值快慢参数。函数还处理极小差值和非正速度等情况。参见 [FInterpTo官方API](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/Core/FMath/FInterpTo)。

这段示例仅补表现状态。若以后希望相机也上抬或射击出现散射，应另设计控制器旋转/子弹方向逻辑，不能把网格姿态改动直接当成已经实现那些功能。

## 8. 最终位置和旋转为何统一写入

当前位置：

```text
DefaultMeshLocation
    + FVector(-CurrentRecoilBack, 0, 0)
    + FVector(0, 0, -ReloadLowerDistance × ReloadAlpha)
```

当前旋转：

```text
DefaultMeshRotation
    + FRotator(CurrentRecoilPitch + CurrentSwayPitch, CurrentSwayYaw, 0)
    + FRotator(0, 0, ReloadTiltAngle × ReloadAlpha)
```

`FRotator` 构造顺序是Pitch、Yaw、Roll，单位是度。当前用加法叠加各轴数值来表达这些小姿态偏移；不要把它当成一般情况下按顺序组合三维旋转的通用运算。

最后统一SetRelativeLocation/Rotation，能避免不同表现代码分别设置完整变换、彼此覆盖。父组件旋转会把局部X/Z偏移转换到世界空间，所以相机转向后“局部后退”不会固定沿世界X轴。

## 9. 枪口跟着网格动，但子弹仍向相机选点飞

MuzzleLocation挂在WeaponMesh下面。网格后退、上抬或换弹下沉后，枪口世界变换也随之改变。

`Fire()` 每次重新取得 `MuzzleLocation->GetComponentLocation()`，用 `AimPoint - MuzzlePosition` 算方向。因此本次没有把子弹旋转换成网格上抬角度；仍以相机选点为目标，仅发射起点可能随网格姿态改变。

Tick顺序还要注意：**当前先执行可能的Fire，再合成本帧网格变换**。这一帧子弹读取的是Fire调用当时已经存在的枪口变换，之后网格更新不会回头修改已经生成的子弹。

```text
Tick：冷却结束 → Fire读取当前枪口并生成子弹
    → Fire增加后坐力状态
    → Tick继续合成姿态并更新WeaponMesh
    → 后续一次Fire读取更新后的枪口位置
```

这解释了为什么武器视觉状态会影响下一次枪口位置，但子弹生成之后仍独立飞行。
