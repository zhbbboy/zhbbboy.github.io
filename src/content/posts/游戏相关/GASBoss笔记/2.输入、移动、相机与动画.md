## 1. 输入系统需要接通两端

当前 `Config/DefaultInput.ini` 指定：

```ini
DefaultPlayerInputClass=/Script/EnhancedInput.EnhancedPlayerInput
DefaultInputComponentClass=/Script/EnhancedInput.EnhancedInputComponent
```

本项目使用 Enhanced Input。理解它时要分别检查“物理输入如何产生动作值”和“动作事件由哪个函数处理”。Input Action、Mapping Context、Modifier、Trigger 是官方文档中的四个核心概念。[Epic：Enhanced Input](https://dev.epicgames.com/documentation/en-us/unreal-engine/enhanced-input-in-unreal-engine?application_version=5.7)

| 概念 | 用途 | 本工程可定位的例子 |
| --- | --- | --- |
| Input Action，IA | 表示移动、视角、跳跃等动作及值类型 | `IA_Move`、`IA_Look`、`IA_MouseLook`、`IA_Jump` |
| Input Mapping Context，IMC | 组织物理按键到动作的映射 | `IMC_Default`、`IMC_MouseLook` |
| Modifier | 对输入值做轴交换、取反、缩放等处理 | 具体配置待打开 IMC 核对 |
| Trigger | 决定动作何时满足触发条件 | 具体配置待打开 IA / IMC 核对 |
| LocalPlayerSubsystem | 为某个本地玩家安装或移除上下文 | `UEnhancedInputLocalPlayerSubsystem` |
| EnhancedInputComponent | 将动作事件交给 C++ 函数 | 角色中的 `BindAction` |

源码可确认 `Move` 读取 `FVector2D`，因此这段代码期望 IA 提供二维值；资源中的实际 Value Type 仍属于编辑器核对项。

## 2. Controller 负责安装输入映射

入口是 `AGASGamePlayerController::SetupInputComponent`，位于 `Source/GASGame/GASGamePlayerController.cpp`。

```text
SetupInputComponent
    ↓ 仅对 IsLocalPlayerController() 生效
获取当前 LocalPlayer 的 EnhancedInputLocalPlayerSubsystem
    ├─ 遍历 DefaultMappingContexts → AddMappingContext(Context, 0)
    └─ 不使用触摸控件时
         遍历 MobileExcludedMappingContexts → AddMappingContext(Context, 0)
```

这里的上下文数组是 `UPROPERTY(EditAnywhere)`，C++ 没有写死数组中的资源。虽然目录里存在 `IMC_Default` 和 `IMC_MouseLook`，仍需打开实际 Controller 蓝图确认它们分别放在哪个数组。

源码中这些上下文的优先级均传入 `0`。未来增加菜单、载具、锁定等输入模式时，可以评估动态切换上下文及其优先级；那属于后续扩展。

### 触摸输入的入口

`ShouldUseTouchControls()` 返回平台触摸界面判断与 `bForceTouchControls` 的逻辑或。`BeginPlay` 在需要触摸操作且为本地 Controller 时创建 `MobileControlsWidgetClass`，并调用 `AddToPlayerScreen(0)`。

`Content/Input/Touch/UI_TouchSimple.uasset` 和 `UI_Thumbstick.uasset` 已存在。触摸控件实际怎样调用角色 `DoMove`、`DoLook` 或跳跃接口，需打开 Widget 事件图确认，不能只凭接口注释认定蓝图已经连好。

## 3. Character 负责把动作绑定到行为

入口是 `AGASGameCharacter::SetupPlayerInputComponent`。

| 属性引用 | 触发事件 | 绑定目标 |
| --- | --- | --- |
| `MoveAction` | `Triggered` | `AGASGameCharacter::Move` |
| `LookAction` | `Triggered` | `AGASGameCharacter::Look` |
| `MouseLookAction` | `Triggered` | `AGASGameCharacter::Look` |
| `JumpAction` | `Started` | `ACharacter::Jump` |
| `JumpAction` | `Completed` | `ACharacter::StopJumping` |

这些是 C++ 属性名与函数绑定。它们实际指向哪个 `IA_*` 资源，以及键盘、鼠标、手柄的具体键位，需要在蓝图和输入资源中核对。

`Started` 表示开始进行触发判断，`Triggered` 表示满足触发条件，`Completed` 表示触发流程完成。不要把 `Triggered` 永远等同于“按下一次”，也不要脱离 IA 的 Trigger 配置解释所有行为。[Epic：输入动作与触发状态](https://dev.epicgames.com/documentation/en-us/unreal-engine/enhanced-input-in-unreal-engine?application_version=5.7)

### `Do*` 接口为什么有价值

基础角色把输入回调和行为入口分开：

```text
Move(FInputActionValue) → 读取 Vector2D → DoMove(Right, Forward)
Look(FInputActionValue) → 读取 Vector2D → DoLook(Yaw, Pitch)

蓝图 / 触摸控件也可以调用 DoMove、DoLook、DoJumpStart、DoJumpEnd
```

`Do*` 是 `BlueprintCallable` 的行为入口。但基础角色的 `JumpAction` 当前直接绑定到 `ACharacter::Jump/StopJumping`，没有经过 `DoJumpStart/DoJumpEnd`。以后如果只在跳跃包装函数中加限制，必须检查键盘绑定是否也改为走同一入口。

## 4. 从一次移动输入追到实际位移

```text
物理按键 / 摇杆
    ↓ 当前生效的 IMC、Modifier、Trigger
MoveAction 产生二维输入
    ↓ EnhancedInputComponent 派发事件
Move(Value)
    ↓ DoMove(Value.X, Value.Y)
从 Controller 的 Yaw 算出世界空间前 / 右方向
    ↓ AddMovementInput
CharacterMovement 消费移动输入，结合速度、加速度和碰撞更新角色
```

`DoMove` 的关键代码为：

```cpp
const FRotator Rotation = GetController()->GetControlRotation();
const FRotator YawRotation(0, Rotation.Yaw, 0);
const FVector ForwardDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::X);
const FVector RightDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::Y);

AddMovementInput(ForwardDirection, Forward);
AddMovementInput(RightDirection, Right);
```

这里有三个要点：

1. 输入二维向量的 X 被传作 Right，Y 被传作 Forward；世界方向并非简单照搬输入向量。
2. 方向来自控制器的 Yaw，忽略 Pitch 与 Roll。因此抬头看天不会让向前输入变成向上飞。
3. `AddMovementInput` 提交移动意图，角色最终怎样加速、停下和处理阻挡由移动组件负责，不是这两行直接设置坐标。

假设视角 Yaw 为 0，Forward 对应世界 +X，Right 对应世界 +Y；将视角水平转动后，输入参考方向也随之转动。

### 基础角色的 C++ 初始移动参数

| 参数 | 初始值 | 用途 |
| --- | --- | --- |
| Capsule 半径 / 半高 | `42 / 96` | 角色主要碰撞尺寸 |
| `MaxWalkSpeed` | `500` | 默认步行移动模式下的速度上限 |
| `MinAnalogWalkSpeed` | `20` | 模拟输入较小时的最小目标走速设置 |
| `JumpZVelocity` | `500` | 跳跃竖直初速度 |
| `AirControl` | `0.35` | 空中横向操作能力 |
| `BrakingDecelerationWalking` | `2000` | 地面制动减速度 |
| `BrakingDecelerationFalling` | `1500` | Falling 模式制动减速度 |
| `RotationRate.Yaw` | `500` | 移动朝向的旋转速率设置 |

这张表来自构造函数，**实际运行值可能被蓝图覆盖**。调节手感时应同时观察对应组件的 Details。

## 5. 角色朝向与镜头朝向为什么可以分开

基础角色设置：

```cpp
bUseControllerRotationPitch = false;
bUseControllerRotationYaw = false;
bUseControllerRotationRoll = false;
GetCharacterMovement()->bOrientRotationToMovement = true;
```

`DoLook` 则调用 `AddControllerYawInput` 和 `AddControllerPitchInput`。因此视角输入先影响控制旋转，而身体朝向由移动朝向设置驱动。站着移动鼠标时，身体不必跟着水平旋转；移动时身体再趋向移动方向。

```text
LookAction / MouseLookAction
       ↓ DoLook
Controller 的 ControlRotation
       ├─ 提供 DoMove 使用的水平参考方向
       └─ 提供 CameraBoom 使用的视角旋转

移动输入 → CharacterMovement → 身体朝向
```

`ControlRotation`、`ActorRotation`、组件相对旋转是不同概念。开发瞄准、锁定和侧移时，先决定“谁跟着谁转”，再调整 `bUseControllerRotationYaw`、`bOrientRotationToMovement` 等设置。

## 6. 相机的两层关系

基础第三人称的 `CameraBoom` 附着在角色根组件，`FollowCamera` 附着在弹簧臂末端。弹簧臂设置 `bUsePawnControlRotation = true`，相机自身设置为 `false`；镜头通过父组件关系继承位置和旋转。

`TargetArmLength = 400` 是构造函数初始值。实际镜头距离还要结合蓝图覆盖、弹簧臂碰撞设置和场景阻挡判断。

Combat 和 Platforming 各自也创建相机与弹簧臂，部分参数不同；SideScrolling 另外提供 `PlayerCameraManager` 实现。改基础角色相机不会统一改变这些变体。

## 7. Mesh、AnimBP 和动画通知如何分工

角色移动组件产生速度与移动模式，Mesh 负责显示骨骼角色，AnimInstance / AnimBP 根据自己图表中的数据处理姿态，动画通知则在动画时间线上回调玩法逻辑。

```text
移动 / 攻击等玩法状态
    ↓（具体数据读取和绑定需查看 AnimBP）
AnimBP、动画序列、Montage
    ↓ 输出姿态
Skeletal Mesh 显示动作

动画到达某个 Notify
    ↓
角色收到命中检测 / 连击检查 / 冲刺结束等回调
```

本项目目录中存在：

| 资源路径 | 能确认的事实 |
| --- | --- |
| `Content/Characters/Mannequins/Anims/Unarmed/ABP_Unarmed.uasset` | 存在共享未持武器动画蓝图资源 |
| `Content/Characters/Mannequins/Rigs/CR_Mannequin_FootIK.uasset` | 存在脚部 IK Control Rig 资源 |
| `Content/Characters/Mannequins/Rigs/CR_Mannequin_Body.uasset` | 存在身体 Control Rig 资源 |
| `Content/Variant_Combat/Anims/ABP_Manny_Combat.uasset` | 存在战斗变体动画蓝图 |
| `Content/Variant_Platforming/Anims/ABP_Manny_Platforming.uasset` | 存在平台变体动画蓝图 |
| `Content/Variant_SideScrolling/Anims/ABP_Manny_SideScroller.uasset` | 存在横版变体动画蓝图 |

**待编辑器核对：** 哪个角色真正使用哪个 Anim Class；AnimBP 中有没有状态机、Slot、Root Motion 设置和 Control Rig 节点，以及它们怎样连接。官方模板文档中的旧资源路径和名称不能替代本工程的实际绑定。

动画通知可在动画的指定时刻触发自定义行为。本项目的 Combat 通知会调用攻击接口，Platforming 通知会结束冲刺，下一篇和第 4 篇分别展开。[Epic：Animation Notifies](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-notifies-in-unreal-engine?application_version=5.7)

## 8. 修改入口与排查顺序

| 现象 / 需求 | 推荐核对顺序 |
| --- | --- |
| 完全不能移动 | 实际 Pawn 是否被控制 → Controller 是否安装 IMC → IA 引用和值类型 → 事件是否到达 `Move` |
| 某方向不正确 | IMC 的轴交换 / 取反 → `DoMove` 参数顺序 → ControlRotation |
| 改走速没效果 | 当前控制的是哪套角色 → 蓝图移动组件覆盖值 → 运行时模式和参数 |
| 镜头绕转不正确 | IA 绑定 → `DoLook` → ControlRotation → 弹簧臂和相机设置 |
| 角色会走但没有动画 | Mesh、Animation Mode、Anim Class → AnimBP 实际取值和图表 |
| 想统一键盘和触摸的技能限制 | 让各输入入口经过共同的行为函数，并核对已有直接绑定 |

输入调试可使用控制台 `showdebug enhancedinput` 查看当前动作和映射状态，这是官方提供的输入调试入口。[Epic：Enhanced Input 调试命令](https://dev.epicgames.com/documentation/en-us/unreal-engine/enhanced-input-in-unreal-engine?application_version=5.7)
