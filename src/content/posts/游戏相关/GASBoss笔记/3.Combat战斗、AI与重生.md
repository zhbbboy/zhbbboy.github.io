## 1. 战斗变体的职责分布

本篇代码根目录为 `Source/GASGame/Variant_Combat/`，地图资源为 `Content/Variant_Combat/Lvl_Combat.umap`。先确认地图的实际 GameMode 和默认类，再对照下面的实现。

| 对象 | 主要职责 |
| --- | --- |
| `ACombatGameMode` | 继承 `AGameModeBase`，当前构造函数为占位 |
| `ACombatPlayerController` | 本地输入映射与触摸 UI、保存重生位置、旧角色销毁后生成新角色 |
| `ACombatCharacter` | 玩家移动、攻击输入、Montage、扫描、生命值、受击与死亡 |
| `ACombatEnemy` | 敌人攻击执行、生命值、受击、危险记录、死亡与回调 |
| `ACombatAIController` | 持有 StateTree AI 组件，接管 Pawn 时启动 AI 逻辑 |
| `CombatStateTreeUtility` | StateTree 的自定义条件、任务和任务完成连接 |
| `UCombatLifeBar` | 血条蓝图接口，具体显示交给 Widget 蓝图 |

`ACombatCharacter` 和 `ACombatEnemy` 都直接继承 `ACharacter`，并实现 `ICombatAttacker`、`ICombatDamageable`。敌人并非继承玩家战斗角色。

## 2. 三组接口把不同对象接起来

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `ICombatAttacker` | `DoAttackTrace`、`CheckCombo`、`CheckChargedAttack` | 动画通知调用攻击者的行为 |
| `ICombatDamageable` | `ApplyDamage`、`HandleDeath`、`ApplyHealing`、`NotifyDanger` | 受击、死亡、治疗与危险通知的统一入口 |
| `ICombatActivatable` | `ToggleInteraction`、`ActivateInteraction`、`DeactivateInteraction` | 场景触发器激活刷怪器等对象 |

接口定义位于 `Interfaces/`，`UINTERFACE` 声明为 `NotBlueprintable`，方法可被蓝图调用。不能将其理解为仅在任意蓝图中添加接口就能补齐全部 C++ 实现。

另一个需要分清的名称是：这里的 `Damageable->ApplyDamage(...)` 是自定义接口函数，不是 `UGameplayStatics::ApplyDamage`，也不是 GAS 的 Gameplay Effect。

## 3. 玩家攻击从输入到动画

`ACombatCharacter::SetupPlayerInputComponent` 的主要攻击绑定：

| 输入属性 | 事件 | 回调和行为入口 |
| --- | --- | --- |
| `ComboAttackAction` | `Started` | `ComboAttackPressed` → `DoComboAttackStart` |
| `ChargedAttackAction` | `Started` | `ChargedAttackPressed` → `DoChargedAttackStart` |
| `ChargedAttackAction` | `Completed` | `ChargedAttackReleased` → `DoChargedAttackEnd` |
| `ToggleCameraAction` | `Triggered` | `ToggleCamera` → `BP_ToggleCamera` |

目录中存在 `IA_ComboAttack`、`IA_ChargedAttack`、`IA_ToggleCameraSide` 和 `IMC_Combat`。具体键位、Trigger 与蓝图引用仍为**待编辑器核对**。

### 连击：保存输入时间，在动画窗口检查

```text
DoComboAttackStart
    ├─ 正在攻击 → 只更新 CachedAttackInputTime
    └─ 未在攻击 → ComboAttack
                     ├─ bIsAttacking = true
                     ├─ ComboCount = 0
                     ├─ NotifyEnemiesOfIncomingAttack
                     └─ 播放 ComboAttackMontage，绑定结束委托

动画通知调用 CheckCombo
    ↓ 正在攻击，且没有处于蓄力按住状态
检查最近输入是否落在 ComboInputCacheTimeTolerance 内
    ↓ 消费该输入时间，增加 ComboCount
还有后续 Section → Montage_JumpToSection
```

`ComboInputCacheTimeTolerance` 的 C++ 初始值为 `0.45` 秒。它表示通知到来时能接受多早之前的输入，并不独立决定通知在动画哪一帧发生。窗口位置还取决于 Montage 的通知布置。

`AttackMontageEnded` 会清除 `bIsAttacking`，并用另一项 `AttackInputCacheTimeTolerance` 检查能否接下一次攻击；该项 C++ 初始值为 `1.0` 秒。它与连击通知的缓存容差不是同一个参数。

### 蓄力：按住状态决定循环还是释放

`DoChargedAttackStart` 设置 `bIsChargingAttack`，空闲时进入 `ChargedAttack`。动画检查通知调用 `CheckChargedAttack`，把 `bHasLoopedChargedAttack` 设为真，再根据是否仍按住，跳转 `ChargeLoopSection` 或 `ChargeAttackSection`。

释放输入会清除按住状态；如果已经经过循环检查，就立即调用 `CheckChargedAttack` 转入释放段。Section 名称和资源引用来自可编辑属性，实际值需要查看角色蓝图和 Montage。

注意：当前 `DoAttackTrace` 统一使用 `MeleeDamage`。仅有“Charged Attack”这个名字，不能证明源码已根据蓄力时长计算额外伤害。

## 4. 伤害为什么在动画通知时发生

`Animation/` 下的三个通知负责把动画时间点接回接口：

| 通知类 | 调用 |
| --- | --- |
| `UAnimNotify_DoAttackTrace` | `ICombatAttacker::DoAttackTrace(AttackBoneName)` |
| `UAnimNotify_CheckCombo` | `ICombatAttacker::CheckCombo()` |
| `UAnimNotify_CheckChargedAttack` | `ICombatAttacker::CheckChargedAttack()` |

以命中通知为例，核心逻辑是：

```cpp
if (ICombatAttacker* AttackerInterface = Cast<ICombatAttacker>(MeshComp->GetOwner()))
{
    AttackerInterface->DoAttackTrace(AttackBoneName);
}
```

这使玩家与敌人可以复用通知类型，而各自决定怎么检测命中。通知到来的实际时间仍需查看动画时间线。[Epic：Animation Notifies](https://dev.epicgames.com/documentation/en-us/unreal-engine/animation-notifies-in-unreal-engine?application_version=5.7)

玩家的扫描过程为：

```text
Mesh 上 DamageSourceBone 对应的 Socket / 骨骼位置
    ↓ 作为 TraceStart
角色前方 MeleeTraceDistance 距离
    ↓ 作为 TraceEnd
半径 MeleeTraceRadius 的 SweepMultiByObjectType
    ↓ 查询 Pawn + WorldDynamic，忽略自己
逐个命中 Actor → 尝试转换 ICombatDamageable
    ↓
ApplyDamage(MeleeDamage, 攻击者, 命中位置, 击退冲量)
    ↓
调用攻击者的 DealtDamage 蓝图表现事件
```

敌人的检测只查询 Pawn，并要求目标具有 `ActorHasTag("Player")`。玩家检测没有同样的 Player 标签条件，因而可打到实现受伤接口的动态箱子或假人。

当前扫描函数没有维护“这次攻击已经命中过的 Actor 集合”。后续做多通知、持续武器轨迹或多个碰撞体时，需要重新定义一次挥击的命中次数规则，不能假定模板已自动去重。

## 5. 生命值、受击与血条

角色的伤害链为：

```text
ICombatDamageable::ApplyDamage
    ↓
本类 TakeDamage
    ├─ 已死亡 → 返回 0
    └─ CurrentHP -= Damage
         ├─ HP <= 0 → HandleDeath
         └─ 仍存活 → 更新血条，启用局部物理混合
    ↓ 返回伤害值
非零伤害 → 移动冲量 / 布娃娃冲量 / ReceivedDamage 蓝图事件
```

敌人的 `ApplyDamage` 还会停止连击与蓄力 Montage，打断当前攻击。玩家的对应实现没有这段 `Montage_Stop`，不要把双方受击行为写成完全相同。

血条由 Character 上的 `UWidgetComponent` 承载。`BeginPlay` 取得并转换 Widget 为 `UCombatLifeBar`，随后调用 `SetLifePercentage` 等接口。

`UI/CombatLifeBar.h` 中的 `SetLifePercentage` 和 `SetBarColor` 是 `BlueprintImplementableEvent`：C++ 发出更新请求，真正改进度条或颜色的图表需在 `Content/Variant_Combat/UI/UI_LifeBar.uasset` 中核对。

当前玩家 `MaxHP` 的 C++ 初始值为 `5.0`，`ResetHP()` 会令 `CurrentHP = MaxHP`。伤害计算是简单相减，尚不是防御、暴击、抗性或属性聚合系统；`ApplyHealing` 在玩家和敌人中均为占位函数。

## 6. 玩家死亡、重生和检查点

```text
玩家 HandleDeath
    ├─ 禁用移动
    ├─ 开启 Mesh 布娃娃物理
    ├─ 隐藏血条，拉远相机
    └─ Timer → RespawnCharacter → Destroy 旧角色
                                      ↓ OnDestroyed 委托
ACombatPlayerController::OnPawnDestroyed
    ↓ 按 CharacterClass + RespawnTransform 生成新角色
    ↓ Possess 新角色
```

Controller 在 `OnPossess` 中订阅当前 Pawn 的 `OnDestroyed`，因而重生职责不在 `CombatGameMode` 里。生成失败时，当前实现不会继续调用 `Possess`；它也没有额外的重试流程。

重生位置有两个主要来源：

- `ACombatCharacter::NotifyControllerChanged`：用当前角色 Transform 初始化 Controller 保存的重生位置。
- `ACombatCheckpointVolume::OnOverlap`：玩家进入且尚未使用该检查点时，记录**玩家当时的 Transform**，并将检查点标记为已使用。

这里记录的是进入时角色的位置和朝向，不是直接使用检查点 Actor 的中心。`CharacterClass`、重生等待时间及蓝图具体值均需在编辑器核对。

## 7. 敌人 AI：StateTree 负责决策，角色负责动作

`ACombatEnemy` 构造函数指定默认 `AIControllerClass = ACombatAIController::StaticClass()`，并设置 `AutoPossessAI = PlacedInWorldOrSpawned`。这是 C++ 默认行为，蓝图仍可能覆盖控制器类。

`ACombatAIController` 创建 `UStateTreeAIComponent`，设置 `bStartAILogicOnPossess = true` 和 `bAttachToPawn = true`。具体使用哪棵树，需要查看实际 AIController 蓝图的组件配置。

资源 `Content/Variant_Combat/Blueprints/AI/ST_CombatEnemy.uasset` 存在。它内部的状态层级、绑定和转移条件属于**待编辑器核对项**，不能只根据 C++ 任务名画成已确认的 AI 状态图。

StateTree 是包含状态、条件、任务和转移的层次状态机；本项目用它组织 AI 行为，而不是在 C++ 中实现一棵行为树。[Epic：StateTree Overview](https://dev.epicgames.com/documentation/en-us/unreal-engine/overview-of-state-tree-in-unreal-engine?application_version=5.7)

### `CombatStateTreeUtility` 提供了哪些积木

| 类型 | 源码确认的职责 |
| --- | --- |
| `FStateTreeCharacterGroundedCondition` | 检查移动组件是否在地面，可按属性反转为空中条件 |
| `FStateTreeIsInDangerCondition` | 根据危险记录的时间差和方向点积判断是否需要反应 |
| `FStateTreeComboAttackTask` | 发起敌人连击，等待攻击完成委托 |
| `FStateTreeChargedAttackTask` | 发起敌人蓄力攻击，等待攻击完成委托 |
| `FStateTreeWaitForLandingTask` | 等待敌人的落地委托 |
| `FStateTreeFaceActorTask` / `FStateTreeFaceLocationTask` | 设置 AI 的注视对象 / 位置，退出时清除焦点 |
| `FStateTreeSetCharacterSpeedTask` | 修改角色最大走速 |
| `FStateTreeGetPlayerInfoTask` | 获取索引 0 的玩家 Pawn，更新目标位置与距离 |

### 一个攻击任务怎样知道动作完成了

```text
StateTree 攻击任务 EnterState
    ├─ 绑定 Enemy.OnAttackCompleted
    └─ 调用 DoAIComboAttack / DoAIChargedAttack
                         ↓
敌人播放 Montage，通知执行扫描和连段检查
                         ↓
AttackMontageEnded → OnAttackCompleted.ExecuteIfBound
                         ↓
WeakExecutionContext.FinishTask(Succeeded)
                         ↓
StateTree 可以继续选择转移
```

任务在相应 `ExitState` 中解除委托。解除委托不等于取消 Montage；以后加入 Boss 技能中断时，应单独设计动作取消、状态清理和任务结束规则。

## 8. 危险通知和 EQS 的位置

玩家开始攻击时会调用 `NotifyEnemiesOfIncomingAttack`，通过前方球形扫描向受伤接口发送 `NotifyDanger`。敌人只接受来自带 `Player` Actor Tag 的危险源，并保存位置和时间。

危险条件随后检查反应时间范围及危险方向与前向量的夹角。它依据的是**攻击预警记录**，不能直接解释为完整的视觉感知或 AI Perception 系统。

EQS 相关资源与上下文：

| 资源 / 类 | 当前能确认的作用 |
| --- | --- |
| `EnvQuery_Flank.uasset`、`EnvQuery_Fallback.uasset`、`EnvQuery_Evade.uasset` | 三个环境查询资源存在，生成器与评分需编辑器核对 |
| `UEnvQueryContext_Player` | 提供玩家索引 0 的 Pawn 作为 Actor 上下文 |
| `UEnvQueryContext_Danger` | 查询 Owner 能转换为 `ACombatEnemy` 时，提供其记录的危险位置 |

资源位于 `Content/Variant_Combat/Blueprints/AI/`。还需检查 StateTree 从何处执行查询、查询 Owner 如何传入、返回位置如何用于移动，以及地图导航区域是否覆盖可行走区域。

## 9. 刷怪和场景交互形成另一条链

```text
玩家进入 CombatActivationVolume
    ↓ 遍历 ActorsToActivate
ICombatActivatable::ActivateInteraction
    ↓
CombatEnemySpawner 生成敌人，并订阅 OnEnemyDied
    ↓ 敌人 HandleDeath 广播死亡
Spawner 减少 SpawnCount
    ├─ 还有数量 → 延迟生成下一个
    └─ 已耗尽 → 延迟激活 ActorsToActivateWhenDepleted
```

`bShouldSpawnEnemiesImmediately` 为真时，Spawner 在 `BeginPlay` 安排 `InitialSpawnDelay` 后首次生成；这里的“Immediately”仍通过定时器执行。延迟激活模式则由 `ActivateInteraction` 发起第一只敌人。

Spawner 订阅的是敌人的**死亡委托**，不是其 Actor 销毁事件。敌人死亡后还会延迟清理尸体，因此下一次刷怪与旧尸体消失是两件事。

| 场景类 | 与战斗系统的连接 |
| --- | --- |
| `ACombatLavaFloor` | 在 Mesh Hit 事件中对实现受伤接口的对象施加伤害 |
| `ACombatDamageableBox` | 自己维护 HP，受击时施加物理冲量，死亡时调用表现事件并延迟销毁 |
| `ACombatDummy` | 受击时对假人施加冲量并调用蓝图表现事件，不使用角色 HP 流程 |
| `ACombatCheckpointVolume` | 更新玩家 Controller 保存的重生 Transform |

实现了受伤接口不代表所有对象都走 `TakeDamage`：箱子和假人各自有不同实现，接口统一的是入口。

## 10. 开发入口与编辑器核对清单

| 需求 | 优先修改 / 核对位置 |
| --- | --- |
| 调整攻击范围 | `DoAttackTrace`、Melee Trace 属性、通知的骨骼名 |
| 改连段手感 | 缓存容差、`CheckCombo`、Montage Section 与通知位置 |
| 增加受击反馈 | `ReceivedDamage` / `DealtDamage` 蓝图事件与实际蓝图图表 |
| 敌人迟迟不结束动作 | Montage 是否播放成功、是否绑定结束委托、StateTree 任务是否解除或完成 |
| 角色死亡后不重生 | Controller 的销毁订阅、`CharacterClass`、Spawn 结果、重生 Transform |
| 刷怪器没有继续 | 是否触发 `OnEnemyDied`、剩余次数、计时器与激活条件 |
| 加 Boss 阶段 | 先定义阶段状态和决策入口，再连接现有角色执行或后续 GAS Ability |

编辑器重点查看 `BP_CombatGameMode`、`BP_CombatPlayerController`、`BP_CombatCharacter`、AI 目录的敌人与控制器蓝图，以及 `AM_ComboAttack`、`AM_ChargedAttack`、`ABP_Manny_Combat` 和 `UI_LifeBar`。这些资源均存在；内部属性、Slot、通知、Section 和图表未在本次读取中确认。
