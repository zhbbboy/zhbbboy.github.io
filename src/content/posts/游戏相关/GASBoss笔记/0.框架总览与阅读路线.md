## 1. 先确定我们正在读什么

这组笔记对应本机工程 `D:\code\Unreal Projects\GAS\GASGame`，依据截至 **2026-10-15** 的源码、配置和资源文件目录整理。后文的 `Source/`、`Config/`、`Content/` 都相对于这个工程根目录。

当前工程有以下特点：

- `GASGame.uproject` 的 `EngineAssociation` 为 `5.7`，游戏模块名为 `GASGame`。
- 基础第三人称以及 Combat、Platforming、SideScrolling 三套变体的代码和资源都存在。
- `DefaultEngine.ini` 配置的默认游戏地图和编辑器启动地图都是 `/Game/ThirdPerson/Lvl_ThirdPerson`。
- 项目配置的全局默认 GameMode 是 `BP_ThirdPersonGameMode`；具体地图还可能通过 World Settings 覆盖它。
- 项目源码中没有发现 `AbilitySystemComponent`、`AttributeSet`、Gameplay Ability 或 Gameplay Effect 的接入；模块依赖也没有显式列入 `GameplayAbilities`。**工程叫 GASGame，并不表示能力系统已经完成搭建。**

Epic 官方将第三人称模板的三种变体分别定位为战斗、平台跳跃和横版玩法。这里以本地代码确认具体实现，官方介绍只用于建立概念。[第三人称模板文档（UE 5.7）](https://dev.epicgames.com/documentation/en-us/unreal-engine/third-person-template-in-unreal-engine?application_version=5.7)

## 3. 工程目录：代码、资源和配置各管什么

```text
GASGame/
├─ GASGame.uproject              工程描述、模块和插件声明
├─ Source/
│  ├─ GASGame.Target.cs          游戏构建目标
│  ├─ GASGameEditor.Target.cs    编辑器构建目标
│  └─ GASGame/
│     ├─ GASGame.Build.cs        模块依赖与头文件搜索路径
│     ├─ GASGame.cpp / .h        主游戏模块注册、项目日志分类
│     ├─ GASGameGameMode.*       基础第三人称规则入口
│     ├─ GASGamePlayerController.*
│     ├─ GASGameCharacter.*
│     ├─ Variant_Combat/         战斗、敌人 AI、接口、通知和 UI
│     ├─ Variant_Platforming/    平台移动与冲刺
│     └─ Variant_SideScrolling/  横版相机、移动、交互、NPC 和 UI
├─ Config/                      默认地图、输入系统、渲染等设置
├─ Content/                     地图、蓝图、输入、动画、模型等资源
├─ Binaries/                    编译产物
├─ Intermediate/                构建中间文件和 UHT 生成文件
└─ Saved/                       日志、自动保存、用户级配置等
```

理解玩法时优先看 `Source + Config + Content`。`Intermediate` 中的 `.generated.h` 和 `.gen.cpp` 用于反射与构建，不是日常编写角色逻辑的位置。

### 构建目标与游戏模块

`GASGame.Target.cs` 的 `Type` 为 `Game`，`GASGameEditor.Target.cs` 的 `Type` 为 `Editor`；二者都把 `GASGame` 加入 `ExtraModuleNames`。它们决定构建哪一种程序。

`GASGame.Build.cs` 决定模块能使用哪些功能。目前主要依赖如下：

| 依赖 | 在本工程中的用途 |
| --- | --- |
| `Core`、`CoreUObject`、`Engine` | 基础类型、UObject、Actor、Character 和引擎功能 |
| `InputCore`、`EnhancedInput` | 输入类型、Input Action、Mapping Context 和输入绑定 |
| `AIModule` | AIController、导航相关功能及 EQS 上下文 |
| `StateTreeModule`、`GameplayStateTreeModule` | StateTree 条件、任务与 AI 组件 |
| `UMG`、`Slate` | 血条、触摸控件等界面支持 |

这些变体目录**仍属于同一个 GASGame 模块**，不是三个独立模块。`PublicIncludePaths` 中列出变体目录，仅为头文件查找提供路径。

`.uproject` 显式启用了 `StateTree`、`GameplayStateTree`，以及仅用于 Editor 目标的 `ModelingToolsEditorMode`。插件声明与模块依赖是两个不同入口，新增引擎插件功能时通常需要分别检查。

`GASGame.cpp` 中的 `IMPLEMENT_PRIMARY_GAME_MODULE` 注册主游戏模块；它不是“创建玩家角色”的函数。角色生成属于 Gameplay Framework 的运行流程。

## 4. 最重要的类关系：组合与平行变体

```text
AGameModeBase
├─ AGASGameGameMode
├─ ACombatGameMode
├─ APlatformingGameMode
└─ ASideScrollingGameMode

APlayerController
├─ AGASGamePlayerController
├─ ACombatPlayerController
├─ APlatformingPlayerController
└─ ASideScrollingPlayerController

APawn
└─ ACharacter
   ├─ AGASGameCharacter
   ├─ ACombatCharacter          + ICombatAttacker + ICombatDamageable
   ├─ APlatformingCharacter
   ├─ ASideScrollingCharacter
   └─ ACombatEnemy              + ICombatAttacker + ICombatDamageable
```

**修改 `AGASGameCharacter` 不会自动改变其他三个玩家角色。** 它们分别继承引擎的 `ACharacter`，相似代码目前存在于不同实现中。以后若要抽取公共角色基类，需要另外设计继承关系并处理蓝图父类迁移。

总体职责可以这样理解：

```text
地图 / 项目配置
      ↓ 选择 GameMode
GameMode 与引擎默认玩家流程
      ├─ 创建 / 使用 PlayerController
      └─ 按 DefaultPawnClass 生成 Pawn
                       ↑ Possess
                PlayerController
                       │ 安装输入映射、管理本地界面
                       ↓
                  Character
                  ├─ 胶囊体与移动组件
                  ├─ 相机 / 弹簧臂
                  ├─ 输入处理与玩法行为
                  └─ Mesh + 动画资源

Combat AIController → StateTree → CombatEnemy → 动画通知 → 命中与伤害
```

图中箭头表示责任或调用关系，不是所有对象生命周期的严格时间顺序。

## 5. 四套玩法分别从哪里进入

| 玩法 | 地图资源 | 主要 C++ 入口 | 主要资源目录 |
| --- | --- | --- | --- |
| 基础第三人称 | `Content/ThirdPerson/Lvl_ThirdPerson.umap` | `GASGameCharacter`、`GASGamePlayerController` | `Content/ThirdPerson/Blueprints/` |
| 战斗 | `Content/Variant_Combat/Lvl_Combat.umap` | `CombatCharacter`、`CombatEnemy`、`CombatAIController` | `Content/Variant_Combat/` |
| 平台跳跃 | `Content/Variant_Platforming/Lvl_Platforming.umap` | `PlatformingCharacter` | `Content/Variant_Platforming/` |
| 横版 | `Content/Variant_SideScrolling/Lvl_SideScrolling.umap` | `SideScrollingCharacter`、`SideScrollingCameraManager` | `Content/Variant_SideScrolling/` |

以上地图均在目录中存在。运行某张地图时实际使用哪个 GameMode、Controller 和 Pawn，还要检查该地图的 **World Settings → GameMode Override** 及所选 GameMode 的 **Class Defaults**。

## 6. 建议的阅读与核对路线

1. 打开基础地图，查看 Maps & Modes、World Settings 和 GameMode 的默认类，先把“配置如何选中角色”连起来。
2. 读 `GASGameCharacter` 的构造函数，认识 Capsule、Mesh、CharacterMovement、CameraBoom 和 FollowCamera。
3. 对照 Controller 的 `SetupInputComponent` 与 Character 的 `SetupPlayerInputComponent`，追踪一次移动输入。
4. 打开 Combat 地图，按“攻击输入 → Montage → Notify → 扫描 → 伤害 → UI”读完整条链。
5. 从 `CombatAIController` 进入 StateTree，再看敌人动作和任务完成回调。
6. 对比 Platforming 与 SideScrolling，观察同一个引擎基类如何承载不同玩法。
7. 最后再看 GAS/Boss 接入建议，把现有职责映射到新系统。

调试时优先打在行为入口：`DoMove`、`DoComboAttackStart`、`DoAttackTrace`、`TakeDamage`、`OnPawnDestroyed`。一次只回答一条调用链，避免在资源目录里无目标地跳转。
