## 1. 两个变体与基础角色的关系

`APlatformingCharacter`、`ASideScrollingCharacter` 都直接继承 `ACharacter`，各自拥有输入与移动实现。它们可以作为设计参考，但不会自动共享 `AGASGameCharacter` 中的新功能。

| 项目 | Platforming | SideScrolling |
| --- | --- | --- |
| 地图 | `Content/Variant_Platforming/Lvl_Platforming.umap` | `Content/Variant_SideScrolling/Lvl_SideScrolling.umap` |
| 主要代码 | `Source/GASGame/Variant_Platforming/` | `Source/GASGame/Variant_SideScrolling/` |
| 移动方向 | 参考控制器水平朝向的自由移动 | 受约束的 XZ 平面移动 |
| 特殊移动 | 多段跳、蹬墙跳、土狼时间、冲刺 | 多段跳、蹬墙跳、土狼时间、向下穿平台 |
| 相机实现 | 角色上的 SpringArm + Camera | 角色相机组件 + 自定义 CameraManager 类 |
| 场景玩法 | 以角色移动能力为主 | 另有平台、拾取物、NPC 与 UI |

官方对变体的介绍用于理解玩法方向，具体能力以本地实现为准；不能因为文档写到 climbing，就认定这份 C++ 已有完整攀爬系统。[Epic：第三人称模板变体](https://dev.epicgames.com/documentation/en-us/unreal-engine/third-person-template-in-unreal-engine?application_version=5.7)

## 2. Platforming：用移动状态决定如何跳

入口为 `APlatformingCharacter::DoJumpStart` → `MultiJump`。

```text
MultiJump
    ├─ 正在冲刺 → 忽略
    ├─ 地面 → Jump，开启跳跃拖尾
    └─ 空中
         ↓ 当前不在蹬墙跳锁定期
         向前做球形扫描检查墙面
         ├─ 命中 → 按碰撞法线转向、LaunchCharacter、短暂锁定输入
         └─ 未命中
              ├─ 还在土狼时间内 → Jump
              └─ 尚未二段跳 → 标记已使用二段跳，再 Jump
```

“土狼时间”指离开地面后仍保留很短的跳跃宽限期。源码在 `OnMovementModeChanged` 检测进入 Falling 时保存 `LastFallTime`，在 `MultiJump` 中比较经过时间。

`JumpMaxCount = 3` 的源码注释说明它为二段跳和土狼时间检查留出余量。**不能只看这个数值就把玩法定义为三段跳**，还要结合 `bHasDoubleJumped`、`bHasWallJumped` 和各分支限制。

### 蹬墙跳为什么需要临时锁定输入

蹬墙跳通过前方球形扫描取得 `ImpactNormal`，朝远离墙面方向旋转，再组合水平反弹和向上的冲量调用 `LaunchCharacter`。

之后设置 `bHasWallJumped`，用 Timer 延迟执行 `ResetWallJump`。`DoMove` 也检查这个标记，避免玩家刚被弹开又立即用移动输入抵消反弹。

`Landed` 重置二段跳和冲刺使用标记，并关闭拖尾。`EndPlay` 清理蹬墙跳锁定计时器。

### 与基础角色不同的 C++ 初始参数

| 参数 | Platforming 初始值 | 用途 |
| --- | --- | --- |
| `MaxWalkSpeed` | `750` | 更高的地面速度上限 |
| `GravityScale` | `2.5` | 重力倍率 |
| `JumpZVelocity` | `350` | 跳跃初速度 |
| `AirControl` | `1.0` | 空中横向操控 |
| `JumpMaxHoldTime` | `0.4` | 支持按住跳跃的最大持续时间设置 |
| 相机位置 / 旋转 Lag | 开启，速度初始为 `8` | 对视角变化进行平滑 |

这些值还受蓝图覆盖与其他移动参数共同影响，不能只用跳跃初速度单独比较最终跳高。

## 3. Platforming：冲刺的开始与结束

```text
DashAction 的 Triggered → Dash → DoDash
    ├─ bHasDashed 为真 → 忽略
    └─ 设置 bIsDashing、bHasDashed
         ├─ GravityScale = 0
         ├─ 清零当前 Velocity
         ├─ 开启拖尾
         └─ 播放 DashMontage，成功后绑定结束委托

EndDash 的入口
    ├─ UAnimNotify_EndDash → EndDash
    └─ DashMontageEnded（正常或打断）→ EndDash
         ↓
恢复 GravityScale = 2.5，清除 bIsDashing
若已在地面：同时重置 bHasDashed 并关闭拖尾
```

`bIsDashing` 表示目前处于冲刺过程；`bHasDashed` 表示这次机会已经用过。落地时恢复使用机会，所以结束冲刺与恢复冲刺次数不是同一件事。

`SetJumpTrailState` 是交给蓝图实现的表现接口。`DoDash` 本身没有调用 `LaunchCharacter` 或按固定冲刺速度平移角色，因此实际前进来源必须结合 `Content/Variant_Platforming/Anims/AM_Dash.uasset`、Root Motion、AnimBP 及蓝图图表核对。这里不把“使用根运动”写成已验证事实。

后续改动时特别留意：`EndDash` 当前将重力恢复为固定的 `2.5`，不是恢复冲刺前记录的值；Montage 未成功播放时，也没有由这段代码额外安排超时恢复。这些都是重构移动能力时要处理的边界。

## 4. SideScrolling：把输入投到横版平面

构造函数设置：

```cpp
GetCharacterMovement()->SetPlaneConstraintNormal(FVector(0.0f, 1.0f, 0.0f));
GetCharacterMovement()->bConstrainToPlane = true;
```

平面法线沿 Y，角色移动约束在 XZ 平面。`Move` 读取二维输入后只使用 `MoveVector.Y`，传给 `DoMove(float Forward)`。

`DoMove` 的实际方向向量为 `FVector(1.0f, Forward > 0.0f ? 0.1f : -0.1f, 0.0f)`，再以 `Forward` 作为输入强度。理解行为时还要结合平面约束，不能简单把输入资源的 Y 分量写成世界 Y 方向移动。

输入资源名也需要按目录核对：本工程存在 `Content/Variant_SideScrolling/Input/Actions/IA_Mover.uasset`，名称确实是 `IA_Mover`，不是另一份同名 `IA_Move`。IMC 资源为 `IMC_SideScroller`。具体引用仍需查看蓝图。

## 5. 横版相机：CameraManager 计算最终视角

角色构造函数创建一个 Camera 组件，设置相对位置 `(0, 300, 0)`、旋转 `(0, -90, 0)`；此外，`ASideScrollingCameraManager::UpdateViewTarget` 实现了独立视角计算。

```text
UpdateViewTarget
    ↓ 目标必须可转换为 Pawn
设置视角旋转 (0, -90, 0)，FOV = 65
    ↓
首次：建立初始相机位置和高度记录
后续：读取角色位置和当前相机位置
    ├─ X：按 CameraXMinBounds / CameraXMaxBounds 限制
    ├─ Y：角色 Y + CurrentZoom
    └─ Z：结合速度、向下检测与插值更新高度目标
    ↓
插值到目标位置，写入 OutVT.POV
```

`CurrentZoom` 在这里作为相机与目标的距离偏移使用，并不是调整 FOV 的倍率。高度跟随也不是简单把角色 Z 每帧复制给相机。

**待编辑器核对：** `BP_SideScrollingPlayerController` 的 Player Camera Manager Class 是否指向 `BP_SideScrollingCameraManager`，以及 CameraManager 的边界、偏移和缩放配置。仅有这个类和蓝图资源，并不证明运行时已经选中它。

## 6. 横版跳跃和穿透平台

横版 `MultiJump` 的优先级为：

1. `DropValue > 0` 时先尝试向下穿透平台，并结束这次跳跃处理。
2. 在地面则普通跳跃。
3. 空中有横向输入且未被锁定时，用水平射线尝试蹬墙跳。
4. 没有进入蹬墙跳锁定时，再检查土狼时间和二段跳。

它与 Platforming 都有二段跳和蹬墙跳，但检测形状不同：Platforming 使用向前球形扫描，SideScrolling 使用沿世界 X 正负方向的射线。

### `SetSoftCollision(true)` 实际上会忽略碰撞

```cpp
GetCapsuleComponent()->SetCollisionResponseToChannel(
    SoftCollisionObjectType,
    bEnabled ? ECR_Ignore : ECR_Block
);
```

所以不要按函数名直译成“true 表示开启实体碰撞”。在这段代码中，true 表示对软平台通道忽略碰撞，false 才恢复阻挡。

```text
Drop 输入 → 保存 DropValue
    ↓ 跳跃时优先处理下穿
CheckForSoftCollision 向下查询 SoftCollisionObjectType
    ↓ 命中后忽略该通道
角色落穿平台
    ↓ 平台相关 Actor 的 EndOverlap
SetSoftCollision(false) → 恢复阻挡
```

`ASideScrollingSoftPlatform` 在平台下方的检查盒开始重叠时，也会让角色忽略该通道，使角色能够从下方穿过；结束 Actor 重叠后恢复。

**待编辑器核对：** 角色的 `SoftCollisionObjectType`、平台 Mesh 的实际 Object Type、检查盒范围及碰撞响应必须匹配。不要自行假设工程一定建立了一个叫 SoftPlatform 的自定义通道。

## 7. 横版交互：接口连接 NPC 和平台

`DoInteract` 使用球形扫描，查询 Pawn 和 WorldDynamic、忽略自己；命中对象能转换为 `ISideScrollingInteractable` 时调用 `Interaction(this)`。

扫描从角色位置向**世界 +X** 延伸 100，源码没有使用 `GetActorForwardVector()` 选择正反方向。开发“面朝左也能交互”时应先核对这一点。

| 对象 | 收到交互后做什么 |
| --- | --- |
| `ASideScrollingMovingPlatform` | `bMoving` 防重复触发，调用蓝图 `BP_MoveToTarget` 执行真正位移 |
| `ASideScrollingNPC` | 暂时标记失效、停止移动、沿交互者方向弹开，计时后恢复 |

MovingPlatform 的 `ResetInteraction` 在非 `bOneShot` 情况下恢复可触发状态；它何时被调用，需要打开对应蓝图核对。C++ 没有直接实现完整的平台往返轨迹。

`ASideScrollingAIController` 同样创建 StateTree AI 组件并在接管 Pawn 时启动逻辑。`FStateTreeGetPlayerTask` 获取玩家索引 0，并在目标与 NPC 有效时检查距离是否小于 `RangeMax`。`ST_SideScrollingNPC` 的具体状态，以及 NPC 蓝图的控制器与自动接管设置，属于待核对内容。

## 8. 拾取物、弹跳垫和 UI

```text
玩家控制的 Character 与 SideScrollingPickup 重叠
    ↓ 获取 ASideScrollingGameMode
ProcessPickup
    ├─ 增加 PickupsCollected
    ├─ 第一次拾取时把 UI 加入 Viewport
    └─ 调用 UpdatePickups 更新显示
    ↓
拾取物禁用碰撞，调用 BP_OnPickedUp
    ↓ 蓝图负责表现与最终销毁
```

`ASideScrollingGameMode::BeginPlay` 创建 UI，但并未立刻显示；显示发生在第一次拾取。`UserInterfaceClass` 及 `UI_SideScrolling` 内部图表需在编辑器核对。

`ASideScrollingJumpPad` 在 Character 重叠时先调用 `Jump()`，再以 `ZStrength` 调用 `LaunchCharacter` 覆盖竖直速度。它没有使用战斗伤害接口，职责就是施加移动效果。

当前拾取计数由 GameMode 更新 UI，是单机模板式实现。后续若增加远程客户端，不能直接照搬到客户端依赖 GameMode 的路径中，需要重新安排共享状态和 UI 数据来源。

## 9. 两套 Controller 的重生方式

Platforming 和 SideScrolling 的 Controller 都在 `OnPossess` 订阅角色销毁，在 `OnPawnDestroyed` 中查找 `APlayerStart`，使用结果数组第一项的 Transform 创建 `CharacterClass`，再 `Possess`。

这与 Combat 保存检查点 Transform 的方式不同。数组第一项也不代表“最近的出生点”或具备稳定优先级的出生点选择规则。没有找到 PlayerStart 或 Spawn 失败时，现有实现不进行后续控制转移。

## 10. 可以借鉴到 Boss 项目的部分

| 想加入的能力 | 可参考实现 | 移植时要补齐 |
| --- | --- | --- |
| 翻滚 / 闪避 | Platforming 的开始、结束、使用机会标记与 Montage 回调 | 实际位移来源、无敌判定、冷却、中断和重力恢复 |
| 受击击退 | 蹬墙跳 / JumpPad 的 Launch，NPC 的弹开 | 与战斗状态、地形和网络权威的协调 |
| 机关平台 | MovingPlatform 的交互接口和蓝图事件 | 轨迹、终点、重置与多人同步规则 |
| 场景奖励 | Pickup → 计数 → UI | 掉落来源、持久化和多人数据归属 |

以上是后续建议；当前模板没有统一的闪避、Boss 或 GAS 能力实现。
