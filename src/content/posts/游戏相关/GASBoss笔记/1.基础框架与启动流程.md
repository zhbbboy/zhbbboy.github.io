## 1. 游戏为什么一开始就有一个能控制的角色

需要连起来的是两类信息：**配置选中了什么类**，以及**引擎如何使用这些类**。仅看 `GASGameGameMode.cpp` 会发现构造函数几乎为空，但引擎基类仍提供生成玩家等默认流程。

当前 `Config/DefaultEngine.ini` 的关键配置为：

```ini
[/Script/EngineSettings.GameMapsSettings]
GameDefaultMap=/Game/ThirdPerson/Lvl_ThirdPerson.Lvl_ThirdPerson
EditorStartupMap=/Game/ThirdPerson/Lvl_ThirdPerson.Lvl_ThirdPerson
GlobalDefaultGameMode=/Game/ThirdPerson/Blueprints/BP_ThirdPersonGameMode.BP_ThirdPersonGameMode_C
```

| 配置 | 含义 |
| --- | --- |
| `GameDefaultMap` | 游戏未通过其他方式指定地图时的默认地图 |
| `EditorStartupMap` | 编辑器启动时默认打开的地图 |
| `GlobalDefaultGameMode` | 项目级默认规则类 |

在编辑器里点击 Play 通常运行当前打开的世界，因此打开 Combat 地图再 Play，不应理解为必然重新进入 `GameDefaultMap`。另外，地图的 GameMode Override 可以覆盖项目默认设置。[Epic：GameMode 的配置与生成玩家入口](https://dev.epicgames.com/documentation/en-us/unreal-engine/game-mode-and-game-state-in-unreal-engine?application_version=5.7)

### 这次已经确认与尚未确认的边界

源码和配置已经确认全局默认 GameMode 的资源路径；`BP_ThirdPersonGameMode`、`BP_ThirdPersonPlayerController`、`BP_ThirdPersonCharacter` 三个资源文件也确实存在。

但蓝图内部的父类、`DefaultPawnClass`、`PlayerControllerClass`，以及地图覆盖值，仍需在编辑器查看。不能只凭相近文件名就认定它们已经正确相连。

## 2. 三个核心类分别管什么

| 类 | 父类 | 当前代码职责 | 以后常见扩展 |
| --- | --- | --- | --- |
| `AGASGameGameMode` | `AGameModeBase` | 构造函数为占位，依赖基类与蓝图配置 | 游戏规则、胜负、玩家生成规则 |
| `AGASGamePlayerController` | `APlayerController` | 安装本地输入映射；需要时创建触摸控件 | 本地 UI、菜单、切换控制对象 |
| `AGASGameCharacter` | `ACharacter` | 创建相机组件，配置移动，绑定并执行移动/视角/跳跃 | 玩家移动能力、交互、动画驱动 |

这些项目 C++ 类声明为 `UCLASS(abstract)`。抽象类不能直接作为可生成的具体角色使用；应检查所选具体蓝图子类。蓝图父类的实际对应关系仍以 Class Settings 为准。

### Controller 和 Character 的区别

Character 是游戏世界里的身体：有位置、碰撞、Mesh 和移动状态。Controller 表示谁在控制身体，通过 `Possess` 与 Pawn 建立控制关系。

```text
PlayerController
    │ Possess
    ↓
Pawn / Character
    ├─ 身体、碰撞和移动
    ├─ 外观与动画
    └─ 角色相关行为
```

一个 Controller 当前控制哪个 Pawn 可以变化。Combat 重生会换掉旧 Character，再让同一个 Controller 控制新 Character，这正是把“操作者”和“身体”分开的用途之一。

## 3. 玩家生成的责任链

以下是常规默认玩家生成路径的概念图，**不是逐个回调的绝对执行时间表**：

```text
加载地图
    ↓
选择有效 GameMode
    ├─ 项目默认配置
    └─ 地图 / 运行选项可能覆盖
    ↓
GameMode 与引擎处理玩家进入
    ↓
创建 / 使用 PlayerController
    ↓
默认开始玩家流程（HandleStartingNewPlayer / RestartPlayer 等）
    ↓
选择出生位置（通常涉及 PlayerStart）
    ↓
按 DefaultPawnClass 生成 Pawn
    ↓
Controller Possess Pawn
    ↓
本地玩家具备输入组件、映射和行为绑定后开始操作
```

`HandleStartingNewPlayer`、`RestartPlayer`、`SpawnDefaultPawnAtTransform` 是引擎基类中的入口。本工程的基础 GameMode 没有重写这些方法，不能把它们误写成项目自定义实现。[Epic：AGameModeBase 常见函数](https://dev.epicgames.com/documentation/en-us/unreal-engine/game-mode-and-game-state-in-unreal-engine?application_version=5.7)

若地图存在已放置且自动被控制的 Pawn，或者更改了 PIE 出生设置，也可能走不同路径。排查“为什么生成了两个角色”时，应同时检查 Default Pawn 与场景中 Pawn 的 Auto Possess Player 设置。

## 4. 初始化函数要按职责理解

| 入口 | 本项目中做什么 | 阅读时的注意点 |
| --- | --- | --- |
| C++ 构造函数 | 创建默认子对象、设置初始组件参数 | 也参与类默认对象的构建，不能等同于“玩家开始游戏” |
| `BeginPlay` | 基础 Controller 按条件创建触摸 UI | 基础 Character 没有自定义该函数 |
| `PlayerController::SetupInputComponent` | 把配置数组里的 IMC 加入本地玩家输入子系统 | 这是输入映射安装入口 |
| `Character::SetupPlayerInputComponent` | 把 IA 触发事件绑定到角色函数 | 这是角色行为绑定入口 |
| `Possess` / `OnPossess` | 建立控制关系；变体 Controller 在这里订阅角色销毁 | 需要区分服务端控制逻辑和本地输入逻辑 |
| `NotifyControllerChanged` | Combat 角色更新 Controller 保存的重生 Transform | 基础 Character 没有对应的项目自定义实现 |
| `EndPlay` | 若该类有 Timer 等资源，则做清理 | 在变体中经常用于清理定时器 |

网络模式、已放置 Actor 与运行时生成 Actor、PIE 与独立游戏等条件会影响回调发生的时机。应在对应入口设置断点观察，而不是背诵“Possess → BeginPlay → 输入绑定”这一种固定顺序。

## 5. Character 的组件树

`Source/GASGame/GASGameCharacter.cpp` 的构造函数创建 `CameraBoom` 和 `FollowCamera`。Capsule、Mesh 与 CharacterMovement 则来自引擎 `ACharacter`。

```text
AGASGameCharacter
├─ CapsuleComponent                    根碰撞体
│  ├─ Mesh                             来自 ACharacter
│  └─ CameraBoom（SpringArmComponent）  本类创建
│     └─ FollowCamera（CameraComponent）本类创建
└─ CharacterMovementComponent          移动逻辑组件，不是场景附着节点
```

构造函数中的关键片段：

```cpp
CameraBoom = CreateDefaultSubobject<USpringArmComponent>(TEXT("CameraBoom"));
CameraBoom->SetupAttachment(RootComponent);
CameraBoom->TargetArmLength = 400.0f;
CameraBoom->bUsePawnControlRotation = true;

FollowCamera = CreateDefaultSubobject<UCameraComponent>(TEXT("FollowCamera"));
FollowCamera->SetupAttachment(CameraBoom, USpringArmComponent::SocketName);
FollowCamera->bUsePawnControlRotation = false;
```

`CreateDefaultSubobject` 声明角色自带的组件，`SetupAttachment` 描述场景附着关系。相机通过弹簧臂末端 Socket 定位；不要把 CharacterMovement 画成附着在 Capsule 上的可视场景组件。

## 6. C++、蓝图与地图的分工

| 层次 | 本工程中的例子 | 应该到哪里修改 |
| --- | --- | --- |
| C++ 行为 | `DoMove` 的方向计算、IA 的函数绑定 | 对应 `.h/.cpp` |
| C++ 初始值 | 最大走速、弹簧臂长度、转向方式 | 构造函数；同时检查蓝图是否覆盖 |
| 蓝图资源配置 | Mesh、Anim Class、Input Action 引用、IMC 数组 | 对应蓝图组件与 Class Defaults，待编辑器核对 |
| 蓝图表现扩展 | Combat 的 `ReceivedDamage`、`BP_ToggleCamera` | 蓝图事件图，待编辑器核对 |
| 地图实例与规则选择 | PlayerStart、关卡里的 Actor、GameMode Override | Level Editor 与 World Settings |

基础角色源码注释明确把骨骼 Mesh 和动画蓝图引用交给派生蓝图设置，避免直接在 C++ 中硬编码资源引用。其具体取值依然需要打开资源确认。

以后遇到“改了 C++ 速度但运行没有变化”，先确定正在控制哪一种角色，再看对应蓝图的移动组件是否保存了不同值。

## 7. 一次编辑器核对就能补齐的配置链

以下均为**待编辑器核对项**；本次没有读取这些二进制资源的内部默认值。

1. 在 Project Settings → Maps & Modes 对照默认地图和默认 GameMode。
2. 打开 `Content/ThirdPerson/Lvl_ThirdPerson.umap`，查看 World Settings → GameMode Override。
3. 打开最终生效的 GameMode，在 Class Settings 查看父类；在 Class Defaults 记录 Default Pawn Class、Player Controller Class。
4. 打开实际 Pawn 蓝图，在 Class Settings 核对父类，在 Components 核对 Mesh、Anim Class 和移动参数。
5. 打开实际 Controller 蓝图，记录 Default Mapping Contexts、Mobile Excluded Mapping Contexts、Mobile Controls Widget Class。
6. Play 后确认实际角色类及 Controller 类，再对照源码断点。核对过程不需要修改或保存资源。

判断框架是否接通，要看“配置引用 → 实际实例 → C++ 行为”三者是否一致。

## 8. 还没有自定义实现的框架类

本次对项目 `Source`、配置及 `.uproject` 的检索，没有发现项目自定义的 GameInstance、GameState、PlayerState 或自定义 GAS 组件类。这不代表引擎不会创建或使用默认框架对象，也不表示以后需要一次性把它们全部重写。

后续根据需求再选择：跨地图保留的本地数据可考虑 GameInstance 及其子系统；多人共享状态与玩家状态则分别评估 GameState 和 PlayerState。GameMode 实例只存在于权威端，不能让远程客户端 UI 直接依赖它取实时数据。[Epic：GameMode 与 GameState 的职责](https://dev.epicgames.com/documentation/en-us/unreal-engine/game-mode-and-game-state-in-unreal-engine?application_version=5.7)

## 9. 源码入口与自查

先读 `Config/DefaultEngine.ini`，再读 `Source/GASGame/` 下的 `GASGameGameMode.*`、`GASGamePlayerController.*`、`GASGameCharacter.*`。使用类名和函数名定位，比依赖易变化的行号更稳妥。

读完应能回答：

- 哪个配置决定默认地图？当前打开的地图能否有自己的 GameMode？
- GameMode 构造函数为空，为什么仍然能生成角色？
- Controller 和 Character 分别保存什么职责？
- 添加 IMC 和绑定 IA 的函数分别属于哪个对象？
- 哪些结论来自源码，哪些需要继续打开蓝图确认？
