# Game Programming Patterns：命令模式（Command Pattern）核心笔记

## 一、 模式定义与本质

- **对象化方法调用（Method Call in an Object）**：将一个请求/操作封装为一个独立的对象，从而可以用不同的请求对客户进行参数化。
- **回调函数的面向对象等价物**：本质上是用面向对象语言（如 C++ 虚函数）实现闭包（Closure）或第一类函数（First-Class Function）的功能。
## 二、 核心应用场景与解决的痛点

1. **输入映射解耦（Input Handling）**：将“按键/输入事件”与“实际执行的具体游戏行为”解耦，支持玩家运行时自定义按键绑定。
2. **撤销与重做系统（Undo / Redo）**：通过保存命令历史栈（History Stack），实现状态变更的可逆操作。
3. **AI 与网络指令队列（Actor Control）**：将控制指令参数化，使其可以被推入队列、延迟执行、序列化传输或分配给不同的游戏实体（Actor）。
## 三、 经典结构组成

- **Command 基类**：声明统一的抽象执行接口（如 `execute()`，撤销场景下增加 `undo()`）。
- **ConcreteCommand（具体命令）**：实现 `execute()` 接口，包含执行具体操作所需的上下文参数或目标对象引用。
- **Invoker / InputHandler（发起者）**：触发命令调用的对象（如按键监听器、UI 按钮），仅持有 `Command` 接口指针。
- **Receiver / Actor（接收者/作用目标）**：被命令操作的具体实体对象（如 `GameActor` / `Player`）。
## 四、 关键变体与设计抉择

### 1. 静态绑定 vs 动态参数化 Actor

- **直接作用于特定对象**：命令在构造时固化作用对象指针（适用于单例/特定系统，如 `OpenMenuCommand`）。
- **作为参数传入 Actor**：`virtual void execute(GameActor& actor)`，使得同一命令对象可复用于控制任何实体（如控制玩家、NPC 或 AI 单位）。
### 2. 状态存储与内存策略

- **无状态命令（Stateless Command）**：  
    - 命令不包含任何内部数据或临时状态。
    - **优化手段**：可声明为**单例（Singleton）**或**静态共享对象**，避免频繁 `new`/`delete` 引发的内存分配开销。
- **有状态命令（Stateful Command - 撤销/重做）**：  
    - 命令内部需要记忆“执行前”的具体数据状态（如移动前的位置 `x_`, `y_`）。
    - **优化手段**：每次执行生成新的命令实例，通常需要配合对象池（Object Pool）或智能指针进行管理，防止内存碎片与泄漏。
## 五、 撤销/重做（Undo/Redo）机制的核心约束

- **操作的可逆性**：必须能够在 `execute()` 执行前准确捕获恢复原状所需的最少增量数据（Delta State）。
- **命令历史栈结构**：  
    - 维护 `std::vector<Command*>` 历史记录与当前指针位置 `m_current`。
    - 新执行操作时，清空当前指针位置之后的所有“已撤销”历史。
- **流式撤销限制**：并非所有操作都容易撤销（如涉及随机数生成的粒子系统、涉及网络同步的状态变化），此类场景通常需结合快照（Snapshot/Memento）或直接禁用撤销。


###  核心难点 1：可重用实体命令（Actor-Parametric Commands）

#### 1. 原文痛点与原理
传统的命令模式往往将“命令”与“作用对象”强绑定（例如 `JumpCommand` 内部持有一个确定的 `Player*` 成员变量）。这会导致：
- 按键映射逻辑与特定玩家对象死板绑定。
- 无法把相同的 AI / 按键逻辑复用到其他角色（如控制 NPC、切换载具或控制派系的任何单位）。
**原书解决方案**：将作用目标作为参数传入 `execute(GameActor& actor)` 虚接口中。输入处理器（InputHandler）只负责**根据输入返回“想做什么”的命令**，再由游戏系统决定“由谁去执行”。
#### 2. 精简代码实现

```C++
#include <iostream>

// 实体基类
class GameActor {
public:
    virtual ~GameActor() = default;
    virtual void jump() { std::cout << "[Actor] 向上跳跃！\n"; }
    virtual void fireGun() { std::cout << "[Actor] 开火射击！\n"; }
};

// 抽象命令类：将 Actor 作为参数传入 execute
class Command {
public:
    virtual ~Command() = default;
    virtual void execute(GameActor& actor) = 0;
};

// 具体命令：无状态，可复用
class JumpCommand : public Command {
public:
    void execute(GameActor& actor) override {
        actor.jump(); // 作用于传入的任意实体
    }
};

class FireCommand : public Command {
public:
    void execute(GameActor& actor) override {
        actor.fireGun();
    }
};

// 输入处理器：解耦按键绑定与实际执行者
class InputHandler {
public:
    InputHandler() {
        // 绑定的命令本身不包含任何 Player 指针
        buttonX_ = new JumpCommand();
        buttonY_ = new FireCommand();
    }

    ~InputHandler() {
        delete buttonX_;
        delete buttonY_;
    }

    // 根据输入返回相对应的 Command 对象
    Command* handleInput(char key) {
        if (key == 'X' || key == 'x') return buttonX_;
        if (key == 'Y' || key == 'y') return buttonY_;
        return nullptr;
    }

private:
    Command* buttonX_;
    Command* buttonY_;
};

// 使用场景
int main() {
    InputHandler inputHandler;
    GameActor player;
    GameActor aiControlledNpc;

    // 1. 获取按键触发的命令
    Command* command = inputHandler.handleInput('X');
    
    if (command) {
        // 2. 可以让玩家执行
        command->execute(player);
        
        // 3. 也可以直接让 AI 实体执行完全相同的命令
        command->execute(aiControlledNpc);
    }

    return 0;
}
```

### 核心难点 2：有状态撤销/重做栈（Undo/Redo with Dynamic State）

#### 1. 原文痛点与原理
简单的无状态命令（如上面的 `JumpCommand`）不需要记录数据，且全局共享一份单例即可。
但如果要实现撤销（Undo）功能（例如在战棋/益智游戏中移动单位）：
1. 命令**必须有状态**：它必须在执行前记录“移动前的坐标”与“移动后的坐标”。
2. **每次操作生成新实例**：每次触发移动，必须动态 `new` 出一个包含当时增量数据的具体 Command 对象，并推入历史记录栈（History Stack）。
#### 2. 精简代码实现
```C++
#include <iostream>
#include <vector>
#include <memory>

// 可移动单位
class Unit {
public:
    Unit(int x, int y) : x_(x), y_(y) {}
    
    void moveTo(int x, int y) {
        x_ = x;
        y_ = y;
        std::cout << "[Unit] 当前位置: (" << x_ << ", " << y_ << ")\n";
    }

    int getX() const { return x_; }
    int getY() const { return y_; }

private:
    int x_, y_;
};

// 支持 Undo 的有状态命令
class MoveUnitCommand {
public:
    MoveUnitCommand(Unit& unit, int x, int y)
        : unit_(unit), x_(x), y_(y), xBefore_(0), yBefore_(0) {}

    // 执行：记录旧状态，应用新状态
    void execute() {
        xBefore_ = unit_.getX();
        yBefore_ = unit_.getY();
        unit_.moveTo(x_, y_);
    }

    // 撤销：将旧状态恢复回去
    void undo() {
        unit_.moveTo(xBefore_, yBefore_);
    }

private:
    Unit& unit_;
    int x_, y_;       // 目标位置（新状态）
    int xBefore_, yBefore_; // 记录的过去位置（旧状态）
};

// 撤销/重做管理器（Command History Stack）
class CommandManager {
public:
    void executeCommand(std::shared_ptr<MoveUnitCommand> cmd) {
        cmd->execute();
        
        // 如果在撤销后执行了新操作，清空当前指针之后废弃的 redo 历史
        if (currentIndex_ < static_cast<int>(history_.size())) {
            history_.erase(history_.begin() + currentIndex_, history_.end());
        }

        history_.push_back(cmd);
        currentIndex_++;
    }

    void undo() {
        if (currentIndex_ <= 0) {
            std::cout << "[History] 已经回到最初状态，无法继续撤销！\n";
            return;
        }
        currentIndex_--;
        std::cout << "[Undo] 正在撤销操作...\n";
        history_[currentIndex_]->undo();
    }

    void redo() {
        if (currentIndex_ >= static_cast<int>(history_.size())) {
            std::cout << "[History] 已经是最新状态，无法继续重做！\n";
            return;
        }
        std::cout << "[Redo] 正在重做操作...\n";
        history_[currentIndex_]->execute();
        currentIndex_++;
    }

private:
    std::vector<std::shared_ptr<MoveUnitCommand>> history_;
    int currentIndex_ = 0; // 当前在历史纪录栈中的游标位置
};

// 使用场景
int main() {
    Unit wizard(0, 0);
    CommandManager manager;

    // 1. 玩家把法师从 (0,0) 移到 (2,3)
    auto cmd1 = std::make_shared<MoveUnitCommand>(wizard, 2, 3);
    manager.executeCommand(cmd1);

    // 2. 玩家把法师从 (2,3) 移到 (5,8)
    auto cmd2 = std::make_shared<MoveUnitCommand>(wizard, 5, 8);
    manager.executeCommand(cmd2);

    // 3. 撤销上一步 -> 恢复到 (2,3)
    manager.undo();

    // 4. 重做上一步 -> 再次回到 (5,8)
    manager.redo();

    return 0;
}
```
