# Game Programming Patterns：状态模式（State Pattern）核心笔记

## 一、 模式解决的核心痛点

- **状态爆炸与分支污染**：避免使用庞大的 `switch-case` 或多重 `if-else` 条件分支控制对象行为。
- **有限状态机（FSM）抽象**：将“状态”封装为独立的类/对象，将“不同状态下的行为”与“状态转移逻辑”解耦，提高代码的扩展性与可维护性。

## 二、 有限状态机的三大核心要素

1. **状态集合（States）**：包含对象所有可能处于的有限个状态。
2. **输入集合（Inputs / Events）**：触发状态转移或行为改变的信号/事件。
3. **转移规则（Transitions）**：在特定状态下收到特定输入时，切换到下一个状态的映射关系。

## 三、 经典状态模式的实现结构

- **状态基类（State Base Class）**：定义公共虚接口（如 `handleInput()`, `update()`）。
- **具体状态类（Concrete States）**：派生自状态基类，仅实现该状态专属的行为逻辑与转移判断。
- **状态持有者（Context / Entity）**：包含当前状态指针（`State* currentState`），将更新循环与输入事件委派（Delegate）给当前状态处理。

## 四、 状态对象的分配与管理策略

| **管理策略**                         | **适用场景**                 | **优缺点**                                                                                |
| -------------------------------- | ------------------------ | -------------------------------------------------------------------------------------- |
| **静态/单例状态（Static State）**        | 状态不包含任何实例数据（无状态/只读）。     | **优点**：无需频繁创建销毁，零内存分配开销。<br><br>  <br>  <br><br>**缺点**：多个实体共享同一个状态，无法存储独立的状态内部数据。      |
| **动态实例化（Dynamic Instantiation）** | 状态需要记录局部数据（如动画播放进度、定时器）。 | **优点**：数据隔离，灵活性高。<br><br>  <br>  <br><br>**缺点**：每次状态切换伴随 `new`/`delete`，可能引发内存碎片或GC开销。 |

## 五、 状态转移的三种触发方式
1. **状态类内部自行转移**：具体状态在 `handleInput` 中返回新的状态指针或调用 Context 的 `changeState()`。
2. **状态持有者（Context）统一控制**：Context 监听事件并决定何时切换 State（适合全局/高层级逻辑）。
3. **状态转移表（State Transition Table）**：使用映射表 `(CurrentState, Event) -> NextState` 数据驱动配置（简化逻辑，但较难嵌入复杂过渡条件）。
## 六、 状态模式的高级演进形态

### 1. 并行状态机（Concurrent State Machines）

- **解决问题**：角色可以同时处于多个独立维度的状态（如“上半身开枪”与“下半身跑步”）。
- **核心机制**：实体持有所属不同维度的多个状态指针（如 `EquipmentState` + `MovementState`）。
角色可以同时处于**多个独立维度**的状态（例如：上半身开枪/挥刀，下半身站立/跑步）。实体只需同时维护**多个独立的 State 指针**。
```cpp
#include <iostream>

class Hero;

// 维度 1：移动状态接口
class MovementState {
public:
    virtual ~MovementState() = default;
    virtual void handleInput(Hero& hero, char input) = 0;
    virtual void update() = 0;
};

// 维度 2：装备/攻击状态接口
class EquipmentState {
public:
    virtual ~EquipmentState() = default;
    virtual void handleInput(Hero& hero, char input) = 0;
    virtual void update() = 0;
};

// 具体移动状态：跑步
class RunningState : public MovementState {
public:
    void handleInput(Hero& hero, char input) override { /* 移动方向切换 */ }
    void update() override { std::cout << "[下半身] 正在跑步..." << std::endl; }
};

// 具体装备状态：开枪
class FiringState : public EquipmentState {
public:
    void handleInput(Hero& hero, char input) override { /* 换弹/射击切换 */ }
    void update() override { std::cout << "[上半身] 正在开火！" << std::endl; }
};

// 实体持有者：并行组合两个状态维度
class Hero {
private:
    MovementState*  movementState_;   // 下半身状态
    EquipmentState* equipmentState_;  // 上半身状态

public:
    Hero(MovementState* move, EquipmentState* equip)
        : movementState_(move), equipmentState_(equip) {}

    ~Hero() {
        delete movementState_;
        delete equipmentState_;
    }

    // 统一分发事件给各个独立状态机
    void handleInput(char input) {
        movementState_->handleInput(*this, input);
        equipmentState_->handleInput(*this, input);
    }

    // 逐个更新每个状态
    void update() {
        movementState_->update();
        equipmentState_->update();
    }
};

int main() {
    Hero hero(new RunningState(), new FiringState());
    
    // 一帧更新中，两个状态独立运行，互不干扰
    hero.update(); 
    // 输出:
    // [下半身] 正在跑步...
    // [上半身] 正在开火！
    
    return 0;
}
```
### 2. 分层状态机（Hierarchical State Machines / HSM）

- **解决问题**：消除相似状态之间的重复代码（如“在地面蹲下”与“在地面站立”共享“在地面”的通用受击逻辑）。
- **核心机制**：状态类继承自“超状态类（Superstate）”。未被派生状态重写的输入处理会自动向上继承给父状态处理。

通过继承（Inheritance）实现超状态（Superstate）与子状态（Substate），当子状态不处理某个输入时，**自动交给超状态（父类）处理**，从而消除重复代码。
```cpp
#include <iostream>

// 实体类前置声明
class Hero;

// 1. 状态基类
class HeroState {
public:
    virtual ~HeroState() = default;
    
    // 默认实现：如果子状态没有重写 handleInput，自动向上继承给父状态处理
    virtual HeroState* handleInput(Hero& hero, char input) {
        return nullptr; // 默认不进行状态切换
    }
    
    virtual void update(Hero& hero) {}
};

// 2. 超状态：在地面（OnGroundState）
// 封装所有在地面时共用的逻辑（例如：按下 'D' 键闪避）
class OnGroundState : public HeroState {
public:
    HeroState* handleInput(Hero& hero, char input) override {
        if (input == 'D') {
            std::cout << "[超状态 OnGround] 触发通用闪避！" << std::endl;
            // 处理闪避逻辑...
            return nullptr;
        }
        // 未处理的输入传给更上层（若有）
        return HeroState::handleInput(hero, input);
    }
};

// 3. 具体子状态：站立（StandingState）
// 继承自 OnGroundState
class StandingState : public OnGroundState {
public:
    HeroState* handleInput(Hero& hero, char input) override {
        if (input == 'J') {
            std::cout << "[子状态 Standing] 按下跳跃，切换到空中状态" << std::endl;
            // 切换状态逻辑...
            return nullptr;
        }
        // 如果不是 'J'（如按下了 'D'），交给父类 OnGroundState 处理
        return OnGroundState::handleInput(hero, input);
    }
};

// 4. 实体持有者
class Hero {
private:
    HeroState* state_;
public:
    Hero(HeroState* initState) : state_(initState) {}
    
    void handleInput(char input) {
        HeroState* newState = state_->handleInput(*this, input);
        if (newState != nullptr) {
            delete state_;
            state_ = newState;
        }
    }
};
```
### 3. 下推自动机（Pushdown Automata）

#### 1. 核心痛点与背景

在标准 FSM 中，切换到新状态通常会彻底覆盖（丢弃）当前状态。
- **典型场景**：玩家在“站立”、“下蹲”或“跑步”时按下了“暂停键”或“被击飞”。
- **标准 FSM 的缺陷**：恢复时，实体无法知道“上一个状态”是什么，必须通过额外的变量硬编码记录，或者导致状态逻辑污染。
#### 2. 解决方案：状态栈（State Stack）

下推自动机使用栈（Stack）结构来存储状态历史，用 **Push（压栈）** 和 **Pop（出栈）** 替代简单的赋值覆盖。
- **Push（压栈）**：暂停当前状态并保留在栈中，将新状态压入栈顶（例如：打开菜单、被强力打断）。
- **Pop（出栈）**：销毁当前栈顶状态，**自动恢复并回到上一个状态**（例如：关闭菜单、击飞恢复）。
#### 3. C++ 代码示例
```cpp
#include <vector>
#include <memory>
#include <iostream>

class Hero;

class State {
public:
    virtual ~State() = default;
    virtual void handleInput(Hero& hero, char input) = 0;
    virtual void update(Hero& hero) = 0;
};

class Hero {
private:
    // 使用栈（Stack）管理状态历史
    std::vector<std::unique_ptr<State>> stateStack_;

public:
    // 压入新状态（如：打开暂停菜单）
    void pushState(std::unique_ptr<State> newState) {
        stateStack_.push_back(std::move(newState));
    }

    // 弹出当前状态，自动回到上一状态（如：关闭菜单）
    void popState() {
        if (!stateStack_.empty()) {
            stateStack_.pop_back();
        }
    }

    // 仅在栈顶（当前处于的状态）处理逻辑
    void handleInput(char input) {
        if (!stateStack_.empty()) {
            stateStack_.back()->handleInput(*this, input);
        }
    }

    void update() {
        if (!stateStack_.empty()) {
            stateStack_.back()->update(*this);
        }
    }
};
```

## 七、 进阶补充：进入与退出动作（Entry / Exit Actions）
#### 1. 核心痛点与背景
当状态发生切换时，通常需要伴随一些**一次性的初始化与清理工作**。
- **例子**：进入 `JumpState` 时播放跳跃音效并设置向上冲量；离开 `JumpState` 时将重力系数恢复默认。
- **如果不使用 Entry/Exit**：任何**触发**切换到 `JumpState` 的地方（如从 `StandingState` 切换、从 `RunningState` 切换）都必须手动编写“播放音效”、“施加冲量”的逻辑，导致大量重复代码且易漏写。
#### 2. 解决方案：显式回调函数 `enter()` 与 `exit()`
将“进入该状态该做什么”和“离开该状态该做什么”封装在状态类自身内部。
- **`enter()`**：状态被激活时（刚设为当前状态时）**立即且仅执行一次**。
- **`exit()`**：状态即将被替换/销毁前**立即且仅执行一次**。
#### 3. C++ 代码示例
```cpp
#include <iostream>

class Hero;

class HeroState {
public:
    virtual ~HeroState() = default;

    // 进入状态时执行（初始化）
    virtual void enter(Hero& hero) {}

    // 退出状态时执行（清理）
    virtual void exit(Hero& hero) {}

    virtual HeroState* handleInput(Hero& hero, char input) { return nullptr; }
};

// 跳跃状态
class DuckingState : public HeroState {
public:
    void enter(Hero& hero) override {
        // 显式保证：只要进入下蹲状态，立刻调整碰撞盒
        std::cout << "[Enter] 缩小角色碰撞盒高度" << std::endl;
    }

    void exit(Hero& hero) override {
        // 显式保证：只要离开下蹲状态，立刻还原碰撞盒
        std::cout << "[Exit] 恢复角色碰撞盒高度" << std::endl;
    }
};

class Hero {
private:
    HeroState* state_;

public:
    Hero(HeroState* initState) : state_(initState) {
        state_->enter(*this);
    }

    void changeState(HeroState* newState) {
        if (newState == nullptr) return;

        // 切换全流程：旧状态 exit -> 替换指针 -> 新状态 enter
        state_->exit(*this);
        delete state_;
        
        state_ = newState;
        state_->enter(*this);
    }
};
```

## 八、 高级演进形态对比总结

| 模式/技术扩展                | 核心设计思想                                  | 最适用场景                        |
| ---------------------- | --------------------------------------- | ---------------------------- |
| **分层状态机 (HSM)**        | 通过类继承建立超状态，子状态处理不了的事件向上委托。              | 多个状态有大量共用逻辑（如地面移动、受击等）。      |
| **并行状态机 (CSM)**        | 实体持有多个不同维度的独立状态指针。                      | 角色的上半身与下半身动作互不干涉。            |
| **下推自动机 (Pushdown)**   | 用状态栈 `std::vector<State*>` 替代单一状态指针。    | 临时打断、UI 菜单层级、弹出框、历史状态恢复。     |
| **Entry/Exit Actions** | 给 State 增加 `enter()` / `exit()` 生命周期回调。 | 切换状态时的初始化/清理逻辑（如碰撞盒修改、音效播放）。 |
