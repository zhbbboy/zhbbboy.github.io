GAMES104 第 3 节《如何构建游戏世界》（How to Build a Game World）核心解决的是**游戏世界在内存中的表达与组织方式**。围绕你提供的 5 条核心 Takeaways，这里为你梳理出一份逻辑严密的精炼笔记。

### GAMES104 第3节：如何构建游戏世界（5 大核心 Takeaways 深度提炼）

**核心思想**：游戏世界并非现实世界的简单复制，而是通过**组件化拼装实体**、**Tick 驱动状态**、**事件机制解耦交互**以及**空间分割高效管理**构建出的虚拟系统。
### 1. Everything is an object (Game Object)

- **本质**：游戏世界中的万物（角色、灯光、NPC、空气墙、甚至逻辑触发器）本质上都是一个 **Game Object**（在 Unreal 中称为 Actor，Unity 中称为 GameObject）。
- **ID 载体**：Game Object 本身应该尽可能保持“轻量”，它主要是作为一个包含唯一标识符（GUID / Unique ID）和生命周期管理的容器。
### 2. Game object could be described in the component-based way
- **为什么弃用纯 OOP 继承？**
    - 面向对象（OOP）深度继承树会导致“菱形继承”与结构臃肿（例如：既能飞又能被骑乘的怪物，继承关系极难设计）。
- **组件化（Component-Based）哲学：组合优于继承**
    - 将能力拆解为独立的 Component，Game Object 只需像搭积木一样“插拔”组件：
        - **Transform Component**：赋予其空间位置与姿态（基础组件）。
        - **Mesh / Light Component**：赋予其视觉渲染能力。
        - **RigidBody / Collider Component**：赋予其物理碰撞与运动属性。
        - **Gameplay Component**：赋予其血量、技能等玩法逻辑。
### 3. States of game objects are updated in tick loops

- **动态世界的本质**：Game Object 的各种属性（位置、动画、血量）随时间变化的本质，是引擎在 **Tick Loop（循环刷新）** 中不断重新计算并更新其状态。
- **分层/批量 Tick（Batch Update）**：  
    - 为了避免逐个调用对象的 `Update()` 带来大量的虚函数开销与 CPU Cache Miss，现代引擎倾向于将同类 Component 交给对应的 Subsystem（如 Physics System、Render System）统一集中进行数据连续的批量 Tick。
### 4. Game objects interact with each other via event mechanism

- **解耦交互（Decoupling）**：Game Object 之间不能硬编码直接调用对方的内部接口，否则会导致网状耦合，极难维护。
- **事件与消息机制 (Event / Messaging System)**：
    - **观察者模式 / 订阅发布**：Object A 抛出一个事件（如 `OnTakeDamage`），并不关心是谁触发的或谁来接收；广播系统将事件派发给所有订阅了该事件的 Component 或其他 Object。
    - **延迟与队列处理**：部分事件通过事件队列（Event Queue）跨帧异步分发，避免单帧高并发阻塞主线程。

### 5. Game objects are managed in a scene with efficient strategies

- **场景与世界架构 (Scene & World Management)**：
    - **Scene / Sub-Scene**：单个关卡或数据块，负责承载具体的 Game Object 集合。
    - **World**：管理多个 Scene 的顶层容器，支持场景流式加载（Scene Streaming）。
- **空间划分与剔除（Spatial Data Structures）**：
    - 面对成千上万个 Game Object，不能用线性数组盲目遍历。
    - **高效管理策略**：采用 **BVH (Bounding Volume Hierarchy)**、**八叉树 (Octree)** 或 **网格划分 (Grid/BVH)** 等空间数据结构，实现快速的视锥体剔除（Frustum Culling）、射线检测（Raycast）和邻近查询。

### 总结：Game Object、Component、Scene、World 的关系

$$\text{World} \longrightarrow \text{Scenes} \longrightarrow \text{Game Objects} \stackrel{\text{Composition}}{\longleftarrow} \text{Components}$$

1. **Component** 决定 **Game Object**“有什么属性与能力”；
2. **Game Object** 在 **Tick** 与 **Event** 中动态改变状态并与外界交互；
3. **Scene & World** 利用空间数据结构对 **Game Objects** 进行高效组织、管理与流式加载。
