动画压缩

GAMES104 第 8 节《游戏引擎动画技术基础》（Animation System Fundamentals）的核心在于讲解**如何让虚拟角色“动起来”**，即从基础的骨骼动画存储、姿态计算到多动画混合的完整技术链条。
### 一、 核心概念：2D 动画 vs 3D 骨骼动画

- **2D 帧动画 (Flipbook/Sprite)**：通过连续播放多张预先绘制好的图像呈现动态，资源占用随分辨率和帧数成倍增加。
- **3D 骨骼动画 (Skeletal Animation / Skinning)**：
    - **逻辑与表现分离**：用轻量的“骨骼（Skeleton）”驱动重量的“三维网格（Mesh）”。
    - **核心组成**：
        1. **Skeleton（骨骼层）**：由具有层级关系的关节点（Joints/Bones）组成的树状结构。
        2. **Skinning Mesh（皮肤层）**：绑定了骨骼权重（Bone Weights）的 3D 网格顶点。
        3. **Animation Data（数据层）**：随时间变化的骨骼变换信息（PRS：Position, Rotation, Scale）。
### 二、 骨骼动画的核心数学与姿态计算

#### 1. 姿态（Pose）的数学表达
- 每一根骨骼在空间中的变换通常由 **PRS** 表达：
    - **Translation (P)**：3D 向量 (Vector3)。
    - **Rotation (R)**：四元数 (Quaternion，避免万向节死锁，便于平滑插值)。
    - **Scale (S)**：3D 向量 (Vector3)。
#### 2. 局部空间 vs 世界空间 (Local Space vs Model/World Space)

- **Local Space（局部空间）**：每根骨骼的变换是相对于其**父节点骨骼**的。
- **Model Space（模型空间）**：为了进行蒙皮计算，必须将局部变换沿骨骼树向上层层累乘，转换到统一的模型坐标系下：
    $$T_{\text{Model}}^{\text{Bone}} = T_{\text{Model}}^{\text{Parent}} \cdot T_{\text{Parent}}^{\text{Bone}}$$

#### 3. 蒙皮算法 (Skinning Algorithm)

- **LBS (Linear Blend Skinning, 线性混合蒙皮)**：
    - 引擎中最常用的实时蒙皮算法。顶点的最终位置由影响它的多根骨骼按权重加权求和求得：
    $$v_{\text{final}} = \sum_{i} w_i \cdot M_i \cdot B_i^{-1} \cdot v_{\text{mesh}}$$
    
    _(其中 $w_i$ 为权重，$M_i$ 为骨骼当前变换矩阵，$B_i^{-1}$ 为 Bind Pose 逆矩阵)_
    
- **LBS 的缺陷**：在关节大幅度旋转（如折叠肘部、扭转手腕）时会出现“糖果纸捏拧（Candy-wrapper）”和体积损失（Volume Loss）问题。

### 三、 动画数据压缩 (Animation Compression)

动画数据占用的内存极大，必须在引擎中进行极致压缩：
1. **关键帧抽稀 (Keyframe Reduction)**：剔除变化不明显或可通过插值线性还原的帧（如曲线拟合/Douglas-Peucker 算法）。
2. **量化 (Quantization)**：
    - 将 32 位浮点数（Float32）量化压缩为 16 位甚至 8 位整数。
    - 四元数 $w$ 分量恢复（只存储 $x, y, z$，利用 $x^2+y^2+z^2+w^2=1$ 实时计算 $w$）。
3. **基于 Track 的分离**：将平移、旋转、缩放轨迹分别独立压缩存储。

### 四、 动画混合 (Animation Blending)
为了实现动作之间的平滑过度，必须对不同的动画姿态进行混合：
- **1D / 2D 混合空间 (Blend Space)**：
    - 依据游戏参数（如移动速度 Speed、移动方向 Direction），在多个基础动画（站立、走路、跑步）之间进行加权插值（LERP / SLERP）。
- **分层动画与掩码 (Layered Animation & Skeleton Mask)**：
    - 将骨骼树按部位切分。例如：上半身播放“射击/攻击”动画，下半身播放“跑步”动画，实现上半身与下半身解耦。
- **加法动画 (Additive Animation)**：
    - 存储“相对差值姿态”（如 Breathing 呼吸抖动、受伤挨打），叠加到任何基础动画（Idle/Run）之上。

### 五、 本节核心 Takeaways

1. **数据驱动与层级变换**：骨骼动画本质是用**树状层级**和**时间序列的 PRS 数据**驱动顶点变换。
2. **性能与内存平衡**：从 CPU 的矩阵乘法、GPU 的 LBS 蒙皮，到骨骼数据的极致压缩，一切都在为实时性（16.6ms）服务。
3. **从 Single Animation 到 Blending**：现代游戏不是播放单一动作，而是通过混合空间、分层和加法机制，用有限的动画资源拼装出无限的动态表现。

把截图中的核心公式与数据结构梳理为以下 4 个最关键的考点：
### 重点 1：骨骼的数据结构（Memory Representation）

对应截图 1，骨骼树在内存中通常用数组（扁平化）存储，关键结构体 `Joint` 包含：
- **父节点索引 (`m_parent_joint_index`)**：通过数组下标定位父节点，根节点为 `0xFF`。
- **绑定姿态的 PRS 变换 (`m_bind_pose_...`)**：包含 Translation、Rotation、Scale。
- **逆绑定姿态矩阵 (`m_inverse_bind_pose_transform` / $(M_{b(J)}^m)^{-1}$)**：**核心重难点**，预先计算好的矩阵，用于将顶点从模型空间转回骨骼的局部空间。
### 重点 2：蒙皮矩阵的推导过程（Skinning Matrix Formulation）

对应截图 2 与 3，为什么顶点变换需要先乘以“逆绑定矩阵”？

1. **绑定状态下的转换**：
    网格顶点 $V_b^m$（Bind Pose 下的模型空间坐标）转换到骨骼 $J$ 的局部空间 $V_b^l$：
    $$V_b^l = (M_{b(J)}^m)^{-1} \cdot V_b^m$$
2. **$t$ 时刻的动画更新**：
    在 $t$ 时刻，骨骼 $J$ 在模型空间下的变换为 $M_J^m(t)$。由于顶点与骨骼的相对位置固定（$V^l(t) \equiv V_b^l$），顶点在 $t$ 时刻的模型空间坐标 $V^m(t)$ 为：
    $$V^m(t) = M_J^m(t) \cdot V_b^l = M_J^m(t) \cdot (M_{b(J)}^m)^{-1} \cdot V_b^m$$
    
3. **得出蒙皮矩阵 $K_J$**：
    $$K_J = M_J^m(t) \cdot (M_{b(J)}^m)^{-1}$$
    - **含义**：先用 $(M_{b(J)}^m)^{-1}$ 把顶点“拉回”**骨骼局部空间，再用 $M_J^m(t)$ 把顶点**“带到” $t$ 时刻的最新位置。

### 重点 3：蒙皮矩阵调色板优化（Skinning Matrix Palette）

对应截图 4，这是 CPU 提交给 GPU 渲染时的优化技术：
- **矩阵预合**：CPU 直接将 **Model Space $\rightarrow$ World Space** 的变换矩阵 $M^w$ 连同 $K_J$ 一起算好：
    $$K'_J = M^w \cdot M_J^m(t) \cdot (M_{b(J)}^m)^{-1}$$
- **GPU 传参**：把所有骨骼算好的 $K'_J$ 组成的数组（即 Palette / 调色板）一次性传给 GPU Shader。GPU 顶点着色器只需做一次矩阵乘法 $V^w = K'_J \cdot V_b^m$，极大节省 GPU 计算量。
### 重点 4：动画运行时管线（Animation Runtime Pipeline）
对应截图 5，展示了一帧内 CPU 到 GPU 的完整数据流：
1. **Extract（采样）**：根据动画 Clip 与时间 $t$，从前一帧（Previous Frame）和后一帧（Next Frame）提取 keyframe 数据。
2. **Interpolate（插值）**：在 **Local Space** 对 PRS 进行插值（平移/缩放用 LERP，旋转用 SLERP），得到 `Local Current Pose`。
3. **Calculate Skinning Matrix（累乘与计算）**：沿骨骼树向上累乘计算出 `Model Current Pose`，再乘以 Inverse Bind Pose 得到 `Skinning Matrix Palette`。
4. **Skinning（GPU 蒙皮）**：将 Palette 传给 GPU，GPU 根据顶点权重加权计算，输出最终的 `Mesh Vertex Position` 并渲染。
### 总结口诀（面试必背）

> **“Local 插值，Model 累乘，乘以逆绑定，调色板传 GPU 蒙皮。”**

### 补充重点 1：四元数（Quaternion）在动画中的原理与应用

在引擎中，旋转用 $3 \times 3$ 矩阵存太耗内存，用欧拉角（Euler Angle）又存在**万向节死锁（Gimbal Lock）**且极难插值，因此必须使用**四元数**。
#### 1. 什么是四元数？
四元数由一个实部和三个虚部构成：

$$q = w + x\mathbf{i} + y\mathbf{j} + z\mathbf{k} = (w, \mathbf{v})$$

- **物理意义（轴-角表示）**：四元数代表“绕空间中某个旋转轴 $\mathbf{u}$ 旋转了角度 $\theta$”：
    $$q = \left( \cos\frac{\theta}{2}, \, \mathbf{u} \sin\frac{\theta}{2} \right)$$
    
- **三维旋转必须是单位四元数**：即 $w^2 + x^2 + y^2 + z^2 = 1$。
#### 2. 为什么动画插值必须用四元数？

- **LERP（线性插值）**：计算快，但会导致旋转角速度不均匀（两头快中间慢），且插值出来的四元数会失去单位化，必须做标准化（NLERP）。
- **SLERP（球面线性插值）**：沿四元数单位球面的大圆弧进行等角速度插值。
    $$\text{SLERP}(q_1, q_2, t) = \frac{\sin((1-t)\theta)}{\sin\theta}q_1 + \frac{\sin(t\theta)}{\sin\theta}q_2$$
- **双倍覆盖问题（Double Cover / 最短路径选择）**：
    - $q$ 与 $-q$ 代表完全相同的 3D 旋转。
    - 做插值前必须先计算点积 $q_1 \cdot q_2$：**若点积 $< 0$，必须把 $q_2$ 反转为 $-q_2$**，否则动画会绕远路旋转 $360^\circ$（出现俗称的“脖子甩一圈”Bug）。
### 补充重点 2：动画数据压缩（Animation Compression）深度拆解
**为什么必须压缩？**
一个未压缩的骨骼动画：$90\text{ Joints} \times 30\text{ FPS} \times (\text{Translation}(12\text{B}) + \text{Rotation}(16\text{B}) + \text{Scale}(12\text{B})) \approx 108\text{ KB/秒}$。若游戏有上千种动作，内存会立刻爆掉。
引擎通常采用 **“三步走” 压缩策略**：
#### 1. 关键帧抽稀（Keyframe Reduction / Pruning）
- **原理**：去除变化不大或可由前后帧线性插值还原的帧。
- **常用算法**：
    - **Catmull-Rom / Spline 拟合**：将关键帧连接成曲线，离曲线极近的中间点直接丢弃。
    - **误差容忍度判定（Error Tolerance）**：模拟剔除某帧后对终端骨骼（如手掌顶点）造成的空间位移误差，若误差 $< 1\text{mm}$，则该帧可安全删掉。
#### 2. 轨迹分离（Track Separation）
- 并非每根骨骼都有完整 PRS。
- 绝大多数身体骨骼（如肘关节、膝盖）只有 **Rotation** 变化，其 Translation 和 Scale 在 Bind Pose 下是恒定不变的。引擎会**剥离无效通道**，只保留有数据的 Track。
#### 3. 量化与位压缩（Quantization & Bit Packing）—— _最核心_

- **四元数“丢弃 $w$ 分量”（Drop W / Smallest Three）**：
    - 因为单位四元数满足 $w^2 + x^2 + y^2 + z^2 = 1$，且 $w$ 一定可以通过 $\sqrt{1 - (x^2 + y^2 + z^2)}$ 恢复。
    - **做法**：只需要找到最大的一项，把剩下三项压缩存入，解压时实时计算第四项。
- **浮点数转整数（Float32 $\rightarrow$ Fixed-Point Int16/Int8）**：
    - 旋转角度或平移范围通常在固定区间 $[-\text{Max}, \text{Max}]$ 内。
    - 将 32 位浮点数映射压缩到 16 位甚至 8 位整数（如把范围均分成 65535 份），解码时再还原为 Float。
### 💡 复习速记卡片
```
[ 四元数插值 ] -> 认准 SLERP -> 插值前检查 q1·q2 < 0 (防止绕远路) -> 避免万向节死锁
[ 蒙皮核心 ]   -> Skinning Matrix K = M(t) * M_bind^-1 -> CPU 算出 Palette 扔给 GPU
[ 动画压缩 ]   -> 丢无用 Track -> 删拟合关键帧 -> 四元数只存 3 个分量量化为 Int16
```
