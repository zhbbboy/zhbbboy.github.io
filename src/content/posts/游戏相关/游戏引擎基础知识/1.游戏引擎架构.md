# 第1节游戏引擎导论
### 一、 什么是游戏引擎？

- **核心定义**：游戏引擎是用于创建和开发交互式实时图像（实时渲染）软件（即游戏）的集成开发环境（IDE）与底层基础设施。
- **核心价值**：避免重复造轮子，让开发者专注于游戏内容（Gameplay）与艺术表现，而非底层硬件适配与基础设施搭建。

### 二、 游戏引擎的五层经典架构
游戏引擎通常遵循分层架构原则，从底向上划分为 **5 个主要层级**：
```
+-------------------------------------------------------+
| 5. Gameplay 层 ( Gameplay / Game Logic )               |
+-------------------------------------------------------+
| 4. 工具层 ( Tooling / Editor )                         |
+-------------------------------------------------------+
| 3. 核心功能层 ( Function / Systems )                   |
+-------------------------------------------------------+
| 2. 资源层 ( Resource / Data Management )              |
+-------------------------------------------------------+
| 1. 平台/硬件层 ( Platform / Hardware Layer )            |
+-------------------------------------------------------+
```
#### 1. 平台/硬件层 (Platform & Hardware Layer)

- **目标**：屏蔽硬件与操作系统的物理差异。

- **涵盖内容**：
    - **硬件端**：PC (Windows/Mac/Linux)、主机 (PS/Xbox/Switch)、移动端 (iOS/Android)。
    - **图形 API**：DirectX 11/12、Vulkan、Metal、OpenGL ES。
    - **系统接口**：内存分配、多线程调度、网络 Socket、输入设备 (Keyboard/Mouse/Gamepad)。
#### 2. 资源层 (Resource Layer)

- **目标**：管理所有的外部资产（Assets），将磁盘上的文件转换为运行时可用的高效内存数据。
- **核心概念**：**数据驱动（Data-Driven）**。
- **主要职责**：
    - **离线导入与编译**：将 `.obj`, `.fbx`, `.png`, `.wav` 等原始格式编译转换为引擎专属的高效格式（如 `.uasset` 或压缩纹理 `ASTC/BC7`）。
    - **虚拟文件系统 (VFS)** 与包管理（Pak File）。
    - **资产句柄与生命周期**：异步加载、卸载、垃圾回收 (GC) 与延迟加载 (Stream-in/Stream-out)。
#### 3. 核心功能层 (Function Layer)
- **目标**：驱动游戏每一帧运行的核心子系统集合（引擎的最重头部分）。
- **核心子系统**：
    - **渲染系统 (Rendering Engine)**：负责把 3D 场景转化为 2D 图像（前向/延迟渲染、光照、阴影、后处理、PBR 等）。
    - **物理系统 (Physics Engine)**：碰撞检测（Rigid body/Shape）、刚体动力学、流体与布料模拟（PhysX/Havok/Chaos）。
    - **动画系统 (Animation Engine)**：骨骼动画、Blend Space、IK (逆运动学)、状态机 (State Machine)。
    - **音频系统 (Audio Engine)**：3D 空间音效、混响、音频事件触发（FMOD/Wwise）。
    - **场景管理/世界构建 (Scene Management)**：场景树（Scene Graph）、空间划分算法（Octree, BVH）与可见性剔除（Culling）。
    - **逻辑/脚本系统 (Scripting Engine)**：C++、Lua、C# 或蓝图（Visual Scripting）。
#### 4. 工具层 (Tooling Layer)
- **目标**：为策划、美术、程序员提供可视化的创作平台（即“引擎编辑器”）。
- **核心组件**：
    - **关卡编辑器 (Level Editor)**：场景摆放、Terrain/Foliage 植被编辑。
    - **材质编辑器 (Material Editor)**：节点化 Shader 编写。
    - **动画编辑器 & 序列帧**：Timeline/Sequencer 动画合成。
    - **调试与性能分析 (Profiler)**：帧率检测、内存占用、GPU/CPU 耗时分析、Gizmo 辅助线。
#### 5. Gameplay 层 (Gameplay Layer)
- **目标**：具体游戏的逻辑实现。
- **核心模式**：
    - **ECS 架构** (Entity-Component-System) 或 **组件化架构** (Component-Based Architecture)。
    - **Game Mode / Rules**：胜负判定、规则计算、玩家输入映射 (Input Control)。

### 三、 游戏引擎的动力核心：游戏循环 (Game Loop)

游戏引擎运行的基础逻辑是无限死循环，直到退出游戏：
$$\text{Game Loop: } \text{Process Input} \rightarrow \text{Update Game State (Physics/AI/Anim)} \rightarrow \text{Render Frame}$$
- **关键概念：Delta Time ($\Delta t$)**
    - 由于各台机器帧率不同，不能按帧做逻辑更新，必须根据上一帧消耗的时间进行物理与位移计算（确保在 30FPS 和 144FPS 下角色移动速度一致）。
### 四、 GAMES104 核心视角总结

1. **引擎不是一堆库的简单堆砌**：它是高度模块化、高度协作且极其强调实时性（Real-time, 通常为 33ms 或 16.6ms 每帧）的复杂软件系统。
2. **数据与逻辑分离**：资源层负责数据，功能层负责计算，工具层负责创作，Gameplay 层负责表达。
3. **架构优先**：学游戏引擎，先看清“树干”（架构分层），再填充“叶子”（算法细节）。
